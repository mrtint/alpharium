- Q: 사용자가 사진이 있는 날에서 사진 내용을 미리 읽는 중(아직 안 끝난 상태)에 일기 쓰기를 누르면 어떻게 동작해야 하는가? → A: 미리 읽기가 끝날 때까지 기다린 뒤, 그 결과를 이어서 사용해 생성한다(사용자는 대기가 약간 더 길어질 뿐 정상 완성)

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 사진 없는 날, 대기가 짧아진다 (Priority: P1)

사용자가 캐릭터와 날짜를 고르고 일기 쓰기를 누른다. 그 날에 읽을 사진이 없는
경우, 일기가 완성되기까지 지금보다 눈에 띄게 적게 기다린다. 화면에 보이는
결과물(문장 내용, 분량, 말투)은 이전과 똑같다 — 달라지는 것은 기다리는
시간뿐이다.

**Why this priority**: 가장 작고 안전하게 낼 수 있는 효과다. 사진을 읽는
경로를 건드리지 않으므로 위험이 가장 적고, 이 시나리오 하나만으로도 사용자가
체감할 수 있는 개선이 나온다.

**Independent Test**: 사진이 없는 날 하나를 골라, 이 기능 적용 전후로 각각
몇 차례 일기를 써서 화면에 표시되는 "작성하는 데 걸린 시간"을 비교한다.
전후 모두 같은 캐릭터·같은 날짜 조건에서 재는 것으로 충분히 판단할 수 있다.

**Acceptance Scenarios**:

1. **Given** 사용자가 캐릭터와, 읽을 사진이 없는 날짜를 이미 고른 상태,
   **When** 그 상태로 화면에 머무르다가 일기 쓰기를 누르면, **Then** 일기가
   기존보다 짧아진 대기 시간 안에 완성되고, 내용·분량·말투는 이 변경이 없었을
   때와 같다.
2. **Given** 사용자가 방금 캐릭터나 날짜를 바꿔 아직 대기 시간을 벌지 못한
   상태, **When** 곧바로 일기 쓰기를 누르면, **Then** 일기는 정상적으로
   완성된다(이전과 같은 시간이 걸리더라도 실패하거나 이상하게 동작하지
   않는다).
3. **Given** 사용자가 캐릭터·날짜 선택 화면에 머무는 동안, **When** 앱을
   벗어나 다른 앱으로 전환하면, **Then** 돌아왔을 때 일기 쓰기가 이전과
   다름없이 정상 동작한다 — 화면을 벗어나 있던 동안의 내부 준비 상태와 무관하게
   사용자에게 보이는 동작은 달라지지 않는다.

---

### User Story 2 - 사진 있는 날에도 대기가 짧아진다 (Priority: P2)

사용자가 사진이 있는 날을 골라 일기 쓰기를 누른다. 사진을 읽는 과정과 글을
쓰는 과정을 합친 전체 대기 시간이 지금보다 뚜렷하게 줄어든다. 사진 내용이
일기에 반영되는 정도와 정확성은 이전과 같다.

**Why this priority**: 사진이 있는 날이 지금 가장 오래 기다리는 경우이므로
효과가 가장 크지만, User Story 1보다 손대는 범위가 넓어(사진 읽기 순서 자체를
옮김) 위험도 더 크다. P1이 먼저 안전하게 자리 잡은 뒤에 얹는다.

**Independent Test**: 사진이 있는 날 하나를 골라, 적용 전후로 각각 몇 차례
일기를 써서 화면에 표시되는 전체 대기 시간을 비교한다. 완성된 일기가 사진
내용을 반영하는지도 함께 확인한다.

**Acceptance Scenarios**:

1. **Given** 사용자가 사진이 있는 날을 고른 상태, **When** 일기 쓰기를
   누르면, **Then** 사진을 읽는 시간과 글을 쓰는 시간을 합친 전체 대기가
   기존보다 뚜렷하게 짧아지고, 완성된 일기는 그 사진들의 내용을 이전과 같은
   수준으로 반영한다.
2. **Given** 사용자가 사진이 있는 날을 고르고 화면에서 사진을 미리 살펴보는
   동안, **When** 그 뒤 일기 쓰기를 누르면, **Then** 사진을 다시 읽지 않고도
   그 대기 동안 이미 준비된 내용을 사용해 더 빠르게 완성된다.
3. **Given** 사용자가 사진이 있는 날을 고른 직후, 사진 내용을 미리 읽는
   과정이 아직 끝나지 않은 상태, **When** 그 상태에서 곧바로 일기 쓰기를
   누르면, **Then** 시스템은 새로 처음부터 다시 읽지 않고 진행 중이던
   미리 읽기가 끝나기를 기다린 뒤 그 결과를 이어서 사용해 일기를 완성한다 —
   사용자는 대기가 조금 더 길어질 뿐, 일기는 정상적으로 완성된다.
4. **Given** 사용자가 사진이 있는 날을 고른 뒤 그 날짜를 다른 날짜로
   바꾸면, **When** 이후 일기 쓰기를 누르면, **Then** 일기는 새로 고른
   날짜의 사진 내용만 반영하며, 이전 날짜에서 미리 준비해 둔 내용이 섞여
   들어가지 않는다.

---

### Edge Cases

- 미리 준비하는 동작 자체가 실패하면 어떻게 되는가? 사용자는 알아채지 못해야
  한다 — 일기는 이 기능이 없었을 때와 같은 속도로라도 정상적으로 완성되어야
  한다(무음 실패, 재시도 없음, 사용자에게 오류를 보이지 않음).
- 사용자가 캐릭터를 고른 직후 화면을 오래 떠나 있다가(다른 앱 사용, 화면
  잠금 등) 한참 뒤 돌아와 바로 일기 쓰기를 누르면? 미리 준비된 내용이
  그 사이 시스템 사정으로 사라졌더라도 일기는 정상적으로(다만 예전 속도로)
  완성되어야 한다.
- 사용자가 일기 쓰기를 누르기 전에 캐릭터를 여러 번 바꾸면? 마지막으로 고른
  캐릭터를 기준으로만 준비가 이루어져야 하며, 이전에 고른 캐릭터를 위해
  준비하던 것이 결과에 섞이거나 자원을 이중으로 붙잡고 있으면 안 된다.
- 저사양 기기이거나 다른 작업으로 메모리가 빠듯한 상황에서, 화면에 머무르는
  동안 미리 준비해 둔 상태를 계속 붙잡고 있으면 다른 기능(특히 사진 읽기)이
  자원 부족으로 실패하지 않는가? 화면을 벗어나면 미리 준비해 둔 상태를
  놓아주어야 한다.
- 사진이 있는 날인지 없는 날인지의 판단이 일기 생성 시점의 실제 판단과
  어긋나면(예: 준비 시점엔 "없음"으로 봤는데 생성 시점엔 사진이 있는 것으로
  드러남) 어떻게 되는가? 두 판단은 항상 같은 기준으로 이루어져야 하며,
  어긋남으로 인해 두 개의 큰 처리 과정이 동시에 자원을 붙잡는 일이 있어서는
  안 된다.
- 사진 내용을 미리 읽는 과정이 아직 끝나지 않았는데 사용자가 일기 쓰기를
  누르면 어떻게 되는가? 새로 다시 읽지 않고 진행 중이던 읽기를 그대로 이어
  받는다(FR-006a) — 사용자에게는 대기가 조금 더 이어지는 것으로만 보이고,
  사진 읽기가 두 번 동시에 돌지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 사용자가 캐릭터와 날짜를 고른 뒤, 아직 일기 쓰기를
  누르기 전인 대기 시점에 다음 생성을 위한 준비를 미리 시작할 수 있어야
  한다(MAY, 사용자가 명시적으로 요청한 동작이 아니라 시스템이 스스로 판단해
  수행한다).
- **FR-002**: 이 준비 동작은 일기의 내용·분량·말투·판정 결과를
  조금도 바꾸지 않아야 한다(MUST) — 오직 완성까지 걸리는 시간만 달라진다.
- **FR-003**: 이 준비 동작은 그 자체로 어떠한 글도 사용자에게 노출해서는 안
  된다(MUST NOT) — 준비 중 생성되는 어떤 중간 산출물도 화면·저장소·로그
  어디에도 나타나지 않는다.
- **FR-004**: 이 준비 동작은 사진을 읽는 과정과 동시에 진행되어서는 안
  된다(MUST NOT) — 하나가 끝난 뒤에만 다른 하나가 시작된다. (근거: 헌법이
  이미 정한 "한 번에 하나의 추론 엔진만 연다"는 제약.)
- **FR-005**: 읽을 사진이 없는 날에 한해, 사용자가 캐릭터와 날짜를 고른 뒤
  곧바로 준비를 시작할 수 있어야 한다(MUST, 이 기능의 1단계 범위).
- **FR-006**: 읽을 사진이 있는 날에는, 사진 내용을 먼저 다 읽어 그 결과를
  확보한 뒤에만 준비를 시작해야 한다(MUST, 이 기능의 2단계 범위) — 사진
  읽기와 준비 과정이 겹치지 않게 순서를 지킨다.
- **FR-006a**: 사진 내용을 미리 읽는 과정이 아직 끝나지 않은 상태에서
  사용자가 일기 쓰기를 누르면, 시스템은 새로 처음부터 다시 읽지 않고
  진행 중이던 읽기가 끝나기를 기다린 뒤 그 결과를 이어서 사용해야
  한다(MUST) — 별도의 두 번째 사진 읽기를 동시에 시작하지 않는다.
- **FR-007**: 준비 동작이 실패하거나 아직 끝나지 않은 상태에서 사용자가
  일기 쓰기를 누르면, 시스템은 오류를 보이지 않고 처음부터 정상적으로 일기를
  생성해야 한다(MUST) — 준비가 없었을 때와 같은 결과가 나오되, 다만 그만큼
  더 걸릴 뿐이다.
- **FR-008**: 사용자가 캐릭터·날짜 선택 화면을 벗어나면(다른 화면으로
  전환, 앱이 백그라운드로 감), 시스템은 그 시점까지 미리 준비해 둔 내부
  상태를 놓아주어야 한다(MUST) — 화면을 벗어난 채로 자원을 계속 붙잡고
  있지 않는다.
- **FR-009**: 사용자가 고른 날짜가 바뀌면, 이전 날짜를 위해 미리 읽어 둔
  사진 내용은 폐기되어야 하며, 새로 고른 날짜의 일기에 섞여 들어가서는
  안 된다(MUST NOT).
- **FR-010**: 사진을 미리 읽어 둔 결과를 사용해 일기를 생성한 경우, 시스템은
  그 생성 과정에서 "사진을 읽는 데 걸린 시간"을 별도로 기록하지 않아야
  한다(MUST NOT) — 그 호출에서는 사진을 읽지 않았으므로 걸리지 않은 일을
  걸린 것처럼 기록하지 않는다. 반면 "글을 쓰는 데 걸린 시간"은 이전과
  동일한 방식으로 계속 기록되고 사용자에게 보여야 한다(MUST).
- **FR-011**: 이 기능은 어떤 형태로도 모델 식별자, 내부 처리 단계 이름,
  성능 수치를 사용자 화면에 노출해서는 안 된다(MUST NOT) — 사용자가 보는
  것은 오직 "완성까지 걸린 시간이 줄었다"는 체감뿐이다.
- **FR-012**: 이 기능은 여러 차례의 생성을 비교하거나, 평균 내거나,
  순위를 매기거나, 성능을 자동으로 채점하는 어떠한 기록도 남기지 않아야
  한다(MUST NOT).

### Key Entities

- **준비 상태(prepared state)**: 사용자가 캐릭터와 날짜를 고른 뒤, 일기 쓰기를
  누르기 전 대기 시간 동안 시스템 내부에 만들어지는 임시 상태. 어떤 캐릭터를
  위한 것인지와 연결되어 있으며, 화면을 벗어나거나 캐릭터·날짜가 바뀌면
  사라진다. 사용자에게 직접 보이지 않는다.
- **미리 읽은 사진 내용**: 사용자가 사진이 있는 날을 고른 뒤 일기 쓰기를
  누르기 전에 미리 확보해 둔, 그 날짜 사진들의 내용 요약. 어떤 날짜의 것인지와
  연결되어 있으며, 날짜가 바뀌면 폐기된다. 기존에 일기 생성 도중 만들어지던
  것과 같은 성격의 데이터이며, 다만 만들어지는 시점만 앞당겨진다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사진이 없는 날에 사용자가 캐릭터·날짜를 고르고 잠시(수 초 이상)
  머문 뒤 일기 쓰기를 누르면, 완성까지 걸리는 시간이 이 변경 전보다 뚜렷하게
  줄어든다(전후 비교에서 매번 확인 가능한 수준으로).
- **SC-002**: 사진이 있는 날에 같은 조건으로 비교했을 때, 완성까지 걸리는
  전체 시간(사진 읽기 + 글쓰기)이 이 변경 전보다 뚜렷하게 줄어든다.
- **SC-003**: 이 변경 전후로 같은 조건(같은 캐릭터, 같은 신호)에서 생성된
  일기의 내용·분량·말투에 시스템적인 차이가 없다 — 달라지는 것은 대기 시간
  뿐이라는 것을 사용자가 체감할 수 있다.
- **SC-004**: 미리 준비하는 동작이 실패하거나 아직 끝나기 전에 사용자가
  일기 쓰기를 눌러도, 100%의 경우 일기가 정상적으로 완성된다(오류 화면이나
  멈춤이 나타나지 않는다).
- **SC-005**: 캐릭터·날짜 선택 화면을 오래 벗어났다가 돌아와도, 다른 앱이나
  기능이 자원 부족으로 영향받는 사례가 없다.

## Assumptions

- 이 기능은 새로운 사용자 기능이 아니라 기존에 이미 존재하는 "일기 쓰기"
  흐름의 체감 속도를 개선하는 것이다. 화면에 새 버튼이나 설정이 추가되지
  않는다.
- 사용자가 캐릭터와 날짜를 고른 뒤 일기 쓰기를 누르기까지 어느 정도(수 초
  이상)의 자연스러운 대기가 있다는 것을 전제로 한다 — 고르자마자 즉시 누르는
  경우에는 이 기능의 효과가 온전히 나타나지 않을 수 있으며, 이는 실패가
  아니라 준비 시간이 부족했던 것뿐이다.
- "사진을 읽어야 하는 날인가"의 판단 기준은 기존에 일기 생성 시점에 쓰이던
  기준과 동일한 것을 그대로 재사용한다 — 이 기능을 위해 별도의 새로운 판단
  기준을 만들지 않는다.
- 이 기능은 2단계로 나뉘어 순차 적용될 수 있다: 먼저 사진이 없는 날에만
  적용하고(위험이 적음), 이어서 사진이 있는 날까지 확장한다(효과가 더 크지만
  범위가 넓음). 두 단계 모두 이 스펙 하나가 포괄하며, 별도 스펙으로 나누지
  않는다.
- 성능 확인은 화면에 이미 표시되는 "작성하는 데 걸린 시간"을 사람이 직접
  여러 차례 비교해 읽는 방식으로 충분하며, 이를 위한 별도의 자동 측정·기록
  코드는 만들지 않는다(헌법 원칙 IV).
