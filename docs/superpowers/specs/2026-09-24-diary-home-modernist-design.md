# 일기 홈 Modernist 이관 — 설계 (로드맵 31번)

- 날짜: 2026-09-24
- 상태: 048로 구현 완료(`specs/048-diary-home-modernist/`)
- 참조 디자인: 리뷰 보드 `1d`("Day-first — one date fills the screen") — 원본 위치는
  `docs/roadmap/README.md` 「참고 — 디자인 리뷰 보드」 절. `1e`(포스터)는 채택하지 않았다.
- 대상: `App.tsx`(탭 구조), `src/ui/DiaryListScreen.tsx`, `src/ui/DayPicker.tsx`,
  `src/ui/DiaryHomeScreen.tsx`, `src/app/state.ts`, `src/app/wiring.ts`

## 왜 로드맵 31번 그대로가 아닌가

로드맵 31번은 「상단 날짜 선택 바 + 쓰기 버튼 영역 + 카드 목록」을 지금 구조 위에서 모양만
바꾸는 것으로 적혀 있었다. 그러나 `1d`는 **화면 위쪽 400px를 날짜가 꽉 채우고 하단에 CTA 바가
고정된** 구조라, 지금 앱의 **맨 위 「일기 · 설정 · 개발자」 탭 줄**(`App.tsx`)과 공존할 수 없다.
그래서 이 설계는 **화면 이동 구조를 함께 바꾼다.**

## 1. 화면 구조

```
홈(루트) ──⋯──▶ 설정(하위)   ──뒤로──▶ 홈
          └──▶ 개발자(하위, local·dev만) ──뒤로──▶ 홈
홈 ──카드──▶ 일기 상세(기존) / 홈 ──일기 쓰기──▶ 덮어쓰기 확인(012) ▶ 쓰는 중(기존)
```

- `App.tsx`의 `tab` 상태(`"diary" | "characters" | "settings" | "developer"`)를
  `"home" | "settings" | "developer"` 화면 상태로 바꾼다. 탭 줄 JSX와 `styles.tabs` 계열을 지운다.
- 설정·개발자 화면 상단에 「← 일기」 되돌아가기가 있고, 안드로이드 뒤로 가기(`BackHandler`)도
  같은 일을 한다. 홈에서 뒤로 가기는 지금처럼 OS에 맡긴다.
- **개발자 항목은 prod에서 메뉴에 존재하지 않는다**(FR-024·SC-013 계승) — 숨김이 아니라 항목이
  없다. `showsDiagnostics` 조건 그대로.
- 기존에 `setTab("settings")`를 부르던 자리(029 `onGoToSettings`)는 설정 화면을 여는 것으로 바뀐다.
- 알림 라우팅(020 `pendingRoute` → 상세 직행)과 040 `autoGeneratedToken` 재마운트는 홈에 그대로 붙는다.
- 새 내비게이션 라이브러리를 들이지 않는다 — 지금처럼 상태 하나로 가른다(006 관례).

## 2. 헤더 (`1d`)

위에서 아래로:

1. **월 표시**(빨강, 예: 「2026년 9월」)와 우상단 표지 「일기」.
2. **고른 날**: 큰 숫자(일), 요일, 상태 한 줄.
   - 일기 없음: 「아직 쓰지 않았어요」
   - 일기 있음: 「이미 썼어요 · 다시 쓰면 덮어써요」(012 덮어쓰기 사전 고지를 여기로 옮긴다)
3. **7칸 스트립** — 오늘로 끝나는 7일(요일 머리 + 날짜 숫자 + 점).
   - 선택 칸: 빨간 배경.
   - 쓴 날: 빨간 점(7칸 전부에 표시 — 읽기 전용 정보).
   - **누를 수 있는 칸**: `selectableDays(now)`의 셋 + **정오 전이면 오늘**. 나머지는 흐리고 눌리지 않는다.
   - 흐린 칸에 쓴 날이 있어도 누르면 아무 일도 없다 — 읽기는 아래 목록이 맡는다.
   - 칸마다 `testID="day-<YYYY-MM-DD>"`(기존 `DayPicker` testID 계승).
4. **안내 캡션**(있을 때만) — 되돌림(009 `revertedFrom`), 캐릭터 옮김(029 `movedNotice`),
   거부 권한(021 `deniedNotices`). 해요체로 다시 쓴다.
5. **신호 줄** — 세 칸.

| 칸 | 값 | 없음 | 모름 | 읽는 중 |
| --- | --- | --- | --- | --- |
| 사진 | `photos.value.photos.length` | 「없음」 | 「모름」 | 「…」 |
| 다닌 자리 | `places.value.trace.visitCount` | 「없음」 | 「모름」 | 「…」 |
| 쓸 수 있는 때 | 「지금」 / 「오후 12시부터」 | — | — | — |

- 「없음」과 「모름」을 서로 다른 글자로 둔다(원칙 V). 0을 기본값으로 채우지 않는다(FR-003).
- 신호 줄은 언제나 **「지금 쓰면 볼 것」**이다. 이미 쓴 날도 지금 기기에서 다시 읽은 값을 보인다.
  그 일기가 실제로 본 것은 상세 화면(017 「이 일기가 본 것」)이 맡는다 — 줄의 뜻이 하나로 유지된다.
- 「오후 12시부터」의 12는 `WRITABLE_FROM_HOUR`에서 온다. 화면 소스에 숫자 12를 적지 않는다.
- 정오 전의 오늘도 신호 줄을 채운다(그 시각까지의 사진).

## 3. 목록

- 머리: 「최근」 + 「n편」.
- **모든 일기**를 싣는다(보드의 3편은 프레임 크기 때문). 헤더와 목록이 함께 스크롤되고 하단 바만 고정된다.
- 카드: 회색 사진 더미 + 빨간 장수 배지(`PhotoHint.known.count`) / 「2026 · 09 · 12 · 금」 / 제목.
  - 사진 없음·모름: 빈 테두리 사각형, 배지 없음. 대신 날짜 줄 끝에 「사진 없음」 / 「사진 모름」을
    적어 **둘을 구분한다**(007 FR-018·019, 원칙 V — 지금 목록이 지키는 구분을 잃지 않는다).
  - 실제 사진 썸네일은 쓰지 않는다(목록 항목이 사진 경로를 갖지 않는다 — 범위 밖).
  - 제목이 없으면(014 `title: undefined`) 날짜만. 읽을 수 없는 일기는 제목 자리에 「읽을 수 없어요」.
  - `onOpen(item)` 동작·testID 불변.
- 빈 목록: 무엇을 하면 생기는지 말한다(006 S7) — 「위에서 하루를 고르고 「일기 쓰기」를 누르면
  휴대폰이 그 하루를 일기로 써요」.

## 4. 하단 바

- 쓸 수 있는 날: `[⋯] [일기 쓰기 │ 13일]`
  - 「13일」은 **누를 수 없는 글자**. 화살표·드롭다운 없음.
  - `onWrite`는 인자를 받지 않는다(006 S1). 이미 쓴 날이면 기존대로 덮어쓰기 확인(012)을 거친다.
- 정오 전의 오늘: `[⋯] 오늘 일기는 오후 12시부터 쓸 수 있어요` — 버튼이 없다(비활성 버튼도 아니다).
- `⋯` 메뉴: CTA와 같은 높이의 정사각, 잉크 테두리(빨강 아님). 누르면 위로 펼치는 목록 —
  「설정」, 「개발자」(local·dev만). 바깥을 누르거나 뒤로 가기로 닫힌다. 새 네이티브 의존성 없이
  코어 RN(`Modal` 또는 절대 배치 `View`)으로 만든다.

## 5. 상태와 판정 (계약 변경)

### 5.1 `writePromptFor()` — 「볼 수 있다」와 「쓸 수 있다」를 가른다

- `SelectableDay`에 `writable: boolean`을 더한다. `selectable` 배열은
  `selectableDays(now)`(모두 `writable: true`) + **정오 전이면 오늘**(`writable: false`)이다.
- `WritePrompt`에 `writable: boolean`을 더한다 — 고른 날의 것.
- 009 불변식 I1 「`day`는 반드시 `selectable` 안에 있다」는 그대로 참이다. 다만 `selectable`의 뜻이
  「스트립에서 고를 수 있는 칸」으로 넓어지고, 쓸 수 있는지는 `writable`이 따로 말한다.
- 기본 선택(D9)은 `writable: true`인 첫 날(지금의 `days[0]`)이다. 정오 전 오늘은 사용자가 고를 때만 선택된다.
- 판정은 여전히 `day-boundary.ts`의 `isDayWritable()` 한 곳. `state.ts`는 그것을 부를 뿐이다.
- 되돌림(009 FR-009a)은 그대로 매 렌더 재판정. 「쓸 수 없는 오늘」은 04:00~12:00에만 존재하므로
  그것을 보는 동안 04:00을 넘기는 일은 없다 — 이 칸이 겪는 경계는 12:00(아래 5.3) 하나뿐이다.

### 5.2 쓰기 방어는 세 겹

1. 화면: `writable === false`면 CTA 버튼이 렌더되지 않는다.
2. 파이프라인: `pipeline.run()`의 기존 `isDayWritable` 게이트(012)가 그대로 막는다.
3. 계약 테스트: 소스를 읽어 「`writable`이 거짓인 갈래에 `onWrite`가 닿지 않는다」를 잠근다.

### 5.3 정오 경계 전환

- 오늘(쓸 수 없음)을 보고 있는 동안에만 **다음 12:00에 한 번 울리는 타이머**를 건다. 울리면 다시
  렌더해 CTA가 나타난다. 화면을 떠나거나 다른 날을 고르면 지운다.
- `AppState`가 `active`로 돌아올 때도 다시 판정한다(잠든 동안 타이머가 밀리는 경우).
- 이것으로 012가 「실기기 미확인」으로 남긴 정오 경계 갱신 갈래를 닫는다.

### 5.4 018 미리 준비

- 고른 날이 `writable === false`면 `prepare()`·`captionDay()`를 부르지 않는다(쓸 수 없는 날에 VLM을
  돌리지 않는다). 쓸 수 있는 날로 바꾸면 지금처럼 시작한다.

## 6. 신호 미리보기 배선 (선택지 A)

- `wiring.ts`에 `previewDay(day): Promise<DayPreview>`를 새로 둔다. 004의 `collectDaySignals()`를
  그대로 부르고, 결과를 **숫자로 좁힌다**:

  ```ts
  // src/app/state.ts (화면이 import 가능한 쪽)
  export type CountHint = { kind: "known"; count: number } | { kind: "none" } | { kind: "unknown" };
  export type DayPreview = { photos: CountHint; places: CountHint };
  ```

- **화면은 `DaySignals`를 모른다**(009 이후 경계 유지) — `DayPreview`만 받는다. 좁히는 함수는 순수
  함수로 `state.ts` 또는 `app/` 안에 두고 단위 테스트한다.
- 날이 바뀔 때마다 부른다. 늦게 도착한 이전 날의 결과는 버린다(요청한 날과 대조).
- 실패(예외)는 두 칸 모두 「모름」.
- 캡션 경로(`captionDay`)와 미디어 라이브러리를 두 번 읽는다 — 느리다는 실측이 생기기 전에는 캐시를
  두지 않는다(선택지 C는 보류).
- 데스크톱(`local`) 경로에서도 같은 함수가 돈다(`loadSignals` 주입 재사용).

## 7. 범위 밖

- 쓰는 중 화면, 일기 상세, 설정 화면 **내부**는 건드리지 않는다. 이번에 바뀌는 것은 설정·개발자로
  **들어가는 길**뿐이다.
- 실제 사진 썸네일, 신호 캐시, 다국어.

## 8. 검증

- 기기 없는 테스트
  - `writePromptFor()`: 정오 전/후 × 오늘 선택/미선택 × 04:00 넘김, `writable` 값, 기본 선택(D9).
  - `DayPreview` 좁히기: known/none/unknown/예외.
  - 화면: 스트립 칸의 눌림 가능 여부, CTA ↔ 안내 문구 교체, CTA 날짜에 누름 핸들러가 없음,
    메뉴 항목(prod에서 개발자 없음), 신호 칸의 「없음」·「모름」·「…」.
  - 정오 타이머: 가짜 시계로 12:00 전환.
  - 위반 주입: `writable: false`인데 CTA 렌더 / 화면이 `DaySignals` import / 화면 소스에 12 하드코딩.
- Maestro — 「설정」 탭을 눌러 들어가던 흐름을 `⋯` → 「설정」 경로로 고친다:
  `diary-body-screen`, `diary-character-select`, `diary-user-path`, `download-conflict`,
  `model-acquisition`, `parallel-model-download`, `photo-selection-over-limit`, `photo-vision`,
  `scheduled-diary-notification`, `welcome-naming`. 「개발자」 탭을 누르던 흐름(`skeleton`,
  `prompt-preview` 등)도 같다. `parallel-model-download`·`download-conflict`는 기존의 알려진 실패
  (037·026)임을 유지한다.
- 실기기(dev) — 정오 전 오늘 선택 → 안내 문구 → 12:00 전후 전환(가능하면), 신호 줄 숫자가 합성 하루
  (010 `seed:day`)의 장수와 일치, 메뉴 → 설정 → 뒤로 가기 복귀.
