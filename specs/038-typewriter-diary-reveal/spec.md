# Feature Specification: 완성된 일기 첫 표시를 타자기 연출로

**Feature Branch**: `038-typewriter-diary-reveal`

**Created**: 2026-09-11

**Status**: Draft

**Input**: User description: "23 완성된 일기 첫 표시를 타자기 연출로"

## 배경

지금은 홈에서 "일기 쓰기"를 누르면 회전 표시 + 독백 한 줄(생성 중 화면)만 보다가,
생성·판정·저장이 모두 끝나면 **일기 전문이 한 번에** 나타난다. 사용자는 그
"완성의 순간"을, 저장된 본문이 **타자기처럼 글자 단위로 흐르는** 연출로 바꾸고
싶어 한다("클로드 코드가 답을 글자씩 흘려보내는 것처럼").

이 연출은 헌법이 금지하는 대상이 아니다 — 원칙이 막는 것은 *생성 중인 글*을
보여주는 것(005 FR-028b, 생성 중 화면은 회전 표시만)이고, 이 연출은 이미
**생성 완료·4갈래 판정 통과·저장까지 끝난** 본문 문자열을 잘라 순차로 드러내는
것이다. 다만 타자기가 "실시간으로 쓰는 중"처럼 *보이면* "생성 중엔 회전 표시만"
경계를 화면상 흐리므로, 생성 중 화면과 이 연출은 명확히 다른 상태로 유지한다.

  탭하면 건너뛰기로 동작해야 하나? → A: 제목·본문·하단 절이 전부 나타나기 전이면
  경계 구간 포함 어느 시점의 탭이든 건너뛰기로 동작한다(완료 전 = 건너뛰기,
  완료 후 = 아님).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 생성 직후 첫 일기가 타자기로 드러난다 (Priority: P1)

일기 생성이 끝나 첫 표시로 넘어가는 순간, 제목이 한 글자씩 나타나고 이어서
본문이 한 글자씩 흐른다. 본문 타이핑이 끝나면 그 아래 "이 일기가 본 것" 절(사진·
장소명·소요 시간)과 사진 슬라이더가 나타난다. 그 화면은 그대로 일기 상세 화면이
되며 별도 화면 전환은 없다.

**Why this priority**: 이 스토리가 곧 기능 전체다. 이것 하나만 구현해도
"완성의 순간" 연출이라는 사용자 가치가 온전히 전달된다.

**Independent Test**: 일기를 하나 생성하고 첫 표시 화면에서 제목·본문 글자가
시간에 따라 늘어나는지, 타이핑이 끝난 뒤에만 하단 절과 슬라이더가 보이는지
확인한다.

**Acceptance Scenarios**:

1. **Given** 일기 생성·판정·저장이 방금 끝났고 첫 표시 화면이 열렸다, **When**
   화면이 그려진다, **Then** 제목이 빈 상태에서 시작해 글자 단위로 채워진다.
2. **Given** 제목 타이핑이 끝났다, **When** 계속 기다린다, **Then** 본문이
   글자 단위로 흐르기 시작한다.
3. **Given** 본문 타이핑이 진행 중이다, **When** 아직 끝나지 않았다, **Then**
   "이 일기가 본 것" 절과 사진 슬라이더·갤러리는 화면에 없다.
4. **Given** 본문 타이핑이 끝났다, **When** 마지막 글자가 나타난다, **Then**
   "이 일기가 본 것" 절과 (사진이 있으면) 사진 슬라이더가 나타난다.
5. **Given** 타이핑이 전부 끝난 화면이다, **When** 사용자가 그 화면을 본다,
   **Then** 그 화면은 목록에서 일기를 연 것과 동일한 상세 화면이다(별도 전환 없음).

---

### User Story 2 - 화면을 탭하면 즉시 전체가 드러난다 (Priority: P1)

타이핑이 도는 동안 화면 아무 곳이나 탭하면 제목·본문이 즉시 전부 나타나고
하단 절과 슬라이더도 바로 등장한다. 기다리기 싫은 사용자를 붙잡지 않는다.

**Why this priority**: 연출이 사용자를 가두면 안 된다. 건너뛰기 없이는
"드러남"이 "기다림"이 된다.

**Independent Test**: 타이핑 도중 화면을 탭하고, 제목·본문 전문과 하단 절이
즉시 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 제목·본문·하단 절이 아직 전부 나타나지 않았다(제목 타이핑 중,
   제목→본문 전환 순간, 본문 타이핑 중, 본문 종료 후 하단 절 등장 직전 중 어느
   시점이든), **When** 사용자가 화면 아무 곳이나 탭한다, **Then** 제목·본문이
   즉시 전부 표시된다.
2. **Given** 탭으로 연출을 건너뛰었다, **When** 화면이 갱신된다, **Then**
   "이 일기가 본 것" 절과 사진 슬라이더가 즉시 나타난다.
3. **Given** 제목·본문·하단 절이 모두 나타난 화면이다, **When** 사용자가 화면을
   탭한다, **Then** 건너뛰기 동작은 일어나지 않는다(사진 슬라이더·갤러리 탭 등
   기존 상호작용은 정상 동작).

---

### User Story 3 - 나중에 목록에서 다시 열면 즉시 전체 (Priority: P1)

목록에서 이미 쓴 일기를 다시 열면 타이핑 연출 없이 즉시 전문이 보인다. 연출은
생성 직후 첫 표시에서만 재생된다.

**Why this priority**: "완성의 순간"은 한 번뿐이다. 매번 재생하면 소음이 되고
일기를 다시 읽으려는 사용자를 방해한다.

**Independent Test**: 일기를 생성해 첫 표시에서 연출을 보고, 뒤로 나갔다가
목록에서 같은 일기를 다시 열어 연출 없이 즉시 전문이 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 목록에 이미 저장된 일기가 있다, **When** 사용자가 그 일기를 연다,
   **Then** 제목·본문이 처음부터 전부 보인다(타이핑 없음).
2. **Given** 생성 직후 첫 표시에서 연출을 봤다, **When** 뒤로 나가 목록에서
   같은 일기를 다시 연다, **Then** 연출이 재생되지 않는다.
3. **Given** 첫 표시 화면이다, **When** 타이핑 도중 뒤로 나갔다가 목록에서 그
   일기를 연다, **Then** 즉시 전문이 보인다(중단된 타이핑을 이어서 재생하지 않는다).

---

### Edge Cases

- **제목이 없는 일기**(판정은 통과했으나 제목을 못 뗌, 014): 제목 줄 자체가
  없으므로 본문 타이핑부터 시작한다.
- **본문이 매우 짧은 일기**(신호 없는 날의 몇 문장): 타이핑이 순식간에 끝나고
  바로 하단 절이 나타난다 — 정상.
- **본문이 매우 긴 일기**: 글자 수에 비례해 타이핑이 길어진다. 사용자는 언제든
  탭으로 건너뛸 수 있다(US2).
- **이모지·서로게이트 쌍·한글 완성 글자**: 글자 경계에서 깨지지 않게 잘린다
  (반쪽 글자가 화면에 나타나지 않는다).
- **저장 실패한 일기 첫 표시**(`saved: false`): "저장하지 못했다..." 안내는
  타이핑과 무관하게 지금처럼 보인다 — 이 안내는 본문 아래에 있으나 사용자가
  즉시 알아야 하는 정보다. 타이핑 완료를 기다리지 않고 표시한다.
- **덮어쓴 일기 첫 표시**(`overwrote: true`): "이전 일기를 덮어썼다" 안내도
  마찬가지로 타이핑과 무관하게 표시한다.
- **화면 회전·백그라운드 복귀 중 타이핑**: 앱은 세로 고정이라 회전은 재현
  불가(016 계열). 백그라운드에서 돌아왔을 때 타이핑이 어디까지 갔든 이어서
  진행하거나 완료 상태면 완료 유지 — 처음부터 다시 재생하지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 생성·판정·저장이 끝난 뒤의 **첫 표시**에서, 시스템은 일기 제목과
  본문을 글자 단위로 순차 노출해야 한다(MUST). 제목이 먼저 전부 노출된 뒤 본문이
  시작한다.
- **FR-002**: 제목이 없는 일기(014에서 제목을 못 뗀 경우)는 제목 줄 없이 본문
  타이핑부터 시작해야 한다(MUST).
- **FR-003**: 본문 타이핑이 완료되기 전에는 "이 일기가 본 것" 절(사진 수·장소명·
  소요 시간)과 사진 슬라이더·갤러리가 화면에 나타나지 않아야 한다(MUST).
- **FR-004**: 본문 타이핑이 완료되면 "이 일기가 본 것" 절과 (사진이 있으면) 사진
  슬라이더가 나타나야 한다(MUST). 이후 화면은 목록에서 연 상세 화면과 동일하다.
- **FR-005**: 제목·본문·하단 절이 **전부 나타나기 전**의 어느 시점에서든(제목
  타이핑 중, 제목→본문 전환 순간, 본문 타이핑 중, 본문 종료 후 하단 절 등장
  직전 포함) 사용자가 화면 아무 곳이나 탭하면, 제목·본문이 즉시 전부 표시되고
  하단 절·슬라이더가 즉시 나타나야 한다(MUST).
- **FR-006**: 제목·본문·하단 절이 **모두 나타난 뒤**의 화면 탭은 건너뛰기로
  동작하지 않아야 한다(MUST) — 사진 슬라이더·갤러리 등 기존 상호작용은 정상
  동작한다. 즉 판정 기준은 단일하다: 연출 완료 전 = 건너뛰기, 완료 후 = 아님.
- **FR-007**: 목록에서 이미 저장된 일기를 여는 경우(첫 표시가 아닌 경우)에는
  타이핑 연출 없이 제목·본문이 즉시 전부 표시되어야 한다(MUST). 이 경로의 화면
  동작은 이 기능 도입 전과 100% 동일하다.
- **FR-008**: 첫 표시에서 타이핑 도중 화면을 벗어난 뒤 목록에서 같은 일기를 다시
  열면, 중단된 지점을 이어서 재생하지 않고 즉시 전문을 보여야 한다(MUST).
- **FR-009**: 글자 단위 노출은 이모지·서로게이트 쌍·결합 문자 경계에서 반쪽
  글자가 화면에 나타나지 않도록 안전하게 잘라야 한다(MUST).
- **FR-010**: 타이핑 속도(글자당 시간)는 한 곳의 상수로 관리되어야 하며(MUST),
  나중에 조정 가능해야 한다. 기본값은 빠른 편("기다림"보다 "드러남"에 가깝게)으로
  한다.
- **FR-011**: 생성 중 화면(회전 표시 + 독백 한 줄)은 이 기능으로 바뀌지 않아야
  한다(MUST) — 회전 표시, "그만두기" 버튼, 진행률 숫자·경과 시간·생성 중인 글
  미노출이 그대로다.
- **FR-012**: "저장하지 못했다..."(`saved: false`)와 "이전 일기를 덮어썼다"
  (`overwrote: true`) 안내는 타이핑 완료를 기다리지 않고 표시되어야 한다(MUST).
- **FR-013**: 타이핑 연출은 일기 생성 파이프라인·판정·저장·저장 데이터 모양에
  영향을 주지 않아야 한다(MUST NOT change). 새로 저장되는 필드가 없다.
- **FR-014**: 화면을 벗어날 때(뒤로 가기, 앱 백그라운드) 진행 중이던 타이핑이
  자원을 계속 소비하지 않아야 한다(MUST) — 타이머·상태가 정리된다.

### Key Entities

이 기능은 새 데이터를 저장하지 않는다. 관련되는 것은 이미 존재하는
`DiaryEntry`(제목·본문·신호·타이밍·사진)의 **읽기 전용 소비**뿐이다. 첫 표시인지
여부는 화면 계층의 일시 상태이며 파일에 남기지 않는다(009·025 선례).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 일기 생성 직후 첫 표시에서, 사용자는 제목과 본문이 글자 단위로
  나타나는 것을 눈으로 확인할 수 있다(실기기 육안).
- **SC-002**: 본문 타이핑이 도는 동안 "이 일기가 본 것" 절과 사진 슬라이더는
  화면에 존재하지 않으며, 타이핑 완료 직후 나타난다(실기기 육안 + 계약 테스트).
- **SC-003**: 타이핑 도중 화면을 한 번 탭하면 1초 이내에 제목·본문 전문과 하단
  절이 모두 표시된다.
- **SC-004**: 목록에서 기존 일기를 여는 경로는 이 기능 도입 전후로 화면 표시가
  동일하다(회귀 없음) — 기존 상세 화면 계약 테스트와 Maestro 흐름이 무수정
  통과한다.
- **SC-005**: 생성 중 화면(회전 표시)에는 이 기능 도입 후에도 진행률 숫자·경과
  시간·생성 중인 본문 글자가 하나도 나타나지 않는다(계약 테스트가 금지어 개수를
  센다, 기존 SM3 계열).
- **SC-006**: 일기 생성 파이프라인·판정 4갈래·저장 파일 스키마에 변경이 없다
  (`git diff`로 `src/diary/`·`src/inference/`·`src/vision/` 0줄, 계약 테스트가
  파이프라인 시그니처를 소스로 잠근다).

## Assumptions

- **연출 방식은 타자기**(글자가 하나씩 흐름)로 확정한다 — 문단 페이드인·전체
  슬라이드인은 채택하지 않는다(2026-09-08 브레인스토밍).
- **흘릴 범위는 제목 + 본문**뿐이다. 날짜 캡션, "이 일기가 본 것" 절, 사진
  슬라이더·갤러리는 타이핑 대상이 아니라 타이핑 완료 후 등장한다.
- **속도는 글자당 약 15ms**(빠름)를 기본값으로 하고 상수 한 곳에 둔다 — 이후
  실기기 육안으로 조정 가능.
- **노출 시점은 생성 직후 첫 표시만**이다. 목록에서 다시 여는 경우는 즉시 전체이며
  재생하지 않는다.
- 이 기능은 화면 표시 계층 안에서 완결된다 — 일기 저장 데이터·파이프라인·판정을
  건드리지 않는다(025 갤러리와 같은 성격).
- 새 네이티브 모듈이 필요 없으므로, 실기기 검증은 dev(debug) 1회로 충분하다는
  프로젝트 기준(012, AGENTS.md "테스트" 절)을 따른다.
