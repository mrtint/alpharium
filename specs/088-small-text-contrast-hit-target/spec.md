## Clarifications

### Session 2026-10-17 (brainstorming)

- Q: 밝은 배경 위 작은 강조 글자 다섯 자리(홈 월 라벨·쓰는 중 상태 줄·쓰는 중 머리말·작명 표지·설정 묶음 머리)의 색상을 보드 원문(`COLORS.accent`, 대비 3.76~3.85:1) 그대로 둘지, 대비 이유로 `COLORS.danger`(`#ae1800`, 대비 6.41~6.56:1)로 바꿀지? → A: 다섯 자리 모두 `COLORS.danger`(`#ae1800`)로 바꾸고 `src/ui/` 안에서 `COLORS.accent`를 글자 스타일 색으로 쓰는 일이 0건임을 소스 계약으로 잠근다(보드 1d·2b·1a·6a/6c 이탈 승인).
- Q: 주간 스트립(`DayPicker`) 요일 약자의 보드 1d 불투명도(`opacity: 0.7`) 제거와 글자 크기(10pt) 변경 범위를 어떻게 할지? → A: 요일 약자의 `opacity: 0.7`을 걷고 색상(선택 칸 `COLORS.accentForeground` `#f3f2f2` 3.76:1, 비선택 칸 `#5f5e5d` 5.79:1)으로 바꾸며, 글자 크기(10pt)는 그대로 둔다(보드 1d 불투명도 이탈 승인).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 밝은 배경 위 작은 강조 라벨이 또렷하게 읽힌다 (Priority: P1)

사용자가 홈(월 라벨·쓰는 중 상태 줄·쓰는 중 머리말), 첫 만남 작명 화면(표지), 설정·개발자·진단 화면(묶음 머리)을 볼 때, 밝은 배경 위의 11~13pt 강조 글자가 일반 글자 명암비 기준(4.5:1 이상)을 만족하는 진한 빨강(`#ae1800`)으로 그려져 화면 밝기를 낮춘 상태에서도 또렷하게 읽힌다.

**Why this priority**: 다섯 자리는 모두 11~13pt·600 굵기의 작은 글자로 WCAG 큰 글자 기준에 해당하지 않는데도 기존 강조색(`#ec3013`, 대비 3.76~3.85:1)을 써서 일반 글자 AA 기준(4.5:1)에 미달했다.

**Independent Test**: 홈(안 쓴 날·쓴 날·쓰는 중), 작명 화면, 설정·개발자·진단 화면을 열어 다섯 자리 글자색이 `#ae1800`이고 배경과의 상대 명암비가 4.5:1 이상인지 확인한다.

**Acceptance Scenarios**:

1. **Given** 사용자가 홈 화면을 보고 있다(안 쓴 날·쓴 날·쓰는 중), **When** 상단 월 라벨을 본다, **Then** 글자색이 진한 빨강(`#ae1800`)이고 홈 배경(`#f3f2f2`)과의 대비가 4.5:1 이상(6.41:1)이다.
2. **Given** 홈 화면이 「쓰는 중」 상태다, **When** 날짜 헤더의 「쓰는 중」 상태 줄과 지면의 머리말(「WRITING DIARY」)을 본다, **Then** 두 글자 모두 진한 빨강(`#ae1800`)이고 홈 배경과의 대비가 4.5:1 이상이다.
3. **Given** 사용자가 첫 만남 작명 화면을 보고 있다, **When** 상단 표지 문구를 본다, **Then** 글자색이 진한 빨강(`#ae1800`)이고 배경과의 대비가 4.5:1 이상이다.
4. **Given** 사용자가 설정·개발자·진단 화면을 열었다, **When** 각 묶음 머리 라벨을 본다, **Then** 글자색이 진한 빨강(`#ae1800`)이고 설정 지면 배경(`#f8f4f4`)과의 대비가 4.5:1 이상(6.56:1)이다.

### User Story 2 - 주간 스트립의 선택된 날과 선택되지 않은 날 요일이 모두 기준 대비를 지킨다 (Priority: P1)

사용자가 홈 주간 스트립에서 날을 고를 때, 선택된 칸(빨간 배경)의 요일 약자는 불투명도 감쇠 없이 오프화이트(`#f3f2f2`, 대비 3.76:1)로 그려져 3.0:1 대비 하한을 지키고, 선택되지 않은 칸의 요일 약자는 불투명 회색(`#5f5e5d`, 대비 5.79:1)으로 그려져 기존 시각 인상을 그대로 유지한다.

**Why this priority**: 기존에는 요일 약자에 일괄 `opacity: 0.7`이 걸려 선택된 빨간 칸 위에서 실효 대비가 2.44:1까지 떨어졌고, 불투명도 합성이라 토큰 대비 테스트가 이를 감지하지 못했다.

**Independent Test**: 홈 주간 스트립에서 선택된 칸과 선택되지 않은 칸의 요일 약자 색상을 확인하고, 요일 글자 스타일에 불투명도(`opacity`)가 쓰이지 않는지 검증한다.

**Acceptance Scenarios**:

1. **Given** 홈 주간 스트립에 7칸이 그려져 있다, **When** 선택된 칸의 요일 약자를 본다, **Then** 불투명도 없이 오프화이트(`#f3f2f2`)로 그려져 선택 칸 배경(`#ec3013`)과의 대비가 3.0:1 이상(3.76:1)이다.
2. **Given** 홈 주간 스트립에 7칸이 그려져 있다, **When** 선택되지 않은 과거·오늘 칸의 요일 약자를 본다, **Then** 불투명도 없이 `#5f5e5d`로 그려져 홈 배경(`#f3f2f2`)과의 대비가 4.5:1 이상(5.79:1)이고 기존 합성 색과 픽셀 단위로 같다.
3. **Given** 홈 주간 스트립에 미래 칸이 있다, **When** 미래 칸을 본다, **Then** 칸 전체의 비활성 불투명도(`0.3`)만 적용되고 요일 약자에 별도 불투명도가 겹치지 않는다.

---

### User Story 3 - 설정 토글의 위아래 가장자리를 눌러도 켜고 끌 수 있다 (Priority: P2)

사용자가 설정 화면의 「자동으로 쓰기」 토글이나 개발자 화면의 상태 흉내 토글을 누를 때, 시각 크기는 기존(44×26dp) 그대로이면서 위아래로 각 9dp씩 확장된 44×44dp 영역 안쪽 어디를 눌러도 토글이 동작한다.

**Why this priority**: 「자동으로 쓰기」 행은 행 자체에 누름 동작이 없고 높이 26dp인 토글만 눌려서 세로 터치 대상이 최소 권고 크기(44dp)보다 작았다.

**Independent Test**: 설정 화면과 개발자 화면에서 토글의 시각 크기(44×26dp)가 바뀌지 않았는지 확인하고, 토글 보이는 경계 위·아래 가장자리 바깥(슬롭 안쪽)을 탭해 토글 상태가 바뀌는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 설정 화면에 「자동으로 쓰기」 토글이 보인다, **When** 토글의 시각 크기와 누름 영역을 확인한다, **Then** 보이는 크기는 44×26dp이고 위·아래 각 9dp의 확장 누름 영역을 합쳐 세로 44dp가 된다.
2. **Given** 설정 화면의 「자동으로 쓰기」 토글이 꺼져 있다, **When** 사용자가 토글 위쪽 또는 아래쪽 가장자리에서 2dp 바깥(확장 누름 영역 안쪽)을 탭한다, **Then** 토글이 켜진다.
3. **Given** 설정 화면의 「자동으로 쓰기」 토글이 꺼져 있다, **When** 사용자가 확장 누름 영역(위·아래 9dp)보다 2dp 더 바깥을 탭한다, **Then** 토글이 바뀌지 않는다.

---

### Edge Cases

- ** 강조색(`#ec3013`)을 면이나 테두리·인디케이터로 쓰는 자리**: 하단 쓰기 바·스트립 선택 칸·대화상자 주 버튼·사진 배지·토스트 표식의 배경색, 설정 「허용 안 함」 꼬리표의 테두리(`SettingsScreen.tsx:448`), 첫 만남 확인 중 로딩 인디케이터(`WelcomeScreen.tsx:120`)는 글자가 아니므로 기존 `#ec3013`을 그대로 유지한다.
- **글꼴 크기 2.0배 확대**: 다섯 자리 강조 라벨과 주간 스트립 요일 약자는 색상만 바뀌고 크기·자간·행간·배치가 바뀌지 않으므로 글꼴 2.0배에서도 줄바꿈과 배치가 깨지지 않는다.
- **토글 아래 펼쳐지는 행과의 겹침**: 토글 세로 확장 영역(위·아래 9dp)은 부모 행 최소 높이(44dp) 안쪽에 정확히 들어맞으므로(`26 + 9 × 2 = 44`) 위·아래 이웃 행의 누름 영역을 침범하지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

**작은 강조 글자 대비 (UX-07)**

- **FR-001**: 홈 월 라벨, 홈 「쓰는 중」 상태 줄, 쓰는 중 지면 머리말, 첫 만남 작명 화면 표지, 설정·개발자·진단 화면의 묶음 머리 다섯 자리의 글자색은 진한 빨강(`#ae1800`, `COLORS.danger`)이어야 한다(MUST).
- **FR-002**: 사용자 화면 부품(`src/ui/`) 전체에서 기본 강조색(`#ec3013`, `COLORS.accent`)을 글자 스타일 색(`color`)으로 쓰지 않아야 한다(MUST NOT). 면(`backgroundColor`), 테두리(`borderColor`), 로딩 인디케이터 prop은 예외로 한다.
- **FR-003**: 진한 빨강(`#ae1800`)은 기본 배경(`#f3f2f2`) 및 쓴 날·설정 지면 배경(`#f8f4f4`) 모두와 4.5:1 이상의 상대 명암비를 만족해야 한다(MUST).

**주간 스트립 요일 약자 대비 (UX-08)**

- **FR-004**: 홈 주간 스트립의 요일 약자는 글자 스타일에 불투명도(`opacity`)를 쓰지 않고 명시적 색상으로만 그려야 한다(MUST).
- **FR-005**: 주간 스트립에서 선택된 칸의 요일 약자 색은 선택 칸 글자색(`#f3f2f2`, `COLORS.accentForeground`)이어야 하며, 선택 칸 배경(`#ec3013`)과 3.0:1 이상의 상대 명암비를 만족해야 한다(MUST).
- **FR-006**: 주간 스트립에서 선택되지 않은 칸의 요일 약자 색은 단일 출처 토큰에 정의된 불투명 상수(`#5f5e5d`, `DAY_STRIP.dowMuted`)여야 하며, 홈 배경(`#f3f2f2`)과 4.5:1 이상의 상대 명암비를 만족해야 한다(MUST). 전역 기본 색상 역할(`COLORS` 9개 키)에는 새 키를 추가하지 않는다(MUST NOT).
- **FR-007**: 주간 스트립 요일 약자의 글자 크기(10pt)와 자간(0.6)은 기존 값을 유지해야 한다(MUST).

**설정 토글 누름 영역 (UX-10)**

- **FR-008**: 설정 및 개발자 화면이 공용으로 쓰는 토글 부품은 시각 크기(44×26dp)를 바꾸지 않고 위·아래 각 9dp의 확장 누름 영역(`hitSlop`)을 가져 세로 누름 높이가 44dp가 되어야 한다(MUST).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 다섯 자리 작은 강조 글자(11~13pt·600)와 각 배경 사이의 WCAG 상대 명암비가 모두 4.5:1 이상(실제 6.41:1 및 6.56:1)이다.
- **SC-002**: 주간 스트립 요일 약자와 칸 배경 사이의 실효 상대 명암비가 선택 칸에서 3.0:1 이상(3.76:1), 비선택 칸에서 4.5:1 이상(5.79:1)이며, 글자 불투명도 합성이 0건이다.
- **SC-003**: 설정 토글의 세로 터치 반응 높이가 44dp(시각 높이 26dp + 위·아래 각 9dp)이고, 실기기에서 확장 영역 안쪽 탭으로 토글이 전환된다.
- **SC-004**: 단위·계약 테스트 전체 통과, 위반 주입(강조 글자 1곳을 `#ec3013`으로 되돌림, 요일 약자에 `opacity: 0.7` 복원) 시 테스트 실패 확인, 안드로이드 실기기(`SM-S901N` dev) 최저 밝기·글꼴 1.0/2.0배 육안 확인 및 Maestro 층 1(`settings-time-place`, `week-strip-swipe`) 통과를 완료한다.

## Assumptions

- 043에서 확정한 「강조 면(`#ec3013`) 위 오프화이트 글자(`#f3f2f2`, 3.76:1)」 결정은 그대로 유지하며, 그 반대 방향인 「밝은 배경 위 작은 강조 글자」만 진한 빨강(`#ae1800`)으로 바꾼다.
- 달력 대화상자의 이전·다음(`‹ ›`) 버튼(40×40dp)은 부모 머리 영역 높이(40dp)에 묶여 있어 레이아웃 크기 변경 없이 `hitSlop`만으로는 세로 확장이 되지 않으므로 이 스펙 범위에서 제외한다.
