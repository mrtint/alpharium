# Contract: 다시 걸기 (RA1~RA8)

`ReminderDeps.rearm?: RearmGate` (없으면 다시 걸기 없음 = 종전 동작).

- **RA1** `rearm.pending()`이 참이고 계획이 비어 있지 않으면, 같은 예약(id·at·title)이 이미 걸려 있어도 계획의 모든 항목을 `schedule`한다.
- **RA2** `pending()`이 거짓이면 종전처럼 차이만 고친다(같은 것은 `schedule`하지 않는다).
- **RA3** 소비(`done()`)는 모든 `schedule`이 성공한 맞추기에서만, 그리고 RA1 조건(계획 비지 않음)일 때만 부른다. `schedule` 하나라도 실패하면 부르지 않는다.
- **RA4** 설정·일기 목록·이름을 못 읽어 맞추기가 일찍 끝나면(RC6) `pending()`도 `done()`도 부르지 않는다. 꺼짐(계획 빔)이면 소비하지 않는다.
- **RA5** `scheduled()`가 던진 맞추기(목록 모름)도 계획 전부를 거는 맞추기이므로 RA3 조건이 같다.
- **RA6** 취소 규칙(쓴 날 거두기·RC8·104 지연 예약·트레이 거두기)은 다시 걸기와 무관하게 같다. 다시 걸기가 RC8/104 보존 예약을 취소하지 않는다.
- **RA7** 맞추기는 한 줄로 서므로(RC4) 거의 동시에 불려도 첫 맞추기는 한 번이다.
- **RA8** `expoReminderDeps`의 문은 프로세스 모듈 상태(overrides.rearmGate로 덮을 수 있다). `reminders.ts`는 프로세스 상태를 직접 읽지 않는다.
