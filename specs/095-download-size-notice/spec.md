# Feature Specification: 첫 실행 다운로드 크기 공지 — App Store 4.2.3(ii)

**Feature Branch**: `ccr-f53e093e-45ulrl` (스펙 번호 095 — 세션 규칙상 지정 브랜치를 그대로 쓴다)

**Created**: 2026-10-21

**Status**: Draft

**Input**: User description: "docs/superpowers/specs/2026-10-21-download-size-notice-design.md 를 입력으로 — 첫 실행 표준 다운로드 동의에 받을 양 공지(App Store 4.2.3(ii), C1)."

## 배경

App Store 심사 지침 4.2.3(ii)는 첫 실행에 추가 자원을 받아야 하면 받을 크기를 알리고 먼저 물으라고 한다. 지금 첫 실행의 표준 동의(연결이 Wi-Fi이거나 연결 종류를 모를 때)는 묻기는 하지만 받을 양을 보이지 않는다 — 045 FR-003이 일부러 정했다. 074 뒤로는 모바일 데이터로 **확인될 때만** 받을 양이 보인다. 이 기능은 **045 FR-003을 대체**한다(소유자 승인 2026-10-21). 헌법은 고치지 않는다 — 원칙 IV는 다운로드 상태 표시를 금지하지 않고, 원칙 III은 받을 양이 아니라 모델 내부 사양을 막는다.

## Clarifications

### Session 2026-10-21

소유자가 「특별한 이견이 없으면 추천대로」로 위임했다 — 아래 답은 추천안이다.

- Q: 연결 종류가 먼저 읽히면 양을 기다리지 않고 안내를 먼저 띄우고 양은 나중에 채울까, 둘 다 끝난(또는 한도가 지난) 뒤 한 번에 띄울까? → A: 둘 다 끝나거나 한도가 지난 뒤 한 번에 띄운다(본문이 뜬 뒤 바뀌지 않는다 — 읽는 도중 문장이 늘어나면 버튼 위치가 움직인다).
- Q: 045 스펙 문서(FR-003)는 고칠까, 이력으로 두고 095가 대체한다고만 적을까? → A: 045 스펙은 이력으로 두고, 코드·테스트 주석이 「045 FR-003」을 근거로 인용하는 자리는 095로 고친다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Wi-Fi에서 처음 여는 사용자가 받을 양을 보고 동의한다 (Priority: P1)

앱을 처음 열고 권한 단계를 지난 사용자가 Wi-Fi(또는 연결 종류를 알 수 없는 상태)에서 동의 안내를 본다. 안내는 무엇을 받는지와 함께 받을 양(예: 「약 2.0GB」)을 말하고, [받을게요] 하나로 묻는다.

**Why this priority**: App Store 제출의 필수 요건이며 이 기능의 전부다.

**Independent Test**: 모델이 없는 상태에서 첫 실행을 Wi-Fi로 진행해 동의 안내 본문에 받을 양이 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 필수 모듈이 없고 연결이 Wi-Fi이며 받을 양을 읽을 수 있다, **When** 동의 안내가 뜬다, **Then** 본문이 「일기를 쓰려면 사진을 읽는 모델과 글을 쓰는 모델을 약 {양} 내려받아야 해요. 한 번만 받으면 이후로는 필요 없어요.」이고 버튼은 [받을게요] 하나다.
2. **Given** 연결 종류를 읽지 못했다(모름·한도 초과), **When** 동의 안내가 뜬다, **Then** 시나리오 1과 같은 표준 안내에 받을 양이 보인다.
3. **Given** 위 안내, **When** [받을게요]를 누른다, **Then** 지금처럼 내려받기가 시작된다(동작 불변).

---

### User Story 2 - 받을 양을 못 읽으면 지어내지 않는다 (Priority: P1)

받을 양을 읽지 못했거나 읽기가 한도 안에 끝나지 않으면, 안내는 양 없이 지금 문장을 그대로 보인다.

**Why this priority**: 원칙 V(모르는 것을 기본값으로 채우지 않는다). 틀린 양은 없는 양보다 나쁘다.

**Independent Test**: 양 읽기가 실패·지연되는 상태로 동의 안내를 띄워 숫자가 없는 원래 문장이 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 받을 양 읽기가 실패한다, **When** 표준 동의가 뜬다, **Then** 본문은 「일기를 쓰려면 사진을 읽는 모델과 글을 쓰는 모델을 내려받아야 해요. 한 번만 받으면 이후로는 필요 없어요.」이다.
2. **Given** 받을 양 읽기가 한도(3초) 안에 끝나지 않는다, **When** 한도가 지난다, **Then** 시나리오 1과 같다.

---

### User Story 3 - 안내가 늦게 뜨지 않는다 (Priority: P2)

받을 양을 읽느라 표준 동의가 지금보다 늦게 뜨지 않는다.

**Why this priority**: 첫 실행에서 빈 화면이 길어지면 앱이 멈춘 것처럼 보인다.

**Independent Test**: 연결 읽기와 양 읽기가 모두 한도까지 걸리는 상태에서 안내가 뜨기까지 걸리는 시간을 본다.

**Acceptance Scenarios**:

1. **Given** 연결 읽기와 양 읽기가 둘 다 응답하지 않는다, **When** 한도 3초가 지난다, **Then** 그 시점에 (양 없는) 표준 동의가 뜬다 — 6초가 아니다.

### Edge Cases

- 이어 받기(일부 파일이 이미 있음): 받을 양은 **남은 양**이다 — 074 모바일 동의와 같은 정의다.
- 양이 1GB 미만: 「약 350MB」꼴로 보인다(074와 같은 형식).
- 모바일 데이터로 확인된 경우: 074 모바일 동의가 뜨고 이 기능은 그 문구·동작을 바꾸지 않는다.
- 「나중에 받기」 뒤 다시 확인하기·전경 복귀: 다시 읽을 때도 같은 규칙이다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 표준 동의 안내는 받을 양을 읽었을 때 본문에 그 양을 「약 {양}」으로 보여야 한다(MUST). 문구는 User Story 1 시나리오 1의 문장이다.
- **FR-002**: 받을 양을 읽지 못했거나 한도를 넘기면 표준 동의는 지금 문장을 그대로 보여야 하며(MUST), 기본값·추정값을 넣지 않아야 한다(MUST NOT).
- **FR-003**: 받을 양은 074 모바일 동의가 쓰는 값과 같은 출처·형식이어야 한다(MUST) — 남은 바이트, 1000 기준, 「2.0GB」·「350MB」꼴.
- **FR-004**: 표준 동의에는 계속 [받을게요] 하나만 있다(MUST, 045 FR-002a 유지). 거절·나중에 조작을 더하지 않는다(MUST NOT).
- **FR-005**: 표준 동의는 모델 내부 식별자·자산 키·서버 주소를 보이지 않아야 한다(MUST NOT, 원칙 III — 045 FR-003 중 받을 양을 뺀 나머지 유지). 안내 화면은 받을 양을 문자열로만 받고 모듈 자산 목록에 직접 닿지 않는다(MUST NOT).
- **FR-006**: 연결 종류와 받을 양은 동시에 읽어야 한다(MUST). 각각의 한도는 3초이며, 둘 다 응답하지 않아도 안내는 3초 뒤에 뜬다.
- **FR-006a**: 안내는 연결·양 읽기가 둘 다 끝나거나 한도가 지난 뒤 한 번에 뜬다(MUST). 뜬 뒤 본문이 양 때문에 바뀌지 않는다(MUST NOT).
- **FR-007**: 074 모바일 동의의 문구·선택지·동작은 바뀌지 않아야 한다(MUST).
- **FR-008**: 바뀐 문구는 한국어 카탈로그에만 둔다(MUST). 062 문구 골든은 다시 쓰지 않는다 — 양이 든 새 문장은 「골든 이후 추가」 목록에 올리고, 양 없는 원래 문장은 못 읽을 때 그대로 쓰이므로 골든에 남는다.
- **FR-009**: 코드·테스트 주석이 「045 FR-003(용량 비노출)」을 근거로 인용하는 자리는 이 기능(095)을 가리키도록 고친다(MUST). 045 스펙 문서는 이력으로 두고 고치지 않는다.

### Key Entities

- **받을 양 표시(sizeLabel)**: 남은 필수 모듈 바이트를 사람이 읽는 문자열로 바꾼 것, 또는 「모름」. 074가 정의했고 이 기능은 표준 동의에도 쓴다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Wi-Fi 첫 실행(실기기, 모델 없음)에서 동의 안내 본문에 받을 양이 보인다 — 실기기 1회 이상.
- **SC-002**: 받을 양을 못 읽는 모든 경우에 숫자가 보이지 않는다(자동 테스트로 실패·지연 두 경우).
- **SC-003**: 연결·양 읽기가 둘 다 응답하지 않을 때 안내가 뜨기까지 3초를 넘지 않는다(자동 테스트).
- **SC-004**: 모바일 동의 화면(074)의 기존 테스트가 고치지 않고 통과한다(동의 게이트 훅의 표준 갈래 단언은 이 기능이 바꾼다).

## Assumptions

- App Store 4.2.3(ii)의 「크기를 알린다」는 대략값(「약 2.0GB」)으로 충족된다 — 정확한 바이트를 요구하지 않는다.
- 받을 양 읽기는 기기 안 파일 크기와 고정 기대 크기만 쓰고 네트워크를 쓰지 않는다(074와 같음).
- Play 심사 메모(W7)는 이 기능의 범위가 아니다 — 저장소에 아직 그 문서가 없다.
- 실기기 확인은 소유자 몫이다(이 작업 세션은 기기가 없는 클라우드 컨테이너).
