# 상태 흉내 — 설계

- 날짜: 2026-10-06
- 입력: `docs/superpowers/specs/2026-10-01-settings-developer-decomposition-design.md` §3.7(보드 `6e` ③·`6i`), 결정 S7·S8, 공통 규칙 D2·D3
- 상태: brainstorming에서 저장소 소유자 승인. 다음은 `/speckit-specify`.

## 목적

개발 환경에서 홈 화면의 상태(오늘 날짜·실패 토스트·쓸 재료 0·사진 권한 없음)를 실제 데이터 없이 띄워 본다. 흉내가 하나라도 켜져 있는 동안에는
일기를 쓰지 않는다 — 가짜 상태를 보며 진짜 일기가 저장되지 않게(원칙 I, S8).

## 이 세션에서 정한 것

## 흉내 넷

- **오늘 날짜** — 홈이 쓰는 「지금」만 바꾼다: 주간 스트립·큰 숫자·미래 칸 흐림·「N시간 M분 전에 작성」. 백그라운드 `decideSchedule`의 `now`에는 주입하지 않는다.
- **쓸 재료 0으로 보기** — 안 쓴 날의 미리보기를 사진 0장·장소 0곳(관측된 0)으로 갈아 끼운다(보드 `2e`).
- **사진 권한 없음으로 보기** — 안 쓴 날의 미리보기를 사진 권한 없음으로 갈아 끼운다(보드 `2l`).
- **실패 토스트 보기** — B1.

쓴 날의 지면(제목·본문·사진)은 흉내 대상이 아니다.

## 하나라도 켜져 있을 때 (보드 `6i`)

- 홈 월 라벨 옆에 「DEV」(누르면 설정 위에 개발자를 쌓아 연다).
- 쓰기 바(「일기 쓰기」·「다시 쓰기」)가 회색 면 + 「DEV」. 누를 수 있고, 누르면 「상태 흉내가 켜져 있어서 일기를 쓰지 않아요. 개발자 화면에서 끌 수 있어요.」 2초. 쓰는 중으로 넘어가지 않는다.
- 진단의 「한 번 써 보기」·「자동 쓰기 지금 실행」은 누를 수 없는 행이 되고 차단 문구를 보조 줄로 보인다.
- 모두 끄면 원래 바로 돌아온다.

## 단위

- **순수 판정**(`src/app/`): 흉내 상태 파싱, 「하나라도 켜짐」, 쓰기 차단, 홈 「지금」 치환, 미리보기 치환(우선순위 B7).
- **저장 통로**: `preferences/simulation.json` 읽기·쓰기·지우기(059 `developer-menu-store.ts`와 같은 모양, 읽기는 던지지 않는다).
- **화면**: 개발자 화면 「상태 흉내」 묶음(개발 환경만), 날짜 대화상자, 홈의 DEV 표시·회색 바·차단 토스트.
- **조립**(`App.tsx`): 마운트 때 한 번 읽어 들고 있고(056 설정 값과 같은 자리), 홈에 치환된 `now`·미리보기·차단 여부를 넘긴다.

## 테스트

- 순수 함수: 파싱(깨짐 → 꺼짐), 「하나라도 켜짐」, 미리보기 치환과 우선순위, 「지금」 치환.
- 소스 계약: 세 진입점이 차단 함수를 부른다 · 흉내 모듈이 `diary/pipeline`·`schedule/decision`·`signals/fake`에 닿지 않고 그 반대도 차단 함수 외에는 닿지 않는다(헌법 검사).
- 화면: 개발자 묶음의 보드 원문 글자, DEV 표시, 회색 바·토스트.
- 실기기 dev: 넷을 각각 켜고 홈 표시, 흉내를 켠 채 쓰기 바(일기 안 생김), 헤드리스 자동 쓰기(일기·알림 안 생김).
