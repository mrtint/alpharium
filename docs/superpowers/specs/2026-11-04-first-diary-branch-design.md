# 첫 일기 분기(G3) — 설계

정본은 `docs/user-guidance-rules.md` 0장 D1·L2, 0-1, 0-2, 0-4다. 이 문서는 정본을 코드 구조로 옮기는 결정만 적는다.

## 목적

첫 실행이 재료 없이 「지어낸 하루」를 묻지도 않고 쓰고, 실패하면 조용히 삼키는 것을 고친다. 정상 동작 확인을 통과하면 오늘 재료를 보고, 재료가 있을 때만 묻고, 사용자가 고른 때만 쓴다. 쓰다가 실패하면 막다른 길이 되지 않게 확인으로 한 번 되돌린다.

## 범위

- 넣는다: D1(재료 → 확인창 → 쓰기), L2(실패 시 확인으로 한 번 되돌림, 두 번째는 토스트), e2e 흐름표.
- 뺀다: G4(자동 쓰기 설정 창·U1·D5·슬라이드 문구), 110(필수 모듈 받기), 하단 바 색 채우기.
- G4를 위해 하나만 둔다: 「첫 일기 흐름이 끝났다」를 한 값으로 읽을 수 있게 한다(아래 `done`).

## 흐름

```
확인 통과 → reading(확인 중 화면 유지) → 쓸 수 있나
  아니오 → done (안내 없이 홈 · 안 쓴 날)
  예 → asking(홈 위 확인창)
         나중에 → done
         써 보기 → writing(홈의 제자리 쓰기)
            저장·그만두기·끊김·칸 막힘 → done
            실패, 되돌림 전 → before(확인 다시) → 통과하면 reading부터 다시
            실패, 되돌림 뒤 → 실패 토스트 → done
확인 실패 화면의 [그냥 시작하기] → done
```

## 결정

| 결정 | 근거 |
| --- | --- |
| 첫 일기는 홈의 쓰기 요청(060 `writeRequest`)으로 쓴다. `triggerFirstRunAutoDiary`와 `src/firstrun/auto-diary.ts`는 걷는다 | 흐름도가 「홈 · 쓰는 중」과 「그만두기」를 요구한다. 파이프라인을 따로 돌리면 둘 다 없다(042: 검증 경로가 제품과 다르면 검증이 아니다) |
| 단계 판정은 순수 함수 `src/firstrun/first-diary.ts`에, 상태와 재료 읽기·되돌림 신호는 훅 `src/app/use-first-diary-flow.ts`에 둔다(`useAutoWriteClaim`처럼 조립 시험을 돌릴 수 있게). `resolveFirstRunStage`의 입력·단계는 바꾸지 않는다 | 규칙 문서는 `progress.ts`를 자리로 적었지만 그 파일은 권한~확인 단계 판정이다. 첫 일기는 `done` 이후의 일이라 파일을 나눈다. 되돌림 횟수는 세션 로컬(파일 없음) |
| 재료는 확인 중 화면을 유지한 채 읽는다(10초 한도, 사람이 정한 값 — 측정 아님) | 홈을 먼저 그리면 읽는 사이 「일기 쓰기」를 누를 수 있고 그 뒤 확인창이 겹친다. 읽기가 걸려도 첫 실행이 막히면 안 되므로 한도를 둔다 |
| 판정은 `decideMaterial`을 그대로 쓴다: `write`면 묻고 `confirm`(`zero`·`unseen`)이면 묻지 않는다. 읽기 실패·한도 초과도 묻지 않는다 | 「재료가 없으면 안내 없이 쓰지 않는다」(D1). 볼 수 없는 날은 재료가 있다고 말할 근거가 없다(원칙 V). 묻지 않는 것일 뿐 「없다」고 말하지 않는다 |
| 오늘 일기가 이미 있으면 묻지 않는다 | `writeRequest`는 덮어쓰기 확인을 거치지 않는다. 있는 일기를 첫 일기 확인으로 덮으면 안 된다 |
| 확인창은 `AppFrame`이 홈 위에 그린다 | 흐름을 `AppFrame`이 든다(되돌림은 홈을 내리는 일이라 홈이 못 한다). 부품은 `ConfirmDialog`. 뒤로 가기는 「나중에」 |
| 첫 일기는 이어 하기를 신청한다(iOS) | 홈이 그리는 쓰는 중 화면에 「앱을 나가도 계속 써요」가 보인다. 신청하지 않으면 그 말이 틀린다. AGENTS의 「첫 실행 자동 첫 일기는 신청하지 않는다」를 고친다 |
| 되돌리는 실패는 파이프라인 실패 중 「모델·판정·저장·시간」이다. 사용자 그만두기, 앱이 앞을 벗어나 끊김(`interrupted`), 다른 쓰기에 막힘(`already-running`), 시작 거절은 되돌리지 않는다 | L2의 목적은 모델이 도는지 다시 보는 것이다. 앱을 나가서 끊긴 것은 모델 문제가 아니고, 되돌리면 한 번뿐인 기회를 쓴다. 끊김은 종전 홈 쓰기처럼 토스트 |
| 되돌리는 실패에는 토스트를 띄우지 않는다. 요청의 `silencesFailure`가 그 결과만 가른다(끊김은 토스트가 있다) | 규칙 0-2의 4: 되돌릴 때 보이는 말은 확인 중 화면 그대로. 두 번째부터는 홈의 실패 토스트 그대로 |
| 쓰기 실패 기록(`recordWriteFailure`)은 첫 일기에도 그대로 남는다 | 홈의 `recordFailure` 경로를 그대로 탄다 |
| `firstRunTried`는 「이 실행이 첫 일기 흐름에 들어갔다」로 유지한다 | 첫 실행이 앱 열기 자동 쓰기를 이긴다(057)는 규칙은 그대로다. 확인창 아래서 앱 열기 쓰기가 시작되면 안 된다 |
| 자동 첫 일기 트리거가 쓰던 홈 재마운트 토큰(`autoGeneratedToken`)을 걷는다 | 홈이 직접 쓰고 목록을 다시 읽는다 |

## 문구

규칙 문서 0-1의 초안을 그대로 쓴다(사람이 확정, 설계 구간 커밋 확인 때 묻는다). 제목 「오늘 사진으로 첫 일기를 써 볼까요?」, 본문 「사진과 다닌 곳으로 하루를 짐작해 써요. 몇 분 걸릴 수 있어요.」, 버튼 「써 보기」/「나중에」. 장소 수는 사진 좌표에서 오므로(`visitCount`) 재료가 있으면 사진이 있다 — 「사진으로」가 틀리는 경우는 없다.

## 시험

- 순수: 단계 전이 전부, 쓰기 결과 → 되돌림 여부 표.
- 조립: 재료 읽기(오늘 일기 있음·재료 있음·없음·못 읽음·한도 초과), 홈의 쓰기 요청 결과 콜백(저장·실패·그만두기·거절), 조용한 실패에 토스트 없음.
- 소스 계약: `AppFrame` 배선, `triggerFirstRunAutoDiary` 소멸.
- e2e: 층 2 흐름(안드로이드·iOS)에 확인창 단계를 넣고 흐름표를 고친다. 재료 없음 경로를 덮는다.
- 시뮬레이터: 재료 있음·없음·나중에·확인창 모양. 실기기: 실제 쓰기와 실패 되돌림(기기가 빌 때까지 미룬다 — 그 전에 완료로 닫지 않는다).

## 재현 경로의 함정

「온보딩부터 다시」는 `welcomeShown`·`namingDoneThisSession`을 되돌리지 않아 작명·확인을 다시 타지 않는다 — 이 흐름에 닿지 않는다. 모델을 지키며 다시 보려면 층 2 실행기처럼 `onboarding.json`의 `welcomeShown`·`completed`를 `false`로 고치고 앱을 다시 띄운다(시뮬레이터는 `simctl get_app_container`).

## 위험

- 앱이 뒤에 있는 동안(iOS 이어 하기) 실패하면 되돌림이 뒤에서 모델을 올린다. 지금도 확인 중에 앱을 나가면 같은 일이 벌어져 새 위험은 아니지만 기기에서 본 적 없다.
- 시뮬레이터에서 확인이 실패하면 분기까지 닿지 못한다 — 그때의 대안은 스펙 quickstart에 적는다.
