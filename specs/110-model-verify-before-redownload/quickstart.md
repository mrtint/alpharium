# 110 측정과 확인 기록

## iOS 시뮬레이터 (2026-11-04, iPhone 17e, iOS 27, Release 빌드)

실제 모델 파일 셋(지문이 로스터와 일치)을 앱 데이터에 미리 두고 `state.json` 없이 첫 실행 흐름을 탔다. 「받기가 끝났고 검증 기록이 없는」 상태를 만든 것이고, 앱을 실제로 그 순간에 죽이지는 않았다. 메모리는 2초마다 `vmmap -summary`의 `Physical footprint (peak)`로 읽었다.

| 회차 | 코드 | 결과 | 메모리 최고치 |
|---|---|---|---|
| 온전한 파일 | MD5 패치 없음 | 받지 않고 검증 기록 셋 통과 | **1.9GB** |
| 온전한 파일 | 패치 | 받지 않고 검증 기록 셋 통과 | **약 70MB** |
| 온전한 파일(리뷰 반영 뒤) | 패치 | 받지 않고 검증 기록 셋 통과 | 약 70MB |
| 사진 모델 v2 4바이트 변조 | 패치 | v2만 지우고 다시 받음, a1·v1 수정 시각 그대로, 통과 | 160.8MB |

- 받지 않았다는 근거: 파일 수정 시각이 복사 때 그대로이고 `CFNetworkDownload_*`가 없다.
- 첫 실행 흐름을 지나 진행 화면의 「다음」까지 57~75초였다(권한 탭 포함, 맥에서 잰 값이라 기기 시간이 아니다). 해시 시간은 따로 재지 않았다.
- 맥 환경이고 기기의 메모리 한도는 재현되지 않는다. 13 mini의 종료 원인이 이 메모리라고 확정하지 못한다. 합치기 구간(`copyInto`)의 메모리는 이번에 재지 않았다.

## 아직 못 본 것 — 실기기가 비면 한다

1. iPhone 13 mini에 개발 서명 빌드를 새로 설치해 필수 모듈을 받고 첫 일기까지 간다. 새 `JetsamEvent-*.ips`가 없는지 본다(SC-004).
2. 받기 끝 무렵에 앱을 실제로 죽이고 다시 열어 전송 없이 준비되는지 본다(SC-001).
3. 13 mini에서 검증에 걸리는 시간을 잰다. 해시 중에는 JS 스레드가 멈춘다(`info`가 동기 함수 — 소스 읽기). 수십 초면 안내를 소유자와 정한다.
4. 갤럭시에서 새 설치로 한 번 받는다. 안드로이드 빌드 설정은 바꾸지 않았고 패치는 iOS 소스뿐이다.

## 고치지 않고 남긴 것

- 낡은 주석: `src/models/expo-port.ts`·`src/models/port.ts`의 「내려받기 직후 한 번만」, `src/ui/OnboardingScreen.tsx`·`src/app/essential-assets-port.ts`의 「이어받기가 자동으로」. 경량 트랙의 변경 파일 한도 때문에 뒀다.
- 기록 쓰기나 삭제가 계속 실패하면 자동 재시도마다 해시를 다시 돈다.
- 겹친 받기 호출을 막는 장치가 없어 받는 중인 파일을 지울 수 있다. 찾은 경로는 개발자 「온보딩 다시」뿐이다.
