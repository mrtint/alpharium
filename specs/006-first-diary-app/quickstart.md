# Quickstart: 손에 쥐는 첫 빌드 검증

**Feature**: 006-first-diary-app | **Date**: 2026-08-18

**이 기능의 완료 조건은 하나다: 개발 기계를 끄고, 케이블을 뽑고, 앱을 열어 일기를 쓸
수 있다.** 아래 D-절차가 그것을 확인한다.

**⚠️ 건너뛴 실기기 검증은 통과가 아니다**(헌법 원칙 V). 기기 없이 전부 초록불이어도
release는 검증되지 않은 상태다 — **005까지의 모든 실기기 확인이 debug였고 release는
처음이다.**

---

## 사전 조건

| 필요한 것 | 확인 |
| --- | --- |
| Android 기기 (arm64-v8a) | 실검증 기기: SM-G986N / Android 13 |
| 기기 잠금 해제 + 화면 켜짐 | `adb shell dumpsys trust` → `deviceLocked=0` |
| 서명 키 | [contracts/release-build.md §4](contracts/release-build.md) |
| 캐릭터 모델 하나 | 앱에서 내려받는다. `imaginative`가 2026-08-17에 기기에 있었다 |

## A. 기기 없이 (항상 돈다)

```
npm test          # 기기 불필요 갈래
npm run lint      # eslint + tsc + 헌법 검사
```

**기대**: 전부 통과. 다음이 포함된다.

| 검사 | 계약 |
| --- | --- |
| 화면 상태 전이 전 갈래 | [screens.md §5](contracts/screens.md) |
| 조립이 `selectBackend`를 거친다 | [persistence.md §6](contracts/persistence.md) — P3 |
| `backend.generate()` 직접 호출 0건 | persistence.md — P1 (정적 검사) |
| 저장 실패 시 글이 화면에 남는다 | persistence.md — P5 |
| `unknown`이 왕복에서 산다 | persistence.md — P6 |
| 프롬프트에 단언 금지 지시가 있다 | FR-036·037 |
| 출력 판정 갈래가 **넷** | FR-039, SC-021 |

**⚠️ `npm test`가 통과해도 release는 검증되지 않았다.** 기기 없는 테스트는 debug·release
구분을 보지 않는다.

---

## B. release 빌드 뽑기

**구현 초기에 한 번 해 본다.** 마지막에 확인하면 깨졌을 때 되돌릴 것이 많다.

```
npx expo prebuild --platform android --clean
```

**⚠️ `--clean`을 건너뛰지 않는다.** `android/`가 이미 있으면 prebuild를 건너뛰고,
그러면 서명 plugin이 반영되지 않는다. **004에서 이것 때문에 권한이 빠진 APK가
설치됐다.**

그다음 release 빌드 → APK 설치. 절차는
[contracts/release-build.md §4](contracts/release-build.md).

### 빌드 성공을 믿지 않는다

**빌드가 성공했다는 것은 설정이 맞다는 뜻이 아니다**(004의 교훈).

| 확인 | 방법 | 통과 |
| --- | --- | --- |
| **R1** debug 키가 아닌가 | `apksigner verify --print-certs <apk>` | `CN=Android Debug`가 **아니다** |
| **R2** 키가 저장소에 없는가 | `git status`, `git ls-files \| grep -i jks` | 아무것도 안 나온다 |

---

## C. release에서 도는가

Metro를 **켠 채로** 먼저 확인해도 좋지만, **최종 확인은 D에서 끈 채로 한다.**

| 확인 | 무엇 | 통과 |
| --- | --- | --- |
| 앱이 뜬다 | 실행 | 흰 화면·즉시 종료가 아니다 |
| **R5** prod로 판정 | 화면을 본다 | `build-error` 화면이 **아니다** |
| **S9** 진단 차단 | 화면을 본다 | 진단 화면이 **보이지 않는다** |
| 동적 import | 캐릭터 목록·사진 권한 | 모델 상태가 읽히고 사진 수집이 된다 |
| **R7** 네이티브 | 일기 쓰기 | 모델이 적재되고 생성이 끝난다 |

**⚠️ 원칙 IV**: release가 debug보다 빠른지 느린지 **재지 않는다.** 도는지만 본다.
005의 「적재 2.1초 / 생성 30초」는 배경 사실이지 비교 대상이 아니다.

**깨지면** — [release-build.md §5](contracts/release-build.md)의 위험 표를 본다.
동적 import와 `llama.rn` JNI 심볼이 후보이며, **둘 다 이 저장소에서 아직 관측되지
않았다**(짐작이다).

## D. 완료 조건 — 케이블을 뽑는다

**이것이 SC-001이며 이 기능의 완료 조건이다.**

```
1. Metro를 끈다                    (개발 기계에서 expo start 종료)
2. USB를 뽑는다                    (adb 연결 없음)
3. 기기에서 앱을 연다
```

| # | 확인 | 통과 | SC |
| --- | --- | --- | --- |
| D1 | 앱이 뜬다 | `Unable to load script`가 **없다** | SC-002 |
| D2 | 캐릭터를 고르고 모델을 받는다 | 003 화면이 돈다 | — |
| D3 | 일기를 쓴다 | 「쓰고 있다」가 보이고 끝나면 전문이 뜬다 | SC-001 |
| D4 | **진행률·시간·생성 중인 글이 없다** | 「쓰고 있다」뿐 | SC-020 |
| D5 | 목록으로 돌아간다 | 방금 쓴 일기가 목록에 있다 | SC-012 |
| D6 | 항목을 눌러 읽는다 | 전문과 날짜가 보인다 | — |
| D7 | **앱을 완전히 종료하고 다시 연다** | **일기가 그대로 있다** | **SC-008** |
| D8 | **기기를 재부팅하고 앱을 연다** | **일기가 그대로 있다** | **SC-008** |
| D9 | 다른 날짜로 하나 더 쓴다 | **둘 다** 목록에 있다 | SC-008a |
| D10 | 진단 화면을 찾아본다 | 어디에도 없다 | SC-010 |

**D7·D8이 이 기능의 새 축이다.** 005까지는 확인된 적이 없다 — 저장 자체가 끊겨
있었다.

### D11. 사람이 일기를 읽는다 (P2 — SC-017·018)

**자동 판정을 만들지 않는다**(원칙 IV). 사람이 읽는다.

| 확인 | 통과 |
| --- | --- |
| 화자가 휴대폰인가 | 「나」가 휴대폰이다. 사람 시점으로 뒤집히지 않았다 |
| 기록에 없는 것을 단언했는가 | **없다.** 005에서 "날씨가 정말 좋았다"·"친구와 산책을 했다"가 나왔던 자리 |
| 짐작은 있는가 | 있어도 **위반이 아니다**. 헌법이 권장한다 |

**005의 SC-002a가 실패했던 자리다.** 고친 뒤 다시 확인한다.

## E. 덮어 설치 (SC-006)

**미루면 되돌릴 수 없는 것을 확인한다.**

```
1. D를 마쳐 일기가 저장된 상태
2. app.json의 versionCode를 올린다
3. 같은 키로 재빌드
4. adb install -r <새 apk>
```

| 확인 | 통과 |
| --- | --- |
| 설치가 성공한다 | `INSTALL_FAILED_UPDATE_INCOMPATIBLE`이 **아니다** |
| **일기가 그대로 있다** | D에서 쓴 일기가 목록에 |

**실패하면 서명이 어긋난 것이다.** 이 시점에 발견하는 것이 사용자가 발견하는 것보다
훨씬 싸다.

## F. Maestro (실기기 자동 흐름)

```
EXPO_PUBLIC_APP_ENV=dev npx expo start --dev-client   # 별도 터미널
npm run test:device
```

**⚠️ 세 가지가 갖춰져야 돈다** (AGENTS.md의 실측):

1. Metro가 dev로 떠 있어야 한다 — debug APK에는 번들이 없다
2. 기기 잠금이 풀려 있어야 한다
3. 한글 문구는 `-Dfile.encoding=UTF-8`이 필요하다 — 실행기가 넣어 준다

**⚠️ 새 흐름 `.maestro/diary-user-path.yml`을 `scripts/run-device-tests.mjs`의
`FLOWS`에 등록해야 돈다.** 등록하지 않으면 파일이 있어도 안 돌고, **초록불인데 아무것도
검증되지 않은 상태**가 된다.

**F는 D를 대신하지 않는다.** Maestro는 dev 빌드에서 돌고, D는 release에서 돈다.
