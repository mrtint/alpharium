# 정상 동작 확인 단축(G2·F1) — 실기기 확인

스펙의 SC-002·SC-003을 실기기에서 본 기록이다. PR #225는 클라우드 세션이라 기기 확인 없이 머지됐다.

## 갤럭시 SM-S901N (2026-11-10, dev 빌드 + Metro 번들, 모델 보존)

**방법**: 첫 실행 플래그(`onboarding.json` `completed:false`·`welcomeShown:false`)를 되돌리고 `character-names.json`을 지운 뒤, Maestro로 작명을 마치고 logcat 시각(`-v epoch`)으로 쟀다. 「상한 없음」은 `checkLiveness()`가 `LIVENESS_MAX_TOKENS`를 넘기지 않게 임시로 고친 번들이다(커밋하지 않았다). 생성 토큰 수는 측정용 임시 `console.log`(`llama-port.ts` `complete()` — `tokens_predicted`·`stopped_eos`)로 읽고 지웠다. 오늘 사진이 없는 상태라 확인이 끝나면 확인창 없이 홈으로 간다.

- 체류 = 「확정」을 누른 때(마지막 `ViewPostIme pointer 1`) → 홈으로 넘어가는 첫 `StatusBarModule` 줄
- 적재 = `loadModel` 시작 → `Input processed`(프롬프트 18토큰 처리 끝)

| 회차    | 상한      | 체류  | 적재  | 생성 토큰 수(끝) |
| ------- | --------- | ----- | ----- | ---------------- |
| after1  | 16        | 8.9초 | 6.4초 | (로그 없음)      |
| after2  | 16        | 8.3초 | 5.9초 | (로그 없음)      |
| before1 | 없음(512) | 8.3초 | 5.9초 | (로그 없음)      |
| before2 | 없음(512) | 8.0초 | 5.8초 | 10 (EOS)         |
| after3  | 16        | 8.3초 | 5.7초 | 12 (EOS)         |
| after4  | 16        | 8.3초 | 6.1초 | 9 (EOS)          |

**결론**:

- 상한을 둔 뒤 체류가 길어지지 않았다(SC-003 통과, 첫 실행 확인도 매번 통과).
- **줄어들지도 않았다.** 이 모델은 「안녕?」에 9~12토큰을 쓰고 EOS로 스스로 끝내 16토큰 상한에 닿지 않는다 — 상한이 걸리지 않으니 시간이 같다. 체류의 약 70%는 모델 적재(약 6초)다. 상한은 답이 길어지는 경우(EOS를 못 내는 경우)의 방어로만 남는다.
- 일기 본문·제목 상한은 그대로다(SC-002) — 같은 날 층 2(SM-S901N)에서 일기 쓰기 흐름이 정상 길이로 저장됐다(2026-11-09, `specs/111-first-diary-branch/quickstart.md`).
- 표본은 상한 있음 4·없음 2다.

## iPhone 14 (2026-11-10, 개발 서명 Release 빌드, iOS 27.0.1)

**방법**: Release 빌드라 번들을 바꾸려면 다시 빌드해야 해서 측정용 빌드 둘(상한 있음·없음)을 만들어 깔았다. 둘 다 `checkLiveness()` 앞·적재 뒤·생성 뒤에 임시 `console.error` 줄을 넣어 기기 로그(`pymobiledevice3 syslog live`)의 시각으로 쟀다(측정 뒤 걷고 정식 빌드를 다시 깔았다). 작명은 사람이 했다. iPhone 화면 쓰기는 조각 생성 경로(`SCREEN_IOS_PACING`)라 토큰 수를 읽는 임시 로그(`complete()`)에 닿지 않아 **토큰 수는 못 봤다.**

- 확인 = `checkLiveness()` 시작 → 판정 직전(적재 + 생성). 화면 전환 시간은 넣지 않았다.

| 회차 | 상한               | 확인   | 적재   | 생성   |
| ---- | ------------------ | ------ | ------ | ------ |
| r1   | 16                 | 3.86초 | 2.47초 | 1.39초 |
| r2   | 없음(조각 32 × 16) | 4.07초 | 2.49초 | 1.57초 |
| r3   | 없음               | 4.19초 | 2.41초 | 1.79초 |

**결론**: 상한을 둔 뒤 확인이 길어지지 않았다(SC-003 통과). 생성은 상한 있음이 0.2~0.4초 짧았지만 표본이 1:2이고 토큰 수를 못 봐서 상한이 걸렸는지는 모른다 — 갤럭시처럼 답이 16토큰 안에서 끝났다면 차이는 잡음이다.
