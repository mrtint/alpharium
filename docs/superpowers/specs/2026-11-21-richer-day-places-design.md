# 일기가 하루의 장소를 더 풍부하게 말한다 — 설계

- 날짜: 2026-11-21
- 로드맵: 「일기가 하루의 장소를 더 풍부하게 말한다 — 여러 자리·더 구체적인 이름」
- 트랙: 전체(새 데이터 계약 「자리 목록」, 변경 파일 5개 초과, 외부 연동 제거·권한 변경)

## 목적

일기가 하루의 장소를 더 많이, 더 와닿게 말한다. 회사→카페→집이면 첫 자리 하나가 아니라 여러 자리를 시각순으로 말하고, 이름은 행정명(「역삼동」)이 아니라 사람이 아는 장소(「강남역」「서울숲」「경복궁」)로 말한다. 자리는 단정하지 않고 「~근처」로 짐작한다(헌법 원칙 II).

이 과제가 정하는 「자리 목록」 계약을 뒤의 두 과제(앱 화면에 장소 보여주기, 사진 밖 위치 수집)가 읽거나 확장한다.

## 소유자가 정한 것 (2026-11-21 대화)

| 결정 | 내용 |
|---|---|
| 이름 붙일 자리 수 | 하루 최대 3곳(시각순), 넘는 자리는 「그 밖에 N곳」 개수만 |
| 말투 | 「어디다」로 단정하지 않고 「~근처」로 짐작 |
| 이름 단위 | 행정명이 아니라 장소명(역·광장·궁·공원·큰 건물·단지 수준). 가게·음식점은 뺀다 |
| 장소명의 출처 | 기기 안의 장소 데이터(OpenStreetMap 한국 추출본 가공) — 외부 지도 서비스 아님 |
| 여러 자리를 말하는 법 | 시각순 + 때(아침·낮·저녁 등)와 함께 |
| OS 지도 서비스(역지오코딩) | 걷는다. 좌표가 휴대폰 밖으로 나가지 않는다 |
| 설정 「장소 이름으로 보기」 | 「켬/끔」 두 갈래로 줄인다. 기존 「자동」·「켬」은 「켬」으로 옮긴다 |
| 위치 권한 | 이번에 걷는다(첫 실행 요청·설정 꼬리표·매니페스트·iOS 문구·방침·스토어 선언) |

## 실측 근거 (스파이크, 2026-11-21 — 코드는 버렸다)

**기기 지오코더로는 장소명을 얻을 수 없다.** 맥의 Apple `CLGeocoder`(iOS와 같은 서비스, iPhone 직접 실측 아님)로 공개 지점 7곳을 ko_KR로 물었다.

- `subLocality`는 동 단위(역삼동·성수동1가·백현동·우1동·세종로), 구는 주지 않는다(`subAdministrativeArea` 비어 있음). 동보다 구체적인 값은 도로명·번지·우편번호뿐이다. `areasOfInterest`는 비어 있었고 `expo-location`은 넘기지도 않는다.
- MapKit `MKLocalPointsOfInterestRequest`(반경 150~200m)는 7곳 중 5곳에서 결과가 없었고(경복궁 포함), 나온 두 곳도 근처 아무 가게(「올리브영 센트럴 강남 타운」)·영문 이름이었다.
- 안드로이드 Google 지오코더는 재지 않았다(걷기로 해서 더 잴 필요가 없어졌다).

**기기 안 OSM 데이터로는 원하는 수준의 이름이 나온다.** Geofabrik `south-korea-latest.osm.pbf`(292,399,858바이트, 2026-11-21 00:58 GMT)를 pyosmium으로 걸렀다.

- 이름 붙은 장소 전체 약 50만 곳(압축 7.5MB). 한글 이름 + 가게·음식점 제외 + 지명 포함 + 경계 다각형(40점으로 단순화)이면 22.6만 곳(주거 7.9만·건물 4.5만·기관 4.3만·공원 2.8만·지명 2.1만·명소 0.7만·역 0.2만·몰 0.1만), 압축 약 3~4MB.
- 시험 20곳 중 고친 규칙으로 맞은 곳: 강남역·판교역·홍대입구역·부산역·광화문광장·경복궁·서울숲·롯데월드·해운대 해수욕장·성산일출해양도립공원·정자역·성수역. 틀린 곳과 원인: 코엑스(건물 안인데 역을 먼저 봄), 망원·여의도 IFC(긴 공원 경계를 거칠게 줄임), 전주 한옥마을·느티마을 단지(동네·단지 이름이 뒤로 밀림), 인천공항 T1(공항보다 역), 두물머리(OSM에 없음 → 지명 「양수리」).

## 접근안

1. **(채택) 앱 번들 자산** — 이진 파일 하나를 앱에 넣고, 일기를 쓸 때 읽어 격자 색인으로 찾는다. 받을 것이 없어 첫 일기부터 이름이 나오고 오프라인에서 동작한다. 새 네이티브 의존성이 없다. 데이터 갱신은 앱 업데이트와 함께한다.
2. 필수 모듈 내려받기에 포함 — 앱 크기는 그대로지만 동의 문구·용량·검증·이어받기 경로를 모두 건드리고 받기 전에는 이름이 없다.
3. SQLite(R-tree) — 하루 세 번 찾는 일에 새 네이티브 의존성은 과하다.

## 설계

### ① 데이터 만들기

- 저장소 밖 도구 `osmium`(Homebrew)으로 추출본을 태그로 거르고 GeoJSON으로 내보낸 뒤, Node 스크립트(`scripts/places/`)가 이진 파일 하나로 묶는다. 추출본 날짜·원본 크기·결과 해시를 기록 파일에 남긴다.
- 담는 것: 역·명소·공원·몰·기관·건물·주거 단지·지명. 가게·음식점은 뺀다. 이름은 `name:ko` → `name` 순이며 한글이 있는 것만 담는다.
- 경계 다각형은 형태를 지키는 단순화(Douglas–Peucker)로 줄인다(스파이크의 등간격 추림이 긴 공원을 틀리게 했다).
- 라이선스: ODbL. 라이선스 페이지(101, `site/licenses/`)에 출처를 표기하고, 가공 파일은 저장소에 커밋해 같은 라이선스로 제공한다.

### ② 「자리 목록」 계약 (`src/signals/types.ts`)

```ts
type PlaceVisit = {
  coordinate: Coordinate;              // 그 자리 첫 사진의 좌표
  firstSeenAt: Date;                   // 그 자리 사진들의 첫 시각
  lastSeenAt: Date;                    // 그 자리 사진들의 마지막 시각
  photoCount: number;
  source: "photo-exif";                // 사진 밖 수집 과제가 다른 출처를 더한다
};

type PlaceName =
  | { kind: "known"; label: string; category: PlaceCategory }
  | { kind: "none" }                   // 근처에 이름 붙은 곳이 없다
  | { kind: "unknown" };               // 데이터를 읽지 못했다

PhotoPlaces = { trace, visits: PlaceVisit[] /* 시각순, 전부 */, source, photosWithLocation, photosConsidered }
```

- `visits`는 `tracePlaces()`가 이미 하는 순차 묶기의 결과를 그대로 낸 것이다. 100m 묶기 규칙은 바꾸지 않는다(짐작 값, 범위 밖).
- 이름은 신호 수집이 아니라 파이프라인 단계가 붙인다(설정 「끔」이면 찾지 않는다). 이름이 붙은 자리는 `NamedVisit = PlaceVisit & { name: PlaceName }`이다.

### ③ 이름 고르기 (`src/signals/place-names.ts`)

- 순수 함수 `choosePlaceName(index, coordinate)`와 데이터를 읽는 포트(번들 자산 → 바이트, 동기 읽기 — `expo-file-system` `File`의 비동기 호출 금지 규칙).
- 고르는 순서(거리는 모두 사람이 정한 값이며 실측이 아니다): 안에 있는 명소·공원·몰 중 가장 큰 것 → 안에 있는 큰 건물·기관·주거 단지 → 250m 안의 역(「○○역」) → 300m 안의 명소·공원·몰 → 100m 안의 건물·기관 → 1.5km 안의 지명 → `none`.
- 시험 20곳을 기대 이름과 함께 대조 테스트로 둔다(실제 데이터 파일로 돈다). 결정적 조회이며 모델 출력 채점이 아니다(원칙 IV와 무관).

### ④ 일기로 흐르기

- 파이프라인 4c: 지오코딩 대신, 설정이 「켬」이면 자리마다 기기 안에서 이름을 찾는다. 바깥 호출이 없다.
- 프롬프트(`src/diary/prompt.ts`만): 이름이 다른 자리 최대 3곳을 시각순으로 싣는다. 예: 「아침에는 판교역 근처, 낮에는 서울숲 근처에서 사진이 찍혔어요. 그 밖에 한 곳에서도 찍혔어요.」 이름이 없는 자리는 「이름을 모르는 곳」. 사실은 「사진이 찍혔다」까지만 주고 「있었던 것 같다」는 모델의 짐작에 맡긴다. 새 문장은 v5에서 잰 문장이 아니다.
- 저장: `DiaryEntry.places`(자리별 이름·때)를 더한다. 옛 `placeName` 일기는 그대로 읽는다.

## 남은 위험

- OSM 빈 곳은 지명으로 내려가고 시골은 이름이 드물다.
- 새 프롬프트 문장을 2B 모델이 시각순으로 따를지는 실기기에서 처음 본다.
- 앱 크기가 수 MB 늘어난다.
- 데이터는 앱 업데이트 때만 갱신된다.
