## iPhone 실기기 (개발 서명 빌드, 안드로이드는 쓰지 않는다)

전제: iPhone 14, 개발 빌드가 깔려 있고 모델이 없는 상태(앱 데이터에서 `models/`를 앱 안에서 지운다 — `devicectl … --remove-existing-content`는 쓰지 않는다, AGENTS 097).

1. 첫 실행 받기 시작 → 진행 중간(약 30~50%)에 `devicectl device process terminate`로 앱을 죽인다.
2. `state.json`(`devicectl device copy from`)에서 `segmented[].doneIndices`가 남았는지 본다.
3. 앱을 다시 열어 받기를 이어 간다 → 끝난 구간을 다시 받지 않는지(받은 양의 시작점이 0이 아님) 본다.
4. 끝나면 검증이 통과하고 「준비됨」이 되는지 본다(지문 일치).
5. 비행기 모드로 끊은 뒤 풀어서 같은 확인.

## 실측 (2026-11-11, iPhone 14 · 개발 서명 Release 빌드, 유선·집 Wi-Fi)

모델 파일 셋이 있는 기기에서 `devicectl device copy to`로 대상 파일 하나를 0바이트 파일로 바꾸고 앱을 띄웠다(앱이 알아서 다시 받기 시작). 기록은 `devicectl device copy from`으로 `models/state.json`을 몇 초 간격으로 읽었고, 앱은 `devicectl device process terminate`로 죽였다. 시간은 맥에서 읽은 값이라 몇 초 오차가 있다.

| 대상 | 경우 | 결과 |
|---|---|---|
| 언어 모델 a1 (1.42GB) | 16구간 중 8개가 기록된 때(받기 시작 후 약 80초) 앱 종료 | 종료 뒤 기록 `[0..7]` 그대로. 다시 열자 `[0..7]`을 유지한 채 8~15가 더해지고 약 70초 만에 끝남. 검증 기록 `a1` 통과, 지문이 받기 전 값과 같음(`d8506380…`), 구간 기록 지워짐, `a1.bin` 1.42GB |
| 사진 모델 v1 (379MB) | 16구간 중 3개가 기록된 때(받기 시작 후 약 12초) 앱 종료 | 종료 뒤 `[0,1,2]`. 다시 열자 유지한 채 이어 받아 약 50초 만에 끝남. 검증 기록 `v1` 통과, 지문이 받기 전 값과 같음(`b0f40eda…`), 구간 기록 지워짐 |

- 끝난 구간 번호가 다시 열 때 사라지지 않고 늘기만 한 것이 「끝난 구간은 받지 않는다」의 근거다(`[0..7]` → `[0..7,10]` → … → 지워짐). 구간을 처음부터 다시 받았다면 기록이 비어 다시 시작했을 것이다. 받은 바이트를 직접 센 것은 아니다.
- 못 본 것: 비행기 모드·연결 끊김(기기에서 끌 수단이 없어 단위 테스트(`acquisition.test.ts`의 실패 뒤 이어받기)로 갈음), 어긋난 기록(파일 삭제·크기 부족)의 기기 재현, 받는 도중 앱을 죽이는 시점이 구간을 막 끝내는 순간과 겹치는 경우, 안드로이드 전부(다른 측정 중), iPhone 13 mini(연결 안 됨), 처음부터 받는 시간 비교(SC-005 — 위 시간은 이어받기라 비교 대상이 아니다. 같은 기기에서 처음부터 받는 시간은 따로 재지 않았다).
- 이 시험은 앱을 죽인 직후 다시 연 것이라 구간 임시 파일(`.seg<i>`)이 남은 채 이어 받았다. 이어받는 쪽이 구간 시작 때 지우고 덮어쓰는 것으로 문제없이 끝났다.
