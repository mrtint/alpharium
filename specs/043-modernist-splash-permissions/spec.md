# Feature Specification: Modernist 디자인 시스템 적용 1차 — 스플래시·권한 요청 흐름

**Feature Branch**: `043-modernist-splash-permissions`

**Created**: 2026-09-18

**Status**: Draft

**Input**: User description: "Modernist 디자인 시스템 적용 1차 — 스플래시·권한 요청 흐름 재구현"

## 배경 및 이전 시도 경위

claude.ai/design에서 받은 디자인 리뷰 보드(`Alpharium Mobile Screens (standalone).html`,
20개 화면 대안 포함)를 이 앱에 적용하는 것이 전체 목표다. 이전 시도(043 최초본,
2026-09-18에 전면 롤백됨)는 홈·상세 화면까지 한 번에 재구현하려다 기존 계약
(038 타자기 연출, 017 소요 시간 즉시 표시, 025 사진 갤러리)과 세 차례 충돌했고,
매번 "충돌을 피하는 쪽으로 축소"한 끝에 최종 결과물이 리뷰 보드의 시각적
정체성(Modernist — 오프화이트, 단일 레드 강조, 제로 라디우스)을 거의 반영하지
못하는 수준으로 빈약해졌다. 저장소 소유자가 실기기에서 직접 확인하고 브랜치
전체를 삭제(`git branch -D`)했다.

이번 스펙은 그 실패를 반복하지 않기 위해 **범위를 스플래시 화면과 그 직후의
권한 요청 흐름 하나로만 좁힌다.** 홈·상세·설정 등 나머지 화면은 명시적으로
범위 밖이며, 이번 스펙의 완료를 확인한 뒤 후속 스펙에서 순서대로 다룬다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 앱 최초 진입 시 브랜드 스플래시를 본다 (Priority: P1)

사용자가 앱을 처음(또는 온보딩이 필요한 상태로) 실행하면, 디자인 리뷰 보드가
정한 시각 언어(오프화이트 배경, 레드 사각 마크, 굵은 브랜드 타이틀, 하단 안내
문구와 로딩 표시)로 된 스플래시 화면을 먼저 본다. 화면에는 사용자가 누를
버튼이 없다 — 정해진 시간 뒤 자동으로 다음 단계(권한 요청)로 넘어간다.

**Why this priority**: 스플래시는 사용자가 앱을 열 때마다(온보딩이 필요한
상태에서) 가장 먼저 보는 화면이라 새 디자인 시스템의 첫인상을 결정한다. 권한
흐름 전체가 이 화면 위에서 이어지므로 다른 작업의 전제 조건이기도 하다.

**Independent Test**: 온보딩이 필요한 상태로 앱을 실행해 스플래시 화면의
레이아웃·색상·문구를 눈으로 확인하고, 정해진 시간 뒤 자동으로 다음 화면(권한
요청)으로 전환되는 것을 관찰하는 것만으로 독립적으로 검증된다.

**Acceptance Scenarios**:

1. **Given** 온보딩을 완료한 적이 없는 상태, **When** 앱을 실행한다,
   **Then** 오프화이트 배경 위에 레드 사각 로고 마크와 브랜드 타이틀이 좌측
   정렬로 표시되고, 하단에 안내 문구와 로딩 표시가 보인다.
2. **Given** 스플래시 화면이 표시된 상태, **When** 정해진 시간이 지난다,
   **Then** 사용자 조작 없이 자동으로 권한 요청 흐름으로 전환된다.
3. **Given** 스플래시 화면이 표시된 상태, **When** 화면을 관찰한다,
   **Then** 모델 이름·다운로드 진행률·추론 관련 수치 등 내부 지표가 전혀
   보이지 않는다(로딩 표시는 장식적 요소일 뿐 실제 진행률을 계산해 보여주지
   않는다).

---

### User Story 2 - 필요한 권한을 순서대로 요청받는다 (Priority: P1)

스플래시 화면 이후, 사용자는 앱이 정상 동작하는 데 필요한 권한(사진, 사진
위치, 위치, 알림, 배터리 최적화 예외)을 정해진 순서대로 요청받는다. 각 권한
요청은 새로 그려진 Modernist 스타일의 안내 화면 위에서 이루어지며, 실제
권한 승인/거부는 운영체제가 제공하는 표준 다이얼로그로 처리된다. 사용자는
원하면 각 단계를 건너뛸 수 있다.

**Why this priority**: 권한이 없으면 앱의 핵심 기능(사진 기반 일기 생성,
자동 생성 알림 등)이 조용히 축소된 채로 동작한다 — 사용자가 그 사실을 알고
선택할 수 있어야 한다. 이 흐름은 이미 검증된 로직(021, 040) 위에 새 화면만
입히는 것이라 스플래시 다음으로 우선순위가 높다.

**Independent Test**: 온보딩이 필요한 상태로 앱을 실행해 스플래시 이후
권한 요청 화면이 이어지는 것을 확인하고, 각 권한을 허용/거부/건너뛰기 했을
때 다음 단계로 정상적으로 넘어가는 것을 관찰하는 것으로 독립적으로 검증된다.

**Acceptance Scenarios**:

1. **Given** 스플래시 화면이 자동 전환된 직후, **When** 권한 요청 화면이
   뜬다, **Then** 새 디자인 토큰(오프화이트 배경, 레드 강조, 제로 라디우스)
   으로 그려진 화면 위에서 권한 안내와 진행 상태가 보인다.
2. **Given** 권한 요청 화면에서 특정 권한을 허용한다, **When** 운영체제
   다이얼로그가 승인으로 닫힌다, **Then** 그 권한 단계가 완료로 표시되고
   다음 권한 단계로 넘어간다.
3. **Given** 권한 요청 화면에서 특정 권한을 건너뛴다, **When** 건너뛰기를
   선택한다, **Then** 그 권한 없이 다음 단계로 넘어가고 이후에도 앱은
   정상적으로 동작한다(그 권한을 요구하는 기능만 제한된 형태로 동작).
4. **Given** 모든 권한 단계를 마쳤다, **When** 마지막 단계가 끝난다,
   **Then** 이번 스펙 범위를 벗어난 다음 단계(작명·에셋 다운로드)로
   흐름이 이어진다(그 화면 자체는 이번 스펙에서 새로 그리지 않는다).

---

### Edge Cases

- 이미 온보딩을 완료한 사용자가 앱을 다시 실행하면 스플래시·권한 화면을
  다시 보지 않는다(기존 021/040 게이트 로직 그대로 — FR-010).
- 설정에서 "권한 안내 다시 보기"를 선택해 온보딩을 강제로 다시 띄운 경우에도
  같은 스플래시·권한 화면이 그려진다(기존 `forceOnboarding` 경로 재사용).
- 사용자가 스플래시 화면이 자동 전환되기 전에 앱을 백그라운드로 보내면,
  포그라운드로 돌아왔을 때 기존 타이머 로직에 따라 이어지거나 재시작한다
  (기존 `LogoScreen`의 `useEffect` 타이머 동작 그대로 — 이번 스펙은 이
  동작을 바꾸지 않는다).
- 이미 일부 권한이 부여된 기기(예: 다른 앱에서 사진 권한을 이미 허용)에서는
  해당 권한 단계가 이미 충족된 것으로 표시되고 자동으로 다음 단계로
  넘어간다(기존 021 로직 — 021 실기기 검증에서 확인된 동작).
- 사용자가 특정 권한을 안드로이드의 "다시 묻지 않음" 옵션과 함께 거부하면,
  이후 그 권한을 다시 요청해도 OS 다이얼로그가 뜨지 않고 즉시 거부로
  처리된다 — 이 경우 화면은 재요청을 반복 시도하지 않고, 앱 설정 화면으로
  이동하도록 안내하는 기존 021 문구를 새 디자인 토큰으로 표시한다(FR-008a).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 스플래시 화면은 리뷰 보드 프레임 1k의 레이아웃 구조(상단
  좌측 정렬 로고 마크+타이틀 블록, 하단 안내 문구+로딩 표시, 그 사이 구분선)
  을 그대로 따라야 한다.
- **FR-002**: 스플래시 화면의 로고 마크는 72×72 크기의 단색 사각형(accent
  색, 모서리 반경 0)이어야 한다(실제 로고 이미지 에셋은 이번 스펙 범위 밖 —
  색 블록으로 대체).
- **FR-003**: 스플래시 화면의 브랜드 타이틀 텍스트는 굵은 글씨(font-weight
  800 상당)로 표시되어야 한다. 표시 문구("Alpharium" 원문 유지 — 아래
  Clarifications 참조)
- **FR-004**: 스플래시 화면 하단에는 안내 문구("휴대폰 안에서만")와 로딩
  표시(점 3개, 순서대로 강조·중간·비활성 색상)가 구분선 아래 좌우로
  배치되어야 한다.
- **FR-005**: 로딩 표시는 장식적 요소여야 하며, 실제 다운로드·초기화
  진행률을 계산하거나 표시해서는 안 된다(원칙 IV) — 정적 표시 또는 반복
  애니메이션은 허용되지만 숫자·퍼센트·모델명은 어떤 형태로도 노출되지
  않아야 한다.
- **FR-006**: 스플래시 화면은 정해진 시간 후 사용자 조작 없이 자동으로
  다음 단계(권한 요청 흐름)로 전환되어야 한다(기존 `LogoScreen`의
  `LOGO_DISPLAY_MS` 타이머 로직 재사용).
- **FR-007**: 권한 요청 흐름은 사진 → 사진 위치 → 위치 → 알림 → 배터리
  최적화 예외 순서를 유지해야 한다(021 `PERMISSION_REQUIREMENTS`의 고정
  순서를 그대로 재사용 — 이번 스펙은 순서·판정 로직을 재구현하지 않는다).
- **FR-008**: 각 권한 요청 단계는 사용자가 건너뛸 수 있어야 한다(021
  원칙 I 계승 — 필수 강제 아님).
- **FR-008a**: 사용자가 특정 권한을 "다시 묻지 않음"과 함께 거부해 OS가
  더 이상 권한 다이얼로그를 띄우지 않는 상태가 되면, 화면은 재요청을
  반복하지 않고 앱 설정 화면 이동을 안내해야 한다(021의 기존 안내 로직
  재사용, 문구·시각 스타일만 새 토큰으로 표시).
- **FR-009**: 권한 요청 화면(온보딩 화면)의 시각 스타일(배경색·텍스트
  색·강조색·모서리 반경)은 Modernist 토큰으로 교체되어야 하지만, 화면의
  레이아웃 구조(단계별 리스트 형태, 버튼 배치)는 이번 스펙에서 새로
  설계하지 않는다 — 기존 구조에 새 토큰만 입힌다.
- **FR-010**: 이미 온보딩을 완료한 사용자, 또는 이미 필요한 권한을
  보유한 사용자에게는 기존 게이트 로직(`onboardingGateNeeded`,
  `shouldShowLogo`)에 따라 스플래시·권한 화면이 다시 표시되지 않아야
  한다(021/040 로직 무변경).
- **FR-011**: 디자인 토큰(`src/ui/theme/tokens.ts`)의 `COLORS`는
  Modernist 팔레트(오프화이트 배경, 단일 레드 강조, 저채도 회색조 보조
  색)로 전면 교체되어야 하고, `RADIUS`는 모든 역할이 0(제로 라디우스)이
  되어야 한다.
- **FR-012**: 새 팔레트의 모든 텍스트/배경 조합은 기존 WCAG AA 대비 검증
  (`theme-tokens.test.ts` DT4, 본문 4.5:1 / 큰 텍스트 3:1)을 통과해야
  한다. 리뷰 보드 원본 accent 색(#ec3013)이 특정 조합에서 기준을 만족하지
  못하면, 배경/블록 전용 강조색과 텍스트 전용 강조색을 구분해 대안 값을
  적용한다(Clarifications 참조).
- **FR-013**: 이번 스펙은 `src/ui/` 중 스플래시 화면과 온보딩(권한 요청)
  화면 두 개의 시각 구현만 새로 작성한다. 그 외 화면(`DiaryHomeScreen`,
  `DiaryListScreen`, `DiaryDetailScreen`, `DayPicker`, `CharacterListScreen`,
  `AuthorPicker`, `AutoDiarySettingsScreen`, `DiagnosticsScreen`,
  `WelcomeScreen`, `WaitingForDownloadScreen` 등)은 토큰 값 교체가
  자동으로 상속되는 것 외에 레이아웃을 변경하지 않는다.
- **FR-014**: `src/diary/`, `src/models/`, `src/onboarding/`,
  `src/firstrun/`, `src/schedule/`, `src/signals/`, `src/vision/`,
  `src/inference/`, `src/app/` 등 로직 계층의 코드는 이번 스펙에서 한
  줄도 변경하지 않는다 — 순수 화면(뷰) 구현만 다룬다.
- **FR-015**: `src/ui/`는 기존 경계 검사(`checkSourceFile`)가 금지하는
  `models/roster`·`diary/prompt`·`ModelAsset`에 직접 접근해서는 안 된다.
- **FR-016**: 이번 스펙은 새로운 네이티브 의존성을 추가하지 않는다.

### Key Entities

이 스펙은 새로운 영속 데이터 타입을 만들지 않는다. 화면이 소비하는 기존
타입(`OnboardingFlag`, `PermissionRequirement`, `PermissionStatus` 등,
021/040이 이미 정의)을 읽기 전용으로 사용한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 실기기에서 온보딩이 필요한 상태로 앱을 실행했을 때, 스플래시
  화면이 리뷰 보드 마크업과 동일한 레이아웃 구조(로고 마크 위치, 타이틀
  위치, 하단 안내 문구·로딩 표시 위치)로 렌더되는 것을 육안으로 확인할 수
  있다.
- **SC-002**: 스플래시 화면에서 별도 조작 없이 5초 이내에 권한 요청
  흐름으로 자동 전환되는 것을 관찰할 수 있다.
- **SC-003**: 권한 요청 흐름의 5단계(사진·사진 위치·위치·알림·배터리
  예외)를 실기기에서 순서대로 거치며, 각 단계에서 허용·거부·건너뛰기
  중 하나를 선택했을 때 앱이 멈추거나 죽지 않고 다음 단계로 진행하는
  것을 확인할 수 있다.
- **SC-004**: 새 디자인 토큰 적용 후에도 기존 자동화 테스트
  (`npm test`, `npm run lint`)가 전부 통과한다.
- **SC-005**: 새 팔레트의 모든 텍스트/배경 조합이 WCAG AA 대비 기준을
  통과하는 것을 자동화 테스트(`theme-tokens.test.ts`)로 확인할 수 있다.

## Assumptions

- 마크업의 1l/1m/1n(사진·위치·알림 권한 다이얼로그)은 iOS 스타일 네이티브
  다이얼로그를 흉내낸 참고 자료이며, 이 저장소는 Android 전용이므로 실제
  구현은 Android OS가 제공하는 표준 권한 다이얼로그를 그대로 사용한다 —
  다이얼로그 자체의 커스텀 UI 구현은 범위 밖이다.
- 리뷰 보드가 요구하는 서체(Archivo)는 032 FR-019a("폰트 파일을 새로
  번들하지 않는다")를 계승해 시스템 기본 서체로 대체한다.
- 배터리 최적화 예외 요청은 021/040이 이미 구현한 흐름(설정 화면 유도,
  네이티브 다이얼로그 없음)을 그대로 재사용하며 이번 스펙에서 변경하지
  않는다.
- 스플래시 화면의 72×72 사각형은 실제 브랜드 로고 이미지가 아직 없는
  상태의 자리표시자(placeholder)이며, 향후 실제 로고 에셋이 준비되면
  별도 작업으로 교체한다.
