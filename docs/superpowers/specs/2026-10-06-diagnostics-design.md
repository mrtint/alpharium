## 목적

기존 `DiagnosticsScreen`(022·012·005·020)을 보드 `6h`의 모양으로 다시 그리고, 「지금 한 번 써 보기」를 홈의 쓰는 중(054)으로 잇고, 쓰기 실패를 기록(D3)한다.
진입은 059가 둔 「개발자 → 진단」 행 그대로다(개발 환경만, S7).

## 골격

1. **화면 틀**: `SettingsFrame`·`Group`·`Row`·`Value`(설정·개발자와 같은 부품, C7)로 일곱 묶음을 그린다 — 환경 / 저장 점검 / 사진 권한 / 신호 프로브 / 입력 프롬프트 미리보기 / 생성 / 최근 실패.
   `PermissionPanel`·`SignalProbe`·`PromptPreviewPanel`·`GenerationProbe`·`AutoDiaryTriggerButton`은 새 모양으로 교체한다(옛 모양 폴백을 남기지 않는다).
2. **최근 실패**: 별도 파일(`preferences/write-failures.json`)에 이유 갈래 + 시각만, 10건 상한(D3, S11). 걸린 시간 등 측정값 필드가 없다(원칙 IV). 홈의 쓰기 실패 경로(054 `toastKindFor`)가 기록한다.
   건너뜀은 넣지 않는다. 읽기·쓰기 실패는 던지지 않는다.
3. **지금 한 번 써 보기**: 진단을 닫고 홈의 오늘에서 쓰는 중으로 시작한다(덮어쓰기 확인 생략, 제품과 같은 경로 S10). 토스트 「진단에서 쓰기를 시작했어요.」 2초.
   홈의 쓰기 진입점을 바깥에서 부를 통로가 필요하다(057의 `autoWriteDay` 요청과 같은 방향).
4. **자동 쓰기 지금 실행**: 기존 `runAutoDiaryTask()` 호출을 유지하고 결과를 한 줄로 알린다.
5. **저장 점검**: 탭하면 다시 읽어 「{n}편 · 정상」/「{n}편 · {k}편 읽기 실패」. 고치지 않는다.
6. **사진 권한**: 읽기·위치 정보·범위(전체/선택한 사진만)를 따로 표시한다.
7. **신호 프로브**: 다섯 축, 사진·장소만 숫자, 나머지는 「모름」(회색 면·회색 글자). 열 때와 「다시 읽기」에만 읽는다. 헌법 검사 `DIAGNOSTICS_HIDES_AXES` 유지.
8. **프롬프트 미리보기**: 고정 프리셋 둘(S12). 기존 계약(PP1·`UI_TOUCHES_PROMPT`·PP6) 유지.
9. **문구**: §3.6 KO 표를 글자 단위 계약 테스트로 잠근다(047).

## 열린 결정 (clarify에서 확정)

실패 기록의 이유 갈래와 백그라운드 실패 기록 여부 · 「자동 쓰기 지금 실행」이 목표 시각 창을 무시하는가 · 캐릭터별 모델 줄을 지우는가 · 추론 위치의 CPU/GPU 표기 근거.
