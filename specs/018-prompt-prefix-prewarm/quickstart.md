# Quickstart: 일기 대기 시간 단축 검증

이 기능은 새 측정 코드를 만들지 않는다(헌법 원칙 IV) — 확인은 화면에
이미 있는 "일기를 작성하는 데 N초가 걸렸어요"(017,
`DiaryDetailScreen.tsx`) 표시를 사람이 직접 여러 차례 비교해 읽는
방식이다.

## 사전 준비

- 실기기(Android), dev 빌드, `EXPO_PUBLIC_APP_ENV=dev npx expo start
  --dev-client`로 Metro가 떠 있어야 한다(AGENTS.md 「도구 사용법」).
- 캐릭터 하나(예: `narrative`)가 이미 다운로드되어 준비 상태여야 한다.
- 사진이 없는 날 하나, 사진이 있는 날(3장 이상) 하나를 미리 파악해
  둔다 — 010의 `npm run seed:day`로 합성 데이터를 심어도 되지만,
  **품질 비교에는 쓰지 않는다**(AGENTS.md — 심은 하루로 품질을
  결론짓지 않는다). 여기서는 "경로가 도는가"와 "시간이 줄었는가"만
  본다.

## 검증 1 — 1단계: 사진 없는 날 (FR-005, SC-001)

1. 사진이 없는 날을 고르고, 캐릭터를 고른 뒤 **곧바로**(수 초 이내)
   "쓰기"를 누른다. 완성 시간을 기록한다(변경 전 기준값, 3회).
2. 같은 날·같은 캐릭터로, 캐릭터·날짜를 고른 뒤 **몇 초 이상 화면에
   머무른 다음** "쓰기"를 누른다. 완성 시간을 기록한다(3회).
3. **기대 결과**: 2번(대기 후)의 시간이 1번(즉시)보다 뚜렷하게
   짧다(원 문서 기준: 10초 이상 차이). 두 경우 모두 일기 내용은
   생성될 때마다 자연히 달라지되(같은 신호에서 같은 문체), 형식·분량
   면에서 이상 징후(잘림, 빈 본문, 언어 오류)가 없어야 한다.
4. **회귀 확인**: 1번(즉시 누름)의 시간이 이 기능 적용 전과 비슷한
   수준인지 확인한다 — 준비가 안 된 상태에서도 정상적으로(다만
   느리게) 완성되어야 한다(FR-002, Edge case).

## 검증 2 — 화면 이탈 후 정상 동작 (FR-008, Edge case)

1. 캐릭터·날짜를 고른 직후 홈 버튼으로 앱을 벗어난다.
2. 몇 초 뒤 앱으로 돌아와 곧바로 "쓰기"를 누른다.
3. **기대 결과**: 일기가 정상적으로 완성된다(느리더라도 오류 없음).
   기기를 다른 앱과 함께 잠시 써 보아(예: 다른 무거운 앱 실행) 메모리
   부족으로 인한 다른 앱의 강제 종료 등 이상 징후가 없는지도 함께
   살핀다(SC-005).

## 검증 3 — 2단계: 사진 있는 날 (FR-006, SC-002)

1. 사진이 3장 이상 있는 날을 고르고 캐릭터를 고른다.
2. 화면에서 사진을 미리 살펴보는 정도의 자연스러운 대기(사진 캡션이
   끝날 만큼, 대략 10~20초) 후 "쓰기"를 누른다.
3. **기대 결과**: 전체 대기(사진 읽기 + 글쓰기)가 이 기능 적용 전보다
   뚜렷하게 짧다. 완성된 일기가 그 사진들의 내용을 반영하는지
   확인한다(내용이 이 기능 적용 전과 같은 수준으로 사진을 반영해야
   한다 — 반영 정도 자체가 달라지면 회귀다).

## 검증 4 — 사진 읽기 도중 "쓰기"를 누름 (FR-006a, Clarification)

1. 사진이 있는 날을 고른 **직후**(캡션이 끝나기 전, 1~2초 이내) 곧바로
   "쓰기"를 누른다.
2. **기대 결과**: 새로 처음부터 다시 읽지 않고, 진행 중이던 읽기가
   끝난 뒤 이어서 생성된다 — 일기가 정상적으로 완성되고, 사진 읽기가
   두 번 도는 것으로 보이는 징후(캡션 단계가 유난히 오래 걸림, 로그에
   두 번의 VLM 로드)가 없어야 한다.

## 검증 5 — 날짜를 바꿈 (FR-009, User Story 2 시나리오 4)

1. 사진이 있는 날 A를 고르고 화면에 머물러 캡션이 끝나기를 기다린다.
2. "쓰기"를 누르기 전에 날짜를 사진이 있는 다른 날 B로 바꾼다.
3. 곧바로 "쓰기"를 누른다.
4. **기대 결과**: 완성된 일기가 B 날짜의 사진 내용만 반영한다 — A
   날짜의 캡션이 섞여 들어간 흔적(A에서만 나올 수 있는 구체적 사물·
   장소가 B의 일기에 등장하는 것)이 없어야 한다.

## 기기 없는 확인 (커밋 전 항상)

```
npm run test:logic   # engine-port/llama-port/prompt/on-device 로직
npm run test:ui       # DiaryHomeScreen 준비 트리거·자원 해제
npm run lint          # eslint + tsc + 헌법 검사 + prettier
```
