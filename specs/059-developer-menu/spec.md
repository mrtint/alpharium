- 「정보」 묶음의 버전 7번 탭 → 개발자 메뉴 켜기(남은 횟수 토스트·켜짐 강조·이미 켜짐 토스트·기기에 저장), 「개발자」 행.
- 개발자 화면 `6e`(개발 환경)·`6j`(배포 환경): 모듈 그룹(읽는·쓰는 모듈 상태·크기, 모듈 다시 받기), 다시 보기 그룹(온보딩부터 다시), 개발자 메뉴 끄기, 개발 환경의 「진단」 진입 행.

- 055가 설정 조립에서 걷은 옛 화면(`CharacterListScreen`·`PermissionsSection`·`AuthorPicker`)과 자기 테스트의 정리, 설정·개발자를 지나던 Maestro 흐름 열한 개 각각의 새 경로 수선 또는 폐기 결정.

- Wi-Fi 판정 외의 새 네이티브 모듈(연결 종류를 읽는 의존성 하나만 들인다 — Clarification Q2).

## Clarifications

### Session 2026-10-02

분해 설계 §3.5의 질문 넷을 저장소 소유자 지시대로 이 단계에서 정했다.

- Q: 개발자 화면의 「모듈 다시 받기」를 확인하면 앱이 이미 받은 모듈 파일을 어떻게 다루나? → A: 지우지 않는다. 필수 모듈을 다시 읽어 빠졌거나 잘린 것만 받고, 다 있으면 곧바로 홈으로 돌아온다(037, 055 `onRedownload`와 같은 경로) (FR-019).
- Q: 확인 문구의 「모바일 데이터로 {size}」를 위해 연결 종류를 읽는 새 의존성을 들이나? → A: 들인다(`expo-network`). Wi-Fi가 아님이 확인될 때만 그 문구를 보이고, 연결 종류를 읽지 못하면 모바일 문구를 보이지 않는다(모르는 것을 지어내지 않는다, 원칙 V). 새 네이티브 모듈이므로 dev 빌드를 다시 만들어야 한다 (FR-020, FR-030).
- Q: 「온보딩부터 다시」가 다운로드 동의·작명까지 다시 묻고 이미 받은 모듈을 다시 받으러 가나? → A: 끝난 단계는 건너뛴다. 로고 → 권한 안내만 다시 보이고 동의·작명·다운로드는 지금 판정(이미 동의함·작명함·모듈 있음)대로 지나간다. 기존 `forceOnboarding`과 같은 동작 (FR-022).
- Q: 개발 환경에서 「개발자 메뉴 끄기」는 그 실행 동안만 꺼지나? → A: 그 실행 동안만 꺼진다(세션 상태). 저장된 값은 건드리지 않고 다음 실행에 다시 켜진다. 꺼진 동안 7번 탭은 다시 켠다 (FR-008, FR-024).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 버전을 7번 눌러 개발자 메뉴를 켠다 (Priority: P1)

배포 환경 사용자가 설정 → 「정보」 → 「버전」을 1초 이내 간격으로 연달아 7번 누르면 개발자 메뉴가 켜지고 「개발자」 행이 「정보」 묶음 맨 아래에 나타난다.
4번째 탭부터는 「개발자 메뉴까지 {n}번 남았어요」 토스트가 남은 횟수를 알린다. 켜진 상태는 이 기기에 저장돼 앱을 다시 열어도 유지된다.

**Why this priority**: 개발자 화면에 닿는 유일한 길이다(051이 진입점을 없앴다). 이것이 없으면 모듈 다시 받기·온보딩 다시·진단 어느 것도 닿을 수 없다.

**Independent Test**: 배포 환경으로 띄운 앱의 설정에서 버전을 7번 눌러 「개발자」 행이 생기는지, 앱을 다시 열어도 남는지 본다.

**Acceptance Scenarios**:

1. **Given** 개발자 메뉴가 꺼져 있다, **When** 버전을 탭 사이 1초 이내로 7번 누른다, **Then** 「개발자」 행이 「정보」 묶음 맨 아래에 나타나고 「개발자 메뉴가 켜졌어요」(보조 「이 기기에서만」) 토스트가 2초 뜬다.
2. **Given** 개발자 메뉴가 꺼져 있다, **When** 4번째·5번째·6번째 탭을 누른다, **Then** 각각 「개발자 메뉴까지 3번 남았어요」·「2번」·「1번」 토스트가 뜬다(1~3번째 탭에는 토스트가 없다).
3. **Given** 3번째 탭까지 눌렀다, **When** 이전 탭으로부터 1초가 넘게 지난 뒤 누른다, **Then** 횟수는 처음부터 다시 센다(그 탭이 1번째다).
4. **Given** 개발자 메뉴가 켜졌다, **When** 앱을 닫았다 다시 열고 설정을 본다, **Then** 「개발자」 행이 그대로 있다.
5. **Given** 개발자 메뉴가 이미 켜져 있다, **When** 버전을 다시 7번 누른다, **Then** 「이미 켜져 있어요」 토스트가 2초 뜬다.
6. **Given** 방금 켜졌다, **When** 「개발자」 행이 나타난다, **Then** 옅은 빨강 바탕으로 강조되고 1.5초 뒤 사라진다. 이후 설정을 다시 열 때는 강조가 없다.
7. **Given** 개발 환경(`local`·`dev`)이다, **When** 설정을 연다, **Then** 7번 탭 없이 처음부터 「개발자」 행이 있다.

### User Story 2 - 개발자 화면에서 모듈 상태를 본다 (Priority: P1)

「개발자」 행을 누르면 개발자 화면이 오른쪽에서 밀려 들어온다. 「모듈」 그룹에 읽는 모듈(사진을 읽는 쪽)과 쓰는 모듈(일기를 쓰는 쪽)의 로드 상태와 크기가 고정폭 글꼴로 보인다(예: 「loaded · 610MB」). 모델 이름·사양은 없다. 머리글 오른쪽에는 버전이 있다 — 개발 환경은 「DEV · 1.0.0 (24)」, 배포 환경은 「1.0.0 (24)」.

**Why this priority**: 개발자 화면의 기본 내용이다. 사용자 보고를 받은 개발자가 기기에 모듈이 제대로 있는지 보는 첫 자리다.

**Independent Test**: 개발자 메뉴를 켠 뒤 개발자 화면을 열어 두 모듈의 상태·크기가 보이고 모델 이름이 없는지, 환경별 머리글을 본다.

**Acceptance Scenarios**:

1. **Given** 개발자 메뉴가 켜져 있다, **When** 「개발자」 행을 누른다, **Then** 개발자 화면이 열리고 제목 「개발자」, 뒤로 「‹ 설정」이 보인다.
2. **Given** 개발자 화면이다, **When** 「모듈」 그룹을 본다, **Then** 「읽는 모듈」·「쓰는 모듈」 두 행에 로드 상태와 크기가 있다.
3. **Given** 배포 환경이다, **When** 개발자 화면을 본다, **Then** 그룹이 「모듈」·「다시 보기」·「개발자 메뉴 끄기」뿐이다 — 「진단」 그룹이 없다(보드 `6j`).
4. **Given** 개발 환경이다, **When** 개발자 화면을 본다, **Then** 「진단」 그룹이 「모듈」과 「다시 보기」 사이에 있다(보드 `6e`).
5. **Given** 개발자 화면이 열려 있다, **When** 뒤로 가기(‹ 설정·시스템 뒤로)를 누른다, **Then** 설정으로 돌아간다.

### User Story 3 - 모듈을 다시 받는다 (Priority: P2)

개발자가 개발자 화면의 「모듈 다시 받기」를 누르면 확인이 뜨고, 확인하면 온보딩 다운로드 화면(진행 슬라이드)으로 가서 모듈을 받는다. 받는 동안 일기 쓰기는 할 수 없다. 설정에서 캐릭터 목록·내려받기가 사라진(055, S5) 뒤의 대체 경로다.

**Why this priority**: 모듈이 빠졌거나 깨진 기기를 되살리는 유일한 길이다. 쓰기 전 「캐릭터를 먼저 준비해야 한다」 안내의 「모듈 다시 받기」(055)는 이미 같은 경로를 쓴다.

**Independent Test**: 확인 대화상자에서 취소하면 아무 일도 없고, 확인하면 다운로드 화면이 뜨며 끝나면 홈으로 돌아오는지 본다(모듈 파일을 지우는 경로인지 먼저 코드로 확인한 뒤 실기기에서 누른다).

**Acceptance Scenarios**:

1. **Given** 개발자 화면이다, **When** 「모듈 다시 받기」를 누른다, **Then** 확인 대화상자가 뜬다.
2. **Given** 확인 대화상자가 떠 있다, **When** 취소·뒤로 가기를 누른다, **Then** 대화상자만 닫히고 아무것도 바뀌지 않는다.
3. **Given** 확인 대화상자가 떠 있다, **When** 확인한다, **Then** 앱이 온보딩 다운로드 진행 화면으로 가고, 필수 모듈이 준비되면 완료 확인을 거쳐 홈으로 돌아온다.
4. **Given** 필수 모듈이 이미 모두 준비돼 있다, **When** 「모듈 다시 받기」를 누른다, **Then** 받을 것이 없으므로 확인 대화상자를 열지 않고, 개발자 화면에 머문 채 「이미 모두 준비돼 있어요」(보드 밖 문구) 한 줄을 알린다.
5. **Given** 모듈을 받는 중이다, **When** 홈이나 설정으로 나가려 한다, **Then** 나갈 수 없다(진행 화면이 전부를 덮는다 — 045).

### User Story 4 - 온보딩부터 다시 본다 (Priority: P2)

개발자가 「다시 보기」 그룹의 「온보딩부터 다시」를 누르면 일기는 그대로 둔 채 첫 실행 흐름(로고 → 권한 → …)이 다시 시작된다. 설정에서 걷은 「권한 안내 다시 보기」(055)를 대신한다.

**Why this priority**: 권한 안내·첫 실행 문구를 개발자가 다시 보는 유일한 길이다.

**Independent Test**: 일기가 있는 기기에서 누른 뒤 첫 실행 흐름이 뜨고, 끝낸 뒤 일기가 그대로인지 본다.

**Acceptance Scenarios**:

1. **Given** 개발자 화면이다, **When** 「온보딩부터 다시」를 누른다, **Then** 첫 실행 흐름이 처음(로고)부터 다시 시작된다.
2. **Given** 1의 흐름이다, **When** 끝까지 마친다, **Then** 홈으로 돌아오고 기존 일기·이름·설정이 그대로다.
3. **Given** 1의 흐름이다, **When** 권한 단계를 모두 마친다, **Then** 이미 동의한 다운로드·이미 지은 이름·이미 받은 모듈은 다시 묻지 않고 지나간다.

### User Story 5 - 개발자 메뉴를 끈다 (Priority: P2)

개발자가 개발자 화면 맨 아래 「개발자 메뉴 끄기」를 누르면 개발자 메뉴가 꺼지고 설정의 「개발자」 행이 사라진다. 개발 환경에서는 그 실행 동안만 꺼지고 다음 실행에 다시 켜진다.

**Why this priority**: 켠 메뉴를 되돌리는 길이 없으면 일반 사용자 기기에서 흔적이 영구히 남는다.

**Independent Test**: 켠 뒤 끄고 「개발자」 행이 사라지는지, 앱을 다시 열어도 꺼져 있는지(배포) / 다시 켜져 있는지(개발) 본다.

**Acceptance Scenarios**:

1. **Given** 개발자 화면이다, **When** 「개발자 메뉴 끄기」를 누른다, **Then** 설정으로 돌아가고 「정보」 묶음에 「개발자」 행이 없다.
2. **Given** 배포 환경에서 껐다, **When** 앱을 다시 열고 설정을 본다, **Then** 꺼진 채다(저장된 켜짐 값이 지워졌다).
3. **Given** 개발 환경에서 껐다, **When** 앱을 다시 열고 설정을 본다, **Then** 「개발자」 행이 다시 있다(저장된 값은 그대로다).
4. **Given** 껐다(개발 환경은 그 실행 동안), **When** 버전을 다시 7번 누른다, **Then** 다시 켜진다(US1).

### User Story 6 - 개발 환경에서 진단에 들어간다 (Priority: P3)

개발 환경에서는 개발자 화면에 「진단」 그룹이 있고, 한 행(「진단」, 보조 「개발 빌드만」 표지)을 누르면 기존 진단 화면이 열린다. 진단 화면의 내용은 지금 그대로다.

**Why this priority**: 051 이후 진단·프롬프트 미리보기에 닿을 길이 없다. 진입만 되살린다 — 내용 개편은 별도 조각이다.

**Independent Test**: 개발 환경에서 「진단」 행으로 진단 화면이 열리고 뒤로 가면 개발자 화면으로 돌아오는지, 배포 환경에서는 행도 진단 화면도 없는지 본다.

**Acceptance Scenarios**:

1. **Given** 개발 환경의 개발자 화면이다, **When** 「진단」 행을 누른다, **Then** 기존 진단 화면이 열린다.
2. **Given** 진단 화면이다, **When** 뒤로 가기를 누른다, **Then** 개발자 화면으로 돌아온다.
3. **Given** 배포 환경이다, **When** 어떤 경로로도, **Then** 진단 화면은 그려지지도 열리지도 않는다(S7).

### User Story 7 - 걷은 옛 화면과 막힌 실기기 흐름을 정리한다 (Priority: P3)

055가 설정 조립에서 걷은 옛 캐릭터 목록·권한 섹션·작성자 고르기 화면과 그 테스트를 정리하고, 진입점이 없어 실행기(`FLOWS`) 밖에 있던 Maestro 흐름 열한 개를 새 경로로 고쳐 되살리거나 폐기를 정한다.

**Why this priority**: 쓰는 곳 없는 코드와 「등록 안 되어 아무것도 검증하지 않는 초록불」이 쌓이면 이후 조각의 계약 테스트가 헷갈린다(AGENTS 「FLOWS 등록」).

**Independent Test**: 정리 뒤 `npm test`·`npm run lint`가 통과하고, `FLOWS` 밖에 남은 흐름이 없거나 남은 것마다 폐기·보류 사유가 기록돼 있는지 본다.

**Acceptance Scenarios**:

1. **Given** 정리를 마쳤다, **When** 저장소를 본다, **Then** 쓰는 곳이 없어진 옛 화면 파일과 그 자기 테스트가 없고 다른 테스트가 그 파일을 읽지 않는다.
2. **Given** 열한 흐름 각각, **When** 결과를 본다, **Then** 새 경로로 고쳐 `FLOWS`에 등록됐거나 폐기됐다(폐기는 사유를 한 줄로 남긴다).

### Edge Cases

- **탭 사이가 정확히 1초**: 이내로 센다(1000ms 이하 포함, 1001ms부터 처음부터 다시 센다 — plan R12).
- **7번을 넘겨 계속 누름**: 이미 켜진 상태로 취급해 「이미 켜져 있어요」 토스트가 7번째마다 뜬다(7번 연속이 다시 채워질 때).
- **토스트 겹침**: 새 토스트는 이전 것을 대신한다(토스트는 한 번에 하나).
- **설정을 닫았다 열기**: 탭 횟수는 설정 겹이 열려 있는 동안만 이어진다(겹이 닫히면 비운다). 켜짐 강조는 켜진 그 순간만이다.
- **개발자 메뉴 켜짐 값을 읽지 못함·깨짐**: 꺼짐으로 본다(모르는 것을 켜짐으로 채우지 않는다, 원칙 V). 개발 환경은 파일과 무관하게 켜짐이다.
- **켜짐 값 저장 실패**: 그 실행 동안은 켜짐이다(세션 상태). 다음 실행에는 꺼져 있을 수 있다 — 실패를 숨기는 문구를 따로 두지 않는다.
- **모듈 크기를 읽지 못함**: 크기를 비운다(0·지어낸 값 금지, 058 FR-005와 같은 규칙). 상태는 읽은 대로 쓴다.
- **쓰는 중에 개발자 화면을 열고 「모듈 다시 받기」·「온보딩부터 다시」를 누름**: 두 동작 모두 프레임이 다른 화면으로 바뀌어 홈이 언마운트되므로 **먼저 쓰는 중인 홈을 멈춘다**(058 지우기·054 그만두기와 같은 경로, plan R6·R7 — 생성이 뒤에서 이어져 저장되지 않게). 멈춘 글은 저장되지 않는다.
- **개발자 화면에서 앱이 뒤로 갔다 돌아옴**: 개발자 겹이 그대로 열려 있다.
- **글꼴 2.0배**: 라벨·값이 한 줄에 안 들어가면 줄을 바꾸되 자르지 않는다(055 행 규칙). 대화상자는 안전 영역 안에서 스크롤된다(056 DLG8).
- **개발자 메뉴가 꺼진 채 개발자 겹이 열림**(끄기 직후): 겹은 설정으로 돌아가며 닫힌다 — 꺼진 메뉴로 개발자 화면이 남지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

**켜기 — 버전 7번 탭 (보드 `6c` ⑤·`6d`)**

- **FR-001**: 설정 「정보」 묶음의 「버전」 행을 누르는 탭 사이 간격이 1초 이내이면 연속으로 센다. 1초를 넘기면 그 탭을 1번째로 센다.
- **FR-002**: 연속 7번째 탭에서 개발자 메뉴를 켠다. 「개발자 메뉴가 켜졌어요」·보조 줄 「이 기기에서만」 토스트를 2초 보인다.
- **FR-003**: 연속 4번째 탭부터 6번째 탭까지 「개발자 메뉴까지 {n}번 남았어요」({n} = 7 − 탭 수 = 3, 2, 1)를 토스트로 보인다. 1~3번째 탭에는 토스트가 없다.
- **FR-004**: 이미 켜져 있을 때 연속 7번째 탭에서 「이미 켜져 있어요」를 2초 보이고 켜짐 상태·강조는 바꾸지 않는다. 이 상태에서 4~6번째 탭의 남은 횟수 토스트는 없다.
- **FR-005**: 연속 탭 판정(1초·7번·4번째부터 남은 횟수·이미 켜짐)은 「지금」을 인자로 받는 순수 함수다(`day-boundary.ts` 관례). 판정 결과는 「아무 일 없음 / 남은 횟수 n / 켜짐 / 이미 켜짐」을 가른다.
- **FR-006**: 켜지는 순간 「정보」 묶음 맨 아래에 「개발자」 행이 나타나고 옅은 빨강 바탕으로 강조되며 1.5초 뒤 사라진다. 이미 켜진 채 설정을 열 때 강조는 없다.
- **FR-007**: 개발자 메뉴 켜짐은 이 기기에 저장한다. 별도 파일(`preferences/` 아래)이며 `auto-diary.json`·온보딩 플래그 등 다른 설정 파일에 필드를 더하지 않는다(D3). 값은 켜짐 여부 하나뿐이고 시각·횟수·이력을 담지 않는다.
- **FR-008**: 개발 환경(`local`·`dev` — `showsOnScreen`으로 판정, D2)에서는 저장된 값과 무관하게 처음부터 켜져 있고 「개발자」 행은 강조 없이 항상 있다. 켜진 동안 7번 탭은 상태를 바꾸지 않는다(「이미 켜져 있어요」). 개발 환경에서 끄기(FR-024)로 그 실행 동안 꺼졌다면 7번 탭은 다시 켠다(FR-002·FR-006과 같다 — 저장 값은 쓰지 않는다).
- **FR-009**: 저장된 값을 읽지 못하거나 깨져 있으면 꺼짐으로 본다. 켜짐 값을 저장하지 못해도 그 실행에서는 켜진 채로 둔다.
- **FR-010**: 「개발자」 행은 라벨 「개발자」와 ›가 있고 누르면 개발자 화면이 오른쪽에서 밀려 들어온다(055 겹 쌓기). 행 모양은 055 설정 행 그대로다.

**개발자 화면 틀 (보드 `6e`·`6j`)**

- **FR-011**: 개발자 화면은 055 설정 틀(고정 머리, 큰 제목 「개발자」, 「‹ 설정」 뒤로, 회색 지면, 묶음 머리·행)을 쓴다. 머리글 오른쪽에 버전 문자열이 있다 — 개발 환경은 「DEV · {버전} ({빌드})」, 배포 환경은 「{버전} ({빌드})」(「DEV」 없음). 버전·빌드 값은 설정 「버전」 행과 같은 출처다(055).
- **FR-012**: 개발자 화면은 **설정 위에 쌓인다** — 개발자가 열려 있는 동안 설정 겹은 닫히지 않고 그대로 아래에 있다(「‹ 설정」으로 돌아가도 설정이 다시 밀려 들어오지 않는다). 개발자 겹이 열린 동안 아래 겹들(설정·홈)의 뒤로 가기는 등록되지 않는다 — 055의 겹 규칙(`active`·`covered`)을 그대로 따른다. 뒤로 가기·「‹ 설정」은 설정으로 돌아간다.
- **FR-013**: 배포 환경의 개발자 화면은 「모듈」·「다시 보기」 그룹과 「개발자 메뉴 끄기」뿐이다(`6j`). 개발 환경은 「모듈」 다음에 「진단」 그룹이 더해진다(`6e`). 진단·(범위 밖인) 상태 흉내는 `showsOnScreen` 경유로만 그린다(S7, `src/diagnostics/sink.ts`) — 배포 환경에서는 그룹도 컴포넌트도 만들어지지 않는다.

**모듈 그룹**

- **FR-014**: 「모듈」 그룹에 「읽는 모듈」(사진을 읽는 쪽)·「쓰는 모듈」(일기를 쓰는 쪽) 두 행을 둔다. 값은 로드 상태와 크기를 고정폭 글꼴로 한 줄에 보인다(예: 「loaded · 610MB」). 라벨은 보드 문구 그대로다. **모델 이름·파라미터 수·양자화를 보이지 않는다**(원칙 III).
- **FR-015**: 크기는 058의 용량 표기(1000 기준)를 쓴다. 읽는 모듈은 필수 모듈 중 사진을 읽는 쪽 둘의 합, 쓰는 모듈은 일기를 쓰는 쪽 하나의 크기다. 합계·키 판정은 `src/app/`에서 하고 화면은 문자열만 받는다(`UI_TOUCHES_ASSET`, 058 FR-006).
- **FR-016**: 로드 상태는 보드의 영문 상태어(`loaded` 등)를 그대로 쓴다. 상태·크기를 읽지 못한 모듈은 값을 비운다(지어내지 않는다, 원칙 V). 개발자 화면이 열릴 때 읽고 다시 받기에서 돌아오면 다시 읽는다.

**모듈 다시 받기 (보드 `6e` ①)**

- **FR-017**: 「모듈」 그룹의 「모듈 다시 받기」 행(›)을 누르면 확인 대화상자(050 `ConfirmDialog`)를 연다. 취소·뒤로 가기는 닫기만 한다. 덮개 탭은 닫지 않는다.
- **FR-018**: 확인하면 설정·개발자 겹을 닫고 온보딩 다운로드 진행 화면(045)으로 간다 — 055의 `onRedownload`와 같은 경로(다운로드 시작 표식·완료 확인을 먼저 되돌린 뒤 필수 모듈을 다시 읽는다). 받는 동안 일기 쓰기는 불가하고(진행 화면이 전부를 덮는다) 끝나면 완료 확인을 거쳐 홈으로 돌아온다.
- **FR-019**: 이미 모든 필수 모듈이 준비돼 있으면 받을 것이 없으므로 확인 대화상자를 열지 않고 개발자 화면에 머문 채 「이미 모두 준비돼 있어요」 토스트를 2초 보인다(plan R3 — 055의 「홈으로 돌아온다」는 쓰기 전 안내 화면에서 온 호출이라 맞았지만 개발자 화면에서는 조용히 홈으로 가면 아무 일도 안 일어난 것처럼 보인다). 이 경로는 이미 받은 모듈 파일을 **지우지 않는다**(037) — 없거나 잘린 것만 받는다.
- **FR-020**: 확인 문구는 무엇을 하는지(모듈을 받는다는 사실)를 말한다. 연결 종류를 읽어 Wi-Fi가 **아님이 확인되면** 확인 문구에 「모바일 데이터로 {size}」(보드 `dev.redownload.cellular`)를 보인다. Wi-Fi이거나 연결 종류를 읽지 못하면 그 문구를 보이지 않는다(모르는 것을 모바일로 채우지 않는다, 원칙 V). {size}는 이번에 받을 양(빠졌거나 잘린 모듈의 몫)이고 058 용량 표기(1000 기준)를 쓴다 — 받을 것이 없으면 확인 대신 FR-019대로 알린다. 연결 종류를 읽는 새 의존성(`expo-network`) 하나를 들인다. 읽기는 조립 계층이 하고 화면은 문자열만 받는다.

**온보딩부터 다시 (보드 `6e` ④)**

- **FR-021**: 「다시 보기」 그룹의 「온보딩부터 다시」 행(›)을 누르면 일기·이름·설정을 지우지 않고 첫 실행 흐름을 처음(로고)부터 다시 시작한다 — 021의 `forceOnboarding`과 같은 경로. 확인 대화상자는 두지 않는다(되돌릴 수 없는 데이터 손실이 없다).
- **FR-022**: 다시 시작한 흐름은 로고 → 권한 안내를 다시 보이고, 동의·작명·다운로드는 지금 첫 실행 흐름의 판정(045 `권한 → 동의 → 진행 → 작명` 중 이미 끝난 단계는 건너뜀)을 그대로 따른다. 보드 메모의 「온보딩 → 이름 짓기 → 권한 안내」 순서는 무시한다. 흐름을 마치면 홈으로 돌아온다.

**끄기 (보드 `6e` ⑤)**

- **FR-023**: 개발자 화면 맨 아래 「개발자 메뉴 끄기」를 누르면 개발자 메뉴를 끈다 — 저장된 켜짐 값을 지우고, 개발자 겹을 닫고 설정으로 돌아가며 「개발자」 행이 사라진다.
- **FR-024**: 개발 환경에서의 끄기는 그 실행 동안만 효과가 있다(세션 상태) — 저장된 값을 지우지 않고(개발 환경은 값과 무관하게 켜짐) 다음 실행에 다시 켜진다.

**진단 진입 (개발 환경 전용)**

- **FR-025**: 개발 환경의 「진단」 그룹은 한 행(라벨 「진단」, 표지 「개발 빌드만」, ›)이다. 누르면 기존 `DiagnosticsScreen`을 개발자 화면 위에 한 겹 더 쌓아 연다(내용은 지금 그대로). 뒤로 가기는 개발자 화면이다. 진단 화면 내용·보조 문구 개편은 하지 않는다(§3.6).

**정리**

- **FR-026**: 055가 설정 조립에서 걷은 옛 화면 파일(`CharacterListScreen`·`PermissionsSection`·`AuthorPicker`)과 그것만 읽는 자기 테스트·소스 계약을 정리한다. 쓰는 곳이 남은 것(다른 화면·계약 테스트가 기대는 것)은 plan이 확인해 남기거나 옮긴다.
- **FR-027**: 설정·개발자를 지나던 Maestro 흐름 열한 개(`diary-body-screen`·`diary-character-select`·`diary-user-path`·`download-conflict`·`model-acquisition`·`parallel-model-download`·`photo-vision`·`prompt-preview`·`scheduled-diary-notification`·`skeleton`·`welcome-naming`) 각각을 새 경로(개발 환경은 처음부터 켜짐 → 설정 → 개발자)로 고쳐 `scripts/run-device-tests.mjs`의 `FLOWS`에 되살리거나 폐기한다. 폐기는 사유를 한 줄로 남긴다. 고친 흐름은 기기에서 한 번 돌려 본다.

**공통**

- **FR-028**: 모든 새 문구는 보드 KO 원문이다(`about.developer`·`dev.*`) — `about.developer`는 `settings-text.ts`, `dev.*`는 `developer-text.ts`에 두고 계약 테스트가 글자 단위로 잠근다(C4). 보드 표에 없는 문구(다시 받기 확인의 제목·본문·버튼, 「이미 모두 준비돼 있어요」, 진단 겹 제목·뒤로)는 해요체이고 `developer-text.ts`에서 보드 밖임을 주석으로 표시한다(문구는 contracts TX).
- **FR-029**: 개발자 화면·행·토스트는 `tokens.ts`의 색만 쓴다. 새로 들이는 색은 보드 `accent-100`(`#fff2ef`, 「개발자」 행 켜짐 강조 바탕) 하나이고 `tokens.ts`에 이름을 붙여 둔다(C5). 토스트는 054의 토스트 틀을 재사용하되 문구·시간(2초)만 다르다.
- **FR-030**: 새 네이티브 모듈은 Wi-Fi 판정용 `expo-network` 하나뿐이다(FR-020). 새 모듈을 들이면 dev 빌드를 `expo prebuild` 뒤 다시 만들어 실기기에서 확인한다(AGENTS — 빌드 성공이 매니페스트·링크가 맞다는 뜻이 아니다). 헌법 검사(`UI_TOUCHES_ASSET`·`UI_TOUCHES_PROMPT` 등)가 계속 통과한다.

### Key Entities

- **개발자 메뉴 켜짐**: 이 기기에서 개발자 메뉴가 켜져 있는가. 값은 켜짐/꺼짐 하나이고 별도 파일에 저장된다. 개발 환경에서는 저장된 값보다 환경이 이긴다.
- **연속 탭 상태**: 「버전」 행을 연속으로 누른 횟수와 마지막 탭 시각. 설정 겹이 열려 있는 동안만 산다(저장하지 않는다).
- **모듈 줄(읽는/쓰는)**: 로드 상태 하나와 크기 문자열. 둘 다 못 읽을 수 있다(비움).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 배포 환경의 설정에서 버전을 탭 사이 1초 이내로 7번 누르면 100% 개발자 메뉴가 켜지고, 1초를 넘긴 탭이 끼면 0%다(횟수가 다시 시작).
- **SC-002**: 켠 뒤 앱을 완전히 닫았다 열어도 「개발자」 행이 유지되고, 끄기 뒤에는 (배포 환경에서) 다시 열어도 없다.
- **SC-003**: 배포 환경 개발자 화면의 어디에도 진단·상태 흉내 화면이 그려지지 않는다 — 소스 계약이 `showsOnScreen` 경유만 허용한다.
- **SC-004**: 개발자 화면 어디에도 모델 이름·파라미터·양자화 표기가 없다(소스·화면 문자열 검사).
- **SC-005**: 「모듈 다시 받기」·「온보딩부터 다시」 뒤에 기존 일기가 하나도 줄지 않는다(편수 전후 같음).
- **SC-006**: 확인 대화상자의 취소로 아무 것도 바뀌지 않는다(다운로드 화면에 가지 않고 모듈 파일 수·크기가 같다).
- **SC-007**: 정리 뒤 `FLOWS` 밖에 사유 없이 남은 Maestro 흐름이 0개이고 `npm test`·`npm run lint`가 통과한다.
- **SC-008**: 개발 환경 실기기에서 설정 → 개발자 → 진단 → 뒤로 → 뒤로로 홈까지 돌아오고, 그동안 쓰는 중이던 일기가 완주한다(홈 언마운트 없음).

## Assumptions

- 「개발 빌드 / 배포 빌드」는 코드의 환경(`local`·`dev` / `prod`)이다(D2). `__DEV__`를 쓰지 않는다.
- 필수 모듈은 사진을 읽는 둘과 일기를 쓰는 하나이고(`ESSENTIAL_ASSET_KEYS`, 058), 「읽는 모듈」은 앞의 둘, 「쓰는 모듈」은 뒤의 하나를 가리킨다. 보드의 「loaded」는 모듈 준비 상태의 영문 표기이며 준비 상태의 나머지 갈래(받다 만·없음·쓸 수 없음)를 `loaded`·`partial`·`missing`·`unusable` 넷으로 옮긴다(plan R4).
- 개발자 화면 안의 행 모양(라벨 15/600·값 고정폭·›)·묶음 머리·수치는 055 설정 틀 그대로이고, 보드 `6e`의 고유 수치(「DEV」 표지·「개발 빌드만」 표지의 모양)는 보드 마크업을 따른다.
- 실기기 확인은 dev 빌드로만 한다(release 없음, AGENTS). 「모듈 다시 받기」·「온보딩부터 다시」를 기기에서 누르기 전에 `files/`의 `diary`·`vision-cache`·`preferences`를 백업하고 모델 파일을 지우는 경로인지 코드로 먼저 확인한다. `pm clear`는 하지 않는다.
- 058 「지우기」 버튼 색 결정은 이 조각의 범위 밖이다.
- 상태 흉내(분해 설계 §3.7)는 이 조각이 만들지 않는다. 그것이 생기면 「개발자 메뉴 끄기」가 상태 흉내도 함께 끄도록 그 조각이 잇는다(보드 `6e` ⑤).
