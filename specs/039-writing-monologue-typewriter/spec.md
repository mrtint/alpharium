# Feature Specification: 생성 중 독백 문구 타자기 연출

**Feature Branch**: `039-writing-monologue-typewriter`

**Created**: 2026-09-11

**Status**: Draft

**Input**: User description: "생성 중 화면의 독백 문구에도 타자기 연출을 적용한다"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 독백 문구가 글자 단위로 나타난다 (Priority: P1)

일기를 쓰는 동안 사용자는 회전 표시와 함께 "글을 쓰는 중…" 같은 독백 문구를 본다.
이 문구가 화면에 나타날 때 한 번에 통째로 뜨는 대신, 앞서 완성된 일기 첫 표시에
적용된 것과 같은 방식으로 글자가 하나씩 이어지며 채워진다.

**Why this priority**: 038(완성된 일기 첫 표시 타자기)로 이미 이 저장소의 화면
전반에 자리 잡은 "글이 쓰이는 듯한" 인상을 생성 대기 화면까지 일관되게 넓히는
것이 이 기능의 유일한 목적이다. 이 문구 하나가 이 기능의 전부이므로 P1이다.

**Independent Test**: 일기 쓰기를 시작해 생성 중 화면에서 독백 문구가 바뀌는
순간(신호 확인→사진 보기→모델 준비→글쓰기 각 단계 전환, 또는 같은 단계 안에서
새 문구로 갱신되는 순간)을 관찰해, 문구가 즉시 전부 나타나지 않고 글자 단위로
이어지는 것으로 검증한다.

**Acceptance Scenarios**:

1. **Given** 생성 중 화면이 막 다음 단계로 넘어가 새 독백 문구를 고른 직후,
   **When** 그 순간을 관찰하면, **Then** 문구가 빈 상태에서 시작해 글자 단위로
   채워진다.
2. **Given** 독백 문구가 글자 단위로 채워지는 도중, **When** 문구 전환 조건
   (아래 단계로 넘어가거나 일정 시간 경과로 다음 무작위 문구로 교체)이 발생하면,
   **Then** 남은 글자를 마저 채우려 애쓰지 않고 새 문구가 다시 처음부터 글자
   단위로 시작한다(끊긴 채로 남지 않는다).
3. **Given** 생성이 끝나 결과 화면(완성/실패)으로 전환되는 순간, **When** 독백
   문구가 아직 다 채워지지 않은 상태였더라도, **Then** 그 문구의 잔여 애니메이션이
   결과 화면까지 이어지거나 잔상으로 남지 않는다.

---

### User Story 2 - 탭으로 건너뛰기 없음 (Priority: P2)

독백 문구는 사용자에게 실질적 정보를 담고 있지 않은 분위기 연출이므로, 038의
일기 본문과 달리 사용자가 이 문구를 다 보기 위해 애써 기다리거나 건너뛸 필요를
느끼지 않는다.

**Why this priority**: 038은 "완성된 결과"를 다 보고 싶어할 수 있어 건너뛰기가
필요했지만, 생성 중 문구는 다음 문구로 금방 자연 교체되는 짧은 것이라 별도 상호작용
설계의 우선순위가 낮다. 하지만 "탭해도 아무 반응이 없어야 한다"를 명시하지 않으면
구현자가 임의로 건너뛰기를 넣어 038의 조작 방식이 이 화면에도 있다고 착각할 수
있어 P2로 남긴다.

**Independent Test**: 생성 중 화면에서 문구가 채워지는 도중 화면을 탭해보고,
건너뛰기 동작이나 다른 화면 요소 변화가 없음(기존 "그만두기" 버튼 동작 제외)을
확인한다.

**Acceptance Scenarios**:

1. **Given** 독백 문구가 글자 단위로 채워지는 도중, **When** "그만두기" 버튼이
   아닌 화면의 다른 곳을 탭하면, **Then** 아무 일도 일어나지 않는다(문구가 즉시
   완성되지 않는다).

---

### User Story 3 - 기존 화면 규칙 무변경 (Priority: P1)

이 기능은 생성 중 화면에 이미 있는 문구가 나타나는 "방식"만 바꾼다 — 화면에
새 정보(진행률, 경과 시간, 생성 중인 일기 본문 등)를 추가하지 않는다.

**Why this priority**: 이 저장소의 헌법 원칙 IV(생성 중인 글이나 성능 지표를
보여주지 않는다)를 건드릴 위험이 가장 큰 지점이다. 독백 문구 자체는 이미 사람이
미리 써둔 고정 문장집합에서 고르는 것이라 원칙 위반이 아니지만, 구현 중 실수로
새로운 지표성 정보가 얹히면 안 되므로 이 경계를 별도 User Story로 명시한다.

**Independent Test**: 기능 적용 전후로 생성 중 화면을 촬영·비교해, 회전 표시 +
독백 문구 한 줄 + "그만두기" 버튼 구성이 그대로이고 그 외 요소가 늘지 않았음을
확인한다.

**Acceptance Scenarios**:

1. **Given** 생성 중 화면, **When** 이 기능이 적용된 이후를 관찰하면, **Then**
   진행률 숫자·경과 시간·생성 중인 일기 본문 등 이 기능 이전에 없던 정보가 여전히
   보이지 않는다.

---

### Edge Cases

- 문구가 매우 짧아(예: 한두 글자만 남기고 이미 다음 문구로 교체될 만큼 빠르게)
  전환되면? → 잔여 애니메이션을 강제로 끝까지 채우지 않고 새 문구로 즉시
  전환한다(US1 시나리오 2).
- 생성이 아주 빨리 끝나(예: 이미 데워둔 모델 + 신호 없는 하루) 독백 문구가
  한 번도 다 채워지기 전에 결과 화면으로 넘어가면? → 잔여 애니메이션이 다음
  화면으로 새지 않는다(US1 시나리오 3, 038의 등가 규칙과 동일한 원칙).
- 그만두기를 누르는 시점이 문구가 채워지는 도중이면? → 기존 "그만두기" 동작
  (생성 중단 → 목록 복귀)이 그대로 실행된다. 이 기능이 그만두기 버튼의 동작이나
  반응 속도를 바꾸지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 생성 중 화면은 독백 문구가 새로 정해질 때마다(단계 전환 또는 같은
  단계 안에서의 문구 교체) 그 문구를 한 번에 표시하는 대신 글자 단위로 순차
  노출해야 한다.
- **FR-002**: 문구가 아직 글자 단위로 채워지는 도중에 새 문구로 교체되는 조건이
  발생하면, 이전 문구의 잔여 글자를 채우려 시도하지 않고 새 문구를 처음부터
  글자 단위로 시작해야 한다.
- **FR-003**: 생성이 끝나 결과 화면(완성/실패/덮어쓰기 확인 등)으로 전환되면,
  독백 문구의 노출 애니메이션 상태가 그 화면들에 남거나 영향을 주지 않아야
  한다.
- **FR-004**: 이 연출은 화면을 탭해도 즉시 끝나거나 건너뛰어지지 않아야 한다
  (US2) — "그만두기" 버튼의 기존 동작은 변경하지 않는다.
- **FR-005**: 이 기능은 생성 중 화면에 회전 표시·독백 문구 한 줄·"그만두기"
  버튼 외의 새로운 정보(진행률 수치, 경과 시간, 생성 중인 일기 본문 등)를
  추가하지 않아야 한다(원칙 IV, US3).
- **FR-006**: 독백 문구 자체(문구 후보 집합, 고르는 규칙, 단계별 분기)는 이
  기능의 범위가 아니며 변경하지 않는다 — 오직 이미 정해진 문구가 화면에
  "나타나는 방식"만 바꾼다.
- **FR-007**: 글자 노출 간격은 038이 정한 값(사람이 정한 상수)과 같은 값을
  재사용해야 한다 — 화면마다 다른 타이핑 속도로 느껴지지 않게 한다.

### Key Entities

- **독백 문구(MonologueLine)**: 진행 단계·갈래별로 미리 정해진 문장 중 하나.
  이 기능에서는 그 문구가 "무엇인지"가 아니라 "어떻게 나타나는지"만 다룬다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 생성 중 화면에서 독백 문구가 바뀔 때마다 육안으로 글자가 하나씩
  이어지는 것이 관찰된다(038의 제목/본문 타이핑과 동일한 체감).
- **SC-002**: 문구가 채워지는 도중 다음 문구로 교체되는 경우, 화면에 이전 문구의
  글자가 섞여 남거나 깨진 상태로 보이지 않는다.
- **SC-003**: 생성 완료 직후 전환된 화면(완성/실패 등)에서 독백 문구의 타이핑
  애니메이션 잔상이나 오류가 관찰되지 않는다.
- **SC-004**: 이 기능 적용 전후로 생성 중 화면에 보이는 정보의 종류가 늘지
  않는다(회전 표시·문구 한 줄·그만두기 버튼, 그대로).
- **SC-005**: 생성 중 화면을 탭해도 문구가 즉시 완성되지 않는다.

## Assumptions

- 038(`REVEAL.charMs` — 글자당 노출 간격, `TypewriterText` 컴포넌트)이 이미
  구현·검증된 상태이며, 이 기능은 그 자산을 재사용하는 것을 전제로 한다.
- 독백 문구는 `src/diary/monologue.ts`의 `pickMonologue()`가 고르는 고정
  문장집합에서만 오며, 이 기능이 그 목록이나 선택 규칙을 바꾸지 않는다.
- 문구 교체 빈도(단계 전환 시점, 또는 같은 단계 안에서 몇 초마다 새 문구로
  바뀌는지)는 기존 `DiaryHomeScreen`의 생성 진행 콜백(`pipeline.run`의 진행
  콜백)이 정하는 대로이며, 이 기능이 그 주기를 바꾸지 않는다.
- 새 네이티브 의존성은 없다 — 038과 마찬가지로 코어 React/RN API만으로
  구현 가능하다고 가정한다.
