# Feature Specification: 다운로드 진행 화면(캐러셀 + 프로그레스 바) 완성

**Feature Branch**: `046-download-progress-carousel`

**Created**: 2026-09-21

**Status**: Draft

**Input**: User description: "다운로드 진행 화면(캐러셀 + 프로그레스 바) 완성 — 온보딩 첫 실행 흐름(043~045)에서
필수 자산(VLM v1/v2, 캐릭터 모델 a1) 다운로드 동의 이후 보여지는 진행 화면
(`DownloadProgressScreen`)이 계약(`resolveSlideStage`, `essentialDownloadFraction`)만
구현되어 있고 실제 화면은 미완성이다: 4초 자동 타이머로만 카드가 넘어가고 스와이프가
안 되며, 프로그레스 바 4칸이 실제 다운로드 진행률과 무관하게 정적이고 애니메이션이
없다. 다운로드 실패 시에는 전체 화면이 별도의 막다른 실패 화면으로 바뀌어 사용자가
수동으로 재시도해야 한다. 카드 캐러셀은 무한 순환(스와이프 + 4초 자동 전환 병행),
프로그레스 바는 캐러셀과 독립적으로 실제 합산 진행률을 4등분해 애니메이션과 함께
반영, 완료 시 버튼을 눌러야 다음 화면(작명)으로 진행, 실패 시 화면 전환 없이 하단
텍스트만 바뀌고 10초 간격 자동 재시도. 상세 설계는
`docs/superpowers/specs/2026-09-21-download-progress-carousel-design.md` 참조."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 다운로드가 진행되는 동안 계속 넘어가는 이야기 카드를 본다 (Priority: P1)

사용자가 첫 실행 다운로드 동의를 확인한 직후, 필수 자산이 받아지는 동안 이 앱이
무엇을 해주는지 설명하는 카드 4장을 넘겨 보며 기다린다. 카드는 가만히 있지 않고
손으로 넘길 수도 있고, 가만히 두면 저절로 다음 카드로 넘어간다. 마지막 카드에서
더 넘기면 다시 처음 카드로 돌아가— 몇 번을 넘겨도 막히지 않는다.

**Why this priority**: 지금 이 화면은 정적으로 멈춰 있는 것처럼 보여 사용자가 앱이
멈췄다고 오인하게 만든다. 카드가 실제로 움직이고 조작에 반응하는 것이
"다운로드가 살아서 진행 중"이라는 가장 기본적인 신뢰를 준다.

**Independent Test**: 온보딩 다운로드 동의를 확인한 뒤 이 화면에 진입해, 좌우로
스와이프했을 때 카드가 바뀌는지, 아무 조작 없이 몇 초 기다렸을 때도 카드가
자동으로 바뀌는지, 마지막 카드에서 계속 같은 방향으로 넘겼을 때 처음 카드로
되돌아오는지를 확인하는 것만으로 검증된다(다운로드 완료를 기다릴 필요 없음).

**Acceptance Scenarios**:

1. **Given** 사용자가 다운로드 동의를 확인해 진행 화면에 막 진입했다, **When** 아무
   조작도 하지 않고 기다린다, **Then** 일정 시간 뒤 카드가 다음 카드로 자동으로
   바뀐다.
2. **Given** 진행 화면에서 카드가 보이고 있다, **When** 사용자가 카드 영역을 손으로
   좌우로 스와이프한다, **Then** 스와이프 방향에 맞는 다음/이전 카드로 즉시
   바뀐다.
3. **Given** 사용자가 마지막(4번째) 카드를 보고 있다, **When** 같은 방향으로 한 번
   더 넘긴다, **Then** 첫 번째 카드로 돌아간다(막히지 않는다).
4. **Given** 사용자가 첫 번째 카드를 보고 있다, **When** 반대 방향으로 넘긴다,
   **Then** 마지막(4번째) 카드로 돌아간다.

### User Story 2 - 다운로드가 실제로 얼마나 진행됐는지 눈으로 확인한다 (Priority: P1)

사용자가 카드를 넘겨 보는 동안, 화면 하단의 진행 표시가 카드와 별개로 실제
다운로드 진행 상황을 보여준다. 진행 표시는 네 칸으로 나뉘어 있고, 받은 양만큼
칸이 채워지며 지금 채워지고 있는 칸은 움직임이 있어 "지금도 받고 있다"는 것이
느껴진다. 카드를 아무리 넘겨도 이 진행 표시는 흔들리지 않고 계속 쌓인다.

**Why this priority**: 지금 이 진행 바는 실제 다운로드량과 무관하게 정적이라
사용자가 "정말 다운로드가 되고 있는가"를 확인할 방법이 없다. 이야기 카드(US1)가
지루함을 달래는 장치라면, 이 진행 표시는 실제 상태를 정직하게 보여주는 유일한
근거다.

**Independent Test**: 다운로드가 진행되는 도중 화면을 관찰해, 시간이 지날수록
진행 칸이 채워지는 방향으로만 변하는지(줄어들지 않는지), 카드를 스와이프해도
진행 칸 상태가 그대로인지, 다운로드가 완전히 끝났을 때 네 칸이 모두 채워져
있는지를 확인하는 것으로 검증된다.

**Acceptance Scenarios**:

1. **Given** 다운로드가 막 시작되어 진행률이 낮다, **When** 시간이 지나며 자산을
   더 받는다, **Then** 진행 칸이 채워지는 양이 그만큼 늘어난다(줄어들지 않는다).
2. **Given** 진행 칸 중 하나가 부분적으로 채워지는 중이다, **When** 화면을 계속
   보고 있다, **Then** 그 칸에서 채워지고 있음을 알 수 있는 움직임이 보인다.
3. **Given** 사용자가 카드를 여러 번 스와이프해 다른 카드를 본다, **When** 진행
   표시를 다시 확인한다, **Then** 카드 전환 전과 같은(또는 그 사이 실제로 진행된
   만큼만 늘어난) 진행 상태를 보인다 — 카드 전환으로 리셋되지 않는다.
4. **Given** 필수 자산이 전부 받아졌다, **When** 진행 표시를 확인한다, **Then**
   네 칸이 전부 채워져 있다.

### User Story 3 - 다운로드가 끝나면 확인하고 다음으로 넘어간다 (Priority: P2)

다운로드가 전부 끝나면 카드 넘기는 화면 대신 "준비됐다"는 안내와 버튼 하나가
나온다. 사용자가 그 버튼을 직접 눌러야 다음 화면(이름 짓기)으로 넘어간다 —
자기도 모르는 새 화면이 휙 넘어가지 않는다.

**Why this priority**: US1·US2가 다운로드 "동안"의 경험이라면, 이건 그 경험을
매듭짓는 자리다. 사용자가 준비 완료를 인지할 틈도 없이 다음 화면으로 넘어가면
무엇이 끝났는지 모른 채 다음 단계를 마주하게 된다(045에서 이미 한 번 겪은
문제).

**Independent Test**: 필수 자산이 이미 준비된 상태로 이 화면에 진입해, 카드
대신 완료 안내와 버튼이 뜨는지, 버튼을 누르기 전까지 이 화면에 머무는지, 버튼을
누르면 다음 화면으로 넘어가는지를 확인하는 것으로 검증된다.

**Acceptance Scenarios**:

1. **Given** 필수 자산 다운로드가 전부 끝났다, **When** 화면을 확인한다, **Then**
   카드 대신 완료 안내 문구와 버튼 하나가 보인다.
2. **Given** 완료 안내 화면이 떠 있다, **When** 사용자가 아무것도 누르지 않는다,
   **Then** 화면은 자동으로 넘어가지 않고 그대로 머문다.
3. **Given** 완료 안내 화면이 떠 있다, **When** 사용자가 버튼을 누른다, **Then**
   다음 화면(이름 짓기)으로 넘어간다.

---

### User Story 4 - 다운로드가 멈춰도 사용자가 손 쓸 필요가 없다 (Priority: P2)

다운로드 도중 네트워크 문제 등으로 받는 것이 멈추면, 화면이 완전히 다른 실패
화면으로 바뀌지 않는다. 대신 지금까지 보던 카드와 진행 표시는 그대로 있고,
진행 표시 아래 안내 문구만 "받다가 멈췄다"는 내용으로 바뀐다. 사용자가 아무것도
누르지 않아도 앱이 스스로 다시 시도하며, 성공할 때까지 계속한다.

**Why this priority**: 지금은 실패하면 완전히 다른 막다른 화면으로 튕겨나가
사용자가 직접 재시도 버튼을 눌러야 한다 — 첫 실행에서 이런 기술적인 개입을
요구하는 것은 이 앱의 톤과 맞지 않는다. 다만 이건 실패라는 예외 상황에 대한
방어이므로 정상 경로(US1~US3)보다 우선순위가 낮다.

**Independent Test**: 다운로드 도중 네트워크를 끊어 실패를 유도한 뒤, 화면
레이아웃(카드·진행 표시)이 그대로인지, 안내 문구만 바뀌는지, 사용자 조작 없이
일정 시간 뒤 재시도가 일어나는지, 네트워크를 복구했을 때 결국 완료 화면까지
도달하는지를 확인하는 것으로 검증된다.

**Acceptance Scenarios**:

1. **Given** 다운로드 도중 자산을 받지 못하는 상태가 됐다, **When** 화면을
   확인한다, **Then** 카드·진행 표시 레이아웃은 그대로이고 진행 표시 아래
   안내 문구만 "받다가 멈췄다"는 내용으로 바뀐다.
2. **Given** 받지 못하는 상태로 화면에 안내 문구가 떠 있다, **When** 사용자가
   아무것도 하지 않고 기다린다, **Then** 앱이 스스로 다시 시도한다(사용자 조작
   불필요).
3. **Given** 반복된 재시도가 계속 실패하고 있다, **When** 원인이 되던 문제(예:
   네트워크 단절)가 해소된다, **Then** 이후 재시도에서 다운로드가 재개되어
   결국 완료 화면(US3)에 도달한다.
4. **Given** 받지 못하는 상태다, **When** 안내 문구를 확인한다, **Then** 실패의
   기술적인 원인(오류 메시지, 원인 코드 등)은 노출되지 않는다.

---

### Edge Cases

- 사용자가 카드를 매우 빠르게 연속으로 스와이프하면? → 카드 전환은 매번 정상
  반영되어야 하고, 진행 표시(US2)는 그 조작과 무관하게 영향받지 않아야 한다.
- 다운로드가 이 화면에 진입하기 전에 이미 100% 끝나 있었다면? → 카드 화면을
  거치지 않고 곧바로 완료 화면(US3)이 보여야 한다.
- 자동 재시도가 진행되는 도중 사용자가 앱을 완전히 종료했다가 다시 열면? → 이
  화면에 다시 진입했을 때 카드는 처음(1번째)부터 다시 시작하고, 진행 표시는
  실제 누적된 다운로드 상태를 반영한다(기존 045 계약 유지 — 세션 재시작 시
  카드 순서만 리셋, 진행률 자체는 파일 기반이라 유지).
- 진행률이 정확히 칸 경계(25%, 50%, 75%)에 걸쳐 있을 때 애니메이션 대상 칸은
  어느 것인가? → 그 경계를 막 채운 칸이 완전히 채워진 상태로, 다음 칸이 0%에서
  애니메이션을 시작하는 것으로 본다.
- 실패와 완료가 동시에 겹치는 순간(마지막 자산을 받다가 실패했지만 이미 다른
  자산은 다 받은 경우)은? → 전체가 100%가 아니므로 여전히 실패 처리(US4)로
  본다. 완료(US3)는 전체 100% 도달 시에만 보인다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 다운로드 동의가 확인된 직후, 지체 없이 필수 자산(VLM
  v1/v2, 캐릭터 모델 a1) 다운로드를 시작해야 한다.
- **FR-002**: 시스템은 다운로드가 진행되는 동안 이야기 카드 4장을 순서대로
  보여줘야 하며, 4번째 다음은 다시 1번째로, 1번째 이전은 다시 4번째로 이어지는
  끊김 없는 순환 구조여야 한다.
- **FR-003**: 사용자는 카드 영역을 손으로 좌우로 스와이프해 다음/이전 카드로
  즉시 전환할 수 있어야 한다.
- **FR-004**: 시스템은 사용자 조작이 없어도 일정한 간격으로 카드를 자동으로
  다음 카드로 전환해야 한다.
- **FR-005**: 시스템은 진행 표시를 4개의 구간으로 나누어 보여줘야 하며, 전체
  다운로드 진행률(0~100%의 연속값)에 비례해 구간이 순서대로 채워져야 한다
  (예: 전체 62% 완료 시 앞 두 구간은 완전히, 세 번째 구간은 절반 못 미치게
  채워짐).
- **FR-006**: 시스템은 현재 채워지고 있는 진행 구간에 진행 중임을 알 수 있는
  시각적 움직임을 줘야 한다.
- **FR-007**: 진행 표시는 카드 전환(수동 스와이프 또는 자동 전환)과 독립적으로
  동작해야 하며, 카드가 바뀌어도 리셋되거나 값이 줄어들어서는 안 된다.
- **FR-008**: 시스템은 필수 자산 전부가 준비 완료됐을 때, 카드 화면 대신 완료
  안내와 하나의 확인 조작(버튼)을 보여줘야 한다.
- **FR-009**: 시스템은 사용자가 완료 화면의 확인 조작을 실행하기 전까지 자동으로
  다음 화면으로 넘어가지 않아야 한다.
- **FR-010**: 사용자가 완료 화면의 확인 조작을 실행하면 시스템은 다음(작명)
  화면으로 전환해야 한다.
- **FR-011**: 다운로드가 진행되지 못하는 상태(실패)가 되면, 시스템은 카드·진행
  표시가 있는 같은 화면 레이아웃을 유지한 채 진행 표시 하단의 안내 문구만
  실패를 알리는 내용으로 바꿔야 한다 — 별도의 전체 화면 전환을 하지 않는다.
- **FR-012**: 시스템은 다운로드 실패 상태에서 사용자 조작 없이도 일정한 간격
  으로 자동으로 재시도해야 하며, 성공할 때까지 반복해야 한다.
- **FR-013**: 시스템은 실패 안내에 기술적인 오류 원문이나 실패의 구체적 원인을
  노출하지 않아야 한다.
- **FR-014**: 시스템은 다운로드 진행 화면 어디에도 자산의 식별자, 파일 크기,
  전송 속도, 정밀한 남은 시간과 같은 내부 지표를 노출하지 않아야 한다 — 사용자에게
  보이는 진행 신호는 완료까지의 비율(구간 채움 정도)뿐이어야 한다.

### Key Entities *(include if feature involves data)*

- **이야기 카드**: 사용자에게 앱의 가치를 설명하는 고정된 텍스트(제목·본문)와
  이미지 자리 하나로 구성된 항목. 4개가 고정 순서로 존재하며 그 내용 자체는
  이번 작업의 변경 대상이 아니다.
  캐러셀 안에서의 "현재 보고 있는 카드"라는 상태만 이번 작업이 새로 다룬다.
- **다운로드 진행률**: 필수 자산 전체에 대한 0~100% 사이의 단일 값. 기존
  계산 방식(합산 비율)을 그대로 사용하며, 이번 작업은 그 값을 4구간으로
  나누어 표시하는 방식만 새로 정의한다.
- **진행 화면 상태**: 지금 보여줄 것이 "카드 진행 중"인지 "완료 안내"인지를
  가르는 상태. 실패 여부는 이 상태와 별개로, 같은 화면 위에 겹쳐지는 안내
  문구로만 표현된다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자가 다운로드 진행 화면에서 아무 조작도 하지 않아도, 관찰
  중 카드가 최소 한 번 이상 자동으로 전환되는 것을 10초 이내에 확인할 수
  있다.
- **SC-002**: 사용자가 카드 영역을 스와이프하면 매번 예외 없이(반복 10회 기준)
  즉시 다음/이전 카드로 전환된다.
- **SC-003**: 사용자가 카드를 같은 방향으로 4회 이상 연속으로 넘겨도 화면이
  멈추거나 막히지 않고 항상 다음 카드가 나타난다(무한 순환).
- **SC-004**: 진행 표시는 다운로드가 진행되는 동안 관찰 시점마다 이전 관찰
  시점보다 같거나 더 채워진 상태로만 나타난다(퇴행 없음).
- **SC-005**: 필수 자산 다운로드가 완료된 시점에서 진행 표시의 4개 구간이
  전부 채워진 상태로 관찰된다.
- **SC-006**: 다운로드가 완료된 후 사용자가 확인 조작을 하기 전까지, 몇 초를
  기다려도 화면은 자동으로 전환되지 않는다.
- **SC-007**: 다운로드가 진행되지 못하는 상태가 발생했을 때, 사용자가 아무
  조작을 하지 않아도 문제가 해소되면(예: 네트워크 복구) 별도의 사용자 조작
  없이 결국 완료 화면에 도달한다.
- **SC-008**: 다운로드 실패가 발생해도 사용자는 화면이 완전히 바뀌었다고
  느끼지 않는다 — 카드·진행 표시의 위치와 모양은 실패 전후로 동일하게
  유지된다.

## Assumptions

- 이야기 카드 4장의 문구(제목·본문)와 이미지 자리(빈 placeholder)는 045에서
  이미 정해진 그대로 재사용하며, 이번 작업에서 문구나 실제 이미지를 새로
  만들지 않는다.
- "필수 자산 다운로드"의 대상(VLM v1/v2, 캐릭터 모델 a1)과 그 합산 진행률을
  계산하는 방식은 기존 로직을 그대로 사용하며, 이번 작업은 그 값을 소비하는
  화면 표현만 다룬다.
- 자동 카드 전환 간격은 기존에 정해진 값(4초)을 그대로 유지한다.
- 자동 재시도 간격은 10초로 하며, 성공할 때까지 횟수 제한 없이 반복한다.
- 이 화면에 진입하기 전 단계(다운로드 동의를 구하는 절차)와 이 화면 다음
  단계(캐릭터 이름 짓기)의 내용 자체는 이번 작업의 범위가 아니다 — 그
  전환 시점과 조건만 이번 작업이 다룬다.
- 사용자는 이 화면을 볼 때 인터넷 연결이 가능한 환경에 있다고 가정하되,
  일시적인 연결 문제(끊김)는 정상적으로 발생할 수 있는 상황으로 다룬다.
