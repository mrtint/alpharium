# Quickstart — 007이 됐는지 확인하는 법

**Date**: 2026-08-20 | **Plan**: [plan.md](plan.md)

**건너뛴 실기기 테스트는 통과가 아니다**(헌법 원칙 V). 기기 없이 전부 초록불이어도
온디바이스는 검증되지 않은 상태다.

## 0. 기기 없이 (항상 돈다)

```
npm test
npm run lint          # eslint + tsc + 헌법 검사
```

**기대**: 전부 통과. 새 테스트는 `__tests__/app/selection*.test.ts`,
`__tests__/ui/character-picker.test.tsx`에 있다.

### ⚠️ Windows에서 느리면 Defender다

`npm test`에 `--maxWorkers=50%`가 이미 붙어 있다. 그래도 느리면
`scripts/windows-dev-exclusions.ps1`을 **관리자 권한으로** 돌린다(AGENTS.md).

## 1. 실기기 준비 (셋 다 갖춰야 돈다)

```
adb devices                              # 기기가 보이는가
adb reverse tcp:8081 tcp:8081            # ⚠️ USB에서도 필요하다
adb shell dumpsys trust | grep deviceLocked   # 0이어야 한다 (PIN은 사람이)
EXPO_PUBLIC_APP_ENV=dev npx expo start --dev-client
```

**⚠️ 재부팅하면 `adb reverse`가 사라진다.** 다시 건다.

```
npm run test:device        # Maestro 흐름. FLOWS에 등록해야 돈다
```

## 2. Story 1 — 캐릭터를 고른다

### 2-1. 고르고 유지되는가 (FR-001·002·003, SC-001·002)

1. 캐릭터 화면에서 **둘 이상 준비한다** (`quiet`과 `imaginative` 권장 — 006에서
   출력 차이가 실측된 조합이다)
2. 일기 탭 → **「일기 쓰기」 자리에 지금 고른 캐릭터가 보이는가**
3. 다른 캐릭터로 바꾼다
4. **앱을 완전히 종료한다** — 최근 앱에서 밀어 없앤다. 홈 버튼만으로는 부족하다
5. 다시 연다 → **바꾼 캐릭터가 그대로인가**

**✅ 통과**: 4~5에서 선택이 유지된다.
**❌ 실패 신호**: 다시 열 때 첫 준비된 것으로 돌아간다 → 저장이 안 되고 있다.

### 2-2. 옮김과 알림 (FR-005·005a, SC-003a)

1. 캐릭터 A를 고른 상태에서
2. 캐릭터 화면에서 **A를 지운다**
3. 일기 탭으로 돌아온다

**✅ 통과**: 준비된 다른 캐릭터로 옮겨져 있고 **「옮겼다」는 알림이 보인다.**
**❌ 실패 신호**: 말없이 바뀌어 있다 → FR-005a 위반. 이것이 이 기능이 고치려는
문제 그 자체다.

4. 준비된 것을 **전부 지운다** → 「캐릭터를 먼저 준비해야 한다」로 가는가(FR-005c)

### 2-3. 자동으로 고르지 않는가 (FR-008)

**앱을 지웠다 다시 깐다** — 고른 적 없는 상태를 만드는 유일한 방법이다.

1. 캐릭터 하나를 준비한다 (아직 고르지는 않는다)
2. 일기 탭을 연다

**✅ 통과**: 「고른 것이 없다」 상태다. 준비된 것이 있어도 자동으로 골라지지 않는다.
**❌ 실패 신호**: 준비된 것이 이미 골라져 있다 → FR-008 위반.

### 2-4. 모델 정보가 새지 않는가 (FR-007, SC-011)

캐릭터를 고르는 자리를 **눈으로 훑는다.**

**✅ 통과**: 파라미터 수·양자화(`Q4_K_M`)·파일 크기·GB·속도가 **하나도 없다.**
`imaginative`에 「상상을 섞는다」 고지는 **있어야 한다**(헌법 로스터 MUST).

## 3. Story 2 — 30초를 견딘다

### 3-1. 회전 표시 (FR-010, SC-004)

1. 「일기 쓰기」를 누른다
2. **30초 동안 화면을 본다**

**✅ 통과**: 회전 표시가 계속 돌고 「쓰고 있다」가 있다.
**❌ 실패 신호**: 정지해 있다 → 앱이 멈춘 것과 구분되지 않는다.

### 3-2. 금지된 것이 없는가 (FR-011·012, SC-012·013)

같은 화면을 훑는다.

**✅ 통과**: 백분율·초·토큰 수·속도·**단계 이름**·생성 중인 글이 **하나도 없다.**
**❌ 실패 신호**: 「하루를 살펴보는 중」 같은 단계 표시 → FR-010b 위반.

### 3-3. ★ 그만두기 (FR-013~015, SC-005·006)

**이것이 007에서 처음으로 검증되는 것이다**(research §3 — 005 FR-014b의 배선이
끊겨 있었다).

1. 「일기 쓰기」를 누른다
2. **10초쯤 기다린 뒤** 「그만두기」를 누른다

**✅ 통과**:
- **10초 안에** 목록으로 돌아온다(SC-005)
- 그 하루의 일기가 **목록에 없다**(SC-006)
- **거기까지 쓴 글이 어디에도 보이지 않는다**(SC-006a)
- 앱이 죽지 않고 멈추지도 않는다

**❌ 실패 신호**:
- 목록으로 갔는데 **생성이 뒤에서 계속 돈다** → `stop`이 배선되지 않았다
- 「여기까지 썼다」로 글이 보인다 → FR-014a 위반

3. 곧바로 다시 「일기 쓰기」를 누른다 → 「이미 쓰고 있다」로 막힐 수 있다(정상)

### 3-4. 하드웨어 뒤로 가기 (FR-016)

생성 중에 **뒤로 가기**를 누른다.

**✅ 통과**: 그만두기와 같은 결과이거나, 쓰는 중 화면에 그대로 있다.
**❌ 실패 신호**: 말없이 목록으로 빠져나가고 생성이 뒤에 남는다.

## 4. Story 3 — 목록

### 4-1. 사진 세 갈래 (FR-018·019, SC-007·008)

**서로 다른 세 날을 만들어야 한다.**

| 만드는 법 | 나와야 할 것 |
| --- | --- |
| 사진이 있는 날 (권한 허용) | 「사진 N장」 |
| 사진이 없는 날 (권한 허용, 그날 사진 0) | **「사진 없음」** |
| 권한을 **거둔** 상태로 쓴 날 | **「사진 모름」** |

**✅ 통과**: 셋이 **서로 다른 문구**다.
**❌ 실패 신호**: 「없음」과 「모름」이 같은 말이다 → 원칙 V가 화면에서 무너졌다.

> 권한 거두기: 설정 → 앱 → 권한 → 사진. 004에서 이 방법으로 `unknown` 전환을
> 실측했다.

### 4-2. 나머지 신호가 없는가 (FR-018a, SC-008a)

**✅ 통과**: 목록 줄에 자리·걸음·배터리·연결이 **없다.**
**상세 화면에는 셋이 그대로 있어야 한다**(006 FR-032 유지).

## 5. Story 4 — 쓰기 전 안내

### 5-1. 어느 날을 쓰는가 (FR-023, SC-009)

**✅ 통과**: 「일기 쓰기」 자리에 쓰게 될 하루가 보인다. **오늘이 아니라 어제**다 —
오늘은 정의상 닫히지 않았다(006 FR-030).

### 5-2. 덮어쓰기 예고 (FR-024·025, SC-010·014)

1. 이미 일기가 있는 하루 상태에서 「일기 쓰기」 자리를 본다

**✅ 통과**: 「덮어쓴다」가 **누르기 전에** 보인다.

2. 그래도 누른다

**✅ 통과**: **약 30초가 걸린다** — 실제로 생성이 돈다.
**❌ 실패 신호**: **즉시 일기가 뜬다** → 저장된 것을 보여준 것이며 **헌법 원칙 I
위반**이다. 이것이 007에서 가장 위험한 실패다.

## 6. release 빌드에서 다시 (SC-016)

**debug에서 돌았다는 것이 release에서 돈다는 뜻이 아니다**(원칙 V).

```
npx expo prebuild --platform android --clean
cp ~/.alpharium-signing/alpharium.jks android/app/     # ★ prebuild가 지웠다
cd android && NODE_ENV=production ./gradlew assembleRelease
```

`android/app/build/gradle.properties`의 `versionCode`를 **올린다** — 같은 키로
서명하면 덮어 설치되고 일기가 남는다(006 SC-006).

```
adb install -r android/app/build/outputs/apk/release/app-release.apk
apksigner verify --print-certs <apk>     # CN=alpharium 이어야 한다
```

**Metro를 끄고 `adb reverse`를 지운 뒤** 앱을 연다.

| 확인 | 통과 |
| --- | --- |
| 회전 표시가 도는가 | R8·ProGuard에서 살아남았다 |
| 그만두기가 도는가 | JNI `stopCompletion`이 살아남았다 |
| 선택이 유지되는가 | 파일 통로가 살아남았다 |
| 시스템 막대와 안 겹치는가 | 006이 고친 것이 유지된다(SC-017) |

**⚠️ release는 `run-as`가 안 된다**(`package not debuggable`). 기기 안 파일을 볼 수
없으므로 **앱 화면으로 확인한다.**

## 7. 초록불을 믿기 전에 — 위반을 주입해 본다

기억에 남은 절차다(`alpharium-device-verification`). **방어가 실제로 도는지**는
어겨 봐야 안다.

| 주입 | 기대 |
| --- | --- |
| `AppScreen`의 `writing`에 `stage` 필드를 넣어 본다 | **테스트가 실패해야 한다**(SC-012) |
| 선택 파일에 로스터 밖 이름을 써 넣는다 | 「고른 것 없음」으로 떨어진다(계약 §2 표 4번) |
| 선택 파일을 깨뜨린다 | 앱이 죽지 않고 「고른 것 없음」(계약 §2 표 3번) |
| `CharacterPicker.tsx`에서 `roster.ts`를 import 해 본다 | **헌법 검사·리뷰가 잡아야 한다** |
