# Data Model: 로스터를 검증된 하나로 축소

**Phase 1** | 2026-09-09 | [plan.md](./plan.md) · [research.md](./research.md)

**저장 스키마 변경 0건.** 파일 형식·필드·경로가 그대로다. 바뀌는 것은
**타입의 넓이**와 **읽을 때의 방어**뿐이다.

---

## E1. `Character` — 캐릭터 식별자

**변경**: 유니온 다섯 → 하나.

```
전: "quiet" | "narrative" | "imaginative" | "chinese" | "english"
후: "quiet"
```

`CHARACTERS` 배열도 같이 줄어든다. 이 둘이 `src/diary/types.ts`에 있고
**저장소 전체가 여기서 캐릭터의 넓이를 얻는다.**

**성질**:
- 코드 안에만 있다. 설정·환경변수에서 읽지 않는다
- 유니온이 좁아지면 `Record<Character, …>` 리터럴들이 `tsc` 오류를 낸다
  (R1) — 이것이 변경 대상 탐지 수단이다
- **타입은 좁아지지만 런타임 값은 아니다** — 저장된 파일에는 여전히 옛
  캐릭터 문자열이 있다(E3 참조)

---

## E2. 캐릭터에 딸린 레코드들

전부 `Readonly<Record<Character, T>>` 형태이며 키가 하나로 준다.

| 자리 | 담는 것 | 축소 후 |
|---|---|---|
| `diary/persona.ts` `PERSONAS` | 이름·소개 | 금동이 하나 |
| `models/roster.ts` `ASSETS` | 모델 자산(키·URL·바이트·md5) | a1 하나 |
| `models/roster.ts` `DISPLAY_NAMES` | 진단용 모델 표시 이름 | kanana 하나 |
| `diary/prompt.ts` `LANGUAGE` | 출력 언어 | 한국어 하나 |

**불변식**: 네 레코드의 키 집합이 항상 같다. 하나만 줄이면 `tsc`가 잡는다.

## E3. `DiaryEntry` — 저장된 일기 ★ 핵심

**스키마 무변경.** 그러나 **읽을 때의 가정이 바뀐다.**

| 필드 | 타입 | 축소 후 주의 |
|---|---|---|
| `character` | `Character` | **파일에는 로스터 밖 값이 들어 있을 수 있다.** 타입은 좁아졌으나 디스크의 과거 값은 그대로 |
| `authorName` | `string \| undefined` | **옵셔널이다** — 035 이전 일기에는 없다 |
| 나머지(`date`·`text`·`title`·`signalsUsed`·`timing`·`photos`) | 그대로 | 영향 없음 |

### 이름 되짚기 규칙 (FR-008)

```
1. entry.authorName 이 있으면 → 그것
2. 없고, entry.character 가 로스터 안이면 → 사용자 지정 이름 또는 기본 이름
3. 없고, entry.character 가 로스터 밖이면 → 화면이 멈추지 않는 무언가
```

**3번이 이 기능이 새로 더하는 유일한 방어다.**

현행 `DiaryDetailScreen.tsx:167`은 1 → 2만 있고 3에서 `personaOf(로스터
밖)`이 `undefined`를 돌려줘 `.name`에서 멈춘다.

**`personaOf()`는 고치지 않는다**(R3) — 로스터 밖에 페르소나를 돌려주면
원칙 III의 경계가 흐려진다. 방어는 **읽는 쪽**에 둔다.

**"무언가"의 후보**(구현이 고른다):
- 이름 자리를 비우고 나머지(날짜·본문·사진)를 그대로 보인다
- 저장된 캐릭터 식별자를 그대로 보이는 것은 **안 된다** — 모델 식별자
  노출은 아니나 내부 심볼이 사용자 화면에 나오는 것은 006 이후 이 저장소가
  피해 온 것이다

## E4. `selected-character.json` — 마지막으로 쓴 캐릭터

**변경 0줄**(R2). `loadSelection()`의 `isCharacter()` 검사가 `CHARACTERS`를
쓰므로, 로스터가 줄면 옛 값이 자동으로 `null`이 된다.

```
파일에 "imaginative" → isCharacter() false → loadSelection() null
→ resolveSelection()이 "고른 적 없음"으로 처리 → 007 규칙대로 진행
```

**불변식**: 이 파일에서 읽은 값이 로스터 밖이면 캐릭터를 지어내지 않는다.
계약 테스트로 잠근다.

## E5. `AuthorOption` — 작성자 자리의 한 줄

**타입 변경 0건.** `AuthorPicker`는 이미 `options: readonly AuthorOption[]`을
받고 **index로 고른다**(화면은 `Character` 심볼을 모른다 — 007 경계).

```
options 길이 5 → 1
```

컴포넌트는 배열 길이에 무관하므로 **props도 렌더 로직도 안 고쳐도 된다.**
조립부(`App.tsx`)가 `CHARACTERS`를 돌며 만드는 배열이 자동으로 1개가 된다.

**남는 것**(FR-012·013): `onRename`·`nameMaxLength`가 그대로이므로 035의
사용자 지정 이름이 온전히 산다.

**주의**: 035가 실측한 두 결함이 유효하다 —
- 리스트 `key`는 위치여야 한다(표시 문자열을 키로 쓰면 이름 변경 시
  언마운트·리마운트)
- Maestro가 이 화면의 `Pressable` 좌표를 잘못 볼 수 있다(raw adb로 갈음)

## E6. 헌법 「로스터」 절

**데이터가 아니라 문서지만 이 기능의 1차 산출물이다.**

| 항목 | 전 | 후 |
|---|---|---|
| 한국어 캐릭터 | 3 | 1 |
| 외국어 캐릭터 | 2 | 0 |
| 원칙 III 진입 기준 | 없음 | **있음**(FR-002) |
| 버전 | 1.5.0 | **1.6.0** |

**남기는 조항**: "상상을 섞는 것은 특정 캐릭터만의 성질이 아니다" — 남는
캐릭터에도 해당하고, 방어선이 프롬프트라는 결론이 유효하다(FR-003).

## 상태 전이

이 기능에는 상태 기계가 없다. 캐릭터 준비 상태(003 readiness)는 그대로이며
캐릭터 수만 준다.

**단 하나의 전이 변화**(FR-010): 007의 *"고른 캐릭터가 준비를 잃으면 다른
것으로 옮기고 알린다"* 에서 **옮길 곳이 없어진다.**

```
전: 준비 잃음 → 다른 준비된 캐릭터로 옮김 → 화면에 알림
후: 준비 잃음 → 옮길 곳 없음 → 준비되지 않았음을 알림
```

말없이 실패하면 안 된다 — 006·008이 반복해서 겪은 "오류 없이 아무 일도
일어나지 않는" 실패다.
