# 축 경계면 계약 — US1 코어 루프

**대상**: 001 User Story 1
**전제**: [../data-model.md](../data-model.md)

001은 「축들이 무엇을 주고받는가」를 정한 스펙이다. 이 문서는 그 경계면을 US1이 요구하는
만큼 **호출 가능한 형태**로 옮긴다.

이 프로젝트의 반복 실패는 한 축이 자신에게 편한 입출력을 상정한 것이었다. 따라서 이
계약은 **각 축이 무엇을 받고 무엇을 내놓는지, 그리고 무엇에 접근할 수 없는지**를 함께
적는다.

---

## 경계면 1 — 퍼소나 → 추론

### 넘기는 것

| 값 | 근거 |
| --- | --- |
| 이름 | 002 FR-140 |
| 성격 (식별자 + 표시명 + 서술) | 002 FR-140·FR-141 |

**이 둘이 전부다.** 그 외의 값을 함께 넘기지 않는다 (002 FR-140).

### 넘기지 않는 것 (MUST NOT)

기기 정보, 관측 신호, 과거 일기, 이름 변경 이력 (002 FR-142).

### 검증 지점

- 넘겨지는 값을 전수 조사했을 때 위 둘 외의 것이 없다
- 기기 식별자가 달라져도 이름·성격이 동일하다 (001 SC-005)

## 경계면 2 — 수집·정제 → 추론

### 넘기는 것

**일별 집계 한 덩어리가 전부다** (003 FR-280). 형태는 [data-model.md](../data-model.md)의
엔티티 2.

집계에는 **FR-244의 항목 목록과 항목별 관측 여부 표시**가 그대로 담긴다 (003 FR-281).

### 추론 축이 할 수 없는 것 (MUST NOT)

| 금지 | 근거 |
| --- | --- |
| 원본 신호나 소스에 직접 접근 | 003 FR-280, 001 FR-008 |
| 전달받은 집계가 쓸 만한지 재판정 | 003 FR-282, 001 FR-013b |
| 「적음」을 이유로 거부하거나 다르게 취급 | 003 FR-282, 001 FR-043a |
| 미관측 항목을 값이 있는 것처럼 다룸 | 003 FR-283, 001 FR-010 |

**이 경계면의 핵심**: 「쓸 만한가」의 판단은 **수집·정제 축에만** 있다. 추론 축이 이
판단을 시작하면 그것이 품질 판정이 되고, 원칙 0이 금지한 「빈약해서 못 쓴다」로
미끄러진다.

### 규모 판정의 전달

집계에 **비어 있음 / 적음 / 보통** 중 하나가 함께 담긴다 (003 FR-270).

- **비어 있음** → 추론을 시도하지 않는다 (001 FR-013)
- **적음** → 추론은 정상 진행. 판정 결과는 **사용자 확인에만** 쓰인다 (003 FR-276)
- **보통** → 정상 진행

「적음」 판정은 집계의 내용이나 후속 처리를 바꾸지 않는다 (003 FR-276).

## 경계면 3 — 추론 → 저장

### 입력

| 값 | 근거 |
| --- | --- |
| 일별 집계 하나 | 001 FR-014 |
| 퍼소나 고정 정체성 | 001 FR-014 |
| 회상 슬롯 | 001 FR-015 — **US1에서 항상 비어 있다** |

### 성공 시 산출

**일기 한 편** — 날짜·퍼소나 귀속·본문 셋 (004 FR-300).

산출된 본문은 저장 축에 도달하기 전에 **두 관문**을 통과해야 한다:

1. **형식 검사** — 본문을 식별할 수 있고 비어 있지 않은가 (004 FR-340)
   - 본문 외의 내용이 덧붙어 있어도 본문을 식별할 수 있으면 성공 (004 FR-341)
2. **화자 판정** — 화자가 휴대폰인가 (004 FR-345)

### 화자 판정 계약 — research.md 결정 1

| 성질 | 요구 |
| --- | --- |
| 결정성 | 같은 본문에 항상 같은 결과 (004 FR-346, SC-309) |
| 재량 배제 | 사람의 판단이 개입하지 않는다 (004 FR-346) |
| 내용 비평가 | 판정 대상은 「누가 말하고 있는가」뿐 (004 FR-347) |
| 교정 금지 | 위반 시 고쳐서 저장하지 않는다 (004 FR-349) |

**판정기의 위치**: `AIEngine` 구현체 **밖**. 어댑터를 교체해도 같은 판정이 적용되어야
한다 (헌법 원칙 III).

**표지 목록은 이 계약에서 비운다** — 실측으로 채운다. 계약이 고정하는 것은 위 네 성질과
판정기의 위치뿐이다.

### 실패 네 가지 (004 FR-350)

| 실패 | 발생 지점 |
| --- | --- |
| 입력 구성 실패 | 모델 호출 **전** — 호출하지 않는다 (004 FR-352) |
| 모델 응답 실패 | 모델이 응답하지 않음 |
| 형식 실패 | 본문 식별 불가 또는 빈 본문 (004 FR-340) |
| 화자 위반 | 화자 판정 불통과 (004 FR-345) |

**어느 경우든**: 일기를 저장하지 않는다 (004 FR-351). 대체 문장으로 메우지 않는다
(004 FR-353). 재시도가 가능하다 (004 FR-354).

넷을 구별하는 이유는 006이 사용자에게 무엇이 갈리는지 알려야 하기 때문이다 (004 FR-350).
**사용자 표현 방식은 006의 몫이다** (004 FR-356).

### 추론 실패가 아닌 종료 — 사용자 취소·이탈 (001 FR-027)

004 FR-350의 넷과 **출처가 다르다.** 추론이 실패한 것이 아니라 완결되지 않은 것이므로
004의 실패 분류에 넣지 않는다. 다만 저장 축에 도달하지 않는다는 결과는 같다.

| 조건 | 요구 |
| --- | --- |
| 추론 중 사용자가 취소하거나 앱을 벗어남 | 완결되지 않은 일기를 저장하지 않는다. 부분 결과가 남지 않는다 (001 FR-027) |

**넷과 함께 검사하는 이유**: 부분 결과가 남는 경로는 실패 경로와 같은 자리에서 새고,
그것을 삼키면 헌법 원칙 II의 흔한 빠져나감이 된다.

## 경계면 4 — 저장 → UI

### 저장 축이 제공하는 것 (005 FR-470·FR-471)

US1이 쓰는 것만 옮긴다:

| 종류 | 항목 |
| --- | --- |
| 조회 | 보이는 기록의 목록, 특정 날짜의 기록 묶음 |
| 조작 | 기록 묶음 저장 |

**기록 묶음 저장은 전부 성공하거나 전부 실패한다** (005 FR-411). 실패 시 부분적으로
저장된 것을 남기지 않으며 사용자에게 알린다 (005 FR-412).

### 저장 축이 정하지 않는 것

조작의 화면 표현·확인 절차·진입 경로는 006의 몫이다 (005 FR-472).

### 재료 요약

저장 축은 재료 요약을 **주지 않는다**. UI가 집계에서 **파생해** 표시한다 (005 FR-473,
004 FR-304).

## 경계면 5 — UI가 도달해야 하는 것 (US1 범위)

006 FR-500의 다섯 자리 중 US1이 요구하는 것:

| 자리 | US1에서의 역할 | 근거 |
| --- | --- | --- |
| **오늘** | 생성 진입. 앱을 열었을 때 도달하는 자리 | 006 FR-501 |
| **기록 목록** | 보이는 기록만 나열. 상세로 이동 가능 | 006 FR-502·FR-503 |
| **일기 상세** | 본문 + 재료 요약 + **근거 집계** + 퍼소나 이름 | 006 FR-504 |

**퍼소나 자리·데이터 관리 자리는 US1 범위 밖**이다 (US3·US5).

### 일기 상세의 필수 구성 — 대조

006 FR-510이 **본문과 근거 집계의 대조를 일기 상세의 필수 구성**으로 두었다. 집계를
별도 영역으로 벗어나게 하지 않는다.

이것이 **이 앱의 유희가 성립하는 지점**이다 (001 FR-031). 부가 기능이 아니다.

### 집계 표시의 제약

| 요구 | 근거 |
| --- | --- |
| 미관측은 값-없음과 **구별**되어 보인다 | 006 FR-514, 001 FR-010 |
| 미관측을 결함·미완으로 표시하지 않는다 | 006 FR-515 |
| 재료 요약은 관측된 항목만 센다 | 006 FR-512 |
| 셀 대상이 없으면 0을 나열하지 않는다 | 006 FR-513 |

### 진행·실패 표시

| 요구 | 근거 |
| --- | --- |
| 생성 진행 중임이 나타난다 | 006 FR-520, 001 FR-041 |
| 요청은 완료 또는 실패 중 하나의 결말에 도달한다 | 006 FR-521 |
| 실패는 명시적으로 표시된다 — 조용히 지나가지 않는다 | 006 FR-522 |
| 실패 표시는 **다음에 할 수 있는 일이 갈리는 만큼** 구별된다 | 006 FR-523 |
| 어떤 실패 표시에서도 재시도 경로가 있다 | 006 FR-524 |
| 실패한 날짜는 **일기가 없는 날**로 표시된다 | 006 FR-525 |
| **추론 외의 실패도 알린다** — 집계·저장 실패 | 006 FR-528 |

**FR-528이 이 절의 핵심이다.** 추론 실패만 다루고 집계·저장 실패를 삼키는 것이 헌법
원칙 II의 흔한 빠져나감이다.

### 「적음」 확인 — 구조로 지키는 중립성

| 요구 | 근거 |
| --- | --- |
| 「적음」일 때**만** 표시한다 | 006 FR-540 |
| **진행이 기본 선택**이다 | 006 FR-542 |
| 부족·빈약·미흡·불충분 등 **평가어와 경고 기호를 쓰지 않는다** | 006 FR-543 |
| 전달하는 것은 **지금 반영되는 관측의 셈** | 006 FR-544 |
| 진행을 택하면 정상 생성·저장된다 | 006 FR-545, 001 SC-012 |
| 적다는 이유로 거부·지연하지 않는다 | 006 FR-546 |

**문면이 아니라 구조로 지킨다** — 기본 선택의 위치, 기호·색의 금지가 이 절의 핵심이다.
문장만 부드럽게 쓰고 취소를 기본 선택에 두면 그것은 게이트다.

## 개발 모드 표시 (헌법 원칙 I)

클라우드 어댑터를 쓰는 동안 **클라우드 사용 중임을 지나칠 수 없는 자리에 표시**한다
(006 FR-590~FR-593, 헌법 원칙 I의 개발 예외 조건 3).

프로덕션에서는 표시하지 않으며, 애초에 클라우드 어댑터가 번들에 포함되지 않는다.
