# Quickstart — 내려받기 충돌을 사용자에게 알린다

**Date**: 2026-08-21 | **Plan**: [plan.md](plan.md) | **계약**: [download-view.md](contracts/download-view.md)

**이 기능이 고쳐졌는지 확인하는 방법이다.** 검증 항목의 전체 목록은 계약의 검증 표(V1~V22)에
있고, 여기는 **그것을 실제로 돌리는 절차**다.

---

## 기기 없이 (항상 돈다)

```
npm run lint    # eslint + tsc + 헌법 검사
npm test
```

**둘 다 돌린다.** 007에서 **`npm test`만으로는 타입 위반이 잡히지 않았다** — 타입은
지워지므로 jest가 통과했고 **잡은 것은 `tsc`뿐이었다.** `tsc`는 `npm run lint`에 있다.

기대: 전부 통과. 007 기준선이 **700개**이며 이 기능이 더한 만큼 늘어난다.

**헌법 검사가 함께 돈다** — `src/ui/`가 `roster`·`assetFor`·`ModelAsset`에 닿으면
여기서 막힌다(007이 세운 규칙). 안내 문구에 크기를 넣으려면 그 import가 필요하므로
**FR-004 위반이 구조적으로 걸린다.**

### 초록불을 믿기 전에 — 위반을 주입해 본다

**테스트가 정말 잡는지 확인한다.** 007에서 「타입에 자리가 없으니 안전하다」가
`npm test`만 돌리는 사람에게는 거짓이었다.

| 주입할 것 | 어디에 | 걸려야 하는 것 |
| --- | --- | --- |
| `DownloadView`에 `elapsedMs: number` | `src/models/download-view.ts` | V7 (선언을 직접 읽는 검사) |
| 거부 시에도 `setProgress(null)` | `App.tsx` | V1·V9 |
| `notice`를 배열로 | `download-view.ts` | V5 |
| `import { assetFor }` | `CharacterListScreen.tsx` | 헌법 검사 |

**주입한 것은 반드시 되돌린다.**

## 실기기 — 여기가 이 기능의 진짜 검증이다

**두 버그 모두 「받는 중일 때만」 나타난다.** 그래서 기기 없는 테스트가 전부 초록불이어도
**아무것도 검증되지 않은 것일 수 있다**(원칙 V).

### 준비

003·007이 실측으로 확인한 세 가지가 갖춰져야 돈다. 하나라도 없으면 **화면에 값이
멀쩡히 있어도 실패한다.**

1. **Metro가 dev로 떠 있다** — `EXPO_PUBLIC_APP_ENV=dev npx expo start --dev-client`
   (변수를 앞에 붙이는 것이 핵심이다. `.env.dev`는 자동 로드되지 않는다)
2. **`adb reverse tcp:8081 tcp:8081`** — 연결 방식과 무관하게 필요하다. 재부팅으로 사라진다
3. **기기 잠금이 풀려 있다** — `adb shell dumpsys trust`의 `deviceLocked=0`

**Metro가 번들을 안 내주면**(「Loading from localhost:8081」에 머물면)
`npx expo start --clear`로 캐시를 지운다(007 실측).

### ⚠️ 실제 내려받기가 필요하다

**`quiet`을 쓴다** — 006·007에서 실기기 내려받기가 확인된 캐릭터다. 받는 데 시간이
걸리는 것이 여기서는 **유리하다**: 007의 「그만두기」는 생성이 2.4초라 Maestro 블록이
SKIPPED로 지나갔지만, GB 내려받기는 다른 것을 누를 시간이 넉넉하다.

**검증이 끝나면 지운다** — 003이 「지우기」를 만들어 두었다.

## F1 — 거부가 보인다 (FR-001·002·003, SC-001)

1. 캐릭터 탭 → `quiet`의 「준비하기」를 누른다
2. 진행률이 도는 것을 확인한다
3. **`narrative`의 「준비하기」를 누른다**

**통과**:
- 화면에 **거부되었다는 안내가 뜬다**(3초 안에)
- 안내에 **`quiet`**이 적혀 있다 (무엇을 멈춰야 하는지)
- 안내에 **멈추면 된다**는 것이 적혀 있다

**실패로 읽을 것**: 아무 일도 일어나지 않는다 = **버그 ①이 그대로다.**

**⚠️ 함께 볼 것**(SC-004): 안내에 크기·주소·모델 이름·시간·속도가 **하나도 없다.**

---

## F2 — ★ 받던 것이 사라지지 않는다 (FR-008·009, SC-002)

**이것이 버그 ②의 검증이며 이 기능의 핵심이다.**

F1에 이어서, `narrative`를 누른 **직후**:

**통과**:
- `quiet`의 줄에 **진행률이 그대로 있고 계속 오른다**
- `quiet`의 줄에 **멈추기 버튼이 그대로 있다**
- `narrative`의 줄은 **「받아야 함」 + 「준비하기」**다 (받는 중으로 보이지 않는다, FR-010)

**실패로 읽을 것**: `quiet`의 진행률과 멈추기가 사라진다 = **버그 ②가 그대로다.**
그때 사용자는 **갇힌다** — 멈출 수도 없고 다른 것을 받을 수도 없다.

---

## F3 — ★ 갇히지 않는다 (FR-009, SC-003) — 003 FR-020a의 첫 화면 검증

F2에 이어서, **화면에 보이는 버튼만으로**:

1. `quiet`의 **멈추기**를 누른다
2. `narrative`의 **준비하기**를 누른다

**통과**:
- 1에서 `quiet`이 멈추고 「받다 멈춤 — 이어받을 수 있음」이 된다
- **2에서 거부되지 않고 받기 시작한다**
- 거부 안내가 사라져 있다 (더 이상 참이 아니다, FR-005)

**★ 이것이 003 FR-020a가 약속한 것이며 지금까지 화면에서 실행 불가능했다.**

---

## F4 — 탭을 왕복해도 남는다 (FR-013·014, SC-006)

1. `quiet`을 받기 시작한다
2. **일기 탭으로 간다**
3. 캐릭터 탭으로 **돌아온다**

**통과**:
- `quiet`의 진행률과 멈추기 버튼이 **보인다**
- **★ 진척이 2단계 전보다 늘어 있다** (내려받기가 계속됐다, FR-014)

**⚠️ 이것이 research §2가 찾은 셋째 결함의 검증이다.** 지금 코드는 탭을 옮기면
`Acquisition` 인스턴스가 통째로 사라진다.

**⚠️ 진척이 늘지 않았다면 미해결 항목이 답을 얻은 것이다** — `expo-file-system`의
전송이 JS 참조와 함께 죽는다는 뜻이며, **원칙 V에 따라 관측한 대로 적는다.** 그 경우
FR-014를 다시 봐야 한다.

**10회 왕복**(SC-006): 매번 보이는지 본다.

## F5 — 백분율을 모를 때 (FR-017, 원칙 V)

F4에서 돌아온 **직후**를 본다.

**통과**: 백분율이 아직 없으면 **「받는 중…」**으로 보인다 — **숫자를 지어내지 않는다.**
다음 진행 콜백이 오면 백분율이 붙는다.

**실패로 읽을 것**: 「받는 중… 0%」가 보인다 = 모르는 것을 0으로 채운 것이다.

`quiet`을 받는 중에 `narrative`·`imaginative`·`chinese`를 **연달아** 누른다.

**통과**: 화면에 보이는 안내가 **하나**다. 세 줄이 쌓이지 않는다.

**통과**: 안내가 사라지고, **받던 것은 그대로다**(진행률·멈추기가 남아 있다).

**통과**: 진행률이 붙은 줄이 **언제나 최대 하나**다. 003 FR-020이 유지된다.

## F9 — release에서 확인한다 (SC-007)

```
npx expo prebuild --platform android --clean
cp ~/.alpharium-signing/alpharium.jks android/app/     # ★ prebuild가 지웠다
cd android && NODE_ENV=production ./gradlew assembleRelease
```

**세 줄을 다 한다** — `--clean`을 건너뛰면 매니페스트가 낡고(004의 교훈), 가운데 줄을
건너뛰면 키가 없다(006의 교훈).

**확인**:

| 무엇 | 어떻게 | 통과 |
| --- | --- | --- |
| 서명 | `apksigner verify --print-certs <apk>` | **`CN=alpharium`** |
| 새 문구가 R8에서 산다 | F1을 다시 돈다 | 거부 안내가 보인다 |
| 진행 유지가 R8에서 산다 | F2를 다시 돈다 | 진행률·멈추기가 남는다 |

**⚠️ release는 좌표가 다르다** — 진단 패널이 없어 모든 것이 위로 올라온다(007 실측).

**⚠️ debug↔release는 서명이 달라 덮어 설치가 거부된다.** 지우고 깔아야 하며 **그때
일기와 모델이 사라진다.** `quiet`을 다시 받아야 한다.

## Maestro 흐름

새 흐름을 만들면 **`scripts/run-device-tests.mjs`의 `FLOWS`에 등록한다.** 등록하지
않으면 초록불인데 아무것도 검증되지 않는다 — 원칙 V가 막으려는 바로 그 상황이다.

```
npm run test:device
```

**007이 실측으로 얻은 주의**:

1. **부분 문자열은 정규식으로** — `"받는 중"`은 「받는 중… 42%」와 맞지 않는다.
   `.*받는 중.*`으로 준다
2. **조건을 좁게** — dev에는 진단 패널이 함께 떠서 목록 밖의 글자가 걸린다
3. **화면 아래 것은 `scrollUntilVisible`** — 캐릭터 다섯이 화면을 넘긴다
4. **`uiautomator dump`가 실패하면**(「could not get idle state」) 화면이 움직이는
   중이다 — 내려받기 진행 중에는 정상이며 `screencap`으로 본다

**★ SKIPPED가 나오면 통과가 아니다**(원칙 V). 손으로 확인하고 결과를 AGENTS.md에 적는다.
