# Contract: 눌림 피드백 불변식 (PF)

**Feature**: 033-character-screen-press-feedback

reanimated를 이 저장소에서 **처음 실제로 쓰는** 계약이다. 032가 의존성만 들여놓고
`src/ui/`에서 import 0건이던 상태를 끝낸다.

---

## PF1 — 세기·시간은 토큰 한 곳의 상수다

`src/ui/theme/tokens.ts`가 `PRESS = { scale, durationMs }`를 `as const`로 export한다.

- **사람이 정한 값이다**(헌법 원칙 V). 코드가 화면·상태·기기를 보고 계산하지
  않는다 — 조건 분기나 `Math.*` 유도가 들어가면 위반이다.
- **참조하는 파일은 `Button.tsx`·`ListRow.tsx` 둘뿐**(spec SC-008). 계약 테스트가
  저장소를 훑어 `PRESS` 참조 파일 수를 세어 잠근다.
- 화면 파일(`src/ui/*.tsx`)이 `PRESS`를 import하지 않는다.

## PF2 — 새 컴포넌트를 만들지 않는다

`src/ui/components/`의 파일 수가 **7개 그대로**다(spec FR-016a). 눌림 반응 전용
컴포넌트·HOC·커스텀 훅 파일을 새로 두지 않는다.

**근거**: 032가 만들고 안 쓴 컴포넌트 4개를 남긴 것이 이 스펙의 존재 이유다.
같은 실패(쓸 자리 없는 추상을 먼저 만듦)를 되풀이하지 않는다. 세 번째 소비자가
생기면 그때 빼낸다.

## PF3 — 눌린 것이 보이고 떼면 돌아온다

`Button`과 `ListRow`(`onPress`가 있는 경우)가:

- `onPressIn` → 크기가 `PRESS.scale`로 줄어든다
- `onPressOut` → 크기가 `1`로 돌아온다
- 둘 다 `PRESS.durationMs` 동안 부드럽게 이어진다

**검사**: 계약 테스트가 `onPressIn`/`onPressOut` 핸들러의 **존재와 배선**을
확인한다. 실제 시각적 움직임은 jest가 못 본다(PF7).

## PF4 — 자리·크기 배치를 바꾸지 않는다

눌림 반응은 **변형(transform)** 으로만 일어난다. `width`·`height`·`margin`·
`padding`·`flex`를 애니메이션하지 않는다 — 그러면 주변 요소가 밀려나며 목록 전체가
출렁인다(spec FR-013).

## PF5 — 탭의 결과를 바꾸지 않는다

- `onPress`가 불리는 조건·횟수·시점이 이관 전과 같다.
- 눌렀다가 **밖으로 끌고 나가 떼면 `onPress`가 안 불린다**(RN `Pressable`의 기존
  동작 그대로 — 눌림 반응이 이것을 가로채지 않는다).
- 눌림 반응이 `onPress`를 지연시키거나 삼키지 않는다.

**검사**: `Button`·`ListRow`의 **기존 테스트가 무수정 통과**하는 것이 이 계약의
1차 증거다.

## PF6 — 비활성은 반응하지 않는다

`disabled`인 `Button`·`ListRow`는 눌림 반응을 주지 않는다(spec FR-015). 반응만
있고 아무 일도 안 일어나면 008이 고쳤던 「버튼이 고장났다」 인상이 돌아온다.

## PF7 — ★ 기기 없는 테스트는 "배선됐는가"만 잠근다

**reanimated는 jest에서 목으로 대체된다**(research R2 — 실측). 따라서:

- 계약 테스트가 검증할 수 있는 것: 핸들러가 있는가, `PRESS`를 참조하는가,
  참조 파일이 둘뿐인가, 기존 동작이 안 깨졌는가.
- 계약 테스트가 **검증할 수 없는 것**: 실제로 움직이는가, 부드러운가, worklet이
  UI 스레드에서 도는가.

**후자는 실기기 육안(spec FR-022)이 유일한 통로다.** 초록불을 "동작한다"로 읽지
않는다 — 011(`has_media=0`)·013(URI 계약)·020(헤드리스 `defineTask`)이 전부
"기기 없는 테스트 전부 통과 + 실기기에서 조용히 안 됨"이었다.

**특히 `babel.config.js`의 worklets 플러그인 누락은 jest가 구조적으로 못 잡는다**
(research R1). 목이 진짜 reanimated를 대신하므로, 플러그인이 없어도 테스트는
초록이다.

## PF8 — 새 수치를 만들지 않는다 (원칙 IV)

- 눌림 반응이 화면에 **어떤 숫자도 새로 표시하지 않는다.**
- 애니메이션 성능(프레임·지속시간 실측)을 재거나 기록하는 코드가 없다.
- 생성 중 화면(`screen.kind === "writing"`)에 진행률·경과 시간·생성 중인 글이
  **여전히 0개**다(005 FR-028b, spec SC-006).
- 다운로드 진행 문장(`받는 중… N%`)은 **현행 그대로** — 인디케이터를 꾸미면서
  새 수치·비교·예상 시간을 만들지 않는다(spec FR-019).

**검사**: 계약 테스트가 소스에서 금지 어휘(`fps`·`frame`·`elapsed`·`duration` 표시
문자열 등)의 부재를 확인하고, 생성 중 뷰의 기존 미노출 테스트가 계속 통과한다.
