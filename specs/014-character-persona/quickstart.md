# Quickstart: 캐릭터 페르소나

이 문서는 014가 끝났음을 확인하는 절차다. 기기 없는 검증(D0)과 실기기 검증(D1~D8)으로
나뉜다. 새 의존이 없고 새 네이티브 모듈도 없으므로 AGENTS.md 「실기기 검증 범위」
기준상 **debug 1회로 충분**하다 — release 재확인은 필요 없다.

## D0 — 기기 없는 검증

```
npm run test:logic
npm run test:ui
npm run lint
```

**통과 기준**:
- `persona.test.ts`가 P1~P4(contracts/persona.md)를 검증한다
- `title.test.ts`가 P1~P4(contracts/title.md)를 검증한다
- `acceptance.test.ts`의 A-7(판정 갈래가 넷임을 세는 테스트)이 그대로 통과한다 —
  이 기능이 `judge()`를 건드리지 않았다는 증거
- 위반 주입: `persona.ts`에서 `roster.ts`를 import해 보면 헌법 검사가 걸려야 한다
- 위반 주입: `title.ts`의 반환 타입에 `parsedAt: Date` 같은 필드를 추가해 보면
  contracts P4 테스트(선언을 직접 읽는 것)가 걸려야 한다
- `character-list.test.tsx`·`character-picker.test.tsx`(있다면)가 이름·소개
  텍스트가 렌더링되고 내부 식별자 문자열이 렌더링되지 않는 것을 검사한다

## D1 — debug 빌드로 실기기에 올린다

```
npx expo run:android --device
```

새 네이티브 모듈이 없으므로 `prebuild --clean`이 필요 없다(기존 매니페스트가
이미 맞다) — 다만 확신이 없으면 002~013의 관례대로 한 번 돌려도 안전하다.

## D2 — 캐릭터 목록에서 이름·소개를 본다 (FR-001~004, SC-001)

캐릭터 탭을 연다.

**확인**:
- 다섯 줄 모두 금동이·루이·오드·샤오바이·모카 이름이 보인다
- 각 줄에 한 줄 소개가 보인다
- `quiet`·`narrative` 같은 내부 식별자가 화면 어디에도 안 보인다
- 007의 `IMAGINATIVE_NOTICE`("상상을 섞어 씁니다")가 오드의 소개로 자연스럽게
  흡수되어 있거나, 소개와 별도로 여전히 표시된다(어느 쪽이든 고지 자체는 사라지지
  않아야 한다 — 헌법 로스터 MUST)

## D3 — 일기 탭 「누가 쓸까」에서도 이름을 본다 (FR-001)

일기 탭을 연다.

**확인**: `CharacterPicker`의 다섯 줄도 D2와 동일하게 이름·소개로 보인다.

## D4 — 캐릭터가 옮겨질 때 이름으로 안내한다 (FR-005)

준비된 캐릭터 중 하나를 고른 뒤, 캐릭터 탭에서 그 모델을 지운다. 일기 탭으로
돌아온다.

**확인**: "○○을(를) 쓸 수 없어 △△(으)로 바꿨다" 안내가 내부 식별자가 아니라
이름으로 나온다.

## D5 — 제목이 붙은 일기를 생성한다 (FR-006~011, SC-002)

신호가 있는 하루(사진이 있는 날)로 일기를 생성한다. 다섯 캐릭터 중 최소 2개
이상으로 반복한다.

**확인**:
- 목록 줄에 제목이 보인다(있는 경우)
- 상세 화면에도 제목이 보인다
- 제목이 안 붙은 경우가 있어도(모델이 형식을 안 지킨 경우) 일기 생성 자체가
  실패하지 않고 날짜만으로 정상 저장된다 — **거부되지 않는다**(FR-009)
- **관측 기록**: 40자 상한(research.md R2)이 실제로 적절한지, 특히 `narrative`
  (길게 쓰는 캐릭터)에서 제목이 너무 길어 상한에 걸려 통째로 미채택되는 사례가
  있는지 적는다. 있으면 상수 조정을 후속 관측으로 남긴다.

## D6 — 지어내기가 줄었는지 사람이 읽어 확인한다 (FR-012~013, SC-003, SC-004)

010의 `seed:day` 도구로 신호가 `unknown`/`none` 위주인 합성 하루를 만들거나,
실제로 그런 하루(사진 권한 없음 등)로 다섯 캐릭터 각각 최소 1건씩 생성한다.

**확인**:
- 생성된 일기를 사람이 읽고, 기록에 없는 구체적 사물·사건(날씨, 먹은 것, 만난
  사람 등)을 확정형 어미("~했다", "~였다")로 서술한 문장이 있는지 표시한다
- 같은 조건에서 있었던 AGENTS.md의 이전 관측(005·007·011 사례)과 나란히 놓고
  비교한다
- 다섯 캐릭터의 문체 차이(길이·짐작의 정도)가 여전히 구별되는지 함께 기록한다
  (SC-004) — 전부 비슷해졌다면 프롬프트가 캐릭터 차이를 뭉갠 것이다(FR-013 위반
  신호)
- **이것은 자동 채점이 아니다** — 사람이 읽고 판단한 결과를 AGENTS.md에
  "합성/실사 하루에서의 관측"으로 남긴다(010의 관례를 따른다).

## D7 — 진단 화면에서 모델 이름을 본다 (FR-017~019, SC-005)

local 또는 dev 환경에서 앱을 연다(진단 패널이 보이는 환경).

**확인**: 진단 화면에 다섯 캐릭터 각각의 모델 표시 이름이 보인다.

release 빌드가 있다면(이전 기능에서 남은 빌드로 충분, 새로 만들 필요 없음) 그
빌드에서 진단 화면에 닿는 경로가 없는 것도 확인한다(001 SC-013 재확인).

## D8 — 기존 일기 파일이 깨지지 않는다 (FR-010, SC-006)

이 기능 배포 이전에 저장된(`title` 필드가 없는) 일기 파일이 기기에 남아 있다면
목록·상세 화면에서 그대로 열리는 것을 확인한다. 없다면 `title` 필드를 뺀 JSON
파일을 수동으로 만들어(또는 D5 이전 커밋에서 생성한 파일을 재사용해) 같은 것을
확인한다.

**확인**: 오류 없이 목록에 뜨고, 상세를 열면 제목 없이(날짜만) 표시된다.
