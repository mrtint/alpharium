# 139 iPad 창 모드 — 고친 것과 확인

**실기기 확인이 아니다. 전부 시뮬레이터다**(iPadOS 실기기는 없다). 원인 확인과 방법 시험은 [research.md](research.md).

## 고친 것

로컬 모듈 `modules/pocketlog-ipad-window`(iOS 전용). 앱 시작에 **iPad에서만** expo 장면 대리자에 메서드 둘을 붙인다.

| 메서드 | 답 |
| --- | --- |
| `preferredWindowingControlStyleForScene:` | 창 조절 점 「최소」 모양 |
| `supportedInterfaceOrientationsForWindowScene:` (iOS 27부터 불린다) | 화면 짧은 변이 700pt 이상(창 모드)이면 네 방향, 아니면 세로 둘 |

앱이 앞으로 올 때(iPad만) 지원 방향을 다시 묻게 한다. 화면(JS) 코드는 바꾸지 않았다. 700pt는 사람이 정한 값이다.

구현 중에 두 가지를 더 고쳤다.

- 네 방향을 늘 답하자 「전체 화면 앱」의 가로가 낮고 넓은 화면(667×375)이 되어 홈 재료 칸이 잘렸다. 그 설정에서는 시스템이 앱에게
  iPhone 크기의 화면(375×667)을 흉내 내 주므로 화면 크기로 가른다.
- 「전체 화면 앱」에서 「윈도우형 앱」으로 바꾼 뒤 켜져 있던 앱은 옛 답(세로만)을 계속 써 가로에서 누웠다. 다시 묻게 하자 바로 섰다.

## 확인 (2026-11-28)

환경: iPad Pro 11-inch (M5) · iPhone 18 Pro 시뮬레이터, iOS 27.0, Xcode 27.2, Release, `EXPO_PUBLIC_APP_ENV=dev`.
모델 파일은 내려받지 않았다(이전 점검이 시뮬레이터에 둔 것을 썼다).

### iPad, 윈도우형 앱

| 본 것 | 결과 |
| --- | --- |
| 설정의 「‹ 일기」를 글자 자리(251, 63)에서 누름 | 홈으로 돌아옴. 고치기 전에는 같은 좌표에서 창 메뉴가 펼쳐졌다. 창이 오른쪽으로 옮겨진 뒤에는 글자 자리(284, 63)에서도 돌아옴 |
| 이름 바꾸기·서체 라이선스의 「‹ 설정」 | 겹침 없음, 돌아옴 |
| 홈, 쓴 날, 지도 면, 확대 화면(장수·닫기), 작명 | 창 조절 점이 앱 내용을 덮지 않음 |
| 가로 회전, 실행 중 되돌림 | 바로 선 417×834 창 |
| 전체 화면 앱에서 바꾸고 켜져 있던 앱으로 돌아와 가로 | 바로 선 창(같은 프로세스) |

작명 화면은 `welcomeShown`을 잠깐 `false`로 바꿔 띄우고 원래 파일로 되돌렸다.

### iPad, 전체 화면 앱

세로·가로 모두 고치기 전과 같은 화면(가운데 375×667, 바로 선 세로). 창 조절 점은 없다. 고치기 전 빌드에서도 겹침은 없었다.
윈도우형에서 바꾼 뒤 켜져 있던 앱도 같았다. **확인 뒤 설정은 「윈도우형 앱」과 원래 토글 값으로 되돌렸다.**

### iPhone

두 메서드가 붙지 않는다(`class_respondsToSelector` 둘 다 `NO`, iPad는 `YES`). 홈이 전과 같고 돌려도 세로다.
이 확인은 화면 크기 분기와 「다시 묻기」를 넣기 전 빌드였다 — 두 변경은 모두 iPad 확인 뒤에만 돈다(계약 테스트).

위 iPad 화면 가운데 작명·확대 화면·지도 면·이름 바꾸기·서체 라이선스도 그 전 빌드에서 봤다. 창 모드의 답은 그 뒤 바뀌지 않았다.

캡처: `after/`.

### 자동 검사

- `npm test`: 460 묶음 통과, 9381 통과·7 건너뜀. 그 뒤 새 테스트 파일만 고쳐 그 파일(11개)을 다시 돌렸다.
- `npm run lint`: 통과(기존 경고 6개).
- 위반 주입 10가지(클래스·셀렉터 이름, 점 모양, iPad 확인 두 곳, 다시 묻기, 화면 크기 분기, 세로 답, 모듈 설정)가 모두 테스트에 잡힌다.
  처음에는 붙이는 함수의 iPad 확인을 빼도 통과해 테스트를 고쳤다.

## 남은 것

- **상태 표시줄의 앱 이름과 겹침**: 세로 창 모드에서 시스템이 상태 표시줄에 「포켓로그」를 띄운 동안 최소 모양의 점이 그 글자와 겹친다.
  몇 분 이어진 때도, 이름이 없던 때도 있었다. 시스템이 그리는 영역이고 앱 내용은 덮지 않는다. 고치지 않았다.
- 설정을 바꿔 창 너비가 달라진 뒤 날 스트립이 고른 날(28일)이 안 보이는 자리(5~11일)에 있었다. 고치기 전에도 그런지는 보지 않았다.
- iPadOS 26 이하: 회전 메서드가 불리지 않아 가로는 그대로일 것이다(보지 않았다).
- 보지 않은 것: 실기기 iPad, 다른 iPad 크기, 스테이지 매니저, VoiceOver, 키보드를 띄운 상태, Xcode 26 이하 SDK 빌드
  (`native-build.yml`의 경로 목록에 `modules/**`가 없어 PR에서 저절로 돌지 않는다).
