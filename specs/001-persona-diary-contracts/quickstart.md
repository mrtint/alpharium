# Phase 1 — 검증 가이드: US1 코어 루프

**대상**: 001 User Story 1
**전제**: [contracts/axis-boundaries.md](contracts/axis-boundaries.md)

US1이 실제로 관통했는지 확인하는 시나리오다. **일기의 내용이 실제 하루와 맞는지는
검증하지 않는다** (001 SC-009, FR-020, 헌법 원칙 0).

---

## 실행 준비

```powershell
npm install
npx expo install --check     # 헌법: 버전은 Expo API가 해석한다
npm run lint                 # eslint + tsc --noEmit
npm test
```

휴대폰에서 확인할 때 (AGENTS.md — Metro가 IPv6에 바인딩되므로 Tailscale 주소를 쓴다):

```powershell
$env:REACT_NATIVE_PACKAGER_HOSTNAME = "100.98.26.61"; npx expo start --host lan
```

Expo Go에서 `exp://100.98.26.61:8081`을 연다.

## 시나리오 1 — 정상 경로 (001 AS-1, AS-2)

**전제**: 퍼소나가 존재하고 오늘 관측된 신호가 있다.

1. 앱을 열면 **오늘 자리**에 도달한다 (006 FR-501)
2. 생성을 요청한다 → 진행 중임이 나타난다 (006 FR-520)
3. 일기 한 편이 산출되고 **근거 집계와 함께** 저장된다
4. 일기 상세에서 **본문·재료 요약·근거 집계·퍼소나 이름**에 모두 도달한다 (006 FR-504)

**통과 조건**
- 001 SC-002 — 일기와 집계가 함께 저장되어 조회 가능한 상태에 도달한다
- 006 FR-510 — 집계가 별도 영역으로 벗어나지 않고 본문과 대조된다
- 재료 요약의 셈이 **집계의 관측 항목과 일치**한다 (004 FR-303)

**검증하지 않는 것**: 본문이 실제 하루와 맞는지, 문장이 자연스러운지.

---

## 시나리오 2 — 빈 집계 (001 AS-3)

**전제**: 오늘 관측된 신호가 전혀 없다 (모든 소스 권한 거부로도 재현 가능 — 003 FR-217).

1. 생성을 요청한다
2. **쓸 재료가 없어 쓸 수 없음**이 알려진다 (006 FR-526)
3. 일기가 저장되지 않는다

**통과 조건**
- 추론이 **시도되지 않았다** (001 FR-013) — 모델 호출이 일어나지 않아야 한다
- 그 날짜를 조회했을 때 일기가 존재하지 않는다
- 대체 문장이 그 자리를 채우지 않는다 (001 FR-024)

**왜 중요한가**: 빈 집계로 추론을 돌리면 휴대폰이 **아무것도 못 본 날을 지어내게** 된다
— 원칙 0의 「근거의 한계」 위반이다.

---

## 시나리오 3 — 「적음」 확인 (001 AS-6)

**전제**: 관측된 항목이 0보다 크고 임계값 미만이다 (003 FR-274).

1. 생성을 요청한다
2. **반영될 것이 적다는 사실**이 알려지고 확인을 받는다
3. 진행을 택하면 일기가 **정상적으로** 생성·저장된다

**통과 조건 — 구조로 검사한다**
- 001 SC-012 — 시스템이 적음을 이유로 거부하거나 다르게 취급하지 않는다
- 006 FR-542 — **진행이 기본 선택**이다
- 006 FR-543 — 부족·빈약·미흡·불충분 등 평가어가 없고 경고 기호가 없다
- 006 FR-540 — 「보통」에서는 이 확인이 뜨지 않는다
- 006 FR-546 — 거부·지연이 없다

**이월된 관찰 항목**: 사용자가 실제로 「말리는 것」으로 느끼는지는 위 구조적 조건으로
닫히지 않는다. 006이 구현 후 관찰로 넘겼다. 이 시나리오는 **구조적 조건까지만** 검사한다.

---

## 시나리오 3b — 시각 무제약 (001 FR-042, SC-013)

**전제**: 하루 중 임의의 시각. 이른 아침을 포함한다.

1. 생성을 요청한다

**통과 조건**
- 001 SC-013 — 생성이 **시각을 이유로 거부되지 않는다**
- 001 FR-042 — 잠정·미완 상태로 구별해 표시하지 않는다
- 그 시점까지 관측된 것만으로 쓰이며, 이후 시간대에 대한 서술이 없다

**왜 중요한가**: 「아직 하루가 안 끝났으니 나중에」는 시스템이 사용자 대신 판단하는
형태다 — 원칙 0의 「품질 판정 금지」와 같은 자리다. 집계가 적으면 시나리오 3의 확인이
적용되고, 나중에 다시 쓰고 싶으면 시나리오 4의 재생성 경로를 쓴다.

## 시나리오 4 — 덮어쓰기와 재생성 (001 AS-4, AS-5)

**전제**: 오늘자 일기가 이미 저장되어 있다.

1. 다시 생성을 요청한다 → **덮어쓸지 확인**을 받는다 (001 FR-040)
2. 몇 시간 뒤 덮어쓰기로 재생성한다
3. **그 시점까지 관측된 것으로 집계가 새로 만들어진다** (001 FR-040a)

**통과 조건**
- 001 SC-008 — 그 날짜에 보이는 일기가 최대 한 편이다
- 001 SC-011 — **두 번째 일기가 두 번째 시점의 집계와 짝지어져 있다**. 첫 번째 집계가
  두 번째 일기에 남아 있는 경우가 없다
- 003 FR-264 — 새 집계의 항목이 이전보다 **적어져도 정상**이다. 이전 값으로 메우지 않는다

**왜 중요한가**: 이전 집계를 재사용하면 저녁의 휴대폰이 아침의 기억으로 쓰게 된다.

---

## 시나리오 5 — 원본 로그 미보관 (001 AS-7)

**전제**: 임의의 날짜에 일기가 저장되어 있다.

저장된 데이터를 **전수 조사**한다.

**통과 조건**
- 001 SC-004 — 원본 로그에 해당하는 것이 **하나도 발견되지 않는다**
- 005 FR-402 — 담을 자리 자체가 존재하지 않는다. 저장 시점 걸러내기로 대신하지 않았다
- 003 FR-255 — 집계 산출에 쓰인 중간 결과물도 남지 않는다
- 좌표·이동 경로·사진 원본·기기 정보가 없다 (003 FR-249·FR-252)
- 005 FR-404 — 기기 식별자가 없다

**로그·크래시 리포트도 확인한다** — 일기 본문과 원시 신호가 남지 않아야 한다
(001 FR-037, 005 FR-405, 헌법 원칙 I).

## 시나리오 6 — 실패 경로 (US2 선행 검사)

US2는 이번 범위 밖이지만, **성공 경로만 만들고 실패를 나중에 붙이면 그 사이에 빈칸을
메우는 코드가 반드시 생긴다**(001 US2 Why this priority). 따라서 US1과 함께 확인한다.

다섯 종료 사유를 각각 강제해 재현한다. 앞의 넷은 추론 실패(004 FR-350)이고 마지막
하나는 실패가 아니라 **미완결**(001 FR-027)이다 — 결과가 저장 축에 도달하지 않는다는
점만 같다:

| 실패 | 재현 방법 |
| --- | --- |
| 입력 구성 실패 | 성격 참조가 해소되지 않는 상태 |
| 모델 응답 실패 | 어댑터가 응답하지 않는 상태 |
| 형식 실패 | 본문을 식별할 수 없거나 빈 본문 |
| 화자 위반 | 사용자를 화자로 하는 본문 |
| 사용자 취소·이탈 | 추론 중 취소하거나 앱을 벗어난다 |

**통과 조건 (다섯 경우 모두)**
- 001 SC-003 — 그 날짜를 조회했을 때 **저장된 일기가 존재하지 않는다. 예외 없음**
- 004 FR-353 — 대체 텍스트가 그 자리를 채우지 않는다
- 006 FR-522 — 실패가 **명시적으로** 표시된다. 조용히 이전 화면으로 돌아가지 않는다
- 006 FR-524 — 재시도 경로가 있다
- 006 FR-525 — 실패한 날짜는 **일기가 없는 날**로 표시된다
- 004 FR-352 — 입력 구성 실패에서는 **모델이 호출되지 않는다**
- 001 FR-027 — 취소·이탈에서는 **부분 결과가 남지 않는다**

**추론 외의 실패도 확인한다** (006 FR-528): 집계 생성 실패(003 FR-265), 저장 실패
(005 FR-412). 이 둘을 삼키는 것이 헌법 원칙 II의 흔한 빠져나감이다.

**통과 조건**: 001 SC-006 — US1의 **모든** 추론 요청에서 회상 슬롯이 비어 있다. 예외 없음.

## 시나리오 8 — 화자 판정기의 실측 (004 FR-348)

**이 시나리오가 research.md 결정 1의 표지 목록을 채우는 자리다.**

판정기는 순수 함수이므로 모델 없이도 검사할 수 있다.

### 8a. 성질 검사 (모델 불필요)

| 검사 | 근거 |
| --- | --- |
| 같은 본문에 반복 판정 시 **항상 같은 결과** | 004 SC-309, FR-346 |
| 내용·품질이 판정에 관여하지 않는다 — 같은 화자의 좋은 글과 나쁜 글이 같은 판정 | 004 FR-347 |
| 위반 시 **교정하지 않는다** — 판정기는 참·거짓만 내놓는다 | 004 FR-349 |

### 8b. 표지 목록의 실측 (모델 필요)

실제 모델 출력을 모아 판정기를 조정한다.

1. 정상 생성을 반복해 본문을 모은다
2. 각 본문에 대해 판정 결과와 실제 화자를 대조한다
3. **위음성**(사용자 화자인데 통과)을 우선 없앤다 — 이것이 통과하면 001 FR-019가
   실제로 깨진 채 지나간다
4. **위양성**(휴대폰 화자인데 위반)은 실패로 표시되고 재시도 경로가 있으므로 회복
   가능하다 (004 FR-354)

**닫히는 조건**: 004 Assumptions의 「화자 판정 가능성」 가정이 실측으로 확인된다. 이
가정이 깨지면 001 FR-019의 검증이 성립하지 않으므로, **여기서 닫지 못하면 대안을
명시해야 한다** (ROADMAP 004 완료 조건).

## 함께 닫는 실측 항목

US1이 돌아가면 아래 값들을 관측으로 채울 수 있다. **값을 비운 채로도 루프는 돌아가므로
US1의 완료를 막지 않는다.**

| 항목 | 출처 | 관측 방법 |
| --- | --- | --- |
| 항목별 상한, 시간대 세분도 | 003 FR-257 | 집계를 키우며 추론 품질 변화를 관측 |
| 규모 판정 임계값 (2~6) | 003 FR-274 | 「적음」 확인의 발생 빈도 |
| 입력 구성 규칙 | 004 FR-318 | 프롬프트 구성별 형식 실패율 |
| 추측의 강도 | 004 FR-331 | 본문이 관측 범위를 넘는지 |
| 「적음」 확인의 중립성 | 006 | 구현 후 사용자 관찰 |

003 FR-257이 **실측 없이 정한 값을 최종값으로 남기지 않을 것**을 요구한다. 값을 채울
때는 관측 결과를 근거로 남긴다.

## 헌법 게이트 (병합 전)

```powershell
npm run lint    # tsc --noEmit 포함
npm test
```

추가로 확인한다:

- **원칙 I** — 프로덕션 번들에 클라우드 어댑터가 포함되지 않는다. 개발 모드에서는
  클라우드 사용 중임이 표시된다 (006 FR-590~FR-593)
- **원칙 II** — 시나리오 6이 전부 통과한다. 조용한 fallback이 없다
- **원칙 0** — 시나리오 2·3·5·8이 통과한다

**원칙 0·I·II를 위반하는 변경은 병합할 수 없다. 예외 없음** (헌법 Governance).
