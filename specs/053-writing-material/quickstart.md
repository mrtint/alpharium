# Quickstart: 쓸 재료 (053) 검증

## 1. 기기 없는 검증

```bash
npm run test:logic -- material day-preview written-day state
npm run test:ui -- material-grid diary-home diary-list
npm test
npm run lint
```

통과 기준: 전부 초록. 위반 주입(contracts의 각 항목)으로 테스트가 실제로 잡는지 확인하고 결과를 §5에 적는다.

## 2. 실기기 준비 (dev, `pm clear` 없음 — 모델 보존)

```bash
npx expo run:android            # dev 빌드 설치 (기존 데이터 유지)
EXPO_PUBLIC_APP_ENV=dev npx expo start --dev-client
adb reverse tcp:8081 tcp:8081
adb shell dumpsys trust | grep deviceLocked   # deviceLocked=0
```

Metro는 gradle 빌드가 끝난 뒤에 띄운다. 권한은 `adb shell pm revoke/grant com.anonymous.alpharium android.permission.READ_MEDIA_IMAGES`로 바꾼다
(Maestro `launchApp`은 권한을 다시 줄 수 있으니 `permissions: {all: deny}`로 제어한다 — 048 §6).

## 5. 위반 주입 결과 (2026-09-29)

전부 실제로 어겨 보고 잡히는 것을 확인했다(테스트 실패 수).

| 계약 | 주입 | 결과 |
| --- | --- | --- |
| MAT1 | `fromCountHint`의 `unknown`→`zero` | 1 실패 |
| DEC11 | 「전부 unseen」의 `because`를 `zero`로 | 3 실패 |
| MADE1 | `madeUpDay`가 늘 `false` | 3 실패 |
| MADE2 | `paperFor`가 `madeUp: false` 고정 | 2 실패 |
| MADE3 | `DiaryEntry`에 `madeUp` 필드 추가 | 1 실패 |
| MADE5 | `WrittenDayPaper`가 늘 「지어낸 하루」 그림 | 1 실패 |
| PRM2 | `photoAccessOf`에서 `undetermined`→`ok` | 2 실패 |
| PRM5 | 사진 0장이면 장소를 0곳으로 승격하는 분기 제거 | 1 실패 |
| GRID4 | 「권한이 없어요」 색을 accent로 / 최소 높이 41 | 각 1 실패 |
| GRID6 | 권한 없음일 때도 안내 한 줄 | 1 실패(첫 주입은 적용되지 않아 — 코드가 그 조건을 갖고 있지 않았다 — 테스트를 더하고 조건을 넣은 뒤 다시 주입) |
| DLG1·DLG2 | 확인 판정을 뒤집음(`confirm`↔`write`) | 7 실패 |
| DLG6 | 도착한 미리보기를 무시 | 2 실패 |
| DLG8 | 다시 쓰기에도 재료 판정 | 1 실패 |

**첫 GRID6 주입이 적용되지 않은 것이 이 표의 교훈이다** — 주입이 「실패하지 않은 채 통과」로 보일 뻔했다. 문자열 치환이 코드에 닿지 않은 것을 확인하려면 치환 성공을 먼저 단언한다.

## 6. 실기기 결과 (2026-09-29, SM-S901N, dev, `pm clear` 없음)

Metro `--clear`로 띄운 dev 빌드. 권한은 `adb pm revoke/grant`로 바꿨다.

| # | 결과 |
| --- | --- |
| D1 | 두 칸(사진·장소)이 보이고 「쓸 수 있는 때」 칸·세로선이 없다. 지면이 바닥까지 채워지고 「일기 쓰기」 바가 그 위에 붙는다 |
| D2 | 사진 0장인 오늘 — `0 장`·`0 곳` 회색 숫자(단위는 본색), 아래 「기록 대신 상상으로 하루를 채워요.」. ★ **첫 화면은 「0 장 · 모름」이었다** — 수집이 사진 0장일 때도 장소를 「모름」으로 주기 때문이다. `toDayPreview`가 사진이 관측된 0장이면 장소를 0곳으로 옮기게 고쳤다(PRM5). 사진이 `unknown`이면 승격하지 않는다 |
| D3 | 권한 회수 후 복귀 — 두 칸 모두 빨간 「권한이 없어요 ›」(`danger`), 안내 한 줄 없음 |
| D4 | 「권한이 없어요 ›」 → OS 권한 창(제한된 액세스/모두 허용/허용 안함) → 「모두 허용」 → 홈으로 돌아와 `0 장`·`0 곳`으로 바뀐다 |
| D5 | 허용 안함을 반복해 다시 물을 수 없게 된 뒤 누르면 OS 창 대신 「설정에서 사진 접근을 허용해 주세요」 대화상자(설정 열기·취소) |
| D6 | 「설정 열기」 → `com.android.settings` 딥링크 활동이 실제로 생성됨(logcat). 설정에서 허용한 것을 `adb pm grant`로 흉내 내고 앱을 앞으로 가져오면 자동으로 다시 센다(안내 캡션도 사라짐). **설정 화면에서 손으로 토글하는 것은 하지 않았다** |
| D7 | (후속 관측) 사진 3장·장소 2곳인 안 쓴 날에서 「일기 쓰기」 → 확인 대화상자 없이 바로 쓰는 중, 약 75초 뒤 저장. 본문에 「지어낸 하루」 없음. 테스트로 만든 일기는 지웠다 |
| D8 | 재료 0인 오늘 「일기 쓰기」 → 「😢 아무 기록도 없어요」 / 「이렇게 작성하면 하루를 상상해서 적어요.」 / 확인·취소. 취소 → 그대로 |
| D9 | 권한 없음에서 「일기 쓰기」 → 「😢 기록을 볼 수 없어요」 |
| D10 | 옛 일기 27일(저장된 신호가 재료 없음)에서 본문 위에 「지어낸 하루」 한 줄, 사진이 있던 28일에는 없다. (후속 관측) 사진 0장인 오늘에서 확인으로 새로 쓰자 본문 맨 위에 「지어낸 하루」가 붙었다(약 45초, 일기는 지웠다) |
| D11 | 글꼴 1.3배 — 두 칸의 「권한이 없어요 ›」가 잘리거나 겹치지 않고 하단 바가 보인다(설정한 뒤 1.0으로 되돌림) |

**Maestro**: `writing-material.yml` PASS. 회귀 `diary-home-1d`·`today-diary`·`week-strip-swipe`·`dialog-foundation` 4흐름 PASS.

**후속 관측**: 설정 앱(삼성)에서 사진 및 동영상 권한을 「항상 모두 허용」으로 손으로 바꾸고 복귀하니 자동으로 `0 장 · 0 곳`으로 바뀌었다. 글꼴 2.0배에서 「권한이 없어요 ›」 두 칸이 붙고 오른쪽 「›」가 지면 밖으로 새던 결함을 찾아 `flexWrap: wrap`·라벨 `flexShrink: 1`로 고쳤고(GRID4 테스트 추가) 실기기에서 「›」가 칸 안 아래 줄로 내려오는 것을 확인했다.

**미확인 잔여**: 제스처 내비게이션 기기·다른 키보드 앱·삼성 밖 설정 화면. **홈 헤더의 021 안내 캡션(「사진을 볼 수 없어서 일기는 사진 없이 써요」)이 권한 없음 칸과 같은 사실을 두 번 말한다** — 이 조각은 021 안내를 건드리지 않았다(후속 판단).
