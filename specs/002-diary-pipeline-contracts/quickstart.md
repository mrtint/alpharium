# Quickstart: 파이프라인 뼈대가 섰는지 확인하기

**기능**: 일기 파이프라인의 축 사이 계약 | **날짜**: 2026-08-12

이 문서는 이 기능이 동작하는지 끝에서 끝까지 확인하는 절차다. 구현 코드는 담지 않는다.

**이 기능은 실기기가 필요 없다.** 실제 추론도 실제 수집도 하지 않으므로 전부 기기 없이
검증된다(SC-003). 001과 다른 점이다.

---

## 사전 준비

| 필요한 것 | 왜 |
| --- | --- |
| Node 20.19 이상 | `package.json`의 `engines` |
| 의존성 설치 | `npm ci` |

실기기·시뮬레이터·Maestro **모두 필요 없다.**

---

## A. 검사와 테스트

```bash
npm ci
npm run lint          # eslint + tsc + 헌법 검사
npm test              # 기기 불필요 테스트
```

**기대 결과**:

| 확인 항목 | 기대 | 근거 |
| --- | --- | --- |
| 하루 경계 테스트가 돈다 | 통과 | [contracts/signals.md](contracts/signals.md) |
| **00:30이 전날로 판정된다** | 통과 | **FR-021 — 자정 기준과 다른 지점** |
| **03:59가 전날, 04:00이 당일** | 통과 | **FR-021 방어선** |
| `none`과 `unknown`이 구분된다 | 통과 | FR-002 |
| 파이프라인이 `generation`에서 멈춘다 | 통과 | FR-015 |
| 헌법 검사 위반 0건 | 통과 | 001에서 이어짐 |
| 001의 테스트가 여전히 통과한다 | 통과 | 회귀 없음 |

마지막 줄을 확인하라. 이 기능은 001의 `InferenceBackend`를 확장하므로, 기존 테스트가
깨지지 않았는지가 중요하다.

---

## B. 원칙 I — 가짜 일기가 나오지 않는가

이 기능에서 가장 중요한 확인이다.

```bash
npm test -- inference
```

| 확인 항목 | 기대 | 근거 |
| --- | --- | --- |
| 온디바이스 `generate()` | `{ kind: 'not-implemented' }` | FR-015 |
| 데스크톱 `generate()` | `{ kind: 'not-implemented' }` | FR-015 |
| **실패 결과에 텍스트가 없다** | `text` 필드 없음 | **FR-016, SC-004** |

**실패에 플레이스홀더 텍스트가 붙어 있으면 이 기능은 실패다.** "일기를 생성할 수 없습니다"
같은 문자열이 일기 자리에 들어가는 순간 가짜 일기와 구분이 사라진다(헌법 원칙 I).

### 직접 확인

파이프라인을 돌려 결과를 본다. `generation` 단계에서 멈추고, 어떤 텍스트도 나오지 않아야
한다. **텍스트가 나온다면 어디선가 가짜를 만들고 있는 것이다.**

---

## C. 원칙 V — 모르는 것을 0으로 채우지 않는가

```bash
npm test -- signals
```

| 확인 항목 | 기대 | 근거 |
| --- | --- | --- |
| 걸음 수 `unknown`이 0이 되지 않는다 | `{ kind: 'unknown' }` 유지 | FR-003, SC-002 |
| `none`과 `unknown`이 다른 값이다 | 구분됨 | FR-002 |
| 저장 후 꺼내도 `unknown`이 살아 있다 | 유지 | SC-007 |

마지막 줄이 놓치기 쉽다. 직렬화가 `unknown`을 `null`로 뭉개면 왕복 후 "없음"이 되어버리고,
그 순간 헌법 원칙 V가 깨진다.

### 금지된 것이 없는지 확인

```bash
grep -rn "valueOr\|?? 0\|:: 0" src/signals/
```

**신호를 기본값으로 대체하는 함수가 있으면 안 된다**(FR-003). 편의를 위해 만들고 싶어지는
함수이며, 만드는 순간 "걷지 않았다"는 거짓이 생긴다.

---

## D. 원칙 III — 모델 식별자가 새어 나오지 않는가

```bash
grep -rn "kanana\|exaone\|hyperclovax\|qwen\|gemma\|gguf\|Q4_K\|1\.7b\|2\.4b" src/diary/ src/signals/
```

**0건이어야 한다**(FR-008, FR-013, SC-005). 캐릭터는 사용자가 고른 성격이지 모델이 아니다.

---

## E. 원칙 IV — 측정 장치가 들어오지 않았는가

```bash
grep -rn "score\|benchmark\|elapsed\|duration\|tokensPerSec" src/diary/
```

**0건이어야 한다**(FR-027). `DiaryEntry`에 "생성에 몇 초 걸렸는지"를 넣고 싶어지지만, 그것이
모델 비교의 시작점이 된다. 필요하면 별도 저장소에서 한다.

---

## F. 저장 왕복

```bash
npm test -- store
```

| 확인 항목 | 기대 | 근거 |
| --- | --- | --- |
| 저장한 것과 꺼낸 것이 같다 | 동일 | SC-007 |
| 같은 날짜 저장 시 `overwrote: true` | 드러남 | FR-023a |
| 어느 날짜가 비었는지 안다 | 목록 반환 | FR-018f, SC-012 |
| 저장 실패가 드러난다 | `ok: false` | FR-024 |

### 실기기 확인 (2026-08-13 완료)

파일 저장 구현은 `expo-file-system` 57의 API를 이 저장소에서 처음 쓰는 것이었다
(research.md §3). **Galaxy S20+ (SM-G986N, Android 13, arm64-v8a)에서 실제로 확인했다.**

```bash
npm run test:device
```

| 확인 항목 | 결과 |
| --- | --- |
| 저장·조회가 실기기에서 돈다 | ok |
| 덮어쓰기가 `overwrote: true`로 드러난다 | ok |
| **`unknown`이 파일 왕복에서 살아남는다** | ok |
| `listDays`가 저장한 날짜를 찾는다 | ok |

확인 경로는 `src/diagnostics/storage-check.ts`이며 진단 화면 「저장 점검」 줄에 결과가
뜬다. **local·dev에서만 보이고 prod에서는 도달하지 않는다**(FR-007a).

**이 점검이 정직한지도 확인했다**: 직렬화가 `unknown`을 `none`으로 뭉개도록 일부러
깨뜨렸더니 화면이 `failed — unknown이 none로 뭉개졌다`로 바뀌고 Maestro가 실패했다.
통과가 「돌지 않아서 초록」이 아니라는 뜻이다.
