# 안드로이드 배터리 예외 인지 — 쓸 차례 알림 지연과 안내 (설계)

- 날짜: 2026-10-24
- 출처: 로드맵 「백그라운드 자동 쓰기가 완주하지 못한다」 할 일 2번(소유자 결정 2026-10-15 — 배터리 예외를 받게 이끄는 쪽을 강화한다) + 소유자 관측(2026-10-24, 안드로이드에서 완료 알림 전에 「쓸 차례」 예고 알림이 따로 온다).
- 범위: 안드로이드만. iOS 동작은 바뀌지 않는다.

## 1. 의도 (합의한 이해)

- **무엇을 원하는가**: 백그라운드가 일기를 쓸 수 있는 기기에서는 사용자가 **완성 알림만** 받는다. 쓸 차례 알림은 백그라운드가 못 쓸 때만 간다.
- **누구를 위한가**: 배터리 예외를 준 안드로이드 사용자(알림 소음 제거), 예외가 없는 사용자(예외를 받게 이끎, 알림은 종전대로 제때).
- **성공 기준**:
  1. 예외를 준 기기에서 백그라운드가 목표 시각 직후 쓰기를 완주하면 쓸 차례 알림이 뜨지 않고 완성 알림만 온다.
  2. 예외가 없거나 모르는 기기의 쓸 차례 알림은 지금과 같은 시각(정각)에 간다.
  3. 예외 여부를 사용자가 설정에서 볼 수 있고, 예외가 없는 채 「열어서 쓰게 된」 순간 안내를 받는다.
- **사실로 확인한 것**
  - 쓸 차례 알림은 목표 시각 **정각**에 예약된다(`reminder-plan.ts`). 백그라운드 쓰기는 같은 시각 이후 시작해 안드로이드에서 약 4분(한도 600초) 걸리므로 알림이 먼저 뜬다. 쓰기가 저장되면 알림을 거두고 완성 알림을 띄운다(085).
  - 백그라운드 잡의 최소 반복 간격은 15분이다(`background-port.ts`). 잡이 목표 시각 직후에 시작한다는 보장이 없다.
  - `expo-battery`는 아직 의존성에 없다. 배터리 예외 통로는 설정 목록을 여는 `battery-exception-port.ts`뿐이고 읽는 통로는 없다.
- **가정(맞는지 확인 대상)**: `isBatteryOptimizationEnabledAsync()`가 헤드리스(백그라운드 잡)에서도 읽힌다. 읽히지 않으면 「모름」이고 지연 0이다 — 설계가 이 경우를 이미 안전한 쪽으로 처리한다.

## 2. 결정

| 상태 | 쓸 차례 알림 시각 | 설정 꼬리표 | 홈 안내 |
|---|---|---|---|
| 안드로이드, 예외 있음(`isBatteryOptimizationEnabledAsync() === false`) | 정각 + **30분** | 허용됨 | 없음 |
| 안드로이드, 예외 없음(`true`) | 정각 (지연 0) | 허용 안 함 | 앱 열기 자동 쓰기가 시작된 때 |
| 안드로이드, 모름(읽기 실패·미지원) | 정각 (지연 0) | 꼬리표 없음 | 없음 |
| iOS | 정각 (지연 0) | 해당 없음 | 없음 |

- **30분의 근거**: 잡 반복 간격 15분 + 쓰기 한도 600초(10분) = 최악 약 25분. 사람이 정한 값이다(원칙 V — 측정이 아니다).
- **iOS는 지연 0 — 근거와 재검토 조건**: iOS에는 「백그라운드가 목표 시각 근처에 쓴다」를 알려 주는 신호가 없다. 충전 중 OS 깨움은 표본 1이고 깨우는 시각을 OS가 정하며(090), 충전하지 않으면 약 31시간 동안 깨우지 않았다(091). 충전하지 않는 사용자에게는 쓸 차례 알림이 유일한 경로라 근거 없이 늦추지 않는다. 사람이 정한 판단이며 측정이 아니다. TestFlight 테스터 기록(로드맵 4번 할 일 1)에서 「쓸 차례 알림이 뜬 뒤 완성 알림이 온」 사례가 나오면 다시 정한다.
- **알림은 저장된 뒤에만 거둔다(안전장치)**: 쓸 차례 알림 예약은 그날 일기 **파일이 생겼을 때만** 맞추기(`reconcileReminders`)가 지운다. 쓰기 시작·도중에는 지우지 않는다 — 쓰기가 실패하거나 프로세스가 죽거나 얼어도 예약(OS 알람)은 남아 뜬다. 쓰기 시작 때 거두면 「쓰는 중」이 프로세스 메모리 상태라 도중에 죽을 때 일기도 알림도 없는 날이 생기므로 하지 않는다. 지연 30분은 이 조건 아래서 잡 시작 지연(최대 15분)과 쓰기 한도(10분)를 덮는 값이다.
- **모름이면 지연 0**: 지연은 「백그라운드가 쓸 수 있다」는 사실이 확인된 때만 건다. 모르는 것을 「예외 있음」으로 채우지 않는다.
- **지연 중 쓰기가 끝나면**: 맞추기가 그날 예약을 거둔다(기존 085 동작) — 알림이 뜨기 전이므로 완성 알림만 남는다. 지연 시각이 쓰기 도중이면 종전처럼 알림이 뜨고 완성 때 거둔다.

## 3. 구성

### 3.1 예외 읽기 통로 — `src/schedule/battery-exception-port.ts` 확장
- `BatteryExceptionPort`에 `readStatus(): Promise<"exempt" | "restricted" | "unknown">`를 더한다. iOS와 읽기 실패는 `"unknown"`.
- `expo-battery`의 `isBatteryOptimizationEnabledAsync()`를 **호출 시점에** 읽는다(`await import`가 아니라 필요한 곳에서 지연 로드 — iOS 크래시 규칙 066에 걸리지 않게 `Platform` 판정 뒤에만 로드). 반환값만 쓰고 그 밖의 값은 버린다(원칙 IV).
- 새 네이티브 의존성이다: `npx expo install expo-battery`(SDK 57 호환 확인), `expo prebuild --platform android --clean` 뒤 `dumpsys package com.a810labs.pocketlog`로 **권한이 늘지 않았는지** 확인한다.

### 3.2 지연 계획 — `src/schedule/reminder-plan.ts`
- `planReminders` 입력에 `delayMinutes`(0 이상 60 미만 정수)를 더한다. `at = 정각 + delay`. 겨냥하는 날(`day`)은 정각 기준 그대로(DB11 불변). 범위 밖 값은 던진다(순수 함수 방어).
- `fire <= now` 판정과 「지난 예약 유지(RC8)」는 지연이 적용된 `at` 기준이다.

### 3.3 맞추기 — `src/schedule/reminders.ts`, `reminder-deps.ts`
- `ReminderDeps`에 `loadDelayMinutes(): Promise<number>`를 더한다. 기본 조립(`expoReminderDeps`)이 `readStatus()`로 정한다: `exempt` → 30, 그 밖 → 0. 읽기 실패는 `readStatus()`가 `unknown`으로 삼키므로 `loadDelayMinutes`는 던지지 않고 0이 된다 — 설정·일기 목록을 못 읽을 때처럼 맞추기를 멈추지 않는다(알림이 더 늦어지는 쪽이 아니라 종전대로 가는 쪽).
- 앱 훅·헤드리스 태스크가 같은 조립을 쓰므로 한 곳이다. 이미 걸린 예약은 `at`이 달라 첫 맞추기에서 새 시각으로 다시 걸린다(마이그레이션 없음).
- 설정 앱에서 돌아오면(`AppState` → `active`) 기존 `useReminderSync` 효과 B가 맞추기를 다시 부르므로, 예외를 준/끈 직후 예약이 새 지연으로 바뀐다.

### 3.4 설정 꼬리표 — `SettingsScreen`, `use-permission-tags.ts`, `app/battery-row.ts`
- 설정 배터리 행에 다른 권한 행처럼 꼬리표를 붙인다: 예외 있음 「허용됨」(`permAllowed`), 예외 없음 「허용 안 함」, 모름 꼬리표 없음.
- 설정 목록에서 돌아오면(`AppState` → `active`) 다시 읽는다. 따로 토스트를 띄우지 않는다.
- 문구는 `src/i18n/catalogs/ko/`에만 둔다(062). 골든은 `ADDED_AFTER_GOLDEN`에 올린다.

### 3.5 홈 안내 — 앱 열기 자동 쓰기가 시작됐고 예외가 없을 때
- 조건: 안드로이드 && `readStatus() === "restricted"` && 앱 열기 자동 쓰기(057)가 시작됐다(「백그라운드가 못 써서 열어야 했다」를 막 겪은 순간).
- 홈에 한 줄 안내 + [설정 열기]([설정 열기]는 기존 `openSettingsList()`).
- 닫으면 **7일 동안** 다시 보이지 않는다. 새 기록 파일 하나(`preferences/`), 062 B6·069 G-1 가드 표에 등록한다.
- 설정에서 예외를 주고 돌아오면 안내가 사라진다.
- 온보딩 배터리 카드는 그대로 둔다.

## 4. 범위 밖 (4번의 나머지로 남김)
- iOS TestFlight 기록 수집(1번), 080 잔여(5번), 한도 타이머(6번), 078 잔여.
- **하룻밤 소크(3번)**: 이 기능의 실기기 확인과 같은 기기·같은 상태(예외를 준 채 밤새 둠)지만 결과가 늦게 나오므로 완료 조건에 넣지 않는다. 구현 뒤 별도 단계로 돌린다.
- 「한 번 눌러 허용」(`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`)은 Play 정책상 되살리지 않는다(065). 배터리 예외 요청 직접 권한을 선언하지 않는다.
- 쓸 차례 알림 시각 자체를 바꾸는 사용자 설정은 만들지 않는다(YAGNI).

## 5. 테스트
- **계획(logic)**: 지연이 `at`에만 적용되고 `day`는 같다 / 지연 0은 종전과 같다 / 0~59 밖 값은 던진다 / 지난 시각 판정이 지연 기준이다.
- **맞추기(logic)**: 지연이 계획까지 전달된다 / `at`이 달라진 기존 예약이 다시 걸린다 / `exempt`→30, `restricted`·`unknown`·iOS→0.
- **통로(logic)**: `readStatus`가 안드로이드 `false`→`exempt`, `true`→`restricted`, 던지면 `unknown`, iOS→`unknown`.
- **조립(상태·이유 문자열을 공유하는 두 부품)**: 예외 있음 + 백그라운드 완주 시 실제 파이프라인·맞추기로 쓸 차례 예약이 알림 전에 거둬진다.
- **화면(ui)**: 꼬리표 3상태, 홈 안내의 노출 조건·닫기 7일·설정 복귀 후 사라짐.
- **소스 계약**: `expo-battery` 호출은 통로 한 곳에서만 / 문구는 카탈로그에만 / `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`가 매니페스트에 없다.
- **위반 주입**: 지연 판정을 `restricted`에도 걸어 보고 테스트가 잡는지 확인한 뒤 되돌린다.

## 6. 실기기 확인 (SM-S901N dev)
1. 권한: `expo prebuild --clean` 뒤 `dumpsys package`에 `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`가 없다.
2. 예외를 끈 채: 설정 꼬리표 「허용 안 함」, 앱 열기 자동 쓰기 시작 시 홈 안내, [설정 열기] → 「제한 없음」 → 돌아오면 꼬리표 「허용됨」·안내 사라짐.
3. 예외를 준 채 화면을 끄고 강제 잡(`cmd jobscheduler run -f`)을 목표 시각 직후에 돌려 완주: 쓸 차례 알림 없이 완성 알림만 온다.
4. 예외를 준 채 잡을 돌리지 않고 +30분을 지나면 쓸 차례 알림이 뜬다(폴백).
5. 예외를 끈 채: 쓸 차례 알림이 정각에 뜬다(삼성은 얼림으로 미뤄질 수 있음 — 알려진 한계).

## 7. 위험
- 새 네이티브 의존성으로 재빌드가 필요하다(모델 2GB를 지우지 않도록 debug APK를 지우지 않고 설치).
- 예외를 준 기기에서 OS가 그날 잡을 아예 깨우지 않으면, +30분에 쓸 차례 알림이 폴백으로 뜬다 — 알림이 없는 하루는 생기지 않는다.
- `isBatteryOptimizationEnabledAsync`가 삼성 등 기기별로 다르게 답할 수 있다. 모름은 지연 0이라 안전하지만, 잘못 `exempt`로 읽히면 알림이 30분 늦는다 — 실기기 한 대(SM-S901N)로만 확인했다는 점을 기록에 남긴다.
