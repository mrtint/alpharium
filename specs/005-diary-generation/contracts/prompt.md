# 계약: 프롬프트 구성

**Feature**: 005-diary-generation | **모듈**: `src/diary/prompt.ts`

**기기를 모른다.** 문자열만 다루므로 전부 기기 없이 검증된다.

---

## 이 자리가 무엇을 지키는가

**여기가 헌법 원칙 II의 유일한 통과 지점이다.** 001의 `policy.ts`가 원칙 I을, 003의
`roster.ts`가 원칙 III을, 004의 `collect.ts`가 원칙 V를 한 곳에 모은 것과 같은 구조다.
화자가 휴대폰이라는 규칙이 저장소 전체에서 **여기 하나뿐**이어야 한다(FR-013b).

**동시에 원칙 V가 두 번째로 갈리는 자리다.** 004가 「관측한 것」과 「관측하지 못한 것」을
값에서 갈랐고, 이 자리가 그 구분을 **언어로 옮긴다.** 여기서 뭉개면 004가 지킨 것이
무의미해진다 — `unknown`을 「0걸음」으로 적는 순간 일기가 거짓을 쓴다.

---

## 함수

```
buildPrompt(request: DiaryRequest) → string
```

**입력이 `DiaryRequest` 하나인 이유**: 002가 이미 신호·캐릭터·시각 설정을 묶어 두었다.
따로 받으면 부르는 쪽이 조합을 만들 수 있고, 그러면 파이프라인이 넘긴 것과 다른 것이
모델에 갈 수 있다.

**출력이 문자열 하나인 이유**: `messages` 배열이 아니라 평문이다(research §4). 다섯
모델의 채팅 템플릿이 서로 다르면 최종 문자열이 모델마다 달라지고, **FR-005(양쪽이 같은
프롬프트)와 FR-014(다섯이 같은 구조)를 확인할 수 없다.**

---

## 불변식

### P1. 화자 규칙이 항상 들어간다 (FR-013·013a)

어떤 캐릭터, 어떤 신호에서도 프롬프트는 이것을 담는다:

- **"나"는 휴대폰이다** — 주인이 아니다
- **시야가 좁다** — 주머니와 가방 속에 있어 세상을 조금밖에 보지 못한다
- **기록에 없는 것을 단언하지 않는다** — 짐작은 괜찮다, 단언이 금지다

**세 번째의 표현이 중요하다.** "지어내지 마라"라고 쓰면 모델이 짐작까지 멈추고, 그러면
헌법 원칙 II가 **권장한** 것("아마 ~했을 것이다")까지 잃는다. 금지 대상은 **없는 대상을
등장시키는 것**이다.

### P2. 캐릭터에서 오는 것은 언어뿐이다 (FR-014·014a·014b)

```
quiet | narrative | imaginative → 한국어
chinese                        → 중국어
english                        → 영어
```

**이것 외에 캐릭터가 프롬프트에 영향을 주지 않는다.** 성격 지시("짧게 써라", "감정을
얹어라")를 넣지 않는다 — 그 성격은 **모델 자체의 성질**이고, 프롬프트로 만들면 관측된
성격이 아니라 우리가 지어낸 성격이 된다(원칙 III).

**금지**: 캐릭터별 분기를 언어 외의 것으로 넓히지 않는다. 넓히는 순간 로스터의 근거가
무너진다.

### P3. 신호의 세 갈래가 서로 다른 말이 된다 (FR-012a·b)

| 갈래 | 프롬프트에서 |
| --- | --- |
| `known` | 관측된 사실로 적는다 |
| `none` | **「없었다」** — 찾아봤는데 없었다 |
| `unknown` | **「모른다」** — 볼 수 없었다. 이유를 함께 적는다 |

**`unknown`을 0이나 빈 값으로 적지 않는다.** 걸음 수가 `unknown`인데 "0걸음"이라고 쓰면
일기가 "걷지 않았다"가 되고, 그것이 004가 막은 바로 그 거짓이다.

**`none`과 `unknown`을 같은 문장으로 적지 않는다.** 사진 0장은 일기의 내용이 되지만,
권한이 없어 못 본 것은 되지 못한다.

### P4. 관측의 한계가 함께 간다 (FR-012c·d)

004가 값에 붙여 둔 한계를 프롬프트도 옮긴다:

- **사진이 잘렸으면**(`complete: false`) — 그것이 그날의 전부가 아님을 적는다. **사진의
  수를 단언하지 말라는 지시를 함께 넣는다**(004 FR-014d)
- **자리가 사진에서 왔으면**(`source: "photo-exif"`) — 하루의 궤적이 아니라 **사진이 찍힌
  지점들**임을 적는다(004 FR-013e). `photosWithLocation` / `photosConsidered`가 함께 가야
  「열 장 중 두 장만 봤다」가 드러난다

**이것이 P3보다 미끄럽다.** `PhotoObservation`에서 `photos`만 꺼내 쓰면 한계가 사라지고,
그것이 004 FR-027이 편의 함수를 금지한 이유다. **이 모듈이 그 금지의 첫 시험대다.**

### P5. 모델 정보가 없다 (FR-015)

프롬프트에 모델 식별자·파라미터 수·양자화 방식·파일 이름이 들어가지 않는다. 모델이 자기
정체를 되뱉으면 그것이 화면으로 새는 경로가 된다(원칙 III).

### P6. 결정적이다

같은 입력 → 같은 문자열. 시각·난수를 읽지 않는다.

**왜 필요한가**: FR-016b-1(되뱉기 판정)이 **우리가 보낸 문자열을 알아야** 성립한다.
프롬프트가 부를 때마다 달라지면 판정이 무엇과 비교할지 모른다.

### P7. 고정 부분과 신호 부분이 갈린다

되뱉기 판정이 **고정 지시문만** 비교 대상으로 삼기 때문이다(research §7). 신호가 들어간
줄("사진 세 장")은 일기에 자연스럽게 나올 수 있으므로 비교하면 오탐이 된다.

```
buildPrompt(request)        → 모델에 보내는 전체 문자열
instructionLines(request)   → 되뱉기 판정이 비교할 지시문 줄들
```

**두 함수가 같은 상수에서 나와야 한다.** 각자 문자열을 들고 있으면 프롬프트를 고칠 때
한쪽만 바뀌고, 그 순간 판정이 조용히 무력해진다.

**⚠️ 구현 중 계약이 하나 바뀌었다 (2026-08-17).** 처음에는 `instructionLines()`가 인자를
받지 않는 「고정 줄」이었다. 그런데 경고 두 줄(잘림·자리 한계)은 **그 하루의 신호에 따라
프롬프트에 들어가기도 하고 빠지기도 한다.** 인자 없이 늘 반환하면 사진이 잘리지 않은
하루에서 P-7이 깨진다.

둘을 목록에서 빼는 선택지도 있었으나 **그러면 모델이 그 두 줄을 그대로 되뱉어도 잡지
못한다** — 지시문인데 판정에서 빠지는 구멍이 생긴다. 그래서 `request`를 받아 **그
프롬프트에 실제로 들어간 지시문**을 반환한다. 반환값이 신호 값을 담지 않는 성질은
그대로이므로 오탐은 나지 않는다.

---

## 금지 (다른 계약과 같은 형태)

- **캐릭터별 프롬프트 분기를 언어 외로 넓히지 않는다**(P2)
- **`unknown`에 기본값을 넣지 않는다**(P3) — 004 FR-003의 연장
- **`PhotoObservation`·`PhotoPlaces`에서 알맹이만 꺼내지 않는다**(P4) — 004 FR-027
- **시각·난수를 읽지 않는다**(P6)
- **모델 정보를 담지 않는다**(P5)
- **프롬프트 문자열을 이 모듈 밖에서 만들지 않는다**(FR-013b) — 데스크톱 어댑터도 이것을
  부른다

## 검증 (기기 불필요)

| # | 무엇 | 어떻게 |
| --- | --- | --- |
| P-1 | 화자 규칙이 항상 있다 | 다섯 캐릭터 × 여러 신호 조합에서 화자 문구 포함 |
| P-2 | 언어만 캐릭터에서 온다 | `chinese`/`english` 프롬프트에 한국어 지시가 없다. 나머지 부분은 다섯이 동일 |
| P-3 | 세 갈래가 다른 문자열 | `known`/`none`/`unknown`이 서로 다른 문장. **`unknown`에 "0"이 없다** |
| P-4 | 한계가 전달된다 | `complete: false`면 「전부가 아님」이, `places`가 있으면 「궤적이 아님」이 들어간다 |
| P-5 | 모델 정보 없음 | 로스터의 `key`·`url` 조각이 프롬프트에 없다 |
| P-6 | 결정적 | 같은 입력 두 번 → 같은 문자열 |
| P-7 | 두 함수가 일치 | **다섯 가지 하루 모양 각각에서** `instructionLines(request)`의 모든 줄이 `buildPrompt(request)` 결과에 들어 있다 |

**P-7이 회귀를 막는 장치다.** 프롬프트를 고치면서 판정 쪽을 잊으면 이 테스트가 깨진다.
