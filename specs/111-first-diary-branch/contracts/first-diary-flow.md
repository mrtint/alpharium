# Contract: 첫 일기 흐름

## 단계 전이 (`firstDiaryNext`)

| # | 지금 | 사건 | 다음 |
| --- | --- | --- | --- |
| FD1 | `before` | `liveness-passed` | `reading` |
| FD2 | `before` | `liveness-skipped` | `done` |
| FD3 | `reading` | `material-read`(canAsk 참) | `asking` |
| FD4 | `reading` | `material-read`(canAsk 거짓) | `done` |
| FD5 | `asking` | `confirmed` | `writing` |
| FD6 | `asking` | `later` | `done` |
| FD7 | `writing` | `write-settled`(`failed`), `rolledBack` 거짓 | `before`, `rolledBack` 참 |
| FD8 | `writing` | `write-settled`(`failed`), `rolledBack` 참 | `done` |
| FD9 | `writing` | `write-settled`(그 밖) | `done` |
| FD10 | 표에 없는 조합 | 아무 사건 | 그대로 |
| FD11 | 초기값 | — | `before`, `rolledBack` 거짓 |

## 결과 갈래 (`firstWriteOutcome`)

| # | 입력 | 갈래 |
| --- | --- | --- |
| FO1 | 시작 거절(흉내·쓰는 중·남의 쓰기·캐릭터 없음) | `refused` |
| FO2 | 홈의 그만두기·지우기 요청 | `stopped` |
| FO3 | `ok: true` | `saved` |
| FO4 | `cancelled: true` | `stopped` |
| FO5 | `stage: "already-running"` | `busy` |
| FO6 | 사유 분류가 `interrupted` | `interrupted` |
| FO7 | 그 밖의 `ok: false`, 쓰기가 던짐 | `failed` |

## 재료 읽기 (`readFirstDiaryMaterial`)

- FM1 오늘 일기가 있으면 미리보기를 읽지 않고 `canAsk: false`.
- FM2 `decideMaterial`이 `write`면 `canAsk: true`, `confirm`이면 `false`.
- FM3 일기 유무·미리보기가 던지면 `canAsk: false`. 던지지 않는다.
- FM4 한도(`FIRST_DIARY_READ_LIMIT_MS`, 10초 — 사람이 정한 값)를 넘으면 `canAsk: false`.

## 홈 쓰기 요청 (`DiaryHomeScreen`)

요청에 `firstDiary: { silencesFailure(result) }`가 있으면:

- HR1 이어 하기를 신청한다(없으면 종전대로 신청하지 않는다).
- HR2 끝나면 `onWriteRequestSettled(id, settled)`를 **한 번** 부른다. `settled`는 `refused` · `stopped` · `threw` · `finished(result)`.
- HR3 `silencesFailure(result)`가 참이면 실패 토스트를 올리지 않는다. 실패 기록은 그대로 남는다.
- HR4 `firstDiary`가 없는 요청(진단)은 종전과 같다: 콜백 없음, 이어 하기 없음, 토스트 있음.

## 훅 (`useFirstDiaryFlow`)

`App.tsx`가 부르고 시험이 실제 홈과 묶어 돌린다.

- HK1 `reading`에 들어가면 재료를 한 번 읽고 `material-read`로 넘어간다. 언마운트 뒤의 결과는 버린다.
- HK2 `writeRequest` 만들기: `asking`의 `confirm()`이 재료를 읽은 날로 요청을 낸다. `silencesFailure(result)`는 그 결과가 FD7로 갈 때만 참이다.
- HK3 FD7이면 `onRollBack`을 한 번 부른다.
- HK4 실제 홈과 묶은 조립 시험: 실패 → 토스트 없음·`onRollBack` / 되돌림 뒤 실패 → 토스트·`done` / 그만두기 → 토스트 없음·`done` / 저장 → `done`. 실패 기록은 실패마다 남는다.

## 조립 (`App.tsx`)

- AS0 정상 동작 확인은 재료를 읽기 전에 재료와 상관없이 돈다(FR-001). 흐름은 확인 결과 뒤에만 시작한다.
- AS1 확인 통과와 `liveness-passed`는 같은 차례에 일어나 홈이 한 프레임도 먼저 그려지지 않는다. `reading`이면 `WelcomeScreen`(`checking`).
- AS2 `liveness-passed`에서 첫 실행 표식을 세워 앱 열기 자동 쓰기가 시작하지 않는다(057).
- AS3 `asking`이면 홈 위에 확인창. `써 보기` = 재료를 읽은 날의 쓰기 요청, `나중에`·뒤로 가기 = `later`.
- AS4 FD7이면 `livenessOutcome`을 비우고 확인을 다시 돌린다.
- AS5 `done`은 흐름의 끝을 읽는 유일한 값이다. 작명을 이번 실행에 하지 않은 실행은 `before`에 머문다(G4는 이 실행에서 `done`이 된 때만 본다).
- AS6 파이프라인을 직접 실행하는 첫 실행 경로가 없다(`triggerFirstRunAutoDiary`·`shouldAutoGenerate`·`autoGeneratedToken` 소멸).
