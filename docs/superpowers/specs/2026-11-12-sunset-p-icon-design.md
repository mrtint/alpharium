# 앱 아이콘을 노을 「P.」로 바꾼다 — 설계 (보드 밖)

- 경로: 아키텍처형(아이콘 정본의 형식이 바뀐다). 규모 판정은 전체 트랙 — 새 정본 형식(그림 SVG), 변경 파일 5개 초과, 수용 기준 3개 초과.
- 입력: 로드맵 「앱 아이콘을 노을 「P.」로 바꾼다」, `design/icon-candidates/sunset-p/README.md`, 102의 `design/icon.json`·`scripts/design/icon-build.ts`.

## 이해한 것 (소유자가 한 말과 내가 채운 것)

**소유자가 정한 것**: 노을 풍경을 품은 「P」를 A안(작은 원을 기둥 옆 마침표로 옮긴 「P.」)으로 앱 아이콘에 쓴다. 정본은 **(가) 그림 SVG**다 — 생성기는 래스터화·배율만 맡는다. 안드로이드 foreground 배율 0.784·iOS 1.0은 런처를 보기 전의 임시값이다. PNG는 손으로 만들지 않는다.

**성공 모습**: `npm run build:icons -- --check` 0, 두 런처(갤럭시 SM-S901N 런처, iPhone 14 홈 화면)에서 본 것·못 본 것이 기록에 남고, DESIGN.md·AGENTS.md의 아이콘 서술이 새 아이콘으로 고쳐진다.

**내가 채운 가정**: 앱의 강조색(빨강)과 아이콘의 파스텔 노을이 갈라지는 것은 소유자가 시안을 받아들인 결과로 본다 — 토큰·화면은 이 과제에서 바꾸지 않는다.

## 설계

### 1. 정본 — 그림 하나, 배치 값 하나

- **그림 정본**: `design/icon-art.svg`(1024×1024 좌표계, 그림 전체가 한 `<g id="art">`). 후보 `source.svg`에서 작은 원만 마침표 자리 `(508, 875)`로 옮긴 것이다. 그라데이션·경로·clipPath·16진수 색은 이 파일에만 있다. `<defs>`에 `<path id="p-shape">`(P 윤곽)와 `<circle id="dot-shape">`(마침표)를 두고 그림은 이것을 `<use>`로 쓴다 — monochrome이 같은 모양을 다시 쓰기 위해서다.
- **배치 정본**: `design/icon.json`은 모양 대신 **그림을 놓는 값**만 정한다 — 그림 파일 이름, 그림 중심 `(473.1, 561.5)`(P를 감싸는 가장 작은 원의 중심, 후보 README의 실측), 출력별 배율(iOS 1.0 · 안드로이드 foreground/monochrome 0.784 · 기능 그래픽 0.5), 안전 영역 66/108. 색은 적지 않는다.
- 래퍼는 생성기가 만든다: `translate(W/2 H/2) scale(s) translate(-cx -cy)`. 래퍼는 그림 파일 밖에 있어 그림 파일은 그대로 유지된다.

### 2. 생성기 — 래스터화만

- SVG를 PNG로 바꾸는 자리는 `scripts/design/icon-build.ts` **하나**다. 래스터라이저는 `@resvg/resvg-js`(devDependency, 정확한 버전 고정)다. 지금 저장소에는 SVG 렌더러가 없고(102 R1은 기하 도형 때문에 3×3 슈퍼샘플링을 직접 짰다), 그라데이션·곡선·clipPath·불투명도를 직접 그리면 SVG 렌더러를 다시 짜는 일이다.
- 출력 목록은 102 그대로다: `assets/icon.png`(RGB, 알파 없음)·`android-icon-foreground.png`(투명 바탕)·`android-icon-background.png`·`android-icon-monochrome.png`·`favicon.png` 48·`store/ko/store-icon-512.png`(RGBA)·`feature-graphic-1024x500.png`(RGB)·`design/icon.svg`(iOS 합성 SVG 미리보기 — 이제 래스터화에 쓴 바로 그 SVG 문자열).
- 출력별 합성:
  - iOS·favicon·스토어 512: 배경 그라데이션(`#bg`) + 그림, 배율 1.0.
  - 안드로이드 background: `#bg`만(그림 파일의 배경 사각형을 같은 방식으로 그린다).
  - 안드로이드 foreground: 그림만, 투명 바탕, 배율 0.784.
  - 안드로이드 monochrome: `p-shape` + `dot-shape`를 검정 단색으로(알파만 쓰인다), 배율 0.784.
  - 기능 그래픽 1024×500: 배경 그라데이션이 캔버스를 채우고 그림은 가운데, 배율 0.5.
- 불투명(알파 없음) 출력은 resvg 결과를 RGBA로 받아 알파를 지워 RGB로 쓴다(바탕이 `#bg`로 완전히 덮이므로 알파는 255다).

### 3. 규칙 — 16진수는 그림 파일에만

- `icon.json`에 16진수가 없다(I1을 이 뜻으로 바꾼다). 16진수 색은 `design/icon-art.svg` **한 파일에만** 있고 계약 테스트가 다른 곳(생성기·icon.json·docs 제외)에 새로 생기지 않는지 본다.
- `app.json`의 adaptive `backgroundColor`는 그림의 `#bg` 첫 정지점 색과 같아야 한다(테스트가 SVG에서 읽어 대조). 이 값은 OS가 이미지 대신 쓰는 폴백이다.
- DESIGN.md의 「색은 토큰으로만」·「보드에 없는 장식(그림자·그라데이션) 금지」에 **아이콘 그림 한정 예외**를 적는다 — 앱 화면·웹에는 그대로다.

### 4. 정리

- `design/icon-candidates/sunset-p/`는 승격 뒤 지운다(파생 SVG·미리보기 PNG는 생성기가 다시 만들 수 있고 원본은 `design/icon-art.svg`의 출처가 되며 git 기록에 남는다). 후보 README의 알려진 문제·실측은 스펙의 「배경」으로 옮긴다.
- 로드맵 「앱 아이콘·등록 에셋 마무리 확인」의 아이콘 항목(iOS 배율 2.3, monochrome)은 이 과제로 대체된다 — 항목에서 걷고 iPad 호환·스크린샷·콘솔 글자 한도만 남긴다.

### 5. 테스트(`__tests__/design/icons.test.ts`를 새 정본에 맞춘다)

- 102의 줄을 이어 가는 것: 생성물 픽셀 대조(I3), iOS 알파 없음(I4), 크기(FR-004), `app.json` 경로(I6), 위반 주입(배율 키우면 안전 영역 넘음, 픽셀 변조, 알파 낮춤).
- 새로 생기는 것: 그림 파일의 마침표가 기둥 옆 `(508, 875)`(A안)인지, 16진수는 그림 파일에만 있는지, monochrome의 불투명 픽셀이 안전 영역 안이고 P 윤곽과 마침표 둘 다 있는지, foreground 감싸는 원이 안전 영역 안인지(A안의 0.784 근거), 없는 그림 파일·없는 `id`를 가리키면 아무것도 쓰지 않고 실패하는지.

## 수용 기준

1. `design/icon-art.svg`가 정본이고 `icon.json`은 배치 값만 가진다. 생성기가 둘에서 102의 출력 목록을 그대로 만든다.
2. `npm run build:icons -- --check`가 0이고 `__tests__/design/icons.test.ts`가 생성물을 픽셀까지 대조한다(안전 영역·알파·monochrome·16진수 가둠 포함).
3. DESIGN.md·AGENTS.md의 아이콘 서술이 새 아이콘으로 고쳐지고 로드맵이 정리된다.
4. `expo prebuild --clean` 뒤 갤럭시 런처에서 foreground·monochrome을 보고, iPhone 14 홈 화면은 소유자가 본 결과를 받아 기록한다. 못 본 것은 못 봤다고 적는다.

## 남은 위험

작은 크기(29~48px)에서 풍경이 뭉개진다 · 아이콘(파스텔)과 앱·스플래시(빨강)가 갈라진다 · resvg 픽셀이 플랫폼마다 다를 수 있다 · iPhone 홈 화면은 소유자의 눈이 필요하다.
