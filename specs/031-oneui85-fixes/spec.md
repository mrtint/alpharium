# Feature Specification: One UI 8.5+ 다크 모드 dimmed 화면 + 온보딩 photo-location 무반응 수정

**Feature Branch**: `031-oneui85-darkmode-photolocation`

**Created**: 2026-09-03

**Status**: Draft

**Input**: User description: "One UI 8.5+ 두 가지 버그 수정 — ① 다크 모드 시 앱 화면이 dimmed/까맣게 보임, ② 온보딩 photo-location 단계에서 '허용' 버튼이 무반응(무한 갇힘). 로드맵 20번 참조. 브랜치 031에서 작업. 완료 후 One UI 8.5 기기(S24U, SM-S928N)에서 실기기 검증(다크 모드 auto로 두고 밤 시간대 + 새 설치 온보딩)."

두 결함 모두 **One UI 8.5+에서만** 드러난다. S22/S20+(이전 세션의 주 검증 기기)에서는 낮에 써서 ①이 안 보였고, ②는 우연히 "건너뛰기"만 눌러 지나쳤다. 사용자가 어제(2026-09-02) 22시대에 찍은 스크린샷 2장이 ①을 증명한다.

## Clarifications

### Session 2026-09-03

- Q: ② 온보딩 "photo-location" 단계를 어떻게 처리할까? → A: **온보딩에서 단계를 제거한다.** `PERMISSION_REQUIREMENTS`에서 `photo-location` 항목을 빼고 `order`를 재배치(사진 1·위치 2·알림 3·배터리 예외 4). 사진 좌표는 신호 수집 계층이 실제로 읽어보고 처리하므로(FR-013a) 온보딩에서 물어볼 이유가 없다. 설정 탭 "권한" 섹션의 `photo-location` 행도 함께 제거한다. 매니페스트의 `ACCESS_MEDIA_LOCATION` 선언·플러그인 설정(`isAccessMediaLocationEnabled: true`)은 유지한다.
- Q: ① 다크 모드 라이트 고정을 어떤 수단으로 할까? → A: **`expo-system-ui` 설치 + `AppTheme` 부모를 `DayNight` → `Light`로 교체(이중).** `npx expo install expo-system-ui`로 `app.json`의 `userInterfaceStyle: "light"`가 실제 네이티브에 적용되게 하고(RN 뷰·컴포넌트 레벨), 추가로 plugin(`plugins/with-*.js` 형태)으로 `AppTheme`의 부모 테마를 `Theme.AppCompat.DayNight.NoActionBar` → `Theme.AppCompat.Light.NoActionBar`로 바꿔 윈도우 배경이 시스템 night 모드에 끌려가는 것을 막는다(윈도우 배경 레벨). `expo-system-ui`는 새 네이티브 모듈이므로 release 빌드 재확인 1회가 필요하다(012).
  - **실기기 조사로 정정(2026-09-03, SM-S928N)**: 초안은 "`forceDarkAllowed=false`로 One UI의 **force-dark 반전**을 차단"이었으나, 그 속성을 양쪽 테마(+`-v29`)에 넣은 빌드에서도 배경이 `#303030`(`background_material_dark`)으로 나왔다. 원인은 force-dark 반전이 아니라 **`DayNight` 부모 테마가 시스템 night 모드에서 윈도우 배경을 다크로 해석**하는 것이었고(`expo-system-ui`의 `MODE_NIGHT_NO`는 리소스 계층만 되돌림, `uiMode`가 `configChanges`에 있어 Activity 재생성도 안 됨), 진짜 수정은 **부모 테마 교체**다. `forceDarkAllowed=false`는 제조사 force-dark 대비 방어로 함께 남긴다. research.md R1a에 상세.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 밤에 앱을 열어도 화면이 정상으로 보인다 (Priority: P1)

주인이 저녁~밤에 휴대폰의 시스템 다크 모드가 켜진 상태에서 앱을 연다. 일기 목록·상세·온보딩·설정 어느 화면이든 배경과 글자가 또렷하게 보이고, 낮에 보던 것과 같은 밝은 화면이 나온다. "화면이 어둡게 눌린 것 같다", "글자가 안 보인다"는 일이 없다.

**Why this priority**: 사용자가 어제 실제로 겪은 증상이고(스크린샷 2장), 다크 모드를 자동(시간대)으로 쓰는 사람은 매일 밤 앱이 사실상 못 읽는 상태가 된다. 배포하면 다크 모드 사용자 전체가 영향받는다 — 12번(배포용 패키징)보다 먼저 막아야 한다.

**Independent Test**: One UI 8.5 기기에서 시스템 다크 모드를 켠 뒤(또는 `adb shell "cmd uimode night yes"`) 앱의 모든 주요 화면을 열어, 배경이 밝고 글자 대비가 충분한지 눈으로 확인한다. 어제 스크린샷과 나란히 비교한다.

**Acceptance Scenarios**:

1. **Given** 기기 시스템 다크 모드가 켜져 있고 앱이 설치돼 있다, **When** 사용자가 앱을 연다, **Then** 일기 목록 화면의 배경은 밝고(라이트) 글자는 어둡게 또렷이 보인다 — 낮에 여는 것과 화면이 같다.
2. **Given** 다크 모드가 켜진 상태로 앱이 홈에 있다, **When** 사용자가 일기 하나를 눌러 상세로 들어간다, **Then** 상세 화면(제목·본문·사진 슬라이더)도 밝은 배경으로 정상 표시된다.
3. **Given** 새로 설치해 다크 모드가 켜진 상태다, **When** 앱을 처음 열어 온보딩·에셋 다운로드 화면이 뜬다, **Then** 온보딩 화면의 텍스트·진행률 바·버튼이 밝은 배경 위에서 또렷하게 보인다(어제 22:03 스크린샷의 dimmed 상태가 재현되지 않는다).
4. **Given** 앱을 켠 상태에서 시스템이 다크 모드로 자동 전환된다(예: 일몰 시각 도래), **When** 사용자가 앱으로 돌아온다, **Then** 화면은 여전히 밝은 배경으로 유지되고, 어두워지거나 레이아웃이 깨지지 않는다.
5. **Given** 시스템 다크 모드가 꺼진(라이트) 상태다, **When** 사용자가 앱을 연다, **Then** 지금까지와 똑같이 정상 표시된다 — 이번 수정이 라이트 모드 동작을 바꾸지 않는다.

### User Story 2 - 온보딩이 "사진 위치" 단계에서 막히지 않는다 (Priority: P1)

새 사용자가 앱을 처음 설치하고 온보딩을 진행한다. 사진 권한을 허용하면 온보딩은 **곧바로 다음 단계(위치)로 넘어간다** — "사진에 담긴 위치"라는 별도 단계가 아예 나타나지 않는다. "허용"을 눌렀는데 아무 일도 안 일어나 같은 화면에 갇히는 일이 없다.

**Why this priority**: 사용자가 정확히 관찰한 결함("당장 시작하기도 안 눌려", "건너뛰기만 해야 하는 경험"). 새 설치 사용자가 온보딩에서 막히면 앱을 아예 못 쓴다. "건너뛰기"를 아는 사용자만 겨우 빠져나온다. 이 단계는 판정할 방법이 없어(`ACCESS_MEDIA_LOCATION` 조회 API 부재) 온보딩에서 물어볼 수 없다 — 제거가 옳다.

**Independent Test**: 앱을 완전히 새로 설치(uninstall 후 install)하고 One UI 8.5 기기에서 온보딩을 진행한다. 사진 단계에서 "모두 허용"을 누른 뒤, 다음 화면이 "사진 위치"가 아니라 "위치"(장소명) 단계인지 확인한다. 온보딩 단계 수가 4개(+에셋)인지 센다.

**Acceptance Scenarios**:

1. **Given** 새로 설치한 앱의 온보딩 사진 단계에 있다, **When** 사용자가 "모두 허용"을 누른다, **Then** 다음 화면은 "위치"(장소명) 단계다 — "사진에 담긴 위치" 단계는 나타나지 않는다.
2. **Given** 사진 단계에서 "건너뛰기"를 눌렀다, **When** 다음 단계로 넘어간다, **Then** 마찬가지로 "위치" 단계가 나온다(사진을 건너뛰어도 "사진 위치"를 별도로 묻지 않는다).
3. **Given** 온보딩의 모든 단계를 주 동작(허용/건너뛰기)으로 통과했다, **When** 마지막 에셋 다운로드 단계까지 진행한다, **Then** "필수 에셋 다운로드" 화면에 정상 도달한다 — 어느 권한 단계에서도 갇히지 않았고, 거친 권한 단계는 사진·위치·알림·배터리 예외 4개다.
4. **Given** 온보딩을 마치고 앱을 쓰던 중 설정 탭의 "권한" 섹션을 연다, **When** 목록을 본다, **Then** "사진에 담긴 위치" 항목이 목록에 없다 — 사진·위치·알림·배터리 예외 항목만 보인다.
5. **Given** 사진 권한을 허용해 사진 좌표가 있는 하루의 일기를 쓴다, **When** 그 일기를 확인한다, **Then** 사진 좌표로 장소를 짐작하는 동작이 이번 수정 전과 똑같이 작동한다(권한 있으면 지명, 없으면 비움) — 온보딩 단계를 뺀 것이 실제 기능에 영향을 주지 않는다.

### Edge Cases

- **다크 모드 auto가 앱 실행 중 전환**: 사용자가 앱을 켠 채로 일몰 시각이 지나 시스템이 다크로 바뀌면 — 앱 화면은 밝게 유지되어야 한다(레이아웃 재생성·깜빡임·색 반전 없음).
- **"자세히 봄"/"Extra dim" 등 다른 화면 어둡게 기능**: 시스템 다크 모드와 별개인 초저휘도·블루라이트 필터가 켜져 있어도 이번 수정 범위는 **시스템 다크 모드(night mode)** 뿐이다. 그 외 기능으로 화면이 전반적으로 어두워지는 것은 OS 레벨이며 앱이 관여하지 않는다(범위 밖으로 명시).
- **사진 위치 항목 제거 범위**: 온보딩(`OnboardingScreen`)과 설정 탭 "권한" 섹션(`PermissionsSection`) **둘 다**에서 `photo-location` 항목이 사라져야 한다. `App.tsx`가 `PERMISSION_REQUIREMENTS[...].ifDenied`를 모아 만드는 `deniedNotices`에서도 `photo-location`의 거부 안내가 빠진다(021 FR-014 경로). 한쪽만 빼면 두 화면이 어긋난다.
- **이미 온보딩을 마친 사용자**: 이번 수정을 담은 새 버전으로 업데이트한 기존 사용자는 온보딩을 다시 보지 않는다(`completed` 유지). 사진 위치 단계 변경은 새로 온보딩하는 사용자와 "권한 안내 다시 보기"를 누른 사용자에게만 보인다.
- **iOS**: `userInterfaceStyle` 설정은 iOS에도 적용되지만, 이 프로젝트의 실기기 검증은 Android 전용이다(Expo Go 불가, `llama.rn`). iOS 동작은 이번 검증 범위 밖이나, 라이트 고정 설정이 iOS를 깨지 않아야 한다.

## Requirements *(mandatory)*

### Functional Requirements

**① 다크 모드 dimmed 수정**

- **FR-001**: 앱은 시스템(기기)의 다크 모드 설정과 무관하게 **항상 라이트(밝은) 외형**으로 표시되어야 한다. 시스템 다크 모드가 켜져 있어도 앱의 배경·글자·컴포넌트 색이 라이트 모드와 동일해야 한다. 라이트 고정은 앱 레벨 선언(`userInterfaceStyle: "light"`가 `expo-system-ui`로 실제 적용됨 — RN 뷰 레벨)과 **`AppTheme`을 비-DayNight(`Theme.AppCompat.Light`) 테마로 만들어 윈도우 배경이 시스템 night 모드를 따라가지 않게 하는 것**(윈도우 배경 레벨) **둘 다**로 달성되어야 한다 — 한쪽만으로는 부족하다(실기기 확인: `expo-system-ui` 단독으로는 윈도우 데코 배경이 `#303030`으로 잔존). `forceDarkAllowed=false`는 제조사 force-dark 대비 방어로 함께 둔다.
- **FR-002**: 이 라이트 고정은 앱의 **모든 화면**에 적용되어야 한다 — 온보딩, 일기 목록, 일기 상세(사진 슬라이더·갤러리 포함), 설정, 생성 중 화면, 진단/개발자 탭. 특정 화면만 라이트이고 다른 화면은 시스템을 따라가는 상태가 없어야 한다.
- **FR-003**: 앱 실행 중 시스템 다크 모드가 전환되어도(auto 설정으로 일몰/일출 시각 도래) 앱 화면은 라이트를 유지해야 하며, 화면 재생성·깜빡임·부분적 색 반전이 없어야 한다.
- **FR-004**: 라이트 모드에서 앱이 지금 표시되는 방식은 이번 수정으로 바뀌지 않아야 한다(회귀 없음).
- **FR-005**: 이 수정은 "화면을 어둡게" 계열의 다른 OS 기능(초저휘도, 블루라이트 필터, 절전 모드의 화면 어둡게)까지 무력화하지 않는다 — 대상은 시스템 다크 모드(night mode) 하나다.

**② 온보딩 photo-location 무반응 수정**

- **FR-006**: 온보딩의 "사진 위치"(`photo-location`, `ACCESS_MEDIA_LOCATION`) 단계는 **온보딩 흐름에서 제거**되어야 한다 — 사용자가 이 단계를 마주하는 일 자체가 없어야 한다. 사진 권한을 허용한 뒤 온보딩은 곧바로 다음 실제 단계(위치 → 알림 → 배터리 예외)로 진행된다.
- **FR-007**: 온보딩의 어느 단계에서도 사용자가 갇히지 않아야 한다 — "사진 위치" 제거 후 남는 단계(사진·위치·알림·배터리 예외)는 각각 "허용" 또는 "건너뛰기"로 반드시 다음으로 넘어간다.
- **FR-008**: "사진 위치" 제거로 남는 권한 단계의 순서·문안·동작·건너뛰기 가능성은 그대로 유지되어야 한다 — 단계가 하나 빠질 뿐 나머지 단계가 달라지지 않는다.
- **FR-009**: 설정 탭 "권한" 섹션에서도 사진 위치(`photo-location`) 항목이 **제거**되어야 한다 — 온보딩과 설정 화면이 일관되게 사진 위치를 별도 항목으로 다루지 않는다. 사진 권한 항목의 안내 문안은 **변경하지 않는다** — 사진 위치는 사용자가 인지할 필요 없는 자동 처리이므로 사진 권한 문안에 그 언급을 더하지 않는다.
- **FR-010**: 사진 위치(`ACCESS_MEDIA_LOCATION`)를 **실제로 사용하는 기능**(사진 좌표로 장소를 짐작하는 신호 수집)의 동작은 이번 수정으로 바뀌지 않아야 한다 — 좌표를 읽을 수 있으면 읽고, 없으면 비워 두는 기존 판정이 유지된다.
- **FR-011**: 앱이 요구하는 권한 목록(매니페스트에 선언된 권한)은 이번 수정으로 줄어들지 않는다 — 온보딩·설정 화면에서 항목을 빼더라도 `ACCESS_MEDIA_LOCATION` 선언과 `expo-media-library` 플러그인 설정(`isAccessMediaLocationEnabled: true`)은 그대로 유지된다.

**검증**

- **FR-012**: 두 수정은 One UI 8.5 이상 기기(SM-S928N/S24 Ultra)에서 실기기로 검증되어야 한다 — ①은 시스템 다크 모드를 켠 상태(auto라면 밤 시간대 또는 강제 전환)에서, ②는 앱을 완전히 새로 설치한 온보딩에서.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: One UI 8.5 기기에서 시스템 다크 모드를 켠 채 앱의 6개 화면군(온보딩, 일기 목록, 일기 상세, 설정, 생성 중, 개발자 탭)을 열었을 때 **6/6 모두** 밝은 배경 + 충분한 글자 대비로 표시된다. 어제(2026-09-02) 22시대 스크린샷의 dimmed 상태가 **0건** 재현된다.
- **SC-002**: 앱을 완전히 새로 설치하고 One UI 8.5 기기에서 온보딩을 진행할 때, 사진 권한을 허용하면 **"사진 위치" 단계가 나타나지 않고** 곧바로 다음 단계(위치)로 넘어간다. `PERMISSION_REQUIREMENTS` 항목 수가 5→4로 준다(사용자가 체감하는 화면 수는 권한 상태에 따라 원래 가변 — 배터리 예외가 이미 조건부 자동 처리).
- **SC-003**: 온보딩 전체를 주 동작(허용/건너뛰기)으로 통과해 에셋 다운로드 화면까지 도달하는 성공률이 새 설치 시 100%다(어느 권한 단계에서도 갇히지 않는다).
- **SC-004**: SM-S901N/S22(One UI 8 이하)에서 라이트 모드 화면 6개군과 온보딩 흐름이 이번 수정 전과 동일하다 — 회귀 0건.
- **SC-005**: 설정 탭 "권한" 섹션과 온보딩(또는 "권한 안내 다시 보기") 어디에도 사진 위치(`photo-location`)가 **별도 항목으로 나타나지 않는다** — 두 화면 모두에서 이 항목이 사라졌고, 남은 항목(사진·위치·알림·배터리 예외)만 표시된다.
- **SC-006**: 사진 좌표로 장소를 짐작하는 신호 수집 동작(권한 있을 때 지명, 없을 때 비움)이 이번 수정 전후로 동일하다.

## Assumptions

- **다크 모드 원인은 `DayNight` 부모 테마의 윈도우 배경 해석이다** (실기기로 확정, 2026-09-03 SM-S928N — research.md R1a): `app.json`에 `userInterfaceStyle: "light"`가 선언돼 있으나 `expo-system-ui`가 없어 무시됐고, 설치해서 `AppCompatDelegate.setDefaultNightMode(MODE_NIGHT_NO)`가 돌아도 **리소스 해석 계층만** 라이트로 되돌아간다. `AppTheme`의 부모가 `Theme.AppCompat.DayNight.NoActionBar`(DayNight)라 시스템 night 모드에서 **윈도우 데코 배경이 만들어질 때** night 리소스(`#303030` = `background_material_dark`)로 칠해지고, 매니페스트 `android:configChanges`에 `uiMode`가 있어 Activity가 재생성되지 않아 그 배경이 잔존한다. **이건 force-dark 반전이 아니다** — 초안의 진단이 실기기에서 틀린 것으로 확인됐다(`forceDarkAllowed=false`를 양쪽 테마 + `-v29`에 넣어도 배경 `#303030` 유지). **수정 수단: `expo-system-ui` 설치 + `AppTheme` 부모를 `Theme.AppCompat.Light.NoActionBar`로 교체(config plugin). `forceDarkAllowed=false`는 방어로 유지.**
- **앱은 라이트 전용으로 설계돼 있다**: `src/ui/` 어디에도 다크 팔레트·색상 스킴 감지가 없다. 실제 다크 모드 대응(다크 팔레트 작업)은 이 스펙의 범위가 아니며 로드맵 11번(NativeWind UI)에 속한다. 이 스펙은 "다크 모드에서도 라이트로 보이게" 고정하는 것만 다룬다.
- **photo-location 단계는 판정 불가능하다**: `ACCESS_MEDIA_LOCATION`은 사용 중인 미디어 라이브러리 API에 전용 요청·조회 함수가 없다(021에서 확인·문서화된 제약, `expo-port.ts:95-97` 주석). 사진 권한이 허용되면 이 권한 상태는 항상 "미정"으로 판정되고, 온보딩이 "미정 → 사용자에게 물어봐야 함"으로 해석해 같은 단계를 무한 반복한다. **수정 방식은 clarify에서 확정: 온보딩·설정 양쪽에서 `photo-location` 단계/항목을 제거.** 021이 이 제약을 `collect.ts`(실제 좌표 읽기)에 흡수했으므로 온보딩에서 물어볼 이유가 없다.
- **실제 좌표 사용은 별도 경로가 담당한다**: 사진 좌표를 읽어 장소를 짐작하는 것은 신호 수집 계층이 "실제로 좌표를 읽어보고 실패하면 비운다"는 방식으로 이미 처리한다(021 설계, FR-013a). 온보딩 단계를 빼도 이 동작은 영향받지 않는다.
- **매니페스트 권한은 유지된다**: 온보딩·설정 화면에서 항목을 빼는 것과 앱이 그 권한을 선언·사용하는 것은 별개다. `ACCESS_MEDIA_LOCATION`은 `app.json` 권한 목록과 `expo-media-library` 플러그인 설정(`isAccessMediaLocationEnabled: true`)에 그대로 남는다.
- **검증 기기 상태**: S24U(SM-S928N)는 이번 조사 중 `pm clear` + 재설치로 모델·샘플 일기가 삭제됐다. 검증 세션 시작 시 dev 빌드 재설치 + 모델 재배치 또는 온보딩 에셋 다운로드(~2GB)가 필요하다.
- **다크 모드 검증은 시각 의존**: 사용자 기기는 다크 모드가 `auto`(시간대)다. 검증 시 밤 시간대에 하거나 `adb shell "cmd uimode night yes"`로 강제 전환한다. 강제 전환 후 반드시 `auto`로 복원한다.
- **release 재확인은 다크 모드 수정 때문에 필요하다**: `expo-system-ui`가 새 네이티브 모듈이므로 다크 모드 수정은 debug + release 각 1회 실기기 확인이 필요하다(012 기준). 온보딩 `photo-location` 제거는 순수 상수/화면 변경이라 debug 1회로 충분하나, 어차피 같은 세션에서 release도 도므로 함께 본다.
- **`checkOnboardingFile` 헌법 검사**: `src/onboarding/`는 `models/roster` 등 직접 import가 금지된 경계다(021). 이번 수정은 `requirements.ts`의 상수 항목을 빼는 것이라 이 경계를 새로 건드리지 않지만, 계약 테스트가 `PERMISSION_REQUIREMENTS`를 소스로 읽어 항목 수·`order`·문안 토큰을 잠그고 있으므로(021 관례) 그 테스트도 함께 갱신한다.
- **plan에서 볼 것**: `expo-system-ui` 버전은 Expo 57에 맞는 것을 `expo install`로 해석(`npm view` 금지 — AGENTS.md). `forceDarkAllowed` plugin은 `plugins/with-battery-exception.js`가 선례(선언적 매니페스트/테마 수정, `android/`는 gitignore이므로 build.gradle 직접 수정 금지).
