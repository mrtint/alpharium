# Quickstart: 실제 일기 생성

**Feature**: 005-diary-generation | **Date**: 2026-08-17

이 문서는 **이 기능이 실제로 됐는지 확인하는 절차**다. 구현 코드를 담지 않는다.

**건너뛴 실기기 검증은 통과가 아니다**(헌법 원칙 V). 기기 없이 전부 초록불이어도
`generate()`가 진짜 도는지는 검증되지 않은 상태다.

---

## 0. 준비

```powershell
npm install
npm run lint          # eslint + tsc + 헌법 검사
npm test              # 기기 불필요 갈래
```

**모델 파일이 기기에 있어야 한다**(003). 없으면 D1부터 막힌다 — 진단 화면의 캐릭터
목록에서 「준비 시작」으로 받는다. `quiet`가 md5 지문이 채록된 유일한 캐릭터이므로
**첫 확인은 `quiet`로 한다.**

## 1. 기기 없이 확인 (항상 돈다)

### N1 — 프롬프트가 세 갈래를 가른다 (원칙 V)

```powershell
npm test -- prompt
```

**보아야 할 것**:
- `unknown`인 신호가 **「0」이 아니라 「모른다」**로 나온다
- `none`과 `unknown`이 **서로 다른 문장**이다
- 잘린 사진(`complete: false`)에 「전부가 아님」이 붙는다
- `places`에 「궤적이 아님」이 붙는다

**여기서 `unknown`이 0으로 나오면 004가 지킨 것이 무의미해진다.** 프롬프트 경계가 원칙 V의
두 번째 시험대다.

### N2 — 판정이 넷을 넘지 않는다 (원칙 IV)

```powershell
npm test -- acceptance
```

**보아야 할 것**:
- `RejectReason`이 **넷**이다 (A-7)
- `Verdict`에 **number 필드가 없다** (A-8)
- 끊겼고 동시에 되뱉은 글이 `unfinished`로 나온다 — 순서가 지켜진다 (A-5)
- 정상 일기가 `echo`로 거부되지 않는다 (A-2b)

**A-7과 A-8이 이 기능의 자동 방어다.** 판정이 자라면 여기가 깨진다.

### N3 — 파이프라인이 처음으로 끝까지 간다

```powershell
npm test -- generate
```

**보아야 할 것**:
- 대역 엔진으로 파이프라인이 **`ok: true`**로 끝난다 — 002 이후 처음이다
- 대역이 빈 글/되뱉기/엉뚱한 언어를 내면 **저장이 일어나지 않는다**
- 실패 뒤 **기존 일기가 그대로 있다**
- 어느 실패 경로에서도 `unload()`가 불린다 (E-2)
- **끊긴 결과의 부분 출력이 저장되지 않는다** (E-6)

### N4 — 헌법 검사

```powershell
npm run check:constitution
```

원격 API 키·대체 응답 스위치가 설정에 없는지 본다. **모델 출력을 재지 않는다** —
그 경계가 `scripts/constitution-rules.ts` 주석에 있다.

## 2. 실기기 확인 (이것이 끝나야 기능이 끝난다)

### 붙이기 — 무선 adb (실측, AGENTS.md)

```powershell
adb mdns services              # 기기를 찾는다
adb connect <IP>:<포트>
adb reverse tcp:8081 tcp:8081  # Metro를 localhost로
adb shell dumpsys trust        # deviceLocked=0 확인 — 잠금 화면 위에서는 앱이 안 뜬다
```

**세 가지가 갖춰져야 돈다**(AGENTS.md 실측). 하나라도 없으면 화면에 값이 멀쩡히 있어도
실패한다:

1. Metro가 dev 환경으로 떠 있다 — `EXPO_PUBLIC_APP_ENV=dev npx expo start --dev-client`
2. 기기 잠금이 풀려 있다
3. 한글 검증 문구는 `-Dfile.encoding=UTF-8`이 필요하다 — `run-device-tests.mjs`가 넣는다

**`expo run:android --device`는 `IP:포트`를 받지 못한다** — 기기가 하나면 플래그를 뺀다.

### ⚠️ 실측으로 얻은 함정 (2026-08-17)

- **`expo run:android`를 비대화형에서 쓰지 않는다.** 포트 8081이 이미 쓰이면
  `Use port 8082 instead?`를 물으려다 `Input is required, but 'npx expo' is in
  non-interactive mode`로 죽는다. **`| tail`로 감싸면 그 사실조차 안 보인다.**
  → **Gradle을 직접 부르고**(`cd android && ./gradlew assembleDebug --console=plain`)
    Metro를 따로 띄운다.
- **죽인 빌드가 Gradle 락을 남긴다.** 다음 빌드가 `checkDebugAarMetadata`에서
  `Timeout waiting to lock file hash cache`로 실패한다. **코드 문제가 아니다** —
  `./gradlew --stop`으로 데몬을 정리하고 다시 돌린다.
- **`./gradlew clean`이 실패할 수 있다.** `:app:externalNativeBuildCleanDebug`가
  armeabi-v7a의 CMake를 다시 돌리려다 `Configuring incomplete`로 죽는다. **이것도 코드
  문제가 아니다** — 청소 작업이 CMake 캐시를 건드리는 것이며, 빌드 자체는 정상이다.
  깨끗한 빌드가 필요하면 `clean` 대신 **디렉터리를 지운다**:
  `rm -rf android/app/.cxx android/app/build`
- **무선 adb는 화면이 잠기면 끊긴다.** `adb devices`가 `offline`이 되고 `adb mdns
  services`도 아무것도 못 찾는다. **폰 화면을 켜 두어야 한다.** 다시 붙일 때는
  포트가 바뀌었을 수 있으므로 `adb mdns services`로 다시 찾는다.
- **기기에 어느 캐릭터의 모델이 있는지 먼저 본다.**
  `adb shell run-as <패키지> ls files/models/`로 확인한다 — 자산키(`a1`~`a5`)로 보이며,
  로스터가 그 매핑을 안다. 없는 캐릭터로 시험하면 `model-load-failed`가 나오고 그것이
  정상이지만, D2를 확인하려면 **있는 캐릭터**로 해야 한다.

### ⚠️ 이 기능은 매니페스트를 바꾸지 않는다

004에서 `expo run:android`가 prebuild를 건너뛰어 권한이 빠진 APK가 설치된 일이 있었다.
**이 기능은 새 권한을 요구하지 않으므로** 그 함정이 없다. 다만 `llama.rn`이 네이티브
모듈이므로 **네이티브 빌드가 필요하다** — JS만 고친 것이 아니다.

### D1 — 모델이 실제로 열리는가 (E-7)

진단 화면에서 `quiet`를 고르고 생성을 시도한다.

**보아야 할 것**: `initLlama`가 성공한다. 003은 파일을 두었을 뿐 **연 적이 없다** —
여기가 그 첫 확인이다.

**실패하면 볼 것**:
- 파일이 실제로 있는가 — `adb shell run-as <패키지> ls -la files/`
- 메모리가 모자란가 — `n_ctx`를 줄여 본다(D4와 이어진다)
- 003의 md5 검증을 통과했는가

### D2 — 일기가 실제로 나오는가 (SC-001, E-8) ★

**이 기능의 존재 이유다.**

닫힌 하루(어제)를 고르고 생성을 요청한다.

**보아야 할 것**:
- 일기가 나온다
- 파이프라인이 **`generation`에서 멈추지 않는다** — 002 이후 처음이다
- 저장된다

**나온 글을 사람이 읽는다**(D6로 이어짐).

### D3 — 백그라운드로 갈 때 끊기고 정리되는가 (E-9)

생성이 도는 중에 **홈 버튼을 누른다.** 다시 앱으로 돌아온다.

**보아야 할 것**:
- 생성이 끊긴다
- **일기가 저장되지 않았다** — 부분 출력이 남으면 FR-021c 위반이다
- 앱으로 돌아와 **다시 요청하면 정상적으로 돈다** — `unload()`가 됐다는 증거다

**두 번째 요청이 메모리 부족으로 죽으면 E2가 깨진 것이다.** 이 확인이 D3의 핵심이며,
끊김 자체보다 **정리가 됐는지**가 중요하다.

**짐작인 부분**(research §2): `stopCompletion()`이 얼마나 빨리 듣는지 모른다. 즉시 듣지
않으면 돌아온 뒤 잠깐 기다려야 할 수 있다.

### D4 — `n_ctx` 2048이 맞는가 (E-10)

사진이 여러 장인 하루(신호가 많은 하루)로 생성한다.

**보아야 할 것**: `context_full`로 거부되는 일이 **잦지 않다.**

**잦으면**: `n_ctx`를 올린다. 다만 메모리를 먹으므로 D1이 깨질 수 있다 — 둘이 맞물린
값이다. **2048은 짐작이며, 여기서 재면 실측이 된다**(원칙 V).

### D5 — 생성이 얼마나 걸리는가 ★ 판단이 필요한 자리

**시계로 잰다.**

**왜 재는가**: FR-021b(앱이 앞에 있을 때만)가 사용성 문제가 될지 **여기서 갈린다.**
체크리스트가 남긴 위험이며, 이 관측이 그 결정을 다시 볼 유일한 근거다.

| 걸린 시간 | 뜻 |
| --- | --- |
| ~30초 | FR-021b가 문제가 되지 않는다 |
| 1~2분 | 견딜 만하나 「쓰고 있다」 표시가 반드시 필요하다 |
| 3분 이상 | **결정을 다시 볼 근거다** — 백그라운드 실행이라는 축을 열지 판단한다 |

**⚠️ 재되 코드에 담지 않는다**(FR-011, 원칙 IV). 사람이 보고 판단하는 값이지 제품이 아는
값이 아니다. **이 구분이 원칙 IV의 경계다** — 재는 것이 금지된 게 아니라, 제품 코드에
측정 장치가 쌓이는 것이 금지됐다.

`n_predict`(길이 한도)와 시간 한도의 값도 여기서 정해진다.

### D6 — 사람이 읽어 확인한다 (SC-002·002a) ★ 기계가 하지 않는다

D2에서 나온 일기를 **읽는다.**

| 볼 것 | 위반인가 |
| --- | --- |
| 화자가 휴대폰인가 | 사람 시점이면 **위반**(원칙 II) |
| 없는 사물을 단언하는가 | "나비에게서 눈을 떼지 않았다" → **위반** |
| 짐작을 하는가 | "아마 ~했을 것이다" → **정상, 오히려 권장** |
| 모른다고 말하는가 | "나는 알 수 없었다" → **정상** |
| 캐릭터의 언어인가 | `quiet`가 한국어인가 |
| 모델 정보가 있는가 | 모델 이름·파라미터 수가 보이면 **위반**(원칙 III) |

**이것을 기계로 채점하지 않는다**(FR-018, 원칙 IV). 의미를 읽어야 판정되는 것이고,
그것을 재려는 순간 이 저장소가 「측정하는 제품」이 된다.

**위반이 보이면 프롬프트를 고친다** — 판정에 갈래를 더하지 않는다(FR-018b).

### D7 — 시각 설정이 막히는가 (SC-009)

시각 설정을 「빠르게 봄」으로 두고 요청한다.

**보아야 할 것**: **일기가 나오지 않는다.** 사진을 보지 않은 일기가 대신 나오면
FR-022 위반이다.

### D8 — 캐릭터를 바꿔도 죽지 않는가 (E-1, SC-006)

`quiet`로 생성한 뒤 다른 캐릭터로 생성한다(그 캐릭터의 모델이 있어야 한다).

**보아야 할 것**: 앱이 죽지 않는다. **두 모델이 동시에 열리면 GB 둘이 되어 죽는다** —
죽지 않는 것 자체가 E1의 증거다.

## 3. Maestro 흐름

```powershell
npm run test:device
```

**⚠️ 새 흐름을 `scripts/run-device-tests.mjs`의 `FLOWS`에 넣어야 한다.**

지금 `FLOWS`는 이렇다:

```
[".maestro/skeleton.yml", ".maestro/model-acquisition.yml"]
```

**004는 Maestro 흐름을 더하지 않았다**(확인함, 2026-08-17 — `.maestro/`에 파일이 둘뿐이다).
그러므로 지금 목록은 맞다. 다만 **이 기능이 흐름을 더하면 반드시 여기 등록한다** —
등록되지 않은 흐름은 `npm run test:device`가 돌리지 않고, 그러면 초록불인데 아무것도 안
돈 상태가 된다. 그것이 원칙 V가 막으려던 바로 그 상황이다.

**흐름이 확인할 것**(자동화 가능한 것만):
- 생성을 요청할 수 있다
- 「쓰고 있다」가 보인다
- 끝나면 그 표시가 사라진다
- 진행률·생성 중인 글이 **보이지 않는다**

**D5·D6은 자동화하지 않는다** — 시간 판단과 글 읽기는 사람의 몫이다.

## 4. 끝났다고 말할 수 있는 조건

**전부 충족되어야 한다.**

- [ ] N1~N4 통과 (기기 없이)
- [ ] **D1 — 모델이 열렸다**
- [ ] **D2 — 일기가 실제로 나왔다** ★ SC-001
- [ ] D3 — 끊기고 정리됐다 (두 번째 요청이 돈다)
- [ ] D4 — `n_ctx`가 맞다
- [ ] D5 — 소요를 쟀고, FR-021b를 유지할지 판단했다
- [ ] **D6 — 사람이 읽었고 화자가 휴대폰이었다** ★ SC-002
- [ ] D7 — 시각 설정이 막힌다
- [ ] D8 — 캐릭터를 바꿔도 죽지 않는다
- [ ] 새 Maestro 흐름이 `FLOWS`에 등록됐다

**D2와 D6이 별표인 이유**: 나머지는 「무너지지 않는다」를 보지만, 이 둘은 **「된다」를
본다.** 헌법 원칙 I과 II가 실제로 성립했는지는 이 둘로만 확인된다.

## 5. 실측으로 얻은 것을 남긴다 (원칙 V)

확인이 끝나면 **AGENTS.md에 옮긴다.** 다음 세션이 값을 다시 확인하는 데 시간을 쓰지
않도록.

남길 것:
- 날짜·기기·안드로이드 버전 (예: 2026-08-__, SM-G986N, Android 13)
- **`n_ctx`의 최종 값과 그것이 이제 실측인지**
- **생성 소요와 FR-021b에 대한 판단**
- `stopCompletion()`이 실제로 얼마나 빨리 듣는지
- 프롬프트 평문 방식이 지시 준수에 문제가 됐는지 (research §4의 trade-off)

**짐작이 실측으로 바뀐 것만 「실측」이라고 적는다.** 확인하지 않은 것을 확인한 것처럼
적으면 그것이 원칙 V 위반이다.
