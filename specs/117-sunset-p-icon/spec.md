# Feature Specification: 앱 아이콘을 노을 「P.」로 바꾼다

**Feature Branch**: `117-sunset-p-icon`

**Created**: 2026-11-12

**Status**: Draft

**Input**: 로드맵 「앱 아이콘을 노을 「P.」로 바꾼다 (보드 밖)」. 설계: `docs/superpowers/specs/2026-11-12-sunset-p-icon-design.md`

## 근거와 원본

- 설계문서에 사실·결정 표·수용 기준이 있다. 전체 트랙이다(새 정본 형식, 변경 파일 5개 초과, 수용 기준 3개 초과). 아래 「설계 결정」은 설계문서의 결정 표 요약이고, 출처는 설계문서다.
- 용어:
  - **그림 정본** = 노을 풍경을 품은 「P」와 기둥 옆 마침표를 그린 SVG 파일 한 개(`design/icon-art.svg`). 색·그라데이션·곡선이 여기에만 있다.
  - **배치 값** = 그림을 각 출력 크기에 어떻게 놓는지(배율·그림 중심·안전 영역)를 적은 정본(`design/icon.json`). 색을 적지 않는다.
  - **생성물** = 정본에서 생성기가 만드는 PNG·미리보기 SVG(`assets/`의 아이콘 PNG, `store/ko/`의 스토어 아이콘·기능 그래픽, `design/icon.svg`).
  - **안전 영역** = 안드로이드 adaptive icon에서 어느 마스크에도 잘리지 않는 가운데 66/108 지름 원.
- 지금(102) 앱 아이콘은 빨강 면 + 기하 「P」이고 정본은 `design/icon.json`(토큰 색 + 기하 도형)이다. 소유자가 외부 시안(2026-11-01)을 받아 A안(작은 원을 기둥 옆 마침표로 옮긴 「P.」)으로 가기로 했고, 정본 방식은 (가) 그림 SVG 정본으로 정했다(2026-11-12).
- 후보 파일(`design/icon-candidates/sunset-p/`)의 실측: P만 감싸는 가장 작은 원의 중심 (473.1, 561.5), 반지름 388.8(Chromium 렌더, 알파 > 8). 원본 자리의 원을 두면 안전 영역에 넣으려 배율이 0.673까지 줄어 걷었다(A안은 0.784).

## Clarifications

### Session 2026-11-12

- Q: 정본 방식은? → A: (가) 그림 SVG가 정본이고 생성기는 래스터화·배율만 맡는다 (소유자 결정 · `DESIGN.md` 「색은 토큰으로만」에 아이콘 그림 한정 예외가 생긴다).
- Q: 래스터화는 무엇으로? → A: `@resvg/resvg-js`를 정확한 버전으로 고정한 devDependency로 한다 (에이전트 판단 · 근거: 저장소에 SVG 렌더러가 없고 직접 그리면 렌더러를 다시 짜는 일이며 Chromium은 환경마다 픽셀이 달라 픽셀 대조가 흔들린다).
- Q: 안드로이드 monochrome은? → A: P 윤곽 + 마침표를 한 가지 색으로 칠한 것, 배율은 foreground와 같다 (에이전트 판단 · 근거: 테마 아이콘은 알파만 쓰고 풍경 안의 산·해는 한 색에서 구분이 안 된다. 마침표가 「P.」의 정체성이라 넣는다).
- Q: 기능 그래픽 1024×500은? → A: 배경 그라데이션이 캔버스를 채우고 그림은 가운데, 배율 0.5(P 높이 약 356/500) (에이전트 판단 · 근거: 102의 비율(300/500)보다 크고 Play가 가장자리를 잘라도 P는 남는다. 사람이 정한 임시값이며 렌더를 보고 소유자가 확인한다).
- Q: 작은 크기(29~48px) 단순화 판을 둘까? → A: 두지 않는다 (에이전트 판단 · 근거: 두 OS 모두 아이콘 한 장만 받아 단순화 판은 favicon·스토어에만 쓰여 아이콘이 둘이 된다. 작은 크기 읽힘은 렌더로 보고 기록만 한다).
- Q: 배율은? → A: iOS 1.0, 안드로이드 foreground·monochrome 0.784, 기능 그래픽 0.5 — 모두 런처를 보기 전의 임시값이고 사람이 정한 값이다 (에이전트 판단 · 근거: 후보 README, 원칙 V. 런처 확인 뒤 확정하거나 고친다).
- Q: 앱 강조색(빨강)·스플래시·화면은? → A: 바꾸지 않는다 (에이전트 판단 · 근거: 소유자는 아이콘만 바꾸기로 했다. 아이콘 색과 앱 색이 갈라지는 것은 로드맵이 이미 알려 둔 위험이다).
- Q: 후보 폴더는? → A: 승격 뒤 지운다 (에이전트 판단 · 근거: 정본이 둘로 갈라지는 것을 막고 파생물은 생성기가 다시 만든다. 원본은 git 기록에 남는다).
- Q: 생성물 대조는? → A: 정확 일치로 시작하고 플랫폼 차이가 확인되면 그때 허용 오차를 정한다 (에이전트 판단 · 근거: 102가 정확 일치였고 값을 미리 지어내지 않는다).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 두 기기의 런처에서 노을 「P.」가 보인다 (Priority: P1)

주인이 갤럭시와 iPhone의 홈 화면에서 앱 아이콘을 볼 때 빨강 면 + 기하 「P」 대신 노을 풍경을 품은 「P.」가 보이고, 안드로이드 어느 마스크(원·스퀘어클 등)에서도 P와 마침표가 잘리지 않는다.

**Why this priority**: 이 과제의 전부다 — 앱의 얼굴이 바뀐다.

**Independent Test**: 생성기가 만든 PNG를 대조하고(테스트), `expo prebuild --clean` 뒤 갤럭시 런처에서 보며, iPhone 14에서는 소유자가 본다.

**Acceptance Scenarios**:

1. **Given** 새 정본, **When** 생성기를 돌리면, **Then** `assets/icon.png`는 1024² RGB(알파 없음)로 노을 「P.」를 배율 1.0으로 담고, 마침표는 기둥 오른쪽 기준선 옆에 있다.
2. **Given** 새 정본, **When** 안드로이드 adaptive 이미지를 만들면, **Then** foreground는 투명 바탕에 그림만, background는 배경 그라데이션만 있고, foreground의 불투명 영역은 안전 영역 안이다.
3. **Given** 갤럭시 SM-S901N, **When** `expo prebuild --clean`으로 새로 깔고 런처를 보면, **Then** 아이콘이 새 그림이고 P·마침표가 잘리지 않는다 — 본 것·못 본 것을 기록한다.
4. **Given** iPhone 14에 개발 서명 Release 빌드를 깔았을 때, **When** 소유자가 홈 화면을 보면, **Then** 소유자가 본 결과(배율이 맞는지)가 기록에 남는다. 그 결과를 받기 전에는 확인했다고 쓰지 않는다.

---

### User Story 2 - 안드로이드 테마 아이콘과 스토어 에셋이 새 아이콘으로 나온다 (Priority: P1)

안드로이드 13+ 테마 아이콘(monochrome)과 스토어 아이콘 512·기능 그래픽 1024×500·favicon이 같은 정본에서 나와 새 아이콘과 어긋나지 않는다.

**Why this priority**: 아이콘만 바뀌고 스토어 에셋이 옛 모양이면 등록 화면이 어긋난다.

**Independent Test**: 출력 목록의 모든 PNG가 정본에서 나온 것과 픽셀까지 같고 크기·색 유형이 규칙을 지킨다.

**Acceptance Scenarios**:

1. **Given** 새 정본, **When** monochrome을 만들면, **Then** 투명 바탕에 P 윤곽과 마침표만 한 색으로 있고 안전 영역 안이다.
2. **Given** 새 정본, **When** 스토어 에셋을 만들면, **Then** 스토어 아이콘은 512² RGBA, 기능 그래픽은 1024×500 RGB(알파 없음), favicon은 48²다.
3. **Given** 사람이 PNG 한 픽셀을 고쳤을 때, **When** 계약 테스트를 돌리면, **Then** 실패한다.

---

### User Story 3 - 아이콘이 정본 하나로 관리되고 문서가 새 아이콘을 말한다 (Priority: P2)

개발자는 그림 SVG 하나와 배치 값 하나만 보면 아이콘이 어떻게 나오는지 알고, 색 16진수는 그림 SVG 밖에서 늘어나지 않으며, 디자인 문서가 새 아이콘과 그 예외를 말한다.

**Why this priority**: 정본이 둘로 갈라지거나 예외가 새면 다음 사람이 손으로 PNG를 고치게 된다.

**Independent Test**: 계약 테스트가 정본·생성물·문서의 어긋남을 잡는지 위반 주입으로 확인한다.

**Acceptance Scenarios**:

1. **Given** 정본, **When** `icon.json`을 읽으면, **Then** 16진수 색이 없고 그림 파일·그림 중심·출력별 배율·안전 영역만 있다.
2. **Given** 그림 정본 외 파일에 새 16진수 색이 생겼을 때, **When** 계약 테스트를 돌리면, **Then** 실패한다.
3. **Given** 작업이 끝났을 때, **When** `DESIGN.md`·`AGENTS.md`를 읽으면, **Then** 아이콘이 노을 「P.」이고 정본 방식과 「색은 토큰으로만」의 아이콘 한정 예외가 적혀 있다.
4. **Given** 로드맵, **When** 「앱 아이콘·등록 에셋 마무리 확인」을 읽으면, **Then** 아이콘 항목(iOS 배율 2.3·monochrome)은 이 과제로 대체됐다고 정리돼 있다.

### Edge Cases

- 정본이 없는 그림 파일이나 없는 요소 id를 가리키면 아무것도 쓰지 않고 실패한다.
- 안드로이드 foreground 배율을 키우면 안전 영역을 넘는 것을 테스트가 잡는다(위반 주입).
- iOS 아이콘의 한 픽셀 알파를 낮추면 알파 검사가 잡는다.
- 작은 크기(29~48px)에서 풍경이 뭉개져 분홍·파랑 P로만 읽힐 수 있다 — 렌더로 보고 기록하고 단순화 판은 두지 않는다.
- 래스터라이저가 플랫폼마다 다른 픽셀을 내면 정확 일치 대조가 실패한다 — 그때 허용 오차를 사람이 정한다.
- 아이콘 PNG를 바꾼 뒤 `expo prebuild --clean`을 다시 돌리지 않으면 런처에 옛 아이콘이 남는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 그림 정본(`design/icon-art.svg`)은 노을 풍경을 품은 「P」와 기둥 오른쪽 기준선 옆 마침표(A안, 후보 원본에서 마침표 원만 옮긴 것)를 담아야 한다. 16진수 색·그라데이션·곡선은 이 파일에만 있다.
- **FR-002**: 배치 값(`design/icon.json`)은 그림 파일 이름·그림 중심 (473.1, 561.5)·출력별 배율(iOS 1.0, 안드로이드 foreground·monochrome 0.784, 기능 그래픽 0.5)·안전 영역 66/108을 정해야 하고, 16진수 색을 적지 않아야 한다. 모든 배율은 사람이 정한 값이며 런처 확인 뒤 확정한다.
- **FR-003**: 생성기는 정본에서 102의 출력 목록을 그대로 만들어야 한다 — `assets/icon.png`·`android-icon-foreground.png`·`android-icon-background.png`·`android-icon-monochrome.png`·`favicon.png`·`store/ko/store-icon-512.png`·`feature-graphic-1024x500.png`·`design/icon.svg`. PNG를 손으로 만들지 않는다.
- **FR-004**: 크기·색 유형: iOS 1024² RGB(알파 없음), foreground·monochrome 1024² RGBA, background 1024² RGB, favicon 48², 스토어 아이콘 512² RGBA, 기능 그래픽 1024×500 RGB.
- **FR-005**: foreground와 monochrome의 불투명 영역은 안전 영역 안에 있어야 한다.
- **FR-006**: monochrome은 투명 바탕에 P 윤곽과 마침표만 한 색으로 그려야 한다(풍경은 없다).
- **FR-007**: 그림을 SVG에서 PNG로 바꾸는 자리는 생성기 한 곳이며, 래스터라이저는 정확한 버전으로 고정한 devDependency다. 생성기의 출력은 입력만으로 정해진다.
- **FR-008**: `app.json`이 가리키는 아이콘 경로가 모두 실재하고 생성 목록에 있어야 한다. adaptive 아이콘의 `backgroundColor`는 그림의 배경 그라데이션 첫 정지점 색과 같아야 한다.
- **FR-009**: 계약 테스트는 생성물을 정본에서 나온 것과 픽셀까지 대조하고, 16진수가 그림 파일 밖에 생기는 것·없는 그림 파일/요소 id를 가리키는 것·안전 영역 이탈·iOS 알파를 위반 주입으로 잡아야 한다.
- **FR-010**: `npm run build:icons -- --check`는 정본과 생성물이 같을 때 0으로 끝나야 한다.
- **FR-011**: `DESIGN.md`의 「아이콘」을 새 아이콘과 정본 방식으로 고치고, 「색은 토큰으로만」·「그라데이션 금지」에 아이콘 그림 한정 예외를 적어야 한다. `AGENTS.md`의 아이콘 서술(「빨강 면 + 기하 「P」」)도 고쳐야 한다. 새로 적은 이름이 실재하는지는 기존 문서 테스트가 본다.
- **FR-012**: 로드맵에서 「앱 아이콘·등록 에셋 마무리 확인」의 아이콘 항목(iOS 배율 2.3·monochrome)을 이 과제로 대체됐다고 정리하고, 이 과제를 진행 예정에서 완료 이력으로 옮기는 것은 구현이 끝난 뒤의 완료 처리 단계에서 한다(이 과제의 구현 태스크 밖).
- **FR-013**: `design/icon-candidates/sunset-p/`는 정본 승격 뒤 지운다. 후보 README의 알려진 문제·실측은 이 스펙의 근거로 옮겨졌다.
- **FR-014**: 갤럭시 SM-S901N은 `expo prebuild --clean` 뒤 런처에서 foreground·monochrome·마스크 잘림을 보고, iPhone 14는 개발 서명 Release 빌드를 깔아 소유자가 홈 화면을 본다. 본 것·못 본 것은 `quickstart.md`에 남기며, 소유자가 본 결과를 받기 전에는 iPhone을 확인했다고 쓰지 않는다.

### Key Entities

- **그림 정본**: 풍경이 든 P 윤곽·마침표·배경 그라데이션을 담은 SVG 한 개. P 윤곽과 마침표는 이름 붙은 요소로 따로 쓸 수 있다.
- **배치 값**: 그림 파일 이름·중심·출력별 배율·안전 영역. 그림의 모양과 색은 담지 않는다.
- **생성물**: 정본에서 나온 PNG·미리보기 SVG. 손으로 고치지 않는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 정본에서 생성기를 두 번 돌리면 두 번째는 바뀐 파일이 0개다(결정적).
- **SC-002**: `npm run build:icons -- --check`가 종료 코드 0이고, 생성 목록 8개 파일이 모두 정본과 같다.
- **SC-003**: 안드로이드 foreground·monochrome의 불투명 영역이 안전 영역(가운데 66/108) 안에 100% 있다.
- **SC-004**: 그림 파일 밖에서 16진수 색이 새로 발견되면 계약 테스트가 실패한다(위반 주입으로 확인).
- **SC-005**: 갤럭시 런처에서 foreground·monochrome·마스크 잘림 확인 결과가 기록에 남고, 못 본 것(예: iPhone 홈 화면 소유자 확인 전)은 못 봤다고 적혀 있다.
- **SC-006**: `npm test`·`npm run lint`가 통과한다.

## Assumptions

- `@resvg/resvg-js`는 이 저장소의 Node(v24)와 macOS·Linux 플랫폼 바이너리로 돌아간다 — 설치로 확인한다. 안 돌면 플랜 단계에서 대안(Chromium 렌더 등)을 다시 정한다.
- 후보 SVG의 그림·색은 소유자가 받아들였다(2026-11-01). 색 값은 바꾸지 않는다.
