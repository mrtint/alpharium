### Session 2026-11-25

- Q: 새 설치를 어떻게 가르나? → A: 온보딩의 `completed`가 false→true로 저장될 때 대기를 함께 남긴다. 이미 완료된 설치는 그 전이를 지나지 않아 쓰지 않는다 (에이전트 판단 · 근거: 소유자 「새 설치만」, 별도 이행 불필요)
- Q: 창 안 「쓰는 시각」 변경은 언제 저장되나? → A: 「켜기」를 누를 때 함께 저장한다. 「나중에」면 버린다 (에이전트 판단 · 근거: FR-006 「나중에는 아무것도 바꾸지 않는다」)
- Q: 설정 화면의 배터리 권한 행은? → A: 그대로 둔다 — 첫 실행 단계 목록에서만 뺀다 (에이전트 판단 · 근거: 104 꼬리표·설정 보조 줄이 이미 쓰인다, D4 C)
- Q: 배터리 행을 눌렀을 때 대기를 지우나? → A: 지우지 않는다 — 창은 열린 채 돌아와 꼬리표만 갱신 (에이전트 판단 · 근거: 0-1 흐름도, 「켜기/나중에」만 닫는다)
- Q: 슬라이드 3 제목·권한 설명·스토어 문구의 새 글은? → A: 구현에서 K4 조건을 품은 초안을 쓰고 커밋 확인 때 소유자가 뒤집는다 (에이전트 판단 · 근거: 규칙 문서 「문구 초안은 구현 때 사람이 확정」)

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 첫 실행 끝에 자동 쓰기를 한 번에 정한다 (Priority: P1)

새로 설치한 사용자가 첫 일기 흐름(쓰기·나중에·재료 없음·건너뜀)을 마치면, 한 창에서 「자동으로 쓰기」·쓰는 시각·(안드로이드) 배터리 제한 풀기를 보고 「켜기」 또는 「나중에」를 고른다.

**Why this priority**: 「자동으로 쓰기」는 기본 꺼짐이라, 묻지 않으면 대부분 사용자가 이 기능을 모른 채 지난다.

**Independent Test**: 새 설치 상태로 첫 실행을 끝까지 진행해 창이 한 번 뜨고, 「켜기」 뒤 설정 화면에 켬·시각이 보이는지 확인.

**Acceptance Scenarios**:

1. **Given** 새 설치 · 첫 일기 흐름이 끝남 · 쓰는 중 아님, **When** 홈에 도착, **Then** 설정 창이 뜬다.
2. **Given** 창이 떠 있음, **When** 「켜기」, **Then** 토글 상태와 시각이 저장되고 창은 다시 뜨지 않는다.
3. **Given** 창이 떠 있음, **When** 「나중에」, **Then** 아무 설정도 바뀌지 않고 창은 다시 뜨지 않는다.
4. **Given** 첫 일기를 쓰는 중, **When** 쓰기가 끝나기 전, **Then** 창은 뜨지 않고, 쓰기가 끝난 뒤 뜬다.

### User Story 2 - 배터리 제한을 창에서 푼다 (Priority: P2, 안드로이드)

배터리 제한 풀기 행을 눌러 OS 배터리 설정 목록으로 갔다 돌아오면 행의 꼬리표가 현재 상태(「허용됨」/「허용 안 함」)로 바뀐다.

**Independent Test**: 안드로이드 실기기에서 행을 눌러 예외를 주고 돌아와 꼬리표 변화 확인.

**Acceptance Scenarios**:

1. **Given** 예외 없음, **When** 행을 누르고 예외를 준 뒤 앱으로 돌아옴, **Then** 꼬리표가 「허용됨」.
2. **Given** iOS, **Then** 배터리 행이 없다.

### User Story 3 - 첫 실행 권한 단계가 한 모양이다 (Priority: P2)

첫 실행 권한 단계에 배터리 글 화면이 없고, 모든 단계가 스플래시 위 OS 창으로만 진행된다.

**Independent Test**: 새 설치 첫 실행에서 배터리 화면이 나오지 않는지 확인.

**Acceptance Scenarios**:

1. **Given** 새 설치 안드로이드, **When** 권한 단계 진행, **Then** 사진·알림만 묻고 배터리 화면이 없다.

### Edge Cases

- 첫 일기 흐름이 끝나기 전에 앱이 종료됨 → 다음 실행에서 쓰는 중이 아니면 창을 띄운다(대기 상태는 기기에 남는다).
- 기존 사용자(이 기능 전 첫 실행 완료) → 창을 띄우지 않는다.
- 다른 확인 질문(첫 일기 확인창 등)이 떠 있음 → 그것이 닫힌 뒤 띄운다.
- 창 안에서 토글을 끄고 「켜기」 → 꺼짐으로 저장한다(창은 닫힌다).
- 배터리 상태를 읽지 못함 → 꼬리표 없이 행만 보인다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 첫 실행 권한 단계에서 배터리 예외 단계를 제외한다.
- **FR-002**: 새 설치의 첫 실행 권한 단계가 처음 끝날 때 「설정 창 대기」를 기기에 남긴다. 기존 설치에는 남기지 않는다.
- **FR-003**: 홈이 보이고(첫 실행 단계가 끝남), 대기 중이고, 첫 일기 흐름이 끝났거나 이번 실행에서 돌지 않으며, 쓰는 중이 아니고, 다른 확인 질문이 없을 때만 창을 띄운다.
- **FR-004**: 창 제목 「매일 일기를 써 드릴까요?」, 행 「자동으로 쓰기」(창 안 기본 켬)·「쓰는 시각」(현재 저장 시각, 누르면 시각 선택)·「배터리 제한 풀기」(안드로이드만, 꼬리표 「허용됨」/「허용 안 함」).
- **FR-005**: 조건 줄 — iOS 「이 시간에 충전중이라면 자동으로 작성해요」 / 안드로이드 「이 시간에 배터리 제한을 풀거나 충전중이라면 자동으로 작성해요」.
- **FR-006**: 「켜기」는 설정 화면과 같은 방식으로 토글·시각을 저장한다. 「나중에」는 아무것도 바꾸지 않는다. 둘 다 대기를 지운다.
- **FR-007**: 배터리 행을 누르면 OS 배터리 설정 목록을 열고, 앱이 앞으로 돌아오면 상태를 다시 읽는다.
- **FR-008**: 첫 실행 문구(진행 슬라이드 3 제목·권한 설명)와 스토어 설명문에서 자동 쓰기를 약속하는 문장은 「켜 두면/켜면」 조건을 품는다.
- **FR-009**: 안내 규칙 문서에서 끝난 G4 행·전수 목록 행을 지운다.

### Key Entities

- **설정 창 대기**: 새 설치에서만 참이 되는 한 비트. 「켜기」/「나중에」로 거짓이 된다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 새 설치 첫 실행 1회당 설정 창이 정확히 1번 뜬다(앱이 중간에 죽어도 끝내 1번).
- **SC-002**: 쓰는 중에 창이 뜨는 경우 0건.
- **SC-003**: 기존 사용자에게 창이 뜨는 경우 0건.
- **SC-004**: 첫 실행 권한 단계에서 글 화면 0개.

## Assumptions

- 설정 화면의 「자동으로 쓰기」 행은 지금 모양을 유지한다(창과 부품을 공유하지 않는다).
- 「나중에」 뒤에는 다시 묻지 않는다(규칙 문서 0-1).
- 기존 사용자 판정은 「대기가 남아 있지 않음」으로 갈음한다 — 따로 이행하지 않는다(소유자, 2026-11-25).
