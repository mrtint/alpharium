# Quickstart: 자동 쓰기 규칙 (057) — 검증

## 기기 없이

```bash
npm run test:logic   # AW·SK·BG·NT·SL1
npm run test:ui      # SL2~4·OP
npm test && npm run lint
```

## 실기기 (dev 빌드 1회, AGENTS 「도구 사용법」 네 가지를 먼저 갖춘다)

준비: `EXPO_PUBLIC_APP_ENV=dev npx expo start --dev-client`(gradle 빌드 뒤), `adb reverse tcp:8081 tcp:8081`, 잠금 해제. **`pm clear` 하지 않는다**(모델·일기 보존).
배터리 예외(「제한 없음」)를 켜 둔다 — 없으면 하루 넘게 미뤄진다(019). 판정은 **`files/diary/`의 새 파일 + `files/preferences/auto-write-skipped.json` + 알림 트레이**를
함께 본다(`"skipped"`는 로그로 정상 완주와 구분되지 않는다, 020 B6). 정오 이후의 목표 시각이어야 오늘이 쓸 날 후보다(`selectableDays`).

1. **재료 0 하루 (SC-001)** — 오늘 찍은 사진이 0장인 상태에서 설정 → 자동으로 쓰기 켬 → 매일 쓰는 시각 = 지금 시. 오늘 일기가 있으면 안 된다.
   **홈 버튼**으로 나가고 화면을 끈다(`am force-stop` 금지 — 잡이 취소된다). 15~40분 뒤 `adb logcat`에서 `Worker result SUCCESS`를 보고:
   오늘 일기 파일 없음, 알림 없음, 건너뜀 파일 없음(재료 없음은 기록하지 않는다).
2. **사진 권한 회수 하루 (SC-002·SC-003)** — 휴대폰 설정 앱에서 Alpharium의 사진 권한을 끈다(`pm revoke` 금지 — 프로세스가 죽는다). 1과 같이 헤드리스로 한 창을 지난다.
   일기 파일 없음, 알림 없음, `run-as … cat files/preferences/auto-write-skipped.json` = 그 날. 앱을 열어 설정 → 사진 행 아래 빨간 「{M}월 {d}일 …」(또는 다음 날이면 「어제 …」).
   사진 행을 눌러 권한을 허용하고 돌아온다 → 보조 줄이 사라지고 파일이 없다.
3. **앱을 열면 쓰는 중 (SC-004)** — 사진이 있는 오늘, 목표 시각 = 지금 시, 오늘 일기 없음. 앱을 최근 앱에서 밀어 닫았다가 다시 연다 → 홈이 오늘을 고른 쓰는 중으로 시작한다.
   그만두기 → 같은 실행 동안 다시 시작하지 않는다.
4. **완성 알림 (SC-005)** — 사진이 있는 날 1처럼 헤드리스 한 창 → 알림 「{이름}{이|가} {M}월 {d}일 일기를 다 썼어요」, 본문 없음, 누르면 그 날.

결과(시각·관측)는 spec의 「미확인 잔여」와 이 파일 아래에 사람이 적는다(검증 전용 로그 모듈을 만들지 않는다).
