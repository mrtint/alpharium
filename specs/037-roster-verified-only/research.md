# Research: 로스터를 검증된 하나로 축소

**Phase 0** | 2026-09-09 | [plan.md](./plan.md)

이 기능은 새 기술을 들이지 않는다. 연구 대상은 **기존 코드가 캐릭터 축소를
어떻게 견디는가**이며, 답은 소스를 직접 읽어 얻었다(추측 0건).

---

## R1. 타입을 좁히면 어디가 깨지는가

**결정**: `src/diary/types.ts`의 `Character` 유니온을 `"quiet"`로 좁히는
것을 **첫 코드 변경**으로 삼고, `tsc`가 낸 오류 목록을 변경 대상 목록으로
쓴다.

**근거** (`grep`으로 확인한 실제 소비 지점):

| 자리 | 형태 | 좁히면 |
|---|---|---|
| `diary/persona.ts:42` | `Readonly<Record<Character, Persona>>` | 남는 키가 잉여 속성 오류 |
| `models/roster.ts` | `ASSETS`·`DISPLAY_NAMES` 동일 형태 | 같음 |
| `diary/prompt.ts` | `LANGUAGE` 레코드 | 같음 |
| `diary/acceptance.ts:120` | `switch (character)` 전수 | 도달 불가 `case` 드러남 |
| `ui/DiagnosticsScreen.tsx:61` | `const PROBE_CHARACTER: Character = "imaginative"` | **할당 불가 오류** |

**대안 검토**: 캐릭터별로 파일을 하나씩 손으로 고치는 방식 — 기각. 007·009가
"jest는 타입을 지우므로 `tsc`만 잡는 위반이 있다"를 반복 확인했고, 손으로
찾으면 빠뜨린 자리가 조용히 남는다. 이 저장소가 겪은 실패의 대부분이 그
계열이다.

## R2. 마지막으로 쓴 캐릭터가 로스터 밖이면 (FR-009)

**결정**: **코드 변경 0줄.** 기존 방어가 이미 성립한다.

**근거**: `src/app/selection-store.ts:33-57`

```
function isCharacter(value: unknown): value is Character {
  return typeof value === "string" && (CHARACTERS as readonly string[]).includes(value);
}
```

`loadSelection()`이 이 검사를 거치며, 주석이 의도를 명시한다 — *"파일이
없든, 깨졌든, **로스터 밖 이름이 들었든**, 통로가 예외를 던지든 결과가
같다 — 어느 경우에도 캐릭터를 지어내지 않는다."*

`CHARACTERS`가 줄면 `"imaginative"`가 담긴 `selected-character.json`은
자동으로 `null`이 되고, 007의 `resolveSelection`이 "고른 적 없음"으로
처리한다. **FR-009는 이 기능에서 새로 만들 것이 없다** — 계약 테스트로
이 성질을 명시적으로 잠그기만 한다.

**대안 검토**: 마이그레이션(파일을 읽어 로스터 밖 값을 지우는 코드) — 기각.
읽는 쪽이 이미 방어하므로 불필요하고, 파일을 건드리는 코드는 새 실패
지점이다.

## R3. 옛 일기의 작성자 이름 (FR-008)

**결정**: 방어를 **읽는 쪽**에 두고 `personaOf()`는 그대로 둔다.

**근거**: 이름을 되짚는 자리가 둘이다.

1. `src/diary/character-name.ts:50`
   `chosen !== undefined && chosen !== "" ? chosen : personaOf(character).name`
2. `src/ui/DiaryDetailScreen.tsx:167`
   `entry.authorName ?? currentAuthorName ?? personaOf(entry.character).name`

`DiaryEntry.character`는 **파일에서 온 값**이라 좁아진 타입을 런타임에
만족한다는 보장이 없다(저장된 일기에는 여전히 `"imaginative"`가 있다).
`authorName`은 옵셔널이므로(`types.ts:144`, 035 이전 일기에 없다) 2번이
`personaOf(로스터 밖) → undefined → .name` 으로 멈출 수 있다.

**`personaOf()`에 기본값을 넣지 않는 이유**: 로스터 밖 캐릭터에도 페르소나가
돌아오면 "로스터에 없는데 성격은 있다"가 되어 원칙 III의 경계가 흐려진다.
`persona.ts`는 "캐릭터→이름·소개의 유일한 통과 지점"이며 그 지점이 로스터를
넘어서면 안 된다.

**대안 검토**:
- *마이그레이션으로 옛 일기에 `authorName`을 채워 넣기* — 기각. 저장된
  사용자 기록을 고치는 일이고, 원본이 무엇이었는지 알 수 없는 경우가 있다.
- *로스터 밖 일기를 목록에서 숨기기* — 기각. 사용자의 기록을 사라지게
  하는 것은 어떤 정리로도 정당화되지 않는다(spec US2가 P1인 이유).

## R4. `STALE_LOCK_MS`의 근거가 사라진다

**결정**: **값 6분은 유지하고 근거 주석만 갱신한다.**

**근거**: `src/schedule/lock.ts:31-43`의 현행 근거는 *"`narrative`(exaone,
로스터에서 가장 느린 캐릭터) 백그라운드 완주 ≈ 170초 × 2 + 여유"*다.
그 캐릭터가 나가면 **문장이 사실과 어긋난다** — 근거로 든 캐릭터가 로스터에
없다.

값을 줄이려면 "이제 가장 느린 것은 quiet이고 그 완주는 N초"를 재야 하는데,
그것은 이 기능의 범위 밖이고 **안 잰 값을 쓰는 것은 원칙 V 위반**이다.
6분은 quiet(024 헤드리스 52.5초, 036 포그라운드 19~22초)에 대해 넉넉하다.

같은 처리를 `src/vision/select.ts`(상한 상향 조건이 narrative 완주),
`src/onboarding/essential-assets.ts`(기본 캐릭터 선정 근거)에 적용한다.

**대안 검토**: 상수를 quiet 기준으로 다시 계산 — 기각(위 이유). 주석을
지우기만 하기 — 기각. 왜 6분인지 모르면 다음 사람이 근거 없이 바꾼다.

## R5. 넷의 부적합을 다시 잴 것인가

**결정**: **재지 않는다.** 근거가 이미 충분하다.

**근거**:

| 캐릭터 | 관측 | 출처 | 회차 |
|---|---|---|---|
| narrative | 헤드리스 완주 불가(26분+ 산출물 없음) | 024 T034 | — |
| narrative | 포그라운드 mojibake | 024 §10 | 3/3 |
| imaginative | 되뇜·주인화·지어내기 | **037 이 세션** | 3/3 |
| chinese | 추론 블록이 예산 소진, 본문 미도달 | 028 | 3/3 |
| english | 환각 + 서식 잔존 / 한국어 혼입 + 반복 붕괴 | 028 | 3/3 |
| 전부 | 로스터 5개 중 kanana 하나 | my-ollama 리포트 | 222런 |

**루이 mojibake의 현행 프롬프트 재확인은 하지 않는다** — 024는 036 이전
프롬프트로 관측했으나, **헤드리스 완주 불가(T034)만으로 자동 생성 부적합이
성립한다.** mojibake가 프롬프트로 고쳐진다 해도 완주하지 못하는 것은
그대로다. 리포트도 원인을 *"llama.rn + LGAI HF GGUF 경로"*로 좁혔으므로
프롬프트 문제가 아니다.

**대안 검토**: 넷 전부 현행 프롬프트로 재측정 — 기각. 037 세션에서 오드를
3회 재는 데 든 시간(모델 배치 포함 약 1시간)을 넷에 곱하면 이 기능이 측정
세션이 된다. 그리고 리포트 222런이 이미 답을 냈다.

## R6. 교체 후보를 이 기능에서 다룰 것인가

**결정**: **다루지 않는다.** 진입 기준(FR-002)을 세우는 것이 이 기능이고,
그 기준을 통과할 후보를 찾는 것은 다음 기능이다.

**근거**: 리포트가 조건과 첫 확인 대상만 지목했고 **실측하지 않았다**고
명시했다:

- 중국어: *"비추론 모델 + 한국어 지시문에서 중국어 출력 + 1~2B.
  Qwen2.5-1.5B-Instruct가 첫 확인 대상이다(**검증 전이다**)"*
- 영어: *"한국어 지시문에서 영어 출력 + 1~3B. Llama-3.2-1B/3B-Instruct가
  첫 확인 대상. gemma3-4B는 3.3GB라 폰 예산 밖"*

관측 없이 로스터에 넣으면 **이 기능이 세우는 기준을 이 기능이 어긴다.**
