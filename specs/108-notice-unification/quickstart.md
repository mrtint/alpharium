# Quickstart: 제약 띠 검증

## 기기 불필요 (항상)

```sh
npx jest __tests__/app/constraint-band.test.ts __tests__/app/use-constraint-band.test.tsx __tests__/ui/constraint-band.test.tsx __tests__/config/notice-rules.test.ts
npm test && npm run lint
```

위반 주입: ① `DiaryListScreen`에 `Notices`를 되살린다 ② `ConstraintBand`에 `onDismiss` 프롭을 더한다 ③ 판정에서 사진 권한 우선을 뒤집는다 — 각각 계약 테스트가 실패해야 한다. 확인 뒤 되돌린다.

## 실기기 (SM-S901N dev, Metro 번들)

1. 설정에서 사진 권한을 거부 → 홈: 쓰기 바 위에 띠 한 줄 + 버튼. 스트립 아래에 아무것도 없다. 버튼 → 권한 창/설정 안내. 허용 후 돌아오면 띠가 사라진다.
2. 사진 권한 허용 + 자동 쓰기 켬 + 배터리 예외 없음 → 배터리 띠. 버튼 → 배터리 예외 목록. 예외를 주고 돌아오면 사라진다. 자동 쓰기를 끄면 사라진다.
3. 둘 다 걸림 → 사진 권한 띠 하나.
4. 쓰기 실패 토스트가 뜨는 동안 띠가 흐려지고 3초 뒤 돌아온다.
5. 쓴 날: 스크롤하면 바와 띠가 함께 내려가고, 맨 끝에서 함께 올라온다. 마지막 문단이 띠에 가리지 않는다.
6. 글꼴 2.0배: 띠가 한 줄, 버튼이 보이고 눌린다. 첫 화면 본문 줄 수를 적는다.
7. iOS 시뮬레이터: 사진 권한 띠만(배터리 띠 없음).

못 본 것은 기록에 「미확인」으로 남긴다.

## 결과 기록 — iOS 시뮬레이터 (2026-11-01, iPhone 18 Pro, iOS 27.1, Debug 빌드 + Metro 8082)

**방법**: 8081은 다른 작업의 Metro가 쓰고 있어, 이 워크트리의 Metro를 8082로 띄우고 앱이 그쪽을 보게 했다 — `xcrun simctl spawn <UDID> defaults write com.a810labs.pocketlog RCT_jsLocation "localhost:8082"`(앱 컨테이너의 plist를 직접 쓰면 cfprefsd 캐시 때문에 먹지 않았다). 사진 권한은 `xcrun simctl privacy <UDID> revoke|grant photos com.a810labs.pocketlog`로 바꿨다(**권한을 바꾸면 앱이 종료된다** — iOS 설정 앱에서 바꿔도 같다). 조작은 Maestro, 화면은 `simctl io screenshot`.

| 항목 | 결과 |
| --- | --- |
| 1 사진 권한 거부 → 띠 | ✓ 쓰기 바 바로 위에 한 줄(「사진 권한이 없어 사진 없이 써요」)과 채운 「권한 허용」 버튼. 스트립 아래에는 아무것도 없다(옛 줄글 없음) |
| 1 버튼 | ✓ 눌렀더니 053의 설정 안내 대화상자(「설정에서 사진 접근을 허용해 주세요」)가 떴다(거부 후 다시 물을 수 없는 상태) |
| 1 허용 뒤 사라짐 | △ iOS 설정 앱에서 「전체 접근」으로 바꾸자 앱이 종료돼 **같은 프로세스에서 띠가 사라지는 것은 못 봤다**. 새로 띄운 앱(허용 상태)에서는 띠가 없다 ✓ |
| 6 글꼴 `accessibility-large`(≈1.94배) | ✓ 띠가 한 줄이고 버튼이 가려지지 않았다(글자는 1.2배 상한이라 작게 남음). 쓰기 바·재료 칸은 커졌고 본문을 밀어내지 않았다. 본문 줄 수는 안 쓴 날이라 재지 않았다 |
| 7 iOS는 배터리 띠 없음 | ✓ 소스·테스트로(iOS는 읽지도 않는다), 화면으로는 사진 권한 띠만 봤다 |
| 2·3·4·5 | **미확인**: 배터리 띠(안드로이드 전용), 토스트와 띠 겹침, 쓴 날 끝에서의 바·띠 움직임 — 시뮬레이터로는 못 했다(안드로이드 실기기 필요 · 쓴 날은 모델·표본 사진이 필요) |

**관찰**: 설정 앱에서 사진 권한을 바꾸고 돌아온 첫 실행에서 앱이 잠깐 첫 화면(로고·소개)으로 시작하고 LogBox에 `Cannot read property 'reload' of undefined`(Uncaught in promise) 두 건이 났다. 이 변경의 코드에는 `reload`가 없다(소스 검색) — 개발 빌드의 Expo 개발 도구 쪽으로 보이나 **원인은 확인하지 않았다**. 앱을 다시 띄우면 정상 홈으로 열렸다.

## 결과 기록 — 안드로이드 실기기 (2026-11-01, Galaxy SM-S901N, 디버그 빌드 versionCode 13 + Metro 8082)

**방법**: 앱 데이터를 비운 새 설치에서 온보딩(사진은 처음에 허용 상태였고 `pm revoke`로 거부로 돌렸다, 알림 허용·위치 거부·배터리 건너뛰기)·모델 수신·자동 첫 일기까지 거친 뒤 자동 쓰기를 켰다(시각 오후 10시쯤). 사진 권한은 `pm revoke`/앱의 「권한 허용」 창, 배터리 예외는 `dumpsys deviceidle whitelist +/-`, 쓰기 실패는 `files/models/a1.bin`을 같은 크기의 0으로 채운 파일로 바꿔 일으켰다(끝나고 원래 파일로 되돌렸다). 쓴 날의 사진은 `npm run sample:fetch`·`sample:seed` 표본이다. 화면은 `screencap`.

| 항목 | 결과 |
| --- | --- |
| 1 사진 권한 거부 → 띠 | ✓ 쓰기 바 위에 한 줄(「사진 권한이 없어 사진 없이 써요」)과 「권한 허용」 버튼. 스트립 아래에는 아무것도 없다 |
| 1 버튼 | ✓ 안드로이드 사진 권한 창(제한된 액세스/모두 허용/허용 안 함)이 떴다 |
| 1 허용 뒤 사라짐 | ✓ 「모두 허용」 뒤 띠가 없다. 다만 권한을 바꾸면 OS가 앱을 다시 띄우므로 **같은 프로세스에서 사라지는 것은 아니다**(홈은 앱 열기 자동 쓰기로 그 날을 쓰기 시작했다) |
| 2 배터리 띠 | ✓ 사진 허용 + 자동 쓰기 켬 + 예외 없음 → 「배터리 제한을 풀면 화면이 꺼져도 써 둬요」 + 「설정 열기」 |
| 2 버튼 | △ 삼성 「배터리 사용 관리」(`AppBatteryUsageActivity`, 앱 목록)가 열렸다 — 예외 목록 화면은 아니다. 열리는 곳은 기기 쪽 결정이다 |
| 2 예외를 주고 돌아오면 사라짐 | ✓ `deviceidle whitelist +`로 예외를 주고 앱으로 돌아오니 띠가 없다 |
| 2 자동 쓰기를 끄면 사라짐 | **미확인** |
| 3 둘 다 걸림 → 사진 권한 띠 하나 | ✓ 사진 거부 + 자동 쓰기 켬 + 예외 없음에서 사진 권한 띠 하나만 보였다 |
| 4 쓰기 실패 토스트 | ✓ 「일기를 쓰지 못했어요.」 토스트가 뜬 프레임에서 띠 자리에는 토스트만 보이고 띠는 없었다. 다음 프레임에서 띠가 돌아왔다(프레임 간격 1.3초 안팎이라 3초 흐림·복귀의 시간은 재지 못했다) |
| 5 쓴 날 스크롤 | ✓ 위쪽에서는 바·띠가 없고 스크롤하면 끝에서 함께 나타난다. 마지막 문단 끝 줄이 띠에 가리지 않는다. 끝에서 읽는 중 띠가 사라져도(예외 부여) 바 위치가 같았다(한 번 관찰) |
| 6 글꼴 2.0배(`font_scale 2.0`) | ✓ 띠 한 줄(글이 말줄임표로 잘림), 「설정 열기」 버튼이 가려지지 않고 눌려 설정이 열렸다. 쓴 날 첫 화면 본문은 **3줄**이 보였다(캐러셀·제목 포함 첫 화면) |

**관찰**: 개발 빌드의 노란 LogBox 토스트(글 없음)가 하단 바·띠를 덮는다 — 닫아서 확인했다(제품 아님). 설정 화면의 배터리 행은 라벨 아래 줄바꿈으로 꼬리표가 아래로 떨어져 보였다(이 변경 밖).
**못 본 것**: 자동 쓰기를 끈 뒤 띠 사라짐, 토스트 중 흐림의 3초 시간, 작은 화면, 배터리 예외가 있는 상태에서의 사진 띠 단독 조합.
