# Quickstart — 실기기 검증

**기능**: 010 가상의 하루를 기기에 심는 도구

**이 문서는 「도구가 도는가」와 「도구가 준비한 하루에서 앱이 무엇을 보는가」를 확인한다.**
**일기가 좋은지는 확인하지 않는다** — 그것이 헌법 원칙 V가 금지한 것이다(FR-021).

---

## ⚠️ 이 검증에서 결론 내리면 안 되는 것

| 적어도 되는 것 | 적으면 안 되는 것 |
| --- | --- |
| 「사진: 3장」이 화면에 보였다 | 「프롬프트가 좋아졌다」 |
| 자리가 2곳으로 나왔다 | 「`quiet`이 `narrative`보다 낫다」 |
| 생성된 일기에 지어낸 것이 N건 있었다 | 「지어내기가 줄었다」 |

**심은 하루는 우리가 만든 것이며, 우리가 기대한 답을 유도하도록 만들었을 수 있다.**
얻을 수 있는 것은 **「이 경로가 도는가」**이지 **「출력이 좋은가」**가 아니다.

관측은 적되 **「합성 하루에서의 관측」으로 구분해 적는다**(FR-020) — 진짜 하루에서 본
것과 같은 자리에 적지 않는다.

---

## 준비

```
adb devices                    # 기기가 하나만 붙어 있어야 한다
adb shell dumpsys trust        # deviceLocked=0 이어야 한다
```

**기기가 여럿이면 도구가 실패한다** — 대상을 특정할 수 없다.

**앱에 사진 권한이 있어야 한다.** 없으면 심어도 `unknown`으로 나온다(그것도 갈래이지만
A/B에서 확인하려는 것이 아니다):

```
adb shell dumpsys package <패키지> | grep -A2 READ_MEDIA_IMAGES
```

## A — 도구가 도는가 (기기만, 앱 없이)

### A1. 심는다

```
npm run seed:day -- rich 2026-08-21
```

**통과**: 종료 코드 `0`. 마지막 줄이 이런 JSON이다.

```
{"ok":true,"day":"2026-08-21","shape":"rich","seeded":3,"withLocation":2,"existing":0}
```

### A2. ★ 기기에 실제로 색인됐는가 (research.md §1이 잡은 실패)

```
adb shell "content query --uri content://media/external/images/media \
  --projection _id:_data:datetaken --where \"_data LIKE '%<전용폴더>%'\""
```

**통과**: 행이 3개이고 **`datetaken`이 NULL이 아니다.**

**⚠️ `datetaken=NULL`이면 도구가 성공을 보고했더라도 결함이다.** 그 상태에서는 앱이
사진을 못 본다 — FR-018d가 막으려는 것이 정확히 이것이다.

`datetaken` 값을 사람이 읽는 시각으로 바꿔 **2026-08-21의 04:00~다음날 04:00 안**인지
확인한다. 밖이면 시간대가 어긋난 것이다(research.md §8).

### A3. 좌표가 파일에 박혔는가

```
adb pull /sdcard/Pictures/<전용폴더>/<파일> /tmp/check.jpg
```

EXIF GPS를 읽어 심으려 한 좌표와 같은지 본다.

### A4. 목록이 답하는가 (FR-011c)

```
npm run seed:list
```

**통과**: 3장과 그 하루가 보인다.

### A5. 범위 밖 하루를 거부하는가 (FR-005a, SC-013a)

```
npm run seed:day -- rich 2030-01-01     # 미래
npm run seed:day -- rich 2020-01-01     # 너무 오래됨
```

**통과**: 둘 다 종료 코드 `1`, `reason: "day-out-of-range"`, **그리고 기기에 사진이 하나도
안 들어갔다**(A2의 질의로 확인).

### A6. 되돌리기 (FR-012, SC-006·007)

**심기 전 기기의 전체 사진 수를 세어 둔다:**

```
adb shell "content query --uri content://media/external/images/media --projection _id" | wc -l
```

```
npm run seed:clear
```

**통과 셋**:
1. 전용 폴더가 사라졌다
2. **MediaStore에 유령 행이 없다** — `_data LIKE '%<전용폴더>%'`가 `No result found`
3. **전체 사진 수가 심기 전과 같다**(SC-006) — 진짜 사진이 하나도 안 지워졌다(SC-007)

### A7. ★ 자동으로 치우지 않는가 (FR-011a, SC-006a — 명확화 Q4)

```
npm run seed:day -- rich 2026-08-21
# seed:clear를 부르지 않는다
npm run seed:list
```

**통과**: 3장이 그대로 있다. **도구가 스스로 치우지 않았다.**

### A8. 남은 것을 알리는가 (FR-011b)

A7에 이어서:

```
npm run seed:day -- empty 2026-08-20
```

**통과**: 결과의 `existing`이 **0이 아니다** — 앞서 심은 것이 보인다.

## B — 앱이 무엇을 보는가 (★ 이 기능의 존재 이유)

### B1. ★ SC-002 — 신호가 있는 하루의 일기

**005 이후 아직 한 번도 못 본 화면이다.**

```
npm run seed:day -- rich 2026-08-20
```

앱을 열어 2026-08-20을 고르고 일기를 생성한다.

**통과**:
- 목록에 **「사진 3장」**
- 상세에 **「사진: 3장」**과 **자리 2곳**
- 「사진 없음」도 「사진 모름」도 아니다

**관측만 적는다**: 생성된 일기에 지어낸 것이 몇 건인지 세어 적되, **「좋아졌다」를 적지
않는다**(FR-021).

### B2. SC-003 — 「사진 없음」을 의도적으로

```
npm run seed:clear
npm run seed:day -- empty 2026-08-19
```

**통과**: 목록에 **「사진 없음」**. **「사진 모름」이 아니다.**

**이 구분이 핵심이다**(원칙 V): 권한이 있고 물어봤는데 0장인 것(`none`)과, 권한이 없어
못 본 것(`unknown`)은 다르다. 007이 미확인으로 남기고 009가 우연히 본 갈래를 **의도적으로**
만든다.

### B3. SC-004 — 좌표가 일부에만 있는 하루

```
npm run seed:clear
npm run seed:day -- partial-location 2026-08-20
```

**통과**: 사진은 5장인데 자리 값이 **좌표를 본 2장에 근거한 것**으로 나온다.
**5장 전부를 본 것처럼 말하지 않는다.**

### B4. SC-005 — 잘린 하루

```
npm run seed:clear
npm run seed:day -- over-limit 2026-08-20
```

**⚠️ 201장을 심는다. 시간을 재서 적는다** — research.md의 짐작 표에 실측을 채운다.

**통과**: 그 하루가 잘린 것으로 판정되고, **일기가 사진의 수를 단언하지 않는다.**

### B5. `unknown` 갈래 (도구가 만들지 않는다 — FR-014)

```
adb shell pm revoke <패키지> android.permission.READ_MEDIA_IMAGES
```

**통과**: 심은 사진이 그대로 있는데 **「사진 모름」**이 된다. **「사진 없음」이 아니다.**

**같은 사진이 기기에 그대로 있는데 권한만으로 갈린다** — 004가 값에서 지킨 구분이
화면까지 도착하는 것을 도구가 준비한 하루에서 다시 확인한다.

```
adb shell pm grant <패키지> android.permission.READ_MEDIA_IMAGES
```

### B6. SC-010 — 미리 만든 글이 아니다 (원칙 I)

같은 하루로 **두 번** 생성한다.

**통과**: 두 번 다 실제로 생성이 돌고(「쓰고 있다」가 보인다), 저장된 것을 다시
보여주지 않는다.

**⚠️ 두 일기가 서로 비슷할 수 있다.** 신호가 같으면 그것이 정상이다(006 FR-037a) —
**「비슷하다」와 「저장된 것을 다시 보여준다」는 다르다.**

## C — 앱을 바꾸지 않았는가 (SC-008·009)

```
git diff --stat src/ App.tsx
```

**통과**: **변경 0줄.** 이 기능의 가장 강한 주장이다.

```
npm run lint          # 헌법 검사 포함
npm test
```

**통과**: 둘 다 초록불. 헌법 검사가 「도구가 일기에 닿는다」를 잡는 규칙을 포함한다.

### C1. 위반 주입으로 그물을 확인한다

**초록불을 믿기 전에 위반을 넣어 본다**(이 저장소의 관행):

| 주입 | 걸려야 하는 것 |
| --- | --- |
| `scripts/seed/*.mts`가 `src/diary/store`를 import | 헌법 검사 |
| `RunResult`에 `elapsedMs` 추가 | 선언을 직접 읽는 테스트(원칙 IV) |
| 부분 성공을 `ok: true`로 반환 | 결과 판정 테스트(FR-018c) |
| 확인 단계를 건너뛰고 성공 반환 | 확인 테스트(FR-018d) |

**주입한 것을 반드시 되돌린다.**

## 기록할 것 (원칙 V)

검증이 끝나면 **AGENTS.md에 적는다.** 형식:

```
### ✅/⚠️ 010을 실기기에서 확인했다 (날짜, 기기, 빌드)

- 실측으로 바뀐 것: (research.md의 짐작 표에서 채워진 것)
- 새로 관측된 것:
- ⚠️ 어긋난 것:
```

**「합성 하루에서의 관측」임을 명시한다**(FR-020). 진짜 하루의 관측과 같은 자리에 적으면
원칙 V가 깨진다.

### research.md의 짐작 표에서 채울 것

| 값 | 어디서 채워지나 |
| --- | --- |
| 색인이 끝나기까지의 시간 | A1·A2 |
| 201장을 심는 시간 | B4 |
| 시간대가 다를 때 | (다른 시간대 기기가 있을 때만) |
