## User Scenarios & Testing _(mandatory)_

사용자는 **이 앱을 만드는 개발자**다. 개발 환경(실기기 개발 빌드)에서만 쓰인다.

### User Story 1 - 홈의 여러 상태를 실제 데이터 없이 띄워 본다 (Priority: P1)

개발자는 화면 모양을 확인하려고 매번 사진을 지우거나 권한을 끄거나 날짜가 바뀌길 기다릴 수 없다. 개발자 화면의 「상태 흉내」에서
오늘 날짜를 다른 날로 두거나, 안 쓴 날을 「쓸 재료 0」·「사진 권한 없음」으로 보이게 하거나, 실패 토스트를 띄워 홈의 모양을 바로 본다.

**Why this priority**: 이 기능의 존재 이유다. 054·053·049의 상태를 실기기에서 재현하는 데 매번 수 분씩 걸렸다(권한 회수는 앱 프로세스를 죽인다).

**Independent Test**: 개발 환경에서 「쓸 재료 0으로 보기」를 켜고 홈으로 돌아와, 안 쓴 날이 사진 0장·장소 0곳으로 보이는지 본다.

**Acceptance Scenarios**:

1. **Given** 개발 환경, **When** 개발자 화면을 연다, **Then** 「상태 흉내」 묶음에 「오늘 날짜」·「실패 토스트 보기」·「쓸 재료 0으로 보기」·「사진 권한 없음으로 보기」 네 행이 있고 묶음 머리 오른쪽에 「개발 빌드만」이 있다.
2. **Given** 「오늘 날짜」 행을 누른다, **When** 달력에서 날을 고른다, **Then** 행 값에 그 날(예: 2026-09-13)이 보이고 홈이 그 날을 고른 채로 큰 숫자·주간 스트립·미래 칸 흐림을 그 날을 오늘로 그린다.
3. **Given** 날짜 흉내가 켜져 있다, **When** 대화상자에서 「끄기」를 누른다, **Then** 행 값이 비고 홈이 실제 오늘을 고른 채로 돌아온다.
4. **Given** 「쓸 재료 0으로 보기」가 켜져 있다, **When** 홈에서 안 쓴 날을 본다, **Then** 사진 0장·장소 0곳(관측된 0)으로 보인다.
5. **Given** 「사진 권한 없음으로 보기」가 켜져 있다, **When** 홈에서 안 쓴 날을 본다, **Then** 사진 칸이 권한이 없다는 모양으로 보인다. 「쓸 재료 0」이 함께 켜져 있어도 권한 없음 모양이다.
6. **Given** 「실패 토스트 보기」가 켜져 있다, **When** 개발자·설정 겹을 닫고 홈으로 돌아오거나 앱을 연다, **Then** 실패 토스트 「일기를 쓰지 못했어요.」가 한 번 뜬다.
7. **Given** 흉내를 켜 두었다, **When** 앱을 완전히 껐다 다시 연다, **Then** 흉내 값이 그대로다.
8. **Given** 쓴 날, **When** 어떤 흉내를 켜든, **Then** 그 날의 제목·본문·사진은 그대로다.

### User Story 2 - 흉내가 켜진 동안 일기가 써지지 않는다 (Priority: P1)

가짜 상태를 보면서 진짜 일기가 저장되면 일기 기록이 오염된다. 흉내가 하나라도 켜져 있으면 홈의 쓰기, 앱을 열면 쓰는 중, 백그라운드 자동 쓰기,
진단의 두 쓰기 버튼이 모두 일기를 쓰지 않고, 홈이 그 사실을 눈에 띄게 알린다.

**Why this priority**: 헌법 원칙 I(엔드유저가 읽는 일기는 기기에서 실제 신호로 생성된 것이어야 한다)과 S8의 방어선이다. 흉내 기능은 이것 없이 성립하지 않는다.

**Independent Test**: 흉내 하나를 켠 채 홈의 쓰기 바를 눌러 토스트만 뜨고 일기 파일이 생기지 않는지 본다.

**Acceptance Scenarios**:

1. **Given** 흉내가 하나라도 켜져 있다, **When** 홈을 본다, **Then** 월 라벨 옆에 「DEV」가 있고 쓰기 바가 빨간 면 대신 회색 면 + 「DEV」다.
2. **Given** 같은 상태, **When** 쓰기 바(「일기 쓰기」 또는 「다시 쓰기」)를 누른다, **Then** 「상태 흉내가 켜져 있어서 일기를 쓰지 않아요. 개발자 화면에서 끌 수 있어요.」가 약 2초 뜨고 쓰는 중으로 넘어가지 않는다. 확인 대화상자(덮어쓰기·재료 확인)도 뜨지 않는다.
3. **Given** 같은 상태, **When** 「DEV」 표시를 누른다, **Then** 개발자 화면이 열린다.
4. **Given** 같은 상태에서 자동 쓰기가 켜져 있고 목표 시각이 지났다, **When** 앱을 연다, **Then** 홈이 쓰는 중으로 시작하지 않는다.
5. **Given** 같은 상태, **When** 백그라운드 자동 쓰기가 돈다, **Then** 일기도 완성 알림도 생기지 않고 쓰기 실패 기록도 늘지 않는다.
6. **Given** 같은 상태, **When** 진단 화면을 연다, **Then** 「지금 한 번 써 보기」·「자동 쓰기 지금 실행」을 누를 수 없고 차단 문구가 보인다.
7. **Given** 흉내를 모두 끈다, **When** 홈으로 돌아온다, **Then** DEV 표시가 사라지고 쓰기 바가 원래 모양으로 돌아오며 쓰기가 다시 된다.

### User Story 3 - 흉내는 개발 환경에만 있고 끄면 남지 않는다 (Priority: P2)

배포 빌드의 사용자는 흉내를 보거나 켤 수 없어야 하고, 개발자가 개발자 메뉴를 끄면 흉내도 함께 사라져야 한다.

**Why this priority**: S7(배포 빌드에는 묶음 자체가 없다)과 보드 `6e` ⑤(끄면 상태 흉내도 모두 꺼짐).

**Independent Test**: 흉내를 켠 뒤 개발자 메뉴를 끄고 앱을 다시 열어 DEV 표시가 없는지 본다.

**Acceptance Scenarios**:

1. **Given** 배포 환경, **When** 개발자 화면을 연다, **Then** 「상태 흉내」 묶음이 없다.
2. **Given** 배포 환경에서 이전에 저장된 흉내 값이 기기에 남아 있다, **When** 앱을 연다, **Then** 홈에 DEV 표시가 없고 쓰기가 막히지 않는다.
3. **Given** 개발 환경에서 흉내를 켰다, **When** 개발자 메뉴를 끈다, **Then** 흉내가 모두 꺼지고 다음 실행에 메뉴가 다시 켜져도 흉내는 꺼진 채다.

### Edge Cases

- 흉내 값 기록이 깨졌거나 읽지 못하면 흉내는 꺼진 것으로 본다(홈도 실제 데이터를 보이므로 실제 일기를 써도 어긋나지 않는다).
- 날짜 흉내는 미래 날도 고를 수 있다 — 쓰기가 막혀 있으므로 미래 날에 일기가 생기지 않는다.
- 날짜 흉내 중에는 실제 자정이 지나도 홈의 오늘이 넘어가지 않는다.
- 흉내를 켜는 순간 이미 쓰는 중이면 그 쓰기는 그대로 끝까지 간다(흉내는 새 쓰기의 시작만 막는다).
- 일기 모두 지우기·모듈 다시 받기·온보딩부터 다시는 흉내가 켜져 있어도 막지 않는다(일기를 쓰는 동작이 아니다).

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 개발 환경의 개발자 화면은 「상태 흉내」 묶음(머리 오른쪽 「개발 빌드만」)과 네 행 「오늘 날짜」·「실패 토스트 보기」·「쓸 재료 0으로 보기」·「사진 권한 없음으로 보기」를 보여야 한다(MUST). 배포 환경에는 묶음이 없어야 한다(MUST NOT).
- **FR-002**: 「오늘 날짜」 행은 누르면 날을 고르는 달력 대화상자를 연다(MUST). 과거·미래 모두 고를 수 있고(MUST), 대화상자에 날짜 흉내를 끄는 조작이 있다(MUST). 켜져 있으면 행 값이 `YYYY-MM-DD`이고 꺼져 있으면 비어 있다.
- **FR-003**: 나머지 세 행은 켜고 끄는 토글이다(MUST).
- **FR-004**: 흉내 값은 앱을 다시 열어도 유지된다(MUST). 개발자 메뉴를 끄면 모두 지워진다(MUST).
- **FR-005**: 흉내는 개발 환경에서만 효력이 있다(MUST). 배포 환경에서는 남아 있는 흉내 값이 있어도 표시·쓰기 어디에도 영향이 없다(MUST NOT).
- **FR-006**: 날짜 흉내는 홈이 「지금」으로 쓰는 날짜만 바꾼다(MUST) — 큰 숫자·요일·주간 스트립·미래 칸·「N시간 M분 전에 작성」. 시각(시·분)은 실제 시각이다. 흉내 중에는 실제 자정에 날이 넘어가지 않는다(MUST). 날짜 흉내를 켜거나 바꾸면 홈의 고른 날이 그 날이 되고, 끄면 실제 오늘이 된다(MUST).
- **FR-007**: 「쓸 재료 0으로 보기」는 안 쓴 날의 미리보기를 사진 0장·장소 0곳(관측된 0)으로 바꾼다(MUST). 「사진 권한 없음으로 보기」는 안 쓴 날의 미리보기를 사진 권한 없음으로 바꾼다(MUST). 둘 다 켜져 있으면 권한 없음이다(MUST).
- **FR-008**: 「실패 토스트 보기」가 켜져 있으면 홈이 다시 보일 때(겹이 닫힐 때·앱을 열 때)마다 실패 토스트가 한 번 뜬다(MUST).
- **FR-009**: 쓴 날의 지면(제목·본문·사진)은 어떤 흉내에도 바뀌지 않는다(MUST NOT).
- **FR-010**: 흉내가 하나라도 켜져 있으면 홈 월 라벨 옆에 「DEV」 표시가 있고(MUST), 누르면 개발자 화면이 열린다(MUST).
- **FR-011**: 흉내가 하나라도 켜져 있으면 쓰기 바는 회색 면 + 「DEV」이고(MUST) 누를 수 있다. 누르면 차단 토스트(보드 원문)가 약 2초 뜨고 쓰는 중·확인 대화상자로 넘어가지 않는다(MUST).
- **FR-012**: 흉내가 하나라도 켜져 있으면 일기를 새로 쓰기 시작하는 모든 진입점이 쓰지 않는다(MUST) — 홈의 쓰기·다시 쓰기, 앱을 열면 쓰는 중(057), 백그라운드 자동 쓰기, 진단의 「지금 한 번 써 보기」·「자동 쓰기 지금 실행」. 「막는가」의 판정은 한 곳이다(MUST).
- **FR-013**: 백그라운드 자동 쓰기가 흉내 때문에 쓰지 않을 때는 완성 알림도 쓰기 실패 기록도 남기지 않는다(MUST NOT).
- **FR-014**: 진단의 두 쓰기 버튼은 흉내가 켜져 있는 동안 누를 수 없는 행이고 차단 문구를 보조 줄로 보인다(MUST).
- **FR-015**: 흉내 값(날짜·미리보기)은 일기 생성 경로·자동 쓰기 판정·신호 수집에 전달되지 않는다(MUST NOT). 그쪽에 닿는 것은 「쓰기를 막는가」 하나뿐이다. 이 경계는 자동 검사로 지킨다(MUST).
- **FR-016**: 흉내 값 기록이 없거나 깨졌거나 읽지 못하면 흉내는 모두 꺼진 것으로 본다(MUST).
- **FR-017**: 화면 문구는 언어별 카탈로그에서 온다(MUST, 062) — 보드 KO 문자열 표의 `dev.group.sim`·`sim.date`·`sim.fail`·`sim.empty`·`sim.noPhoto`·`sim.blockedToast` 원문, 「DEV」, 「개발 빌드만」.

### Key Entities

- **흉내 상태**: 날짜 흉내(없음 또는 하루), 실패 토스트 보기·쓸 재료 0·사진 권한 없음(각 켬/끔). 기기에 하나 저장된다. 실행 이력(켠 시각·횟수)은 담지 않는다(D3).
- **쓰기 차단**: 흉내 상태에서 나오는 「하나라도 켜짐」 한 값. 쓰기 진입점들이 이것만 본다.

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 개발자가 네 가지 홈 상태(다른 날짜·실패 토스트·재료 0·권한 없음)를 각각 개발자 화면에서 1분 안에 띄워 볼 수 있다(지금은 권한 회수·사진 삭제·날짜 대기로 수 분 이상).
- **SC-002**: 흉내가 하나라도 켜진 동안 다섯 쓰기 진입점 어디에서도 일기 파일이 새로 생기거나 바뀌지 않는다(실기기에서 수동 쓰기·백그라운드 자동 쓰기로 확인).
- **SC-003**: 배포 환경에서 흉내 묶음·DEV 표시·쓰기 차단이 한 번도 보이지 않는다.
- **SC-004**: 흉내를 모두 끄면 홈이 흉내 전과 같은 모양·동작으로 돌아온다(DEV 표시 0, 쓰기 정상).
- **SC-005**: 흉내 값이 일기 생성·자동 쓰기 판정에 닿는 코드 경로가 0개다(자동 검사로 확인).

## Assumptions

- 「개발 환경」은 `local`·`dev`, 「배포 환경」은 `prod`다(D2). 판정은 기존 환경 판정을 쓴다.
- 날짜 대화상자는 050 「날짜로 이동」 달력의 모양을 따른다. 「끄기」 조작의 문구는 보드에 없어 새로 정한다(카탈로그).
- 흉내를 켜는 순간 이미 진행 중인 쓰기는 멈추지 않는다 — 보드는 「켜져 있는 동안 쓰지 않음」만 말하며, 쓰는 중에 개발자 화면으로 가는 경우는 드물다.
- 진단 두 버튼의 차단 문구는 `sim.blockedToast`를 그대로 쓴다(새 문구를 만들지 않는다).
- 실기기 확인은 dev(debug)만 한다(AGENTS 「테스트」).
