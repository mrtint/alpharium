# Feature Specification: 작명 화면을 디자인 보드 1a와 일치시키기

**Feature Branch**: `047-welcome-naming-1a`

**Created**: 2026-09-23

**Status**: Draft

**Input**: User description: "작명 화면(WelcomeScreen welcome 단계)을 Modernist 디자인 리뷰 보드의 First run `1a`(Welcome & naming)와 같게 맞춘다." (전문은 대화 기록 — 1a 마크업 추출값, 지켜야 할 계약 목록 포함)

## 배경

046 머지 후 실기기(SM-S901N, dev)에서 다운로드 완료 → [시작할게요] 다음에 뜨는 작명
화면이 디자인 리뷰 보드 `1a`와 다르게 나온다. 044가 `1a`를 참조해 재작성했지만
실제 마크업과 어긋난 곳이 여럿이다.

| 항목 | 지금(실기기 관측) | `1a` 원본 |
| --- | --- | --- |
| 상단 표지 | 없음 | 붉은 대문자 표지 "ALPHARIUM" |
| 캐릭터 얼굴 | 없음 | 56×56 얼굴 타일 |
| 제목 | "오! 주인님, 반가워요" (중간 크기) | "깨어났어요. 처음 뵙겠습니다." (매우 큰 굵은 제목) |
| 본문 | "이제부터 제가 주인님의 하루를 일기로 적을게요." | "이제부터 제가 주인님의 하루를 사진과 다닌 자리로 읽고, 일기로 적을게요. 모든 일은 이 휴대폰 안에서만 일어나요." |
| 세로 배치 | 위에 몰림 | 가운데 묶음이 세로 중앙, 버튼 줄은 화면 아래 |
| 이름 입력 | 중간 크기 글자, 카운터 없음 | 큰 굵은 글자, 오른쪽에 "n/12" 카운터 |
| 힌트 | "나중에 설정에서 바꿀 수 있어요." | "12자까지. 나중에 설정에서 바꿀 수 있어요." |

## Clarifications

### Session 2026-09-23

- Q: 이름 칸이 비어 있을 때 [이 이름으로 할래요 →] 버튼은 어떻게 보여야 하나요? → A: 늘 `1a`와 같은 진한 강조색. 빈 칸일 때 눌러도 아무 일도 일어나지 않는다.
- Q: 금동이의 얼굴 타일에는 어떤 얼굴을 넣을까요? → A: 🤖 — 금동이는 어미 변형 없는 담백한 화자라 `1u`의 "🤖 plain, no verbal tic"과 같은 성격이다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 첫 만남 화면이 디자인대로 보인다 (Priority: P1)

다운로드를 마치고 [시작할게요]를 누른 사용자는 휴대폰 속 캐릭터가 자기를 소개하고
이름을 묻는 화면을 본다. 이 화면이 디자인 보드 `1a`와 같은 구성·문구·위계로
보여야 앱의 첫인상이 기획대로 전달된다.

**Why this priority**: 사용자가 지적한 불일치 그 자체이며, 이 화면은 첫 실행에서
누구나 반드시 지나간다.

**Independent Test**: 첫 실행 흐름을 작명 단계까지 진행해 화면을 `1a`와 나란히
놓고 항목별로 대조한다.

**Acceptance Scenarios**:

1. **Given** 작명 단계에 진입했다, **When** 화면이 그려진다, **Then** 위에서부터
   "ALPHARIUM" 표지 → 캐릭터 얼굴 타일 → 제목 "깨어났어요. 처음 뵙겠습니다." →
   본문 → 구분선 → "제 이름을 지어주세요." → 이름 입력줄 → 힌트 순서로 보이고,
   버튼 줄 [나중에 할래요] [이 이름으로 할래요 →]가 화면 아래 오른쪽에 있다.
2. **Given** 작명 단계, **When** 화면을 본다, **Then** 가운데 묶음(얼굴~힌트)이
   남은 세로 공간의 중앙에 놓인다.
3. **Given** 작명 단계, **When** 화면을 본다, **Then** 하단 가운데의 캐릭터 이름
   텍스트는 없다.

---

### User Story 2 - 이름을 입력하며 남은 글자를 안다 (Priority: P2)

사용자가 이름을 치면 입력한 글자가 크게 보이고, 오른쪽에 지금 몇 자인지
"n/12"로 보인다. 12자를 넘겨 칠 수 없다.

**Why this priority**: `1a`가 정한 상호작용 요소이며 작명 규칙(상한)을 사용자에게
미리 알려 준다.

**Independent Test**: 이름 입력줄에 글자를 넣고 빼면서 카운터가 따라 바뀌는지,
12자에서 더 입력되지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 입력이 비어 있다, **When** 화면을 본다, **Then** 카운터는 "0/12"다.
2. **Given** "금동" 두 글자를 입력했다, **When** 화면을 본다, **Then** 카운터는
   "2/12"다.
3. **Given** 12자를 입력했다, **When** 한 글자를 더 친다, **Then** 입력은 12자에
   머물고 카운터는 "12/12"다.
4. **Given** 입력이 비었거나 공백뿐이다, **When** [이 이름으로 할래요]를 누른다,
   **Then** 이름이 확정되지 않는다(035 규칙 유지).

---

### User Story 3 - 기존 길이 그대로 이어진다 (Priority: P3)

화면 모양이 바뀌어도 이름 확정·건너뛰기 뒤의 흐름(liveness → 일기 탭)과 키보드가
열렸을 때 버튼에 닿는 방법, 확인 중·실패 단계는 지금과 같다.

**Why this priority**: 회귀 방지. 모양만 바꾸는 작업이 흐름을 깨면 안 된다.

**Independent Test**: 기존 계약 테스트와 Maestro `welcome-naming.yml`이 그대로
통과하고, 실기기에서 키보드를 연 채 버튼까지 스크롤로 닿는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 이름을 입력했다, **When** [이 이름으로 할래요 →]를 누른다, **Then**
   지금과 같이 그 이름으로 확정되고 다음 단계로 간다.
2. **Given** 작명 단계, **When** [나중에 할래요]를 누른다, **Then** 기본 이름으로
   다음 단계로 간다(막다른 길 없음).
3. **Given** 키보드가 열려 화면 아래를 가린다, **When** 스크롤한다, **Then** 두
   버튼에 닿을 수 있다.
4. **Given** 확인 중 또는 실패 단계, **When** 화면을 본다, **Then** 지금과 같다.

### Edge Cases

- **키보드가 화면 대부분을 가리는 좁은 기기**: 가운데 묶음 중앙 정렬과 하단 버튼
  줄이 키보드에 가려져도 스크롤로 버튼에 닿아야 한다(044 T016 유지).
- **긴 제목 줄바꿈**: "깨어났어요. 처음 뵙겠습니다."가 좁은 화면에서 두세 줄로
  나뉘어도 버튼 줄과 겹치지 않는다. 한국어 단어 중간에서 끊지 않는 것이 바람직하다.
- **글꼴 확대(접근성)**: 시스템 글꼴을 크게 해도 화면이 잘리지 않고 스크롤로 전부
  볼 수 있다.
- **12자를 붙여넣기**: 붙여넣은 글이 12자를 넘으면 12자까지만 들어간다.
- **빈 입력에서 확정 버튼**: 버튼 모양은 입력 여부와 무관하게 늘 `1a`의 진한
  강조색이다(옅은 비활성 모양을 쓰지 않는다). 빈 입력·공백뿐일 때 눌러도 아무 일도
  일어나지 않는다(035).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 작명 단계 화면 맨 위에 "ALPHARIUM" 표지를 강조색·작은 대문자·넓은
  자간으로 보여야 한다.
- **FR-002**: 표지 아래 가운데 묶음에 캐릭터 얼굴 타일(정사각 56×56, 얼굴 이모지,
  강조색 배경) **하나**를 보여야 한다 — 현재 로스터가 금동이 하나이므로(037).
  얼굴은 🤖다(`1a` 원본에서 선택된 기본 페르소나이자 `1u`의 어미 없는 화자 — 금동이의 담백한 말투와 같은 성격).
- **FR-003**: 제목은 "깨어났어요. 처음 뵙겠습니다."이며 `1a`의 위계(가장 큰 굵은
  글자, 줄 간격 촘촘하게)로 보여야 한다.
- **FR-004**: 본문은 "이제부터 제가 주인님의 하루를 사진과 다닌 자리로 읽고, 일기로
  적을게요. 모든 일은 이 휴대폰 안에서만 일어나요."여야 한다.
- **FR-005**: 본문 아래 구분선, 그 아래 "제 이름을 지어주세요." 프롬프트가 있어야
  한다.
- **FR-006**: 이름 입력줄은 아래쪽 밑줄만 있고, 입력 글자는 크고 굵게 보이며,
  같은 줄 오른쪽에 현재 글자 수 카운터 "n/12"를 보여야 한다.
- **FR-007**: 이름 입력 상한은 12자이며, 화면의 상한·카운터 분모·힌트의 숫자가
  작명 규칙의 상한과 같은 값이어야 한다.
- **FR-008**: 힌트는 "12자까지. 나중에 설정에서 바꿀 수 있어요."여야 한다.
- **FR-009**: 버튼 줄은 가운데 묶음과 분리되어 화면 아래에 오른쪽 정렬로 놓이며,
  [나중에 할래요](얇은 테두리) 다음 [이 이름으로 할래요](강조색 배경 + 오른쪽 화살표)
  순이어야 한다.
- **FR-010**: 가운데 묶음(얼굴~힌트)은 표지와 버튼 줄 사이 남은 공간의 세로 중앙에
  놓여야 한다.
- **FR-011**: 작명 단계에서 하단 가운데의 캐릭터 이름 텍스트를 보이지 않아야 한다.
  (확인 중·실패 단계의 표시 여부는 지금과 같다.)
- **FR-012**: 빈 입력·공백뿐인 입력으로는 이름을 확정할 수 없어야 한다(035 유지). 이때도 확정 버튼은 옅어지지 않고 `1a`와 같은 진한 강조색 모양을 유지하며, 눌러도 아무 일도 일어나지 않는다.
- **FR-013**: 화면은 계속 문자열과 콜백만 받아야 하며 모델 식별자·확인 결과 객체·
  작명 모듈에 닿지 않아야 한다(035 W12~W14, 원칙 III).
- **FR-014**: 화면의 모든 문구는 사람이 쓴 고정 상수여야 한다(035 L16).
- **FR-015**: 키보드가 열린 상태에서도 스크롤로 두 버튼에 닿을 수 있어야 한다
  (044 T016 유지).
- **FR-016**: 확인 중·실패 단계의 모양과 동작은 바꾸지 않는다.
- **FR-017**: 기존 화면 식별자(`welcome-screen`, `welcome-greeting`,
  `welcome-name-input`, `welcome-name-submit`, `welcome-name-skip` 등)는 유지해
  기존 계약 테스트·Maestro 흐름이 계속 찾을 수 있어야 한다.
- **FR-018**: 색은 기존 디자인 토큰만 써야 한다(새 하드코딩 색 없음, 043·044 관례).

### Key Entities

- **작명 화면 문구 묶음**: 표지·제목·본문·프롬프트·힌트·두 버튼 라벨. 모두 고정
  상수이며 캐릭터별로 다르지 않다.
- **이름 초안**: 사용자가 입력 중인 문자열(최대 12자). 화면 로컬 상태이며 확정 전
  파일에 남지 않는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 실기기 작명 화면을 `1a`와 대조했을 때 위 배경 표의 9개 불일치 항목이
  전부 해소된다(9/9).
- **SC-002**: 화면 문구 7종(표지·제목·본문·프롬프트·힌트·두 버튼)이 `1a` KO 문자열과
  글자 단위로 일치한다.
- **SC-003**: 입력 0~12자 전 구간에서 카운터가 실제 입력 글자 수와 항상 같다.
- **SC-004**: 이름 확정과 건너뛰기 두 경로 모두 지금처럼 다음 단계로 이어진다 —
  기존 작명 관련 기기 없는 테스트와 Maestro `welcome-naming.yml`이 회귀 없이 통과.
- **SC-005**: 키보드를 연 상태에서 사용자가 스크롤 한 번 이내로 두 버튼에 닿는다.

## Assumptions

- `1a` 원본의 얼굴 타일은 여러 페르소나(🤖·🐱·🐶)를 나열하고 선택된 것만 강조색이다.
  로스터가 하나이므로 타일 하나, 강조색 배경, 🤖로 둔다. 다중 페르소나·어미 변형
  (`1u`/`1v`/`1w`)은 범위 밖.
- 치수(패딩 70/20/44, 제목 38px 등)는 `1a`의 402×874 iOS 프레임 기준이다. 안드로이드
  실기기에서는 같은 비율·위계를 따르되 상태 표시줄 안전 영역과 겹치지 않게 조정할 수
  있다.
- "n/12" 카운터는 입력 중인 글자 수 표시일 뿐 원칙 IV가 금지한 측정 지표가 아니다.
- 글자 수는 사용자가 보는 글자 단위로 센다(한글 한 음절 = 1자). 기존 입력 상한이
  세는 방식과 어긋나면 작명 규칙(035) 쪽 셈을 따른다.
- 확인 중·실패 단계, 첫 실행 단계 전이, 이름 저장 방식은 범위 밖이다.
- 디자인 원본: `C:\Users\mrtin\Downloads\Alpharium Mobile Screens (standalone).html`의
  `dv-opt id="1a"`와 KO 문자열 테이블(`welcomeTitle:` 부근).
