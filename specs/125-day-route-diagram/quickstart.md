# Quickstart — 125 실기기 확인

전제: 개발 빌드 + Metro 번들(SM-S901N, `adb reverse tcp:8081 tcp:8081`). 기기에 `files/diary/`의 아래 날이 있다 — 이 기기의 11월 표본 날을 쓴다.

| 날 | 상태 | 기대 |
| --- | --- | --- |
| 2026-11-16 | 사진 8장·자리 4곳(121 이후 일기) | 본문 아래 점 4개·선 3개·범례 4줄·설명 한 줄 |
| 2026-11-15 | 사진 6장·자리 1곳 | 도식 없이 한 줄만 |
| 2026-11-12 | 121 이전 일기(`places` 없음) | 「하루 동선」 칸이 없다 |

## 절차
1. Metro를 띄우고 앱을 연다. 날 스트립에서 11-16을 고르고 지면을 끝까지 내린다 → 도식·범례·설명 한 줄. 점 번호와 범례 번호가 같은 순서다.
1b. 도식의 가로세로 비율: 같은 거리의 동서 간격과 남북 간격이 화면에서도 비슷한 길이로 보인다(세로가 눌려 보이지 않는다). 선이 점의 가운데에서 가운데로 이어진다.
2. 같은 날 첫 화면: 본문 노출이 도식 추가 전과 같다(글꼴 1.0배 8줄 이상). OS 글꼴 2.0배로 바꿔 범례가 줄바꿈되고 첫 화면 본문이 3줄인지 본다.
3. 11-15 → 한 줄만, 11-12 → 칸 없음. 날을 빠르게 넘겨(좌우 밀기) 늦은 결과가 다른 날에 그려지지 않는다.
4. 사진 권한을 OS 설정에서 끈 뒤 11-16 → 도식 없이 저장된 이름·때 목록만, 지면은 막히지 않는다(제약 띠가 권한을 말한다).
5. 일기 파일이 바뀌지 않았다 — 도식을 본 뒤 `run-as … cat files/diary/2026-11-16.json`이 시험 전 사본과 바이트까지 같다.
6. 같은 절차를 iPhone 14에서 11-16 하나로 한 번(개발 서명 Release 또는 개발 빌드).

## 못 보는 것 (기록할 때 채운다)
- 사진을 지운 날(자리 수 어긋남)과, 수는 같고 자리의 처음 시각·사진 수만 다른 날은 실기기에서 만들기 번거로워 단위 테스트(`day-route.test.ts` DR3)로 갈음한다 — 그렇게 적는다.
- 도식이 늦게 붙어 지면 높이가 늘 때 하단 바(「다시 쓰기」)가 어떻게 보이는지는 FR-016의 의도된 동작(끝 판정을 다시 하고 값이 바뀔 때만 알림)이라 실기기에서 거슬리지 않는지만 본다.
- iOS 사진 서비스 막힘(4099) 영향, 점·선 크기의 손맛은 실기기에서만 본다.

## 기록 (SM-S901N, 2026-11-22, 개발 빌드 + Metro)

| 절차 | 결과 |
| --- | --- |
| 1 · 11-16 | 점 3개(1·4가 한 점)·선 2개·설명 한 줄·범례 4줄. 처음 점이 마지막 점에 가려지던 것을 보고 겹친 점을 한 점으로 합쳐 번호를 잇게 고쳤다(DU8, 「1·4」, 강조 색 유지) — 고친 뒤 다시 봤다 |
| 2 · 첫 화면 | 글꼴 1.0배 본문 9줄(도식 추가 전과 같다), 2.0배 4줄, 범례는 줄바꿈된다. 글꼴 배율은 1.0으로 되돌렸다 |
| 3 · 11-15 / 11-12 | 11-15는 제목과 「1 · 오전 · 양수리」 한 줄만, 11-12는 칸이 없다. 빠른 좌우 넘김의 늦은 결과는 단위 테스트(DF4 경쟁)로 갈음했고 실기기에서 따로 만들어 보지 않았다 |
| 4 · 사진 권한 거부 | 권한을 거부한 채 띄우면 도식 없이 목록만(`day-route-diagram` 없음). 처음 시도는 Maestro `launchApp`이 권한을 다시 허용해 도식이 그려졌다 — 시험 환경 탓이며 `permissions: all: deny`로 띄워 확인했다. 시험 뒤 세 권한을 다시 허용했다 |
| 5 · 파일 | 세 날(11-12·11-15·11-16) 일기 파일이 시험 전 사본과 바이트까지 같다(`cmp`) |

못 본 것: 사진을 지운 날·수만 같고 시각·사진 수가 다른 날(DR3 단위 테스트로 갈음), 도식이 늦게 붙을 때 하단 바(FR-016) 거슬림, iOS 사진 서비스 막힘(4099), 점·선 크기의 손맛은 소유자 몫. 절차 6(iPhone 14)은 아직 못 했다.
