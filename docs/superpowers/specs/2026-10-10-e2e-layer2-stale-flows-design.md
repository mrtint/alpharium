# e2e 마무리 — 낡은 흐름 정리와 층 2(실제 생성 스모크) 설계

로드맵 「주요 기능별 e2e 테스트」(069·070 후속)의 남은 조각 중 **낡은 흐름 셋 정리**와 **층 2**를 다룬다. iOS 갈래·CI 판단은 로드맵에 남긴다(맥이 필요하다).

## 목적과 성공 기준

- `FLOWS`에서 실패하는 흐름이 없다(고쳤거나, 근거와 함께 지웠다).
- 대응표(`docs/e2e/feature-flow-map.md`)의 모든 주요 기능에 층 1 또는 층 2 흐름이 있거나 「사람이 봄」이 이유와 함께 적혀 있다.
- 층 2가 안드로이드 dev 실기기에서 한 번 완주한다. 단언은 상태 전이까지이고 본문은 단언하지 않는다(헌법 원칙 IV).
- 층 2 흐름은 `FLOWS`에 등록한다.

## A. 낡은 흐름 셋

실기기에서 원인을 가른 뒤 판정한다. **다른 흐름이 같은 것을 이미 보면 폐기하고(파일 삭제, 사유는 `FLOWS` 주석과 대응표), 지키는 것이 유일하면 현재 화면에 맞게 고친다.**

- `skeleton`: 「loaded」·`on-device`·저장 점검 단언이 유일한 방어일 가능성이 크다 — 진단의 현재 문구로 고친다.
- `prompt-preview`: 프롬프트 문안이 바뀐 것이 원인으로 보인다 — 문안이 아니라 구조(프리셋 둘·근사 크기 라벨)만 단언한다. 문안은 `prompt.ts`에서 바뀌므로 흐름에 박지 않는다.
- `today-diary`: 「일기」 단언 실패가 문구 탓인지 기준 상태 탓인지 먼저 가른다. 덮어쓰기 확인은 `dialog-foundation`이 보므로 중복이면 폐기한다.

## B. 층 2

`npm run test:layer2` (= `run-device-tests.mjs --layer2`). 층 1의 `runLayer1`을 재사용해 기준 상태(설정 파일 되돌리기·모델 존재 점검)를 만들되 `pm clear`·재설치는 하지 않는다. 일기 픽스처는 흐름이 요구하는 만큼(오늘 일기 없음, 지난 날 일부 있음)만 둔다. 사진은 070의 표본(MediaStore)을 쓴다. 전용 테스트 기기에서만 돈다.

흐름 넷(단언은 상태 전이까지):

1. **쓰기 → 저장 → 쓴 날 홈**: 쓰기를 누르면 쓰는 중, 끝나면 쓴 날 홈(제목·「다시 쓰기」).
2. **앱을 열면 쓰는 중(057)**: 자동 쓰기를 켜고 어제 재료가 있는 상태로 앱을 열면 쓰는 중을 거쳐 쓴 날로 끝난다.
3. **진단 한 번 써 보기(060)**: 쓰는 중 홈으로 가서 쓴 날로 끝난다.
4. **첫 실행 자동 첫 일기(040)**: 모델이 있는 채 온보딩 플래그만 되돌려 로고부터 자동 첫 일기까지. 모델 내려받기는 층 2가 아니므로 제외한다.

완료 대기는 `stop-button` 소멸(타임아웃 300초)로 한다. 끝나면 실행기가 저장된 일기 파일을 `adb pull`해 경로를 출력한다 — 사람이 읽을 뿐 자동 채점하지 않는다.

릴리스 전 체크리스트 `docs/e2e/layer2-release-checklist.md`를 두고 AGENTS의 release·iOS 절에서 링크한다.

## C. 대응표 갱신

기능 표의 「층 2」 열을 위 흐름으로 채우고, 폐기·수정한 낡은 흐름을 인벤토리에 반영한다. `flow-map.test.ts`를 층 2 목록까지 확장해 `FLOWS`·파일 정합을 잠근다.

## D. 검증

- 실행기 조립은 `Layer2Device` 주입으로 기기 없이 jest 테스트(층 1과 같은 방식). 대응표·`FLOWS` 등록은 계약 테스트.
- 위반 주입: 층 2 흐름의 완료 표식을 틀리게 하면 실패로 뒤집히는지 확인.
- 실기기(dev)에서 낡은 흐름 정리 결과와 층 2 네 흐름을 각각 한 번 완주한다.
