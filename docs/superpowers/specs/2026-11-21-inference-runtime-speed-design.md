# 온디바이스 추론 런타임 속도 최적화 — 설계

날짜: 2026-11-21 · 로드맵 「온디바이스 추론 런타임 속도 최적화 — Flash Attention·2턴 컨텍스트 재사용」 할 일 1~3

## 목적
사진 있는 날 본문 + 제목(2턴) 생성의 총 시간을 모바일 ARM 실기기에서 줄일 수 있는지 재고, **이득이 실측된 옵션만** 제품에 넣는다. 성공 모습: 두 기기(SM-S901N, iPhone 14)의 변경 전후 표(t/s, 1+2턴 총 시간, 최고 RAM)와, 메모리 한도(2 GiB 미만) 안에서 회귀 없이 완주하는 확인.

## 소스로 확인한 사실 (llama.rn 0.12.9, node_modules)
- `flash_attn_type: "auto"|"on"|"off"`을 `initLlama`가 받는다. 기본은 `auto`라 CPU에서 이미 켜져 있을 수 있다 — 효과는 `on`/`off`를 `auto`와 비교해서만 말할 수 있다.
- 본문(`run`)과 제목(`ask`)은 이미 같은 컨텍스트다. 해제는 `finally`의 `unload()` 한 번.
- `cache_prompt`·`cache_reuse` 옵션은 없다. 슬롯은 요청 시작에 KV를 지운다. 접두어 재사용은 `save_state_path`/`load_state_path`(상태 파일)로만 된다.
- `cache_type_k`/`cache_type_v`는 `initLlama`가 받는다. 양자화 V 캐시는 flash attention이 필요하다(llama.cpp 규칙, 실측으로 확인).

## 결정
| 결정 | 근거 | 뒤집으면 |
|---|---|---|
| 규모: 전체 트랙 | 수용 기준 3개 초과, 변경 파일 미확정 | 경량이면 plan·tasks·루프 생략 |
| 측정은 개발 중 로그·기기 도구로만, 제품에 측정 장치 없음 | 원칙 IV | 제품 코드에 계측이 들어옴 |
| 이득 없거나 크래시 나는 옵션은 넣지 않고 수치·까닭만 기록 | 로드맵 주의, 원칙 V | 수치 없이 넣게 됨 |
| 2턴 재사용은 상태 파일로 시도 | 0.12.9에 `cache_prompt` 없음 | 라이브러리 업그레이드 필요 |
| q8_0 KV는 RAM 2 GiB 미만 기기에서만, 기준 2 GiB는 사람이 정한 값 | 로드맵 값 | 실측 기반이면 저사양 기기 필요 |
| 시험 기기는 2 GiB 이상이라 q8_0은 강제 설정으로만 재현 | 기기 사양 | 실제 저사양 기기가 있으면 직접 확인 |

## 구성
1. 기준선: 변경 전 코드, 새 a1, 두 기기에서 측정.
2. FA: `contextParams`에 `flash_attn_type`을 명시하는 안을 `auto` 대비 측정.
3. 2턴 재사용: 본문 끝에 상태 저장 → 제목 호출이 `load_state_path`로 이어받기. 079 해제 순서·106 직렬화를 테스트로 다시 잠그고, 제목 구간 박동과 `assembly.ts` 한도·`SCREEN_IOS_PACING`(`use_mmap: false`)과 부딪히지 않는지 확인.
4. KV q8_0: 메모리 읽는 자리는 한 곳, 기준은 한 상수.

## 수용 기준
- 옵션별 변경 전후 실측표가 `specs/<번호>/quickstart.md`에 있다.
- 채택한 옵션은 테스트가 잠그고, 위반 주입이 잡힌다.
- 1+2턴 연속 생성이 두 기기에서 회귀 없이 완주한다. 못 본 것은 [미확인].
- `npm run lint`·`npm test` 통과.
