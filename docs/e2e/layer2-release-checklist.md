# 릴리스 전 체크리스트 — 층 2(실제 생성 스모크)

Google Play 내부 테스트나 TestFlight에 올리기 **전에** 사람이 따라 한다. 근거는 스펙 073, 기능별 대응은 [feature-flow-map.md](feature-flow-map.md).
층 1(화면 흐름)은 일기를 쓰지 않고 끝난다 — 실제 모델로 쓰는 경로는 이 체크리스트의 층 2가 처음이자 마지막 자동 확인이다. 건너뛴 것은 통과가 아니다(헌법 원칙 V).

## 전제

- [ ] **전용 테스트 기기** 하나만 연결돼 있다(`adb devices`). 이 기기의 일기가 지워진다.
- [ ] **dev 빌드**가 깔려 있다(`com.a810labs.pocketlog`) — release가 아니다(`run-as`가 필요하다). Metro가 dev 환경으로 떠 있고 `adb reverse tcp:8081 tcp:8081`이 걸려 있다.
- [ ] 기기 잠금이 풀려 있고 화면이 켜져 있다(`adb shell dumpsys trust`의 `deviceLocked=0`).
- [ ] **모델이 받아져 있다**(`files/models/`에 `a1.bin`·`v1.bin`·`v2.bin`). 없으면 실행기가 중단한다 — 이 실행은 모델을 받지 않고 `pm clear`도 하지 않는다.
- [ ] 사진·위치 권한이 부여돼 있다(권한 단계가 저절로 지나가려면).
- [ ] 070 표본은 실행기가 알아서 보장한다(처음이면 심는다).

## 실행

```
npm run test:layer2
```

- 흐름 네 개가 **하나씩** 돈다(각각 기준 상태를 다시 만든다). 전체 10~20분. 쓰기 하나가 1~4분이다.
- [ ] 끝에 `PASSED`가 나왔다. `SKIPPED`·`ABORTED`·`FAILED`는 통과가 아니다 — 이유를 읽는다.
- [ ] 흐름 네 개가 모두 `PASS`다: `layer2-write-and-read`, `layer2-open-app-writes`, `layer2-diagnostics-try-write`, `layer2-first-run-auto-diary`.

## 본문 읽기 (사람)

실행기가 끝에 `.cache/layer2/<시각>/` 아래로 가져온 일기 파일의 경로를 출력한다. 본문은 자동으로 채점하지 않는다(원칙 IV) — 사람이 읽는다.

- [ ] 일기가 **주인의 휴대폰이 화자**다(원칙 II). 주인의 시점으로 뒤집히지 않았다.
- [ ] 기록에 없는 사실(사람·장소·사건)을 있었던 것처럼 **단언하지 않았다**.
- [ ] 사진이 있는 날(어제, 5장)의 일기가 사진 내용을 반영한다.
- [ ] 지시문이 그대로 일기로 나오지 않았다.
- [ ] 제목이 붙었는지 본다(없어도 일기는 저장된다).

## 사람이 보는 항목 (대응표의 「사람이 봄」 중 릴리스 전에 볼 것)

- [ ] 사진 확대 화면의 핀치·두 번 탭·이동(`adb`로 두 손가락 입력을 만들 수 없다).
- [ ] 백그라운드 자동 쓰기와 완성 알림이 실제로 뜨는지(OS가 깨워야 한다 — 하루를 두고 본다).
- [ ] 큰 글꼴(2.0배)에서 설정·대화상자가 잘리지 않는지.
- [ ] 설정의 「일기 모두 지우기」를 실제로 눌렀을 때(058 quickstart).

## iOS

층 2의 iOS 갈래는 없다(맥이 필요해 로드맵에 남아 있다). **TestFlight에서 받은 앱이 실제 iPhone의 첫 실측이다** — 설치 → 권한 → 내려받기 → 첫 일기 → 다음 날 자동 쓰기 알림을 테스터가 확인한다(AGENTS 「iOS 빌드·서명·TestFlight」).

## 결과 기록

날짜·기기·소요 시간·`PASSED` 여부와 본문 읽기 소견을 릴리스 노트(또는 해당 스펙의 quickstart 끝)에 한 줄로 남긴다. 못 돈 항목은 「미확인」으로 적는다.
