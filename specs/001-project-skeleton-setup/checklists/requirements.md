## 검증 중 고친 것

1차 검토에서 아래를 발견해 명세를 수정했다.

1. **구현 세부사항 누출** — 초안의 요구사항에 `llama.rn`, `app.json`, `jest`,
   `.env.development` 같은 파일명과 패키지명이 들어 있었다. "네이티브 온디바이스 추론
   모듈", "환경 설정", "테스트 실행"처럼 무엇을 하는지로 바꿔 적었다. 어떤 파일을 어떻게
   고칠지는 `/speckit-plan`의 몫이다.
2. **성공 기준이 기술적이었다** — "`expo install --check`가 통과한다"를
   "선언과 설치본이 어긋나면 검사에서 드러난다"(SC-007)로 바꿨다.
3. **범위가 새고 있었다** — 초안에 모델 파일 내려받기와 기기 신호 수집이 섞여 있었다.
   「범위 밖」 절을 만들어 명시적으로 배제했다. 헌법이 경고한 실패 양상이다.

## 2차 개정 (2026-08-12)

저장소 소유자가 환경을 local / dev / prod 셋으로 나누고, local 시뮬레이터는 서버 추론을,
나머지는 온디바이스를 쓰도록 지시했다. 반영하며 확인한 것:

1. **헌법 개정이 필요한지 먼저 대조했다.** 원칙 I은 「데스크톱 추론 서버는 개발·튜닝
   단계에서 MAY」와 「원격 API 추론은 MUST NOT」을 따로 두고 있다. local이 부르는 것이
   데스크톱 추론 서버임을 확인했으므로 **헌법 개정 없이** 명세만 고쳤다. 외부 모델 API였다면
   원칙 I을 먼저 개정해야 했다.
2. **local의 온디바이스 경로를 막지 않았다.** 기본값만 서버이고, 실기기를 연결하면
   온디바이스로도 돌릴 수 있다 (FR-011).
3. **경계 사례를 추가했다.** 서버가 꺼져 있을 때 대체 응답으로 넘어가지 않을 것,
   서버 출력과 온디바이스 출력이 같다고 가정하지 않을 것.

## 3차 개정 — 명확화 (2026-08-12)

`/speckit-clarify` 세션에서 네 가지를 확정했다.

1. **환경 판정은 실행 시점** — 빌드는 하나, 설정값으로 갈린다 (FR-009a). 이 선택의 귀결로
   FR-012의 "경로가 존재하지 않는다"는 코드 경로만으로 성립하지 않게 되어, dev·prod에서
   서버 추론 시도가 차단되고 드러나야 한다는 조항을 추가했다 (FR-009c).
2. **진단 정보는 환경별로 갈림** — local·dev는 화면과 로그, prod는 로그만 (FR-007a).
   prod에서 화면에 안 보이는 것이 로그에도 안 남긴다는 뜻이 아님을 명시했다 (FR-007b).
3. **헌법 위반은 자동 검사가 막는다** — 커밋·빌드 시점 (FR-026~029). 이 검사가 헌법 원칙 IV의
   "측정 장치"에 해당하지 않음을 명시했다. 설정 위반을 잡는 것이지 모델 출력을 재는 것이
   아니다 (FR-028).
4. **실기기 테스트는 옵셔널** — 기기가 있으면 돌고 없으면 건너뛴다 (FR-021d). 건너뜀을 통과로
   보고하지 않는 것이 이 결정의 전제다 (FR-021e, 원칙 V). 대가로 기기 없이 돌린 실행은 전부
   통과해도 온디바이스가 검증되지 않은 상태이며, 이를 「가정」에 적었다.

FR 25개 → 40개, SC 11개 → 15개.

## 비고

- 이 기능의 "사용자"는 엔드유저가 아니라 저장소에서 일하는 개발자와 에이전트다. 명세
  본문에 그 사실을 밝혀 두었다.
- 의존성 버전(Expo 57)은 이 기능에서 정하는 것이 아니라 2026-08-12에 이미 확정되어
  헌법에 기록된 값이다. 이 명세는 그 위에서 뼈대를 세운다.
- `[NEEDS CLARIFICATION]`을 쓰지 않았다. 사용자가 값을 확정해 주었고(헌법, 의존성 기준선),
  나머지는 저장소 상태에서 확인 가능했다.
