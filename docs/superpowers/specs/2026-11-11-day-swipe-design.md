# 일기 글에서 좌우로 밀어 전날·다음 날로 이동한다 — 설계

## 목적
홈에서 날을 옮기려면 지금은 주간 스트립의 칸이나 달력(`DateJumpDialog`)을 눌러야 한다. **일기 글(지면)에서 좌우로 밀면 전날·다음 날로 넘어가게** 해, 일기를 책장 넘기듯 훑을 수 있게 한다. 소유자 요청(2026-10-30), 보드 밖 초안이다.

## 이해 (말한 것 / 가정)
- 말한 것: 일기 글에서 좌우로 밀면 전날·다음 날로 간다. 오늘 다음(미래)으로는 못 간다. 주간 스트립과 같은 상태를 쓴다. 쓰는 중에도 되는지 확인한다. 접근성 대안과 동작 줄이기를 챙긴다.
- 가정: 밀기는 읽는 장면을 위한 것이다. 쓰는 중(스트립이 잠긴 때)에는 날을 옮기지 않는다(054 잠금과 같다).

## 수용 기준
1. 쓴 날의 본문 영역과 안 쓴 날의 재료 지면에서 오른쪽으로 밀면 전날, 왼쪽으로 밀면 다음 날로 간다. 고른 날이 바뀌면 주간 스트립이 그 날이 든 주로 따라간다.
2. 오늘에서 다음 날로는 가지 않는다(아무 일도 없다). 과거로는 제한이 없다.
3. 사진 캐러셀의 가로 밀기, 지면의 세로 스크롤과 겹치지 않는다. 쓰는 중에는 동작하지 않는다.
4. 스와이프 없이도 쓸 수 있다: 헤더 날짜 요소에 스크린 리더 사용자 지정 동작 「전날」·「다음 날」이 있다.

## 결정
| 결정 | 근거 | 뒤집으면 |
|---|---|---|
| 밀기 영역: 쓴 날은 본문(캐러셀 제외), 안 쓴 날은 재료 지면 전체 | 캐러셀은 자기 가로 밀기가 있어(051) 겹치면 사진 넘기기가 날 넘기기가 된다 | 캐러셀 위에서도 날이 넘어가고 제스처 경합 처리가 필요함 |
| 방향: 오른쪽으로 끌면 전날, 왼쪽이면 다음 날 | 스트립(049)과 같다 — 과거가 왼쪽에서 들어온다 | 스트립과 반대가 됨 |
| 한계: 오늘 다음은 아무 일도 없음(튕김 없음), 과거는 제한 없음 | 스트립이 지난 날 전부를 고르게 한다(049·050). 본문에는 끌림 표현이 없어 튕길 것이 없다 | 과거 한계나 튕김 표현을 새로 정해야 함 |
| 상태: 기존 `setChosenDay`를 쓴다 — 스트립은 고른 날에서 7칸을 만들므로 주 경계를 넘으면 저절로 따라간다 | 두 입력이 같은 상태를 써야 어긋나지 않는다 | 별도 상태가 생겨 동기화가 필요함 |
| 전환 모양: 새 움직임을 만들지 않는다. 지면은 날마다 새로 마운트되고(`key`) 큰 날짜·요일은 기존 150ms 크로스페이드(049) | 스트립 칸을 눌렀을 때와 똑같이 보이게 한다. 동작 줄이기(100)도 기존 규칙을 따른다 | 슬라이드 전환을 새로 만들고 동작 줄이기 대응도 해야 함 |
| 쓰는 중에는 동작하지 않는다 | 054: 스트립이 잠기고 날을 못 옮긴다 | 쓰기 중 날 이동 정책을 새로 정해야 함 |
| 넘김 수치(거리 60pt·속도 600)와 시작 조건(가로 16pt 이상, 세로 12pt에서 포기)은 사람이 정한 값 | 보드에 수치 없음(원칙 V). 스트립의 40pt·500보다 크게 잡아 글을 읽다 스치는 오작동을 줄인다. 실기기에서 손에 맞지 않으면 고친다 | 값이 바뀜 |
| 접근성: 헤더의 날짜 요소(큰 숫자·요일 — 누르면 달력이 열리는 요소)에 사용자 지정 동작 둘(「전날」·「다음 날」) | 스와이프는 스크린 리더에서 쓰기 어렵다. 지면의 문단마다 붙이면 문단 탐색이 바뀐다. 스트립의 칸 누름도 그대로 있다 | 대안이 없어지거나 지면 문단에 동작이 붙음 |
| 안드로이드 시스템 뒤로 제스처(화면 가장자리)와의 충돌은 이번에 따로 처리하지 않는다 | 안드로이드 기기가 다른 측정 중이라 볼 수 없다. 가장자리 제스처는 OS가 먼저 가져간다 | 가장자리 안쪽만 받는 영역 제한이 추가됨 |

## 설계
- **순수 판정**(`src/app/state.ts`): `swipeDay(selected, direction, now)` — 이전은 하루 앞, 다음은 오늘이면 `null`, 아니면 하루 뒤. 날짜 계산은 `config/day-boundary.ts`의 `shiftDay`(새 export)가 한다. 하루 경계가 이 파일로 새지 않는다(`DB11`).
- **제스처**(`src/ui/day-swipe.tsx`, 새 파일): `Gesture.Pan`을 감싼 `DaySwipe` 래퍼. 넘김 판정(`daySwipeDirectionOf`)은 스트립의 `swipeDirectionOf`와 같은 모양의 순수 함수로 둔다.
- **화면**(`DiaryListScreen.tsx`·`WrittenDayPaper.tsx`): 쓴 날은 본문 부분만, 안 쓴 날은 재료 지면을 `DaySwipe`로 감싼다. 쓰는 중에는 감싸지 않는다. 접근성 동작은 헤더의 날짜 요소(`DateJump`)에 둔다. 새 prop은 `onSwipeDay?: (direction) => void` 하나다.
- **홈**(`DiaryHomeScreen.tsx`): `onSwipeDay`에서 `swipeDay()`로 다음 날을 정하고 `setChosenDay`를 부른다(스트립의 `onSwipe` 배선과 같다).
- **문구**(`src/i18n/catalogs/ko/`): 접근성 동작 이름 둘.
- **문서**(`design/DESIGN.md`): 홈의 날 이동 입력이 둘(스트립·본문 밀기)임을 적는다.

## 테스트
순수 판정(`swipeDay`·`daySwipeDirectionOf`)은 단위 테스트, 제스처 배선은 `fireGestureHandler`(RNTL), 접근성 동작은 소스·렌더 테스트. 화면 모양과 경합은 iOS 시뮬레이터에서 보고, 손에 맞는 정도는 iPhone 14에서 사람이 한 번 민다.

## 위험
- 본문 위의 세로 스크롤과 가로 밀기의 경합(수치는 실기기 값 필요).
- 안드로이드 가장자리 제스처 충돌은 보지 못한다.
- 같은 화면에서 캐러셀 위를 밀다 본문으로 손이 넘어가는 경우의 동작은 시뮬레이터로만 본다.
