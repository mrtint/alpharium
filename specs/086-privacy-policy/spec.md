## Clarifications

### Session 2026-10-15 (brainstorming)

- Q: 크래시·오류 수집 SDK를 1.0에 넣는가(D2)? → A: 넣지 않는다. 크래시는 스토어 콘솔과 앱 안 「최근 실패」로 본다.
- Q: 1.0의 백업 범위(D4)? → A: 안내 문구만. 이 기능은 방침의 보존·삭제 설명까지만 쓰고, 백업 규칙·유실 안내 구현은 「일기·모델 백업과 유실 안내」 과제가 한다.
- Q: 어디에 게시하는가? → A: 이 저장소의 GitHub Pages. 사이트 원문을 저장소 안 별도 폴더에 두고 공식 Pages 배포 워크플로로 올린다(main의 docs 폴더·별도 브랜치는 기각).
- Q: 문의 연락처? → A: 지원 전용 새 메일. 주소·운영자 이름·시행일은 자리표시자로 두고 게시 전에 소유자가 채운다.
- Q: 장소 이름 변환 때 좌표가 나가는가(M7)? → A: 나간다 — 소스(OS 지오코더 직접 호출)와 플랫폼 문서(Apple "network-based service", Android "may hit the network")로 확인. 네트워크 패킷으로는 재지 않았다.
- Q: 권한 문구를 고치는가? → A: iOS 위치 문구에 「좌표를 Apple 지도 서비스에 보낸다」를 더한다. 사진 문구는 그대로(사진 파일은 나가지 않는다).
- Q: Play 데이터 보안에서 지오코딩 좌표를 어떻게 답하는가? → A: 보수적으로 「정확한 위치 — 수집함」. iOS App Privacy는 「Data Not Collected」(Apple이 모으는 것은 선언 대상이 아니라는 문서 근거).
- Q: 지원 페이지 내용? → A: 자주 묻는 것 + 문의.

### Session 2026-10-15 (clarify)

- Q: 문의 메일의 주소와 내용을 얼마 동안 보관한다고 적는가? → A: 답장에만 쓰고, 문의 처리가 끝나면 지체 없이 지운다.
- Q: 방침을 고치면 지난 판을 사이트에 남기는가? → A: 현재 판 하나만 둔다. 「변경 이력」 절에 시행일과 바뀐 요지를 쌓고, 이전 원문은 저장소 기록(퍼블릭 git 히스토리)으로 링크한다.
- Q: 테스트가 방침 본문까지 읽어 외부 전송 항목을 대조하는가? → A: 그렇다. 외부 전송 목록(모듈 내려받기·지도 서비스·운영체제 진단 보고)의 항목마다 방침에 같은 표식이 붙은 절이 정확히 하나 있어야 한다 — 목록에만 있거나 방침에만 있으면 실패. 문장은 대조하지 않는다.
- Q: 두 URL이 실제로 열리는 게시까지 이 기능의 완료 조건인가? → A: 포함한다. 구현·리뷰가 끝나면 소유자가 자리표시자 값을 주고 저장소 설정에서 Pages를 켠 뒤 게시하고, 두 URL과 앱의 행을 실기기로 확인한 다음 완료 처리한다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 스토어 심사·사용자가 방침을 읽는다 (Priority: P1)

스토어 심사자와 사용자가 공개 URL로 방침을 연다. 방침은 무엇이 휴대폰 안에만 있고 무엇이 휴대폰 밖으로 나가는지(모듈 내려받기 때의 일반 웹 요청 정보, 장소 이름을 얻으려 보내는 좌표 하나, 운영체제의 진단 보고), 어떻게 지우고 끄는지, 어디로 문의하는지를 근거가 있는 사실로만 말한다.

**Why this priority**: 두 스토어 모두 방침 URL 없이 제출할 수 없고, Play는 비공개 테스트 트랙에서도 데이터 보안 양식(방침 링크 필수)을 요구한다 — 출시의 공통 병목이다.

**Independent Test**: 사이트 원문만으로 시험할 수 있다 — 방침의 각 사실 문장이 설계문서 §1의 근거와 짝지어지고, 자리표시자 외에 빈 곳이 없다. 게시 뒤에는 URL이 열린다.

**Acceptance Scenarios**:

1. **Given** 방침 원문, **When** 「휴대폰 밖으로 나가는 것」 절을 읽으면, **Then** 모듈 내려받기(Hugging Face가 일반 웹 요청 정보를 받음)·장소 이름(일기 한 편당 대표 좌표 하나, 끄는 법 포함)·운영체제 진단 보고(앱이 직접 보내지 않음) 셋이 있고 그 밖의 전송은 없다고 말한다.
2. **Given** 방침 원문, **When** 「보존과 삭제」 절을 읽으면, **Then** 앱 안 「일기 모두 지우기」·앱 삭제 시 함께 지워짐·기기 백업에 포함될 **수 있음**(단정하지 않음)·운영자는 백업에 접근하지 못함을 말한다.
3. **Given** 자리표시자가 남은 원문, **When** 게시를 시도하면, **Then** 게시가 실패하고 남은 자리표시자를 알린다.
4. **Given** 소유자가 자리표시자를 채우고 Pages를 켠 원문이 기본 브랜치에 들어가면, **When** 게시 워크플로가 돌면, **Then** 방침·지원 URL이 열린다(이 기능의 완료 조건).

---

### User Story 2 - 사용자가 앱 안에서 방침과 문의에 닿는다 (Priority: P1)

사용자가 설정 「정보」 묶음에서 「개인정보처리방침」 또는 「도움말·문의」를 누르면 기기의 브라우저로 그 페이지가 열린다. 브라우저를 열지 못하면 그 행 아래에 열지 못했다는 한 줄과 주소가 보여 손으로 옮길 수 있다.

**Why this priority**: App Store 5.1.1(i)은 방침 링크를 앱 안에도 요구한다.

**Independent Test**: 화면 테스트로 두 행의 존재·순서·누름·실패 보조 줄을 보고, 실기기에서 누르면 브라우저가 열리는 것을 본다.

**Acceptance Scenarios**:

1. **Given** 설정 「정보」 묶음, **When** 화면을 보면, **Then** 순서는 버전 → 개인정보처리방침 → 도움말·문의 → 서체 라이선스 → (켜져 있으면) 개발자다.
2. **Given** 브라우저가 있는 기기, **When** 「개인정보처리방침」을 누르면, **Then** 방침 URL이 기기 브라우저에서 열린다(「도움말·문의」는 지원 URL).
3. **Given** 브라우저 열기가 거부되는 상황, **When** 행을 누르면, **Then** 그 행 아래 빨간 한 줄에 「열지 못했다」와 그 URL이 보이고 앱은 계속 쓸 수 있다.
4. **Given** 실패 줄이 보이는 상태, **When** 같은 행을 다시 눌러 열기에 성공하거나 설정을 닫았다 다시 열면, **Then** 실패 줄이 사라진다.

---

### User Story 3 - 소유자가 스토어 데이터 선언을 채운다 (Priority: P2)

소유자가 선언 초안을 보고 Play 데이터 보안과 App Store App Privacy를 콘솔에 옮겨 적는다. 각 답에는 근거와 확신 표식이 붙어 있고, 확인할 수 없는 답은 미확인으로 표시돼 소유자가 판단한다.

**Why this priority**: 방침과 같은 사실을 말해야 하지만 콘솔 입력은 사람이 한다 — 문서가 정확하면 충분하다.

**Independent Test**: 선언 초안의 각 답이 방침의 해당 문장·설계문서 근거와 짝지어지는지, 초안의 URL이 앱·사이트의 URL과 같은지 본다.

**Acceptance Scenarios**:

1. **Given** 선언 초안, **When** Play 절을 읽으면, **Then** 「정확한 위치 — 수집함·공유 안 함·선택 사항·목적 앱 기능」과 그 밖 유형의 「수집 안 함」, 미확인 항목(일시 처리·전송 중 암호화)과 보수적 답이 있다.
2. **Given** 선언 초안, **When** App Store 절을 읽으면, **Then** 「Data Not Collected」와 그 근거(기기 안 처리·Apple이 모으는 것·보관하지 않는 IP)가 있다.
3. **Given** 선언 초안·앱·사이트, **When** URL을 대조하면, **Then** 셋이 같다.

---

### User Story 4 - 방침이 기대는 사실이 바뀌면 개발자가 바로 안다 (Priority: P2)

개발자가 분석·크래시 SDK를 더하거나, 앱에 새 외부 주소를 넣거나, 지오코딩을 다른 곳에서도 부르거나, 게시 워크플로의 자리표시자 검사를 빼면 기기 없는 테스트가 실패하고 「방침과 선언을 고쳐라」고 알린다.

**Why this priority**: 방침이 출시 뒤 조용히 거짓이 되는 것이 이 기능의 가장 큰 위험이다(원칙 V·허위 신고).

**Independent Test**: 위반 주입 — 각 사실을 하나씩 깨고 테스트가 실패하는지 본다.

**Acceptance Scenarios**:

1. **Given** 금지 목록의 SDK를 의존성에 더하면, **When** 테스트를 돌리면, **Then** 실패하고 방침·선언을 고치라는 메시지가 나온다.
2. **Given** 앱 소스에 허용 목록 밖의 외부 주소를 더하면, **When** 테스트를 돌리면, **Then** 실패한다(주석 안 주소는 세지 않는다).
3. **Given** 지오코딩 호출을 통로 밖에 하나 더 두면, **When** 테스트를 돌리면, **Then** 실패한다.
4. **Given** 게시 워크플로에서 자리표시자 검사를 빼거나 업로드 뒤로 옮기면, **When** 테스트를 돌리면, **Then** 실패한다.

---

### User Story 5 - iPhone 사용자가 위치 권한 창에서 사실을 본다 (Priority: P3)

iPhone 사용자가 위치 권한 창에서 「사진의 좌표를 Apple 지도 서비스에 보낸다」는 사실을 읽고 허용 여부를 정한다.

**Why this priority**: 방침과 권한 창이 같은 말을 해야 하지만, 이미 설정 대화상자에 같은 안내가 있고 반영은 다음 iOS 빌드부터다.

**Independent Test**: 설정 파일의 위치 문구를 계약 테스트로 본다.

**Acceptance Scenarios**:

1. **Given** 앱 설정, **When** iOS 위치 권한 문구를 읽으면, **Then** 「…바꾸는 데 위치를 씁니다. 이때 사진의 좌표를 Apple 지도 서비스에 보냅니다.」다.
2. **Given** 앱 설정, **When** 사진 권한 문구를 읽으면, **Then** 지금 문구 그대로다.

### Edge Cases

- 자리표시자 일부만 채우고 게시하면? → 남은 하나라도 있으면 게시가 실패한다.
- 기기에 브라우저가 없거나 열기가 거부되면? → 행 아래 보조 줄(US2-3). 앱이 멈추거나 죽지 않는다.
- 글꼴 2.0배에서 행 라벨·보조 줄이 겹치면? → 행이 줄 바꿈하고 겹치지 않는다(실기기).
- 게시 전에 앱 행을 누르면? → 브라우저는 열리지만 페이지가 없을 수 있다(게시 전 개발 중 상태 — 완료 전에 게시한다).
- 지오코딩이 꺼져 있는 사용자(「끔」 또는 위치 권한 없음)? → 좌표가 나가지 않는다 — 방침이 끄는 법으로 이것을 말한다.
- 사이트 원문만 바뀌는 커밋? → 게시 워크플로와 CI(jest — 사이트 대조 테스트)가 돌고, 네이티브 빌드는 돌지 않는다.
- 개발 환경(local)의 데스크톱 추론 서버 주소? → 소스에 상수 주소가 없고(환경 값, `local` 전용) 검사에 걸리지 않는다. 주소가 상수로 소스에 들어오면 외부 주소 검사가 실패해 다시 판단하게 한다.

## Requirements *(mandatory)*

### Functional Requirements

**사이트**

- **FR-001**: 저장소는 방침·지원 페이지 원문을 앱 코드와 같은 저장소의 전용 폴더에 한국어 정적 페이지로 둔다(방침, 지원, 두 페이지로 가는 첫 페이지).
- **FR-002**: 방침은 다음 절을 담는다: 한 줄 요약, 휴대폰 안에서 다루는 것(코드 리뷰 — 좌표 하나는 밖으로 나가므로 「만」을 뺐다), 휴대폰 밖으로 나가는 것(모듈 내려받기·장소 이름·운영체제 진단 보고), 제3자 제공·처리 위탁(없음), 보존과 삭제, 권한과 철회, 문의와 개인정보 보호 책임자, 시행일과 변경 이력(시행일·바뀐 요지를 쌓는 목록과 이전 원문을 볼 수 있는 저장소 기록 링크 — 판별 페이지는 두지 않는다).
- **FR-002a**: 방침의 문의 절은 「문의 메일의 주소와 내용은 답장에만 쓰고, 문의 처리가 끝나면 지체 없이 지운다」고 적는다 — 운영자가 개인정보를 받는 유일한 경로이며, 그 밖에 운영자가 받거나 보관하는 개인정보는 없다고 말한다.
- **FR-003**: 방침의 사실 문장은 각각 설계문서 §1의 근거([코드]·[문서])가 있어야 하고, 근거가 없는 것은 단정하지 않는다(예: 백업 포함 여부는 「포함될 수 있다」, 안드로이드 지오코더 제공자는 「대개 Google」).
- **FR-004**: 방침의 장소 이름 문장은 앱 설정 대화상자의 안내(「좌표를 기기의 지도 서비스에 물어봐요」)와 같은 사실을 말하고, 끄는 법을 적는다 — 확실한 길은 설정 「장소 이름으로 보기」 → 「끔」이다. 위치 권한 거부는 「자동」(기본값)에서만 끄는 길이다(iOS는 「켬」이면 위치 권한과 무관하게 좌표를 보낸다 — `expo-location` iOS가 권한을 보지 않는다, 구현 중 소스로 확인).
- **FR-005**: 지원 페이지는 문의 메일, 자주 묻는 것 다섯(첫 실행 약 2.0GB 내려받기, 자동 쓰기가 늦거나 안 될 때, 앱을 지우면 일기도 사라짐, 일기는 휴대폰 안에서 씀, 장소 이름 끄는 법), 방침 링크를 담는다. 답은 저장소에 실측된 사실만 쓰고 자동 쓰기 시각을 약속하지 않는다.
- **FR-006**: 문의 메일·운영자 이름·시행일은 정해진 자리표시자로 둔다. 기기 없는 테스트는 자리표시자가 있어도 통과한다.

**게시**

- **FR-007**: 게시 워크플로는 기본 브랜치에서 사이트 폴더가 바뀔 때와 수동 실행으로만 돈다.
- **FR-008**: 게시 워크플로는 비밀을 쓰지 않고, 읽기와 Pages 게시에 필요한 권한만 가진다.
- **FR-009**: 게시 워크플로는 업로드 전에 사이트 안의 자리표시자를 검사해 하나라도 남으면 실패하고 남은 것을 알린다.
- **FR-010**: 게시 워크플로는 플랫폼 제공자(GitHub)의 공식 Action만, 버전을 고정해 쓴다.
- **FR-011**: 자리표시자 값(문의 메일·운영자 이름·시행일)은 소유자가 정하고, 저장소 설정에서 Pages를 켜는 일은 소유자가 한다. 첫 게시는 소유자가 채운 원문을 확인한 뒤에만 하며, 게시와 두 URL 확인은 이 기능의 완료 조건이다.

**앱**

- **FR-012**: 설정 「정보」 묶음은 버전 다음에 「개인정보처리방침」과 「도움말·문의」 두 행을 서체 라이선스보다 앞에 둔다. 두 행은 다른 이동 행과 같은 끝 표시(›)를 쓴다.
- **FR-013**: 두 행을 누르면 기기의 브라우저로 각각 방침·지원 URL을 연다. 두 URL의 정의는 앱 안에 한 곳뿐이고 화면은 URL을 모른다(조립부가 여는 동작을 넘긴다).
- **FR-014**: 브라우저 열기가 실패하면 그 행 아래 빨간 보조 줄에 열지 못했다는 문구와 URL을 보이고, 다시 눌러 성공하거나 설정을 다시 열면 지운다.
- **FR-015**: 브라우저 여는 통로는 `react-native`를 호출 시점에 읽는다(동적 `import` 금지 — 066).
- **FR-016**: 새 화면 문구는 한국어 카탈로그에 두고 062 골든의 「골든 이후 더한 것」에 올린다.
- **FR-017**: 설정의 다른 묶음·행(배터리·권한 포함)은 바꾸지 않는다.

**권한 문구**

- **FR-018**: iOS 위치 권한 문구는 「사진에 담긴 장소를 사람이 읽을 수 있는 이름으로 바꾸는 데 위치를 씁니다. 이때 사진의 좌표를 Apple 지도 서비스에 보냅니다.」다. 사진 권한 문구는 바꾸지 않는다.

**선언 초안**

- **FR-019**: 저장소는 Play 데이터 보안과 App Store App Privacy 답변 초안 문서를 두고, 각 답에 근거와 확신 표식을 단다. 확인할 수 없는 답은 미확인으로 표시하고 보수적 답을 함께 적는다.
- **FR-020**: Play 초안은 정확한 위치를 「수집함·공유 안 함·선택 사항·목적 앱 기능」으로, 그 밖 유형을 「수집 안 함」으로 답한다. App Store 초안은 「Data Not Collected」로 답한다. 두 초안 모두 방침·지원 URL을 적는다.

**사실 잠금**

- **FR-021**: 기기 없는 테스트가 앱 안 URL 정의 ↔ 사이트 페이지 존재 ↔ 지원 페이지의 방침 링크 ↔ 선언 초안의 URL을 대조한다.
- **FR-022**: 기기 없는 테스트가 방침이 기대는 코드의 사실을 잠근다: 앱에 실리는 의존성(`dependencies` — 개발 도구는 앱에 실리지 않아 보지 않는다)에 금지 목록(분석·크래시·광고·원격 푸시 서비스 SDK)이 없다, 푸시 토큰 호출이 없다(`expo-notifications`는 로컬 알림에만 쓰며 이 규칙이 그것을 지킨다), 앱 소스의 외부 주소는 허용 목록(모듈 내려받기 호스트, 이유가 붙은 예외)뿐이다(주석 제외), 지오코딩 호출은 정해진 통로 한 곳뿐이다, 기기의 현재 위치를 읽는 호출과 주소 문자열 지오코딩이 없다(코드 리뷰). 실패 메시지는 방침과 선언을 고치라고 말하고, 이 테스트가 소스만 본다는 범위를 이름이나 주석에 적는다.
- **FR-022a**: 외부 전송 목록은 저장소 안에 한 곳뿐이고 항목마다 식별자·이유·근거 자리(코드 위치 또는 플랫폼 문서)를 갖는다 — 모듈 내려받기(외부 주소 허용 목록과 같은 호스트), 장소 이름(지오코딩 통로), 운영체제 진단 보고(앱 코드가 아니라 플랫폼 — 이유와 함께). 기기 없는 테스트가 방침 원문에서 같은 식별자 표식이 붙은 절을 항목마다 정확히 하나 찾고, 목록에 없는 표식이 방침에 있으면 실패한다. 문장 내용은 대조하지 않는다.
- **FR-023**: 기기 없는 테스트가 게시 워크플로의 계약(FR-007~FR-010)을 잠근다.
- **FR-024**: 각 방어(FR-021~FR-023, FR-018 문구)는 위반 주입으로 실제로 실패하는 것을 한 번씩 확인한다.

### Key Entities

- **방침 페이지**: 절 여덟, 사실 문장(각각 근거와 짝), 자리표시자 셋, 변경 이력(시행일·요지 — 첫 판은 한 줄).
- **지원 페이지**: 문의 메일, 자주 묻는 것 다섯, 방침 링크.
- **정책 링크**: 방침 URL과 지원 URL — 앱·사이트·선언 초안이 같은 값을 쓴다.
- **선언 초안의 답**: 스토어 · 질문 · 답 · 근거 · 확신 표식(문서/코드/미확인).
- **사실 잠금 목록**: 금지 SDK 목록, 외부 주소 허용 목록(주소·이유), 지오코딩 통로의 자리, 외부 전송 목록(식별자·이유·근거 — 방침의 표식과 짝).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 방침의 사실 문장 100%가 설계문서의 근거와 짝지어진다(근거 없는 단정 0건 — 원문 검토로 확인).
- **SC-002**: 설정에서 방침·문의 페이지까지 한 번 누름으로 닿는다(실기기).
- **SC-003**: 자리표시자가 하나라도 남은 원문은 게시되지 않는다(위반 주입으로 확인).
- **SC-004**: 방침이 기대는 사실을 하나씩 깨는 위반 주입이 모두(100%) 테스트 실패로 잡힌다.
- **SC-004a**: 외부 전송 목록과 방침의 표식이 어긋나는 경우가 0건이다(목록에만·방침에만 있는 항목 모두 테스트 실패).
- **SC-005**: 앱·사이트·선언 초안의 URL이 서로 다른 경우가 0건이다.
- **SC-006**: 게시 뒤 두 URL이 열리고, 실기기의 설정 두 행에서 그 페이지가 열린다(완료 처리 전에 확인).

## Assumptions

- 저장소 `mrtint/alpharium`이 퍼블릭으로 남고, URL은 `https://mrtint.github.io/alpharium/privacy/`·`…/support/`다(옛 이름이 URL에 남는 것은 받아들였다).
- 사이트는 빌드 도구 없이 손으로 쓴 정적 페이지다.
- 지원 페이지의 자주 묻는 것은 AGENTS에 실측된 사실(약 2.0GB, 배터리 「제한 없음」, 저전력 모드, 앱을 지우면 함께 지워짐)만 쓴다.
- 백업 포함 여부·안드로이드 지오코더 제공자·지오코더의 전송 암호화는 미실측이며, 방침·초안은 그 사실대로 단정하지 않는다.
- 실기기 확인은 다른 세션이 기기를 쓰지 않을 때 소유자에게 묻고 한다(`pm clear`·설치·`run-as` 쓰기 없음). 게시 전 확인은 브라우저가 열리는 것까지이고(페이지는 404일 수 있다), 게시 뒤 한 번 더 페이지가 열리는 것을 본다.
- 권한 문구 변경은 네이티브 입력이라 다음 iOS 빌드부터 반영되고, 이 기능은 iOS 빌드를 하지 않는다.
- 범위 밖: 백업 규칙·유실 안내 구현, 라이선스 고지, 크래시 SDK, 콘솔 입력 자체, 다국어(화면 언어는 한국어 하나).
