- 「자동으로 쓰기」가 켜졌을 때만 그 아래 펼쳐지는 「매일 쓰는 시각」 행(값 「오후 10시쯤」 꼴)과 시 격자 대화상자(보드 `6f`).

- 055가 남긴 두 결함 고침: 토글 꺼짐 손잡이가 지면 위에서 안 보이는 것(T2), 설정을 열 때마다 「설정을 읽는 중…」이 보이는 것(T3).

**이 조각이 걷는 것**:

- 「일기」 묶음 토글 아래 임시로 있던 옛 0–23 시각 목록(「언제쯤 쓸까」 + 근사치 안내 문장)과 옛 장소명 카드(055 FR-019).
- 옛 시각 목록 아래의 알림 권한 거부 안내(020 N8, T4).

**이 조각이 만들지 않는 것** (C7):

- 자동 쓰기 규칙 변경(재료 0·사진 권한 없음 건너뜀, 앱을 열면 쓰는 중, 알림 문구 — §3.3), 「이 휴대폰」(§3.4), 버전 7번 탭·개발자 화면(§3.5).
- 자동 생성 판정의 시도 창(3시간)·날 고르기 규칙(사흘·정오) 변경 — 재지 않은 값이다.
- 시간대 고르기(보드: 시간대는 고를 수 없음), 분 단위 시각.
- 새 네이티브 모듈.

## Clarifications

### Session 2026-10-01

- Q: 기본값 오후 10시(22)를 어디까지 적용하나? → A: 설정 파일이 없을 때와 파일의 시각 칸이 0–23 정수가 아닐 때(깨짐)만 22다. 이미 저장된 값(옛 기본값 7 포함)은 바꾸지 않는다 — 사용자가 고른 7과 옛 기본값 7을 구분할 길이 없다(FR-005).
- Q: 오전 목표 시각이면 실제로는 어제를 쓰는데 미리보기 「그날 일기를 써요」를 어떻게 하나? → A: 고른 시가 0–11시면 「어제 일기를 써요」, 12–23시면 보드 원문 「그날 일기를 써요」다. 판정(사흘·정오)은 바꾸지 않고 문구가 사실대로 말한다(FR-014).
- Q: 12/24시간 형식과 시간대 도시 이름을 무엇으로 읽나? → A: 새 네이티브 모듈 없이 읽는다. 형식은 이 휴대폰 언어 설정(로케일)의 시간 주기를 따르고 읽지 못하면 12시간이다. 도시 이름은 사람이 못 박은 작은 표(예: 서울)로 옮기고 표에 없으면 시간대 식별자의 도시 부분을 그대로 쓴다. GMT 차이는 기기의 시차에서 계산한다. 기기의 「24시간 형식」 스위치는 읽지 못한다(미확인 잔여, FR-008·FR-038).
- Q: 시각 대화상자(저장)와 장소 대화상자(바로 적용)의 확정 방식이 다른 것을 그대로 두나? → A: 둘 다 바로 적용한다. 시각 대화상자도 시 칸을 누르면 바로 저장되고 닫힌다. 「저장」 버튼은 없고 「취소」 하나만 전체 폭으로 둔다(보드 `6f` ⑤를 뒤집는다, FR-015~FR-017).
- Q: 보드 「오늘 그 시각이 이미 지났으면 내일부터 적용」 — 판정을 바꾸나? → A: 바꾸지 않는다. 저장 시각의 시도 창(3시간)이 지금 밖이면 자연히 다음 창부터이고, 지금이 창 안이면 오늘도 쓸 수 있다. 「언제부터」 필드를 설정 파일에 넣지 않는다(020 S7·D3).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 자동으로 쓰는 시각을 시 단위로 고른다 (Priority: P1)

자동으로 쓰기를 켜면 바로 아래에 「매일 쓰는 시각」 행이 펼쳐지고 값은 「오후 10시쯤」처럼 보인다. 행을 누르면 시 격자 대화상자가
열리고, 오전/오후를 바꾸면 미리보기 문장의 시각이 바로 바뀐다. 시 칸을 누르면 바로 저장되고 대화상자가 닫히며 행 값이 바뀌고 다음 자동
쓰기가 새 시각으로 다시 잡힌다.

**Why this priority**: 지금 설정의 시각 선택은 055가 임시로 남긴 24칸 목록이다. 자동 쓰기를 쓰는 사용자가 매번 마주치는 자리이고, 이 조각의
본 목적이다.

**Independent Test**: 자동으로 쓰기를 켠 설정에서 시각 행을 눌러 다른 시 칸을 누른 뒤, 행 값과 다시 연 대화상자의 선택 칸이 새 시인지 본다.

**Acceptance Scenarios**:

1. **Given** 자동으로 쓰기가 꺼져 있다, **When** 설정을 보면, **Then** 「매일 쓰는 시각」 행이 없다(접혀 있다).
2. **Given** 자동으로 쓰기가 꺼져 있다, **When** 토글을 켜면, **Then** 토글 바로 아래에 「매일 쓰는 시각」 행이 높이 0에서 44로 펼쳐지고 값은 저장된 시각(처음이면 「오후 10시쯤」)이다.
3. **Given** 시각을 오전 7시로 저장해 둔 채 자동으로 쓰기를 끈다, **When** 다시 켜면, **Then** 행이 다시 펼쳐지고 값은 「오전 7시쯤」이다(끈 동안에도 시각을 기억한다).
4. **Given** 시각 행, **When** 누르면, **Then** 「매일 쓰는 시각」 대화상자가 열리고 제목 아래에 이 휴대폰의 시간대 줄, 지금 저장된 시가 선택된 격자, 미리보기 문장, 「취소」가 있다(「저장」 버튼은 없다).
5. **Given** 12시간 형식에서 대화상자가 열렸다(저장된 시 오후 10시), **When** 「오전」을 누르면, **Then** 오전 칸이 검은 면이 되고 격자의 선택은 「10」 그대로이며 미리보기는 「매일 오전 10시쯤…」이다.
6. **Given** 저장된 시가 오후 10시인 대화상자, **When** 미리보기를 보면, **Then** 「매일 오후 10시쯤 그날 일기를 써요. 이미 쓴 날은 건너뛰어요.」다. 「오전」을 누르면 「매일 오전 10시쯤 어제 일기를 써요. 이미 쓴 날은 건너뛰어요.」로 바뀐다.
7. **Given** 대화상자, **When** 저장된 시와 다른 시 칸을 누르면, **Then** 그 시가 바로 저장되고 대화상자가 닫히며 행 값이 새 시각이고 다음 자동 쓰기 예약이 새 시각으로 다시 잡힌다.
8. **Given** 대화상자에서 오전/오후를 바꿨다, **When** 시 칸을 누르지 않고 「취소」·바깥 누름·시스템 뒤로 중 하나로 닫으면, **Then** 행 값과 저장된 시각은 그대로다. 다시 열면 저장된 시가 선택돼 있다.
9. **Given** 대화상자, **When** 저장된 시와 같은 칸(오전/오후까지 같은)을 누르면, **Then** 대화상자가 닫히기만 하고 저장·다시 예약을 하지 않는다.

### User Story 2 - 장소 이름으로 볼지 고른다 (Priority: P1)

「장소 이름으로 보기」 행은 자동으로 쓰기와 상관없이 늘 보이고 값은 고른 갈래 이름이다. 누르면 세 갈래 대화상자가 열리고, 칸을 누르면 바로
적용되며 닫힌다. 「켬」을 고르면 닫힌 직후 위치 권한 요청이 뜬다.

**Why this priority**: 옛 장소명 카드도 055가 임시로 남긴 모양이다. 시각 행과 같은 묶음에 같은 행 모양으로 서야 설정 지면이 보드 `6c`가 된다.

**Independent Test**: 장소 이름 행을 눌러 「끔」을 고르고, 대화상자가 닫히며 행 값이 「끔」인지, 설정을 닫았다 다시 열어도 「끔」인지 본다.

**Acceptance Scenarios**:

1. **Given** 설정, **When** 「일기」 묶음을 보면, **Then** 자동으로 쓰기가 켜졌든 꺼졌든 「장소 이름으로 보기」 행이 있고 값은 지금 갈래(처음이면 「자동」)와 › 다.
2. **Given** 장소 이름 행, **When** 누르면, **Then** 「장소 이름으로 보기」 대화상자가 열리고 세 칸(「자동」·「켬」·「끔」과 각 설명 줄), 지도 고지 한 줄, 「취소」가 있으며 지금 갈래의 칸이 선택돼 있다.
3. **Given** 대화상자가 열렸다, **When** 지금과 다른 칸을 누르면, **Then** 그 값이 바로 저장되고 대화상자가 닫히며 행 값이 바뀐다.
4. **Given** 위치 권한이 없는 기기, **When** 「켬」을 고르면, **Then** 대화상자가 닫힌 직후 안드로이드 위치 권한 요청이 뜬다. 거부해도 값은 「켬」으로 남고 권한 묶음의 위치 행은 「허용 안 함」이다.
5. **Given** 위치 권한이 이미 허용된 기기, **When** 「켬」을 고르면, **Then** 권한 요청 창이 뜨지 않는다.
6. **Given** 대화상자가 열렸다, **When** 「취소」·바깥 누름·시스템 뒤로 중 하나로 닫으면, **Then** 값은 그대로다.

### User Story 3 - 설정이 바로 보이고 토글이 꺼진 것도 보인다 (Priority: P2)

설정을 두 번째로 열 때부터는 「설정을 읽는 중…」 없이 바로 보인다. 자동으로 쓰기 토글이 꺼졌을 때 손잡이가 회색 지면 위에서도 또렷하다.

**Why this priority**: 055 실기기 확인에서 남은 두 결함이다(055 미확인 잔여). 기능은 되지만 열 때마다 깜빡이고, 꺼진 토글이 꺼진 것으로 읽히지 않는다.

**Independent Test**: 설정을 열고 닫은 뒤 다시 열어 「설정을 읽는 중…」이 보이지 않는지, 토글을 끈 채 손잡이가 눈으로 구분되는지 본다.

**Acceptance Scenarios**:

1. **Given** 이번 실행에서 설정을 한 번 열었다 닫았다, **When** 다시 열면, **Then** 「설정을 읽는 중…」 없이 토글·시각 행·장소 이름 행이 바로 마지막 값으로 보인다.
2. **Given** 설정에서 시각이나 장소 갈래를 바꾸고 닫았다, **When** 다시 열면, **Then** 바꾼 값이 보인다.
3. **Given** 앱을 새로 열고 설정을 처음 연다, **When** 값을 아직 읽지 못했으면, **Then** 모르는 값을 기본값으로 그리지 않는다(읽는 중 표시를 둔다).
4. **Given** 자동으로 쓰기가 꺼져 있다, **When** 토글을 보면, **Then** 회색 면 위 왼쪽 손잡이가 면과 뚜렷이 구분되는 진한 색이다.

### Edge Cases

- **자정 넘는 시각**: 오후 11시를 고르면 시도 창이 자정을 넘는다(23시·0시·1시) — 판정은 이미 자정을 넘겨 계산한다(020). 이 조각은 그 판정을 바꾸지 않는다.
- **12시 표기**: 0시는 「오전 12시쯤」, 12시는 「오후 12시쯤」이다. 12시간 격자의 「12」 칸은 오전에서 0시, 오후에서 12시다.
- **저장 실패**: 설정 파일을 쓰지 못하면 행 값은 바꾸지 않는다(저장된 값과 화면이 어긋나지 않게, FR-018).
- **시 칸 연타**: 칸을 빠르게 두 번 눌러도 저장·다시 예약은 한 번이다(대화상자는 첫 누름에 닫힌다).
- **대화상자를 연 채 자동으로 쓰기를 끌 수 없다**: 대화상자가 지면을 덮어 토글을 누를 수 없다.
- **장소 대화상자에서 지금 값과 같은 칸을 누름**: 대화상자가 닫히기만 한다(저장·권한 요청을 하지 않는다).
- **글꼴 크기 2.0배**: 시각 행의 라벨·값이 한 줄에 다 들어가지 않으면 줄이 바뀌되 잘리지 않는다(053 교훈). 격자 칸의 숫자는 칸 안에 들어간다.
- **설정을 연 채 앱이 백그라운드로 갔다 돌아왔다**: 시각·장소 값은 그대로다(권한 꼬리표만 다시 읽는다, 055).
- **시간대 이름을 읽지 못함**: 시간대 줄을 그리지 않는다(지어내지 않는다).

## Requirements *(mandatory)*

### Functional Requirements

**「매일 쓰는 시각」 행 (보드 `6c` ③)**

- **FR-001**: 「일기」 묶음에서 「자동으로 쓰기」 토글 바로 아래에 「매일 쓰는 시각」 행을 둔다. 자동으로 쓰기가 켜져 있을 때만 보이고, 꺼지면 접힌다.
- **FR-002**: 켜면 행이 높이 0에서 행 높이(기본 글꼴에서 44, 글꼴이 커져 행이 더 높으면 그 높이)로 200ms 동안 펼쳐지고, 끄면 같은 시간에 접힌다. 접힌 행은 누를 수 없고 스크린리더에 읽히지 않는다.
- **FR-003**: 자동으로 쓰기를 꺼도 저장된 시각은 지우지 않는다. 다시 켜면 그 시각이 보인다.
- **FR-004**: 행 값은 저장된 시(0–23)를 기기의 시간 형식으로 「쯤」을 붙여 보인다 — 12시간 형식이면 「{오전|오후} {h}시쯤」(h는 1–12), 24시간 형식이면 「{h}시쯤」(h는 0–23). 끝에 › 다. 분은 보이지 않는다.
- **FR-005**: 설정 파일이 없거나 파일의 시각 칸이 0–23 정수가 아니면 시각은 오후 10시(22)다. 이미 저장된 시각(옛 기본값 7 포함)은 바꾸지 않는다.
- **FR-006**: 행을 누르면 「매일 쓰는 시각」 대화상자가 열린다.

**「매일 쓰는 시각」 대화상자 (보드 `6f`)**

- **FR-007**: 대화상자는 050의 틀이다 — 2 두께 본문색 테두리, 가운데 정렬, 좌우 여백 20, 안쪽 여백 24, 요소 사이 16. 바깥 누름·시스템 뒤로는 취소다.
- **FR-008**: 제목은 「매일 쓰는 시각」(20/700)이고, 그 아래(간격 6)에 시간대 줄 「이 휴대폰의 시간대 · {city} ({gmt})」(13, 보조색)이 있다. 시간대는 이 휴대폰의 것이고 고를 수 없다. {city}는 시간대 식별자를 사람이 못 박은 도시 이름 표로 옮긴 것(예: 서울)이고 표에 없으면 식별자의 도시 부분(밑줄은 띄어쓰기)이다. {gmt}는 기기의 지금 시차로 「GMT+9」·「GMT-3:30」·「GMT」 꼴이다. 시간대 식별자를 읽지 못하면 이 줄을 그리지 않는다.
- **FR-009**: 12시간 형식에서만 오전/오후 칸 한 줄이 있다 — 2 두께 본문색 테두리 안에 두 칸(높이 40, 15/600), 선택한 쪽은 본문색 면 + 바탕색 글자(15/800).
- **FR-010**: 오전↔오후를 바꿔도 격자의 선택 칸(1–12 중 하나)은 그대로다 — 오후 10 → 오전 10.
- **FR-011**: 12시간 형식의 격자는 4열×3행, 칸 순서 「12」, 「1」…「11」이다. 24시간 형식의 격자는 6열×4행, 「0」…「23」이고 오전/오후 칸이 없다.
- **FR-012**: 격자 칸은 높이 52, 1 두께 구분선 칸막이, 숫자 18/600 고정폭 숫자다. 선택한 칸은 accent 면 + accent 위 글자색(오프화이트, 043) 글자(18/800)다.
- **FR-013**: 대화상자가 열리면 저장된 시가 선택돼 있다(12시간 형식이면 오전/오후도 그에 맞게).
- **FR-014**: 격자 아래 미리보기 문장(13, 줄높이 1.5, 보조색)은 지금 선택 상태의 시로 「매일 {오전|오후} {h}시쯤 {그날|어제} 일기를 써요. 이미 쓴 날은 건너뛰어요.」다(24시간 형식이면 「매일 {h}시쯤 …」). 시가 12–23시면 「그날」, 0–11시면 「어제」다(오전 시도 창에서는 사흘 범위에 오늘이 없어 어제를 쓴다, 020·049). 오전/오후를 바꾸면 바로 바뀐다.
- **FR-015**: 맨 아래 「취소」(테두리, 높이 48, 전체 폭) 하나다. 「저장」 버튼은 없다(Clarifications — 보드 `6f` ⑤를 뒤집는다).
- **FR-016**: 시 칸을 누르면 대화상자가 바로 닫히고, 그 칸과 지금 오전/오후가 정하는 시가 저장된 시와 다르면 저장한 뒤 다음 자동 쓰기 예약을 새 시각으로 다시 잡으며(020 순서: 저장 → 다시 예약), 저장이 끝나면 행 값을 바꾼다. 같으면 닫기만 한다. 오전/오후 칸은 선택만 바꾸고 저장하지 않는다.
- **FR-017**: 「취소」·바깥 누름·시스템 뒤로는 저장하지 않고 닫는다. 다음에 열면 저장된 시가 선택돼 있다(바꾸다 만 오전/오후는 남지 않는다).
- **FR-018**: 시각 저장이 실패하면 행 값을 바꾸지 않고 다시 예약도 하지 않는다. 장소 갈래 저장이 실패해도 행 값을 바꾸지 않고 위치 권한을 요청하지 않는다.

**「장소 이름으로 보기」 행 (보드 `6c` 장소 이름)**

- **FR-019**: 「일기」 묶음의 맨 아래(시각 행이 있으면 그 아래)에 「장소 이름으로 보기」 행을 늘 둔다. 값은 지금 갈래 이름(「자동」·「켬」·「끔」)과 › 다. 저장한 적이 없으면 「자동」이다.
- **FR-020**: 행을 누르면 「장소 이름으로 보기」 대화상자가 열린다.

**「장소 이름으로 보기」 대화상자 (보드 `6l`)**

- **FR-021**: 대화상자는 FR-007과 같은 틀이다. 제목 「장소 이름으로 보기」(20/700).
- **FR-022**: 칸은 위에서부터 「자동」·「켬」·「끔」 셋이고 칸 사이 8이다. 각 칸은 안쪽 여백 12·14에 왼쪽 12×12 네모 표식, 오른쪽에 이름(16)과 설명 줄(13, 줄높이 1.45, 보조색, 간격 3)이다. 선택한 칸은 2 두께 본문색 테두리 + accent로 채운 표식 + 이름 16/800, 아닌 칸은 1 두께 구분선 테두리 + 옅은 보조색 테두리만 있는 표식 + 이름 16/600이다.
- **FR-023**: 대화상자가 열리면 지금 갈래의 칸이 선택돼 있다.
- **FR-024**: 칸을 누르면 그 갈래가 바로 저장되고 대화상자가 닫히며 행 값이 바뀐다(저장 버튼이 없다). 지금 갈래와 같은 칸이면 닫기만 한다.
- **FR-025**: 「켬」을 새로 고르면 대화상자가 닫힌 직후 위치 권한을 요청한다(이미 허용돼 있으면 OS가 창을 띄우지 않는다). 거부돼도 값은 「켬」으로 남는다. 「자동」·「끔」은 권한을 요청하지 않는다.
- **FR-026**: 칸 목록 아래에 지도 고지 한 줄 「좌표를 기기의 지도 서비스에 물어봐요.」(13, 보조색)를 늘 둔다(017 FR-006을 해요체로, T5).
- **FR-027**: 맨 아래 「취소」(테두리, 높이 48, 전체 폭). 「취소」·바깥 누름·시스템 뒤로는 바꾸지 않고 닫는다.
- **FR-028**: 바꾼 갈래는 다음 일기부터 적용된다. 이미 쓴 일기는 다시 쓰지 않는다.

**055가 남긴 것 (T2·T3)**

- **FR-029**: 「자동으로 쓰기」 토글이 꺼졌을 때 손잡이는 회색 면(`neutral-200`)과 뚜렷이 구분되는 진한 색이다(면 대비 3:1 이상 — 비텍스트 UI 요소 기준). 켜짐 모양(accent 면 + 바탕색 손잡이)은 그대로다. 055 Clarification의 「꺼짐 = 바탕색 손잡이」를 뒤집는다.
- **FR-030**: 자동 쓰기 설정(켜짐·시각)과 장소 갈래는 설정 겹보다 오래 사는 자리가 앱 실행마다 한 번 읽어 들고, 설정에서 바꿀 때마다 그 값을 갱신한다. 그래서 같은 실행에서 설정을 다시 열면 「설정을 읽는 중…」 없이 바로 보인다.
- **FR-031**: 아직 한 번도 읽지 못했으면 설정은 지금처럼 읽는 중 표시를 둔다(모르는 값을 기본값으로 그리지 않는다, 원칙 V).

**걷는 것 (T4)**

- **FR-032**: 옛 시각 목록(「언제쯤 쓸까」 제목, 근사치 안내 문장, 24칸)과 옛 장소명 카드를 설정에서 걷는다. 「쯤」의 근사치 뜻은 행 값과 미리보기 문장이 맡는다.
- **FR-033**: 옛 시각 목록 아래의 알림 권한 거부 안내를 걷는다 — 권한 묶음의 알림 행 「허용 안 함」이 같은 사실을 말한다.

**문구 (C4)**

- **FR-034**: 문구는 보드 「KO 문자열 — 설정 · 개발자」 표의 원문 그대로다: `settings.autoWriteTime` 「매일 쓰는 시각」, `settings.autoWriteTime.value12` 「{오전|오후} {h}시쯤」, `settings.autoWriteTime.value24` 「{h}시쯤」, `settings.placeNames` 「장소 이름으로 보기」, `time.title` 「매일 쓰는 시각」, `time.tz` 「이 휴대폰의 시간대 · {city} ({gmt})」, `time.am`/`time.pm` 「오전」/「오후」, `time.preview` 「매일 {오전|오후} {h}시쯤 그날 일기를 써요. 이미 쓴 날은 건너뛰어요.」, `time.cancel` 「취소」(`time.save`는 쓰지 않는다 — FR-015), `place.title` 「장소 이름으로 보기」, `place.auto`/`place.auto.desc` 「자동」/「위치 권한이 있으면 이름으로, 없으면 비워 둬요」, `place.on`/`place.on.desc` 「켬」/「다닌 자리를 숫자 대신 이름으로 보여줘요」, `place.off`/`place.off.desc` 「끔」/「장소 이름을 옮기지 않아요」, `place.cancel` 「취소」. 보드 표에 없는 문장은 둘이다 — 지도 고지(FR-026, 017 문장을 해요체로)와 오전 시의 미리보기(FR-014, 보드 `time.preview`의 「그날」을 「어제」로 바꾼 것).
- **FR-035**: 시각 문구는 정확한 시각을 약속하지 않는다 — 「정각」·「매일 N시에」처럼 「쯤」 없는 표기를 두지 않는다(020 FR-002).

**경계 (헌법)**

- **FR-036**: 새 네이티브 모듈을 들이지 않는다(분해 설계 S3 — 시각 고르기는 직접 그린 격자다).
- **FR-037**: 화면 계층은 판정하지 않는다 — 시 표기·격자 칸·미리보기 문장·시간대 줄은 화면 밖 순수 판정에서 오고 화면은 그것을 그린다.
- **FR-039**: 대화상자가 화면보다 높아지면(글꼴 2.0배 등) 상태 표시줄·내비게이션 바 안쪽(안전 영역 + 바깥 여백 20)에 머물고, 제목·부제(시간대 줄) 아래 본문이 스크롤된다. 050 공용 대화상자 틀(`DismissibleDialog`·`ConfirmDialog`)에 적용한다(2026-10-02 실기기 확인 뒤 저장소 소유자 지시 — 이 조각의 장소 대화상자가 넘쳤다).
- **FR-038**: 시간 형식은 이 휴대폰 언어 설정(로케일)의 기본 시간 주기를 따른다 — 12시간 주기면 12시간 형식, 24시간 주기면 24시간 형식이다. 읽지 못하면 12시간 형식이다.

### Key Entities

- **자동 쓰기 설정**: 켜짐 여부와 목표 시(0–23). 기존 파일 그대로이고 필드를 늘리지 않는다(020 S7). 바뀌는 것은 파일이 없거나 시각 칸이 깨졌을 때의 시(7 → 22)뿐이다.
- **장소 갈래**: 「자동」·「켬」·「끔」. 기존 파일 그대로다.
- **시간 형식**: 12시간/24시간. 기기에서 읽고 저장하지 않는다.
- **시간대 표시**: 도시 이름과 GMT 차이. 기기에서 읽고 저장하지 않는다.
- **대화상자 안의 오전/오후 선택**: 대화상자 로컬 상태. 시 칸을 누르기 전에는 어디에도 남지 않는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 자동으로 쓰기를 켜고 끌 때 시각 행이 펼쳐지고 접히는 움직임이 실기기 녹화에서 끊김 없이 보인다(1회 이상).
- **SC-002**: 시각 대화상자에서 다른 시 칸을 눌러 바꾸면 행 값이 바뀌고, 다음 자동 쓰기 예약이 다시 잡힌 것이 기기에서 확인된다(1회 이상).
- **SC-003**: 오전/오후를 바꾼 뒤 「취소」·바깥 누름·시스템 뒤로 세 경로 모두에서 저장된 시각이 바뀌지 않는다(3/3).
- **SC-004**: 두 대화상자 모두 칸 한 번으로 값이 바뀌고 닫힌다 — 저장 버튼이 없다(장소 3갈래 모두, 시각 1회 이상).
- **SC-005**: 설정·대화상자 문구가 보드 원문과 글자 단위로 100% 같다(보드 표에 없는 두 문장 — 지도 고지·오전 미리보기 — 은 스펙 원문과 같다).
- **SC-006**: 같은 실행에서 설정을 두 번째로 열면 「설정을 읽는 중…」이 보이지 않는다 — 실기기 녹화 프레임에서 0프레임.
- **SC-007**: 토글 꺼짐 손잡이와 면의 대비가 3:1 이상이다.
- **SC-008**: 설정에서 옛 24칸 시각 목록·옛 장소명 카드·알림 거부 안내가 0개다.

## Assumptions

- **보드 메모의 「오늘 그 시각이 이미 지났으면 내일부터 적용」**: 자동 생성 판정(목표 시각부터 3시간 창, 020)을 바꾸지 않는다(Clarifications). 판정 변경은 §3.3·범위 밖이다.
- **「쯤」의 폭**: 실제 시도 창은 목표 시각부터 3시간이다(020 판정, 바꾸지 않는다). 「쯤」은 그 창과 OS의 지연(019 실측: 배터리 예외가 있으면 +10~32분, 없으면 하루 넘게)을 함께 뜻한다.
- **움직임 시간**: 펼침 200ms는 보드 값이다.
- **기기 24시간 스위치**: 새 네이티브 모듈 없이는 기기 설정의 「24시간 형식」 스위치를 읽을 수 없다. 로케일이 12시간인 기기에서 스위치를 24시간으로 켠 사용자는 12시간 형식을 본다(미확인 잔여).
- **실기기 검증**: dev(debug) 빌드 1회. release 검증은 하지 않는다(AGENTS 「테스트」, C2).
- **Maestro**: 이 조각의 흐름 `settings-time-place.yml`을 새로 써서 실기기 실행기 등록 목록(`FLOWS`)에 넣는다(C8). 시각·장소 자리를 지나던 `scheduled-diary-notification.yml`(「매일 (오전 )?7시」 단언)과 `diary-body-screen.yml`(`geocoding-*` 칸)은 해당 단계만 새 자리로 고치고, 둘 다 다른 stale 단계 때문에 지금처럼 `FLOWS` 밖에 둔다(research R10).
