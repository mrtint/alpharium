## Clarifications

### Session 2026-10-06

- Q: 기기 언어는 언제 읽어 화면 언어를 정하는가? → A: 앱 프로세스가 시작될 때(첫 사용 시점) 한 번 정하고 그 프로세스 동안 유지한다. 기기 언어 변경은 프로세스가 다시 뜨는 경로로만 반영한다.
- Q: 앱 안에 언어 선택 설정을 두는가? → A: 두지 않는다. 안드로이드 시스템 설정의 앱별 언어 목록 선언도 이번 판에는 하지 않는다.
- Q: 기기 언어 태그를 지원 목록에 어떻게 맞추는가? → A: 언어 부분만 대소문자 무시로 비교한다(`ko-KR`·`ko`·`KO` → 한국어). 선호 순서대로 첫 일치, 없으면 기본 언어. 문자 체계·지역을 가르는 규칙은 그런 언어가 들어올 때 정한다.
- Q: 개발 빌드 전용 화면(개발자 메뉴·진단 화면)의 문구도 카탈로그로 옮기는가? → A: 옮긴다. 「화면 한글은 카탈로그에만」 검사를 화면 종류 예외 없이 세운다.
- Q: 감지한 기기 언어와 고른 화면 언어를 진단 화면에 보이는가? → A: 보인다. 진단 「환경」 묶음에 감지한 것과 고른 것을 한 줄로 보이고, 감지 못함이면 「모름」으로 보인다.

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 한국어 사용자는 아무것도 달라진 것을 느끼지 않는다 (Priority: P1)

기기 언어가 한국어인 사용자가 앱을 열어 첫 실행 흐름·홈·쓰는 중·설정·대화상자·토스트·알림을 지나간다. 모든 문구가
이 작업 전과 글자 하나 다르지 않고, 동작도 같다.

**Why this priority**: 이 작업은 사용자 가치가 아니라 구조 개편이다. 지금 유일한 사용자 언어의 화면이 깨지면 구조를 얻은
대가가 너무 크다. 모든 다른 이야기의 전제다.

**Independent Test**: 이관 전에 잡아 둔 한국어 출력(모든 문구와, 문구를 만드는 함수의 대표 입력 결과)과 이관 후의 출력을
바이트 단위로 대조한다. 기존 보드 원문 대조 테스트가 원문을 고치지 않은 채 통과한다.

**Acceptance Scenarios**:

1. **Given** 이관 전 한국어 출력 골든, **When** 이관 후 같은 입력으로 문구를 만든다, **Then** 모든 항목이 바이트 단위로 같다.
2. **Given** 기기 언어가 한국어인 실기기, **When** 홈·설정·쓰는 중·첫 실행 단계를 지난다, **Then** 화면 문구가 이전과 같다.
3. **Given** 백그라운드 자동 쓰기가 끝났다, **When** 완성 알림이 뜬다, **Then** 문구가 「{이름}{이|가} {M}월 {d}일 일기를 다 썼어요」
   그대로다(조사 포함).

---

### User Story 2 - 기기 언어가 지원 목록에 없어도 앱은 기본 언어로 온전히 보인다 (Priority: P1)

기기 언어를 영어(또는 지원하지 않는 다른 언어)로 둔 사용자가 앱을 연다. 앱은 기기 언어를 읽고, 지원 목록에서 맞는 것을
찾지 못하자 기본 언어(한국어)로 떨어진다. 빈 문구·키 이름·섞인 언어가 보이지 않는다. 기기 언어를 읽지 못한 경우에도
(읽기 실패·빈 값) 같은 결과다.

**Why this priority**: 감지 통로가 실제로 도는 이상, 지원하지 않는 언어의 기기에서 앱이 망가지면 그것이 이 작업이 만든 회귀다.

**Independent Test**: 해석 규칙을 기기 없이 여러 입력(영어, 지역 변형, 빈 목록, 읽기 실패)으로 확인하고, 실기기에서 기기 언어를
영어로 바꾼 뒤 앱을 연다.

**Acceptance Scenarios**:

1. **Given** 기기 선호 언어가 영어 하나, **When** 앱이 언어를 정한다, **Then** 고른 언어는 한국어이고 감지한 언어는 영어로 따로 남는다.
2. **Given** 기기 언어 읽기가 실패했다, **When** 앱이 언어를 정한다, **Then** 고른 언어는 한국어이고 감지한 것은 「감지 못함」이다 — 지어낸 값이 아니다(진단 화면 표기는 「모름」).
3. **Given** 실기기에서 기기 언어를 영어로 바꿨다, **When** 앱을 다시 연다(프로세스가 다시 뜨는 경우 포함), **Then** 화면은 한국어 그대로다.
4. **Given** 기기 언어가 영어인 상태에서 백그라운드 작업이 돈다, **When** 완성 알림을 만든다, **Then** 알림도 같은 해석으로 한국어다.

---

### User Story 3 - 개발자는 언어 하나를 파일 하나와 목록 한 줄로 더한다 (Priority: P2)

다음 언어를 더하려는 개발자가 새 카탈로그 모듈 하나(진입 파일 하나 — 안을 영역별 파일로 나눌 수 있다)를 만들고 지원 목록에 한 줄을 더한다. 문구가 빠졌거나 문구를 만드는 함수의
모양이 다르면 타입 검사가 그 자리를 짚는다. 그 밖의 파일(화면·알림·준비 상태)은 고치지 않는다.

**Why this priority**: 이 기능의 존재 이유지만, 이번 판에 실제로 더하는 언어는 없다. 테스트 전용 가짜 카탈로그로 그 비용을
시연하는 것까지가 범위다.

**Independent Test**: 테스트 전용 가짜 카탈로그와 가짜 지원 목록을 주입해 감지 → 해석 → 카탈로그 선택 → 표시 경로를 통과시키고,
그 가짜 카탈로그에 키 하나를 빼면 타입 검사가 실패함을 확인한다.

**Acceptance Scenarios**:

1. **Given** 가짜 지원 목록에 가짜 언어가 있고 기기 선호 언어가 그 언어, **When** 언어를 정한다, **Then** 가짜 카탈로그가 골라지고 화면 한 곳이 가짜 문구로 그려진다.
2. **Given** 가짜 카탈로그에서 문구 하나를 뺐다, **When** 타입 검사를 돌린다, **Then** 실패한다.
3. **Given** 제품의 지원 목록, **When** 소스를 검사한다, **Then** 가짜 언어는 없고 한국어 하나뿐이다.

---

### User Story 4 - 일기를 쓰는 모델의 입력은 이 작업과 무관하게 그대로다 (Priority: P1)

일기를 쓰는 모델에게 가는 프롬프트, 그 출력 언어, 모델이 쓴 본문·제목은 이 작업의 대상이 아니다. 화면 언어를 무엇으로 정하든
프롬프트는 바이트 단위로 같다.

**Why this priority**: 프롬프트 문안은 다른 저장소에서 바이트까지 실측한 확정안(061)이다. 화면 문구 이관이 그것을 건드리면
측정 근거가 무효가 된다(원칙 IV·V).

**Independent Test**: 061의 프롬프트 테스트 둘을 고치지 않고 돌린다. 가짜 카탈로그가 골라진 상태에서도 프롬프트가 같은지 본다.

**Acceptance Scenarios**:

1. **Given** 이 작업이 끝난 저장소, **When** 061 프롬프트 테스트를 무수정으로 돌린다, **Then** 통과한다.
2. **Given** 화면 언어가 가짜 언어로 골라진 상태, **When** 같은 신호로 프롬프트를 만든다, **Then** 한국어 화면일 때와 바이트 단위로 같다.

---

### Edge Cases

- **기기 선호 언어가 여럿**: 선호 순서대로 지원 목록과 맞춰 보고 첫 일치를 고른다. 모두 맞지 않으면 기본 언어.
- **지역 변형·표기 변형**: `ko-KR`·`ko`·`KO`는 모두 한국어로 맞춘다(언어 부분만, 대소문자 무시). 문자 체계·지역을 가르는 규칙은
  그런 언어가 들어올 때 정한다.
- **언어 부분이 비었거나 형식이 깨진 태그**: 그 항목은 건너뛴다. 남는 것이 없으면 「감지 못함」과 같다.
- **기기 언어 읽기가 예외를 던짐**: 던지지 않고 「감지 못함」 → 기본 언어.
- **실행 중 기기 언어가 바뀜**: 안드로이드는 대개 화면을 다시 만들거나 프로세스를 다시 띄운다. 언어는 프로세스 시작 때 한 번
  정하고(FR-011), 프로세스가 다시 뜨면 다시 정한다. 프로세스가 살아남은 채 화면만 다시 만들어지면 이전 결정을 유지한다. 결과가 언제나
  한국어라 사용자에게 보이는 차이는 없다.
- **헤드리스 백그라운드**: 화면이 없는 백그라운드 작업도 같은 해석 함수로 언어를 정한다. 화면 쪽 상태에 기대지 않는다.
- **화면과 프롬프트가 같은 문자열을 쓰는 자리**: 「모른다」의 까닭(권한 없음 등)과 캐릭터 이름은 프롬프트로 흐른다. 프롬프트용은
  제자리에 남고, 화면에 보이는 경로가 있으면 그 경로만 화면용 문구로 가른다.
- **사용자가 지은 이름**: 사용자가 입력한 이름과 기본 캐릭터 이름은 번역 대상이 아니다(고유 이름). 이름 뒤 조사는 그 언어의 규칙을
  카탈로그가 정한다.
- **저장된 데이터**: 일기 파일·설정 파일에 화면 문구가 저장돼 있지 않아야 한다. 저장된 값이 문구라면 언어가 바뀐 뒤 옛 언어가 보인다.
  (이관 중 그런 자리를 찾으면 기록한다.)

## Requirements _(mandatory)_

### Functional Requirements

**구조**

- **FR-001**: 시스템은 언어마다 하나의 문구 카탈로그를 가져야 한다. 카탈로그는 고정 문구뿐 아니라 그 언어의 문장 틀을 만드는
  함수(날짜·요일·월 표기·시각 표기·이름 뒤 조사·수에 따른 꼴)를 담을 수 있어야 한다.
- **FR-002**: 시스템은 지원 언어 목록과 기본 언어를 한 곳에만 가져야 한다. 이번 판의 지원 목록은 한국어 하나, 기본 언어는 한국어다.
- **FR-003**: 기본 언어의 카탈로그가 모든 카탈로그의 모양(문구 항목과 함수 모양)의 기준이어야 하며, 다른 카탈로그가 항목을 빠뜨리거나
  함수 모양이 다르면 빌드 전 타입 검사가 실패해야 한다.
- **FR-004**: 언어 하나를 더하는 일은 카탈로그 모듈 하나(진입 파일 하나)를 더하고 지원 목록에 한 줄을 더하는 것으로 끝나야 한다. 화면·알림·준비
  상태 등 문구를 쓰는 자리를 고칠 필요가 없어야 한다.
- **FR-005**: 한국어 전용 문법 규칙(이름 뒤 조사 고르기 등)은 화면 문구 경로에서 한국어 카탈로그를 거쳐서만 쓰여야 한다. 화면 문구를
  만드는 자리가 그 규칙을 직접 부르지 않아야 한다.

**감지와 해석**

- **FR-006**: 시스템은 기기의 선호 언어 목록을 읽어야 한다. 읽기가 실패하거나 목록이 비면 「감지 못함」으로 다루고, 그 자리를 어떤 값으로도
  채우지 않아야 한다(원칙 V).
- **FR-007**: 시스템은 감지한 언어 목록을 지원 목록과 맞춰 하나를 골라야 한다. 규칙: 선호 순서대로, 각 태그의 언어 부분을 대소문자 무시로
  비교해 첫 일치를 고른다. 일치가 없거나 감지 못함이면 기본 언어.
- **FR-008**: 해석 결과는 「감지한 것」과 「고른 것」을 따로 담아야 한다. 한쪽에서 다른 쪽을 짐작해 채우지 않는다.
- **FR-009**: 해석 규칙은 입력(감지 결과·지원 목록·기본 언어)만으로 결과가 정해지는 순수 규칙이어야 한다 — 기기 없이 테스트할 수 있다.
- **FR-010**: 화면과 백그라운드(헤드리스) 작업은 같은 감지·해석 규칙으로 언어를 정해야 한다. 백그라운드는 화면 쪽 상태에 기대지 않는다.
- **FR-011**: 언어는 앱 프로세스가 시작될 때(첫 사용 시점) 한 번 정하고 그 프로세스 동안 유지한다. 전경 복귀 때 다시 읽지 않는다.
- **FR-011a**: 앱 안에 언어 선택 설정을 두지 않는다. 시스템 설정의 앱별 언어 목록도 선언하지 않는다 — 언어는 기기 언어의 해석으로만 정해진다.
- **FR-011b**: 진단 화면 「환경」 묶음에 감지한 기기 언어(선호 순서의 첫 태그, 감지 못함이면 「모름」)와 고른 화면 언어를 한 줄로 보인다.
  이 줄은 이번 작업이 새로 더하는 유일한 화면 문구이며, 한국어 출력 골든(FR-020)의 「변화 0」 대상 밖이다. 화면에 닿지 않던 죽은 문구
  코드(import하는 곳이 없는 파일)를 지우는 것도 골든의 명시 차이로 적는다 — 화면 문구 변화가 아니다.

**이관 범위**

- **FR-012**: 사용자 화면에 보이는 모든 문구는 카탈로그에서 와야 한다. 대상: 화면 파일과 화면별 문구 모음, 그리고 화면 밖 계층에서
  만들어 화면·알림에 보이는 문구(쓰는 중 혼잣말, 권한 거부 안내, 내려받기·다시 받기 안내, 완성 알림과 알림 채널 이름, 매일 쓰는 시각 표기,
  건너뜀 줄, 쓰기 실패 안내 등). 모듈 준비 상태·파이프라인 중단의 평서체 이유 문자열처럼 화면에 그려지지 않는 내부 값은 대상이 아니며,
  화면에 그려지지 않음을 소스 검사로 잠근다.
- **FR-013**: 사용자 화면에 보이는 한글 문구가 카탈로그 밖 소스에 남지 않음을 소스 검사로 잠가야 한다. 모델 입력 파일과 그 밖에 이유가
  적힌 허용 목록만 예외다.
- **FR-014**: 개발 빌드 전용 화면(개발자 메뉴·진단 화면)의 문구도 같은 카탈로그로 옮긴다. FR-013의 허용 목록에 화면 종류 예외를 두지 않는다.

**경계**

- **FR-015**: 모델 입력(일기 프롬프트 문안, 프롬프트에 들어가는 「모른다」의 까닭, 프롬프트 호칭 줄의 이름과 조사)은 바뀌지 않아야 한다.
  061 프롬프트 테스트는 수정 없이 통과해야 한다.
- **FR-016**: 일기 출력 언어는 캐릭터의 언어 표에서 오며 화면 언어와 무관해야 한다. 화면 언어 결정이 프롬프트·생성 경로에 들어가지 않는다.
- **FR-017**: 화면과 프롬프트가 같은 문자열을 함께 쓰는 자리는 먼저 둘로 가른다. 프롬프트용은 제자리에 두고 화면용만 카탈로그로 옮긴다.
- **FR-018**: 모델이 쓴 일기 본문·제목, 사용자가 지은 이름, 캐릭터의 기본 이름은 번역 대상이 아니다.
- **FR-019**: 번역 품질을 재거나 채점하는 코드를 두지 않는다(원칙 IV).

**회귀 방어**

- **FR-020**: 이관 전에 한국어 출력 골든(모든 고정 문구 + 문구를 만드는 함수의 대표 입력 결과)을 잡고, 이관 후 바이트 단위 동일을 테스트로 잠가야 한다.
- **FR-021**: 기존 보드 원문 대조 테스트는 원문 기대값을 고치지 않고, 참조 경로만 카탈로그로 옮겨 통과해야 한다.
- **FR-022**: 테스트 전용 가짜 카탈로그로 감지 → 해석 → 선택 → 화면 표시 경로를 통과시켜야 하며, 가짜 언어가 제품 지원 목록에 없음을 소스 검사로 잠가야 한다.
- **FR-023**: 기기 언어 감지를 위해 새 네이티브 모듈을 들이면, 그 모듈이 매니페스트와 실기기 동작에 미치는 영향을 dev 실기기에서 확인해야 한다(release 검증 없음).

### Key Entities

- **지원 언어(Language)**: 앱이 화면 문구를 줄 수 있는 언어 식별자. 이번 판은 한국어 하나.
- **카탈로그(Catalog)**: 한 언어의 화면 문구 전부. 고정 문구와 문장 틀 함수를 화면·영역별 묶음으로 담는다. 기본 언어 카탈로그가 모양의 기준이다.
- **언어 해석 결과(Language Resolution)**: 감지한 언어 목록(또는 「감지 못함」), 고른 언어 하나, 감지한 것 중 지원 목록과 맞은 것이 있었는가(맞음/기본 언어로 떨어짐). 셋을 따로 담는다.
- **한국어 출력 골든**: 이관 전 한국어 문구·함수 출력의 기록. 이관 후 바이트 동일 대조의 기준.

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 이관 전 골든의 모든 항목(고정 문구 전부 + 함수 대표 입력 결과)이 이관 후 바이트 단위로 같다 — 차이 0건(명시 차이는 새 진단 언어 줄 FR-011b와 지운 죽은 문구 코드뿐).
- **SC-002**: 061 프롬프트 테스트 두 파일이 한 줄도 고치지 않고 통과한다.
- **SC-003**: 기존 보드 원문 대조 테스트의 원문 기대값 변경 0건.
- **SC-004**: 사용자 화면 문구를 만드는 소스 중 카탈로그 밖에 남은 한글 문구가 허용 목록을 빼고 0개다.
- **SC-005**: 테스트 전용 가짜 언어 하나를 더하는 데 카탈로그 모듈 하나와 (테스트 안의) 지원 목록 한 줄 말고 다른 제품 파일 변경이 0개다.
- **SC-006**: 기기 언어가 한국어·영어·읽기 실패인 세 경우 모두 화면 문구가 한국어이고, 감지한 값은 각각 한국어 태그·영어 태그·「감지 못함」으로 구분된다.
- **SC-007**: dev 실기기에서 기기 언어 한국어 / 영어(언어 변경 뒤 앱 재시작 포함) / 백그라운드 완성 알림 세 경로를 확인하고, 화면 문구 차이 0건이다.
  진단 화면의 언어 줄이 한국어 기기에서 「ko-KR → 한국어」 꼴, 영어 기기에서 「en-… → 한국어」 꼴로 감지한 것과 고른 것을 다르게 보인다.
- **SC-008**: 전체 기기 불필요 테스트와 린트(헌법 검사 포함)가 통과한다.

## Assumptions

- 언어 결정 시점·앱 안 언어 설정·지역 변형 규칙·개발 화면 이관·진단 표시는 Clarifications(2026-10-06)에서 확정했다.
- 캐릭터 이름(「금동이」)은 프롬프트로 흐르는 고유 이름이라 카탈로그로 옮기지 않는다. 소개 문구(`tagline`)는 지금 화면도 프롬프트도 읽지 않아
  이관 대상이 아니다(research R6 실측) — 화면이 읽게 되는 순간 카탈로그로 옮긴다.
- 문자열을 저장된 데이터에서 읽어 화면에 그리는 자리는 일기 본문·제목·사용자 이름·작성자 이름(`authorName`)뿐이고 모두 번역 대상 밖이다
  (research R13에서 확인, tasks에서 소스로 잠근다).
- 실기기 검증은 dev(debug) 빌드로만 한다. release 잔여 위험은 「미확인 잔여」에 한 줄로 남긴다.
