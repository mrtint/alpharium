# 하단 바의 색을 화면 맨 아래까지 채운다 — 설계

## 목적
홈의 하단 바(「일기 쓰기」·「그만두기」·「다시 쓰기」) 아래에 밝은 띠가 남는다. 아래 안전 영역(iPhone 홈 표시줄·안드로이드 내비게이션 바 자리)을 루트 `SafeAreaView`가 `COLORS.bg`로 비워 두기 때문이다(소스 읽기). 그 자리를 바와 같은 색으로 채운다. 소유자 요청(2026-11-03), 보드 `1d`·`2c`에 없는 모양이라 **보드 밖 초안**이다 — 소유자 확인 전까지 초안이다.

## 이해 (말한 것 / 가정)
- 말한 것: 바 면이 화면 맨 아래까지 간다. 글자는 지금 자리에 두고 늘어난 자리는 면만 채운다. 설정·개발자 겹과 첫 실행은 인셋을 계속 비킨다. 위쪽 반경 6은 그대로다. 안드로이드 기기는 다른 측정 중이라 쓰지 않는다.
- 가정: 「홈」은 `App.tsx`의 마지막 `return`(DiarySection + 겹들) 하나다. 첫 실행 화면들은 자기 `SafeAreaView`가 따로 있어 영향받지 않는다(소스 읽기).

## 수용 기준
1. 홈의 바 세 가지(안 쓴 날 「일기 쓰기」·쓰는 중 「그만두기」·쓴 날 「다시 쓰기」, 상태 흉내 회색 포함) 면이 화면 맨 아래까지 닿고 아래 밝은 띠가 없다. 글자 위치는 인셋이 0일 때와 같다.
2. 토스트·제약 띠는 바 위에 같은 간격으로 놓이고, 쓴 날 다시 쓰기 바는 내려갈 때 화면 밖까지 내려간다.
3. 설정·개발자·진단 겹, 이름 바꾸기·서체 라이선스 겹과 첫 실행 화면은 아래 인셋을 전처럼 비킨다.
4. 쓴 날 지면(`WRITTEN_DAY.paper`)과 안 쓴 날 재료 지면은 화면 맨 아래까지 닿고, 마지막 줄은 바·띠·인셋에 가리지 않고 스크롤된다.

## 결정
| 결정 | 근거 | 뒤집으면 |
|---|---|---|
| 지면도 맨 아래까지 닿는다(바가 내려가 있을 때 맨 아래 띠가 지면 색) | 루트 인셋을 걷으면 홈 전체가 맨 아래까지 가므로 지면이 저절로 닿는다. 별도 띠를 만들어 `bg`로 칠하는 것이 새 장식이다. 바가 올라오면 같은 자리가 바 색이 된다 | 지면 아래에 `bg` 띠를 따로 그려야 함(바 색 ↔ 띠 색 두 번 바뀜) |
| 인셋은 홈 쪽에서 뺀다 — 루트 `edges`에서 `bottom`만 걷고, 겹(`StackLayer`)이 `bottom` 인셋을 자기 안쪽 여백으로 비킨다 | 겹은 홈 위 절대 배치라 루트 인셋이 없으면 시스템 막대 밑으로 들어간다(2026-10-01). 겹 한 곳(`StackLayer`)이 인셋을 맡으면 겹 다섯이 한 번에 비킨다 | 겹마다 인셋을 따로 처리해야 함 |
| 바의 `minHeight`는 64 + 인셋, 아래 여백은 10 + 인셋 | 글은 위 64 안에 그대로(가운데), 늘어난 자리는 면만. 잰 높이(`onLayout`)에 인셋이 들어가므로 토스트·제약 띠·다시 쓰기 바가 내려가는 거리가 저절로 따라간다 | 바 높이를 따로 재야 함 |
| 인셋은 `SafeAreaInsetsContext`로 읽는다(`PhotoViewer`와 같은 방식) | 제공자 없는 jest 렌더에서 던지지 않고 0이다 | `useSafeAreaInsets`는 제공자 없는 테스트가 깨짐 |
| 지면 아래 여백은 인셋만큼 늘린다(120 → 120 + 인셋, 쓴 날은 제약 띠 높이에 인셋 더함) | 바가 인셋만큼 커졌으니 마지막 줄이 가리지 않는 여유는 같아야 한다 | 큰 인셋에서 마지막 줄이 바에 가림 |
| `HOME_TOAST_BOTTOM` 88·설정 쪽 토스트 24 에도 인셋을 더한다 | 둘 다 바닥에서 재던 값이라 바닥이 내려갔으니 같이 간다 | 인셋 큰 기기에서 토스트가 바에 겹치거나 시스템 막대에 닿음 |
| 위쪽 반경 6은 그대로, 보드에 없는 그림자·그라데이션 없음 | 요청 그대로, DESIGN.md 「하지 않는 것」 | — |
| 안드로이드 3버튼 아이콘 색·scrim·제스처 겹침은 못 본 것으로 적는다 | 안드로이드 기기를 쓸 수 없다(소유자 지시) | 기기가 풀리면 확인 항목이 된다 |
| iPhone 홈 표시줄과 바 끝쪽 터치 겹침은 안 막는다 — 바 누름 영역은 면 전체다 | 홈 표시줄은 OS가 가장자리 제스처로 먼저 가져가고 글자는 위 64 안이라 오누름 거리가 있다. iPhone 14에서 사람이 눌러 본다 | 누름 영역을 위 64로 줄여야 함 |
| 숫자(64·10·120·88·24)는 보드·기존 사람이 정한 값, 새 숫자는 없다 | 원칙 V | — |

## 설계
- `App.tsx`: 홈 `SafeAreaView` `edges`를 `["top","left","right"]`로. `toastBottom`에 아래 인셋을 더한다(`AppFrame`에서 읽음).
- `src/ui/StackLayer.tsx`: 겹의 안쪽에 아래 인셋만큼 `paddingBottom`(불투명 배경은 그대로).
- `src/ui/DiaryListScreen.tsx`: `BAR`의 높이·여백에 인셋 반영(세 바 공통), 지면·제약 띠 여백에 인셋 반영, 주석(「아래 안전 영역은 루트가 비킨다」·「내비게이션 바 뒤로 비치지 않게 자른다」) 갱신.
- `design/DESIGN.md`: 홈 바의 면이 안전 영역까지 닿는다는 한 줄. `__tests__/ui/safe-area.test.tsx`: 홈은 `bottom`을 걷고 겹이 비킨다는 소스 계약.

## 테스트
인셋 값은 기기에서 오므로 jest는 `SafeAreaInsetsContext`에 인셋을 주어 렌더한다(바 높이·여백·토스트 바닥). 겹·루트 `edges`는 소스 계약. 모양은 iOS 시뮬레이터(iPhone 17e)에서 스크린샷으로, 손으로 누르기·실제 홈 표시줄은 iPhone 14에서 사람이 본다.

## 위험
- 안드로이드 3버튼 내비게이션 아이콘 색, scrim, 제스처 겹침은 못 본다.
- 시뮬레이터의 홈 표시줄 인셋은 실기기와 같은 34pt이나 겹침 느낌은 사람 손이 필요하다.
