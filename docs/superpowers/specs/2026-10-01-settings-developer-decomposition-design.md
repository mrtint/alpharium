## 1. 모든 조각에 공통으로 적용하는 규칙

앞 문서의 **C1~C9를 그대로 따른다**(라이브러리 문서 확인, dev 1회 실기기 검증, 헌법 우선, 해요체 + KO 원문 계약 테스트,
`tokens.ts` 단일 출처, 안드로이드 검증, 자기 영역만, Maestro 영향 기록, jest는 배선만). 그중 C5의 「accent 면 위 글자는
검정」은 2026-10-01에 **오프화이트**로 뒤집혔다(AGENTS 043). 이 문서의 조각에 더하는 규칙:

**D1. 보드는 iOS 프레임, 메모는 안드로이드 기준이다.** 보드 머리글이 「안드로이드 기준 — 보드 프레임만 iOS」라고 밝힌다.
시스템 뒤로(제스처·버튼)·edge-to-edge 하단 여백(제스처 바 높이)은 메모를 따른다.

**D2. 「개발 빌드」는 환경으로 판정한다.** 보드의 「개발 빌드 / 배포 빌드」는 코드의 `EXPO_PUBLIC_APP_ENV`(`local`·`dev` / `prod`)다.
판정은 `src/config/environment.ts`와 `src/diagnostics/sink.ts`의 `showsOnScreen()`을 쓴다(FR-009a — `process.env`를 다른 데서 읽지 않는다).
보드의 `__DEV__`를 쓰지 않는다(release 빌드도 dev 환경으로 띄울 수 있다).

**D3. 실행 기록은 설정 파일에 담지 않는다.** `src/schedule/settings.ts`의 S7(「필드는 둘뿐이다 — 마지막 실행 시각 같은 필드를
넣으면 실행 이력 로그로 자란다」, 원칙 IV)을 지킨다. S11의 실패 기록과 S13의 건너뜀 기록은 **별도 파일**에, **이유와 시각만**,
**건수 상한**을 두고 담는다. 걸린 시간·토큰 수 같은 측정값은 담지 않는다.

**D4. 설정은 홈 위에 쌓는다.** 설정·개발자·진단은 홈을 언마운트하지 않는다(§3.1). 모든 조각의 전제다.

## 2. 조각 사이의 성립 조건 (순서가 아니다)

- **모든 조각은 「설정 진입과 화면 틀」 위에서 성립한다.** 화면 틀(고정 제목·회색 지면·묶음 머리·행 모양)과 홈 위에 쌓는
  구조가 거기서 생긴다.
- **「개발자 메뉴」가 없으면 「진단」·「상태 흉내」에 닿을 수 없다.**
- **「상태 흉내」의 쓰기 차단(S8)은 「진단」의 두 생성 버튼에도 걸린다.** 진단이 먼저 생기면 그 버튼은 흉내가 없는 상태로만
  성립하고, 흉내가 생길 때 비활성 조건을 더한다.
- **「자동 쓰기 규칙」의 건너뜀 표시(`6g`)는 「설정 진입과 화면 틀」의 사진 행 위에 그린다.**
- **「매일 쓰는 시각과 장소 이름」의 시각 행 펼침은 「설정 진입과 화면 틀」의 자동 쓰기 토글 아래에 붙는다.**
- **「이 휴대폰」의 「일기 모두 지우기」는 쓰는 중이면 먼저 멈춘다** — 054의 그만두기 경로를 쓴다.

## 3. 조각별 명세

### 3.1 설정 진입과 화면 틀

**목적**: 홈 헤더 오른쪽 점 세 개로 설정에 들어간다. 설정은 홈 위에 쌓이고, 홈은 보던 날짜·스크롤·쓰는 중을 그대로 갖는다.
기존 설정 내용을 `6c`의 묶음으로 옮겨 담는다.

**보드**: `6a`, `6c`(① 뒤로 · ② 캐릭터 · ③의 「자동으로 쓰기」 토글 · ④ 권한 · ⑤ 버전 표시). 시각 행 펼침·대화상자는 §3.2,
「이 휴대폰」은 §3.4, 7번 탭은 §3.5.

**인터랙션(보드 원문)**
- **`6a` 설정 버튼** — "일기" 라벨 자리에 5px 네모 점 세 개 — 스트립의 일기 점과 같은 어휘. 탭 영역 44×44pt(오른쪽 위 모서리까지). 탭 → 설정( 6c )이 오른쪽에서 밀려 들어옴(스택 push). 홈의 모든 상태 화면에서 같은 자리·같은 아이콘. 쓰는 중( 2b )에도 열 수 있고, 진행 중인 쓰기는 멈추지 않음 — 그동안 바꾼 이름은 다음 일기부터 적용. 쓴 날에서 스트립이 접혀도( 5a ) 아이콘은 월 라벨 줄과 함께 그대로 남음. 스크린리더 라벨 "설정".
- **`6c` ① 뒤로** — "‹ 일기" 또는 시스템 뒤로(제스처·버튼)로 홈 복귀 — 홈은 보던 날짜·스크롤 위치 그대로. 내용이 화면보다 길면 회색 지면만 스크롤하고 제목·뒤로는 고정. edge-to-edge — 지면 아래 여백이 제스처 바 높이만큼 늘어남.
- **`6c` ② 캐릭터** — 이름 → 이름 짓기( 1a )와 같은 입력 화면, 12자 제한. 이름을 다 지우면 저장 버튼 비활성 — 빈 이름은 허용하지 않음(앞뒤 공백은 잘라냄). 쓰는 중에 바꾸면 다음 일기부터 적용.
- **`6c` ④ 권한 · 휴대폰 설정으로 이동** — 네 행 모두 누르면 안드로이드 앱 정보 화면(Alpharium)으로 감 — 앱 안에서 바꾸지 않음. 앱으로 돌아오면 다시 읽어 표시 갱신. 사진 = 사진 읽기 + 사진의 위치 정보를 한 행으로: 둘 다 있으면 "허용됨", 하나만 있거나 선택한 사진만 허용했으면 "일부 허용"(회색 테두리), 사진 읽기가 없으면 "허용 안 함"(빨강 테두리). 배터리는 앱이 상태를 읽을 수 없어 값 없이 보조 문구와 ›만 — 배터리 사용을 "제한 없음"으로 두지 않으면 자동 쓰기가 하루 넘게 미뤄짐.

### 3.2 매일 쓰는 시각과 장소 이름

**목적**: 자동 쓰기를 켜면 「매일 쓰는 시각」 행이 펼쳐지고, 시 격자 대화상자로 시를 고른다. 장소명 3상태를 행 + 대화상자로 옮긴다.

**보드**: `6c` ③(펼침·값 표기), `6f`, `6l`, `6c`의 「장소 이름으로 보기」 메모.

**인터랙션(보드 원문)**
- **`6c` ③ 자동으로 쓰기 · 매일 쓰는 시각**(이 조각의 부분) — 켜면 바로 아래에 "매일 쓰는 시각" 행이 펼쳐짐(높이 0→44, 200ms). 끄면 접히고 시각 값은 기억해 둠. 시 단위만, 기본값 오후 10시. 값은 "오후 10시쯤"처럼 정확한 시각을 약속하지 않는 꼴(실기기에서 늦게 도착하는 일이 있음). 탭 → 6f . 기기의 시간대·12/24시간 형식을 따름. (나머지 동작은 §3.3)
- **`6c` 장소 이름으로 보기** — 자동으로 쓰기와 상관없이 늘 보임. 자동 · 켬 · 끔 중 하나, 기본값 자동. 행 값은 고른 이름 + ›. 탭 → 6l .
- **`6f` ① 다이얼로그** — 날짜로 이동( 2j )과 같은 RNR Dialog 틀 — 2px 테두리, 가운데 정렬. 제목 아래에 현재 기기 시간대를 그대로 표시(시간대는 고를 수 없음). 바깥 탭·시스템 뒤로 = 취소.
- **`6f` ② 오전 / 오후** — 12시간 형식 기기에서만. 선택한 쪽이 검은 면. 바꿔도 시 칸 선택은 유지(오후 10 → 오전 10).

- **`6f` ④ 미리보기 문장** — 칸을 고를 때마다 "매일 오후 10시쯤…"의 시각이 바로 바뀜.
- **`6f` ⑤ 저장** — 저장 → 다이얼로그가 닫히고 설정의 시각 값이 바로 바뀜, 다음 자동 쓰기 예약을 새 시각으로 다시 잡음. 오늘 그 시각이 이미 지났으면 내일부터 적용. 값을 안 바꿨으면 저장도 그냥 닫기.
- **`6l` ① 다이얼로그** — 2px 테두리, 가운데 정렬. 바깥 탭·시스템 뒤로·취소 = 바꾸지 않고 닫기.
- **`6l` ② 선택** — 고른 칸은 2px 검은 선 + 빨간 네모. 칸을 누르면 바로 적용되고 닫힘(저장 버튼 없음). 열릴 때 현재 값이 선택돼 있음.

### 3.3 자동 쓰기 규칙

**목적**: 자동 쓰기가 재료 0인 날과 사진 권한이 없는 날을 건너뛰고, 건너뛴 사실을 설정에 남긴다. 목표 시각이 지난 뒤 앱을 열면 홈이
쓰는 중으로 시작한다. 완성 알림 문구를 바꾼다.

**보드**: `6c` ③(동작 부분), `6g`, `notif.autoWriteDone`.

### 3.6 진단

**목적**: 기존 진단 화면(022·012·005·020)을 개발자의 하위 화면 `6h`로 옮기고, 「지금 한 번 써 보기」를 홈의 쓰는 중으로 잇고, 쓰기 실패를 기록한다.

**보드**: `6h`, `6k`.

**인터랙션(보드 원문)**
- **`6h` ① 환경** — 빌드 종류·버전, 안드로이드 버전, 추론 위치("기기 · CPU" — 이 기기는 GPU 경로를 쓸 수 없음). 모델 이름·파라미터 수는 쓰지 않음. 모듈 상태는 상위 화면( 6e )의 모듈 그룹에 있음.
- **`6h` ② 저장 점검** — 탭하면 저장된 일기를 다시 읽어 점검하고 "41편 · 정상" 또는 "41편 · 2편 읽기 실패"로 갱신. 고치지는 않음.
- **`6h` ③ 사진 권한** — 사진 읽기, 사진의 위치 정보, 범위(전체 / 선택한 사진만)를 따로 표시 — 설정에서는 한 행으로 묶은 것을 여기서 풀어 봄.
- **`6h` ④ 신호 프로브** — 오늘 기준 다섯 칸. 앱이 실제로 읽는 사진·장소만 숫자. 걸음(안드로이드에서 되짚을 길이 없음)·배터리·연결(수집하지 않음)은 "모름" — 회색 면 + 회색 글자, 고정폭 대신 본문 글꼴로 값과 구분. 화면을 열 때와 "다시 읽기"를 누를 때만 읽음.
- **`6h` ⑤ 입력 프롬프트 미리보기** — 프리셋 두 개(신호 없음 / 사진 있음)를 전환. 실제 신호가 아니라 고정 프리셋 — 날짜가 바뀌어도 내용이 같음. 보드에서는 "(예시)" + 회색 줄로만 그림(실제 문안 아님). 텍스트 상자는 안에서 따로 스크롤, 글자는 선택할 수 있게만 둠.
- **`6h` ⑥ 생성** — 두 버튼 모두 제품과 같은 경로(신호 → 생성 → 저장)로 쓰고 저장. 지금 한 번 써 보기 → 오늘 날짜로 바로 씀, 그 날에 이미 일기가 있으면 덮어씀. 누르면 홈의 오늘로 돌아가 쓰는 중( 6k )으로 시작 — 결과 시트는 두지 않음. 자동 쓰기 지금 실행 → 자동 쓰기를 지금 한 번 돌림, 자동 쓰기 규칙(이미 쓴 날·재료 0 건너뜀) 그대로. 상태 흉내가 켜져 있으면 둘 다 비활성.
- **`6h` ⑦ 최근 실패** — 최근 10건, 쓰기 실패의 이유와 시각만. 건너뜀은 넣지 않음. 걸린 시간 같은 측정값은 두지 않음. 탭 동작 없음.
- **`6k` 토스트** — "진단에서 쓰기를 시작했어요." 2초. 나머지는 쓰는 중( 2b )과 같음 — 다 쓰면 쓴 날( 2c ), 실패하면 2i 와 같은 토스트 + 최근 실패에 한 줄. 이미 있던 일기는 다 쓴 순간 새 글로 바뀜.

### 3.7 상태 흉내

**목적**: 개발 빌드에서 홈의 상태(날짜·실패 토스트·재료 0·권한 없음)를 실제 데이터 없이 띄운다. 흉내가 켜진 동안 일기를 쓰지 않는다.

**보드**: `6e` ③, `6i`.

**인터랙션(보드 원문)**
- **`6e` ③ 상태 흉내** — 개발 빌드에서만 보임 — 배포 빌드에는 그룹 자체가 없음. 홈의 표시에만 적용(자동 쓰기 시각 계산 등 실제 동작에는 쓰지 않음): 날짜, 실패 토스트( 2i ), 재료 0( 2e ), 권한 없음( 2l ). 하나라도 켜져 있는 동안에는 일기를 쓰지 않음(수동·자동·진단 모두) — 가짜 상태로 진짜 일기가 저장되지 않게( 6i ). 홈 월 라벨 옆에 "DEV" 표시. 값은 앱을 껐다 켜도 유지(끄기 전까지).
- **`6i` ① DEV 표시** — 상태 흉내가 하나라도 켜져 있으면 월 라벨 옆에 "DEV". 누르면 개발자 화면( 6e )으로 바로 감.
- **`6i` ② 토스트** — 쓰기 바를 누르면 "상태 흉내가 켜져 있어서 일기를 쓰지 않아요. 개발자 화면에서 끌 수 있어요." 2초. 쓰는 중( 2b )으로 넘어가지 않음.
- **`6i` ③ 쓰기 바** — 빨간 면 대신 회색 면 + "DEV" — 눌러야 이유를 알 수 있으니 누를 수는 있게 둠. 자동 쓰기도 그동안 건너뜀(알림 없음). 흉내를 모두 끄면 원래 바로 돌아옴.

  `day-boundary.ts`의 함수가 모두 `now`를 인자로 받으므로 주입 지점은 화면 쪽이다. 백그라운드 `decideSchedule`의 `now`에는 주입하지 않는다(S8).
- **어긋남 — 실패 토스트 보기**: 054의 토스트는 쓰기 실패에서만 뜬다. 「켜 두면 계속 보이는가 / 한 번 띄우는가」가 보드에 없다.
- **새로 생김 — 쓰기 차단 지점**: 수동(홈 쓰기 바)·자동(`task.ts`)·진단(§3.6 두 버튼) 세 곳. 차단 판정은 한 함수로 두고 세 곳이 부른다.
  `task.ts`는 헤드리스에서도 돌므로 흉내 플래그를 파일에서 읽어야 한다.

**clarify로 넘길 질문**
1. 「실패 토스트 보기」는 켜면 토스트를 한 번 띄우는 버튼인가, 켜 두면 홈에 올 때마다 뜨는 토글인가?
2. 흉내 날짜를 미래로 둘 수 있나? (049 미래 칸 흐림·`isDayWritable`과의 관계)
3. 흉내가 켜진 채 개발자 메뉴를 끄면 흉내도 꺼진다(보드) — 개발 빌드에서 다음 실행에 메뉴가 다시 켜질 때 흉내는 꺼진 채인가?
4. 흉내 플래그 파일을 헤드리스 태스크가 읽는 비용·실패(파일 깨짐) 시 기본값 — 「차단」인가 「허용」인가?

**테스트·Maestro 영향**
- 소스 계약: 흉내 모듈이 `diary/pipeline`·`schedule/decision`·`signals/fake`에 닿지 않는다, 쓰기 차단 판정이 세 진입점에서 불린다.
- 순수 함수: 흉내 상태 → `DayPreview`·`now` 치환, 「하나라도 켜짐」 판정.
- 실기기: 흉내를 켠 채 백그라운드 자동 쓰기 시각을 넘겨 일기가 생기지 않는가(헤드리스), 흉내 날짜로 자정·주 넘김 표시가 맞는가.

**`/speckit-specify` 입력 요지**: 「개발 환경의 개발자 화면에 「상태 흉내」 묶음(오늘 날짜·실패 토스트·쓸 재료 0·사진 권한 없음)을 두어 홈의 표시만 바꿔 본다. 하나라도 켜져 있으면
홈 월 라벨 옆에 「DEV」(누르면 개발자 화면), 쓰기 바는 회색 + 「DEV」이고 누르면 「상태 흉내가 켜져 있어서 일기를 쓰지 않아요…」 토스트만 뜬다(보드 `6i`). 수동·자동·진단 모든 쓰기를 막는다.
흉내 값은 파이프라인·스케줄 판정에 닿지 않는다(원칙 I).」
