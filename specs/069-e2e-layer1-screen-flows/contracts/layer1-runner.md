# Contract: 층 1 실행기 (`--layer1`)

호출: `node scripts/run-device-tests.mjs --layer1 [흐름 파일…]` (npm: `npm run test:layer1`). 흐름 파일을 인자로 주면 그것만 돈다(층 1 목록의 부분집합).
`--layer1`이 없으면 지금과 **똑같이** 동작한다(R-1).

## 단계 (순서 고정)

| # | 단계 | 실패 시 |
| --- | --- | --- |
| L0 | 안내 한 줄 출력: 「층 1은 전용 테스트 기기에서만 돈다 — 이 기기의 일기를 지운다」 (확인 질문 없음) | — |
| L1 | adb 있음 / 기기 ≥1 / Maestro 있음 | **건너뜀**(종료 코드 0, 「통과」라 쓰지 않음) |
| L2 | `run-as <pkg> ls files` 성공(debug 빌드·잠금 해제 뒤) | **중단**: 이유(release 빌드 또는 잠금 해제 전) 출력, 종료 코드 1 |
| L3 | 모델 파일 존재(`files/models/`에 필수 모델 3개) | **중단**: 「모델이 없다」, 종료 코드 1 |
| L4 | `am force-stop <pkg>` | 계속(이미 꺼져 있어도 성공) |
| L5 | 설정 기준값 적용(`baseline-state.md`) | 중단, 종료 코드 1 |
| L6 | 일기 폴더 정리 + 픽스처 일기 3편 + 사진 사본 심기 | 중단, 종료 코드 1 |
| L7 | `LAYER1_FLOWS`(또는 인자)를 한 번의 `maestro test`로 실행(JUnit 보고서) | 실패한 흐름 이름을 출력, 종료 코드 1 |

기기가 둘 이상이면 모두에게 적용한다(기존 실행과 같은 방식, `-s <시리얼>`).

## 불변식

- **I-1**: `pm clear`·`adb install`·`adb uninstall`을 부르지 않는다. `files/models/`를 쓰거나 지우지 않는다.
- **I-2**: 일기를 생성하지 않는다(실행기는 앱을 시작만 하고 Maestro 흐름이 생성 버튼을 누르지 않는다 — 대응표가 본다).
- **I-3**: 건너뜀·중단은 「통과」로 보고하지 않는다. 최종 보고는 `passed` / `failed` / `skipped` / `aborted` 넷 중 하나다.
- **I-4**: 기존 실행의 `FLOWS` 배열과 초기화 루틴은 바뀌지 않는다.
- **I-5**: 층 1 흐름은 모두 `FLOWS`에도 있다(`LAYER1_FLOWS ⊆ FLOWS`, 테스트가 잠근다).
- **I-6**: 흐름 사이에서 기준 상태를 되돌리지 않는다 — 흐름이 바꾼 것은 그 흐름이 스스로 되돌린다(FR-021b). 실행기는 **시작 때만** 기준 상태를 만든다.
- **I-7**: 앱이 떠 있는 채로 일기 폴더를 바꾸지 않는다(L4가 L5·L6보다 앞).
