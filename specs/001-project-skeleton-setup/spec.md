**Feature Branch**: `001-project-skeleton-setup`

**Created**: 2026-08-12

## 이 기능이 무엇인가

되돌리기 이후 이 저장소에는 앱 코드가 없다. 헌법은 섰지만 그 위에 무엇을 올릴 바닥이
없다. 이 기능은 **다음 기능들이 올라설 바닥을 만드는 것**이다. 일기 기능도, 모델
캐릭터도, 사진 처리도 여기서 만들지 않는다.

바닥이 갖춰졌다는 것은 이런 뜻이다: 개발자가 저장소를 받아 실기기에서 앱을 띄울 수
있고, 그 앱이 온디바이스 추론 모듈을 실제로 적재할 수 있으며, 헌법을 어기는 설정이
저장소에 남아 있지 않고, 다음 기능이 테스트를 먼저 쓸 수 있다.

**이 기능의 사용자는 엔드유저가 아니라 이 저장소에서 일하는 개발자와 에이전트다.**
따라서 아래 사용자 시나리오의 "사용자"는 그들을 가리킨다.

### 환경은 셋이다

| 환경 | 어디서 도는가 | 추론 위치 |
| --- | --- | --- |
| **local** | 개발자 기계의 시뮬레이터 | 데스크톱 추론 서버 (기본값). 실기기 연결 시 온디바이스도 가능 |
| **dev** | 실기기, 개발 빌드 | 온디바이스만 |
| **prod** | 실기기, 배포 빌드 | 온디바이스만 |

시뮬레이터에는 네이티브 추론 모듈이 없으므로 local은 서버를 쓴다. 이것은 헌법 원칙 I이
개발·튜닝 단계에 허용한 데스크톱 추론 서버이며, 동일 GGUF·동일 프롬프트·동일 샘플링이라는
제약을 그대로 받는다. **엔드유저가 읽는 일기는 prod에서 나오고, prod는 온디바이스다.**

## Clarifications

### Session 2026-08-12

- Q: 앱이 지금 어느 환경(local/dev/prod)인지는 무엇으로 정해집니까? → A: 실행 중 설정값으로 읽는다. 빌드는 하나이고 설정 파일이나 환경 변수로 갈린다.
- Q: 추론 모듈 적재 실패나 서버 연결 실패 같은 문제를 개발자에게 어떻게 알립니까? → A: 환경별로 갈린다. local·dev는 화면과 로그 모두, prod는 로그만 남기고 사용자에게 보이지 않는다.
- Q: dev·prod에 서버 주소가 들어가거나 헌법이 금지한 설정이 되살아나는 것을 무엇이 막습니까? → A: 자동 검사. 커밋이나 빌드 시점에 금지된 설정을 찾아 실패시킨다.
- Q: 이 기능의 수용 시나리오 중 무엇을 자동 테스트로 만들고 무엇을 손으로 확인합니까? → A: 실기기 검증까지 자동화하되, 기기는 옵셔널이다. 기기가 있으면 실기기 테스트가 돌고, 없으면 건너뛴 것으로 보고한다(통과로 처리하지 않는다).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 실기기에서 앱이 뜬다 (Priority: P1)

저장소를 처음 받은 개발자가 development build를 만들어 안드로이드 실기기에 설치하면,
빈 화면이라도 앱이 뜬다. 지금은 등록된 루트 컴포넌트가 없어 아무것도 뜨지 않는다.

**Why this priority**: 앱이 뜨지 않으면 나머지 전부를 확인할 방법이 없다. 이것이 다른
모든 검증의 전제다.

**Independent Test**: 실기기에 설치해 앱을 실행하고, 죽지 않고 화면이 표시되는지 본다.
이것만으로 "빌드 파이프라인이 살아 있다"는 가치가 전달된다.

**Acceptance Scenarios**:

1. **Given** 저장소를 받아 의존성을 설치한 상태에서, **When** development build를 만들어
   안드로이드 실기기에 설치하고 실행하면, **Then** 앱이 죽지 않고 화면이 표시된다.
2. **Given** 앱이 실행 중일 때, **When** 개발 서버에 연결하면, **Then** 코드를 고쳤을 때
   기기 화면에 반영된다.
3. **Given** Expo Go만 설치된 기기에서, **When** 이 앱을 Expo Go로 열려고 하면,
   **Then** 실행되지 않는다. 이것은 결함이 아니라 헌법 원칙 I의 귀결이며, 문서에 그
   이유가 적혀 있다.
4. **Given** local 환경의 시뮬레이터에서, **When** 앱을 실행하면, **Then** 화면과 흐름을
   확인할 수 있다. 실기기 빌드를 기다리지 않아도 된다.

### User Story 2 - 온디바이스 추론 모듈이 실제로 적재된다 (Priority: P1)

개발자가 앱을 실기기에서 실행했을 때, 네이티브 추론 모듈이 존재하고 호출 가능한 상태임을
확인할 수 있다. 일기를 생성하지는 않는다 — 모듈이 붙어 있는지만 본다.

**Why this priority**: 헌법 원칙 I이 타협 불가로 못 박은 것이 온디바이스 추론이다. 이것이
붙지 않으면 이 제품은 성립하지 않는다. 뼈대 단계에서 확인해야 나중에 되돌아오지 않는다.

**Independent Test**: 실기기에서 추론 모듈의 적재 여부를 확인하는 화면이나 로그를 통해
검증한다. 모델 파일이나 일기 생성 없이도 "네이티브 모듈이 붙었다"까지 확인된다.

**Acceptance Scenarios**:

1. **Given** dev 환경으로 실기기에 설치된 앱이 실행 중일 때, **When** 추론 모듈의 적재
   상태를 확인하면, **Then** 모듈이 존재하고 호출 가능함이 확인된다.
2. **Given** 추론 모듈 적재에 실패한 경우, **When** 앱을 실행하면, **Then** 앱이 조용히
   죽지 않고 실패 사실과 원인이 개발자에게 드러난다.
3. **Given** local 환경의 시뮬레이터에서, **When** 앱을 실행하면, **Then** 네이티브 추론
   모듈이 없다는 사실이 오류가 아니라 예상된 상태로 다뤄지고, 추론은 데스크톱 서버로 간다.

---

### User Story 3 - 환경이 셋으로 갈리고, 추론 위치가 환경마다 정해진다 (Priority: P1)

환경을 **local / dev / prod** 셋으로 나눈다. local은 시뮬레이터에서 데스크톱 추론 서버를
부르고, dev와 prod는 온디바이스로만 돈다. 되돌리기 이전 작업이 남긴 원격 API 주소와 대체
응답 스위치는 이 정리 과정에서 사라진다.

**Why this priority**: 시뮬레이터에는 네이티브 추론 모듈이 없어서 온디바이스로 돌 수 없다.
이 통로가 없으면 화면과 흐름을 만드는 작업마다 실기기 빌드를 기다려야 한다. 동시에 그
통로가 실기기까지 새어 들어가면 헌법 원칙 I을 어기게 되므로, 경계를 뼈대 단계에서 못
박아야 한다.

**Independent Test**: 각 환경으로 앱을 실행해 추론이 어디서 도는지 확인하고, 저장소 전체에
원격 API 추론과 대체 응답 설정이 남아 있지 않음을 확인한다.

**Acceptance Scenarios**:

1. **Given** local 환경의 시뮬레이터에서, **When** 앱이 추론을 요청하면, **Then** 데스크톱
   추론 서버로 간다.
2. **Given** local 환경에서 실기기를 연결했을 때, **When** 온디바이스 추론을 선택하면,
   **Then** 기기에서 돈다. local의 기본값은 서버이되 온디바이스 경로가 막혀 있지는 않다.
3. **Given** dev 또는 prod 환경에서, **When** 앱이 추론을 요청하면, **Then** 반드시
   온디바이스에서 돈다. 서버로 넘어가는 경로가 존재하지 않는다.
4. **Given** 데스크톱 추론 서버를 쓰는 경우, **When** 그 설정을 살펴보면, **Then**
   온디바이스와 동일한 GGUF·동일한 프롬프트·동일한 샘플링 파라미터를 쓴다는 제약이 드러난다
   (헌법 원칙 I).
5. **Given** 정리를 마친 저장소에서, **When** 환경 설정을 살펴보면, **Then** 원격 API 추론
   주소와 대체 응답 스위치가 존재하지 않는다.

---

### User Story 4 - 다음 기능이 테스트를 먼저 쓸 수 있다 (Priority: P2)

개발자가 새 기능을 시작할 때, 테스트를 먼저 쓰고 그것이 실패하는 것을 볼 수 있다. 지금은
테스트가 하나도 없어서 테스트 명령이 실패로 끝난다.

**Why this priority**: 헌법 「개발 방식」이 계약과 테스트를 먼저 쓰라고 요구한다. 다만
P1들이 갖춰지지 않으면 테스트할 대상 자체가 없으므로 P2다.

**Independent Test**: 테스트를 하나 쓰고 실행해, 통과와 실패가 모두 정상적으로 보고되는지
확인한다.

**Acceptance Scenarios**:

1. **Given** 저장소를 받은 상태에서, **When** 테스트를 실행하면, **Then** "테스트가 없다"는
   이유로 실패하지 않는다.
2. **Given** 일부러 실패하는 테스트를 추가했을 때, **When** 테스트를 실행하면, **Then**
   실패가 실패로 보고된다.
3. **Given** 코드에 타입 오류나 서식 위반이 있을 때, **When** 검사를 실행하면, **Then**
   위반이 보고된다.
4. **Given** 실기기가 연결되지 않은 기계에서, **When** 테스트를 실행하면, **Then** 기기가
   필요 없는 테스트는 모두 돌고, 실기기 테스트는 건너뛴 것으로 보고된다. 기기가 없다는
   이유로 실행이 실패하지 않는다.
5. **Given** 실기기가 연결된 기계에서, **When** 테스트를 실행하면, **Then** 실기기 테스트가
   실제로 돌아 앱 실행과 추론 모듈 적재를 검증한다.
6. **Given** 실기기 테스트가 건너뛰어진 실행 결과를 볼 때, **When** 결과를 읽으면, **Then**
   건너뛴 것과 통과한 것이 구분된다. 건너뛴 것이 통과로 보이지 않는다.

---

### User Story 5 - 어디에 무엇을 둘지가 정해져 있다 (Priority: P3)

개발자나 에이전트가 새 코드를 쓸 때, 그것을 어느 자리에 둘지 헤매지 않는다. 폴더 구조와
그 경계가 정해져 있고 문서에 적혀 있다.

**Why this priority**: 없어도 앱은 돌지만, 없으면 다음 기능마다 구조 논쟁이 반복된다.
헌법이 경고한 "한 축을 붙잡고 파고드는" 실패와 직결된다. 다만 P1·P2 없이는 둘 코드
자체가 없으므로 P3다.

**Independent Test**: 문서를 읽고 "일기 생성 코드는 어디, 화면은 어디, 기기 신호 수집은
어디"에 답할 수 있는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 저장소를 처음 보는 사람이, **When** 구조 문서를 읽으면, **Then** 새 코드를 둘
   자리를 판단할 수 있다.
2. **Given** 정해진 구조에서, **When** 측정·채점·모델 비교 코드를 두려고 하면, **Then**
   그것을 둘 자리가 없다는 것이 드러난다(헌법 원칙 IV).

### Edge Cases

- 실기기가 없고 시뮬레이터만 있을 때 어디까지 확인되는가? 앱 실행과 화면·흐름은 확인되지만
  온디바이스 추론의 실제 동작과 속도는 확인되지 않는다. 이 한계가 문서에 적혀 있어야 한다.
- **데스크톱 추론 서버가 꺼져 있을 때 local 환경은 어떻게 되는가?** 조용히 대체 응답으로
  넘어가지 않고, 서버에 닿지 못했다는 사실이 드러나야 한다. 대체 응답은 헌법 원칙 I이
  금지한다.
- **데스크톱 서버와 온디바이스의 출력이 다르면 어떻게 아는가?** 동일 GGUF·프롬프트·샘플링을
  쓰더라도 출력이 같다고 보장되지는 않는다. local에서 확인한 것이 실기기에서 그대로
  재현된다고 가정하지 않는다.
- 누군가 dev나 prod 설정에 데스크톱 서버 주소를 넣으면 무엇이 막는가? 커밋 또는 빌드 시점의
  자동 검사가 걸러낸다(FR-026, FR-027). 사람의 주의력에 기대지 않는다.
- **환경 설정값이 비었거나 알 수 없는 값이면 어떻게 되는가?** 추론 위치가 불명인 채로
  진행해서는 안 된다(FR-009b). 실행 중에 환경을 읽는 구조이므로 이 경우가 실제로 발생한다.
- 추론 모듈이 특정 CPU 아키텍처에서만 동작할 때 다른 기기에서 어떻게 되는가? 조용히 죽지
  않고 원인이 드러나야 한다.
- 의존성을 새로 설치했을 때 선언과 설치본이 다시 어긋나면 어떻게 아는가? 어긋남이 검사로
  드러나야 한다.
- 개발자가 실수로 헌법이 금지한 설정을 되살렸을 때 무엇이 막는가? 자동 검사가 실패하며,
  어느 파일의 어느 설정이 걸렸는지 드러난다(FR-029).
- 저장 공간이 부족한 기기에서 앱을 설치하면 어떻게 되는가? 모델 파일은 이 기능의 범위가
  아니지만, 앱 자체 설치 실패는 원인이 드러나야 한다.

## Requirements *(mandatory)*

### Functional Requirements

**앱 실행 기반**

- **FR-001**: 앱은 안드로이드 실기기에서 development build로 설치되어 실행되어야 한다.
- **FR-002**: 앱은 실행 시 루트 화면을 표시해야 한다. 이 단계의 화면 내용은 앱이 살아
  있음을 확인할 수 있는 최소한이면 된다.
- **FR-003**: 개발 중 코드 변경이 실기기 화면에 반영되어야 한다.
- **FR-004**: Expo Go로 실행할 수 없다는 사실과 그 이유가 저장소 문서에 적혀 있어야 한다.

**온디바이스 추론 기반**

- **FR-005**: 앱은 네이티브 온디바이스 추론 모듈을 포함해야 한다.
- **FR-006**: 개발자는 실기기에서 추론 모듈의 적재 성공 여부를 확인할 수 있어야 한다.
- **FR-007**: 추론 모듈 적재가 실패하면 앱은 조용히 죽지 않고 실패 사실과 원인을 드러내야
  한다. 드러내는 방식은 FR-007a를 따른다.
- **FR-007a**: 진단 정보(추론 모듈 적재 실패, 서버 연결 실패, 현재 환경과 추론 위치)는
  환경에 따라 다음과 같이 알린다.
  - **local·dev**: 앱 화면과 로그 양쪽에 드러낸다.
  - **prod**: 로그에만 남기고 엔드유저 화면에는 드러내지 않는다(MUST NOT).
- **FR-007b**: prod에서 진단 정보를 화면에 드러내지 않는 것이 그것을 남기지 않는다는 뜻은
  아니다. 세 환경 모두 로그에는 남아야 한다(MUST).
- **FR-008**: 이 기능은 일기를 생성하지 않는다. 모델 파일의 내려받기·보관·적재는 이 기능의
  범위 밖이다.

**환경 분리와 추론 위치**

- **FR-009**: 환경은 **local / dev / prod** 셋으로 구분되어야 한다.
  - **local**: 개발자의 작업 기계. 시뮬레이터 사용을 전제한다.
  - **dev**: 실기기에 설치하는 개발 빌드.
  - **prod**: 엔드유저에게 나가는 배포 빌드.
- **FR-009a**: 환경은 실행 시점에 설정값으로 결정되어야 한다. 빌드 산출물은 하나이며 환경마다
  따로 빌드하지 않는다.
- **FR-009b**: 환경 설정값이 없거나 알 수 없는 값일 때, 앱은 추론 위치가 불명인 채로
  진행해서는 안 된다(MUST NOT). 이 경우의 동작이 정해져 있어야 한다.
- **FR-009c**: 환경을 실행 중에 읽는 이상 FR-012의 보장은 코드 경로만으로는 성립하지 않는다.
  dev·prod로 실행 중일 때 서버 추론이 시도되면 그 시도가 차단되고 드러나야 한다(MUST).
- **FR-010**: local 환경의 추론 기본값은 데스크톱 추론 서버여야 한다. 시뮬레이터에는
  네이티브 추론 모듈이 없기 때문이다.
- **FR-011**: local 환경에서 실기기를 사용할 때는 온디바이스 추론도 선택할 수 있어야 한다.
  local은 기본값이 서버일 뿐, 온디바이스 경로가 막힌 환경이 아니다.
- **FR-012**: dev와 prod 환경은 온디바이스 추론만 사용해야 한다. 이 두 환경에서 데스크톱
  서버나 원격 추론으로 넘어가는 경로가 존재하지 않아야 한다(MUST NOT).
- **FR-013**: 데스크톱 추론 서버는 온디바이스와 동일한 GGUF·동일한 프롬프트·동일한 샘플링
  파라미터를 사용해야 하며, 그 제약이 설정 또는 문서에 명시되어야 한다(헌법 원칙 I).
- **FR-014**: 데스크톱 서버 주소는 local 환경에만 존재해야 한다. dev·prod 설정에는 그 값이
  없어야 한다.
- **FR-015**: 저장소에서 원격 API 추론(외부 모델 API)을 가리키는 설정을 제거해야 한다
  (헌법 원칙 I). 데스크톱 추론 서버는 이에 해당하지 않는다.
- **FR-016**: 저장소에서 미리 만들어 둔 응답이나 대체 응답으로 우회하는 설정을 제거해야
  한다(헌법 원칙 I).
- **FR-017**: 현재 환경과 추론 위치를 개발자가 확인할 수 있어야 한다. 어느 환경으로
  실행 중인지 모르는 채로 남는 경우가 없어야 한다. 확인 경로는 FR-007a를 따르며, prod에서는
  화면이 아니라 로그로 확인한다.
- **FR-018**: 저장소에는 모델 출력을 점수화·비교·자동 채점하는 코드가 존재하지 않아야
  한다(헌법 원칙 IV).

**개발 기반**

- **FR-019**: 테스트 실행이 "테스트가 없다"는 이유로 실패하지 않아야 한다.
- **FR-020**: 테스트 실패가 실패로 보고되어야 한다.
- **FR-021**: 타입 검사와 서식 검사가 위반을 보고해야 한다.
- **FR-021a**: 이 기능의 수용 시나리오는 실기기 검증까지 자동 테스트로 만들어야 한다. 손으로만
  확인하고 넘어가는 시나리오를 남기지 않는다.
- **FR-021b**: 테스트는 **기기가 필요 없는 것**(환경 판정, 추론 위치 선택 규칙, 설정 검사)과
  **실기기가 필요한 것**(앱 실행, 추론 모듈 적재) 두 갈래로 나뉘며, 따로 실행할 수 있어야
  한다.
- **FR-021c**: 기기가 필요 없는 테스트는 기기 없이 항상 돌아야 한다(MUST). 이 갈래는
  옵셔널이 아니다.
- **FR-021d**: 실기기 테스트는 **옵셔널**이다. 기기가 연결되어 있으면 돌고, 없으면 건너뛴다.
  기기가 없다는 이유로 전체 테스트 실행이 실패해서는 안 된다(MUST NOT).
- **FR-021e**: 건너뛴 실기기 테스트를 통과로 보고해서는 안 된다(MUST NOT). "돌아서 통과함"과
  "기기가 없어 돌지 못함"이 결과에서 구분되어야 한다. 헌법 원칙 V — 관측된 것과 관측하지 못한
  것을 구분해 적는다.
- **FR-021f**: 실기기 테스트는 안드로이드 실기기에서 앱을 실행해 FR-001·FR-006을 검증해야
  한다. 시뮬레이터로 대체하지 않는다(MUST NOT) — 시뮬레이터에는 네이티브 추론 모듈이 없어
  검증 대상 자체가 없기 때문이다.
- **FR-022**: 의존성 선언과 실제 설치본의 어긋남이 검사로 드러나야 한다.
- **FR-023**: 코드가 놓일 자리(화면, 기기 신호 수집, 일기 생성, 저장)의 경계가 정해지고
  문서에 적혀 있어야 한다.
- **FR-024**: 구조 문서에는 측정·채점 코드를 둘 자리가 존재하지 않아야 한다.
- **FR-025**: 추론 위치를 고르는 지점은 한 곳이어야 한다. 일기 생성 코드가 자신이 어디서
  도는지 알 필요가 없어야 한다.

**헌법 위반 자동 검사**

- **FR-026**: 헌법이 금지한 설정이 저장소에 들어오는 것을 자동 검사가 막아야 한다. 검사는
  커밋 또는 빌드 시점에 돌며, 위반을 발견하면 실패해야 한다(MUST).
- **FR-027**: 자동 검사는 최소한 다음을 잡아야 한다.
  - dev·prod 설정에 데스크톱 서버 주소가 존재하는 경우 (FR-014)
  - 원격 API 추론을 가리키는 설정이 존재하는 경우 (FR-015)
  - 미리 만들어 둔 응답이나 대체 응답으로 우회하는 설정이 존재하는 경우 (FR-016)
- **FR-028**: 이 검사는 설정 위반을 잡는 것이지 모델 출력을 재는 것이 아니다. 헌법 원칙 IV가
  금지한 품질 점수화·모델 비교를 이 검사에 넣지 않는다(MUST NOT).
- **FR-029**: 검사가 실패했을 때 무엇이 왜 걸렸는지가 드러나야 한다. 어느 파일의 어느 설정이
  위반인지 알 수 없는 실패는 허용하지 않는다.

### Key Entities

- **환경**: local / dev / prod 셋 중 하나. 앱이 어디서 실행 중인지를 가리키며, 추론 위치의
  허용 범위를 결정한다.
- **추론 위치**: 추론이 실제로 도는 곳. 온디바이스 또는 데스크톱 추론 서버. 환경에 따라
  허용되는 값이 다르며(dev·prod는 온디바이스만), 헌법 원칙 I의 제약을 받는다.
- **환경 설정**: 환경별로 달라지는 값의 묶음. 데스크톱 서버 주소는 local에만 존재한다.
- **코드 배치 경계**: 화면, 기기 신호 수집, 일기 생성, 저장을 서로 구분하는 경계. 헌법
  원칙 IV에 따라 측정·채점은 어느 경계에도 속하지 않는다.
- **의존성 기준선**: 이 프로젝트가 서는 패키지 버전의 집합. 2026-08-12에 Expo 57로
  확정됐다(헌법 원칙 I).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 저장소를 처음 받은 개발자가 문서만 보고 실기기에서 앱을 띄우기까지, 막혀서
  질문할 필요 없이 도달한다.
- **SC-002**: 실기기에서 앱을 실행했을 때 온디바이스 추론 모듈의 적재 성공 여부를 100%
  확인할 수 있다. 모듈 상태가 불명인 채로 남는 경우가 없다.
- **SC-003**: 저장소 전체에서 원격 API 추론 및 대체 응답 관련 설정이 0건이다.
- **SC-004**: dev·prod 환경에서 추론이 기기 밖으로 나가는 경우가 0건이다.
- **SC-005**: 데스크톱 서버 주소가 dev·prod 설정에 존재하는 경우가 0건이다.
- **SC-006**: 개발자가 시뮬레이터만으로 화면과 흐름을 만들 수 있다. 이 작업에 실기기 빌드를
  기다릴 필요가 없다.
- **SC-007**: 앱을 실행한 개발자가 현재 환경과 추론 위치를 100% 확인할 수 있다.
- **SC-008**: 저장소 전체에서 모델 출력을 점수화·비교하는 코드가 0건이다.
- **SC-009**: 새 기능을 시작하는 개발자가 테스트를 먼저 써서 실패를 확인하는 데 추가 설정
  작업이 필요하지 않다.
- **SC-010**: 저장소를 처음 보는 사람이 구조 문서를 읽고 새 코드의 위치를 판단할 수 있다.
- **SC-011**: 의존성 선언과 설치본이 어긋난 상태로 커밋되면 검사에서 드러난다.
- **SC-012**: 헌법이 금지한 설정을 일부러 넣었을 때 자동 검사가 100% 실패한다. 사람이
  알아채는 것에 기대는 경우가 없다.
- **SC-013**: prod로 실행했을 때 엔드유저 화면에 진단 정보가 드러나는 경우가 0건이다.
- **SC-014**: 실기기가 없는 기계에서도 기기가 필요 없는 테스트는 100% 실행된다. 기기가 없다는
  이유로 전체 실행이 막히는 경우가 없다.
- **SC-015**: 건너뛴 실기기 테스트가 통과로 집계되는 경우가 0건이다.

## Assumptions

- **이 기능의 사용자는 개발자와 에이전트다.** 엔드유저에게 보이는 기능은 만들지 않는다.
- **검증 기기는 안드로이드 실기기다.** 이전 작업에서 온디바이스 추론이 실증된 환경이
  Galaxy S20+(Android 13, arm64-v8a)이므로 이를 기준으로 삼는다. iOS 검증은 이 기능의
  범위 밖이다.
- **의존성 기준선은 이미 정해졌다.** 2026-08-12에 Expo 57로 확정하고 선언을 설치본에
  맞췄다. 이 기능은 그 위에서 뼈대를 세우는 것이지 버전을 다시 정하는 것이 아니다.
- **모델 파일은 다루지 않는다.** 추론 모듈이 붙는 것까지가 이 기능이고, 모델을 내려받아
  적재해 일기를 만드는 것은 다음 기능이다.
- **화면 디자인은 다루지 않는다.** 앱이 살아 있음을 확인할 최소한의 화면이면 된다.
- **캐릭터·로스터·시각 처리는 다루지 않는다.** 헌법에 확정되어 있으나 이 기능의 범위가
  아니다.
- **현재 환경 설정 파일은 되돌리기 이전 작업의 잔재다.** 원격 API 추론 주소와 대체 응답
  스위치가 남아 있으며, 헌법 원칙 I과 어긋난다. 이 기능에서 정리한다.
- **데스크톱 추론 서버는 헌법이 이미 허용한 경로다.** 원칙 I이 개발·튜닝 단계에서 이를
  MAY로 허용하되 동일 GGUF·프롬프트·샘플링을 MUST로 요구한다. 따라서 local의 서버 추론은
  헌법 개정 없이 성립한다. 원칙 I이 MUST NOT으로 금지한 "원격 API 추론"은 외부 모델
  API를 가리키며, 데스크톱 서버는 이에 해당하지 않는다.
- **local에서 확인한 것이 실기기에서 재현된다고 가정하지 않는다.** 실행 위치가 다르면
  출력도 다를 수 있다. 온디바이스 확인은 dev 환경에서 한다.
- **데스크톱 추론 서버 자체를 만드는 것은 이 기능의 범위가 아니다.** 앱이 그 서버를 부를 수
  있는 통로를 만드는 것까지가 이 기능이다.
- **실기기 테스트가 옵셔널이라는 것은 온디바이스 검증을 건너뛰어도 된다는 뜻이 아니다.**
  기기가 없는 기계에서 실행을 막지 않겠다는 뜻이다. 이 선택의 대가로, 기기 없이 돌린 실행은
  전부 통과해도 온디바이스가 검증되지 않은 상태다. 그래서 건너뜀과 통과를 구분해 보고하는
  것(FR-021e)이 이 결정의 전제다. 기능이 끝났다고 말하려면 최소 한 번은 실기기에서 돌아야
  한다.

## 범위 밖 *(명시)*

되돌리기의 원인이 "여러 축 중 하나를 붙잡고 파고든 것"이므로, 이 기능이 건드리지 않을
것을 명시한다.

- 일기 생성 로직과 프롬프트
- 모델 파일의 내려받기·보관·선택
- 캐릭터 로스터와 그 화면
- 사진·GPS·걸음 수·배터리 등 기기 신호의 실제 수집
- 사진 시각 처리
- 화면 디자인과 사용자 흐름
- iOS 지원
- 배포와 스토어 등록
