# Quickstart: 다운로드 동의 안내·진행 슬라이드 검증

## 전제 조건

- Android 실기기(dev/debug), USB 또는 무선 디버깅 연결, 잠금 해제 상태.
- `adb reverse tcp:8081 tcp:8081` 실행됨.
- Metro가 `EXPO_PUBLIC_APP_ENV=dev npx expo start --dev-client`로 떠 있음.
- 필수 자산(v1·v2·a1)이 **아직 받아지지 않은** 상태(`adb shell pm clear
  <패키지>` 또는 새 설치) — 동의·슬라이드 화면은 자산이 준비되지 않았을
  때만 나타난다(FR-009).
- 043·044가 이미 병합되어 그 화면을 지나 이 스펙의 화면에 도달할 수 있다.

## 기기 없는 검증 (항상 먼저)

```bash
npm run test:logic    # resolveFirstRunStage 확장, resolveSlideStage 신규
npm run test:ui       # DownloadConsentDialog, DownloadProgressScreen
npm run lint           # eslint + tsc + 헌법 검사 + prettier
npm test               # 전체 (커밋 전)
```

**기대 결과**: `__tests__/firstrun/consent.test.ts`(C1~C9, contracts
대응)와 `__tests__/ui/download-consent-dialog.test.tsx`·
`download-progress-screen.test.tsx`가 통과한다. 위반 주입(C2의 우선순위
순서를 되돌리는 등)이 실제로 실패로 잡히는지 각각 1회 확인한다(원칙 V
"검사가 무엇을 뜻하는지 알 수 없으면 검사가 아니다").

## 실기기 검증 시나리오

### D1 — 동의 안내가 다운로드보다 먼저 뜬다 (SC-001, User Story 1)

1. 필수 자산이 없는 상태로 앱을 실행해 권한 스텝을 전부 결정한다.
2. **관찰**: 다운로드 진행 화면이 아니라 동의 안내 Dialog가 먼저 뜬다.
   "사진을 읽는 모델"·"글을 쓰는 모델"을 받는다는 문장이 보이고, 모델
   식별자·바이트 수치는 보이지 않는다.
3. **관찰**: [확인/시작] 버튼 하나만 있다 — 거부·건너뛰기 버튼이 없다.
4. Dialog를 그대로 두고(누르지 않고) 잠시 기다린다. **관찰**: 다운로드
   진행률이 움직이지 않는다(네트워크 활동 없음, 필요하면 `adb shell
   dumpsys netstats` 또는 화면 관찰로 확인).

### D2 — 확인 후 다운로드 슬라이드가 순서대로 넘어간다 (SC-002, User Story 2)

1. D1에서 [확인/시작]을 누른다.
2. **관찰**: 슬라이드 1 레이아웃(진행 인디케이터 "01/04", 헤드라인, 본문,
   그림 자리, 4칸 진행 표시)이 보인다.
3. 4초 이상 기다린다. **관찰**: 슬라이드 2로 자동 전환되며 헤드라인·본문이
   바뀐다. 다시 4초씩 기다려 슬라이드 3·4까지 전환을 확인한다.
4. **관찰**: 화면 어디에도 바이트·퍼센트·전송 속도 수치가 없다 — "받는
   중이에요" 고정 문구만 보인다.
5. 다운로드가 실제로 끝날 때까지 기다린다(모델 크기에 따라 수십 초~수
   분). **관찰**: 슬라이드가 4번째에서 더 넘어가지 않고 머무르다가,
   다운로드가 끝나는 순간 완료 화면(`1q`)으로 전환된다.
6. **관찰**: 완료 화면에 "시작할게요" 버튼이 보인다.

### D3 — 다운로드 완료 후에만 작명으로 넘어간다 (SC-003, User Story 3)

1. D2의 완료 화면에서 "시작할게요"를 누른다.
2. **관찰**: 044 작명 화면(`WelcomeScreen`)으로 전환된다.
3. (회귀 확인) 다운로드가 끝나기 전 임의로 앱을 여러 번 최소화·복귀해도
   작명 화면에 도달하지 않는지 확인한다.

### D4 — 이미 준비된 사용자는 아무것도 보지 않는다 (SC-004, Edge Case)

1. 필수 자산을 이미 받은 상태(예: D1~D3를 마친 뒤 앱 데이터를 지우지
   않고 재실행, 또는 `run-as`로 모델 파일이 있는 상태 확인)에서 앱을
   재실행한다(권한은 이미 결정됨 가정).
2. **관찰**: 동의 Dialog도 슬라이드 화면도 뜨지 않고 곧바로 다음
   단계(작명 또는 홈)로 진행한다.

### D5 — 041 재개와의 상호작용 (Edge Case)

1. D2의 슬라이드 진행 중(예: 슬라이드 2~3 사이) 앱을 강제 종료한다
   (`adb shell am force-stop <패키지>`).
2. 앱을 다시 연다.
3. **관찰**: 동의 Dialog가 다시 뜨지 않고(이미 동의했으므로) 곧바로
   슬라이드 화면으로 가되, 슬라이드는 1번부터 다시 시작한다(Clarifications
   확정 사항). 041의 재개 가능한 다운로드 덕에 이미 받은 만큼은 다시
   받지 않는다(logcat 또는 다운로드 소요 시간으로 간접 확인).

## Maestro 회귀

```bash
npm run test:device   # .maestro/download-consent-flow.yml 포함, 있으면 실행
```

기존 흐름 중 이 스펙이 순서를 바꾸므로 함께 재확인해야 하는 것:
- `.maestro/welcome-naming.yml` — 작명 화면 진입 경로가 바뀌었으므로
  (다운로드 완료 후에만 도달) 이 흐름이 여전히 작명 화면에 닿는지 확인.
- `.maestro/unified-permission-onboarding.yml` — 권한 온보딩 자체는
  무변경이지만 그 다음 화면이 바뀌었으므로 흐름 끝부분의 어서션이
  깨지지 않는지 확인.
