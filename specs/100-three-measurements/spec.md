## 근거와 원본

- **설계**: `docs/superpowers/specs/2026-10-22-three-measurements-design.md`.
- **로드맵 과제**: 「실측 세 가지 — 제목 구간·동작 줄이기·작은 화면의 쓴 날」.
- **문제**: 검토서가 짚은 세 곳은 코드만으로는 「문제가 있는가」를 가를 수 없다. (1) 쓰는 중 혼잣말은 단계가 넷뿐이라 본문 뒤 제목 질문 동안에도 「글을 쓰는 중」 풀이 도는데 제목 구간 길이를 잰 적이 없다. (2) OS 「동작 줄이기」를 앱이 직접 읽는 자리가 없고 켜고 본 기록이 없다. 내려받기 슬라이드 자동 넘김은 멈추지 않을 것으로 소스에서 짐작했을 뿐이다. (3) 쓴 날 첫 화면의 캐러셀 높이가 고정이라 짧은 화면에서 본문이 몇 줄 보이는지는 추정뿐이다.
- **원칙**: 측정 코드를 제품에 넣지 않는다(헌법 IV). 실측과 짐작을 구분해 기록한다(헌법 V).
- **범위 밖**: 측정 판정이 「닫음」인 항목의 제품 변경, 보드 2c의 소유자 결정 없는 변경, 안드로이드 외 기기의 제목 구간 측정, 동작 줄이기 대응이 「각 애니메이션에 대응」으로 커지는 경우(그때 범위를 다시 정한다).

## 용어

- **닫음**: 측정 결과 문제가 없다고 판정하고 측정값만 남긴다. 제품 변경 0.
- **후속 변경**: 측정 결과가 기준을 넘어 제품을 바꾸기로 판정한다.
- **제목 구간**: 본문 생성이 끝난 뒤 두 번째 모델 호출(제목 질문)의 시작부터 끝까지.
- **혼잣말 교체 간격**: 쓰는 중 혼잣말이 다음 문장으로 바뀌는 간격, 4초.

## Clarifications

### Session 2026-10-22

- Q: 제목 구간 판정을 어떤 값으로 내릴까? → A: 사진 있는 날 중앙값과 없는 날 중앙값 중 하나라도 4초 이상이면 후속 변경. 둘 다 4초 미만일 때만 닫음.
- Q: 동작 줄이기에서 자동 넘김 외 장면이 움직이면 이번에 고치나? → A: 아니다. 결과표에 「따르지 않음」으로 기록하고 로드맵에 후속 과제로 올린다. 이번에 고치는 것은 소유자 확인을 받은 자동 넘김뿐이다.

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 제목 구간 길이를 재고 판정한다 (Priority: P1)

쓰는 중 화면이 본문 뒤 제목을 묻는 동안 어떤 말을 하는지가 실제 대기 길이에 맞는지 가른다.

**Why this priority**: 제목 구간이 길면 사용자는 이미 끝난 본문 쓰기 문구를 계속 본다. 길이를 모른 채 단계를 더하거나 건너뛸 수 없다.

**Independent Test**: 실기기에서 사진 있는 날·없는 날 각 2회 쓰고 제목 구간 네 값과 날 종류별 중앙값을 기록한다. 기준 비교와 판정 기록만으로 독립 검증된다.

**Acceptance Scenarios**:

1. **Given** SM-S901N dev 빌드, **When** 사진 있는 날 2회·없는 날 2회를 쓰고 제목 구간을 잰다, **Then** 네 값과 날 종류별 중앙값이 원값과 함께 quickstart에 있고 AGENTS에 측정값 한 줄이 있다.
2. **Given** 사진 있는 날 중앙값과 없는 날 중앙값이 모두 4초 미만, **Then** 판정은 「닫음」이고 제품 코드는 바뀌지 않는다.
3. **Given** 두 중앙값 중 하나라도 4초 이상, **Then** 판정은 「후속 변경」이며 진행 단계 하나와 사람이 쓴 열 문장 풀 하나가 더해진다(숫자·시간·글 조각 없음). 저장 단계는 더하지 않는다. 이 변경이 깨는 단언(단계 수·갈래 수·숫자 없음·P4 순서·문구 골든)은 같은 변경에서 고친다.

### User Story 2 - OS 「동작 줄이기」에서 앱이 어떻게 움직이는지 본다 (Priority: P1)

OS의 동작 줄이기(안드로이드 「애니메이션 제거」, iOS 「동작 줄이기」)를 켠 사람에게 앱의 움직임이 따라오는지 가른다.

**Why this priority**: 접근성 설정을 켠 사람에게 끄지 않는 자동 움직임은 실제 불편이다. 지금은 켜고 본 기록이 없다.

**Independent Test**: 기기 설정 전후 값을 기록하고 장면별 화면 녹화를 본다. 장면별 결과표로 독립 검증된다.

**Acceptance Scenarios**:

1. **Given** SM-S901N에서 「애니메이션 제거」를 켠 상태와 iOS 시뮬레이터에서 「동작 줄이기」를 켠 상태, **When** 설정 겹 열기·닫기, 날짜 넘김, 실패 토스트, 스트립 튕김, 달력, 사진 확대, 내려받기 화면을 녹화로 본다, **Then** 장면×플랫폼 표에 「OS 값을 따름」/「따르지 않음」이 실측으로 적힌다.
2. **Given** 모든 장면이 OS 값을 따른다, **Then** 판정은 「닫음」이고 AGENTS 실측 규칙에 한 줄이 더해진다.
3. **Given** 내려받기 슬라이드가 동작 줄이기 상태에서 계속 넘어간다, **When** 소유자 확인(046의 복원 동작 변경이므로)을 받는다, **Then** 동작 줄이기가 켜진 때만 자동 넘김이 멈추고 손으로 넘기는 것은 그대로다.
4. **Given** 자동 넘김 외 장면이 동작 줄이기에서도 움직인다, **Then** 이번에 고치지 않고 결과표에 「따르지 않음」으로 적고 로드맵에 후속 과제로 올린다.
5. **Given** OS 값을 앱이 실기기에서 읽지 못하는 것으로 드러난다, **Then** 변경하지 않고 범위를 소유자와 다시 정한다.
6. **Given** 측정이 끝났다, **Then** 바꾼 기기 설정은 시작 전 값으로 돌아와 있다.

### User Story 3 - 작은 화면의 쓴 날 첫 화면 본문 줄 수를 센다 (Priority: P2)

짧은 화면과 큰 글꼴에서 쓴 날 첫 화면에 일기 본문이 몇 줄 보이는지 가른다.

**Why this priority**: 사진 캐러셀 높이가 고정이라 본문이 가려질 수 있으나, 보드 값이라 소유자 결정 없이 건드리지 않는다. 측정은 결정을 위한 근거다.

**Independent Test**: 083 캡처와 새 캡처에서 줄 수를 세어 환경×글꼴 배율 표를 채운다.

**Acceptance Scenarios**:

1. **Given** 083 이후 쓴 날 레이아웃이 바뀌지 않았고 083의 글꼴 2배 캡처(안드로이드·iOS)가 있다(바뀌었으면 현재 코드로 새로 찍은 캡처), **When** 쓴 날 첫 화면의 본문 노출 줄 수를 센다, **Then** 플랫폼별 값이 표에 있다.
2. **Given** 667pt 화면 시뮬레이터(iPhone SE 3rd gen), **When** 글꼴 1.0배·약 2.0배로 쓴 날 첫 화면을 찍는다, **Then** 두 값이 표에 있다.
3. **Given** 1.0배에서 본문 노출이 2줄 이상, **Then** 판정은 「닫음」이고 결과만 적는다.
4. **Given** 1.0배에서 0~1줄, **Then** 판정은 「후속 변경」이며 보드 2c 이탈을 소유자에게 올린다. 이때 「30dp를 줄여도 글꼴 2.0배에서는 한 줄(약 49.5dp)도 못 번다」는 계산을 함께 적는다. 소유자 결정 전에는 제품 코드를 바꾸지 않는다.

---

### Edge Cases

- 제목 호출이 실패하거나 시간 초과인 회차는 중앙값에서 빼고 따로 적으며, 날 종류별 유효 회차 2개가 될 때까지 보충 쓰기를 최대 2회 한다.
- 사진 있는 날의 측정에는 사진 캡션 단계가 앞서므로 제목 구간만 따로 분리해 잰다.
- 동작 줄이기 상태에서 모델 내려받기를 보려면 모델을 지우지 않고 보는 절차(074)를 쓴다. 기기의 모델은 지우지 않는다.
- 시뮬레이터 한 대로 짧은 화면을 대표한다는 한계와 SE급 iPhone이 지원 대상인지 미확인(M1)임을 결과에 함께 적는다.
- 세 판정이 모두 「닫음」이면 제품 코드 변경 0이 정상 결과다.

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 세 측정은 제품 코드를 바꾸기 전에 끝내고, 측정 도구·채점 코드는 저장소에 두지 않는다(헌법 IV).
- **FR-002**: 제목 구간은 SM-S901N dev 빌드에서 사진 있는 날·없는 날 각 유효 회차 2개, 두 번째 모델 호출 시작~끝으로 재며 원값과 날 종류별 중앙값을 기록한다.
- **FR-003**: 제목 구간 판정 기준은 4초다. 사진 있는 날 중앙값과 없는 날 중앙값을 따로 구해, 둘 다 미만이면 닫음, 하나라도 이상이면 후속 변경(FR-004).
- **FR-004**: 제목 구간 후속 변경은 진행 단계 `title` 하나와 사람이 쓴 열 문장 풀 하나를 더하고 저장 단계는 더하지 않는다. 풀 문장에 숫자·시간·글 조각이 없다. 새 문구는 새 키로만 더하고 문구 골든은 `ADDED_AFTER_GOLDEN`에만 올린다.
- **FR-005**: 동작 줄이기는 안드로이드 「애니메이션 제거」와 iOS 「동작 줄이기」에서 정해진 일곱 장면(설정 겹 열기·닫기, 날짜 넘김, 실패 토스트, 스트립 튕김, 달력, 사진 확대, 내려받기 화면)을 화면 녹화로 보고 장면×플랫폼 결과표를 남긴다.
- **FR-006**: 동작 줄이기가 OS 값을 읽는 방식(안드로이드의 어느 설정값이 어느 라이브러리에 닿는가)은 소스 확인이 아니라 실기기 관찰로 확정해 적는다. 소스로 안 것은 「소스 읽기」로 구분해 적는다(헌법 V).
- **FR-007**: 내려받기 슬라이드 자동 넘김이 동작 줄이기에서 멈추지 않으면 소유자 확인 뒤 OS 값을 읽어 자동 넘김만 끈다. 손으로 넘기기·046의 나머지 동작은 그대로이고, 기존 소스 계약 테스트를 깨지 않는다. 자동 넘김 외 장면은 고치지 않고 기록 후 후속 과제로 올린다.
- **FR-008**: 기기 설정(애니메이션 배율, 글꼴 배율 등)을 바꾸면 시작 전 값을 기록하고 측정이 끝나면 되돌려 대조한다. 기기의 모델·앱 데이터는 지우지 않는다.
- **FR-009**: 쓴 날 본문 노출 줄 수는 먼저 083 이후 쓴 날 레이아웃이 바뀌지 않았는지 확인하고, 그대로면 083 캡처(플랫폼 열)에서 세며 모자란 환경(667pt 화면, 글꼴 1.0·약 2.0배)만 새로 찍는다. 바뀌었으면 083 캡처를 증거로 쓰지 않고 현재 코드로 새로 찍는다. 본문 글꼴은 비선형, 큰 날짜는 선형으로 늘어나므로 플랫폼 열을 따로 둔다.
- **FR-010**: 쓴 날 판정은 1.0배에서 2줄 이상이면 닫음, 0~1줄이면 후속 변경(보드 이탈을 소유자에게 올림)이다. 소유자 결정 없이 캐러셀 높이를 바꾸지 않는다.
- **FR-011**: 각 측정은 「닫음」 또는 「후속 변경」 판정과 실측값을 AGENTS 실측 규칙 한 줄(상세 원값·절차는 quickstart)로 남기며, 짐작과 실측을 구분해 적는다.
- **FR-012**: 후속 변경을 하면 그 변경은 실기기(또는 해당 변경의 대상 환경)에서 한 번 확인하고 결과를 적는다.

### Key Entities

- **측정 기록**: 항목(UX-01·11·12), 환경(기기·플랫폼·배율), 원값, 대표값, 판정(닫음/후속 변경), 짐작/실측 구분.
- **기기 설정 기록**: 설정 이름, 시작 전 값, 종료 후 값.

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 세 항목 모두에 실측값과 판정(닫음/후속 변경)이 AGENTS 또는 quickstart에 남는다(세 판정 모두 기록).
- **SC-002**: 제목 구간은 네 회차(사진 있는 날 2·없는 날 2) 원값과 중앙값이, 동작 줄이기는 7장면×2플랫폼 결과표가, 쓴 날은 환경×배율 줄 수 표가 있다.
- **SC-003**: 측정을 마친 뒤 기기 설정 값이 시작 전 기록과 모두 같다.
- **SC-004**: 후속 변경이 있으면 기기 확인 기록이 있고 `npm test`·`npm run lint`가 통과한다. 후속 변경이 없으면 제품 코드 변경은 0줄이다.
- **SC-005**: 저장소에 측정·채점용 코드가 늘지 않는다.

## Assumptions

- 측정 스크립트(로그 파싱 등)는 일회용이며 스크래치에 둔다.
- 상세 절차와 원값은 `specs/100-three-measurements/quickstart.md`, 판정 요약은 AGENTS에 둔다.
- 083 캡처가 현재 코드의 쓴 날 레이아웃과 같은지는 가정하지 않고 먼저 확인한다(083 이후 화면 파일이 바뀌었다). 바뀌었으면 새로 찍는다.
- SE급 iPhone의 지원 여부(M1)는 이번에 결정하지 않는다.
- 다른 세션이 8081을 쓰므로 이 세션의 Metro는 8082이고 `adb reverse`로 돌린 뒤 원복한다.
