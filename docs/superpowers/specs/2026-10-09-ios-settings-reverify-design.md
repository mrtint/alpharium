# iOS 설정·개발자·진단 화면 재검증과 고장 수정 — 설계

2026-10-09 · 로드맵 「iOS 설정·개발자·진단 화면 재검증과 고장 수정」의 설계다.

## 목적과 성공 기준

iOS 사용자가 설정·개발자·진단 화면의 어떤 행·버튼을 눌러도 앱이 튕기지 않고, 안드로이드 전제로 거짓을 말하는 곳이 없다.

- 설정의 모든 행을 눌러 시뮬레이터에서 오류 0건. 고친 곳은 계약 테스트가 잠근다.
- 개발자·진단 화면은 모든 버튼이 의도대로 동작하거나 의도적으로 감춰져 있다.
- 시뮬레이터에서만 본 것은 「실제 iPhone 미확인」으로 적는다(실기기·TestFlight 확인은 저장소 소유자가 한다).

범위 밖: 백그라운드 자동 쓰기의 iOS 실측, 메모리 한도, GPU 캡션 되돌리기, 시뮬레이터 liveness 실패(로드맵에 별도 과제).

## 이미 확인된 것 (2026-10-09, iPhone 17 Pro Max 시뮬레이터 iOS 26.5, dev 빌드)

- 권한 행(사진·위치·알림)을 `a994379` 이전 코드로 누르면 `ERROR [Invariant Violation: new NativeEventEmitter() requires a non-null argument.]`
  (직전 `WARN PushNotificationIOS has been extracted…`)가 재현된다. dev 빌드라 앱은 죽지 않고 화면 아래에 오류 알림이 뜬다.
  `a994379` 이후 코드는 같은 흐름에서 오류 로그가 없고 iOS 설정 앱이 열린다.
- 남은 동적 `await import(...)`는 `expo-*`·`llama.rn`뿐이고 `react-native`는 없다.
- iOS에도 「배터리」 행(`settings-perm-battery`)이 있다. `expo-intent-launcher`가 iOS에서 던지고 앱 설정으로 떨어진다(앱은 죽지 않는다).

## 저장소 소유자 결정 (2026-10-09)

1. **배터리 행(과 온보딩 배터리 단계)은 iOS용 문구로 바꾼다.** 행은 남기고 안내를 iOS에 맞는 것(예: 저전력 모드를 끄면 제때 써요)으로 바꾸며 앱 설정으로 연결한다.
   문구는 `src/i18n/catalogs/ko/`에 둔다(062).
2. **자동 쓰기 토글·「매일 쓰는 시각」은 iOS에서도 그대로 둔다.** iOS BGTask의 실제 동작은 백그라운드 실측 과제로 미루고 스펙의 「미확인」에 적는다.

## 접근

1. **먼저 훑는다.** Maestro(iOS 시뮬레이터)로 설정의 모든 행, 개발자 메뉴(모듈 상태·모듈 다시 받기·온보딩부터 다시·끄기), 진단(일곱 묶음·한 번 써 보기·자동 쓰기 지금 실행),
   상태 흉내 날짜 대화상자를 누르고 Metro·시뮬레이터 로그의 오류와 화면을 모은다. 후보를 미리 고치지 않고 **실제로 걸린 것만 고친다.**
2. **판정이 필요한 후보**(`BackHandler`가 iOS에 없어 겹을 닫는 수단, 모듈 다시 받기의 셀룰러 문구, 「사진의 위치 정보」 꼬리표)는 훑은 결과를 보고 필요할 때만 소유자에게 묻는다
   (고칠 수 없는 것은 코드가 정하지 않는다).
3. **고치는 방식은 둘로 한정한다.**
   - 플랫폼 분기는 `src/app/`의 순수 판정 하나로 모은다(`on-device.ts`의 `isIOS()`는 호출 시점 `require`다 — 같은 방식). 화면·통로가 `Platform`을 직접 읽는 곳을 늘리지 않는다.
   - iOS에서 던지는 `await import`가 더 있으면 066처럼 호출 시점 `require`로 바꾼다(남은 것은 `expo-*`뿐이라 훑기에서 걸릴 때만).
4. **테스트**: 소스 계약(동적 `react-native` import 금지·플랫폼 분기가 한 곳), iOS 문구 단위 테스트, 위 Maestro 흐름 파일. `scripts/run-device-tests.mjs`의 iOS 갈래 등록은
   e2e 과제와 겹치므로 이번에는 흐름 파일만 두고 등록 여부는 그 과제와 맞춘다. 새 흐름을 `FLOWS`에 등록하지 않으면 초록불이 아무것도 검증하지 않는다는 AGENTS 규칙을 스펙에 적는다.

## 위험

- 「iOS 대응」 전반으로 번지기 쉽다 — 설정·개발자·진단 화면에서 누를 수 있는 것만 본다.
- 시뮬레이터(iOS 26.5, dev 빌드)와 피드백 환경(iOS 27.0.1 실기기, 배포 빌드)이 다르다. dev는 오류를 알림으로 보이고 배포는 앱이 종료된다 — 시뮬레이터 통과가 실기기 통과가 아니다.
- 시뮬레이터에 설치된 앱은 옛 `ios/`(`com.anonymous.alpharium`)로 만든 빌드다. 훑기 전에 현재 `app.json`으로 prebuild한 프로젝트를 쓸지 판단한다.
