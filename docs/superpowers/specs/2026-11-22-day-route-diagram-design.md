# 쓴 날 일기 화면의 동선 도식 — 설계

로드맵 「앱 화면에 하루의 장소를 보여준다」의 설계다. 트랙: 전체(새 `app/` 변환·새 화면 부품·문구·테스트로 변경 파일 5개 초과, 수용 기준 3개 초과).

## 목적

쓴 날 일기를 읽다가 **그날 사진이 찍힌 자리들을 시간순으로 이은 동선**을 한눈에 본다. 지도 배경 없이 점·선·번호와 장소 이름으로 그린 도식이다. 외부 요청도, 새 권한도, 새 수집도 없다.

## 소유자가 정한 것 (2026-11-22)

- 모양: 지도 배경 없는 **동선 도식**(실제 지도 배경 아님).
- 장면: **쓴 날 일기 화면**. 안 쓴 날 재료 화면·별도 화면은 이번 범위가 아니다.
- 위치는 **사진 EXIF 좌표만** 쓴다. 사진 없는 날의 위치 수집(C)은 이 과제 밖이고 A가 끝난 뒤 실험한다.

## 읽는 법의 약속 (원칙 V)

도식의 선은 **GPS 궤적이 아니라 사진이 찍힌 자리를 시간순으로 이은 것**이다. 사진 사이에 실제로 어디를 지났는지는 모른다. 도식 아래 한 줄이 그렇게 말한다. 위치를 모르는 날을 기본값으로 채우지 않는다.

## 결정 (에이전트 판단 — 결정 표에 올린다)

| 결정 | 근거 |
| --- | --- |
| **새로 저장하는 값이 없다.** 쓴 날 지면을 열 때 그 날의 사진 좌표를 다시 읽어 위치를 얻고, 저장된 `entry.places`(이름·시각)와 합친다 | 121 코드 리뷰(R9)가 하루 동선 좌표를 백업되는 일기 파일에 늘리지 않기로 했다. 다시 읽기는 옛 일기에도 통한다 |
| 다시 읽은 자리 수가 `entry.places`와 **같을 때만 도식**을 그린다. 다르면(사진을 지웠거나 더했거나) 이름·시각 목록만 보인다 | 둘이 어긋난 채 합치면 이름과 위치가 엉킨다. 일기 글과 같은 자리 목록에 맞춘다 |
| 도식은 **`entry.places`가 있는 일기**(121 이후)에서만 쓴다. 옛 일기·자리가 1곳 이하인 날은 도식 없이 목록(1곳)이거나 아무것도 없다 | 이름 없이 번호만 있는 도식은 뜻이 약하다. 1곳은 이을 선이 없다 |
| 좌표를 화면에 넘기지 않는다. `app/`에 새 변환(`day-route.ts`, 순수)이 자리 좌표를 **0~1 상대 위치**로 정규화해 넘긴다 | `day-preview.ts` DP6 「화면은 좌표를 모른다」를 지킨다 |
| 투영은 위도에 따른 가로 보정(`cos(lat)`)을 한 등각 평면, 가로세로 비율을 유지해 상자에 맞추고 안쪽 여백을 둔다. 모든 점이 100m 안에 겹치면(퇴화) 도식 없이 목록만 보인다 | 한 자리에서만 찍은 날과 먼 거리를 다닌 날을 같은 규칙으로 그린다 |
| 점에는 **번호**를 달고 이름·때는 도식 아래 **범례 목록**에 둔다(「1 오전 · 이름」) | 점 옆 글자 겹침을 풀 필요가 없고 화면 낭독이 목록 순서대로 읽힌다 |
| **`react-native-svg`를 들이지 않는다.** `View`(점은 정사각, 선은 회전한 얇은 `View`)로 그린다 | 네이티브 의존성이 늘면 prebuild·재설치가 필요하다. 점·선 수십 개면 충분하다 |
| 자리는 시간순 **앞에서 12곳**까지 그리고 넘으면 「외 N곳」 한 줄로 한계를 말한다(일기 글처럼 세 곳으로 자르지 않는다). 12는 사람이 정한 값이다 | 신호 수집에는 사진 상한이 없어(012) 자리가 수십 곳일 수 있다. 번호·범례가 읽히는 한도 안에서, 잘린 것을 숨기지 않는다 |
| 자리는 **본문 아래**, 지면 맨 끝에 둔다. 위나 캐러셀 옆에 두지 않는다 | 첫 화면의 본문 노출(083, 글꼴 1.0배 8줄·2.0배 3줄)을 지킨다. 스크롤 접힘(052)에 영향이 없다 |
| 신호 읽기가 오래 걸리면 도식 칸은 비워 두고 목록을 먼저 보인다. 읽지 못했으면(`unknown`) 도식만 없다 | 쓴 날 지면이 읽기를 기다려 막히면 안 된다. 사진 권한 거부는 이미 제약 띠가 말한다(108) |
| 색은 토큰만: 점·선 `text`, 시작점만 `accent`, 선은 직선·1px 이상 굵기, 그림자·곡선·그라데이션 없음 | `design/DESIGN.md` 「하지 않는 것」 |
| 도식 아래 한 줄 설명 「사진이 찍힌 자리를 시간순으로 이은 거예요」는 갈래 D(상태 설명)다 | 108의 다섯 갈래 규칙 |

## 구성

1. `src/app/day-route.ts` — 순수. 자리 목록(`PlaceVisit[]`)과 저장 자리(`SavedPlace[]`)를 받아 도식 모델(`DayRoute`: `ok`+정지점 배열(번호·상대 위치·이름·때) 또는 목록만·없음)을 만든다. 좌표 절대값은 반환하지 않는다.
2. 신호 다시 읽기 — 쓴 날을 열 때 그 날의 `PhotoPlaces`를 읽는 기존 신호 경로를 재사용한다(`day-preview`와 같은 수집기, 새 수집 코드 없음).
3. `src/ui/DayRouteDiagram.tsx` — 모델만 받아 그린다(신호·좌표를 모른다). `WrittenDayPaper` 끝에 붙는다.
4. 문구 — `src/i18n/catalogs/ko/home.ts`(도식 이름·설명 한 줄·화면 낭독).
5. 테스트 — 정규화 경계(1점·공선·가까운 점·위도), 자리 수 불일치 대체, 컴포넌트(점·선·번호·범례, 2.0배), 소스 계약(지도 라이브러리·`fetch` 없음, `ui/`가 신호·좌표에 닿지 않음).

## 수용 기준

1. 자리가 2곳 이상이고 다시 읽은 자리 수가 저장 자리 수와 같은 쓴 날에, 본문 아래에 번호 점·직선·범례 목록·한 줄 설명이 보인다.
2. 자리 수가 어긋나거나 위치를 읽지 못한 날은 도식 없이 저장된 이름·시각 목록만 보이고, 자리가 1곳이거나 `entry.places`가 없는 일기는 도식이 없다. 둘 다 거짓 값으로 채우지 않는다.
3. 외부 요청과 새 권한과 저장 일기의 새 필드가 없고, 절대 좌표가 `app/`를 넘어 화면에 닿지 않는다(소스 계약).
4. 글꼴 2.0배·작은 화면에서 쓴 날 첫 화면의 본문 노출이 바뀌지 않는다.

## 못 보는 것 · 위험

- 사진 좌표 다시 읽기는 사진 보관함 권한과 사진이 지워지지 않은 것에 기댄다. 지워진 날은 목록만 보인다(결정 반영).
- 다시 읽기가 화면을 열 때마다 사진 서비스를 부르는 비용·iOS 사진 서비스 막힘(AGENTS 「iOS 백그라운드 요청」의 4099) 영향은 실기기에서 본다. 백그라운드가 아니라 앞에서 도는 읽기라 막힘은 적을 것으로 추정하지만 관측은 없다.
- 선 굵기·점 크기·번호 글자 크기는 사람이 정한 값이다(보드 밖 초안).
- C(사진 없는 날 위치 수집)는 범위 밖이다.
