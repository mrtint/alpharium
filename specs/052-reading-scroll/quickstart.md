# Quickstart: 읽기 스크롤 (052) 검증

## 1. 기기 없는 검증

```bash
npm run test:logic -- reading-scroll
npm run test:ui -- reading-scroll written-day-home diary-home date-jump

npm run lint
```

## 2. 실기기 준비 (dev, `pm clear` 없음 — 모델 보존)


**★ 실기기에서만 잡힌 결함 셋**(기기 없는 테스트 3070여 개가 통과한 채였다 — 011·013·020·033과 같은 계열):

1. **접는 감쌈의 되먹임**: 안쪽을 흐름에 둔 채 `maxHeight`만 옮기니 안쪽이 눌려 잰 높이가 108 → 64 → 41 → 21로 줄고 그 값으로
   다시 높이를 정해 헤더가 흔들렸다. 지면 스크롤이 튀며 빠른 위 스크롤의 절반이 맨 위에 못 닿고 접힌 채 멈췄다(baseline은 6/6
   맨 위 도달). 안쪽을 절대 배치로 빼서 8/8, 10/10 도달. (`RSDBG` 임시 로그의 `sh` 값이 단서였다.)
2. **위치가 그대로인 `onScroll`이 접힘을 되돌렸다**: 방금 펼친 뒤 같은 위치의 사건이 오면 `y >= previousY`가 「아래」로 읽혀
   되접혔다(PAPER4).
3. **내용 크기의 부동소수 흔들림이 「다시 쓰기」 바를 내렸다**: 773.9999 ↔ 774.0001로 오는 사건이 끝 판정을 줄어든 높이로
   다시 돌렸다(PAPER5). 「이 사건을 다시 판정하지 않는다」를 정확한 같음으로 쓰면 뚫린다 — 1px 톨러런스.

**미확인**: 손가락 손맛(문턱 8px·2px), 자정·날 바뀜 순간, 접힘 끝의 ±8px 흔들림의 원인, 큰 글꼴(1.3배)에서의 접힘, 안 쓴 날의
스크롤(FR-016 — 스크롤이 생기는 큰 글꼴에서는 확인하지 않았다), 알림으로 접힌 채 날이 바뀌는 실기기 경로(D8).

**기기에 남긴 상태 변화**: 앱을 `am force-stop`으로 세 번 다시 띄웠다(WorkManager 자동 생성 잡이 취소됐고 앱을 다시 연 뒤
`defineTask`로 재등록된다 — 027 §1). Metro가 어제부터 응답하지 않아 프로세스를 종료하고 다시 띄웠다. 일기·모델·설정은 손대지 않았다.
