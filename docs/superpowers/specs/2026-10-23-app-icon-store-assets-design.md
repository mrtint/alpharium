# 앱 아이콘과 스토어 등록 에셋 — 설계

로드맵 「앱 아이콘과 스토어 등록 에셋」(C8·C10·W4, 결정 D5·D8). 스펙 번호 102.

## 목적과 성공 기준

두 스토어에 올릴 수 있는 모습으로 앱의 얼굴을 갖춘다.

- 두 플랫폼 런처에 새 아이콘이 보인다(실기기).
- 스토어 등록 에셋이 콘솔 요건을 채운다.
- 헌법 원칙 III(모델 이름·파라미터 수를 화면·에셋에 쓰지 않는다)과 V(스크린샷은 실기기에서 실제로 쓴 일기)를 지킨다.

## 소유자 결정 (2026-10-23)

| 결정 | 내용 |
| --- | --- |
| D5 태블릿 | **iPhone 전용.** `ios.supportsTablet: false`. iPad 스크린샷은 만들지 않는다. |
| D8 국가·언어 | **한국만, 한국어 한 벌.** 앱 화면 문구가 `ko` 카탈로그뿐이라 일치한다. |
| 아이콘 방향 | **빨강 면 + 마크.** 마크는 시안 B(기하 「P」). |

## 이미 해 본 것 (시안, 실측)

시안으로 워크트리에 PNG를 만들어 갤럭시(SM-S901N)에 설치해 런처에서 봤다. iPhone 14 런처는 소유자가 아직 보지 않았다.

- 안드로이드는 108dp 캔버스 중 가운데 72dp만 보인다. 글자 높이를 캔버스의 56%(배율 2.3)로 잡으니 보이는 영역의 약 83%를 채워 너무 컸다. **배율 1.6**(foreground·monochrome)으로 줄이니 적당했다. iOS 아이콘은 배율 2.3(캔버스 높이의 56%) 그대로다.
- `assets/`의 PNG를 바꾸면 `npx expo prebuild --platform android --clean`을 다시 돌려야 런처에 반영된다(안 돌리면 이전 아이콘이 남는다).
- 안드로이드 13+ 테마 아이콘(monochrome)과 iPhone 런처의 모서리 깎임은 아직 보지 못했다.

## 설계

### 1. 설정

- `app.json`의 `ios.supportsTablet`을 `false`로 바꾼다. 계약 테스트가 값을 잠근다.
- C10: iPad 호환 모드는 iPad **시뮬레이터**에서 점검한다(실기기 iPad는 없다 — 시뮬레이터 확인이라고 기록에 적는다, 원칙 V). 깨지는 곳은 이 과제에서 고치지 않고 후속 과제로 남긴다.
- 안드로이드 adaptive `backgroundColor`는 `#E6F4FE`(Expo 기본)에서 accent 빨강으로 바꾼다. 이 값은 시안에서 이미 적용했다.

### 2. 아이콘

- 정본은 SVG 하나다(`design/` 아래). 색은 `design/tokens.json`의 `accent`·`accentForeground`와 같다. PNG는 이 정본에서 나온다.
- 산출물: iOS 1024²(알파 없음), 안드로이드 adaptive foreground·background·monochrome, Play 스토어 아이콘 512², favicon(48²).
- 글리프 배율: iOS 2.3, 안드로이드 1.6(위 실측). 기준은 정본 SVG 옆에 상수로 적는다.
- 래스터화는 `pngjs`로 직접 그린다(시안 생성기 `gen-icon.cjs`의 방식). SVG 렌더러를 새로 들이지 않는다.
- 계약 테스트: 크기, iOS 아이콘의 알파 없음, 안드로이드 foreground의 글리프가 안전 영역 안, `app.json`이 가리키는 경로 실재. 위반 주입으로 검증한다.
- 앱 안 스플래시 마크(빨강 정사각)는 바꾸지 않는다.

### 3. 스토어 등록 에셋 (한국어 한 벌)

- **스크린샷은 실기기에서 실제 일기를 쓴 화면**이다. 합성 데이터와 모의 일기를 쓰지 않는다(원칙 V).
- 장면(안): ① 홈 ② 쓰는 중 ③ 쓴 날(사진 캐러셀+본문) ④ 달력 ⑤ 설정 「이 휴대폰」.
- 앱 화면 원본을 그대로 쓴다. 문구를 얹은 프레임·그림자·그라데이션은 만들지 않는다(디자인 시스템). 기능 그래픽(Play 1024×500)만 아이콘 마크와 앱 이름으로 만든다.
- 규격: Play 휴대폰 스크린샷 최소 4장·기능 그래픽 1024×500·아이콘 512². App Store iPhone은 6.9형 1320×2868 또는 6.5형. **제출 시점의 콘솔 요건은 구현 단계에서 다시 확인한다.**
- 설명문은 `store/ko/`에 둔다: 제목 30자 이내, 짧은 설명 80자 이내, 긴 설명. 모델 이름·파라미터 수를 쓰지 않고(원칙 III) 온디바이스·사진 처리만 서술한다. 방침(`site/privacy`)·지원 문장과 대조해 어긋나지 않게 한다. 글자 수 한도와 금지어는 테스트로 잠근다.
- `src/i18n/catalogs/ko/`, `src/inference/`, `modules/pocketlog-continued-write/`, 홈·설정 화면 문구, `site/`는 건드리지 않는다.

### 4. 실기기 확인

두 플랫폼 런처에서 새 아이콘을 눈으로 본다. 스크린샷 촬영은 실기기에서 일기를 쓰는 작업이라 기기를 오래 쓰며, 다른 세션과 사전에 조율한다.

## 열린 질문 (clarify에서 닫는다)

1. **App Store 스크린샷 규격**: iPhone 14 화면(1170×2532)은 App Store 요구 크기(6.9형 1320×2868 등)와 다르다. 실기기 화면을 올릴 수 있는 길은 (a) 6.5형 규격이 허용하는 크기로 맞춘다 (b) 시뮬레이터로 규격 크기를 찍되 일기는 실기기에서 쓴 것을 쓴다 — 어느 쪽이 원칙 V와 콘솔 요건을 함께 채우는가.
2. **스크린샷에 쓸 사진**: 소유자 실제 사진이다. 개인정보가 보이는 사진을 쓰지 않는 기준.
3. **iOS 아이콘 배율**: iPhone 14 런처를 아직 보지 않았다. 확정하려면 한 번은 눈으로 봐야 한다.
4. **업로드**: 이 과제는 에셋을 만드는 데까지다. 콘솔 업로드는 하지 않는다.
