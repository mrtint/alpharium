# Quickstart: 뼈대가 갖춰졌는지 확인하기

**기능**: 프로젝트 뼈대와 의존성 기반 세우기 | **날짜**: 2026-08-12

이 문서는 이 기능이 실제로 동작하는지 **끝에서 끝까지 확인하는 절차**다. 구현 코드는 담지
않는다 — 무엇을 돌려서 무엇을 봐야 하는지만 적는다.

---

## 사전 준비

| 필요한 것 | 왜 | 없으면 |
| --- | --- | --- |
| Node 20.19 이상 | `package.json`의 `engines` | 설치 불가 |
| 안드로이드 실기기 (arm64-v8a) | 온디바이스 추론 모듈 검증 | **A·B·D만 확인 가능**, C는 건너뜀 |
| Maestro | 실기기 자동 테스트 | C 건너뜀 (FR-021d — 실패가 아니다) |
| 데스크톱 추론 서버 | local의 서버 추론 확인 | B의 일부만 확인 |

**Expo Go로는 실행할 수 없다.** 네이티브 추론 모듈이 Expo Go에 없기 때문이다(헌법 원칙 I의
기술적 귀결). development build가 필요하다.

---

## A. 기기 없이 확인 (항상 가능)

기기가 없어도 **반드시 전부 통과해야 하는** 갈래다(FR-021c).

```bash
npm ci
npm run lint          # eslint + tsc + 헌법 검사
npm test              # 기기 불필요 테스트
```

**기대 결과**:

| 확인 항목 | 기대 | 근거 |
| --- | --- | --- |
| `npm test`가 "테스트가 없다"로 실패하지 않는다 | 통과 | FR-019 |
| 환경 판정 테스트가 돈다 | 통과 | [contracts/environment.md](contracts/environment.md) |
| dev·prod에서 `desktop-server`가 거부되는 테스트가 돈다 | 통과 | **FR-012 — 가장 중요** |
| 헌법 검사가 위반 0건을 보고한다 | 통과 | FR-026 |
| 실기기 테스트가 **건너뜀**으로 보고된다 | `skipped` | FR-021e |

**마지막 줄을 확인하라.** 건너뛴 것이 통과로 집계되면 이 기능은 실패다(SC-015). 전부 초록불인데
온디바이스는 한 번도 검증 안 된 상태가 그것이다.

### 검사가 실제로 잡는지 확인 (SC-012)

검사가 통과만 하고 아무것도 못 잡는 상태가 가장 위험하다. 일부러 위반을 넣어 본다.

```bash
# prod 설정에 서버 주소 키를 넣어 본다
echo 'EXPO_PUBLIC_AI_API_BASE_URL=http://localhost:8080' >> .env.production
npm run lint          # 실패해야 한다. 파일과 키가 지목돼야 한다
git checkout .env.production
```

실패하지 않으면 검사가 제 역할을 못 하는 것이다.

## B. 시뮬레이터에서 확인 (local)

```bash
npx expo start
# 시뮬레이터에서 앱 실행
```

**기대 결과**:

| 확인 항목 | 기대 | 근거 |
| --- | --- | --- |
| 앱이 뜬다 | 화면 표시 | FR-002, SC-006 |
| 진단 화면에 환경이 `local`로 보인다 | `local` | FR-017 |
| 추론 위치가 `desktop-server`로 보인다 | 기본값 | FR-010 |
| 모듈 상태가 `unavailable`로 보인다 | **오류가 아님** | User Story 2 시나리오 3 |
| 코드를 고치면 화면에 반영된다 | 반영됨 | FR-003 |

**`unavailable`이 빨간 오류로 보이면 안 된다.** 시뮬레이터에 네이티브 모듈이 없는 것은 정상이고,
이것을 오류로 다루면 SC-006(시뮬레이터만으로 작업)이 깨진다.

### 서버가 꺼져 있을 때

데스크톱 추론 서버를 끄고 다시 확인한다.

| 확인 항목 | 기대 | 근거 |
| --- | --- | --- |
| 서버에 닿지 못했다는 사실이 드러난다 | 진단에 실패로 표시 | Edge Case |
| **대체 응답으로 넘어가지 않는다** | 응답 없음 | **헌법 원칙 I, FR-016** |

조용히 그럴듯한 답이 나오면 헌법 위반이다.

## C. 실기기에서 확인 (dev) — 옵셔널

기기가 있을 때만 돈다. 없으면 건너뛴다(FR-021d).

```bash
npx expo run:android      # development build
maestro test .maestro/skeleton.yml
```

**기대 결과**:

| 확인 항목 | 기대 | 근거 |
| --- | --- | --- |
| 앱이 실기기에서 뜬다 | 화면 표시 | FR-001 |
| 환경이 `dev`로 보인다 | `dev` | FR-017 |
| **모듈 상태가 `loaded`로 보인다** | `loaded` | **FR-006, SC-002** |
| 추론 위치가 `on-device`다 | `on-device` | FR-012 |

**이것이 이 기능의 진짜 검증이다.** A와 B가 전부 통과해도 이 단계를 한 번도 돌리지 않았다면
온디바이스는 검증되지 않은 것이다(명세 「가정」). **기능이 끝났다고 말하려면 최소 한 번은
여기까지 와야 한다.**

### 관측할 것 (research.md §1의 미확인 항목)

`getBackendDevicesInfo()`가 실기기에서 실제로 무엇을 반환하는지 **아직 재지 않았다**. 이
단계에서 처음 관측된다. 반환값이 예상과 다르면 모듈 적재 판정 기준을 고쳐야 한다.

관측한 값은 문서에 남긴다 — 언제 어디서 쟀는지와 함께(헌법 원칙 V).

**기대 결과**:

## 완료 판정

이 기능이 끝났다고 말하려면:

- [ ] A 전부 통과 (기기 없이)
- [ ] A의 "검사가 실제로 잡는지" 확인 통과
- [ ] B 전부 통과 (시뮬레이터)
- [ ] **C 최소 1회 통과 (실기기)** — 건너뛴 채로 완료 선언하지 않는다
- [ ] D 확인
- [ ] `getBackendDevicesInfo()` 실기기 관측값을 문서에 기록

**C를 건너뛰고 완료를 선언하면 헌법 원칙 V 위반이다.** 관측하지 못한 것을 관측한 것처럼
다루는 것이기 때문이다.
