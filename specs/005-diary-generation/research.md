# Research: 실제 일기 생성

**Feature**: 005-diary-generation | **Date**: 2026-08-17

이 문서는 스펙이 남긴 미지수를 푼다. **실측과 짐작을 구분해 적는다**(헌법 원칙 V).
확인한 것에는 언제 어디서 확인했는지를 남기고, 짐작에는 짐작이라고 적는다.

---

## §1. `llama.rn` 0.12.9가 실제로 주는 것

**출처**: 설치본 타입 직접 확인 (2026-08-17,
`node_modules/llama.rn/lib/typescript/index.d.ts`·`types.d.ts`). **실측이다** — 문서나
기억이 아니라 이 저장소에 설치된 그 버전을 읽었다.

### Decision — 쓰는 것은 다섯 개뿐이다

| 무엇 | 시그니처 | 왜 쓰나 |
| --- | --- | --- |
| `initLlama` | `(ContextParams, onProgress?) => Promise<LlamaContext>` | 모델을 연다 (FR-007) |
| `ctx.completion` | `(CompletionParams, callback?) => Promise<NativeCompletionResult>` | 생성한다 (FR-001) |
| `ctx.stopCompletion` | `() => Promise<void>` | 끊는다 (FR-021b·c) |
| `ctx.release` | `() => Promise<void>` | 닫는다 (FR-008, FR-009) |
| `getBackendDevicesInfo` | `() => Promise<...>` | 001이 이미 쓴다. 건드리지 않는다 |

**`callback`을 주지 않는다**(FR-028b). 토큰 콜백은 생성 중인 글을 흘려보내는 통로이며,
그것이 화면에 닿으면 판정을 통과하지 않은 텍스트가 사용자에게 읽힌다. **콜백을 아예 넘기지
않으면 그 경로가 코드에 존재하지 않는다** — 조심해서 안 쓰는 것보다 못 쓰게 하는 쪽이 낫다
(003 types.ts의 판단과 같다).

**`parallel.*` 갈래를 쓰지 않는다.** 한 번에 하나만 연다는 FR-008과 정면으로 어긋난다.

### Rationale — `completion()`이 우리에게 위험한 것을 함께 준다

`NativeCompletionResult`는 이렇게 생겼다(실측):

```
text, content, reasoning_content, tool_calls, chat_format,
tokens_predicted, tokens_evaluated, draft_tokens, draft_tokens_accepted,   ← 원칙 IV 위반 소재
truncated, stopped_eos, stopped_word, stopped_limit, stopping_word,
context_full, interrupted, tokens_cached,
timings: { prompt_ms, prompt_per_second, predicted_ms,
           predicted_per_token_ms, predicted_per_second, ... }              ← 원칙 IV 위반 소재
```

**`timings`와 `tokens_*`는 헌법 원칙 IV가 금지한 바로 그 값이다.** 이 저장소를 되돌리게
한 것이 「측정 장치와 제품이 같은 자리에 쌓인 것」이었고, 여기서 그 값이 **네이티브 모듈에서
공짜로 흘러 들어온다.** 아무것도 하지 않으면 그것이 어댑터를 지나 위로 샌다.

**그래서 이 값들은 어댑터 경계를 넘지 못한다.** 002가 `DiaryDraft`를 `{ text: string }`
하나로 둔 것이 이 상황을 미리 막아 둔 것이었다 — 어댑터가 돌려주는 타입에 담을 자리가 없다.
**포트 구현이 `NativeCompletionResult`에서 필요한 것만 꺼내고 나머지를 버린다.**

### 쓸모 있는 것 — 잘림 판정이 공짜로 온다

`truncated`·`stopped_limit`·`context_full`·`interrupted`가 **FR-016d(중간에 잘린 글은
거부)를 우리가 문자열로 추측하지 않아도 되게 한다.** 문장 부호를 보고 "잘린 것 같다"를
판정하면 그것이 곧 휴리스틱이고 임계값이며 원칙 IV로 가는 길이다. **모듈이 사실을 알려주므로
짐작할 필요가 없다.**

- `stopped_limit` — `n_predict`에 걸려 멈췄다 → **거부**(FR-016d)
- `truncated` / `context_full` — 컨텍스트가 모자랐다 → **거부**
- `interrupted` — `stopCompletion()`으로 끊겼다 → **거부**(FR-021c)
- `stopped_eos` — 모델이 스스로 끝냈다 → **이것만 정상 종료**

### Alternatives considered

- **토큰 콜백으로 진행률 표시** — 기각. FR-028a·b가 금지한다. 콜백을 안 쓰면 지표가 생길
  자리 자체가 없다.
- **`parallel.completion`으로 취소 다루기** — 기각. `stop()`을 주지만 병렬 큐가 딸려오고,
  FR-008(한 번에 하나)과 어긋난다. `stopCompletion()`으로 충분하다.
- **`messages` + jinja 채팅 템플릿** — §4에서 다룬다.

## §2. 어떻게 끊는가 — FR-021b의 실제 구현

**Decision**: `AppState`가 `active`를 벗어나면 `ctx.stopCompletion()`을 부르고,
결과의 `interrupted`를 보고 실패로 처리한다. **`ctx.release()`까지 간다**(FR-021d).

**Rationale**: `stopCompletion()`은 `completion()`의 Promise를 **거부시키지 않는다** —
`interrupted: true`인 결과로 **정상 resolve된다**(타입상 `interrupted`가 결과 필드이므로).
그러므로 「끊겼다」는 예외가 아니라 값으로 온다. 이것은 002가 실패를 값으로 둔 구조와 맞고,
`try/catch`로 끊김을 잡으려 하면 놓친다.

**중요**: 끊긴 결과에도 `text`에 **거기까지 생성된 글이 들어 있다.** 그것을 저장하면
FR-021c 위반이다. **판정이 `interrupted`를 먼저 보고 거부하므로 그 글은 통과하지 못한다** —
판정을 어댑터 안쪽이 아니라 바깥에 두면 이 방어가 늦는다(§5).

**짐작인 부분**: 안드로이드에서 백그라운드로 간 직후 네이티브 추론 스레드가 얼마나 오래
살아 있는지는 재보지 않았다. `stopCompletion()`이 즉시 듣지 않을 수 있고, 그때도
`release()`가 안전한지는 **실기기에서 확인해야 한다**(quickstart D3).

**Alternatives**: `AppState` 대신 화면 언마운트로 감지 — 기각. 화면을 안 만들기로 했고
(FR-027), 앱이 백그라운드로 가도 화면은 언마운트되지 않는다.

## §3. 모델을 여는 값 — `ContextParams`

**Decision**: `{ model: <경로>, n_ctx: 2048, n_gpu_layers: 0 }`로 시작한다.

| 값 | 정함 | 근거 |
| --- | --- | --- |
| `model` | 003이 저장한 파일 경로 | 003 `storage.ts`가 아는 것을 받는다 |
| `is_model_asset` | 쓰지 않음(`false`) | 번들 자산이 아니라 내려받은 파일이다 |
| `n_ctx` | **2048 (짐작)** | 프롬프트 + 일기가 들어갈 만하고, 1.5~2.4B 모델의 KV 캐시가 감당할 만한 크기. **실측이 아니다** |
| `n_gpu_layers` | **0 (짐작)** | 안드로이드 GPU 오프로드는 기기마다 다르고 실패가 조용하다. 0이 가장 안전한 시작점 |
| `n_threads` | 주지 않음 | 기본값에 맡긴다. 정하면 그것이 성능 튜닝이고 원칙 IV의 언저리다 |

**Rationale**: **`n_ctx`가 이 기능에서 가장 미끄러운 숫자다.** 작으면 `context_full`로
거부가 잦아지고, 크면 메모리를 먹어 기기가 죽는다. 2048은 짐작이며
**실기기에서 재면 근거가 실측으로 바뀐다**(quickstart D4). 004의 사진 상한 200과 같은
성격의 값이다.

**짐작임이 코드에 남아야 한다**(원칙 V, 스펙 Assumptions). 004의 `DEFAULT_PHOTO_LIMIT`가
주석으로 「200은 짐작이며 실측이 아니다」를 남긴 것과 같은 형태로 쓴다.

## §4. 프롬프트를 어떻게 넘기는가 — `prompt` vs `messages`

**Decision**: **`prompt` 문자열 하나로 넘긴다.** `messages`·`jinja`·채팅 템플릿을 쓰지
않는다.

**Rationale**: 세 가지다.

1. **다섯 모델의 채팅 템플릿이 서로 다르다.** `messages`를 쓰면 각 GGUF에 박힌 jinja
   템플릿이 프롬프트를 다르게 감싸고, 그러면 **FR-005(데스크톱과 온디바이스가 같은 프롬프트)
   와 FR-014(다섯이 같은 프롬프트 구조)를 확인할 수 없다.** 최종적으로 모델에 들어가는
   문자열이 모델마다 달라지기 때문이다.
2. **FR-016b-1(되뱉기 = 프롬프트 문장이 출력에 그대로 있는가)이 문자열 비교로 성립하려면
   우리가 보낸 문자열을 알아야 한다.** 템플릿이 중간에 끼면 "우리가 보낸 것"이 무엇인지
   모호해진다.
3. **데스크톱 서버 경로와 맞추기 쉽다**(FR-005a). 양쪽이 같은 문자열을 보내면 된다.

**Trade-off를 정직하게 적는다**: instruct 모델은 자기 채팅 템플릿을 쓸 때 지시를 더 잘
따른다. `prompt` 평문은 **되뱉기·형식 이탈이 늘어날 수 있다.** 그것이 FR-016의 판정이
존재하는 이유이며, **거부가 잦으면 그때 다시 본다** — 지금 템플릿을 도입하면 위 세 가지
검증 가능성을 먼저 잃는다.

**Alternatives considered**: 캐릭터별 템플릿 지정 — 기각. FR-014가 금지한다(캐릭터에서
오는 것은 언어뿐).

## §5. 판정을 어디에 두는가

**Decision**: **판정은 `src/diary/`의 순수 함수이고, 어댑터가 그것을 부른다.**
`generate()`가 이미 판정된 결과를 돌려준다.

**Rationale**: 판정을 파이프라인(어댑터 바깥)에 두면 **어댑터가 거부될 텍스트를 담은
`DiaryDraft`를 돌려주는 순간이 존재한다.** 그 순간이 존재하면 언젠가 누가 그것을 쓴다 —
002가 `GenerationFailure`에 `text`를 두지 않은 이유가 바로 「존재하지 않게 하는 것」이었다.

어댑터가 판정까지 마치면 **`DiaryDraft`는 통과한 글만 담는 타입이 된다.** 002의 계약을
넓히지 않으면서(FR-025) 불변식이 하나 강해진다.

**판정 자체는 기기를 모른다** — 문자열과 몇 개의 불리언만 본다. 그래서 온디바이스와
데스크톱이 같은 판정을 쓰고(FR-005a), 기기 없이 전부 검증된다(FR-023, SC-010).

**Alternatives**: 파이프라인에 새 단계 추가 — 기각. `PipelineStage`를 넓히는 것이고
(FR-025 위반), 위 「존재하지 않게 하는 것」을 잃는다.

## §6. 언어 판정 (FR-016c) — 상한이 먼저다

**Decision**: **문자 범위의 비율로 본다. 임계값은 「하나라도 있는가」가 아니라
「주된 문자가 무엇인가」이며, 갈래를 더하지 않는다**(FR-018b).

| 캐릭터 | 요구 | 판정 |
| --- | --- | --- |
| `quiet`·`narrative`·`imaginative` | 한국어 | 한글 음절(가–힣)이 **있어야** 한다 |
| `chinese` | 중국어 | 한자가 있어야 하고 **한글이 없어야** 한다 |
| `english` | 영어 | 라틴 문자가 있어야 하고 **한글·한자가 없어야** 한다 |

**Rationale**: 헌법이 금지한 것은 구체적이다 — qwen·gemma가 **한국어로 쓰는 것**이다.
그러므로 판정도 그만큼만 하면 된다. 「한국어다움」을 점수로 재지 않는다.

**여기가 원칙 IV로 미끄러지기 가장 쉬운 자리다**(체크리스트의 남은 위험). 비율을 계산하는
순간 임계값이 생기고 임계값은 점수다. **그래서 판정을 「있는가/없는가」의 불리언 조합으로
둔다** — 숫자를 만들지 않으면 그것으로 모델을 견줄 수 없다.

**짐작인 부분**: 한국어 일기에 한자나 라틴 문자가 섞이는 것은 정상이다(고유명사·영어 단어).
그래서 한국어 판정은 「한글이 있는가」만 보고 다른 문자를 금지하지 않는다. **반대로 중국어·
영어 캐릭터는 한글을 금지한다** — 헌법이 그 방향만 못 박았기 때문이다.

## §7. 되뱉기 판정 (FR-016b-1) — 무엇을 비교하는가

**Decision**: **프롬프트를 줄 단위로 쪼개고, 의미 있는 길이의 줄이 출력에 그대로
들어 있으면 거부한다.**

**Rationale**: 프롬프트 전체가 그대로 나오는 경우만 잡으면 부분 되뱉기를 놓치고, 짧은
조각까지 보면 우연히 겹치는 흔한 표현("오늘은")에 걸린다. **줄 단위 + 최소 길이**가 그
사이다.

- **최소 길이는 짐작이다.** 시작값을 두되 실기기에서 오탐이 보이면 고친다(원칙 V).
- **유사도를 재지 않는다**(FR-016b-2). 부분 문자열 포함 여부만 본다 — 불리언이고 점수가
  아니다.
- 신호가 들어간 줄(그날의 사진 수 등)은 **일기에 자연스럽게 나올 수 있으므로 비교 대상에서
  뺀다.** 고정된 지시문만 비교한다.

**Alternatives**: n-gram 겹침 비율 — 기각. 임계값이 필요하고 FR-016b-2가 금지한다.

---

## §8. 데스크톱 서버 경로 (FR-005) — 무엇을 맞추는가

**Decision**: 데스크톱 어댑터도 **같은 프롬프트 문자열과 같은 샘플링 값**을 보내고,
**같은 판정 함수**를 통과시킨다. 서버 프로토콜 자체는 이 기능에서 새로 정하지 않는다.

**Rationale**: 헌법이 요구한 것은 「동일한 GGUF·프롬프트·샘플링 파라미터」이지 특정
프로토콜이 아니다. 프롬프트 구성과 판정을 **양쪽이 공유하는 순수 함수로 두면**(§5)
FR-005a가 구조적으로 성립한다 — 각자 만들 자리가 없다.

**정직하게 남길 것**: `local` 환경의 데스크톱 서버는 **이 기능에서 실제로 검증되지 않을 수
있다.** 실기기 검증(SC-001)이 온디바이스를 보고, 데스크톱은 같은 함수를 쓴다는 것이
코드로 보장될 뿐이다. **그 차이를 plan에 적어 둔다** — "돌 것이다"와 "돌았다"는 다르다
(원칙 V).

---

## §9. 「쓰고 있다」 표시 (FR-028)

**Decision**: 진단 화면에 **불리언 하나**로 둔다. `생성 중 / 아님`.

**Rationale**: FR-028a가 수치를 금지하고 FR-028b가 글을 금지하므로, 남는 것은 불리언
하나뿐이다. **타입에 자리가 하나뿐이면 진행률을 넣을 곳이 없다** — 003이
`DownloadProgress`에 시간 필드를 두지 않은 것과 같은 방어다.

**남은 위험**(체크리스트): 오래 기다리는 화면에 「얼마나 남았나」를 넣고 싶어지는 압력은
실제로 생긴다. 타입이 그것을 못 받게 두는 것이 유일한 방어다.
