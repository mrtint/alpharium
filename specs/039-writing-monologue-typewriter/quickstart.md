# Quickstart: 생성 중 독백 문구 타자기 연출

**Feature**: 039-writing-monologue-typewriter | **Date**: 2026-09-11

이 문서는 기능이 끝났음을 증명하는 **실행 가능한 검증 시나리오**다.

---

## 사전 준비

- 브랜치 `039-writing-monologue-typewriter` 체크아웃.
- `npm install` 완료. 새 의존성 없음.
- 실기기(SM-S901N 등) + Metro dev 환경(`EXPO_PUBLIC_APP_ENV=dev npx expo
  start --dev-client`), `adb reverse tcp:8081 tcp:8081`.
- 실기기에 기본 캐릭터(quiet) 모델이 준비돼 있어야 생성이 돈다.

## 1. 기기 없는 검증 (항상 돈다)

```bash
npm run test:ui        # writing-monologue-typewriter.test.tsx 포함
npm run lint           # eslint + tsc + 헌법 검사 + prettier
```

**기대**:
- 신규 계약 테스트(C1~C10) GREEN. `key` 지정을 제거하면 문구 전환 시
  리마운트가 안 돼 실패(위반 주입 확인). `skipToEnd`를 상태로 바꾸면
  C3 실패.
- 기존 015·016 관련 테스트(`writing-monologue*.test.ts`)가 있다면
  무수정 GREEN.
- `tsc` 0, 헌법 검사 위반 0, prettier 클린.
- `git diff --stat`에서 `src/diary/`·`src/inference/`·`src/vision/`·
  `src/app/state.ts` **0줄**(C9).

## 2. 실기기 검증 (debug 1회 — 새 네이티브 모듈 없음, 012 기준)

### 2-1. 문구가 글자 단위로 나타난다 (US1 / SC-001)

1. 일기 쓰기를 시작해 생성 중 화면으로 전환되는 순간을 관찰한다.
2. **기대**: 회전 표시와 함께 문구("쓰고 있다" 또는 단계별 독백)가 빈
   상태에서 시작해 글자 단위로 채워진다.
3. 단계가 전환되는 순간(신호 확인→사진 보기→모델 준비→글쓰기, 또는
   사진 보기 단계의 "보통"→"많음" 등)을 관찰한다.
   - **기대**: 이전 문구가 갑자기 새 문구로 바뀌고, 새 문구가 다시
     처음부터 글자 단위로 채워진다(이어서 채워지지 않는다).

### 2-2. 완료 후 정지 상태 유지 (US1 시나리오 3 / SC-002)

1. 문구가 다 채워진 뒤 다음 단계 전환까지 시간이 걸리는 구간(예: 모델
   콜드 로드)을 관찰한다.
2. **기대**: 완성된 문구가 그대로 화면에 머무른다. 깜빡임 등 별도의
   대기 표현이 추가되지 않는다.

### 2-3. 탭 무반응 (US2 / SC-005)

1. 문구가 채워지는 도중 "그만두기" 버튼이 아닌 화면의 다른 곳을 탭한다.
2. **기대**: 아무 일도 일어나지 않는다(문구가 즉시 완성되지 않는다).
3. "그만두기"를 눌러 기존 동작(생성 중단 → 목록 복귀)이 그대로
   작동하는지 확인한다.

### 2-4. 결과 화면 전환 시 잔상 없음 (US1 시나리오 4 / SC-003)

1. 생성이 완료돼 결과 화면(완성 `written` 또는 실패 `failed`)으로
   전환되는 순간을 관찰한다. 가능하면 문구가 아직 다 채워지지 않은
   상태에서 생성이 끝나는 경우(신호 없는 하루 + 웜 모델 등 빠른 경로)를
   시도한다.
2. **기대**: 전환된 화면에 이전 화면의 타이핑 애니메이션이나 텍스트
   잔상이 없다.

### 2-5. 기존 화면 구성 무변경 (US3 / SC-004)

1. 생성 중 화면을 촬영해 이 기능 적용 전(038 시점) 스크린샷과 비교한다.
2. **기대**: 회전 표시 + 독백 문구 한 줄 + "그만두기" 버튼 구성이
   동일하다. 진행률 숫자·경과 시간·생성 중인 본문 텍스트 등 새 정보가
   없다.

### 2-6. Maestro 회귀

```bash
node scripts/run-device-tests.mjs
```

**기대**: `writing-monologue.yml`·`writing-monologue-expansion.yml`을
포함한 기존 흐름이 이 기능 적용 후에도 PASS. 신규 흐름 없음, `FLOWS`
목록 불변(contract C10).

**⚠️ 실측 결과(T020, 2026-09-11)**: 이 두 흐름의 `runFlow: when: visible:
"쓰고 있다"`가 실기기에서 실제로 SKIPPED되는 것이 관측돼, `when`을
"그만두기" 버튼(타이핑과 무관하게 즉시 렌더)으로 교체했다. 그럼에도
quiet(kanana) 캐릭터는 생성이 매우 빨라 이 조건부 블록 자체가 계속
SKIPPED될 수 있다 — 037로 로스터가 kanana 하나뿐이라 narrative(루이)
같은 느린 캐릭터로 대체 검증할 수 없다. **이 SKIPPED는 정상 범위다**
(파일 자체의 기존 주석이 이미 명시). 독백 문구의 실제 동작은 quickstart
2-1~2-5의 육안 확인으로 충분히 검증됐다.
