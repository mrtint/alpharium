# 실측 세 가지 — 제목 구간·동작 줄이기·작은 화면의 쓴 날 — 설계

로드맵 「실측 세 가지」(UX-01·UX-11·UX-12). 검토서가 짚은 세 곳은 코드만으로는 「문제가 있는가」를 가를 수 없다. **코드 0줄로 먼저 재고, 결과가 과제를 열거나 닫는다.** 스펙 번호 100.

## 경로 분류

측정이 본체인 과제다. 측정 전에는 제품 코드 변경이 없고, 판정이 「후속 변경」일 때만 작은 변경(제목 단계·autoplay 끄기·보드 이탈 보고)이 생긴다. 후속 변경은 각 판정 기준이 이미 정해져 있어 설계 선택지가 거의 없다.

## 이해 (소유자 지시와 가정을 나눈다)

**소유자가 말한 것**
- 완료 조건: 세 측정값이 AGENTS(또는 quickstart)에 실측으로 남고, 각각 「닫음」 또는 「후속 변경」으로 판정된다. 후속 변경을 하면 실기기에서 한 번 본다.
- 기기는 SM-S901N(dev 빌드)과 iOS 시뮬레이터. Metro는 8082, `adb reverse tcp:8081 tcp:8082`, 끝나면 원복.
- 기기 설정(`transition_animation_scale`·`font_scale` 등)은 값을 기록하고 끝나면 되돌린다. `pm clear`·재설치 금지(모델 ~2GB).
- 「전부 정상」이면 코드 변경이 없다 — 그것도 결과다.

**가정 (틀리면 고친다)**
- A1. 측정 도구(logcat 파싱 스크립트 등)는 저장소에 넣지 않는다(원칙 IV). 필요한 것은 스크래치 디렉터리에 둔다.
- A2. 측정 절차와 원값은 `specs/100-*/quickstart.md`에, 판정 한 줄은 AGENTS 「지금도 유효한 실측 규칙」에 둔다. 후속 변경이 없으면 AGENTS에는 한 줄씩만 더한다.
- A3. UX-12의 「기존 083 캡처에서 줄 수 세기」는 이미 있는 PNG를 눈으로 읽는 일이다. 모자란 환경(iPhone SE 3rd gen 시뮬레이터 667pt)만 새로 찍는다.

## 세 측정과 판정 규칙

### UX-01 제목 구간

- **잰다**: SM-S901N dev. 사진 있는 날·없는 날 각 2회. `adb logcat`에서 본문 뒤 두 번째 `completion()` 시작~끝.
- **판정**: 중앙값 < 혼잣말 교체 간격(4초)이면 **닫음** — 측정값 한 줄만 AGENTS에. ≥ 4초면 **후속 변경** — `ProgressStage`에 `title` 하나와 혼잣말 풀 하나(사람이 쓴 10문장, 숫자·시간·글 조각 없음). 저장 단계는 넣지 않는다.
- **후속 변경 시 고칠 단언**: `types.test.ts`(단계 수), `monologue.test.ts`(갈래 수·숫자 없음), `pipeline.live-write.test.ts` P4 순서, 문구 골든 `ADDED_AFTER_GOLDEN`.
- **실기기 확인**: 제목 풀 전환 프레임.

### UX-11 OS 「동작 줄이기」

- **잰다**: SM-S901N 「애니메이션 제거」(`transition_animation_scale` 등 기록 후 되돌림), iOS 시뮬레이터 「동작 줄이기」. 설정 겹 열기·닫기, 날짜 넘김, 실패 토스트, 스트립 튕김, 달력, 사진 확대, 내려받기 화면을 `screenrecord`로 본다(내려받기는 074 절차로 모델 보존).
- **소스로 이미 아는 것**: reanimated와 RN `AccessibilityInfo`는 둘 다 `transition_animation_scale` 하나를 읽는다. 내려받기 슬라이드 `autoplay`(`src/ui/DownloadProgressScreen.tsx`)는 라이브러리가 reduceMotion을 참조하지 않아 계속 넘어갈 것으로 본다 — **짐작이며 이번에 실측한다**.
- **판정**: 전부 OS 값을 따르면 **닫음**. 슬라이드가 계속 넘어가면 **후속 변경** — 소유자 확인(046 FR-004·FR-006은 2026-09-21 육안 보고로 복원한 동작)을 받은 뒤 `AccessibilityInfo.isReduceMotionEnabled()`로 autoplay만 끈다(`download-progress-screen.test.tsx:57-61` 소스 정규식을 깨지 않는 꼴).
- **범위 경계**: OS 값을 실기기에서 못 읽는 것으로 드러나면 「각 애니메이션에 대응」으로 커진다 — 그때 범위를 다시 정한다(소유자와).

### UX-12 작은 화면의 쓴 날

- **잰다**: 083 `captures/after/font-scale-2/`에서 쓴 날 첫 화면의 본문 노출 줄 수를 센다. 모자란 환경(iPhone SE 3rd gen 시뮬레이터, 글꼴 1.0/≈2.0배)만 새로 찍는다. 플랫폼 열을 둔다(본문은 비선형, 큰 날짜는 선형 배율).
- **판정**: 1.0배에서 2줄 이상이면 **닫음**(결과만 기록). 0~1줄이면 보드 2c 이탈을 **소유자에게 올린다** — 캐러셀 높이 `photoHeight: 210`(`tokens.ts`)은 보드 값이다. 「30dp를 줄여도 글꼴 2.0배에서는 한 줄(약 49.5dp)도 못 번다」는 계산을 함께 적는다. 소유자 결정 없이 제품 코드를 바꾸지 않는다.
- **미확인 전제**: SE급 iPhone이 지원 대상인지(M1)는 아직 모른다 — 결과에 같이 적는다.

## 산출물

- `specs/100-*/` 스펙 문서 일체와 `quickstart.md`(절차·원값·판정).
- AGENTS 실측 규칙에 판정 한 줄씩(헌법 원칙 V: 실측과 짐작 구분).
- 후속 변경이 있으면 그 코드·테스트. 없으면 제품 코드 변경 0.
- 로드맵: 완료 이력으로 이동(3번째 커밋).

## 테스트 방침

측정 자체는 테스트가 아니다. 후속 변경이 생기면 TDD로 해당 단언을 먼저 쓴다(위 고칠 단언 목록). 위반 주입은 새 규칙이 생길 때만(예: 단계 수 계약).

## 위험

- 셋 다 「정상」이면 코드 변경이 없다 — 그것도 결과다.
- 기기 설정을 되돌리지 못하면 다른 세션 검증을 오염시킨다 → 시작 전 값 기록, 종료 시 대조.
- 시뮬레이터 하나로 짧은 화면을 대표하는 한계 — 결과에 명시한다.
