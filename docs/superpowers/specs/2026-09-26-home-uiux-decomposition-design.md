## 3. 조각별 명세

### 3.1 대화상자 기반

**목적**: RNR을 들여온다. 첫 사용처로 덮어쓰기 확인을 전체 화면에서 AlertDialog로 바꾼다.

**보드**: `2d`. 뒤의 `2f`·`2j`·`2m`이 같은 모양을 쓴다.

**인터랙션(보드 원문)**
- **AlertDialog** — RNR `AlertDialog` 구조 그대로: Overlay(bg-black/50) → Content(p-6, gap-4, border, shadow-lg) → Header(Title + Description) → Footer(flex-col-reverse gap-2). 다이얼로그 면은 직선(테마 `--radius: 0`), 버튼만 6px로 하단 바 버튼과 맞춤 — `2f`·`2j`도 같음. AlertDialog라 배경 탭으로 닫히지 않음 — 반드시 둘 중 하나 선택. Android 뒤로가기 = 취소.
- **선택** — `AlertDialogAction`(Button default) "다시 쓰기" → 쓰는 중(`2b`)으로. 기존 일기는 새 일기가 다 써질 때까지 그대로 두고, 완성되는 순간 교체. 도중에 그만두거나 실패하면 기존 일기(`2c`)로 돌아감. `AlertDialogCancel`(Button outline) "취소" → 다이얼로그 닫고 쓴 날(`2c`) 유지.
- (`2j` 메모에서) `Dialog`는 배경 탭·Android 뒤로가기로도 닫힘 — `2d`의 AlertDialog와 다름.

**문구**

| 키 | KO | EN |
| --- | --- | --- |
| `h2.confirmTitle` | 일기를 다시 쓸까요? | Rewrite this entry? |
| `h2.confirmBody` | 다 쓰면 지금 일기가 새 글로 바뀌어요. | The current entry will be replaced by a new one. This can't be undone. |
| `h2.confirmYes` | 다시 쓰기 | Rewrite |
| `h2.confirmNo` | 취소 | Cancel |

EN 본문에만 「This can't be undone.」이 더 붙어 있다. KO를 기준으로 한다.

**시각 수치**
- 덮개 `rgba(0,0,0,.5)`.
- 면: 배경 `bg`, 테두리 2px `text`, 그림자 `0 10px 30px rgba(0,0,0,.18)`, 안쪽 여백 24, 간격 16, 좌우 바깥 여백 20(가로 전폭).
- 제목 20/700, 줄높이 1.3. 설명 16, 줄높이 1.5, 보조색.
- 버튼은 세로로 쌓는다(동작 버튼이 위, 간격 8). 높이 48, 반경 6, 16/600. 동작 버튼은 accent 배경, 취소 버튼은 1px `text` 테두리.

**현재 코드와의 대조**
- **어긋남 — 모양**: 지금은 전체 화면 `OverwriteConfirmScreen`이다(`src/ui/OverwriteConfirmScreen.tsx`). 문구는 해라체
  「이 날의 일기가 이미 있다. 덮어쓸지 확인이 필요하다」이고, 버튼 「취소」·「확인」이 가로로 놓인다.
- **일치 — 데이터**: 기존 일기는 새 일기가 완성될 때만 바뀐다. 파이프라인이 판정을 통과한 뒤에야 `store.save()`를
  부르기 때문이다(`src/diary/pipeline.ts:351`). 보드의 「완성되는 순간 교체」가 이미 참이다.
- **일치 — 상태 기계**: `confirm-overwrite` 상태와 `cancelOverwrite()`·`confirmOverwrite()`(`src/app/state.ts:416-427`)는
  그대로 쓸 수 있다. 바뀌는 것은 그리는 방식뿐이다(홈 위에 겹침).
- **어긋남 — 045의 결정**: `DownloadConsentDialog`가 「새 Dialog 라이브러리를 추가하지 않는다」며 RN `Modal`을 썼다

- **어긋남 — 테마**: RNR은 `global.css`의 CSS 변수(`--background`, `--primary` …)와 그것을 가리키는 tailwind 색 이름을 전제한다.

- **어긋남 — 버튼 색**: 보드의 동작 버튼은 accent에 오프화이트 글자다. C5에 따라 검정 글자로 바꾼다(`Button` `primary`와 같다).

- **`2j` 일** — 스트립과 같은 표현 — 선택한 날은 빨강 바탕, 점 = 일기 있음, 오늘은 빨간 밑줄, 오늘 이후는 흐리게·탭 불가. `onChange` = 바로 이동: 다이얼로그가 닫히고 스트립이 그 날이 있는 주로 바뀌며 그 날이 선택됨. 별도 확인 버튼 없음.
- **`2j` 취소** — `Dialog`라 배경 탭·Android 뒤로가기로도 닫힘(`2d`의 AlertDialog와 다름). 닫으면 아무 것도 바뀌지 않음.

### 3.3 쓸 재료

**목적**: 쓰기 전에 그날 셀 수 있는 재료를 보인다. 없음(0)과 모름(권한 없음)을 가르고, 재료가 없으면 한 번 더 묻는다.

**보드**: `1d`의 ④쓸 재료·⑤하단 고정 바, `2l`, `2m`, `2e`, `2f`

**인터랙션(보드 원문)**
- **쓸 재료** — 그날 기기에서 찾은 사진 수와 장소 수. 제목 없이 숫자 두 칸만, 칸 사이 구분선 없음. 기기 안에서만 집계. 날짜를 바꾸면 그 날 기준으로 바로 셈. 오늘 숫자만 실시간으로 늘지 않고 Home을 열 때(앱 실행·백그라운드에서 복귀) 갱신. 읽기 전용.
- **하단 고정 바** — "일기 쓰기" 탭 → 재료가 하나라도 있으면 확인 없이 바로, 화면 이동 없이 스트립 아래가 쓰는 중 상태(`2b`)로 바뀜. 재료가 0이면 확인 다이얼로그(`2f`) 먼저. 화면 끝까지 닿는 빨강 블록(상단 좌우만 6px). 날짜는 헤더와 중복이라 표시하지 않음. 안 쓴 날은 스크롤이 없어 항상 보임(쓴 날의 "끝에 닿으면 등장" 규칙과 별개).
- **`2l` 권한이 없어요** — 권한이 없는 항목만 숫자 대신 빨간 "권한이 없어요 ›"(탭 영역 44px). 0과 다름 — 셀 수 없다는 뜻. 사진·장소 각각 따로 판단(여기선 사진만 없음, 장소는 2). 탭 → 그 항목의 권한 요청(`2m`). 허용하면 바로 다시 세어 숫자로 바뀜.
- **`2l` 쓰기와의 관계** — "일기 쓰기"는 셀 수 있는 항목 기준: 권한 있는 항목에 재료가 하나라도 있으면 바로 쓰기(`2b`), 권한 있는 항목이 모두 0이거나 두 항목 모두 권한이 없으면 `2f` 확인 후 상상으로 씀. 권한 요청을 강제하지 않음.
- **`2m` 시스템 권한 다이얼로그** — 처음 실행 때(`1l`)와 같은 iOS 기본 다이얼로그. 장소를 눌렀으면 위치 권한 다이얼로그. 선택 후 Home으로 돌아와 해당 항목만 다시 셈.
- **`2m` 이미 거부한 경우** — iOS는 한 번 거부하면 앱에서 다시 물을 수 없음 → 이 경우엔 시스템 다이얼로그 대신 RNR `AlertDialog` "설정에서 사진 접근을 허용해 주세요" + "설정 열기"(설정 앱으로 이동) / "취소". 돌아오면 다시 셈.
- **`2e` 쓸 재료 0** — 재료가 있는 날(`1d`)과 같은 배치에 0을 표시하고, 숫자만 회색으로. 아래 한 줄은 부정형 대신 할 수 있는 것("기록 대신 상상으로 하루를 채워요")으로 안내. 권한이 없어 셀 수 없는 경우는 0이 아니라 "권한이 없어요"(`2l`).
- **`2e` 하단 고정 바** — 버튼은 재료가 있는 날과 똑같음(빨강 "일기 쓰기"). 탭 → 바로 쓰지 않고 확인 다이얼로그(`2f`).
- **`2f` AlertDialog** — `2d`와 같은 RNR `AlertDialog`. 제목은 상황(😢 + 기록 없음), 설명은 결과("상상해서 적어요"). 배경 탭으로 닫히지 않음.
- **`2f` 선택** — `AlertDialogAction` "확인" → 쓰는 중(`2b`)으로, 다 쓴 일기에는 "지어낸 하루"임이 남아야 함(표시 방법은 따로 정할 것). `AlertDialogCancel` "취소" → 닫고 `2e` 유지.

### 3.4 제자리 쓰기

**목적**: 쓰는 동안 화면을 떠나지 않는다. 실패는 토스트 한 줄로 알리고 쓰기 전 상태로 돌아간다.

**인터랙션(보드 원문)**

- **`2b` 혼잣말** — 캐릭터의 한 줄이 몇 초마다 다음 줄로 교체(짧은 페이드). 진행률·남은 시간은 표시하지 않음. 끝나면 이 영역이 비고 헤더에 제목이 들어오며 쓴 날(`2c`)로 전환.

- **`2c` 하단 바 (숨김)** — 평소엔 숨김 — 본문 맨 끝에 닿으면 아래에서 올라옴(`5a` ③), 벗어나면 내려감. 본문이 화면보다 짧으면 처음부터 보임(`2k`). "다시 쓰기"(연회색 전폭 블록, 안 쓴 날보다 한 단계 약하게). 쓴 날에서 할 수 있는 동작은 이것 하나 — 공유·복사·삭제·이전 버전 보기는 두지 않음. 오늘 쓴 일기가 아니므로 작성 시각 표시 없음. 탭 → 덮어쓰기 확인(`2d`).
- **`2k` 본문** — 사진이 한 장도 없으면 캐로셀과 인디케이터를 통째로 렌더하지 않음 — 빈 칸·안내 문구 없음. 본문이 지면 맨 위(여백 20px)부터 시작하고, 스크롤·스트립 접힘 규칙은 `2c`와 같음. 본문이 화면보다 짧아 처음부터 끝이 보이므로 하단 바도 처음부터 보임. 사진이 1장이면 캐로셀은 보이되 스와이프·인디케이터·"1 / 1" 배지 없음.
- **`2g` 날짜 헤더** — 헤더에는 "오늘" 표시 없음 — 오늘은 스트립 숫자의 빨간 밑줄로만 구분(모든 화면 공통). 제목은 다른 쓴 날과 같은 자리.
- **`2g` 하단 바** — 다른 쓴 날과 같은 "다시 쓰기", 아래에 작게 상대 시각("2시간 15분 전에 작성"). 작성 시각은 오늘 쓴 일기에만 표시하고, 다른 날 쓴 일기는 표시하지 않음. 1시간 미만은 "N분 전", 1분 미만은 "방금". 누르면 덮어쓰기 확인(`2d`) 후, 그 시점까지의 하루로 새로 씀.

**「읽기 스크롤」 조각이 들어오기 전의 하단 바**: 이 조각만으로는 「끝에 닿으면 등장」이 없다. 그동안의 표시 규칙(늘 보임 등)을
이 조각 스펙이 정한다(C7).

### 3.6 읽기 스크롤

**목적**: 쓴 날을 읽는 동안 스트립을 접어 지면을 넓히고, 끝에 닿았을 때만 「다시 쓰기」를 올린다.

**보드**: `5a`(스토리보드), `5b`(동작 시안), `2c`의 본문 지면 메모

**인터랙션(보드 원문)**
- **`5a` ① 들어온 직후 — 펼침** — 스트립이 보이는 상태로 시작. 하단 바는 숨김 — 본문이 화면 끝까지 쓰임.
- **`5a` ② 읽는 중 — 스트립 접힘** — 날짜·요일·제목은 크기 그대로, 스트립만 위로 접힘(240ms). 날짜 줄 오른쪽에 ▾가 나타남.
- **`5a` ③ 끝에 닿음 — 하단 바 등장** — 마지막 문단 아래에 닿으면 "다시 쓰기" 바가 아래에서 올라옴. 끝에서 벗어나면 다시 내려감.
- **`5a` ④ 다시 펼침 — 위치 유지** — 스트립이 다시 내려오고 ▾는 사라짐. 읽던 위치·하단 바 상태는 그대로.
- **`5b` 날짜 헤더 · 스트립** — 아래로 8px 넘게 스크롤하면 스트립만 접힘(240ms, ease-out). 날짜·요일·제목은 크기와 위치 그대로 유지, ▾만 페이드인. 위로 스크롤하는 것만으로는 펼치지 않고, 맨 위에 닿거나 접힌 날짜 줄(높이 44px 전체가 탭 영역)을 탭하면 펼침 — 접힌 상태의 탭은 펼치기만 하고 2j를 열지 않음(펼친 상태에서 한 번 더 탭하면 2j). 펼칠 때 스크롤 위치는 유지.
- **`5b` 캐로셀 · 본문** — 지면 전체가 한 덩어리로 스크롤 — 캐로셀도 본문과 함께 올라감.
- **`5b` 하단 바** — 평소엔 화면 아래로 숨김. 본문 맨 끝(4px 이내)에 닿으면 아래에서 올라옴(240ms), 끝에서 벗어나면 다시 내려감. 본문 끝에 바 높이만큼 여백을 둬 마지막 문단을 가리지 않음.

**문구**: 새 문구 없음(「다시 쓰기」·▾).

**시각 수치**
- 접힘: 스트립 높이 180 → 0(`max-height` .24s ease-out), 불투명도 1 → 0(.18s).
- ▾: 폭 28, 14/700, 불투명도 전환 .24s.
- 바: `translateY(100%)` → `0`, .24s ease-out.
- 판정값: 접힘 `y > 8` + 아래로 스크롤. 펼침 `y ≤ 2` + 위로 스크롤, 또는 날짜 줄 탭. 끝 판정은 `y + 높이 ≥ 전체 − 4`.
- 시안은 300ms 디바운스를 쓴다(구현 참고용, 확정값 아님).

**현재 코드와의 대조**
- **새로 생김**: 지금은 헤더와 목록이 하나의 `ScrollView`로 함께 흐르고 하단 바는 늘 고정이다(048 FR-023). 접힘·숨김 동작은 없다.
- **일치 — 기반**: reanimated 4.5.1 + `react-native-worklets/plugin`이 이미 있다(033). 플러그인이 없으면 조용히 움직이지 않는다는 실측이 있다.
- **새로 생김 — 제스처 분리**: 세로 지면 안의 가로 캐러셀은 `onConfigurePanGesture` + `activeOffsetX([-10, 10])`로 가른다(C1).
- **주의**: 「날 고르기」의 헤더 탭(펼친 상태 → `2j`)과 이 조각의 탭(접힌 상태 → 펼치기만)이 같은 노드를 공유한다. 계약은 이 조각이 적는다.

스크롤을 가른다.」
