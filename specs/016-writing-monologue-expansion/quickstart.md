# Quickstart: 쓰는 중 독백 확장 검증

## 기기 없는 검증 (항상 돈다)

```
npm run test:logic   # engine-port.test.ts, llama-port.test.ts, on-device.test.ts,
                      # monologue.test.ts, particle.test.ts
npm run test:ui       # app/state.test.ts (writing 상태 branch 필드)
npm run lint           # tsc + 헌법 검사(monologue.ts·particle.ts의 import 제한)
```

**위반 주입으로 확인할 것** (AGENTS.md 「작업 습관」 관례):
- `monologue.ts`에 일부러 `import { personaOf } from "./persona"`를 추가해
  헌법 검사가 여전히 잡는지 확인한 뒤 되돌린다(research.md §4 — "느슨해진
  것이 아니라 애초에 이 경로가 안전했다"를 실증).
- `particle.ts`에도 같은 위반 주입을 반복한다(신설 파일이라 아직 검증
  이력이 없다).
- `MonologueBranch`에 `{ branch: "cold"; retryCount: number }`처럼 숫자
  필드를 일부러 추가해 계약 테스트가 잡는지 확인한 뒤 되돌린다.
- `LoadResult`의 `{ ok: true }` 갈래에 `loadTimeMs: number`처럼 시간
  필드를 일부러 추가해 계약 테스트(원칙 IV 방어)가 잡는지 확인한 뒤
  되돌린다.

### A3. 조사 선택이 로스터 5인 + 받침 있는 가상 이름에서 올바르다

```
npm run test:logic -- particle.test.ts
```

**기대**: 금동이·루이·오드·샤오바이·모카 전부 `"가"`, 받침 있는 가상
이름(예: "테스트인") 케이스는 `"이"`. research.md §5·contracts/particle.md
검증 표와 일치해야 한다.

## 실기기 검증 (최소 1회, debug로 충분)

**★ 루이(narrative)로 검증한다.** 콜드 스타트가 242초까지 걸리는
캐릭터라(로드맵 실측) 로드 단계 문구를 눈으로 확인하기 가장 쉽다 — 015가
이미 확립한 선택 기준과 같다.

### B1. 콜드 스타트 문구가 캐릭터 이름과 함께 뜬다 (User Story 1)

1. `EXPO_PUBLIC_APP_ENV=dev npx expo start --dev-client`
2. 앱을 처음 열거나 다른 캐릭터를 방금 썼는지 확인한다(루이의 모델이 아직
   로드 안 된 상태).
3. 루이(narrative)를 캐릭터로 고르고 일기 쓰기를 시작한다.
4. **기대**: "그날의 기록을 확인하는 중…" → "사진을 들여다보는 중…"(사진
   보기가 켜져 있으면) → **"루이가 ..." 형태의 콜드 스타트 문구(캐릭터
   이름 포함)** → "글을 쓰는 중…" 순서로 문구가 바뀐다. 로드 단계 문구가
   상당히 오래(콜드면 최대 242초) 머문다.

### B2. 핫 스타트 문구가 콜드 스타트 문구와 다르게 뜬다 (User Story 1)

1. B1 직후, 같은 캐릭터(루이)로 다시 한 번 일기 쓰기를 시작한다(다른
   날짜로, 덮어쓰기 확인 없이 새 하루를 고른다).
2. **기대**: 로드 단계에서 **핫 스타트 문구**(콜드 스타트 문구와 다른
   풀에서 고름, 여전히 "루이" 포함)가 뜬다. 이 구간이 B1보다 눈에 띄게
   짧다(로드맵 실측 26초 이하, kanana류는 훨씬 짧음). "글을 쓸 준비를
   하고 있어요" 류(콜드 전용) 문구가 이번엔 안 보인다.

### B3. 사진이 많은 하루에서 "많음" 계열 문구가 보일 수 있다 (User Story 3)

1. 사진이 5장 이상인 하루를 심는다(010 `seed:day` 도구 사용 가능).
2. "빠르게 봄"으로 설정하고 생성을 시작한다.
3. **기대**: 사진 보기 단계에서 "많다" 인상의 문구(예: "살펴볼 사진이
   많아서 반가운 하루예요" 류)가 나올 수 있다 — 무작위 선택이므로 반드시
   1회차에 나오지 않을 수 있어, 안 나오면 같은 하루로 2~3회 재시도해
   관측한다. 사진이 5장 미만인 하루에서는 같은 절차를 반복해 "많다" 문구가
   전혀 안 나오는지 대조 확인한다(SC-004·SC-005).

### B4. 사진 보기 문구가 실측 캡션 범위를 넘지 않는다 (User Story 2)

이 항목은 실기기가 아니라 **코드 검사로 검증한다** — 011의
`CAPTION_PROMPT`가 얼굴 인식·장소 판별을 하지 않으므로, 화면에서 그런
문구가 우연히 뜨는지 기다리는 것보다 문구 풀 전체를 정적으로 검사하는
편이 확실하다.

```
npm run test:logic -- monologue.test.ts
```

**기대**: `vision-normal`·`vision-many` 풀의 문구 10개+10개 전체에서
"누구"·"인물"·"언제"·"어디"·"찍힌"·"다녀온" 등 정직성 경계를 넘는
낱말이 없는지 테스트가 확인한다(FR-005, SC-003).

### B5. 로드 실패 시 독백이 남지 않는다 (FR-011)

1. 아직 다운로드되지 않은 캐릭터로 생성을 시도한다(모델 파일 없음).
2. **기대**: 로드 시작 문구가 잠깐 보이다가, 콜드/핫 확정 문구 없이 바로
   실패 안내 화면으로 전환된다. 로드 단계 문구가 실패 화면 위에 남아있지
   않다.

### B6. 로드 도중 "그만두기"가 로드 완료 직후 반영된다 (FR-013)

**⚠️ 로드 자체는 즉시 멈추지 않는다** — `llama.rn`에 로드 취소 API가
없다(research.md §7). 이 시나리오는 "취소가 조용히 무시되지 않는다"를
확인하는 것이지 "즉시 멈춘다"를 확인하는 것이 아니다.

1. 아직 로드되지 않은 캐릭터(콜드 스타트, 가능하면 루이)로 일기 쓰기를
   시작한다.
2. 로드 시작 문구가 보이는 즉시(콜드/핫 확정 문구가 뜨기 전) "그만두기"를
   누른다.
3. **기대**: 화면은 로드가 끝날 때까지(콜드 스타트라면 최대 242초까지)
   대기 상태로 남아 있다가, 로드가 끝나는 순간 콜드/핫 확정 문구 없이
   바로 기존 취소 처리 화면(007)으로 전환된다. 로드 단계 문구가 취소
   처리 화면 위에 남아있지 않다.

## 확인 표

| 항목 | 방법 | 통과 |
| --- | --- | --- |
| 옵셔널 확장이 기존 계약을 안 깬다 | `npm test` 전체 | 기존 002/003/005/012/015 테스트 전부 그린 |
| `monologue.ts`·`particle.ts`가 로스터에 안 닿는다 | `npm run lint`(헌법 검사) | 위반 0건 |
| 콜드/핫 판정이 실제 재사용과 일치한다 | `llama-port.test.ts` — 같은 캐릭터 연속 `load()` | 두 번째 호출이 `warm: true`, 다른 캐릭터는 `warm: false` |
| 로드 단계 문구에 캐릭터 이름·올바른 조사가 있다 | B1·B2 실기기 + `particle.test.ts` | 이름 포함, 조사 문법상 자연스러움 |
| 사진 보기 문구가 캡션 실측 범위를 넘지 않는다 | B4(코드 검사) | 금지 낱말 0건 |
| 장수 많음/보통 갈래가 실제 상한과 맞물린다 | B3 실기기 | 5장 이상에서만 "많다" 문구 관측 가능 |
| 각 갈래 문구가 10개 이상이다 | `monologue.test.ts` | 신설·수정 5개 갈래 전부 10개 이상 |
| 로드 실패에서 독백이 안 남는다 | B5 실기기 | 실패 화면 전환, 이전 문구 미잔존 |
| 로드 도중 취소가 완료 직후 반영된다 | B6 실기기 + `on-device.test.ts` | 확정 문구 없이 취소 화면 전환, 즉시 중단은 아님이 문서화됨 |
