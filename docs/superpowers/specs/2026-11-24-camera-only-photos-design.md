# 카메라로 찍은 사진만 재료로 쓴다 — 설계

날짜: 2026-11-24 · 로드맵 「진행 예정 과제」 같은 제목 항목(#287)

## 목적

재료 지면의 「사진 N장」과 일기에 쓰이는 사진이 같은 기준을 따르게 한다. 화면 캡처·다운로드·메신저·퀵셰어 사진은 하루의 재료가 아니다 — **수집 단계에서 뺀다.** 장수 표시·첫 일기 분기·자동 쓰기 훑기·장소(사진 좌표)·선별·캡션이 같은 판정 하나를 따른다.

## 설계

1. **판정 자리 하나 — `src/signals/camera-only.ts`(순수)**. 입력은 사진의 출처 사실(안드로이드 폴더 상대 경로, iOS `mediaSubtypes`·EXIF 기기 유무, 공통 이름·크기)과 「시딩 인정 여부」(불리언). 출력 `camera` / `excluded`. **모르면 뺀다**(카메라라고 확인하지 못한 사진을 카메라로 채우지 않는다 — 원칙 V). 128의 읽기 전 판정(이름 `Screenshot*`·세로/가로 ≥ 2)을 여기로 옮기고 `caption.ts`는 읽은 뒤 판정(문답 꼴·낱말)만 남긴다.
2. **수집에서 한 번 — `collect.ts`**. `photosBetween` 결과를 판정으로 거른 뒤 `known`/`none`을 정한다. 모든 소비자가 이 결과만 받는다. `select.ts`의 `NON_CAMERA_FOLDERS`·되돌림·`folderName`과 `on-device.ts`의 `folderNamesFor`(사진마다 `getUri()`)를 걷는다.
3. **기기 계층 — `expo-port.ts`**. 사실만 싣는다(판정 금지, `checkPhotoPortFile`). 안드로이드는 레거시 일괄 조회가 사진마다 싣는 파일 경로(MediaStore `_data`)를 쓴다 — 경로를 푸는 호출 0회(설계 뒤 조사로 바꿈, specs/129 research R1). iOS는 일괄 조회의 `mediaSubtypes`. 새 네이티브 모듈 없음.
4. **개발 전용 예외 잠금**. `allowsSeedPhotos(resolution)`(`allowsFastCycle` 꼴)이 판정 성공 + local·dev일 때만 참. 헌법 검사 `SEED_PHOTO_LEAKS`가 시딩 폴더 이름의 자리와 인정 여부를 구하는 자리를 잠근다.
5. **검증**. 판정 단위·수집 조립·위반 주입, `npm test`·`npm run lint`, SM-S901N·iPhone 14 실기기에서 스크린샷·다운로드 사진이 장수와 일기에서 빠짐.

## 위험

- 경로를 못 읽은 앨범·`limited` 권한의 사진은 빠진다(모르면 뺀다의 대가).
- 「재료 없음」 날이 늘어 첫 일기 분기·자동 쓰기 동작이 달라진다.
- iPhone에서 사파리·메신저에서 저장한 사진은 EXIF를 읽지 않으면 가르지 못한다.
