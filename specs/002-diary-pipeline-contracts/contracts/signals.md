# 계약: 하루치 신호와 하루 경계

**대상**: `src/signals/types.ts`, `src/signals/fake.ts`, `src/config/day-boundary.ts`
**관련 요구사항**: FR-001~FR-005b, FR-021~FR-021b

순수 함수와 타입만 다룬다. 기기 없이 전부 테스트된다.

---

## SignalValue&lt;T&gt;

```ts
type SignalValue<T> =
  | { kind: 'known'; value: T }
  | { kind: 'none' }
  | { kind: 'unknown'; reason: string }
```

`unknown`은 **왜 모르는지**를 담는다. "권한 없음"과 "안드로이드가 제공하지 않음"은 다른
사실이고, 진단에서 구분되어야 한다.

### 검증 표

| 상황 | 기대 | 근거 |
| --- | --- | --- |
| 사진 3장을 찾음 | `{ kind: 'known', value: [...] }` | — |
| 사진을 찾아봤는데 0장 | `{ kind: 'none' }` | FR-002 |
| 사진 권한이 없어 못 봄 | `{ kind: 'unknown', reason: ... }` | FR-002 |
| 걸음 수 (안드로이드) | `{ kind: 'unknown', reason: ... }` | AGENTS.md 실측 |

### 불변식 — 테스트로 강제한다

1. **`unknown`은 값을 갖지 않는다.** 타입 수준에서 `value` 접근이 불가능해야 한다.
2. **`none`과 `unknown`을 같게 다루는 헬퍼를 만들지 않는다.** `isEmpty()` 같은 함수가
   둘을 뭉개면 FR-002가 무너진다. 필요하면 각각을 따로 묻는다.
3. **기본값으로 대체하는 함수를 만들지 않는다**(FR-003). `valueOr(signal, 0)` 형태의
   편의 함수는 걸음 수를 0으로 만들어 "걷지 않았다"는 거짓을 낳는다. **이 계약이 금지한다.**

3번이 이 파일에서 가장 중요하다. 편의를 위해 만들고 싶어지는 함수이며, 만드는 순간 헌법
원칙 V가 깨진다.

## DaySignals

```ts
type DaySignals = {
  date: DayDate
  photos: SignalValue<Photo[]>
  places: SignalValue<PlaceTrace>
  steps: SignalValue<number>
  battery: SignalValue<BatteryTrace>
  connectivity: SignalValue<ConnectivityTrace>
}
```

### 검증 표

| 상황 | 기대 | 근거 |
| --- | --- | --- |
| 모든 신호가 `unknown` | 유효한 `DaySignals` | FR-005b |
| 모든 신호가 `none` | 유효한 `DaySignals` | FR-005b |
| 신호가 적음 | 생성 요청을 만들 수 있다 | FR-005a |
| `date`가 없음 | 만들 수 없다 | FR-004 |

**빈 하루는 오류가 아니다.** 휴대폰이 아무것도 보지 못한 것 자체가 일기의 내용이 된다
(헌법 원칙 II).

## 가짜 신호 (`fake.ts`)

**용도**: 테스트와 개발용. 파이프라인을 기기 없이 돌리기 위한 것이다.

**규칙**:

- **제품 경로가 아니다.** 가짜 신호로 만든 일기가 사용자에게 보이는 경로를 만들지
  않는다(MUST NOT).
- 이것이 헌법 원칙 I의 "미리 만들어 둔 응답"으로 자라지 않도록, 파일 주석에 경계를 남긴다.
- 가짜 신호는 **여러 모양**을 만들 수 있어야 한다 — 풍성한 하루, 빈 하루, 일부만 `unknown`인
  하루. 한 가지만 있으면 경계 사례를 테스트할 수 없다.

## 하루 경계 (`day-boundary.ts`)

**04:00이라는 값은 이 파일에만 존재한다**(FR-021a). 여기가 유일한 정의처다.

```ts
function dayOf(instant: Date): DayDate
function isDayClosed(day: DayDate, now: Date): boolean
```

**"지금"을 인자로 받는다.** 함수 안에서 `new Date()`를 부르면 경계값을 테스트할 수 없다.

### `dayOf` 검증 표

| 입력 시각 | 기대 하루 | 왜 |
| --- | --- | --- |
| 2026-08-12 04:00:00 | 2026-08-12 | 경계 시작 |
| 2026-08-12 12:00:00 | 2026-08-12 | 한낮 |
| 2026-08-12 23:59:59 | 2026-08-12 | 자정 직전 |
| 2026-08-13 00:30:00 | **2026-08-12** | **자정을 넘겼지만 전날** |
| 2026-08-13 03:59:59 | **2026-08-12** | 경계 직전 |
| 2026-08-13 04:00:00 | 2026-08-13 | 새 하루 |

**굵은 두 행이 자정 기준과 다른 지점이다.** 새벽 활동이 전날 일기에 붙는다는 것이 이
규칙의 전부이며, 이 두 행을 검증하는 테스트가 FR-021의 방어선이다.

### `isDayClosed` 검증 표

| 하루 | 현재 시각 | 기대 | 근거 |
| --- | --- | --- | --- |
| 2026-08-12 | 2026-08-13 03:59 | `false` | 아직 안 닫힘 |
| 2026-08-12 | 2026-08-13 04:00 | `true` | 닫힘 |
| 2026-08-12 | 2026-08-12 12:00 | `false` | 진행 중인 하루 |
| 2026-08-11 | 2026-08-13 12:00 | `true` | 지난 하루 |

아직 닫히지 않은 하루는 일기를 만들 수 없다(FR-018c).

- 사진의 내용 이해 — 시각 처리 기능
