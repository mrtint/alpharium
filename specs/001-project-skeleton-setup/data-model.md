# Phase 1: 데이터 모델

**기능**: 프로젝트 뼈대와 의존성 기반 세우기 | **날짜**: 2026-08-12

이 기능은 영속 데이터를 다루지 않는다. 아래는 **실행 중에만 존재하는 값**의 모양과 그것을
지배하는 규칙이다. 규칙이 곧 테스트 대상이다.

---

## Environment (환경)

앱이 어디서 실행 중인지. 추론 위치의 허용 범위를 결정한다.

| 값 | 의미 |
| --- | --- |
| `local` | 개발자 작업 기계. 시뮬레이터 전제 |
| `dev` | 실기기에 설치하는 개발 빌드 |
| `prod` | 엔드유저에게 나가는 배포 빌드 |

**판정 규칙** (FR-009a):

- 실행 시점에 환경 변수에서 읽는다. 빌드는 하나다.
- 읽는 곳은 `src/config/environment.ts` **한 곳뿐**이다. 다른 모듈이 환경 변수를 다시 읽으면
  단일 판정이 무너진다.

**미지정·오지정 처리** (FR-009b):

| 입력 | 결과 |
| --- | --- |
| `local` / `dev` / `prod` | 해당 환경 |
| 값이 없음 | **판정 실패**. 추론 위치가 불명인 채로 진행하지 않는다 |
| 알 수 없는 값 (`staging` 등) | **판정 실패**. 조용히 기본값으로 떨어지지 않는다 |

판정 실패는 예외가 아니라 값으로 표현한다. 실패했다는 사실과 원인(무엇을 받았는지)이 진단
정보에 실려야 한다. **가장 안전한 환경으로 기본값을 두지 않는다** — 어느 쪽으로 떨어져도
"모르는데 진행한" 것이기 때문이다.

## InferenceLocation (추론 위치)

추론이 실제로 도는 곳.

| 값 | 의미 |
| --- | --- |
| `on-device` | 기기의 네이티브 추론 모듈 |
| `desktop-server` | 개발자 기계의 데스크톱 추론 서버 |

**환경별 허용 규칙** (FR-010~012) — 이것이 이 기능의 핵심 계약이다:

| 환경 | 기본값 | 허용되는 값 | 금지 |
| --- | --- | --- | --- |
| `local` | `desktop-server` | `desktop-server`, `on-device` | — |
| `dev` | `on-device` | `on-device` **only** | `desktop-server` |
| `prod` | `on-device` | `on-device` **only** | `desktop-server` |
| 판정 실패 | 없음 | 없음 | 전부 |

**불변식**:

1. `dev` 또는 `prod`에서 `desktop-server`가 선택되는 경로는 존재하지 않는다(FR-012).
   요청되더라도 차단되고 그 시도가 드러나야 한다(FR-009c).
2. 환경 판정에 실패하면 어떤 추론 위치도 선택되지 않는다(FR-009b).
3. 이 규칙은 순수 함수다. 기기·네트워크·파일 없이 테스트할 수 있어야 한다(FR-021c).

**왜 `local`만 두 값을 허용하는가**: 시뮬레이터에는 네이티브 모듈이 없어 기본값이 서버여야
하지만(FR-010), 개발자가 실기기를 붙였을 때 온디바이스로 확인할 길을 막지 않는다(FR-011).

## InferenceBackend (추론 어댑터)

일기 생성 코드가 보는 **유일한 문**. 구현체가 어디서 도는지 호출자는 모른다(FR-025).

| 필드 | 설명 |
| --- | --- |
| `location` | 이 어댑터가 어디서 도는지. 진단 보고용 |
| `isAvailable()` | 지금 이 어댑터를 쓸 수 있는지. 온디바이스는 네이티브 모듈 적재 여부, 서버는 연결 가능 여부 |

**구현체는 둘**: `on-device` (`llama.rn` 사용), `desktop-server` (HTTP).

**이 기능에서의 범위**: 인터페이스와 `isAvailable()`까지. 실제 추론 호출(일기 생성)은 다음
기능의 몫이므로 여기서 만들지 않는다.

**금지**: 어느 구현체도 미리 만들어 둔 응답이나 대체 응답을 반환하지 않는다(헌법 원칙 I,
FR-016). 서버에 닿지 못하면 **닿지 못했다는 사실**이 결과이지, 대신 만든 답이 결과가 아니다.

## ModuleStatus (네이티브 모듈 적재 상태)

온디바이스 추론 모듈이 붙어 있는지 (FR-006).

| 값 | 의미 |
| --- | --- |
| `loaded` | 네이티브 모듈이 적재되어 호출 가능 |
| `unavailable` | 모듈이 없음. 시뮬레이터에서는 **예상된 상태**이지 오류가 아니다 |
| `failed` | 모듈이 있어야 하는데 적재에 실패. 원인이 함께 실려야 한다 |

**판정 방법**: 모델 파일 없이 네이티브 계층에 닿는 호출의 성공 여부로 판정한다
(research.md §1). 모델을 적재하지 않는다 — FR-008이 범위 밖으로 둔다.

**`unavailable`과 `failed`의 구분이 중요한 이유**: 시뮬레이터(local)에서 모듈이 없는 것은
정상이고, 실기기(dev)에서 없는 것은 문제다. 같은 값으로 뭉뚱그리면 User Story 2 시나리오 3과
FR-007을 동시에 만족할 수 없다.

## DiagnosticReport (진단 정보)

개발자가 지금 상태를 확인하는 값의 묶음 (FR-017).

| 필드 | 내용 |
| --- | --- |
| `environment` | 판정된 환경, 또는 판정 실패와 그 원인 |
| `inferenceLocation` | 선택된 추론 위치, 또는 선택되지 않음 |
| `moduleStatus` | 네이티브 모듈 적재 상태 |
| `failures` | 발생한 실패와 원인 (모듈 적재 실패, 서버 연결 실패 등) |

**출력 규칙** (FR-007a, FR-007b):

| 환경 | 화면 | 로그 |
| --- | --- | --- |
| `local` | 보인다 | 남는다 |
| `dev` | 보인다 | 남는다 |
| `prod` | **보이지 않는다** | 남는다 |
| 판정 실패 | 보인다 | 남는다 |

**불변식**:

1. 세 환경 모두 로그에는 남는다. prod에서 화면에 안 보이는 것이 안 남긴다는 뜻이 아니다
   (FR-007b).
2. prod에서 엔드유저 화면에 진단 정보가 드러나는 경우는 0건이어야 한다(SC-013).
3. 환경 판정에 실패했을 때는 화면에 보인다 — 어느 환경인지 모르는 상태에서 prod 규칙을
   적용할 수 없기 때문이다. 판정 실패는 prod 배포본에서 발생해서는 안 되는 상태이며,
   발생했다면 감추는 것보다 드러나는 편이 낫다.

**모델 식별자를 싣지 않는다**: 헌법 원칙 III이 모델 식별자·파라미터 수·양자화 방식의 사용자
노출을 금지한다. 진단 정보는 개발자용이고 prod에서 감춰지지만, 애초에 싣지 않는 편이 안전하다.
이 기능은 모델을 다루지 않으므로(FR-008) 실을 것도 없다.

## TestTier (테스트 갈래)

자동 테스트가 나뉘는 두 갈래 (FR-021b).

| 갈래 | 필요한 것 | 언제 도는가 |
| --- | --- | --- |
| 기기 불필요 | 없음 | **항상**. 옵셔널이 아니다(FR-021c) |
| 실기기 | 안드로이드 실기기 | 기기가 연결됐을 때만(FR-021d) |

**결과 표현** (FR-021e) — 헌법 원칙 V가 직접 걸리는 지점:

| 상태 | 의미 |
| --- | --- |
| `passed` | 실제로 돌아서 통과함 |
| `failed` | 실제로 돌아서 실패함 |
| `skipped` | 기기가 없어 **돌지 못함** |

**불변식**: `skipped`는 `passed`로 집계되지 않는다(SC-015). 기기 없이 돌린 실행이 전부
초록불이어도 온디바이스는 검증되지 않은 상태이며, 결과가 그 사실을 말해야 한다.

## 이 기능이 다루지 않는 것

명세 「범위 밖」에 따라 아래는 모델링하지 않는다. 다음 기능에서 정의한다.

- 일기, 프롬프트, 샘플링 파라미터
- 모델 파일, 로스터, 캐릭터
- 기기 신호(사진·GPS·걸음 수·배터리)
- 사용자 설정, 저장된 상태
