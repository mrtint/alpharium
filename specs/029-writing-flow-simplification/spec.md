**Status**: Draft

## 배경과 문제 *(참고)*

이 스펙은 **새 기능이 아니라 누적된 UI 파편을 접는 리팩터**다. 지금 일기 하나를
쓰려면 홈 화면 하단 "쓰기 자리"에서 네 개의 위젯을 거쳐야 한다 — 캐릭터 고르기,
하루 고르기, 사진 설정 고르기, 장소명 토글. 각각은 007·009·011·012·014·018이
정당한 이유로 추가한 것이지만, 아무도 전체를 놓고 "매번 이걸 다 물어야 하나"를
재검토하지 않았다(AGENTS.md가 반복 경고하는 "한 축을 깊게 판" 실패의 누적 형태).

동시에 온보딩(021)은 권한만 다루고 캐릭터·VLM 모델은 사용자가 "캐릭터" 탭에서
직접 받게 되어 있다. 그래서 **앱을 처음 켜면 "일기 쓰기"를 눌러도 model-not-ready로
실패한다**(028 실기기 재확인). 최초 사용자가 첫 일기를 못 쓴다.

이 작업은 11번(NativeWind UI 시스템 도입)의 선행 과제다 — 흐름이 잘못된 화면을 먼저
예쁘게 만들면, 나중에 UX 정리로 화면이 합쳐질 때 그 디자인 작업이 버려진다(025에서
017 작업 일부가 날아간 패턴).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 최초 실행: 권한 다음 필수 에셋을 자동으로 받고 첫 일기까지 (Priority: P1)

앱을 처음 설치한 사용자가 온보딩을 진행한다. 권한 단계들을 마치거나 건너뛴 뒤,
"필수 에셋 다운로드" 화면이 나온다(모바일 게임의 "캐릭터 선택 → 에셋 로딩" 톤).
사진 보는 데 필요한 공용 모델과 기본 일기 작성자 캐릭터 하나가 자동으로 내려받아지며,
진행률 바가 채워진다. 다운로드가 끝나면 "시작하기"가 활성화되고, 홈 화면에서
"일기 쓰기"를 한 번 누르면 (오늘 일기가 없으므로 확인 없이) 곧바로 생성이 시작된다.

**Why this priority**: 이것이 없으면 최초 사용자가 앱을 쓸 수 없다(028이 확인한
model-not-ready). 나머지 스토리는 이 하나만 있어도 최초 사용자가 첫 일기를 얻는
최소 제품을 이룬다.

**Independent Test**: 앱 데이터를 완전히 지운 상태에서 온보딩을 끝까지 진행 →
에셋 다운로드 화면이 권한 단계 뒤에 나타나고 건너뛸 수 없음을 확인 → 다운로드
완료 후 홈에서 "일기 쓰기" 한 번 탭으로 생성이 시작되고 model-not-ready가 나지
않음을 확인.

**Acceptance Scenarios**:

1. **Given** 앱을 처음 실행하고 권한 단계를 모두 마쳤을 때, **When** 온보딩이
   다음 단계로 넘어가면, **Then** "필수 에셋 다운로드" 화면이 나타나고 공용 사진
   모델과 기본 캐릭터 하나의 다운로드가 자동으로 시작된다.
2. **Given** 에셋 다운로드 화면이 떠 있을 때, **When** 사용자가 이 단계를
   건너뛰려 하면, **Then** 건너뛸 방법이 없다("건너뛰기" 버튼이 없다) — 권한
   단계와 달리 이 단계는 필수다.
3. **Given** 에셋 다운로드가 진행 중일 때, **When** 화면을 보면, **Then** 진행
   상황이 하나의 합산 진행률 바로 표시되고(항목별 나열 없음) "시작하기"는 아직
   활성화되지 않는다.
4. **Given** 공용 사진 모델과 기본 캐릭터가 모두 준비되었을 때, **When**
   다운로드가 끝나면, **Then** "시작하기"가 활성화되고, 누르면 온보딩이 완료되어
   홈 화면으로 들어간다.
5. **Given** 온보딩을 마쳐 기본 캐릭터가 준비된 상태에서, **When** 홈에서 "일기
   쓰기"를 누르면(오늘 일기 없음), **Then** 캐릭터·사진·장소명을 따로 묻지 않고
   곧바로 생성이 시작된다.
6. **Given** 에셋 다운로드 중 앱을 백그라운드로 보냈다가 돌아오거나 온보딩을
   벗어났다 다시 열었을 때, **When** 에셋 다운로드 화면으로 복귀하면, **Then**
   이미 받은 만큼은 유지되고 남은 부분만 이어받으며, 온보딩 완료 게이트는 여전히
   "필수 에셋 준비됨"이 충족되지 않은 상태다.

### User Story 2 - 홈 화면에서 위젯 4개가 사라지고 "일기 쓰기" 한 번 탭으로 (Priority: P1)

이미 앱을 쓰고 있던 사용자가 홈 화면을 연다. 화면에는 일기 목록, "일기 쓰기"
버튼, 그리고 최근 3일 중 하나를 고르는 날짜 셀렉트 박스만 있다. 캐릭터 고르기,
사진 설정, 장소명 토글은 홈에서 사라졌다. "일기 쓰기"를 누르면 — 고른 날짜에
일기가 없으면 곧바로 생성, 이미 있으면 덮어쓰기 확인을 한 번 거친 뒤 생성.
캐릭터는 마지막에 쓴 캐릭터가, 사진·장소명 설정은 그 순간의 신호·권한 상태로
자동 결정된다.

**Why this priority**: 이 스펙의 본체다. 홈에서 매번 4개 위젯을 거치던 것을
1탭으로 접는다. US1(최초 실행)과 함께 P1 — 둘 다 있어야 "처음 켠 사람도, 쓰던
사람도 1탭으로 쓴다"가 성립한다.

**Independent Test**: 기존 사용자 데이터(마지막에 쓴 캐릭터 있음)로 홈을 열어
캐릭터·사진·장소명 위젯이 없음을 확인 → 날짜 셀렉트에서 오늘을 고르고 "일기
쓰기" 한 번 탭 → 확인 화면 없이(오늘 일기 없을 때) 생성 시작 → 생성된 일기가
마지막에 쓴 캐릭터로 쓰였는지 확인.

**Acceptance Scenarios**:

1. **Given** 마지막에 쓴 캐릭터가 있는 사용자가, **When** 홈 화면을 열면,
   **Then** 일기 목록·"일기 쓰기" 버튼·날짜 셀렉트 박스만 보이고 캐릭터 선택기·
   사진 설정 선택기·장소명 토글은 보이지 않는다.
2. **Given** 날짜 셀렉트에 최근 3일이 있고 기본값이 오늘일 때, **When** 사용자가
   다른 날을 고르지 않고 "일기 쓰기"를 누르면(그 날 일기 없음), **Then** 확인
   화면 없이 오늘 하루에 대한 생성이 시작된다.
3. **Given** 고른 날짜에 이미 일기가 있을 때, **When** "일기 쓰기"를 누르면,
   **Then** 덮어쓰기 확인 화면이 한 번 나오고, 확인을 누르면 생성이 시작된다
   (취소하면 목록으로 돌아간다).
4. **Given** 마지막에 쓴 캐릭터가 quiet인 사용자가, **When** "일기 쓰기"로 생성이
   완료되면, **Then** 그 일기는 quiet 캐릭터로 쓰인 것이다.
5. **Given** 정오 이전이라 오늘을 아직 쓸 수 없을 때, **When** 홈 화면을 보면,
   **Then** "오늘은 아직 쓸 수 없다"는 안내와 언제부터 쓸 수 있는지가 함께
   표시된다(012 정오 게이트 안내 유지).
6. **Given** 날짜 셀렉트에서 사흘 범위 밖으로 밀려난 날을 고른 상태로 시간이
   지났을 때, **When** "일기 쓰기"를 누르면, **Then** 그 선택은 조용히 기본값
   (마지막으로 닫힌 하루)으로 되돌려지고 화면도 같은 판정을 보여준다(009 유지).

### User Story 3 - 배선 계층이 생성 파라미터를 자동으로 정한다 (Priority: P1)

"일기 쓰기"가 눌리면, 화면이 아니라 배선 계층(src/app/)의 순수 함수가 생성에
넘길 네 값을 정한다: 캐릭터는 마지막에 쓴 캐릭터(없으면 온보딩 기본 캐릭터),
하루는 홈 셀렉트 박스 값, 사진 설정은 그 날 사진 신호가 있으면 "빠르게 봄",
없으면 "보지 않음", 장소명은 위치 권한이 있으면 켬·없으면 끔. 설정 탭에서
사용자가 고정값을 정해 두었으면 그 값이 자동 판정을 덮어쓴다.

**Why this priority**: US2가 "1탭"이 되려면 이 자동 판정이 반드시 있어야 한다.
프롬프트 조립(src/diary/prompt.ts)은 이 판정 이전 계층이며 무변경 — 여전히
캐릭터·하루·사진 설정만 받는다.

**Independent Test**: 기기 없는 계약 테스트로 자동 판정 함수에 (마지막 캐릭터,
셀렉트 날짜, 사진 신호 유무, 위치 권한 유무, 설정 탭 고정값) 조합을 넣어 나오는
(캐릭터, 하루, 사진 설정, 장소명) 네 값이 규칙대로인지 검증. prompt.ts의
시그니처가 바뀌지 않았음을 소스로 확인.

**Acceptance Scenarios**:

1. **Given** 마지막에 쓴 캐릭터가 narrative이고 설정 탭에 "일기 작성자" 고정값이
   없을 때, **When** 자동 판정이 돌면, **Then** 캐릭터로 narrative가 선택된다.
2. **Given** 마지막에 쓴 캐릭터가 아예 없는(첫 일기) 사용자가, **When** 자동
   판정이 돌면, **Then** 온보딩 기본 캐릭터(quiet)가 선택된다.
3. **Given** 고른 날짜에 사진 신호가 있을 때, **When** 자동 판정이 돌면(설정 탭
   사진 보기 = "자동"), **Then** 사진 설정으로 "빠르게 봄"이 정해진다.
4. **Given** 고른 날짜에 사진 신호가 없을 때, **When** 자동 판정이 돌면(설정 탭
   사진 보기 = "자동"), **Then** 사진 설정으로 "보지 않음"이 정해진다.
5. **Given** 위치 권한이 없을 때, **When** 자동 판정이 돌면(설정 탭 장소명 =
   "자동"), **Then** 장소명은 꺼진 상태로 정해진다.
6. **Given** 설정 탭에서 사진 보기를 "자세히 봄"으로 고정해 둔 사용자가, **When**
   자동 판정이 돌면(사진 신호 유무와 무관하게), **Then** 사진 설정으로 "자세히
   봄"이 정해진다.
7. **Given** 설정 탭에서 "일기 작성자"를 imaginative로 고정한 사용자가, **When**
   자동 판정이 돌면(마지막에 쓴 캐릭터가 quiet이더라도), **Then** 캐릭터로
   imaginative가 선택된다.

### User Story 4 - 설정 탭에서 작성자·사진 보기·장소명을 관리한다 (Priority: P2)

사용자가 설정 탭을 연다. "일기 작성자" 섹션에서 준비된 캐릭터 중 하나를 골라
고정하거나, 아직 준비되지 않은 캐릭터를 내려받을 수 있다(persona 이름·소개만
보이고 모델 정보는 없다). "사진 보기" 섹션에서 자동/보지 않음/빠르게 봄/자세히
봄 중 하나를 고른다(기본 "자동"). "장소명" 섹션에서 자동/켬/끔 중 하나를 고른다.
"자동"이 아닌 값을 고르면 US3의 자동 판정을 덮어쓴다.

**Why this priority**: 홈에서 걷어낸 통제권을 사용자가 되찾는 자리. P2 — US1~US3이
"1탭으로 쓴다"를 이루고, 이 스토리는 "자동 판정이 마음에 안 들 때 바꾼다"를 더한다.
없어도 최초 사용자는 첫 일기를 얻는다(자동 판정이 항상 작동하므로).

**Independent Test**: 설정 탭에서 "사진 보기"를 "보지 않음"으로 고정 → 사진이
있는 날에 "일기 쓰기" → 생성된 일기가 사진을 보지 않고 쓰였는지 확인. "일기
작성자"에서 준비된 다른 캐릭터로 바꾼 뒤 "일기 쓰기" → 그 캐릭터로 쓰였는지 확인.

**Acceptance Scenarios**:

1. **Given** 설정 탭을 연 사용자가, **When** "일기 작성자" 섹션을 보면, **Then**
   준비된 캐릭터는 골라서 고정할 수 있고, 준비되지 않은 캐릭터는 내려받기를 시작할
   수 있으며, 각 항목은 사람이 지은 이름·소개만 보이고 모델 식별자·파라미터는
   보이지 않는다.
2. **Given** 설정 탭에서 "사진 보기"를 "자세히 봄"으로 골랐을 때, **When** 그
   설정이 저장되면, **Then** 이후 "일기 쓰기"의 자동 판정은 사진 신호 유무와
   무관하게 "자세히 봄"을 쓴다.
3. **Given** 설정 탭에서 "장소명"을 "끔"으로 골랐을 때, **When** 위치 권한이 있는
   상태에서 "일기 쓰기"를 하면, **Then** 장소명은 꺼진 채로 생성된다.
4. **Given** 설정 탭의 세 섹션이 모두 "자동"/고정 없음일 때, **When** 설정 탭을
   처음 여는 사용자가 보면, **Then** "사진 보기"는 "자동", "장소명"은 "자동",
   "일기 작성자"는 마지막에 쓴 캐릭터(또는 온보딩 기본 캐릭터)가 선택된 것으로
   표시된다.
5. **Given** 설정 탭에서 준비되지 않은 캐릭터의 내려받기가 진행 중일 때, **When**
   그 화면을 보면, 진행 상황이 표시되고, 완료되면 그 캐릭터를 작성자로 고정할 수
   있게 된다.

### User Story 5 - 온보딩 완료 게이트에 "필수 에셋 준비됨"이 AND로 더해진다 (Priority: P2)

앱을 열 때, 온보딩 완료 판정은 "사용자가 온보딩을 끝냈다"와 "필수 에셋이
준비됐다"를 모두 만족해야 통과한다. 권한 단계를 다 건너뛰어도 에셋이 준비되지
않았으면 온보딩이 다시 뜬다. 에셋이 준비된 뒤 온보딩을 끝내면, 다음 실행부터는
곧바로 홈 화면으로 들어간다.

**Why this priority**: 028이 확인한 "처음 켜면 model-not-ready" 결함이 재발하지
않도록 하는 잠금. US1의 다운로드가 실제로 완료됐는지를 게이트가 확인한다.

**Independent Test**: 온보딩 완료 플래그는 true지만 기본 캐릭터 파일이 없는
상태를 만들어 앱을 열면 → 온보딩(에셋 다운로드 단계)이 다시 뜨는지 확인. 반대로
플래그 true + 에셋 준비됨이면 곧바로 홈으로 들어가는지 확인.

**Acceptance Scenarios**:

1. **Given** 온보딩 완료 플래그가 true이지만 공용 사진 모델 또는 기본 캐릭터가
   준비되지 않았을 때, **When** 앱을 열면, **Then** 홈 화면 대신 온보딩이 뜨고
   에셋 다운로드 단계로 이어진다.
2. **Given** 온보딩 완료 플래그가 true이고 공용 사진 모델·기본 캐릭터가 모두
   준비됐을 때, **When** 앱을 열면, **Then** 온보딩 없이 곧바로 홈 화면이 뜬다.
3. **Given** 사용자가 권한 단계를 모두 건너뛰었지만 에셋 다운로드는 아직 끝나지
   않았을 때, **When** "시작하기"를 누르려 하면, **Then** "시작하기"가 아직
   활성화되지 않아 온보딩을 끝낼 수 없다.

---

### Edge Cases

- **에셋 다운로드 중 저장 공간 부족**: 공용 사진 모델(~482MB)과 기본 캐릭터를
  받을 공간이 모자라면, 온보딩이 그 사실을 알리고 사용자가 공간을 확보한 뒤
  다시 시도할 길을 준다(막다른 길 금지). "시작하기"는 여전히 비활성.
- **에셋 다운로드 중 네트워크 끊김**: 이미 받은 만큼은 유지되고, 네트워크가
  돌아오면 남은 부분부터 이어받는다(026 세그먼트 이어받기 재사용).
- **마지막에 쓴 캐릭터가 나중에 준비를 잃음**(파일 손상·삭제): "일기 쓰기"의
  자동 판정이 그 캐릭터를 쓰려다 실패하지 않도록, 준비된 캐릭터로 옮기고 그
  사실을 알린다(007 resolveSelection 규칙 재사용). 옮길 준비된 캐릭터가 하나도
  없으면 설정 탭 "일기 작성자"로 안내한다.
- **설정 탭 "일기 작성자" 고정값이 준비를 잃음**: 자동 판정이 그 고정값을 쓸 수
  없으면, 마지막에 쓴 캐릭터 → 온보딩 기본 캐릭터 순으로 폴백하고 알린다.
- **날짜 셀렉트에서 고른 날이 사흘 범위 밖으로 밀려남**: 매 렌더 재판정으로 기본값
  (마지막으로 닫힌 하루)이 되며 파일에 저장하지 않는다(009 FR-010 유지).
- **홈에서 "일기 쓰기"를 눌렀는데 마지막 캐릭터도, 온보딩 기본 캐릭터도 준비되지
  않음**(정상 흐름에서는 US5 게이트가 막지만, 세션 중 파일이 사후 손상된 경우):
  생성을 시작하지 않고 설정 탭 "일기 작성자"로 안내한다(원칙 I — 실패가 텍스트를
  만들지 않는다). 이때 온보딩을 다시 띄우지 않는다 — 온보딩 재노출은 앱 진입
  시점의 FR-020 게이트만 한다(Clarifications 2026-09-02).
- **온보딩 중 에셋 다운로드가 이미 완료된 상태로 재진입**(사용자가 이전 세션에서
  다운로드만 끝내고 "시작하기" 전에 앱을 닫음): 다운로드 단계는 즉시 완료로 보이고
  "시작하기"가 바로 활성화된다.
- **정오 이전에 US2의 날짜 셀렉트 기본값**: 오늘이 아직 쓸 수 없는 상태면 안내
  문구가 뜨되, 셀렉트 박스에는 여전히 오늘이 기본값으로 있고 어제·그제도 고를 수
  있다(012 유지).

## Requirements *(mandatory)*

### Functional Requirements

#### 홈 화면 단순화

- **FR-001**: 홈 화면은 일기 목록, "일기 쓰기" 버튼, 최근 3일 중 하나를 고르는
  날짜 셀렉트 박스만 보여야 한다(MUST). 캐릭터 선택기, 사진 설정 선택기, 장소명
  토글, 그리고 그에 딸린 안내 문구는 홈 화면에 없어야 한다(MUST NOT).
- **FR-002**: 날짜 셀렉트 박스의 기본값은 당일이어야 하며, 고를 수 있는 날은
  009가 정한 최근 3일(마지막으로 닫힌 하루 + 그 앞 둘, 정오 이후에는 당일 포함)
  범위여야 한다(MUST). 이 스펙은 그 범위 규칙을 새로 만들지 않는다.
- **FR-003**: 고른 날짜는 파일에 저장하지 않아야 한다(MUST NOT) — 매 렌더마다
  범위를 재판정하며(009 FR-010), 범위 밖으로 밀려난 선택은 조용히 기본값으로
  되돌린다.
- **FR-004**: "일기 쓰기"를 한 번 누르면, 고른 날짜에 일기가 없을 때는 확인 없이
  곧바로 생성이 시작되어야 한다(MUST). 이미 일기가 있을 때는 덮어쓰기 확인 화면을
  한 번 거친 뒤 생성한다(MUST) — 012의 덮어쓰기 확인 흐름을 그대로 쓴다.
- **FR-005**: 오늘을 아직 쓸 수 없는 시각(정오 이전 등)에는 왜 아직인지와 언제부터
  쓸 수 있는지를 함께 알려야 한다(MUST) — 012 정오 게이트 안내를 유지한다.
- **FR-006**: 홈 화면에서 생성 파라미터(캐릭터·사진 설정·장소명)를 사용자에게
  묻지 않아야 한다(MUST NOT) — 이 값들은 US3의 자동 판정으로 정해진다.

#### 생성 파라미터 자동 판정

- **FR-007**: "일기 쓰기"가 눌리면, 생성에 넘길 네 값(캐릭터, 하루, 사진 설정,
  장소명 여부)을 배선 계층(src/app/)의 순수 함수가 정해야 한다(MUST) — 화면이
  정하지 않는다(MUST NOT).
- **FR-008**: 자동 판정의 캐릭터는 마지막에 쓴 캐릭터여야 한다(MUST). 마지막에 쓴
  캐릭터가 없으면 온보딩 기본 캐릭터를 쓴다(MUST).
- **FR-008a**: "마지막에 쓴 캐릭터"는 생성이 성공한 직후 그 캐릭터를 007의
  `selected-character.json`(preferences 디렉터리)에 기록해 얻어야 한다(MUST) —
  갱신 주체가 (제거되는) 홈 CharacterPicker에서 생성 파이프라인 성공 경로로 옮겨간다.
  설정 탭 "일기 작성자" 고정 선택도 같은 파일에 쓴다. 자동 판정(FR-007)은 이 파일
  하나를 읽는다. 새 저장 파일을 만들지 않는다(MUST NOT). **기록하는 값은 실제로 그
  일기를 쓴 캐릭터다** — 자동 판정이 준비를 잃은 캐릭터를 다른 캐릭터로 옮겼으면
  (FR-014, `movedFrom`), 원래 캐릭터가 아니라 **옮겨진 쪽**을 기록한다(MUST). 다음
  자동 판정의 "마지막에 쓴 캐릭터"가 준비된 캐릭터를 가리키게 된다.
- **FR-009**: 자동 판정의 하루는 홈 날짜 셀렉트 박스의 (재판정된) 값이어야 한다
  (MUST).
- **FR-010**: 자동 판정의 사진 설정은, 설정 탭 "사진 보기"가 "자동"일 때, 그 날
  사진 신호가 1장 이상이면 "빠르게 봄", 0장이면 "보지 않음"이어야 한다(MUST).
  최소 장수 임계값을 두지 않는다(MUST NOT — 원칙 V, 새 magic number 금지). 잡사진
  필터링은 023 `select.ts`가 이미 담당하므로 이 판정은 "사진 신호가 0장인가"만 본다.
- **FR-011**: 자동 판정의 장소명 여부는, 설정 탭 "장소명"이 "자동"일 때, 위치
  권한이 있으면 켬·없으면 끔이어야 한다(MUST).
- **FR-012**: 설정 탭에 고정값("자동"이 아닌 값)이 있으면 그 값이 자동 판정을
  덮어써야 한다(MUST) — 사진 보기 고정값, 장소명 켬/끔, 일기 작성자 고정 캐릭터
  각각.
- **FR-013**: 프롬프트 조립(src/diary/prompt.ts)의 입력 계약은 바뀌지 않아야 한다
  (MUST NOT change) — 여전히 캐릭터·하루·사진 설정만 받는다. 자동 판정은 그 앞
  계층에서 값을 정해 넘길 뿐이다(원칙 II — prompt.ts가 유일한 통과 지점).
- **FR-014**: 자동 판정한 캐릭터가 준비되지 않았으면(파일 손상·삭제 등), 준비된
  다른 캐릭터로 옮기고 그 사실을 알려야 한다(MUST) — 007 resolveSelection 규칙을
  재사용한다. 옮길 준비된 캐릭터가 하나도 없으면 생성을 시작하지 않고 설정 탭
  "일기 작성자"로 안내한다(MUST NOT 빈 일기 생성 — 원칙 I).

#### 온보딩 확장 — 필수 에셋 다운로드

- **FR-015**: 온보딩은 권한 단계들 뒤에 "필수 에셋 다운로드" 단계를 두어야 한다
  (MUST) — 공용 사진 모델(캐릭터 무관, ~482MB)과 기본 캐릭터 한 개를 자동으로
  내려받는다.
- **FR-016**: 에셋 다운로드 단계는 건너뛸 수 없어야 한다(MUST NOT skippable) —
  권한 단계는 건너뛰기를 유지한다(MUST). 모델 없이는 앱이 첫 일기를 쓸 수 없기
  때문이다.
- **FR-017**: 에셋 다운로드 단계는 진행 상황을 **하나의 합산 진행률 바**로 보여야
  한다(MUST) — 받아야 할 총 바이트 대비 받은 바이트. 항목별(파일별) 진행률을
  나열하지 않는다(MUST NOT — 026의 병렬성을 노출하지 않는다). 다운로드가 완료되기
  전에는 "시작하기"가 활성화되지 않아야 한다(MUST NOT).
- **FR-018**: 온보딩의 기본 캐릭터는 사람이 못 박은 고정값이어야 한다(MUST) — 이
  스펙에서 그 값을 quiet(금동이)로 확정한다(가장 빠르고 안정적, 헌법 로스터가
  "짧고 정확하다"로 관측). 코드가 로스터를 보고 정하지 않는다(MUST NOT — 원칙 V).
- **FR-019**: 온보딩 완료 게이트는 "사용자가 온보딩을 끝냈다"와 "필수 에셋
  준비됨"을 모두 만족할 때만 통과해야 한다(MUST AND). "필수 에셋 준비됨"은 공용
  사진 모델과 기본 캐릭터가 모두 준비 상태(003 readiness)임을 뜻한다.
- **FR-020**: 온보딩 완료 플래그가 true이더라도 **앱 진입 시점**(cold start·resume)에
  필수 에셋이 준비되지 않았으면 앱은 홈 화면 대신 온보딩(에셋 다운로드 단계)을 보여야
  한다(MUST) — 028의 model-not-ready 재발 방지. **이미 홈에 들어와 있는 세션 중**
  캐릭터가 사후 손상돼 자동 판정이 실패하는 경우는 FR-014가 다룬다(온보딩 재노출이
  아니라 설정 탭 안내) — 진입 게이트와 런타임 실패를 시점으로 가른다.
- **FR-021**: 에셋 다운로드가 중단되었다가 재개될 때, 이미 받은 부분은 유지되고
  남은 부분만 이어받아야 한다(MUST) — 026의 이어받기를 재사용한다.
- **FR-022**: 에셋 다운로드에 필요한 저장 공간이 부족하면, 온보딩은 그 사실을
  알리고 사용자가 공간을 확보한 뒤 다시 시도할 길을 주어야 한다(MUST — 막다른 길
  금지, 원칙 II).

#### 설정 탭 확장

- **FR-023**: 설정 탭은 "일기 작성자" 섹션을 두어야 한다(MUST) — 준비된 캐릭터를
  골라 고정할 수 있고, 준비되지 않은 캐릭터는 내려받기를 시작할 수 있다. 각 항목은
  사람이 지은 이름·소개(persona)만 보여야 하며, 모델 식별자·파라미터 수·양자화
  방식은 보이지 않아야 한다(MUST NOT — 원칙 III).
- **FR-024**: 설정 탭은 "사진 보기" 섹션을 두어야 한다(MUST) — 자동 / 보지 않음 /
  빠르게 봄 / 자세히 봄 중 하나. 기본값은 "자동"이다(MUST).
- **FR-025**: 설정 탭은 "장소명" 섹션을 두어야 한다(MUST) — 자동 / 켬 / 끔 중
  하나. 기본값은 "자동"이다(MUST).
- **FR-026**: 설정 탭에서 고른 "일기 작성자" 고정값, "사진 보기" 값, "장소명" 값은
  기기에 저장되어 앱을 다시 열어도 유지되어야 한다(MUST) — preferences 디렉터리.
  "일기 작성자" 고정값은 FR-008a의 `selected-character.json`에 쓴다(같은 파일).
  "사진 보기"·"장소명"의 "자동" 상태는 각각 별도 파일(011 `vision-setting.json`,
  017 `geocoding-setting.json`)에 얹는 저장 가능한 상태다. "자동"/고정 없음도 하나의
  명시적 상태이며, 파일이 없을 때의 기본값이 "자동"이다.
- **FR-027**: 설정 탭의 화면 계층은 모델 파일·로스터 매핑을 직접 알지 않아야 한다
  (MUST NOT) — "일기 작성자" 섹션도 persona 문자열과 준비 상태만 받는다(원칙 III,
  007 CharacterPicker 선례).

#### 유지되는 경계 (회귀 금지)

- **FR-028**: 생성 흐름 자체(generate()가 판정 후에만 저장, 거부 시 파일 안
  건드림)는 바뀌지 않아야 한다(MUST NOT change) — 원칙 I.
- **FR-029**: 하루 경계 판정은 여전히 src/config/day-boundary.ts 한 곳에만 있어야
  한다(MUST) — 이 스펙은 새 경계 함수를 만들지 않는다.
- **FR-030**: 판정 갈래(acceptance)는 넷으로 유지되어야 한다(MUST NOT add) — 이

### Key Entities *(데이터가 관련되므로 포함)*

- **온보딩 플래그 (OnboardingFlag)**: 사용자가 온보딩을 끝냈는지, 배터리 안내를
  제시했는지를 담는다(021). 이 스펙은 여기에 "언제 봤나"류 측정 필드를 더하지
  않는다(원칙 IV). "필수 에셋 준비됨"은 이 플래그가 아니라 모델 준비 상태(003
  readiness)를 실시간으로 조회해 AND로 판정한다.
- **필수 에셋 (Essential Assets)**: 공용 사진 모델(v1+v2, 캐릭터 무관)과 온보딩
  기본 캐릭터(quiet) 한 개. 준비 여부는 003의 readiness 판정을 재사용한다. 이
  스펙은 새 다운로드 계층을 만들지 않고 011(vision roster)·003(character
  acquisition)·026(segmented download)을 재사용한다.
- **설정 탭 선호 (Settings Preferences)**: "일기 작성자" 고정 캐릭터(또는 없음),
  "사진 보기" 값(자동/보지 않음/빠르게 봄/자세히 봄), "장소명" 값(자동/켬/끔).
  기기의 preferences 디렉터리에 저장된다(007 선례). "사진 보기"의 3+1 상태는 기존
  VisionSetting(none/quick/detailed)에 "자동" 상태를 얹은 것이다.
- **자동 판정 결과 (Resolved Generation Params)**: 배선 계층 순수 함수가
  (마지막 캐릭터, 셀렉트 날짜, 사진 신호 유무, 위치 권한, 설정 탭 선호)로부터
  정하는 (캐릭터, 하루, 사진 설정, 장소명 여부). prompt.ts로 넘어가기 직전의
  값이며 어디에도 저장되지 않는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 앱을 처음 설치한 사용자가 온보딩을 마친 뒤 홈에서 "일기 쓰기"를 한
  번 눌러 (오늘 일기가 없을 때) 생성을 시작할 수 있다 — model-not-ready 실패가
  발생하지 않는다.
- **SC-002**: 홈 화면에 캐릭터 선택기·사진 설정 선택기·장소명 토글이 하나도
  나타나지 않는다. 일기 하나를 쓰는 데 필요한 홈에서의 탭 수는 최대 2회다("일기
  쓰기" + 덮어쓰기 확인 1회, 오늘 일기가 없으면 1회).
- **SC-003**: 생성된 일기의 캐릭터가 사용자가 마지막에 쓴 캐릭터(또는 설정 탭
  고정값, 또는 첫 일기는 온보딩 기본 캐릭터)와 일치한다.
- **SC-004**: 온보딩 완료 플래그가 true여도 필수 에셋이 준비되지 않은 상태에서
  앱을 열면 온보딩이 다시 뜬다. 에셋이 준비된 뒤 온보딩을 끝내면 다음 실행부터
  곧바로 홈으로 들어간다.
- **SC-005**: 설정 탭에서 "사진 보기"를 "보지 않음"으로 고정한 뒤 사진이 있는 날에
  일기를 쓰면, 그 일기는 사진을 보지 않고 쓰인다(자동 판정이 덮어써진다).
- **SC-006**: prompt.ts의 입력 시그니처가 이 스펙 전후로 동일하다(소스 비교로
  확인). 판정 갈래 수가 넷으로 유지된다.
- **SC-007**: 헌법 파일의 버전이 v1.3.0이고, 로스터 조항이 개정된 문구를 담으며,
  개정 근거가 기록되어 있다 — 이 변경이 코드 변경보다 먼저 커밋되어 있다.
- **SC-008**: 기기 없는 테스트 전부 통과(자동 판정 계약 테스트, 온보딩 게이트
  계약 테스트, 설정 저장/로드 테스트 포함), lint·헌법 검사·prettier 클린.
- **SC-009**: 실기기(SM-S901N)에서 최초 실행 시나리오(앱 데이터 삭제 → 온보딩 →
  에셋 다운로드 → 첫 일기 1탭)와 기존 사용자 시나리오(홈 1탭 → 생성)가 각각 최소
  1회 확인된다.

## Assumptions

- **온보딩 기본 캐릭터는 quiet(금동이)로 확정한다.** 헌법 로스터가 "짧고 정확하다.
  본 것만 쓰고 멈춘다. 한국어가 가장 깨끗하다"로 관측했고, 018·023·024가 quiet를
  웜 2~3초로 가장 빠르게 완주하는 캐릭터로 반복 실측했다. narrative(exaone)는
  024·028이 자동 생성 부적합으로 확정했으므로 기본값이 될 수 없다.
- **공용 사진 모델(VLM)은 011의 vision roster(v1+v2, ~482MB)를 그대로 쓴다.** 이
  스펙은 새 VLM을 고르지 않는다. "빠르게 봄"/"자세히 봄"의 차이는 011~013이 정한
  시각 설정이며 인코더 교체가 아니다.
- **에셋 다운로드는 026의 병렬·세그먼트·이어받기를 재사용한다.** 온보딩이 새
  다운로드 엔진을 만들지 않는다. 공용 사진 모델은 011이 DownloadPort를 캐릭터 없이
  재사용하는 구조라 자동으로 세그먼트 병렬을 얻는다.
- **"사진 보기"·"장소명"의 "자동" 상태 저장 방식은 FR-026을 따른다** — VisionSetting
  타입(none/quick/detailed)은 불변이고, "자동"은 스토어 반환 유니온일 뿐 타입에
  추가되지 않는다. 기본값이 "자동"이므로 이 기능 이전과 동작이 같아야 한다(017
  FR-005 정신 유지: 자동 + 권한 없음 = 이전과 동일).
- **홈에서 걷어낸 위젯의 소스 컴포넌트(CharacterPicker·VisionPicker·
  GeocodingSettingToggle)는 설정 탭에서 형태를 바꿔 재등장하거나 폐기된다** —
  이 스펙은 "홈에서 안 보인다"를 요구할 뿐, 컴포넌트 파일의 물리적 삭제 여부는
  구현 단계 판단이다.
- **실기기 검증은 debug 1회로 충분하다**(012 기준) — 이 스펙은 새 네이티브
  모듈이나 빌드 설정을 건드리지 않는다(온보딩 다운로드는 026의 기존 통로,
  설정 저장은 007의 기존 expo-file-system 통로).
- **"캐릭터" 탭은 설정 탭 "일기 작성자" 섹션에 완전히 흡수하고 별도 탭을 없앤다**
  (2026-09-02 확정, Q1 = A). 설정 탭 "일기 작성자" 섹션이 준비된 캐릭터 고정 선택과
  미준비 캐릭터 다운로드 관리를 모두 담는다. CharacterListScreen과 관련 탭
  네비게이션·Maestro 흐름 문자열을 갱신한다. FR-023이 이것을 요구한다.
- **설정 탭 화면 분리** — AutoDiarySettingsScreen(020, 자동 생성 설정)에 세 섹션
  (작성자·사진 보기·장소명)이 더해지면 화면이 길어진다. 기본 가정은 "한 화면에
  섹션으로 나열하되, 스크롤이 과하게 길어지면 구현 단계에서 하위 화면으로 뗀다"
  — 이는 UI 구조 판단이라 스펙 요구사항으로 못 박지 않는다.
