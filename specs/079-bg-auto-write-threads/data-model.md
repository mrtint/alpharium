# Data Model: 백그라운드 자동 쓰기 완주 (079)

저장되는 것은 없다. 아래는 모두 실행 중에만 있는 값이다.

## 조립 주체 (`AssemblyOwner`)

| 값 | 누가 | 잠금 주체 |
| --- | --- | --- |
| `"screen"` | 홈 쓰기·앱을 열 때 쓰기·첫 실행 자동 첫 일기·진단 「한 번 써 보기」·정상 동작 확인·미리 준비 | `"screen"` |
| `"background"` | `runAutoDiaryTask` — OS가 깨운 실행과 진단의 수동 실행 | `"background"` |

- `wiring.ts`의 `deps.lockOwner ?? "screen"` 한 변수에서 나온다. 잠금(020 L5)과 백엔드 선택이 같은 변수를 받는다.
- 저장하지 않는다. 파이프라인을 조립할 때 한 번 정해지고 그 백엔드의 수명 동안 바뀌지 않는다.

## 주체에서 따라 나오는 값

| 주체 | 플랫폼 | `n_threads` | 생성 시간 한도 |
| --- | --- | --- | --- |
| `screen` | android | 싣지 않음 | 180,000ms (`GENERATION_TIMEOUT_MS`) |
| `screen` | ios | 싣지 않음 | 180,000ms |
| `background` | android | 2 (`BACKGROUND_THREADS`) | 600,000ms (`BACKGROUND_GENERATION_TIMEOUT_MS`) |
| `background` | ios | 싣지 않음 | 600,000ms |

- 「싣지 않음」은 `initLlama` 인자에 키가 없다는 뜻이다(`undefined` 값의 키도 아니다).
- 스레드 값은 본문 모델과 사진 모델에 같이 쓰인다.
- 시간 한도는 본문 생성에 한 번, 제목 질문에 같은 값으로 한 번 더 쓰인다(061).

## 도는 생성 (엔진 내부 상태)

| 상태 | 뜻 | 전이 |
| --- | --- | --- |
| 없음 | 엔진이 호출을 돌리고 있지 않다 | `run`·`ask`·`prewarm`이 시작되면 → 있음 |
| 있음 | 호출 하나가 네이티브에서 돌고 있다 | 그 호출이 끝나면(성공·거부) → 없음 |

- `unload()`는 「있음」이면 멈춤을 보내고 「없음」이 될 때까지 기다린 뒤 컨텍스트를 놓는다. 「없음」이면 바로 놓는다.
- 엔진 인스턴스마다 하나다. 화면의 엔진과 백그라운드의 엔진은 서로의 상태를 모른다(백엔드가 따로 조립된다).
