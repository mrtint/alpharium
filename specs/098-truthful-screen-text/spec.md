## 근거와 원본

- **설계**: `docs/superpowers/specs/2026-10-22-truthful-screen-text-design.md`(새 문장은 소유자 확정, 2026-10-22).
- **로드맵 과제**: 「화면 문구를 사실대로 — 자동 쓰기 약속·장소 이름·교체/삭제 예고」.
- **문제**: 화면이 실제 동작과 다르게 말하거나 결과를 덜 말하는 자리가 다섯 군데 남아 있다. 자동 쓰기는 기본값이 꺼짐인데 첫 실행 슬라이드는 「잠들기 전에 도착해요」라고 약속한다. 설정 「장소 이름으로 보기」의 보조 줄은 051 이후 거짓이다. 홈의 「장소 N곳」이 무엇을 센 값인지 어디에도 없다. 다시 쓰기와 지우기 확인은 결과를 덜 말한다. 해라체 문구가 둘 남아 있다.
- **범위 밖**: UX-14(재료 없는 날의 「상상」·「지어낸 하루」 낱말), C9(앱을 지우면 일기가 사라진다는 안내 — 「일기·모델 백업과 유실 안내」 과제가 맡는다), 동작 변경, `plugins/`·`app.json`·`site/privacy/`·안드로이드 백업 규칙·모델 경로, 지원 페이지 「앱을 지우면」 답 문단.

## 용어

- **확정 문장**: 설계문서 표의 「새 문장」. 소유자가 정했으며 이 스펙의 정본이다.
- **문구 골든**: `__tests__/i18n/ko-golden.test.ts`. 다시 쓰지 않고 `CHANGED_AFTER_GOLDEN`·`ADDED_AFTER_GOLDEN`에 올린다(062).

## Clarifications

### Session 2026-10-22

- Q: 홈 장소 칸이 「0곳」(읽었는데 찍힌 자리가 없음)으로 보이는 날에도 화면 낭독이 「사진이 찍힌 자리 0곳」이라고 읽어야 하나? → A: 읽는다. 화면에 숫자로 보이는 두 경우(1곳 이상·관측된 0곳)에만 라벨을 달고, 모름·읽는 중·권한 없음은 라벨 없이 기존 글자 그대로 둔다.

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 첫 실행 슬라이드가 지킬 수 있는 말만 한다 (Priority: P1)

처음 앱을 연 사람이 모듈을 받는 동안 슬라이드 3을 읽는다. 자동 쓰기를 켜지 않아도 참인 말만 보이고, 알림과 먼저 써 두기는 자동 쓰기를 켠 경우의 이야기로만 나온다.

**Why this priority**: 가장 먼저 만나는 약속이 거짓이면 첫인상과 신뢰를 해친다.

**Independent Test**: 카탈로그의 슬라이드 3 제목·본문을 읽는 단위 테스트와 실기기 내려받기 화면.

**Acceptance Scenarios**:

1. **Given** 첫 실행 내려받기 화면, **When** 슬라이드 3이 보인다, **Then** 제목은 「열면 바로 그날 일기를 써요」, 본문은 「자동으로 쓰기를 켜 두면 쓸 차례에 알림이 오고, 먼저 써 두기도 해요.」다.
2. **Given** 슬라이드 3 본문, **Then** 알림·먼저 써 둠은 「켜 두면」 조건 아래에만 있고, 바이트·퍼센트·시간 표현이 없다(045 FR-006).

---

### User Story 2 - 장소 이름 설정과 홈의 장소 수가 사실대로 설명된다 (Priority: P1)

설정의 「장소 이름으로 보기」 보조 줄은 이름이 일기를 쓸 때 참고될 뿐이라고 말한다. 홈의 「장소 N곳」은 화면 낭독에서 사진이 찍힌 자리의 수로 읽히고, 지원 페이지 FAQ가 그 수가 무엇인지 설명한다.

**Why this priority**: 사용자가 설정 결과를 잘못 기대하거나 장소 수를 이동 거리로 오해한다.

**Independent Test**: 카탈로그 값 단언, 장소 칸의 접근성 라벨 렌더 단언, 지원 페이지 FAQ 계약 테스트.

**Acceptance Scenarios**:

1. **Given** 설정의 장소 이름 대화상자, **Then** 「켬」 보조 줄은 「일기를 쓸 때 다닌 자리의 이름을 참고해요」, 「자동」 보조 줄은 「위치 권한이 있으면 이름을 참고하고, 없으면 비워 둬요」다. 「끔」 보조 줄과 `placeNotice`는 그대로이며 서로 겹치지 않는다.
2. **Given** 사진이 찍힌 자리가 N곳인 날의 홈 재료 칸, **When** 화면 낭독이 장소 값 줄을 읽는다, **Then** 「사진이 찍힌 자리 N곳」이 읽힌다. 라벨은 칸 컨테이너가 아니라 값 줄에 있다.
3. **Given** 홈 재료 격자, **Then** 격자 아래에 보이는 설명 줄은 없다(053 보드 1d ④).
4. **Given** 지원 페이지, **Then** FAQ 맨 끝에 「홈의 장소 수는 무엇인가요?」 항목이 있고 답은 확정 문장이다. 100m 같은 짐작 상수는 적지 않는다. 기존 항목, 특히 「앱을 지우면」 답은 바뀌지 않는다.

### User Story 3 - 다시 쓰기와 지우기가 결과를 사실대로 예고한다 (Priority: P1)

다시 쓰기 확인은 새 글로 바뀐 뒤에는 되돌릴 수 없다고 말한다. 지우기 확인은 휴대폰의 사진 원본이 남는다고 말한다.

**Why this priority**: 되돌릴 수 없는 동작의 확인이 결과를 덜 말하면 사용자가 선택을 잘못한다.

**Independent Test**: 두 확인 대화상자의 본문 단언. 실기기에서 지운 뒤 모델 파일과 사진 수가 그대로인지 센다.

**Acceptance Scenarios**:

1. **Given** 쓴 날의 다시 쓰기 확인, **Then** 본문은 「다 쓰면 지금 일기가 새 글로 바뀌어요. 바뀐 뒤에는 되돌릴 수 없어요.」다. 「바뀐 뒤에는」 조건이 있어 취소·실패 경로에서도 거짓이 아니다(050 OW8·071).
2. **Given** 오늘의 다시 쓰기 확인, **Then** 같은 본문에 `todayNote`가 그대로 이어 붙는다.
3. **Given** 「일기 모두 지우기」 확인, **Then** 본문은 「되돌릴 수 없어요. 휴대폰의 사진과 이름·설정은 남아요.」다. 모듈은 열거하지 않는다.
4. **Given** 일기를 모두 지운 뒤, **Then** 휴대폰의 사진 수와 `files/models` 파일은 지우기 전과 같다(문구가 말한 대로 동작한다).

---

### User Story 4 - 해라체 두 문구가 해요체가 된다 (Priority: P2)

쓰기 시작 직전의 자리 문구와 작성자 준비 안내가 앱의 나머지와 같은 말투가 된다.

**Why this priority**: 말투 일관성. 동작에는 영향이 없다.

**Independent Test**: 카탈로그 값 단언과 홈 화면 렌더 단언.

**Acceptance Scenarios**:

1. **Given** 첫 진행 신호가 오기 전의 쓰는 중 화면, **Then** 「쓰고 있어요」가 보인다.
2. **Given** 준비된 작성자가 없는 홈, **Then** 「일기 작성자를 준비해야 해요」가 「모듈 다시 받기」 버튼과 함께 보인다.

### Edge Cases

- 글꼴 2.0배에서 길어진 문장(슬라이드 3 본문, 지우기 확인 본문)이 잘리거나 가려지지 않는다.
- 관측된 0곳(화면에 회색 `0`으로 보이는 날)은 「사진이 찍힌 자리 0곳」으로 읽힌다. 값을 모르거나(「모름」)·읽는 중이거나·사진 권한이 없는 날은 숫자를 지어내지 않는다 — 모르는 것을 채우지 않는다(원칙 V). 이 경우는 라벨을 달지 않고 기존 값 줄의 읽힘을 그대로 둔다.
- 안드로이드와 iOS가 같은 카탈로그 문장을 쓴다(플랫폼 분기 없음).
- 소스 주석이 옛 문구를 인용하는 자리가 남지 않는다.

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 첫 실행 슬라이드 3은 확정 문장(제목·본문)을 쓴다. 본문에 알림·먼저 써 둠이 조건 없이 나오지 않는다.
- **FR-002**: 설정 장소 이름 대화상자의 「켬」·「자동」 보조 줄은 확정 문장을 쓴다.
- **FR-003**: 홈 재료 칸의 장소 값 줄은 숫자가 화면에 보일 때(1곳 이상·관측된 0곳) 「사진이 찍힌 자리 N곳」이라는 접근성 라벨을 가진다. 문구는 카탈로그의 새 항목에서 온다. 모름·읽는 중·권한 없음이면 라벨을 달지 않고 숫자를 지어내지 않는다.
- **FR-004**: 지원 페이지 FAQ 맨 끝에 「홈의 장소 수는 무엇인가요?」 항목을 더한다. 기존 항목은 바꾸지 않는다.
- **FR-005**: 다시 쓰기 확인 본문은 확정 문장이다.
- **FR-006**: 지우기 확인 본문은 확정 문장이다.
- **FR-007**: 쓰는 중 자리 문구와 작성자 준비 안내는 해요체 확정 문장이다.
- **FR-008**: 화면에 보이는 한글은 카탈로그에만 둔다(062). 바뀐 문구는 문구 골든에 `CHANGED_AFTER_GOLDEN`(literal + outputs)으로, 새 항목은 `ADDED_AFTER_GOLDEN`으로 올린다. 골든 본문은 다시 쓰지 않는다.
- **FR-009**: 옛 문구를 하드코딩한 테스트 단언과 옛 문구를 인용하는 소스 주석을 새 문장에 맞게 고친다.
- **FR-010**: 동작·데이터·권한·플랫폼 설정은 바뀌지 않는다. 지원 페이지 외의 `site/`, `plugins/`, `app.json`은 건드리지 않는다.

### Key Entities

- 없음(문구와 접근성 라벨만 바뀐다).

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 바뀌는 옛 문자열 여덟 개가 화면 어디에도 남지 않는다 — 카탈로그·소스·테스트 단언·Maestro 실행 줄에 옛 문장이 0건이다(옛 값을 일부러 보존하는 골든 json 두 파일과 `ko-golden.test.ts`의 `CHANGED_AFTER_GOLDEN` `from` 값, 주석의 역사 인용은 예외).
- **SC-002**: 첫 실행 슬라이드 3은 자동 쓰기를 켜지 않은 사용자에게도 참이다 — 조건 없는 알림·완성 약속이 0건이다.
- **SC-003**: 장소 값 줄을 화면 낭독으로 들으면 100%의 알려진 값에서 「사진이 찍힌 자리 N곳」으로 읽힌다(실기기 TalkBack 1회).
- **SC-004**: 일기를 모두 지운 뒤 휴대폰의 사진 수와 모델 파일 해시가 지우기 전과 같다(실기기 1회) — 지우기 확인의 약속이 동작과 일치한다.
- **SC-005**: `npm test`와 `npm run lint`가 통과하고, 조건 없는 알림 약속을 슬라이드에 되돌려 넣는 위반 주입을 테스트가 잡는다.

## Assumptions

- 새 문장은 소유자 확정 사항이며 이 과제에서 다시 고르지 않는다.
- 모듈을 받지 않은 채 내려받기 화면을 다시 볼 수 있으므로(074 절차) 실기기 확인은 모델을 보존한 채 한다.
- iPhone 실기기는 지금 prod 빌드라 개발자·진단 화면이 없다. 실기기 확인은 SM-S901N dev 빌드로 한다.
- 지원 페이지 FAQ의 「가까운 곳은 한 자리로 묶어 센다」는 `tracePlaces`가 사용 가능한 좌표만 묶어 센다는 소스 사실에 기대며, 사진에 위치 정보가 없으면 좌표 자체가 없어 세지 않는다.
- 백업 과제(병렬 세션)가 같은 지원 페이지와 `ko-golden.test.ts` 목록을 고친다. 충돌 시 양쪽 항목을 모두 남긴다.
