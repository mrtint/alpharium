# 계약: 낡은 흐름 판정 절차

흐름 하나(`skeleton`·`prompt-preview`·`today-diary`)마다:

1. 층 1 기준 상태를 만든 뒤(`npm run test:layer1 -- <흐름>`처럼 흐름 인자) 그 흐름만 돌려 실패한 첫 단계를 기록한다.
2. 그 단계의 화면을 직접 본다(`screencap`; 이 기기는 `uiautomator dump`가 항상 `Killed`다 — AGENTS). 원인을 하나로 가른다: **문구·문안 변경 / 기준 상태 / 앱 결함**.
3. 앱 결함 → 흐름을 맞추지 않고 결함으로 보고한다(FR-004). 그 흐름은 결함이 고쳐질 때까지 `FLOWS`에 둔다(실패가 신호다) 또는 소유자에게 묻는다.
4. 문구·문안 → 지키는 것이 다른 흐름과 겹치면 삭제, 유일하면 고친다. 고칠 때 문구 대신 `testID`·구조를 쓴다.
5. 결과를 `FLOWS` 위 주석·대응표 인벤토리에 한 줄로 남긴다(원인·고침/삭제·근거).

**겹침 판정 기준**: 삭제하려면 같은 단언을 하는 다른 흐름의 이름과 단언 줄을 근거에 적는다. 적을 수 없으면 고친다.
