# Quickstart: Modernist 첫 만남·작명 화면 검증

## 전제 조건

- Android 실기기(dev/debug), USB 또는 무선 디버깅 연결, 잠금 해제 상태.
- `adb reverse tcp:8081 tcp:8081` 실행됨.
- Metro가 `EXPO_PUBLIC_APP_ENV=dev npx expo start --dev-client`로 떠 있음.
- 043(스플래시·권한 흐름)이 이미 병합되어 있어 그 화면을 지나 작명 화면에
  도달할 수 있어야 한다.

## 기기 없는 검증 (항상 먼저)

```bash
npm run test:ui       # WelcomeScreen 화면 렌더 계약 (기존 welcome-screen.test.tsx)
npm run test:logic    # 토큰 값 계약 (043이 만든 것, 무변경 재확인)
npm run lint           # eslint + tsc + 헌법 검사 + prettier
npm test               # 전체 (커밋 전)
```

**기대 결과**: `__tests__/ui/welcome-screen.test.tsx`의 기존 테스트
(W11~W16, FR-012~FR-014 관련 describe 블록) 전부가 시각 변경 이후에도
그대로 통과한다 — `testID` 조회와 prop 검증만 하므로 스타일 변경과
무관하게 초록불이어야 한다(research.md R5).

## 실기기 검증 시나리오

### D1 — 작명 화면 레이아웃 (SC-001, User Story 1)

1. 온보딩·권한 결정을 마쳐 작명 화면(`welcome` phase)에 도달한다.
2. **관찰**: 오프화이트 배경(043 `COLORS.bg`) 위에 좌측 정렬로 굵은
   제목·본문 텍스트, 구분선, 이름 프롬프트, 입력줄, 힌트, 하단
   [건너뛰기]/[이 이름으로 할래요] 버튼이 가로로 배치되어 보인다.
3. **관찰**: 캐릭터 이름 외에 모델 식별자·자산 키·진행률 수치가
   화면 어디에도 보이지 않는다.

### D2 — 이름 입력·확정 (SC-002, User Story 2)

1. 이름 입력창에 이름을 입력한다.
2. **관찰**: [이 이름으로 할래요] 버튼이 활성 상태(레드 액센트 배경)로
   바뀐다.
3. 버튼을 누른다.
4. **관찰**: 이름이 확정되고 다음 화면으로 전환된다(범위 밖 — 다운로드
   대기 또는 liveness 확인).

### D3 — 건너뛰기 (SC-002, User Story 2)

1. 작명 화면에서 아무것도 입력하지 않는다.
2. [나중에 할래요]를 누른다.
3. **관찰**: 기본 이름으로 다음 화면으로 넘어간다(막다른 길 없음).

### D4 — 12자 초과 입력 (User Story 2 시나리오 4)

1. 이름 입력창에 13자 이상을 입력하려 시도한다.
2. **관찰**: 12번째 글자에서 입력이 막힌다.

### D5 — 확인 중·실패 화면 (SC-001·SC-003, User Story 3)

1. 작명을 마친 뒤 정상 동작 확인(liveness)이 진행되는 순간을 관찰한다.
2. **관찰**: 043 `LogoScreen`과 같은 중앙 정렬 레이아웃 — 로딩
   인디케이터와 안내 문구가 화면 중앙에 카드·테두리 없이 보인다.
   숫자로 된 진행률은 없다.
3. (확인이 실패로 확정되는 경로를 재현할 수 있다면) 실패 화면을 본다.
4. **관찰**: 같은 중앙 정렬 레이아웃 위에 고정 안내 문구와 [다시
   시도]/[그냥 시작하기] 버튼이 함께 보인다. 오류 사유·파일 경로는
   보이지 않는다.

### D6 — Maestro 회귀 (SC-002)

```bash
npm run test:device   # 또는 .maestro/welcome-naming.yml 단독 실행
```

**기대 결과**: 035가 만든 흐름이 시각 변경 이후에도 통과한다 —
`testID`가 바뀌지 않았으므로(research.md R5) 흐름 자체를 수정할 필요가
없어야 한다.
