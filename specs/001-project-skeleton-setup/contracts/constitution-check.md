# 계약: 헌법 위반 자동 검사

**대상**: `scripts/check-constitution.mjs`
**관련 요구사항**: FR-026~FR-029, FR-014~FR-016, SC-003, SC-005, SC-012

---

## 목적

헌법이 금지한 설정이 저장소에 들어오는 것을 **사람의 주의력에 기대지 않고** 막는다.
되돌리기의 원인이 잘못된 설정이 쌓여도 아무도 못 본 것이었다.

---

## 실행 지점 (FR-026)

- `npm run lint`에 포함 — 개발 중 즉시 걸린다
- CI의 test 단계 — 커밋이 원격에 올라갈 때 걸린다

**종료 코드**: 위반 0건이면 `0`, 1건 이상이면 `0이 아닌 값`.

---

## 검사 항목 (FR-027)

| # | 검사 | 근거 |
| --- | --- | --- |
| 1 | dev·prod 환경 설정에 데스크톱 서버 주소 키가 존재하는가 | FR-014 |
| 2 | 원격 API 추론(외부 모델 API)을 가리키는 설정이 존재하는가 | FR-015, 원칙 I |
| 3 | 대체 응답(mock fallback) 스위치가 존재하는가 | FR-016, 원칙 I |

**1번은 값이 아니라 키의 존재를 본다.** 값을 비워도 키가 있으면 위반이다 — 키가 있으면
언젠가 값이 채워진다(research.md §3).

---

## 검증 표 (SC-012)

각 항목은 **일부러 위반을 넣었을 때 실패하는지**로 검증한다. 검사가 아무것도 못 잡는데 통과만
하는 상태가 가장 위험하다.

| 상황 | 기대 |
| --- | --- |
| 위반 없는 저장소 | 종료 코드 `0` |
| prod 설정에 서버 주소 키 추가 | 실패. 파일과 키를 지목 |
| 외부 모델 API 주소 설정 추가 | 실패. 파일과 키를 지목 |
| mock fallback 스위치 추가 | 실패. 파일과 키를 지목 |
| local 설정에 서버 주소 키 존재 | **통과** — local에는 허용된다(FR-011) |

**마지막 줄이 중요하다.** 검사가 과하게 잡으면 local의 정당한 설정까지 막아 개발이 불가능해진다.

---

## 실패 보고 (FR-029)

실패 시 **어느 파일의 어느 설정이 왜 걸렸는지**가 출력되어야 한다.

```
헌법 위반 2건

  .env.production
    EXPO_PUBLIC_AI_API_BASE_URL — prod 설정에 서버 주소 키가 있다 (FR-014, 원칙 I)

  .env.development
    EXPO_PUBLIC_ENABLE_MOCK_FALLBACK — 대체 응답 스위치 (FR-016, 원칙 I)
```

**"검사 실패"만 출력하고 끝내지 않는다.** 무엇이 걸렸는지 모르면 고칠 수 없고, 사람은 검사를
꺼버린다.

---

## 이 검사가 헌법 원칙 IV에 저촉되지 않는 이유 (FR-028)

원칙 IV는 **모델 출력을 점수화·비교·자동 채점하는 코드**를 제품에 들이는 것을 금지한다.

이 검사는 **설정 파일에 금지된 키가 있는지**를 본다. 모델을 부르지 않고, 출력을 만들지 않고,
품질을 재지 않는다. 원칙 IV가 막으려는 "측정 장치"가 아니다.

**이 경계를 스크립트 주석에도 남긴다.** 남기지 않으면 다음 세션이 "이미 검사 스크립트가
있으니 여기에 출력 품질 검사도 넣자"로 확장하고, 그것이 원칙 IV 위반이다. 확장 금지를 코드
가까이에 적어 두는 것이 이 계약의 일부다.

**이 스크립트에 넣지 않을 것**: 추론 속도 측정, 출력 품질 점수, 모델 간 비교, 프롬프트 평가.
