# Quickstart — 122 실기기 확인 (SM-S901N dev)

전제: 기기에 옛 `a1`(1,522,796,768 B)과 검증 기록이 있다. Metro 번들만 올린다(모델 보존 — 옛 파일이 시험 대상).

1. 옛 a1 교체: 앱을 열고 쓰기 → 「AI 모듈을 준비해야 해요」 → 다시 받기. `run-as … ls -l files/models`로 옛 파일 삭제·새 파일 생성 확인.
2. R2 받기·이어받기: 받는 도중 `run-as com.a810labs.pocketlog kill -9 <pid>` → 다시 열고 받기. `state.json`의 `doneIndices`가 남은 채 이어지는지, logcat/네트워크에서 Range 요청 확인.
3. md5: 완료 후 `state.json` 검증 기록 `verifiedMd5 == dfc35a88…`, `passed: true`.
4. HF 폴백: 개발 번들에서 `a1.url`을 존재하지 않는 경로로 임시 교체 → 받기 → 예비 경로로 완료(기기 파일 지운 뒤). 되돌린다.
5. 생성: 사진 있는 날 일기 쓰기 → 본문·제목 저장.

## 기록 (2026-11-21, SM-S901N, dev 빌드 + Metro 번들, 와이파이)

임시 로그(`[122dbg]` — 탐지 응답 코드·구간별 호스트·전환 까닭)를 넣어 보고 걷었다.

| 항목 | 결과 |
| --- | --- |
| 옛 a1 교체 | ✅ 옛 `a1.bin` 1,522,796,768 B + 옛 통과 기록(`d8506380…`) 상태에서 새 번들로 앱을 열자 첫 실행 받기 화면으로 가서 약 50초 만에 새 파일 1,241,435,520 B·검증 기록 `dfc35a88…`로 바뀌었다. 다시 열어도 다시 받지 않았다 |
| R2 받기·Range 206 | ✅ 탐지 `206 bytes 0-0/1241435520`(R2), 구간 0~6이 R2에서 끝남 |
| 이어받기 | ✅ 받는 도중 `kill -9` → `doneIndices [0..10]`·조각 `seg11~14`가 남음 → 다시 열자 `[0..10]`부터 이어 11~15만 R2에서 받고 끝 |
| md5 | ✅ 세 번 모두 `verifiedMd5 dfc35a88fb1f5215f708ea5a348121b8`, `passed: true` |
| HF 폴백 | ✅ 주 주소를 없는 경로로 임시 교체(되돌림) → R2 탐지 404 → 단일 스트림 `HTTP 404`로 실패 → 예비 경로 탐지 206(HF) → 16구간을 HF에서 받고 md5 통과 |
| 생성 완주 | ✅ 새 모델로 오늘(사진·장소 0) 다시 쓰기 → 제목 「별빛 없는 밤」·본문 저장, 프롬프트 두 번(본문·제목) |

**함정(기록)**: 시험 중 `adb reverse`가 풀려 앱이 옛 개발 번들 캐시로 떠 옛 모델로 일기를 두 번 썼다(그 사이 Metro의 `Bundled` 줄은 내 `curl`이었다). 번들을 의심할 때는 `adb reverse --list`부터 본다.

**[미확인]**: iPhone 14, 사진 있는 날의 생성(사진 캡션 모듈은 바뀌지 않았다), 모바일 데이터, R2가 받는 도중 끊겨 예비 경로가 끝난 구간을 이어받는 경우(단위 테스트 AF2만 — 실기기에서는 처음부터 실패하는 경우만 봤다), 비행기 모드, 릴리스 빌드, 옛 단일 스트림 재개 기록이 남은 기기(실기기에 그런 기록이 없었다).
