# 첫 실행 모델 내려받기 — 모바일 데이터면 알리고 고르게 하기 (설계)

작성일: 2026-10-11. 입력: 로드맵 같은 이름 과제, 조사 문서 [2026-10-11-wifi-download-research.md](2026-10-11-wifi-download-research.md).
경로 분류: **architectural**(첫 실행 단계 판정·동의 대화상자·계약 테스트를 건드린다).

## 1. 합의한 이해 (소유자 답, 2026-10-11)

| 항목 | 결정 |
| --- | --- |
| 「Wi-Fi가 아님」 | **`CELLULAR`로 확인될 때만.** `UNKNOWN`·`NONE`·이더넷·VPN·읽기 실패는 모달 없이 지금처럼 진행(원칙 V — 모르는 것을 모바일로 단정하지 않는다). 연결 없음은 기존 내려받기 실패 처리(046)에 맡긴다. |
| 기존 동의와의 관계 | **합친다.** `download-consent` 단계 하나뿐이고 `resolveFirstRunStage()`의 단계·우선순위는 그대로다. |
| 두 번째 선택지 | 로드맵의 「앱 닫기」 대신 **「나중에 받기」**(플랫폼 구분 없음): 아무것도 받지 않고 앱은 열린 채 안내 화면에 머문다. |
| 받는 도중 전환 | **범위 밖.** 시작 시점 판정만 다룬다(알려진 한계로 문서화). 모델 파일은 이어받기를 지원하므로 손실이 적다. |
| 문구 | `src/i18n/catalogs/ko/download.ts`(062). |

로드맵의 완료 조건 「앱 닫기」는 위 결정에 맞게 「나중에 받기」로 고친다(완료 처리 커밋에서).

## 2. 헌법 확인

- 현행 헌법 v2.0.1에는 「앱이 사용자를 막지 않는다」 원칙이 없다(원칙 I은 온디바이스). 「나중에 받기」가 걸리는 조항은 없다. 원칙 III은 「최초 실행 시 기본 캐릭터를 받는 것」을 허용할 뿐 시점을 정하지 않는다.
- 045 FR-002a의 「거부 조작 없음」은 헌법이 아니라 045의 설계 결정이었다. 이 과제는 **모바일 데이터일 때만** 그것을 뒤집는다 — Wi-Fi·모를 때는 [받을게요] 하나인 기존 모양 그대로다. 「나중에 받기」는 거부가 아니라 연기이며, 앱은 막다른 길이 아니다(§4: 안내 화면에서 언제든 다시 시작).
- AGENTS.md 등이 쓰는 옛 원칙 번호 표기(「원칙 I = 사용자를 막지 않는다」)는 이번 과제 밖이므로 고치지 않고 소유자에게 알린다.

## 3. 접근과 선택

- **A. 동의 대화상자에 모바일 갈래를 합친다(채택).** 읽은 연결이 `cellular`면 같은 `ConfirmDialog` 틀에서 제목·본문·버튼 둘(「모바일 데이터로 받기」 / 「나중에 받기」)로 바꾼다. 새 단계 0, `progress.ts` 무변경.
- B. 앞에 별도 단계. 단계·테스트 표(7가지 우선순위)를 늘려야 하고 대화상자가 연달아 뜬다 — 기각.

## 4. 설계

### 4.1 흐름
`download-consent` 단계에 들어가면 연결을 한 번 읽는다(`readConnection()` 재사용, `src/app/network-port.ts`).

| 읽은 값 | 보이는 것 |
| --- | --- |
| 읽는 중 | 대화상자를 아직 안 띄운다(수십 ms, 빈 배경) |
| `cellular` | 모바일 갈래 대화상자 |
| 그 밖 전부 | 기존 대화상자 [받을게요] (**동작·문구·testID 불변**) |

- 「모바일 데이터로 받기」 = 기존 `onConfirmDownloadConsent`와 같다(`downloadConsented: true` 저장 → 기존 다운로드 effect가 시작). 새 저장 필드 0.
- 「나중에 받기」 = **세션 로컬 상태** `downloadDeferred`(저장 안 함)를 세운다. 아무것도 받지 않고 `downloadConsented`도 저장하지 않는다.
- `downloadDeferred`이면 `download-consent` 자리에 **대기 화면**을 그린다: 안내 문구 + 「다시 확인하기」 버튼. 버튼과 앱이 전경으로 돌아올 때(`AppState` `change → active`, 059·021이 이미 쓰는 방식) 연결을 다시 읽고 `downloadDeferred`를 지워 위 표로 돌아간다 — Wi-Fi가 되었으면 기존 [받을게요]가 뜨고, 아직 모바일이면 모바일 갈래가 다시 뜬다. 앱을 종료했다 다시 열어도 `downloadConsented`가 거짓이라 같은 판정이 처음부터 돈다.
- 새 단계값(`FirstRunStage`)을 늘리지 않는다: 대기 화면은 `App.tsx`가 `download-consent` 분기 안에서 `downloadDeferred`로 가른다(`resolveFirstRunStage` 순수 함수 무변경 → 기존 계약 테스트 C2·C3·FR-011 그대로).

### 4.2 용량 표시
모바일 갈래 본문에 받을 양을 보인다(「모바일 데이터로 약 2.0GB」, 059가 만든 `readRemainingBytes` + `formatModuleBytes`, 1000 기준). 사용자가 돈을 쓰는 순간이라 조사에서 본 관행(App Store 대화상자)과 059의 선례를 따른다. 읽지 못하면 용량 없이 문구만 보인다(지어내지 않는다, 원칙 V). 045 FR-003의 「바이트 크기를 노출하지 않는다」는 Wi-Fi/모름 갈래에 그대로 적용되고, **모바일 갈래에서만 예외**다 — 스펙에서 FR-003의 범위를 명시해 고친다. (리뷰 포인트 ①)

### 4.3 코드 경계
- 순수: `src/firstrun/` 또는 `src/app/`에 `consentVariant(connection, remainingBytes)` — `"standard" | "cellular"`와 용량 문자열. 시계·파일 접근 없음.
- 기기 통로: `readConnection`·받을 양 읽기는 이미 있다(059). 새 네이티브 의존성 0.
- UI: `DownloadConsentDialog`가 `variant`·`sizeLabel`·`onDefer`를 받는다(`standard`면 지금 모양 그대로). 대기 화면은 작은 새 컴포넌트(`DownloadDeferredScreen`).
- 문구: 카탈로그 `download.consent`에 모바일 갈래와 `download.deferred` 영역을 더한다(골든 G1·G2는 기존 키 불변, 새 영역은 별도 — 062 규칙).
- `src/ui/`는 `ESSENTIAL_ASSET_KEYS`·`models/`에 닿지 않는다(문자열만 받는다 — 058 `module-size`와 같은 방식).

### 4.4 실패·경계
- 연결 읽기 실패 → `unknown` → 기존 대화상자(막지 않는다).
- 「모바일 데이터로 받기」 이후 Wi-Fi↔모바일 전환: 범위 밖. 설정의 「모듈 다시 받기」(059)는 자기 확인 문구가 이미 있고 이번에 바뀌지 않는다.
- **알려진 한계**: `expo-network`는 핫스팟에 붙은 Wi-Fi를 `WIFI`로 보고하므로(Android 공식도 전송 종류로 과금 여부를 추정하지 말라고 한다) 그 경우 모달이 뜨지 않는다. 판정을 `NET_CAPABILITY_NOT_METERED`로 올리려면 새 네이티브 코드가 필요해 범위 밖이다.

### 4.5 시험 계획
- 기기 없는 테스트(먼저 쓴다): `consentVariant` 표 / 대화상자 두 갈래 렌더(testID, `standard` 불변 회귀) / `AppFrame.firstrun`: 모바일이면 모바일 갈래, 「나중에 받기」 → 다운로드 시작 안 함·`downloadConsented` 저장 안 함·대기 화면, 「다시 확인하기」·전경 복귀 → 재판정, Wi-Fi·unknown은 기존 / 소스 계약: 연결 읽기는 `network-port`만 import, `progress.ts` 무변경.
- 위반 주입: 「나중에 받기」가 `downloadConsented`를 저장하게 바꾸면 테스트가 실패해야 한다.
- 실기기(SM-G986N, dev): 시험은 모델이 없는 상태가 전제 → `pm clear`가 약 2GB를 지운다. 두 갈래를 본다 — (1) Wi-Fi 끈 모바일 데이터에서 모달 → 「나중에 받기」 → 아무 파일도 안 생김 → Wi-Fi 켜고 「다시 확인하기」 → 기존 대화상자, (2) 모바일 데이터에서 「모바일 데이터로 받기」 → 진행 화면 시작(데이터 비용 때문에 진행이 시작된 것만 확인하고 끊는다). 각 상태의 `getNetworkStateAsync()` 값을 실측해 기록한다. 못 본 것은 「미확인」.

## 5. 리뷰 때 확인받을 것
1. §4.2 모바일 갈래에 용량을 보이는 것(045 FR-003의 범위 좁힘).
