  - **정상 동작 확인** = 실제 모델에 짧은 입력을 보내 답이 오는지만 내부에서 보는 첫 실행 단계(사용자에게는 「확인 중」 화면).
  - **재료** = 그 날의 셀 수 있는 사진·장소. 하나라도 1 이상이면 「있음」(053 판정).
  - **첫 일기 흐름** = 정상 동작 확인을 이번 실행에서 처음 통과한 뒤 시작해 「끝남」에 이르는 단계들. 이미 첫 실행을 마친 사용자가 앱을 열 때는 없다.
  - **되돌림** = 첫 일기 쓰기가 실패해 정상 동작 확인으로 돌아가는 것. 한 실행에 한 번.

## Clarifications

### Session 2026-11-04

질문 0개. 사용자만 답할 수 있는 항목은 문구 초안 확정뿐이고, 이것은 설계 구간 커밋 확인에서 묻는다. 아래는 묻지 않고 정한 것이다.

- Q: 앱이 앞을 벗어나 끊긴 쓰기는 「실패」로 되돌리는가? → A: 아니다. 토스트와 안 쓴 날 화면(종전 홈 쓰기와 같음) (에이전트 판단 · 근거: L2의 목적은 모델이 도는지 다시 보는 것이고 끊김은 모델 문제가 아니다. 되돌리면 한 번뿐인 기회를 쓴다)
- Q: 재료를 읽는 동안 무엇을 보이는가? → A: 확인 중 화면을 그대로 둔다. 한도 10초 (에이전트 판단 · 근거: 홈을 먼저 그리면 읽는 사이 「일기 쓰기」를 눌러 확인창과 겹친다. 값은 사람이 정한 값이고 측정이 아니다)
- Q: 재료를 볼 수 없거나(`unseen`) 읽지 못한 날은 어떻게 하는가? → A: 묻지 않고 쓰지 않는다 (에이전트 판단 · 근거: D1은 재료가 있을 때만 묻는다. 재료가 있다고 말할 근거가 없다, 원칙 V)
- Q: 오늘 일기가 이미 있으면? → A: 묻지 않고 그대로 둔다 (에이전트 판단 · 근거: 쓰기 요청은 덮어쓰기 확인을 거치지 않으므로 물으면 있는 일기를 덮는다)
- Q: 첫 일기가 iOS 이어 하기를 신청하는가? → A: 신청한다 (에이전트 판단 · 근거: 쓰는 중 화면이 「앱을 나가도 계속 써요」라고 말한다. 신청하지 않으면 그 말이 틀린다. 092의 「첫 실행은 신청하지 않는다」는 파이프라인을 따로 돌리던 때의 사실이다)
- Q: 첫 일기 흐름을 어디에 두는가? → A: 단계 판정은 첫 실행 계층의 새 순수 함수, 확인창과 되돌림은 앱 조립부, 쓰기는 홈의 쓰기 요청 (에이전트 판단 · 근거: 되돌림은 홈을 내리는 일이라 홈이 할 수 없다. 쓰기를 따로 돌리면 흐름도의 「홈 · 쓰는 중」과 그만두기가 없다)
- Q: 첫 번째 실패에도 토스트를 띄우는가? → A: 아니다 (에이전트 판단 · 근거: 규칙 0-2의 4 — 되돌릴 때 보이는 말은 확인 중 화면 그대로)
- Q: 되돌림 횟수는 앱을 다시 열어도 남는가? → A: 아니다. 다시 열면 첫 일기 흐름 자체가 없다 (에이전트 판단 · 근거: 규칙 0-2 「세션 로컬」, 작명이 끝난 실행은 확인을 타지 않는다)

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 재료가 있으면 묻고, 고른 때만 쓴다 (Priority: P1)

첫 실행에서 작명까지 마친 사용자의 휴대폰에 오늘 찍은 사진이 있다. 정상 동작 확인이 지나면 홈 위에 「첫 일기를 써 볼까요?」 확인창이 뜬다. 「써 보기」를 누르면 홈의 쓰는 중 화면이 그만두기와 함께 보이고, 저장되면 오늘의 쓴 날 화면이 된다. 「나중에」를 누르면 안 쓴 날 화면으로 가고 일기는 쓰이지 않는다.

**Why this priority**: 묻지 않고 쓰는 지금의 동작을 없애는 것이 이 과제의 핵심이다.

**Independent Test**: 오늘 사진이 있는 상태로 첫 실행을 타고 확인창의 두 버튼을 각각 눌러 본다.

**Acceptance Scenarios**:

1. **Given** 오늘 재료가 있고 오늘 일기가 없다, **When** 정상 동작 확인이 통과한다, **Then** 확인창이 뜨고 아직 일기를 쓰지 않는다.
2. **Given** 확인창이 떠 있다, **When** 「써 보기」를 누른다, **Then** 홈이 오늘을 쓰는 중으로 바뀌고 그만두기가 보인다.
3. **Given** 첫 일기를 쓰는 중이다, **When** 저장이 끝난다, **Then** 오늘의 쓴 날 화면이 보인다.
4. **Given** 확인창이 떠 있다, **When** 「나중에」나 안드로이드 뒤로 가기를 누른다, **Then** 안 쓴 날 화면이 보이고 일기는 없고 확인창은 그 실행에서 다시 뜨지 않는다.
5. **Given** 첫 일기를 쓰는 중이다, **When** 그만두기를 누른다, **Then** 안 쓴 날 화면이 보이고 실패 토스트가 없고 되돌리지 않는다.

---

### User Story 2 - 재료가 없으면 안내 없이 쓰지 않는다 (Priority: P1)

오늘 사진이 없거나 사진을 볼 수 없는 사용자는 정상 동작 확인 뒤 곧바로 안 쓴 날 화면을 본다. 확인창도 일기도 없다. 정상 동작 확인 자체는 재료와 상관없이 늘 돈다.

**Why this priority**: 재료 없는 「지어낸 하루」가 첫인상이 되는 것을 막는다(4-5 모순 짝 ②).

**Independent Test**: 오늘 사진이 없는 상태로 첫 실행을 타고 안 쓴 날 화면에 닿는지, 일기 파일이 없는지 본다.

**Acceptance Scenarios**:

1. **Given** 오늘 사진·장소가 관측된 0이다, **When** 정상 동작 확인이 통과한다, **Then** 확인창 없이 안 쓴 날 화면이 보이고 일기가 쓰이지 않는다.
2. **Given** 사진 권한이 거부됐다, **When** 정상 동작 확인이 통과한다, **Then** 확인창 없이 안 쓴 날 화면이 보인다(권한 거부는 홈의 제약 띠가 말한다).
3. **Given** 재료를 읽지 못했거나 읽기가 한도를 넘었다, **When** 정상 동작 확인이 통과한다, **Then** 확인창 없이 안 쓴 날 화면이 보인다.
4. **Given** 오늘 일기가 이미 있다, **When** 정상 동작 확인이 통과한다, **Then** 확인창 없이 오늘의 쓴 날 화면이 보이고 일기가 바뀌지 않는다.

---

### User Story 3 - 쓰기가 실패하면 막다른 길이 없다 (Priority: P1)

첫 일기 쓰기가 실패하면 사용자는 다시 확인 중 화면을 본다(새 문구 없음). 통과하면 재료 판정과 확인창을 한 번 더 거친다. 또 실패하면 실패 토스트와 함께 안 쓴 날 화면으로 가고, 하단 「일기 쓰기」가 다음 행동이다.

**Why this priority**: 지금은 실패를 조용히 삼켜 사용자가 실패를 모른다(4-4).

**Independent Test**: 쓰기 실패를 주입한 조립 시험으로 두 번의 실패 경로를 끝까지 탄다. 실기기에서는 실제 실패를 한 번 이상 본다.

**Acceptance Scenarios**:

1. **Given** 첫 일기를 쓰는 중이고 되돌림을 아직 쓰지 않았다, **When** 쓰기가 실패한다, **Then** 토스트 없이 확인 중 화면으로 돌아간다.
2. **Given** 되돌림 뒤 확인이 통과하고 재료가 있다, **When** 재료 판정이 끝난다, **Then** 확인창이 다시 뜬다.
3. **Given** 되돌림 뒤 확인이 실패한다, **When** 실패 화면이 뜬다, **Then** [다시 시도]·[그냥 시작하기]가 종전대로 받는다.
4. **Given** 되돌림을 이미 썼다, **When** 쓰기가 또 실패한다, **Then** 실패 토스트가 뜨고 안 쓴 날 화면에 머물며 되돌리지 않는다.

---

### User Story 4 - 첫 일기 흐름의 끝을 한 곳에서 안다 (Priority: P3)

다음 묶음(G4 자동 쓰기 설정 창)은 첫 일기 흐름이 끝난 뒤 한 번 뜬다. 이번 과제는 설정 창을 만들지 않고, 흐름이 「끝남」에 이르렀는지를 조립부가 값 하나로 읽을 수 있게만 둔다. 사용자에게 보이는 변화는 없다.

**Why this priority**: G3·G4가 같은 파일을 고치므로 나중에 붙이기 쉽게 하는 준비일 뿐이다.

**Independent Test**: 단계 판정 시험에서 모든 경로가 「끝남」으로 닫히고, 쓰는 중에는 「끝남」이 아닌지 본다.

**Acceptance Scenarios**:

1. **Given** 어떤 경로든(저장·실패 두 번·그만두기·나중에·재료 없음·확인 건너뜀), **When** 흐름이 닫힌다, **Then** 단계는 「끝남」이다.
2. **Given** 쓰는 중이다, **When** 단계를 읽는다, **Then** 「끝남」이 아니다.

### Edge Cases

- 첫 일기를 쓰는 중에 앱이 앞을 벗어나 끊겼다(안드로이드, 또는 iOS 이어 하기 거절·만료): 모델 문제가 아니므로 되돌리지 않고, 종전 홈 쓰기처럼 실패 토스트와 안 쓴 날 화면으로 간다. 앱을 다시 앞으로 가져왔을 때 보인다.
- 다른 쓰기가 칸을 쥐고 있어 시작하지 못했다: 되돌리지 않는다. 홈이 그 쓰기에 합류하거나 안 쓴 날을 보인다.
- 정상 동작 확인 실패 화면에서 [그냥 시작하기]: 쓰지 않고 안 쓴 날 화면, 흐름은 끝남.
- 첫 일기 흐름 도중 앱이 죽었다: 다음 실행은 첫 일기를 다시 묻지 않는다(작명이 끝났으므로 흐름이 없다). 재료가 있어도 하단 「일기 쓰기」가 다음 행동이다.
- 확인창이 떠 있는 채 자정을 넘겼다: 재료를 읽은 그 날을 쓴다.
- 앱 열기 자동 쓰기가 켜진 기기(온보딩을 플래그로 되돌린 경우 등): 첫 일기 흐름에 들어간 실행에서는 앱 열기 쓰기가 저절로 시작하지 않는다(057의 「첫 실행이 이긴다」 유지).
- 개발자 상태 흉내로 쓰기가 막혀 있다: 쓰기 요청이 거절되며 되돌리지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 정상 동작 확인은 재료와 상관없이 첫 실행에서 늘 돌아야 한다(MUST).
- **FR-002**: 앱은 확인 통과 뒤, 확인 중 화면을 유지한 채 오늘의 재료와 오늘 일기 유무를 읽어야 한다(MUST). 읽기는 사람이 정한 한도(10초, 측정 아님) 안에 끝나지 않으면 「묻지 않음」으로 닫혀야 한다(MUST).
- **FR-003**: 재료 판정은 쓰기 전 확인(053)과 같은 규칙을 써야 한다(MUST). 「있음」이고 오늘 일기가 없을 때만 확인창을 띄운다.
- **FR-004**: 재료가 관측된 0이거나, 볼 수 없거나, 읽지 못했으면 앱은 확인창·안내·일기 없이 안 쓴 날 화면으로 가야 한다(MUST).
- **FR-005**: 앱은 사용자가 「써 보기」를 고르기 전에 첫 일기를 쓰지 않아야 한다(MUST NOT). 묻지 않고 쓰는 경로(040 자동 첫 일기)는 없어져야 한다.
- **FR-006**: 확인창은 제목·본문·「써 보기」·「나중에」로 되어 있어야 하고(MUST) 문구는 `docs/user-guidance-rules.md` 0-1 초안을 쓴다. 덮개를 눌러도 닫히지 않고 뒤로 가기는 「나중에」와 같아야 한다(MUST, 050 확인 대화상자).
- **FR-007**: 「써 보기」로 시작한 쓰기는 홈의 제자리 쓰기여야 한다(MUST) — 혼잣말·그만두기·실패 기록이 사용자가 누른 쓰기와 같다. iOS에서는 이어 하기를 신청해야 한다(MUST).
- **FR-008**: 쓰기가 실패하면(FR-011의 넷을 뺀 모든 실패 — 판정 거부·시간 초과·모델·사진·저장·예외) 앱은 그 실행에서 한 번, 토스트 없이 정상 동작 확인으로 돌아가야 한다(MUST).
- **FR-009**: 되돌림 뒤 확인이 통과하면 재료 판정과 확인창을 다시 거쳐야 한다(MUST). 확인이 실패하면 종전 실패 화면이 받아야 한다(MUST).
- **FR-010**: 되돌림을 쓴 뒤의 실패는 되돌리지 않고 실패 토스트를 보이며 안 쓴 날 화면에 머물러야 한다(MUST).
- **FR-011**: 사용자의 그만두기, 앱이 앞을 벗어나 끊긴 것, 다른 쓰기에 막힌 것, 시작 거절은 실패로 세지 않아 되돌림을 쓰지 않아야 한다(MUST). 앞을 벗어나 끊긴 것의 토스트와 실패 기록은 종전 홈 쓰기와 같다.
- **FR-012**: 되돌림 횟수는 파일에 남기지 않아야 한다(MUST NOT) — 세션 로컬이다.
- **FR-013**: 첫 일기 흐름에 들어간 실행에서는 앱 열기 자동 쓰기가 저절로 시작하지 않아야 한다(MUST, 057 유지).
- **FR-014**: 조립부는 첫 일기 흐름이 끝났는지를 값 하나로 읽을 수 있어야 한다(MUST). 설정 창(G4)은 이 과제에서 만들지 않는다(MUST NOT).
- **FR-015**: 층 2 e2e 흐름(안드로이드·iOS)과 흐름표(`docs/e2e/feature-flow-map.md`)가 새 흐름에 맞아야 한다(MUST). 재료 없음 경로도 e2e로 덮어야 한다(MUST).
- **FR-016**: 문구는 문구 골든을 다시 쓰지 않고 `ADDED_AFTER_GOLDEN`에 올려야 한다(MUST). 기능이 끝나면 규칙 문서에서 G3 행과 해소된 전수 목록 행을 지우고 AGENTS의 낡은 서술을 고쳐야 한다(MUST).

### Key Entities

- **첫 일기 흐름 상태**: 세션 로컬. 단계(확인 전·재료 읽는 중·묻는 중·쓰는 중·끝남)와 되돌림을 썼는가. 파일에 남지 않는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 재료 없는 첫 실행 경로에서 일기 파일이 0개다(e2e로 확인).
- **SC-002**: 재료 있는 첫 실행에서 사용자가 고르기 전에 쓰기가 시작되는 경로가 0개다(단계 판정 시험과 소스 계약).
- **SC-003**: 쓰기 실패가 두 번 나도 사용자는 언제나 확인 중·실패 화면이나 안 쓴 날 화면에 닿고, 첫 일기 흐름에서 멈춰 있는 화면이 0개다(조립 시험, 실기기 1회 이상).
- **SC-004**: 되돌림은 한 실행에 많아야 한 번이다(단계 판정 시험).
- **SC-005**: dev 빌드로 실기기에서 재료 있음·없음·실패 되돌림을 각각 한 번 이상 봤다. 기기가 빌 때까지 이 항목은 열려 있고 과제를 완료로 닫지 않는다(헌법 원칙 V).

## Assumptions

- 문구 초안은 소유자가 설계 구간 커밋 확인 때 확정한다.
- 장소 수는 사진 좌표에서 오므로 재료가 있으면 사진이 있다 — 「사진으로」라는 제목이 틀리는 경우가 없다(소스 읽기).
- 앱이 뒤에 있을 때의 실패(iOS 이어 하기)는 되돌림이 뒤에서 모델을 올리게 된다. 확인 중에 앱을 나가는 것과 같은 상황이라 새 처리를 두지 않고, 기기에서 볼 위험으로 남긴다.
- 「온보딩부터 다시」는 작명·확인을 다시 타지 않아 이 흐름에 닿지 않는다(소스 읽기). 다시 볼 때는 `onboarding.json`을 고친다.
- 범위 밖: G4, 110 필수 모듈 받기, 하단 바 색 채우기, 말투 T1~T7.
