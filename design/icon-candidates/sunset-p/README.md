# 아이콘 후보 — 노을 「P.」 (A안)

외부 디자인 시안(`pocketlog_icon.svg`, 2026-11-01 소유자 제공)을 플랫폼 안전 영역에 맞춰 다시 배치한 후보다.
**아직 앱 아이콘이 아니다** — 정본은 여전히 `design/icon.json`(102, 빨강 면 + 기하 「P」)이고, 이 폴더는
로드맵 「앱 아이콘을 노을 「P.」로 바꾼다」 과제의 입력이다. 생성기·테스트는 이 폴더를 읽지 않는다.

## 파일

| 파일                       | 무엇                                                                         |
| -------------------------- | ---------------------------------------------------------------------------- |
| `source.svg`               | 받은 원본 그대로(1024×1024). 경로·색·그라데이션의 출처                       |
| `ios.svg`                  | iOS 1024 아이콘 후보 — 배경 + 그림, 배율 1.0, 가운데로 옮김                  |
| `android-foreground.svg`   | 안드로이드 adaptive foreground 후보 — 투명 배경, 배율 0.784                  |
| `android-background.svg`   | 안드로이드 adaptive background 후보 — 원본 배경 그라데이션만                  |
| `preview-ios-1024.png`     | `ios.svg` 렌더 (Chromium)                                                    |
| `preview-compare.png`      | 원본 · iOS 160/60/40/29 · 안드로이드 원형/스퀘어클 · 안전 영역 · 48 비교      |

## 원본에서 바꾼 것 — 이것뿐이다

1. **작은 원(`#dot`)을 옮겼다**: `(853, 251)` → `(508, 875)`, 반지름 46 그대로. P 오른쪽 위 바깥에 떠 있던
   원이 기둥 오른쪽 기준선의 **마침표**가 된다(「P.」).
2. **그림 전체를 한 `<g transform>`으로 감쌌다**: `translate(512 512) scale(s) translate(-473.1 -561.5)`.
   `(473.1, 561.5)`는 P를 감싸는 가장 작은 원의 중심이다.
3. 경로·색·그라데이션·clipPath·불투명도는 손대지 않았다.

### 왜 원을 옮겼나

그림을 감싸는 가장 작은 원(렌더한 뒤 알파 > 8인 픽셀로 쟀다, Chromium):

| 대상                   | 중심             | 반지름 |
| ---------------------- | ---------------- | -----: |
| 원본(P + 원)           | (586.0, 558.2)   |  453.4 |
| P만                    | (473.1, 561.5)   |  388.8 |
| A안(P + 마침표 원)      | P만과 같다       |  388.8 |

원본 자리의 원은 P 아래 끝의 대각선 반대편이라 감싸는 원을 키운다. 안드로이드 안전 영역(108dp 중 가운데
66dp = 1024 캔버스에서 반지름 312.9)에 넣으려면 원본은 배율 0.673까지 줄여야 했고(B안, 걷었다), A안은 0.784다.

### 배율

| 출력                    | 배율  | 감싸는 원 반지름(실측) | 기준                                  |
| ----------------------- | ----: | ---------------------: | ------------------------------------- |
| iOS                     | 1.0   | 388.7                  | 원본 P 크기 유지 — 사람이 정한 값      |
| 안드로이드 foreground   | 0.784 | 305.1                  | 안전 영역 312.9에서 여유 8px — 사람이 정한 값 |

두 값 모두 **측정으로 정한 값이 아니다** — 런처에서 보기 전의 임시값이다(102의 iOS 2.3과 같은 처지).

## 알려진 문제 (이 후보가 풀지 않은 것)

- **작은 크기 판독성**: 29~40px(설정·알림·스포트라이트)에서는 산·해 빛줄기·물결 선(불투명도 0.3)이 뭉개져
  분홍·파랑 P로만 읽힌다. 단순화한 작은 크기용 판을 따로 둘지는 정하지 않았다.
- **monochrome(안드로이드 13+ 테마 아이콘)이 없다**: 그라데이션 풍경은 단색으로 바꾸면 P 윤곽 + 마침표만
  남는다 — 그 윤곽을 따로 정의해야 한다.
- **정본 체계와 안 맞는다**: `design/icon.json`은 색을 토큰 이름으로만, 모양을 rect·d-shape로만 정의한다.
  이 그림은 16진수 색 약 20개·그라데이션 4개·곡선 경로·clipPath를 쓴다. `DESIGN.md` 「아이콘」의 규칙
  (「색은 토큰 이름으로만, 16진수를 적지 않는다」)과 정면으로 부딪힌다.
- **브랜드 색 불일치**: 앱 강조색은 빨강(`accent`)이다. 아이콘만 파스텔 노을이 된다.
- **기능 그래픽·favicon·스토어 아이콘 512**: 이 후보로는 아직 만들지 않았다.
- **실기기 미확인**: Chromium 렌더로만 봤다. 갤럭시(SM-S901N) 런처·iPhone 홈 화면은 못 봤다.

## 다시 만드는 법

후보 SVG는 원본에서 위 두 치환(원 좌표, `<g transform>`)만 한 결과라 손으로 다시 만들 수 있다. 감싸는 원은
SVG를 투명 배경으로 1024×1024 렌더해 알파 > 8 픽셀 전체에 대해 구했다(근사 반복 — 소수점 아래는 의미 없다).
