# Quickstart: 지난 하루를 골라 쓴다

**Date**: 2026-08-21 | **Plan**: [plan.md](plan.md) | **Contract**: [contracts/write-prompt.md](contracts/write-prompt.md)

**이 기능이 실제로 도는지 확인하는 절차다.** 기기 없는 검증(A)이 전부 통과해도
**온디바이스는 검증되지 않은 상태다**(헌법 원칙 V) — B가 끝나야 완료다.

---

## A. 기기 없이 (항상 돈다)

```
npm test          # 기기 불필요 갈래
npm run lint      # eslint + tsc + 헌법 검사
```

**둘 다 돌린다.** 007에서 **타입 위반이 `npm test` 38개를 전부 통과하고 `tsc`만
잡았다** — 타입은 지워지므로 런타임 검사로는 안 보인다.

| 통과 기준 | 값 |
| --- | --- |
| `npm test` | 008의 **729개**보다 늘어난 수, 실패 0 |
| `npm run lint` | exit 0 (헌법 검사 포함) |

### A1. 위반을 주입해 그물을 확인한다

**초록불을 믿기 전에 일부러 어겨 본다.** 008이 넷을 주입해 전부 걸린 것을 확인했다.

| # | 주입 | 걸려야 하는 것 |
| --- | --- | --- |
| 1 | `WritePrompt`에 `elapsedMs: number` 추가 | I6 (선언을 직접 읽는 테스트) **+ `tsc`** |
| 2 | `write()`가 `latestClosedDay(at)`를 다시 부르게 | W-T1·W-T3 |
| 3 | `revertedFrom`을 고른 것이 유효할 때도 붙게 | 9번 행 (계약 §2) |
| 4 | `selectableDays()`가 개수를 인자로 받게 | D2 + 헌법 검사(값이 두 곳) |
| 5 | 고르는 자리에 사진 갈래를 그리게 | X1 (화면 테스트) |
| 6 | `toWriting()`이 인자를 받게 | I7 |

**하나라도 통과하면 그물이 뚫린 것이다.** 특히 **2번은 이 기능의 가장 위험한
결함**이다 — 화면에서 하루를 골라도 조용히 어제가 쓰이고 **오류가 나지 않는다.**

## B. 실기기 (기기가 있을 때만)

### B0. 준비 — 셋이 갖춰져야 돈다

007·008에서 실측으로 얻은 것이다. 하나라도 없으면 **화면에 값이 멀쩡히 있어도
실패한다.**

```
# 1. Metro가 dev 환경으로
EXPO_PUBLIC_APP_ENV=dev npx expo start --dev-client

# 2. adb reverse — USB에서도 필요하다
adb reverse tcp:8081 tcp:8081

# 3. 기기 잠금 해제 확인 (PIN은 사람이 넣는다)
adb shell dumpsys trust | grep deviceLocked   # 0이어야 한다
```

**⚠️ 재부팅하면 `adb reverse`가 사라진다.** 다시 건다.

**⚠️ 「영영 로딩 중」이면 캐시다** — `npx expo start --clear`. `Unable to load
script`가 아니라 멈춰 있어서 원인을 가리키지 않는다.

**⚠️ 기기 날짜를 바꾸려 하지 않는다.** root가 필요하고 `adb shell date`가 **조용히
실패한다** — 오류도 안 나고 시각도 안 바뀐다(007 실측).

### B1. 자동 흐름

```
npm run test:device
```

**`.maestro/past-day-diary.yml`이 `FLOWS`에 등록돼 있어야 돈다.** 없으면 파일이
있어도 실행기가 건너뛰고 **초록불인데 아무것도 검증되지 않는다.**

### B2. 손으로 — 자동이 못 보는 것

| # | 무엇 | 어떻게 | 통과 | FR/SC |
| --- | --- | --- | --- | --- |
| **D1** | 하루 셋이 보인다 | 쓰기 자리까지 스크롤 | 날짜 셋. **오늘이 없다** | SC-001·004 |
| **D2** | 하나가 골라져 있다 | 열자마자 본다 | 가장 최근 하루에 표시 | FR-007 |
| **D3** | **어제가 아닌 하루를 쓴다** | 가장 이른 하루를 고르고 「일기 쓰기」 | 생성이 돌고 **그 날짜로** 목록에 뜬다 | **SC-013** |
| **D4** | 일기가 **하나만** 는다 | D3 뒤 목록을 센다 | 정확히 하나 | SC-002a |
| **D5** | 그 하루의 신호다 | 만들어진 일기를 연다 | 날짜가 고른 하루 | FR-014·015 |
| **D6** | 덮어쓰기 예고 | D3의 하루를 다시 고른다 | **누르기 전에** 뜬다 | SC-006 |
| **D7** | 그래도 생성이 돈다 | D6에서 누른다 | 「쓰고 있다」가 뜬다 — 저장된 것이 즉시 나타나지 않는다 | **SC-007** |
| **D8** | 껐다 켜도 남는다 | 앱 완전 종료 후 재실행 | 목록에 그대로 | SC-002 |
| **D9** | 생성 중 화면이 그대로 | D3·D7에서 본다 | 「쓰고 있다」·「그만두기」뿐. **수치 0건** | SC-010 |
| **D10** | 모델 정보가 없다 | 고르는 자리를 훑는다 | 이름·크기·파라미터 0건 | SC-009 |
| **D11** | 시스템 막대와 안 겹친다 | 위아래를 본다 | 시계·배터리가 제 띠에 | SC-011 |

**⚠️ D3에서 「사흘 전」이 아니라 「가장 이른 하루」로 적은 이유**: 04:00 경계 때문에
지금이 새벽이면 목록이 하루 밀린다. **화면이 보여주는 셋 중 마지막을 고른다.**

### B3. 되돌림 — 손으로만 볼 수 있다

**04:00을 기다릴 수 없으므로 그대로는 확인이 안 된다.** 기기 날짜도 못 바꾼다.

**그래서 기기 없는 테스트가 이 갈래의 주된 검증이다**(계약 §2의 6·7·8번 행,
W-T3). 실기기에서는 **04:00 전후로 앱을 열어 셋이 밀리는 것**을 볼 수 있으면 보고,
못 보면 **관측하지 못했다고 적는다.**

### B4. release에서 다시 (필수)

**debug에서 돌았다는 것이 release에서 돈다는 뜻이 아니다**(원칙 V). R8·ProGuard가
켜지고 진단 화면이 사라진다.

```
npx expo prebuild --platform android --clean
cp ~/.alpharium-signing/alpharium.jks android/app/     # ★ prebuild가 지웠다
cd android && NODE_ENV=production ./gradlew assembleRelease
```

**`versionCode`를 올린다** — 008이 5였으므로 6이다. 올리지 않으면 덮어 설치가 거부된다.

| 확인 | 통과 |
| --- | --- |
| 서명 | `apksigner verify --print-certs` → **`CN=alpharium`** |
| 덮어 설치 | `adb install -r` → `Success`, **일기가 살아남는다** |
| Metro 없이 | Metro 끄고 `adb reverse` 지우고 실행 → 뜬다 |
| 환경 | 진단 화면이 **없다** |
| **하루 셋** | 고르는 자리가 **R8에서 살아남는다** |
| **생성** | 고른 하루로 실제로 만들어진다 |

**⚠️ release는 좌표가 다르다** — 진단 패널이 없어 모든 것이 위로 올라온다.
debug 좌표를 그대로 쓰면 엉뚱한 곳을 누른다.

**⚠️ release는 `run-as`가 안 된다**(`package not debuggable`). 기기 안 파일을 볼 수
없으므로 **앱 화면으로 확인한다.**

## C. 완료 선언에 필요한 것

| # | 조건 | 근거 |
| --- | --- | --- |
| C1 | `npm test`·`npm run lint` 통과 | A |
| C2 | 위반 주입 6가지가 **전부 걸린다** | A1 |
| C3 | **어제가 아닌 하루의 일기가 실기기에서 만들어져 저장됐다** | **SC-013 — 이것이 완료 조건이다** |
| C4 | release에서 같은 것이 확인됐다 | B4 |
| C5 | 확인하지 못한 것이 **미확인으로 적혔다** | 원칙 V |

### C5 — 확인 못 할 가능성이 큰 것들

**못 본 것을 본 것처럼 적지 않는다.** 007이 `none`을 미확인으로 남긴 그대로다.

| 무엇 | 왜 못 볼 수 있나 |
| --- | --- |
| **사흘 전 사진이 실제로 조회되는가**(SC-014) | 그 하루에 사진이 있는지는 **기기가 정한다.** 없으면 `none`/`unknown`만 보이고 「조회된다」는 확인이 안 된다 |
| **되돌림**(SC-008) | 04:00을 기다려야 하고 기기 날짜를 못 바꾼다(B3) |
| **Maestro의 「쓰는 중」 블록** | 생성이 2.4~2.6초라 SKIPPED로 지나갈 수 있다. **건너뛴 것은 통과가 아니다** |

## D. AGENTS.md에 남길 것

**실측한 값만 적는다.** 짐작은 짐작이라고 적는다.

- 사흘 전 하루의 생성이 실기기에서 도는가 (기기·날짜·빌드 종류)
- **사흘 전 사진이 조회됐는가 — 봤으면 봤다고, 못 봤으면 못 봤다고**
- 하루 셋이 더해진 뒤 쓰기 자리가 화면을 얼마나 넘기는가 (Maestro가 스크롤해야 하는 양)
- release에서 고르는 자리가 살아남았는가
- 생성된 일기가 원칙 II를 지켰는가 — **007에서 두 캐릭터가 어겼다.** 이 기능이 고치는
  것은 아니지만 **관측은 남긴다**
