# 안내·알림 방식 일원화 — 설계

작성: 2026-10-30. 로드맵 「안내·알림 메시지 방식을 일원화한다 — 홈 배터리 안내 자리가 나쁘다」의 설계. 소유자와의 brainstorming에서 확정한 결정만 담는다.

## 배경과 목표

소유자 관찰(2026-10-29): 홈의 배터리 안내(104)가 스트립 아래에서 본문을 밀어내고, 설명 글자와 글자 링크 둘(「설정 열기」·「닫기」)이 버튼처럼 보이지 않아 불쾌하다. 같은 자리에 캐릭터 대체 안내(`movedNotice`)와 권한 거부 안내(`deniedNotices`)도 줄글로 쌓인다. **스트립 아래에 안내를 쌓는 방식은 하지 않는다.**

목표: 안내·알림을 다섯 분류로 나누고 분류별 자리 규칙을 정해 `design/DESIGN.md`에 남기며, 홈의 스트립 아래 안내를 새 규칙으로 옮긴다.

성공 기준:

- 홈 스트립 아래에 안내가 쌓이지 않는다. 본문과 캐러셀 위는 안내 때문에 움직이지 않는다.
- 다섯 분류와 자리 규칙이 `design/DESIGN.md`에 있다.
- 사진 권한 거부와 배터리 제한이 같은 「제약 띠」로 보인다.
- 글꼴 2.0배에서도 읽히고 눌린다.

## 분류와 자리 규칙 (확정)

| 분류 | 정의 | 해당 | 자리 |
| --- | --- | --- | --- |
| A 제약 띠 | 일기를 쓰기 전에 막힌 조건. 닫을 수 없고 조건이 풀리면 사라짐 | 사진 권한 거부, 배터리 제한 | 쓰기 바 위, 한 줄 |
| B 지나가는 알림 | 방금 일어난 일. 행동 없음 | 실패 토스트, 캐릭터 대체 안내, 개발자 토스트 | 쓰기 바 위 토스트, 3초 |
| C 확인이 필요한 질문 | 고르기 전에는 진행 못 함 | 쓰기 전 확인, 다시 쓰기, 지우기 | 대화상자 (변경 없음) |
| D 상태 설명 | 화면이 왜 이런지 설명. 닫기 없음 | 설정 꼬리표, 쓰는 중 안내 | 해당 화면 안 (변경 없음) |
| E 앱 밖 알림 | OS가 보임 | 쓸 차례, 완성 | OS (변경 없음) |

소유자 피드백으로 바뀐 것: 옛 「닫을 수 있는 안내」는 없앤다. 닫기가 없고, 누를 수 있는 것은 설정으로 가는 채워진 버튼 하나뿐이며, 줄바꿈이 없다. 캐릭터 대체 안내는 상태 설명(D)에서 지나가는 알림(B)으로 옮긴다.

## 제약 띠 판정

순수 함수 하나가 「지금 띠에 무엇을 보일지」를 `photos` / `battery` / `none` 중 하나로 정한다. 읽지 못했거나 모르는 값은 `none`이다(원칙 V).

| 조건 | 띠 |
| --- | --- |
| 사진 권한이 `denied`·`blocked` | `photos` |
| 위가 아니고, 안드로이드 + 자동 쓰기 켬 + 배터리 예외 상태 `restricted` | `battery` |
| 그 밖 (iOS의 배터리, `unknown`, 허용됨) | `none` |

- 둘이 걸리면 사진 권한이 먼저다(일기를 못 쓰게 막는 쪽). 한 번에 하나만 보인다.
- 앱이 앞으로 돌아올 때마다 다시 읽는다. 설정에서 허용하고 돌아오면 사라진다.
- 버튼: `photos`는 앱 권한 설정, `battery`는 배터리 예외 설정 목록(`battery-exception-port`의 `openSettingsList`)을 연다.
- 쓰는 중에는 숨긴다. 쓴 날과 안 쓴 날을 가리지 않는다(쓰기 바가 보이면 띠도 보인다).

## 화면

- 공용 부품 `ConstraintBand`(`src/ui/components/`): `surface` 면, 왼쪽 한 줄 글자(`numberOfLines={1}`), 오른쪽 채워진 버튼 하나(누름 영역 44dp 이상). 닫기·글자 링크 없음. 글꼴 배율 상한 1.2.
- 자리: 본문 영역과 쓰기 바 사이. 스트립·캐러셀은 움직이지 않는다.
- 토스트가 뜨는 동안 띠는 흐려졌다 돌아온다. 캐릭터 대체 안내는 기존 토스트 줄을 같이 쓴다.
- TalkBack/VoiceOver는 글자, 버튼 순으로 읽는다.
- 문구는 보드 밖 초안이며 사람이 쓴다. 한 줄에 들어가는 길이의 글자 둘(사진 권한·배터리)과 버튼 라벨 둘을 소유자가 확인한다.

## 없어지는 것

- 홈 스트립 아래의 `Notices`(캐릭터 대체·권한 거부 줄글)와 `BatteryNoticeLine`.
- 닫은 시각 기록(`battery-notice-store.ts`)과 7일 규칙, 「자동 쓰기가 저장된 뒤」라는 시점(`onAutoWriteSaved`). 기기에 남은 `preferences/battery-notice-dismissed.json`은 읽지 않으므로 무해하다.

## 검증

- 판정 함수 단위 테스트.
- 소스 계약: `DiaryListScreen`에서 스트립 아래 안내를 그리는 코드와 닫기 prop이 다시 생기지 않게 잠그고, 위반을 주입해 잡히는지 확인한다.
- 기존 `use-battery-notice`·`battery-notice-store`·`battery-notice-source`·`denied-guidance` 테스트는 새 규칙에 맞게 고친다. 문구 골든은 `CHANGED_AFTER_GOLDEN`에 올린다.
- 실기기(SM-S901N dev): 사진 권한을 빼면 띠가 뜨고 버튼이 설정을 연다 / 허용하고 돌아오면 사라진다 / 자동 쓰기 켬 + 배터리 예외 없음에서 배터리 띠가 뜬다 / 토스트와 띠가 겹치지 않는다 / 글꼴 2.0배에서 첫 화면 본문 줄 수를 잰다. iOS 시뮬레이터에서 사진 권한 띠를 본다.

## 범위 밖

설정 화면, 대화상자, OS 알림, 「자동 쓰기가 되는 조건을 화면이 그대로 말하게 한다」 과제(문구 정리), 토스트 부품 이름 바꾸기.

## 위험

- 줄바꿈 없는 한 줄이라 글꼴이 큰 기기에서 글자가 잘릴 수 있다(문구를 짧게, 실기기 2.0배 확인).
- 배터리 띠가 항상 보이므로 자동 쓰기를 켜고 제한을 풀지 않은 안드로이드 사용자에게 계속 보인다(소유자가 받아들인 동작).
- 띠 높이만큼 첫 화면 본문이 줄어든다.
