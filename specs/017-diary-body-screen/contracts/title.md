# Contract: 제목·본문 서두 보강

FR-010a~FR-010d (2026-08-23 사용자 피드백 두 차례, research.md §8·§9)의 계약이다.

## 배경

014의 `extractTitle()`은 이미 옳다 — 판정 후 사후 분리, 형식(한 줄·40자 이하)만
확인, 예외 없음. 문제는 **`prompt.ts`의 지시문이 형식만 요구하고 내용·서식을
요구하지 않아**, 모델이 세 가지 방식으로 안전한 디폴트를 택한다는 것이다:

1. 제목이 "{캐릭터}의 오늘일기"류 재조합 문구가 된다(§8).
2. 제목·본문에 마크다운 서식 기호(`###`, `**...**`)가 그대로 섞인다 — 실기기
   저장 파일에서 `title: "### 루이의 일기"` 실측(§9).
3. 본문 첫 줄이 지시문의 서식 안내 문구를 문자 그대로 되뱉거나(`text: "빈
   줄\n\n..."`), 날짜를 반복하는 부제목성 줄로 시작한다(`text: "**2026-08-21**
   \n\n..."`) — 둘 다 실측(§9).

이 계약은 지시문 보강(제목 + 본문 서두 + 서식 금지)의 경계를 함께 정한다.

## 불변식

**TL1. `judge()`의 판정 갈래는 여전히 넷이다.** 제목 품질을 이유로 한 다섯 번째
거부 갈래를 추가하지 않는다(MUST NOT, 헌법 원칙 IV, 005 FR-018b) — 이 계약이
보강하는 것은 지시문 텍스트뿐이며, 판정 로직·`extractTitle()`의 형식 규칙 어느
것도 바꾸지 않는다.

**TL2. 지시문은 구체적인 반례를 든다.** "캐릭터 이름과 날짜만 재조합한 제목을
쓰지 말라"를 예시("{이름}의 오늘 일기", "{이름}의 하루" 류)와 함께 명시한다
(MUST) — 추상적으로 "좋은 제목을 써라"라고만 하면 011·012의 관례상 효과가 낮다.

**TL3. 완성된 긍정 예시 문장을 넣지 않는다.** "이렇게 써라"는 형태로 완전한
제목 예시 문장을 지시문에 포함하지 않는다(MUST NOT) — `TITLE_INSTRUCTION`이
`instructionLines()`를 통해 되뱉기(`isEcho()`) 판정 대상이므로(기존 불변식,
`prompt.ts:101-103`), 모델이 그 예시를 그대로 베낄 대상을 만들지 않는다. 무엇을
피할지는 예시로 들되, 무엇을 쓸지는 원칙(구체적인 장면·자리를 담으라)으로만
전달한다.

**TL4. 짐작 어미 규칙이 제목에도 적용됨을 명시한다(원칙 II 방어).** "구체적으로
쓰라"는 요구가 "확실하지 않아도 단정하라"로 오독되지 않도록, 014가 이미 세운
짐작 어미 규칙(`SPEAKER_RULES`의 마지막 항목)이 제목에도 그대로 적용된다는 문장을
지시문 근처에 둔다(MUST) — 본문에서 짐작으로 쓴 것을 제목에서 단정형으로 다시
쓰면 같은 문장 안에서 화자가 모순된 확신 수준을 보이게 된다.

**TL5. 캐릭터별 씨앗(말투)을 침해하지 않는다.** 지시문은 "무엇을 담을지"만
구체화하고 "어떻게 쓸지"는 지시하지 않는다(MUST NOT 추가) — `nameLine()`처럼
캐릭터별로 다른 지시문을 만들지 않는다. 다섯 캐릭터 모두 같은
`TITLE_INSTRUCTION`을 받되, 실제 제목의 문체 차이는 각 캐릭터의 기존 씨앗
(간결/서사적/상상적 등)에서 자연히 나온다.

**TL9. 마크다운 서식 기호를 쓰지 말라고 구체적으로 명시한다(FR-010c).** "#"·
"*"·"**"·"-" 같은 기호를 예로 들며 쓰지 말라고 지시한다(MUST) — 011·012의
관례상 추상적 "서식 없이 써라"보다 기호를 직접 나열하는 편이 더 잘 통한다
(research.md §9). 이 지시는 제목·본문 모두에 적용된다.

**TL10. "빈 줄"이라는 낱말을 지시문에서 없앤다(FR-010d).** 기존
`TITLE_INSTRUCTION`의 "빈 줄을 하나 넣은 뒤" 표현이 모델에 의해 문자 그대로
되뱉어진 사례(§9)가 있으므로, 서식을 실제 개행 구조로만 전달하고 "빈 줄"이라는
낱말 자체는 지시문에서 제거한다(MUST) — 문자로 존재하지 않는 지시는 문자로
되뱉어질 수 없다.

**TL11. 본문이 날짜·제목을 반복하는 줄로 시작하지 말라고 명시한다(FR-010d).**
제목이 이미 그날을 요약하므로 본문 첫 줄에 같은 사실을 다시 여는 줄(부제목)을
만들지 말라고 요구한다(MUST) — "본문을 이어서 적어라"라고만 하던 기존 지시문에
빠져 있던 부분이다.

## 검증 경계 — 채점 코드를 만들지 않는다

**TL6. 제목·본문이 규칙을 지켰는지를 자동 판정하는 코드를 만들지 않는다
(MUST NOT, 원칙 IV).** "재조합 패턴인지", "마크다운이 남아있는지", "부제목이
있는지"를 정규식·유사도·길이 기반으로 모델 **출력**에서 검사하는 코드는 어디에도
만들지 않는다 — 그 순간 이것이 임계값을 가진 측정 장치가 된다. (지시문 **텍스트
자체**에 요구 문구가 포함됐는지 검사하는 것은 TL7과 다른 층위이며 허용된다 —
"우리가 무엇을 요구했는가"이지 "모델이 무엇을 냈는가"가 아니다.)

**TL7. 기기 없는 테스트는 지시문 텍스트 자체만 검사한다.** 지시문 문자열에
TL2(재조합 금지 예시)·TL4(짐작 어미 언급)·TL9(마크다운 금지 예시)·TL10("빈 줄"
낱말 부재)·TL11(본문 시작 지시)이 실제로 포함/불포함되는지 소스 문자열을 직접
읽어 확인한다.

**TL8. 실제 품질 확인은 사람이 실기기에서 여러 제목·본문 서두를 읽는 것으로
한다**(quickstart.md D3a, 016 T022와 같은 방식). 자동화된 통과/실패 기준을
두지 않는다 — 이 검증 단계는 코드 태스크가 아니라 사람의 검수 절차다.

## 테스트로 확인해야 하는 것

- `prompt.test.ts`: 지시문 문자열에 (a) 재조합 패턴 금지 예시, (b) 짐작 어미
  규칙 언급, (c) 마크다운 기호 금지 예시(`#`·`*`·`**`·`-` 명시), (d) 본문이
  날짜·제목을 반복하지 말라는 지시가 **있는지**, (e) "빈 줄"이라는 낱말이
  지시문 문자열에 **없는지**(TL10 역검증), (f) 완성된 제목 형태의 긍정 예시가
  **없는지**(TL3 역검증) 소스 문자열 검사.
- `acceptance.test.ts`(기존 파일 확장 또는 회귀 확인): `judge()`의 판정 갈래
  수가 여전히 4개인지(005의 기존 계약 테스트가 이미 세고 있음 — 이 기능이 그
  수를 건드리지 않았는지 재확인).
- quickstart.md D3a(확장): 사람이 여러 하루의 제목·본문 서두를 직접 읽고
  재조합 패턴·마크다운 기호·부제목 군더더기가 없는지 확인.
