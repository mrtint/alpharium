# iOS 백그라운드 자동 쓰기 — 원인 가르기와 「밤 충전 중 완주」 (설계)

날짜: 2026-10-18 · 로드맵: 「백그라운드 자동 쓰기가 완주하지 못한다 — 안드로이드·iOS」의 iOS 몫(할 일 1, 할 일 4의 보이지 않는 홈 경합)

## 목적 (소유자와 합의)

- iPhone에서 백그라운드 자동 쓰기가 대체로 돌지 않는 원인을 **실제 iPhone(iPhone 14, iOS 27.0.1)**으로 가른다.
- 성공의 기준(방향 A, 2026-10-18 소유자): **밤에 충전하는 동안 iOS가 깨워 준 기회에 어제(놓친 날) 일기를 백그라운드가 써 둔다.**
  목표 시각에는 지금처럼 쓸 차례 알림(085)이 오고, 누르면 앱이 쓴다(057). 목표 시각 근처에 충전 없이 쓰는 것은 약속하지 않는다.
- 범위 밖: 안드로이드 전용 할 일(배터리 예외 유도, 소크, 다른 기기), `BGContinuedProcessingTask`·자체 네이티브 스케줄러.

## 지금 아는 것 (087 실측 + 소스)

1. `expo-background-task`(57.0.14)는 iOS에 `BGProcessingTaskRequest` 하나를 `earliestBeginDate = +15분`·`requiresNetworkConnectivity = true`·
   `requiresExternalPower = false`로 제출한다. 087에서 OS는 **USB 충전·Wi-Fi일 때만** 15~30분 간격으로 깨웠고, 충전하지 않은 27시간 동안 0번이었다.
2. **깨운 기회를 판정이 버린다**: 창 밖 따라잡기 몫(078, 하루 한 번)이 「재료 없음」·「사진 권한 없음」 건너뜀에도 소모된다.
   087 10-16: 15:38 `재료 없음` → 16:08·16:39 `오늘 창 밖에서 이미 한 번 시도함`. 낮 첫 깨움이 몫을 쓰면 그날 밤 충전 중 깨움은 아무것도 안 한다.
3. **보이지 않는 홈이 쓰기를 가져갈 수 있다**(078·080 남은 위험): iOS 백그라운드 실행은 앱 프로세스를 평소대로 띄워 `App.tsx`가 그려지고,
   `useAutoWriteHandoff`가 마운트 즉시 판정해 홈이 쓰기를 시작한다. 태스크는 `already-running`으로 곧바로 끝나고 iOS가 앱을 멈춘다 — 완성 알림도 없다.
   실기기에서 아직 재현하지 않았다.
4. **예산 만료가 JS에 오지 않는다**: expo의 `expirationHandler`는 `onTasksExpired`를 게시하지만 모듈 관찰자가 `userInfo["url"]` 가드로 버린다
   (`BackgroundTaskModule.swift:75`). 그래서 만료는 시도 기록에 `시작한 뒤 끝나지 않음`으로만 남아 「죽었다·멈췄다·만료됐다」를 가르지 못한다.
5. 진짜 백그라운드 예산 아래 완주는 못 쟀다. 강제 깨우기(lldb, 앞 프로세스)로는 사진 4장 52초에 완주했고, 8장 날 앞 실행에 `cpu_resource` 보고(50%)가 있었다.

## 설계

### 1. 따라잡기 몫은 파이프라인을 실제로 돌린 판정만 쓴다 (`src/schedule/task.ts`)

- 지금: `catchingUp && decision.kind !== "idle"`이면 몫 소모. 바꿈: `decision.kind === "write"`일 때만(파이프라인 직전).
- 근거: 몫은 「계속 실패하는 지난 날을 15분마다 다시 돌리지 않기」(078) 위한 것이다. 건너뜀은 모델을 열지 않는 미리보기 읽기뿐이라 그 상한이 막던 비용이 없다.
- 결과: 낮에 「재료 없음」이었던 날도 사진이 생긴 뒤 밤 깨움에서 쓴다. 「이미 쓴 날」·「캐릭터 없음」 등도 몫을 쓰지 않는다.
- 플랫폼 분기 없음(안드로이드에도 같은 판정 — 건너뜀이 잦아도 비용은 미리보기뿐).

### 2. iOS 백그라운드 실행에서 홈은 판정하지 않는다 (`src/app/use-auto-write-handoff.ts`)

- iOS이고 마운트 때 `AppState.currentState !== "active"`면 첫 판정을 하지 않고 `change → active`를 기다린다(이미 구독 중).
- **iOS만**이다 — 안드로이드 헤드리스는 `App.tsx`를 그리지 않고, 안드로이드 콜드 스타트의 `currentState`는 확인하지 않았다(078이 경고한 「조용히 안 도는」 위험).
- 플랫폼 값은 `src/app/platform.ts`의 `appPlatform` 한 곳에서 받는다(068 방식, 훅에 주입).
- **고치기 전에 실기기로 재현한다**: 쓸 날을 두고 앱을 뒤로 보낸 뒤 프로세스를 끝내고 lldb `_simulateLaunchForTaskWithIdentifier:`로 백그라운드 실행을 일으켜
  시도 기록에 `앱 열기 · 홈에 넘김`과 `백그라운드 · 다른 쓰기가 진행 중`이 같은 시각대에 남는지 본다(087 1절 통로). 재현되지 않으면 그 사실을 적고 방어로 남긴다.

### 3. 앱 로그 — 만료와 실행 상태를 시도 기록에 남긴다

원칙 IV는 모델 성능 측정 코드에 대한 것이고 앱 동작 기록은 해당하지 않는다(소유자 2026-10-18).

- **예산 만료 갈래 `expired`**: 로컬 Expo 모듈(`modules/`, Swift 소량)이 `onTasksExpired` 알림을 직접 관찰해 JS 이벤트로 넘기고,
  태스크가 돌던 중이면 시도 기록에 `백그라운드 · 시간 예산이 끝남` 한 줄을 남긴다(같은 시작 시각과 짝). 안드로이드는 이 모듈이 없다(통로가 no-op).
- **깨웠을 때의 상태**: 태스크 시작 줄에 앱 상태(`active`/`background`)를 함께 기록한다 — 강제 깨우기(앞)와 진짜 깨움(뒤)을 기록으로 가른다.
  충전 상태는 새 의존성(`expo-battery`)이 필요해 넣지 않는다 — 087 관찰과 dasd 로그로 본다.
- 개발자 화면 「최근 자동 쓰기 시도」가 새 갈래와 상태를 그린다(문구는 카탈로그, 062 골든 `ADDED_AFTER_GOLDEN`).

### 4. iOS 문구를 사실대로

- 설정 「매일 쓰는 시각」 미리보기와 배터리 행 보조 줄(iOS): 「그 시각에 쓸 차례를 알려요. 충전 중일 때 놓친 날을 써 두기도 해요.」 류 — 확정은 clarify.
- 바뀌는 문구는 062 `CHANGED_AFTER_GOLDEN`에 올린다.

### 5. 실기기 실측 (원칙 V)

1. 고치기 전 2번 재현(위).
2. 고친 개발 환경 Release 빌드를 iPhone에 깔고(087 4절 절차, 데이터 보존), 안 쓴 지난 날(사진 4장, `ios:seed`)을 둔 채 **화면을 잠그고 충전기에 꽂아 하룻밤** 둔다.
   다음 날 시도 기록(상태·`expired`)·일기 `timing`·`write-failures.json`·크래시/Jetsam/`cpu_resource` 보고서를 읽어 **진짜 백그라운드 완주**를 판정한다.
3. dasd 로그: 소유자가 터미널에서 `sudo log collect --device-udid … --last 12h`를 한 번 돌려 주면 `dasd`·`BackgroundTask` 술어로 「왜 미뤘는가」를 읽는다.
4. 결과를 `specs/NNN-*/quickstart.md` 「실측」과 AGENTS에 옮긴다. 네트워크 조건이 미룬 원인으로 드러나면 그때 `requiresNetworkConnectivity` 패치를 따로 판단한다(이번 범위 밖).

## 테스트

- `task.ts`: 창 밖에서 `no-material`·`no-photo-access`·`all-written`은 몫을 쓰지 않고, `write`만 쓴다(같은 날 두 번째 판정이 다시 신호를 읽는다).
- `useAutoWriteHandoff`: iOS·`background` 마운트 → 판정 0회, `active` → 1회. 안드로이드·`background` 마운트 → 종전대로 1회.
- 만료: 통로 대역으로 「돌던 중 만료 → `expired` 줄」, 「돌지 않을 때 만료 → 줄 없음」. 시도 기록 갈래 목록·가드 표(B6 등) 갱신.
- 문구: 골든 표.

## 남는 위험

- 충전하지 않을 때 iOS가 깨우는지는 OS 정책이라 바꿀 수 없다 — 문구가 그것을 약속하지 않는다.
- 진짜 백그라운드 예산이 사진 8장 날(약 90초, CPU 50% 경고)을 견디는지는 실측 한두 번이 전부다.
- 로컬 네이티브 모듈은 재빌드가 필요하고 TestFlight 빌드에서 따로 확인해야 한다.
