# Phase 0 — 조사와 결정: US1 코어 루프

**대상**: 001 User Story 1 「오늘의 신호로 일기 한 편 받기」
**작성**: 2026-08-01

이 문서는 [plan.md](plan.md)의 Technical Context에서 **NEEDS CLARIFICATION**으로 표시된
항목을 닫는다. 스펙이 의도적으로 비운 값(실측 이월)은 **닫지 않고 자리만 만든다** —
근거 없는 값을 계획에 박아 넣지 않는 것이 003·004·006이 일관되게 택한 방식이다.

## 결정 1 — 화자 판정 수단 (004 FR-348)

**이것이 이 계획의 핵심 결정이다.** 이월된 실측 다섯 중 유일하게 「값을 나중에 채우는」
성격이 아니다. 004 Assumptions가 이것을 구현 단계의 **필수 항목**으로 못 박았고, 판정
수단이 없으면 001 FR-019의 검증 자체가 성립하지 않는다.

### 만족해야 할 제약

| 출처 | 요구 |
| --- | --- |
| 004 FR-346 | 기계적으로 결정 가능. 같은 본문에 항상 같은 결과. 재량 개입 금지 |
| 004 FR-347 | 내용·품질을 평가하지 않는다. 판정 대상은 「누가 말하고 있는가」뿐 |
| 004 FR-349 | 위반 시 저장하지 않는다. **고쳐서 저장하지 않는다** |
| 헌법 원칙 IV | 형식 계약만 검사한다 |
| 004 SC-309 | 같은 본문에 반복 판정 시 항상 같은 결과 |

### 결정: 1인칭 지시대상의 어휘적 판정

**본문에 등장하는 1인칭·2인칭 지시 표현이 누구를 가리키는지**만 본다. 문장의 의미나
서술의 품질은 보지 않는다.

판정 규칙의 형태:

1. **위반 표지의 존재 검사** — 사용자가 화자일 때만 성립하는 표현이 본문에 있으면 위반.
   한국어에서 이는 화자가 자신의 신체·감정·소유를 1인칭으로 직접 진술하는 형태로
   나타난다. 휴대폰은 그것을 **관측**할 수는 있어도 **자신의 것으로 진술**할 수 없다.
2. **귀속 표지의 존재 검사** — 휴대폰이 화자일 때 성립하는 표현(주인·그·사용자를 3인칭
   대상으로 두는 서술)이 있는지.

**정확한 표지 목록은 이 계획에서 확정하지 않는다.** 그것은 실제 모델 출력을 보고
정해야 하는 값이며, 003 FR-257·004 FR-318과 같은 성격의 실측 항목이다. 이 계획이
확정하는 것은 **판정의 형태와 그것이 만족하는 성질**이다.

### 근거 — 왜 어휘적 판정인가

| 후보 | 채택 여부 | 이유 |
| --- | --- | --- |
| **어휘적 표지 검사** | **채택** | 결정적(FR-346)이고 내용을 보지 않는다(FR-347). 순수 함수로 구현되어 테스트가 성립한다 |
| 모델에게 되묻기 (LLM-as-judge) | 기각 | 같은 본문에 다른 결과가 나올 수 있어 FR-346 위반. 온디바이스에서 추론이 두 배가 된다 |
| 사람의 검토 | 기각 | FR-346이 명시적으로 금지한다 |
| 출력 형식으로 강제 (구조화 출력에 화자 필드) | 기각 | 모델이 필드에 「휴대폰」이라 적고 본문은 사용자 화자로 쓰는 상태를 막지 못한다. 판정 대상은 **본문**이다 |
| 생성 후 화자 교정 | **금지** | 004 FR-349가 명시적으로 금지 — 고쳐서 저장하는 것은 실패를 성공으로 위장하는 일(헌법 원칙 II) |

### 계획에 미치는 결과

- 화자 판정기는 **모델 어댑터 밖의 순수 함수**다. 어댑터 교체(Cloud→OnDevice)와 무관하게
  같은 판정이 적용되어야 하므로, `AIEngine` 구현체 안에 두지 않는다.
- 판정기는 **추론 축의 마지막 관문**이다. 통과하지 못한 본문은 저장 축에 도달하지 않는다.
- 표지 목록은 비운 채 **실측으로 채울 자리**를 만든다 — [quickstart.md](quickstart.md)의
  검증 시나리오가 그 자리다.

### 남는 위험

표지 기반 판정은 **위양성**(휴대폰 화자인데 위반으로 판정)과 **위음성**(사용자 화자인데
통과)을 둘 다 가질 수 있다. 이 중 **위음성이 더 위험하다** — 사용자 화자의 일기가 저장되면
001 FR-019가 실제로 깨진 채 지나간다. 표지 목록을 정할 때 위음성을 줄이는 쪽을 택한다.
위양성은 실패로 표시되고 재시도 경로가 있으므로(004 FR-354) 회복 가능하다.

## 결정 2 — 추론 어댑터의 첫 구현

**결정**: 헌법이 정한 개발 예외에 따라 **클라우드 어댑터로 시작**하되, `AIEngine` 경계
뒤에 둔다.

**근거**: 헌법 원칙 I의 개발 예외가 이것을 명시적으로 허용한다. 온디바이스 이식 전까지
`.env.development`에서만 클라우드 추론을 허용하며, 세 조건이 따른다:

1. 페이로드는 온디바이스와 동일한 스키마 — 클라우드 전용 필드로 스펙을 분기하지 않는다
2. 사진 원본은 전송하지 않는다 (003이 이미 구조로 보장 — 집계에 원본이 담기지 않는다)
3. 클라우드 모드임을 UI에 표시한다 (006 FR-590~FR-593)

**대안 기각**: 온디바이스 모델부터 시작하는 것은 US1의 관통을 모델 이식 문제에 묶는다.
코어 루프의 목적은 **축 사이 계약이 맞물리는지 확인**하는 것이지 모델 성능 확인이 아니다.

**주의**: 프로덕션 번들에 클라우드 어댑터가 포함되면 헌법 원칙 I 위반이다. 어댑터 선택
지점이 빌드 시점에 갈리도록 두어야 한다.

## 결정 3 — 신호 소스의 첫 구현 범위

003 FR-201이 소스를 **활동·위치·사진·일정 넷**으로 확정했다. US1은 이 넷이 모두 있어야
성립하는가?

**결정**: 넷 모두를 대상으로 하되, **권한 거부가 정상 경로**임을 처음부터 구현한다.

**근거**: 003 FR-217이 「모든 소스가 거부되어도 집계 한 덩어리를 산출해야 한다」고
요구한다. 즉 소스를 하나씩 붙이는 것과 권한 거부 처리는 **같은 코드 경로**다. 소스를
줄이면 오히려 FR-217을 만족하는지 확인할 수 없다.

또한 003 FR-272의 규모 판정은 **여섯 항목을 세는** 것이므로, 소스를 줄이면 「적음」이
상시 발생해 006 FR-540의 확인이 항상 뜬다 — 그 상태로는 US1의 정상 경로를 볼 수 없다.

**패키지 버전은 이 문서에서 확정하지 않는다.** 헌법 「패키지 버전 추측 금지」에 따라
`npx expo install`로 해석하고 `--check`로 검증한다. 버전을 계획에 적으면 그 자체가
추측이 된다.

## 결정 4 — 저장 매체 (005 FR-406)

005 FR-406이 매체 선택을 구현 단계에 넘겼고, FR-400~FR-405의 성질만 정했다.

**만족해야 할 성질**

| FR | 요구 |
| --- | --- |
| FR-400 | 기기 로컬. 동의 없는 외부 동기화 금지 |
| FR-401 | 보관하는 것은 셋뿐 — 퍼소나·집계·일기 |
| FR-402 | **원본 로그 미보관이 구조로 보장** — 담을 자리가 존재하지 않아야 한다 |
| FR-403 | 저장소가 자신의 형식 버전을 식별 |
| FR-404 | 기기 식별자를 포함하지 않는다 |
| FR-411 | 기록 묶음 저장은 전부 성공하거나 전부 실패 |

**결정**: 매체의 구체적 선택은 **[data-model.md](data-model.md)가 정한 구조를 만족하는
범위에서 구현 단계에 남긴다.** 다만 FR-411(원자적 묶음 저장)이 매체 선택을 제약하므로,
**묶음 하나를 단일 쓰기 단위로 다룰 수 있는 매체**여야 한다는 조건을 계획에 남긴다.

**근거**: 매체를 지금 확정하면 ROADMAP이 「파기 시작했다는 신호」로 지목한 자리(인덱스
설계·쿼리 최적화)에 들어간다. US1이 요구하는 것은 묶음 하나의 저장·조회뿐이다.

## 실측으로 닫을 자리 (값을 비워 둔다)

아래는 **이 계획이 값을 정하지 않는** 항목이다. 각각 자리만 만들고 실측으로 채운다.

| 항목 | 출처 | 이 계획이 만드는 자리 |
| --- | --- | --- |
| 항목별 상한, 시간대 세분도 | 003 FR-257 | 집계 산출 규칙의 매개변수 |
| 규모 판정 임계값 (2~6) | 003 FR-274 | 판정 함수의 매개변수 |
| 입력 구성 규칙 | 004 FR-318 | 프롬프트 구성 단계 |
| 추측의 강도 | 004 FR-331 | 프롬프트 구성 단계 |
| 화자 판정의 표지 목록 | 004 FR-348 | **결정 1**의 판정기 |
| 「적음」 확인의 중립성 | 006 | 구현 후 관찰 |

**이 중 화자 판정만 성격이 다르다** — 나머지는 값이 비어도 US1이 돌아가지만, 화자
판정기가 없으면 추론 결과를 저장할지 판단할 수 없어 루프가 닫히지 않는다. 따라서
판정기의 **형태**는 결정 1에서 확정했고, **표지 목록**만 실측으로 남긴다.

## 조사하지 않은 것

- **회상 슬롯의 활성화** — 001 FR-016이 실측 후 판단으로 못 박았고 ROADMAP이 로드맵
  밖으로 뒀다. US1에서 슬롯은 항상 비어 있다(001 SC-006).
- **US2~US5의 구현 방식** — 이번 계획의 범위 밖이다. 다만 **저장 계약은 US4·US5를
  나중에 고칠 수 없게 만들 수 있으므로**(001 US4 Why this priority), data-model.md는
  기기 비종속(FR-404)과 소프트 삭제 표현 가능성을 구조에 포함한다.
- **기존 PoC 코드의 재사용 가능성** — 001 Assumptions와 AGENTS.md가 계승 대상이 아님을
  못 박았다. `src/services/aiService.ts`의 고정 fallback은 헌법 원칙 II 위반으로 폐기
  대상이다(헌법 원칙 II 근거 절).
