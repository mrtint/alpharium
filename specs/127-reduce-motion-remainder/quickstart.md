# 127 — 동작 줄이기 마저: 확인 기록

2026-11-23. 소유자 결정: (1) iOS 사진 확대 뷰어 **한다**, (3) 안드로이드 토글 확인 **한다**, (2) 켜진 채 바뀐 OS 값 따르기 **하지 않는다**(접근성 사용자 관측 0건, 범위가 큼).

## 방법

100과 같다 — 화면 녹화를 프레임 사이 평균 밝기 차이로 읽어 한 장면에서 화면이 바뀌는 구간을 잰다(도구는 스크래치의 일회용 스크립트, 저장소에 없음). 안드로이드 `screenrecord`는 화면이 바뀔 때만 프레임을 내므로 프레임 시각(ms)으로 읽는다. 앱은 Metro(8081, 이 체크아웃)에 붙은 개발 빌드다. 릴리스 빌드는 쓰지 않았다.

## 코드 변경

`PhotoViewer`의 `Modal`은 OS 동작 줄이기가 **켜진 것으로 알려진 때만** `animationType="none"`, 꺼짐·모름은 `"fade"`다. 뷰어는 누를 때 마운트되어 그 안의 훅 값은 첫 열기에서 아직 비어 있으므로 먼저 떠 있는 `PhotoCarousel`이 `useReduceMotion()`을 읽어 prop으로 넘긴다(설계문서의 「PhotoViewer 안에서 훅」을 바꿨다). 테스트: `photo-viewer.test.tsx` RM1(true·false·undefined), `photo-carousel.test.tsx` RM2(읽은 뒤 켜짐 → none, 읽기 전 → fade). 위반 주입 둘 — 조건을 `=== false ? fade : none`으로 뒤집으면 RM1이, `PhotoCarousel`이 값을 넘기지 않으면 RM2가 실패했고 되돌렸다.

## (A) iOS 시뮬레이터 iPhone 17 (iOS 27.0, 한국어) — 사진 확대 열기

동작 줄이기는 `xcrun simctl spawn booted defaults write com.apple.Accessibility ReduceMotionEnabled -bool true`로 켜고 앱을 다시 열었다(설정 앱 토글이 아니다 — 100은 Maestro로 설정 앱 토글을 눌렀다). 앱의 일기 사진 경로가 안드로이드 경로라 시뮬레이터 컨테이너의 일기 JSON(2026-11-22)이 가리키는 사진을 로컬 JPEG으로 바꿔 시험했고 끝나고 원래대로 되돌렸다.

| 조건 | 사진 확대 열기 |
| --- | --- |
| 동작 줄이기 끔 | 약 285ms에 걸친 페이드(17ms 간격 18프레임) |
| 켬 + 위반 주입(항상 `fade`) | 약 300ms 페이드 — 100의 「iOS는 따르지 않는다」를 다시 재현 |
| 켬 + 이 변경 | **한 프레임에 바뀜**(차이 148.8 한 프레임) |

닫기는 녹화가 열기 뒤에 시작해 이번 시뮬레이터 녹화에는 담기지 않았다(열기와 같은 `Modal`이라 같은 값을 쓴다 — 안드로이드 닫기는 아래에서 봤다).

## (B) 안드로이드 SM-S901N (Android 16, One UI) — 토글과 사진 확대

- **토글 이름은 「애니메이션 줄이기」**다(설정 > 접근성 > 시각 보조 > 색상과 선명도 아래). 켜기 전 세 배율은 모두 1.0이었고, 켠 뒤 **`transition_animation_scale`·`window_animation_scale`·`animator_duration_scale`이 모두 0.0**이 되고 `settings get global remove_animations`가 1이었다. 사진 확대 페이드가 따르는 `window_animation_scale`도 0이 된다 → 100의 「토글이 세 값을 함께 0으로 만드는지」 의문은 닫는다.
- 토글을 켠 채 앱을 다시 열어 사진 확대: 열기 한 프레임(차이 162 한 프레임 + 다음 프레임 안착), 닫기 한 프레임. 끈 상태(배율 1.0): 열기 약 170ms 페이드(약 20프레임), 닫기 약 120ms 페이드. 안드로이드는 이 변경 전에도 같은 결과여서(100) 이번 변경의 효과가 아니라 **회귀 없음 확인**이다.
- 토글은 되돌렸다(세 배율 1.0, `remove_animations` 0 — 켜기 전과 같다). 토글 이전의 「색상 필터」 화면을 잘못 한 번 눌러 들어갔으나 그 기능은 꺼진 채(`daltonizer_enabled=0`)였고 값 변화는 확인되지 않았다.

## (C) iOS 실패 토스트 — 잴 수 있는 길이 있었다

100이 못 잰 까닭은 토글이 눌렸는지 확인하지 못해서였다. 길: 시뮬레이터 컨테이너 `Documents/preferences/developer-menu.json`에 `{"enabled":true}`를 두고(버전 7번 탭 대신) 앱을 다시 열어 설정 → 개발자 → 「실패 토스트 보기」를 켠 뒤(켜짐이 화면에서 보인다) 홈으로 돌아오면 「일기를 쓰지 못했어요.」 토스트가 올라온다. 토스트가 있는 하단 영역의 프레임 변화로 쟀다.

| 조건 | 토스트 올라옴 | 토스트 사라짐 |
| --- | --- | --- |
| 동작 줄이기 끔 | 약 215ms(14프레임) | 약 160ms |
| 켬(앱을 다시 연 뒤) | **한 프레임** | 한 프레임 |

토스트 슬라이드는 reanimated `withTiming`이라 100의 안드로이드 결과(재시작 뒤 따른다)와 같다. 개발 메뉴 파일은 끝난 뒤 지웠다.

## 하지 않은 것·못 본 것

- **iPhone 14 실기기(2026-11-23, 소유자 확인)**: 동작 줄이기를 켜고 앱을 다시 열어 사진 확대를 열고 닫으면 페이드 없이 한 번에 바뀌고, 끄고 다시 열면 종전 페이드가 보였다(소유자가 직접 보고 「잘 됨」이라 전했다 — 수치는 재지 않았다). 개발 서명 Release 구성에 JS를 내장한 빌드를 USB로 설치했다(Metro 없이 동작, 환경 `dev`). 처음 Debug 빌드는 Metro 주소를 못 찾아(「No script URL provided」) 검은 화면에서 멈췄다 — 이 변경과 무관한 빌드·네트워크 문제였다.
- 앱이 켜진 채 바꿨을 때의 사진 확대(훅이 알림을 받아 다음에 열 때 반영하는 것은 단위 테스트로만)는 보지 않았다.
- (2) 켜진 채 바뀐 값 따르기는 하지 않기로 했다 — reanimated 장면의 닫기 등은 앱을 다시 열어야 바뀐다는 100의 서술이 그대로다.
- 뷰어 안의 줌·백드롭 움직임(reanimated)은 손대지 않았다.
