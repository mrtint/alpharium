**Feature**: 014-character-persona | **모듈**: `src/diary/title.ts`

**기기를 모른다.** 문자열 파싱뿐이므로 전부 기기 없이 검증된다.

## 이 자리가 무엇을 지키는가

**판정(`acceptance.ts`) 이후에만 호출되는, 판정과 완전히 분리된 자리다.**

005의 `acceptance.md`가 "판정 갈래는 넷뿐이고 다섯 번째를 넣으려면 계약을 먼저
고친다"고 못 박았다. 이 파일은 그 넷 중 어디에도 관여하지 않는다 — `judge()`가
이미 `{ ok: true }`를 반환한 텍스트에 대해서만 불린다. `pipeline.ts`가 이 순서를
지키는 유일한 호출자다.

**여기서 지키는 것**:
1. `judge()`를 몰라도 된다 — `Ending`도 `Character`도 인자로 받지 않는다(P1)
2. 예외를 던지지 않는다 — 어떤 문자열에도 값을 반환한다(P2)
3. 원문을 잃지 않는다 — `title`이 없으면 `body`가 원문 전체다(P3)
4. 지표를 담지 않는다 — 파싱 방식·신뢰도·소요 시간 필드가 없다(P4, 원칙 IV)

## 함수

```
extractTitle(text: string) → { title?: string, body: string }
```

## 규칙

**P1. 판정과 무관하다.**
이 함수는 `judge()`가 이미 통과시킨 텍스트만 받는다는 것을 전제로 설계되지만, 함수
자체는 그 사실을 모른다 — `Ending`이나 `Character`를 인자로 받지 않는다. 판정
로직이 이 함수 안으로 스며들 경로 자체가 타입에 없다.

**P2. 예외를 던지지 않는다.**
빈 문자열, 빈 줄이 여러 개인 텍스트, 40자를 넘는 첫 줄 등 어떤 입력에도 정상적으로
`{ title: undefined, body: text }` 또는 `{ title, body }`를 반환한다.

**P3. 원문 보존.**
`title`이 채택되지 않으면 `body === text`(원문과 완전히 동일)다. `title`이
채택되면 `body`는 원문에서 제목 줄과 그 뒤의 구분 빈 줄만 제거된 나머지다 — 본문
중간의 다른 빈 줄은 그대로 보존된다.

**P4. 지표를 담지 않는다.**
반환 타입은 `{ title?: string, body: string }` 둘뿐이다. "제목을 어떤 규칙으로
찾았는지", "확신도" 같은 필드를 추가하지 않는다 — 005의 `RunResult`가 `{ text,
ending }` 둘뿐인 것과 같은 방어(경계 함수의 반환 타입이 좁을수록 그 값이 다른
용도로 전용될 여지가 준다).

## 판정 순서 (research.md R2)

1. `text`를 첫 번째 빈 줄(연속된 개행)에서 앞/뒤로 나눈다.
2. 앞부분이:
   - 정확히 한 줄이고
   - 40자 이하이면

   → `title` = 그 줄(앞뒤 공백 제거), `body` = 나머지(앞의 공백 제거)
3. 그렇지 않으면 → `title` = `undefined`, `body` = `text` 그대로

**40이라는 숫자는 짐작이다**(헌법 원칙 V) — quickstart D2에서 다섯 캐릭터 모두의
실제 응답으로 확인하고, 오탐(본문 일부가 제목으로 잘못 채택됨)이 관측되면 조정한다.
이 조정은 이 계약의 상수 하나만 바꾸는 것이며 구조를 바꾸지 않는다.

## 되지 않는 것

- `judge()`가 이 함수를 호출하지 않는다 — 판정에 제목 유무가 관여하지 않는다
  (FR-008).
- 제목이 화자 규칙(원칙 II)을 어겨도 별도로 잡지 않는다 — 제목도 판정을 통과한
  텍스트의 일부이므로 이미 `judge()`(주로 `language`·`echo` 판정)를 통과한 것이고,
  화자 뒤집힘·사실 단언처럼 `judge()`가 애초에 다루지 않는 것(사람이 읽어 확인)은
  제목에도 동일하게 적용되지 않는다(005 계약의 기존 한계를 그대로 물려받는다).
