# Feature Specification: 안내·알림 방식 일원화 — 제약 띠

**Feature Branch**: `108-notice-unification`

**Created**: 2026-10-30

**Status**: Draft

**Input**: User description: "홈 스트립 아래에 안내를 쌓는 방식을 없애고, 안내·알림을 다섯 분류로 나눠 자리 규칙을 정한다. 사진 권한 거부와 배터리 제한은 쓰기 바 위의 닫을 수 없는 한 줄 「제약 띠」로 보이고, 캐릭터 대체 안내는 토스트로 간다. 설계: docs/superpowers/specs/2026-10-30-notice-unification-design.md"

## 근거와 원본

- 설계문서: `docs/superpowers/specs/2026-10-30-notice-unification-design.md` — 분류·판정·화면·검증이 거기 있다. 소유자와 brainstorming으로 확정했다.
- 로드맵 「안내·알림 메시지 방식을 일원화한다 — 홈 배터리 안내 자리가 나쁘다」.
- 용어:
  - **제약 띠** = 일기를 쓰기 전에 막힌 조건을 알리는, 쓰기 바 바로 위의 한 줄. 닫을 수 없고 조건이 풀리면 사라진다.
  - **제약** = 사진 권한 거부(`photos`) 또는 안드로이드 배터리 제한(`battery`).
  - **토스트** = 방금 일어난 일을 알리는, 쓰기 바 위에 3초 뜨는 한 줄.
  - 다섯 분류: A 제약 띠, B 지나가는 알림(토스트), C 확인이 필요한 질문(대화상자), D 상태 설명(설정 꼬리표·쓰는 중 안내), E 앱 밖 알림(OS).

## Clarifications

### Session 2026-10-30 (brainstorming — 소유자 확정)

- Q: 스트립 아래에 안내를 쌓는 방식은? → A: 하지 않는다. 그 자리에는 아무것도 쌓이지 않는다.
- Q: 배터리 안내의 모습은? → A: 닫기가 없고 줄바꿈이 없으며 누를 수 있는 것은 설정으로 가는 채워진 버튼 하나뿐이다. 글자 링크는 만들지 않는다.
- Q: 사진 권한 거부 안내는? → A: 같은 제약 띠 방식이다.
- Q: 캐릭터 대체 안내는? → A: 토스트로 보낸다.
- Q: 제약 띠는 언제 보이는가? → A: 사진 권한이 거부됐으면 항상. 배터리는 안드로이드에서 자동 쓰기를 켜 두고 예외가 없을 때 항상. 둘이 걸리면 사진 권한이 먼저이고 한 번에 하나만 보인다.
- Q: 대화상자·OS 알림은? → A: 바꾸지 않는다.

### Session 2026-10-30 (clarify)

소유자 지시: 「특별히 물어볼게 없다면 완주 후 보고」 — 아래는 질문 없이 추천안으로 정한 것이다(소유자 검토 대상).

- **정정**: brainstorming에서 `movedNotice`를 「고른 날이 오늘로 떨어질 때」 안내라고 설명했으나 틀렸다. 소스(`DiaryHomeScreen.tsx`, 029 FR-014)상 **고른 캐릭터를 쓸 수 없어 다른 캐릭터로 바꿔 쓸 때**의 「{A}을(를) 쓸 수 없어 {B}(으)로 바꿨어요」다. 로스터가 하나(금동이)라 지금은 발생하지 않는 경로다. 분류 결정(지나가는 토스트)은 같은 이유로 유지한다 — 쓰기를 시작할 때 일어난 일을 알리고 행동이 없다.
- Q: 사진 권한이 부분 허용(`limited`)이면 띠를 보이는가? → A: 아니다. 제약은 `denied`·`blocked`뿐이다(부분 허용은 사진을 읽을 수 있다).
- Q: 권한이 없을 때 쓰기 바(「일기 쓰기」)를 막는가? → A: 아니다. 쓰기 바 동작은 바꾸지 않는다(053 쓰기 전 확인이 그대로 있다). 띠는 알림이지 잠금이 아니다.
- Q: 제약 띠는 홈에만 있는가? → A: 그렇다. 설정·개발자·진단 겹과 온보딩에는 없다. 설정은 이미 권한·배터리 꼬리표가 있다(분류 D, 변경 없음).
- Q: 실패 토스트와 캐릭터 대체 토스트가 겹치면? → A: 토스트는 한 번에 하나다. 나중 것이 앞의 것을 바꿔 낀다(기존 토스트 부품의 `key` 재마운트 방식).
- Q: 온보딩의 배터리 단계(`batteryNoticeShown` 플래그)는? → A: 홈 배터리 안내와 별개이므로 건드리지 않는다.
- Q: 띠 문구가 한 줄을 넘으면? → A: 말줄임으로 자르고 버튼은 항상 보인다. 문구는 한 줄에 들어가도록 짧게 쓴다(소유자 확인 항목).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 사진 권한이 없으면 쓰기 전에 알고 바로 고친다 (Priority: P1)

사진 권한을 거부한 사용자가 홈을 연다. 쓰기 바 바로 위에 한 줄과 채워진 버튼이 있다. 버튼을 누르면 권한을 묻는 창(막혀 있으면 설정 안내)이 뜨고, 허용하고 돌아오면 띠가 사라진다. 스트립과 캐러셀과 본문은 이 때문에 움직이지 않는다.

**Why this priority**: 지금 이 안내는 스트립 아래 줄글로 본문을 밀어내며 누를 곳이 없다. 가장 많은 사용자가 마주치는 제약이다.

**Independent Test**: 사진 권한 상태 통로를 `denied`로 두고 홈을 그려 띠와 버튼을 확인하고, 상태를 `granted`로 바꿔 앱이 앞으로 돌아오는 신호를 주면 띠가 사라지는지 본다.

**Acceptance Scenarios**:

1. **Given** 사진 권한이 `denied`·`blocked`이다, **When** 홈을 연다, **Then** 쓰기 바 위에 사진 권한 제약 띠가 한 줄로 보이고 닫기는 없다.
2. **Given** 제약 띠가 떠 있다, **When** 버튼을 누른다, **Then** 사진 권한 요청 창이 뜨거나, 다시 물을 수 없으면 설정 안내 대화상자가 뜬다.
3. **Given** 제약 띠가 떠 있다, **When** 권한을 허용하고 앱이 앞으로 돌아온다, **Then** 띠가 사라진다.
4. **Given** 제약 띠가 있거나 없다, **When** 홈을 그린다, **Then** 스트립 아래에는 안내 줄이 없다.

---

### User Story 2 - 배터리 제한도 같은 방식으로 알린다 (Priority: P2)

안드로이드에서 자동 쓰기를 켜 두고 배터리 예외가 없는 사용자의 홈에 배터리 제약 띠가 쓰기 바 위에 한 줄과 버튼으로 항상 보인다. 버튼은 배터리 예외 설정 목록을 연다. 예외를 주고 돌아오면 사라진다. 사진 권한과 동시에 걸리면 사진 권한이 먼저 보인다.

**Why this priority**: 104의 배터리 안내를 새 규칙으로 옮기는 일이다. 사진 권한 띠가 서야 올릴 수 있다.

**Independent Test**: 판정 함수와 홈 조립에 플랫폼·자동 쓰기·배터리 상태 대역을 넣어 표의 모든 조합을 확인한다.

**Acceptance Scenarios**:

1. **Given** 안드로이드이고 자동 쓰기가 켜져 있으며 예외 상태가 `restricted`이고 사진 권한이 허용이다, **When** 홈을 연다, **Then** 배터리 제약 띠가 보인다.
2. **Given** 사진 권한이 거부이고 배터리도 `restricted`이다, **Then** 사진 권한 띠 하나만 보인다.
3. **Given** iOS이거나 자동 쓰기가 꺼져 있거나 예외 상태가 `exempt`·`unknown`이다, **Then** 배터리 띠는 없다.
4. **Given** 배터리 띠가 떠 있다, **When** 버튼을 누른다, **Then** 배터리 예외 설정 목록이 열린다.

---

### User Story 3 - 캐릭터 대체 안내는 지나가는 토스트다 (Priority: P3)

고른 캐릭터를 쓸 수 없어 다른 캐릭터로 바꿔 쓸 때 알리는 한 줄(029)이 스트립 아래 줄글이 아니라 쓰기 바 위 토스트로 3초 뜬다. 제약 띠가 떠 있으면 토스트가 뜨는 동안 띠는 흐려졌다 돌아온다.

**Why this priority**: 스트립 아래를 완전히 비우는 마무리다.

**Independent Test**: 캐릭터 대체를 일으켜(미래 캐릭터 대역으로) 토스트 문구가 나타나고 3초 뒤 사라지는지, 띠와 토스트가 동시에 읽히지 않는지 본다.

**Acceptance Scenarios**:

1. **Given** 고른 캐릭터를 쓸 수 없어 다른 캐릭터가 쓰게 된다, **When** 쓰기를 시작한다, **Then** 스트립 아래 줄글이 아니라 토스트로 알린다.
2. **Given** 제약 띠가 떠 있다, **When** 토스트가 뜬다, **Then** 띠는 토스트 동안 가려지고 토스트가 사라지면 돌아온다.

---

### User Story 4 - 안내 규칙이 문서에 남는다 (Priority: P3)

다섯 분류와 자리 규칙, 하지 않는 것이 `design/DESIGN.md`에 있어 다음 안내를 만들 때 같은 자리를 쓴다. 규칙을 어기는 코드(스트립 아래 안내 줄, 닫기가 있는 안내)는 테스트가 막는다.

**Why this priority**: 안내가 늘면 같은 일이 되풀이된다는 것이 이 과제의 출발이다.

**Independent Test**: 문서 계약 테스트와 소스 계약 테스트, 위반 주입.

**Acceptance Scenarios**:

1. **Given** DESIGN.md, **Then** 다섯 분류·자리 규칙·하지 않는 것이 적혀 있고 문서가 적은 이름이 실재한다.
2. **Given** 홈 화면 소스에 스트립 아래 안내 줄 또는 닫기가 있는 안내를 다시 넣는다, **Then** 소스 계약 테스트가 실패한다.

### Edge Cases

- 사진 권한 상태나 배터리 상태를 읽지 못했거나 `unknown`이다 → 띠 없음(모르는 것을 보이지 않는다, 원칙 V).
- 사진 권한이 부분 허용(`limited`)이다 → 띠 없음.
- 토스트가 둘 겹친다 → 나중 것이 앞의 것을 바꿔 낀다.
- 쓰는 중에는 띠를 숨긴다(쓰는 중 화면 분기).
- 쓴 날에도 쓰기 바가 있으면 띠를 보인다.
- 대화상자가 떠 있으면 띠·토스트는 뒤에 가려진다.
- 글꼴 배율이 커도 한 줄을 유지한다(글꼴 상한 1.2배). 글자가 길면 말줄임으로 자른다 — 버튼은 항상 보인다.
- 앱이 쓰는 중이 아닌 채 권한이 바뀌고 앞으로 돌아오면 다시 읽는다.
- 이미 기기에 남은 배터리 안내 닫기 기록 파일은 읽지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 홈 스트립 아래에는 안내·알림 줄이 어떤 경우에도 그려지지 않는다(캐릭터 대체, 사진 권한, 배터리).
- **FR-002**: 제약 띠는 쓰기 바 바로 위에 한 줄로 보이고, 글자 하나와 채워진 버튼 하나로 이루어진다. 닫기와 글자 링크가 없다.
- **FR-003**: 제약 띠는 조건이 풀리면 사용자 조작 없이 사라진다.
- **FR-004**: 어떤 띠를 보일지는 `photos`·`battery`·없음 중 하나를 정하는 순수 판정이 정한다. 사진 권한이 `denied`·`blocked`이면 `photos`, 아니면 안드로이드 + 자동 쓰기 켬 + 예외 상태 `restricted`이면 `battery`, 그 밖은 없음. 한 번에 하나만 보인다.
- **FR-005**: 사진 권한 상태, 배터리 예외 상태가 읽히지 않았거나 `unknown`이면 해당 띠를 보이지 않는다.
- **FR-006**: 앱이 앞으로 돌아올 때 사진 권한과 배터리 상태를 다시 읽어 띠를 갱신한다.
- **FR-007**: `photos` 띠의 버튼은 053의 사진 권한 요청 흐름을 부른다(다시 물을 수 있으면 OS 권한 창, 막혔으면 설정 안내 대화상자). `battery` 띠의 버튼은 배터리 예외 설정 목록을 연다.
- **FR-008**: 쓰는 중에는 띠를 숨긴다. 그 밖에는 쓴 날과 안 쓴 날을 가리지 않는다. 쓴 날에 다시 쓰기 바가 내려가 있으면 띠도 함께 내려가 있다(바와 한 짝).
- **FR-009**: 캐릭터 대체 안내는 토스트로 3초 보이고, 제약 띠가 있으면 토스트가 뜨는 동안 띠는 가려졌다 돌아온다.
- **FR-010**: 배터리 안내 닫은 시각 기록과 7일 규칙, 「자동 쓰기가 저장된 뒤」 시점 판정은 없앤다.
- **FR-011**: 띠의 글자는 글꼴 배율 상한 1.2배를 따르고 한 줄을 넘지 않는다. 버튼의 누름 영역은 44dp 이상이다.
- **FR-012**: 띠는 접근성에서 글자, 버튼 순으로 읽힌다.
- **FR-013**: `design/DESIGN.md`에 다섯 분류, 분류별 자리, 하지 않는 것(스트립 아래에 쌓기, 닫기 있는 글자 링크)을 적는다.
- **FR-014**: 새 화면 문구는 한국어 카탈로그에만 두고 문구 골든은 다시 쓰지 않고 `CHANGED_AFTER_GOLDEN`·`ADDED_AFTER_GOLDEN`에 올린다.
- **FR-015**: 대화상자, 설정 꼬리표, 쓰는 중 안내, OS 알림은 바꾸지 않는다.

### Key Entities

- **제약 종류**: `photos` | `battery` | 없음. 판정 입력은 사진 권한 상태, 플랫폼, 자동 쓰기 켬 여부, 배터리 예외 상태.
- **띠 내용**: 글자 한 줄, 버튼 라벨, 버튼 동작(사진 권한 요청 흐름 | 배터리 예외 목록 열기).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 어떤 상태에서도 홈 스트립과 캐러셀의 위치가 안내 때문에 바뀌지 않는다(안내가 뜨거나 사라질 때 이동 0).
- **SC-002**: 사진 권한이 없는 사용자는 홈을 연 첫 화면에서 쓰기 바 위의 띠를 보고 한 번 눌러 권한 요청 창 또는 설정 안내에 도달한다.
- **SC-003**: 사진 권한과 배터리 제한이 동시에 걸린 모든 조합에서 보이는 띠는 하나뿐이다.
- **SC-004**: 글꼴 2.0배 실기기에서도 띠가 한 줄이고 버튼이 가려지지 않으며 눌린다.
- **SC-005**: 제약이 풀린 뒤 앱이 앞으로 돌아오면 사용자가 아무것도 누르지 않아도 띠가 사라진다(닫기 조작 0회).

## Assumptions

- 띠 문구는 보드 밖 초안이며 사람이 쓴다. 이 스펙은 문구 내용이 아니라 구조(한 줄·버튼 하나)만 정한다. 구현은 소유자가 확인할 때까지 임시 문구로 두고 확인을 받는다.
- 사진 권한을 읽는 기존 통로(`onboardingPorts.photo.photoPermission`)와 앱 열기·복귀 시 다시 읽는 방식은 그대로 쓴다.
- 배터리 예외 상태는 `battery-exception-port`로, 자동 쓰기 켬 여부는 기존 설정 읽기로 읽는다.
- 이번 범위 밖: 설정 화면, 대화상자, OS 알림, 「자동 쓰기가 되는 조건을 화면이 그대로 말하게 한다」 과제(문구 정리), 토스트 부품 이름 바꾸기.
- 띠 높이만큼 첫 화면 본문이 줄어드는 것은 소유자가 받아들인 대가다.
