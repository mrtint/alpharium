# 계약: 진단 화면의 권한 자리

**기능**: 004-photo-signal-collection | **Date**: 2026-08-14

FR-020~023이 요구하는 것. **사용자용 화면이 아니라 진단 경로다**(FR-022).

---

## 왜 진단 화면인가

권한 요청을 시작할 자리가 없으면 **실기기에서 영원히 `unknown`만 나온다.** SC-008(실제
사진이 신호에 나타나는 것을 확인)을 만족할 방법이 사라진다.

그렇다고 사용자용 권한 안내 화면을 만들면 이 기능의 범위가 커지고, 문안을 지어야 한다.
003이 캐릭터 설명 문안을 짓지 않은 것과 같은 이유로 **004도 사용자에게 보일 문안을 짓지
않는다.**

진단 화면은 이미 있고(`src/ui/DiagnosticsScreen.tsx`), 개발자가 보는 자리다. 거기에
상태와 버튼을 둔다.

---

## 보여야 하는 것

| 항목 | 값 | 근거 |
| --- | --- | --- |
| 사진 접근 | `granted` / `limited` / `denied` / `blocked` / `undetermined` | FR-020 |
| 좌표 접근 | 위와 같음 | FR-020, FR-013a |
| 사진 권한 요청 | 누를 수 있는 것 | FR-021 |
| 좌표 권한 요청 | 누를 수 있는 것 | FR-021 |

**둘을 따로 보인다.** 하나로 합치면 "사진은 되는데 좌표가 안 되는" 상태를 진단할 수 없고,
그 상태가 FR-013a가 다루는 바로 그것이다.

**`blocked`일 때 요청이 소용없다는 것이 드러나야 한다**(FR-023). 안드로이드가 창을 띄우지
않으므로 버튼을 눌러도 아무 일이 없다. 그것을 모르면 반복해서 누른다.

---

## 금지

### 1. 자동으로 요청하지 않는다 (FR-011)

화면이 열렸다는 이유로 권한 창을 띄우지 않는다. 사람이 눌러야 한다.

**흔한 패턴이 위반이다** — expo 문서의 튜토리얼조차 `useEffect`에서 `requestPermission()`을
부른다. 그것을 따라 하면 FR-011이 깨진다.

### 2. 사용자용 문안을 짓지 않는다 (FR-022)

"일기를 쓰려면 사진이 필요해요" 같은 설득 문구를 두지 않는다. 상태 이름과 버튼이면 된다.

### 3. 모델 정보를 보이지 않는다 (FR-019)

003이 세운 경계 그대로다. 진단 경로에서 모델 식별자는 허용되지만(003 FR-004b), 004가
그것을 넓히지 않는다.
