# 계약 — 명령

**이 계약의 독자는 에이전트다**(명확화 Q2). 사람도 칠 수 있지만 그것이 기본 경로가
아니다.

---

## 명령 셋

```
npm run seed:day -- <모양> <하루>      # 심는다
npm run seed:list                       # 지금 뭐가 심겨 있나 (FR-011c)
npm run seed:clear                      # 되돌린다 (FR-011a — 지시할 때만)
```

**`seed:clear`는 아무것도 자동으로 부르지 않는다.** `seed:day`가 끝나면서 치우지 않고,
검증이 끝났다고 치우지도 않는다 — 심은 하루는 검증의 대상이지 부산물이 아니다.

---

## `seed:day` — 심는다

### 인자

| 자리 | 값 | 필수 |
| --- | --- | --- |
| 1 | 모양 이름 — `rich`·`empty`·`partial-location`·`one-place`·`over-limit` | MUST |
| 2 | 하루 — `YYYY-MM-DD` | MUST (FR-005) |

**둘 다 없으면 돌지 않는다.** 도구가 「적당한 하루」를 고르지 않는다 — 그러면 어느
하루를 검증했는지 흐려진다.

**대화형 되묻기가 없다**(FR-018). 인자가 모자라면 **묻지 않고 실패한다.**

### 출력

**두 겹이다**(FR-018b, 명확화 Q3).

```
사람이 읽는 줄들 …
2026-08-20에 3장을 심었다 (좌표 2장).
⚠️ 심기 전부터 폴더에 2장이 있었다 — 이 하루의 사진은 모두 5장이다.
{"ok":true,"day":"2026-08-20","shape":"rich","seeded":3,"withLocation":2,"existing":2}
```

**마지막 한 줄이 기계가 읽는 것이다.** 규칙:

1. **표준 출력의 마지막 줄이 항상 JSON 한 줄이다.** 성공이든 실패든 그렇다.
2. 그 앞의 줄들은 사람이 읽는 문장이며 **기계가 읽지 않는다.**
3. JSON 줄이 없이 끝나는 것은 **도구 자신의 결함**이다 — 에이전트는 그것을 실패로 본다.

### 종료 코드 (FR-018a)

| 코드 | 뜻 |
| --- | --- |
| `0` | 심었고 확인까지 끝났다 |
| `1` | 실패. 기기에 절반만 심긴 것이 없다 |
| `2` | **실패했고 치우다가 또 실패했다** — 기기가 어긋난 채로 남았다 |

**`2`가 따로 있는 이유**: 에이전트가 다음에 할 일이 다르다. `1`이면 다시 시도해도 되고,
`2`면 **`seed:clear`를 먼저 돌려야 한다.** 하나로 뭉치면 에이전트가 어긋난 기기 위에서
검증을 이어 간다.

### 실패의 모양

```
2026-08-25는 지금 고를 수 있는 하루가 아니다.
고를 수 있는 하루: 2026-08-21, 2026-08-20, 2026-08-19
{"ok":false,"reason":"day-out-of-range","detail":"고를 수 있는 하루: 2026-08-21, 2026-08-20, 2026-08-19"}
```

**`detail`이 에이전트가 다음을 정할 수 있을 만큼 구체적이어야 한다**(FR-019). 위의
경우 에이전트는 고칠 날짜를 바로 안다 — 「범위 밖」만 말하면 다시 물어야 한다.

## `seed:list` — 뭐가 심겨 있나 (FR-011c)

**치우는 것과 별개로 물을 수 있어야 한다.** 자동으로 치우지 않기로 했으므로(Q4)
**남은 것이 안 보이는 일이 없어야 한다**(FR-011b).

```
기기에 심긴 사진 5장:
  2026-08-20 — 3장 (rich, 2시간 전에 심음)
  2026-08-19 — 2장 (partial-location, 어제 심음)
{"ok":true,"total":5,"days":[{"day":"2026-08-20","count":3,"shape":"rich"},{"day":"2026-08-19","count":2,"shape":"partial-location"}]}
```

**기기의 폴더를 실제로 세어서 답한다.** 기록만 읽으면 어긋난 것을 못 본다 — 기록은
편의이고 **폴더가 경계다**(data-model.md).

---

## `seed:clear` — 되돌린다

**사람이 지시할 때만 돈다**(FR-011a). 인자가 없으면 **전부** 치운다.

```
npm run seed:clear              # 전부
npm run seed:clear -- 2026-08-20  # 그 하루만
```

### 계약

1. **전용 폴더 안의 것만 지운다**(FR-016a). 폴더 밖에는 어떤 경우에도 닿지 않는다.
2. 파일을 지운 뒤 **볼륨 스캔을 돌린다** — 안 하면 MediaStore에 유령 행이 남고,
   앱이 계속 그 사진을 본다(research.md §5 실측).
3. 지우지 못한 것이 있으면 **조용히 넘기지 않는다**(FR-012b).
4. 심은 것이 없으면 **아무것도 지우지 않고 그 사실을 알린다**.

```
지울 것이 없다.
{"ok":true,"removed":0}
```

## 금지 (계약의 일부다)

| 금지 | 왜 |
| --- | --- |
| 대화형 확인·되묻기·「y를 누르세요」 | 에이전트가 부른다(FR-018) |
| 진행 표시를 JSON 줄 뒤에 찍기 | 마지막 줄이 JSON이 아니게 된다 |
| 실패인데 종료 코드 `0` | 에이전트가 그대로 다음 단계로 간다(FR-018a) |
| **부분 성공을 `ok: true`로** | FR-018c. 3장 중 2장이면 실패다 |
| **일기를 읽거나 쓰기** | FR-003·022, 원칙 IV. 헌법 검사가 막는다 |
| 권한을 주거나 거두기 | FR-014. 004가 가른 갈래를 흐린다 |
| 앱의 저장 영역에 쓰기 | FR-004 |

## 에이전트가 쓰는 모양 (참고)

```
1. npm run seed:day -- rich 2026-08-20
   → 마지막 줄 JSON을 읽는다. ok가 false면 detail을 보고 정한다.
   → existing이 0이 아니면 기대하는 사진 수를 조정한다.

2. 앱에서 그 하루의 일기를 생성한다 (Maestro 또는 손으로)
   → 상세 화면의 사진 수가 seeded + existing과 같은가?

3. (사람이 지시하면) npm run seed:clear
```

**2번에서 도구가 결과를 읽지 않는다.** 일기의 내용을 보는 것은 사람이며, 도구는
**심고 끝난다**(FR-022, 원칙 IV).
