### D4 — 「없다」와 「모른다」가 다르다 (FR-003·SC-005, 원칙 V)

**같은 하루(09-12)를 두 상태로 썼다.**

| 상태                       | `signalsUsed.photos`                                                | 화면 문구        |
| -------------------------- | ------------------------------------------------------------------- | ---------------- |
| 권한 있음 + 사진 0장       | `{"kind":"none"}`                                                   | **사진: 없었다** |
| `pm revoke` 후 (권한 없음) | `{"kind":"unknown","reason":"사진 접근 권한이 아직 열리지 않았다"}` | **사진: 모른다** |

**`unknown`이지 `none`이 아니다** — 024가 `collect.ts`에서 잠근 방어가 그대로 산다.
권한 회수 상태에서도 VLM은 열리지 않았다(`has_media` 0회) — FR-002의 「권한 없음」 쪽.

목록 줄의 요약도 함께 바뀐다(「사진 없음」 → 「사진 모름」). 다만 **회수 직후 첫
덤프에는 아직 「사진 없음」이 남아 있었고 다음 덤프에서 바뀌었다** — 021의 `AppState`
재조회로 갱신되는 것이며, 회수와 화면 갱신 사이에 시차가 있다.

**검증 후 `pm grant`로 두 권한을 되돌렸다**(세션 끝 상태: 4개 권한 전부 `granted=true`).

### D5 ★★ — **미수행. 시각 게이트에 막혔다**

**이 기능의 실질을 보는 자리인데 이 세션에서 관측하지 못했다. 건너뛴 것은 통과가
아니다**(원칙 V).

막은 것은 042가 아니라 **020의 스케줄 판정**이다:

```
decision.ts:74   if (!isNearTarget(now.getHours(), settings.targetHour))
                     return { act: false, reason: "not-near-target" };
WINDOW_HOURS = 3 → 목표 12시의 창은 [12,15)
```

세션 시각이 **17시**라 창 밖이다. 개발자 탭 「지금 자동 생성 트리거」를 눌렀더니 화면에
**`결과: skipped`**가 그대로 찍혔고, 일기는 쓰이지 않았다(`has_media` 0회).
`cmd jobscheduler run -f`도 같은 `runAutoDiaryTask()`를 거치므로 결과가 같다.

**뚫으려면 `targetHour`를 바꾸거나 기기 시각을 바꿔야 하는데 둘 다 하지 않았다** —
전자는 "계속 쓰는 설정이라 끄지 말 것"이라는 보존 조건(T002)을 어기는 것이고, 후자는
root가 필요하다.

> **다음 세션에서 12:00~14:59 사이에 확인한다.** 절차: (1) `selectableDays` 중 사진이
> 있는 하루의 일기 파일을 지워 `pickRetryDay`가 그것을 고르게 한다, (2) 개발자 탭
> 트리거 또는 `cmd jobscheduler run -f <pkg> <jobId>`, (3) `has_media=1`과
> `files/diary/`의 새 파일을 **함께** 본다.
>
> **`skipped`는 로그만으로는 정상 완주와 구분되지 않는다**(027 §1) — 개발자 탭 버튼의
> `결과:` 표시와 `files/diary/`를 반드시 같이 본다.

**다만 코드 경로는 좁혀져 있다**: `task.ts:144`가 `vision: "quick"`을 **무조건** 넘기고
사진 설정을 읽지 않는다(계약 테스트 C3이 소스에서 잠금). D2·D6이 검증한 것과 **같은
`pipeline.run()`**이다. 그래도 이것은 추론이지 관측이 아니다.

## 4. 재지 않은 것

- **`image_max_tokens` 256과 1024의 출력 차이** — 042는 그 차이를 **재지 않고**
  다이얼을 치웠다. 헌법 개정 경위가 그렇게 정했다(재진 적 없는 값을 선택지로
  내놓지 않는다). 되살릴 근거가 생기면 헌법을 다시 고친다.
- **사진을 보게 되어 늘어난 생성 시간** — 사진 있는 하루는 캡션 시간이 붙으므로
  느려지는 것이 정상이다. 이 기능은 속도를 목표로 하지 않으며 비교·평균을 만들지
  않는다(원칙 IV).
