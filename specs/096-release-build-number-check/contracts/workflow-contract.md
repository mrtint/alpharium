# Contract: 워크플로의 「번호 점검」 단계

| ID  | 규칙                                                                                                                                                                                                                                                                               |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| N1  | 두 워크플로 모두 `- name: 번호 점검` 단계가 있고 `npm ci`·`expo prebuild`보다 앞이다. 안드로이드는 `설정 점검` 뒤, iOS는 `릴리스 노트 점검` 뒤                                                                                                                                     |
| N2  | 안드로이드 단계 env는 `PLAY_SERVICE_ACCOUNT_JSON` 하나, iOS는 `ASC_API_KEY_P8`·`ASC_KEY_ID`·`ASC_ISSUER_ID` 셋이다. 모두 `KEY: ${{ secrets.NAME }}` 꼴이고 단계 env 깊이(10칸)에만 있다                                                                                            |
| N3  | 단계 본문(`run`)에 `${{` 가 없다(비밀·입력 보간 금지). 커밋은 `"$GITHUB_SHA"`로 넘긴다                                                                                                                                                                                             |
| N4  | 단계는 저장소 스크립트(`version-check.mts` / `build-number-check.mts`) 하나를 부르고 `npm`·`npx`·`gradlew`를 부르지 않는다                                                                                                                                                         |
| N5  | 통과 줄을 `tee -a "$GITHUB_STEP_SUMMARY"`로 남긴다. 비밀 변수를 echo/cat하지 않는다                                                                                                                                                                                                |
| N6  | 076/075의 기존 계약은 유지된다: 수동 시작 하나, `permissions: contents: read`, 허용 secret 목록 불변, 기존 「사전 점검」은 저장소 코드를 부르지 않는다. 비밀별 참조 횟수 계약(W5b)은 새 단계를 센다 — 안드로이드 `PLAY_SERVICE_ACCOUNT_JSON`은 사전 점검·번호 점검·Play 업로드 3곳 |
