# 일기 말투 교체 — `~요`·감상·첫 문장 틀·로마자 차단 (설계)

- 날짜: 2026-10-12
- 원본: my-ollama PR #8 (머지 `e192c9b`) — `docs/alpharium-diary-tone-handoff.md`(지시서), 문안 원본 `results/hand-prompt/v5/`
  (`user-prompt.md`·`user-instruction.md`·`grammar.gbnf`·`prompts.json`)
- 기준: alpharium `80f8c33`. `src/diary/prompt.ts`는 지시서의 기준 `7e74aa6`과 diff 0(확인함)

## 1. 목적

사용자 피드백 「일기 글투가 탐정 같다」 — 사실만 늘어놓고 감상이 없다. 휴대폰이 화자인 **`~요`로 끝나는, 감상이 있는 글**이 나오게 한다.
my-ollama 측정(llama-server, 기기와 md5가 같은 kanana-1.5-2.1b Q4_K_M, 제품 샘플링):

| 본 장면 있는 날 | v0(지금) | v5 |
| --- | ---: | ---: |
| 블라인드 총평 (1~5, 18편) | 2.17 | 3.44 |
| 탐정 말투 | 10/18 | 0/18 |
| 감상이 글의 한 축 | 5/18 | 16/18 |
| 휴대폰이 화자로 읽힘 | 5/18 | 17/18 |
| 높임·평어 섞임 (60런) | — | 0/60 |
| 로마자 든 본문·제목 (60런) | 드물게 | 0/60 |

본 장면 없는 날은 4.50 → 4.25(차이 없음). v5 60런 모두 `judge()` 통과, 제목 60/60.

## 2. 바꾸지 않는 것

호칭 줄(`speakerHeadLine`)·언어 줄·캡션 감싸기(`{때}에 담은 장면:`)·캡션 상한 8, 제목 질문 둘과 2단계 호출, `judge()` 거부 갈래 넷,
`extractTitle()`, `buildPrompt()`·`instructionLines()`·`titleQuestion()` 시그니처, 날의 갈래 넷(`dayKindOf`), 샘플링 값, 영어 경로(`SPEAKER_RULES` 등),
`src/signals/collect.ts`의 `reason` 문자열(진단 화면이 그대로 보인다).

## 3. 설계

### 3.1 문안 — `src/diary/prompt.ts` 한국어 경로

v5 `user-prompt.md`와 **글자 단위로 같게** 옮긴다(지시서 §1~§3).

- 머리: `E2_RULES` 세 줄 + `E_TONE.quiet` 교체(4행 「주인의 마음은 … 한 번만 짐작한다」가 탐정 말투 교정의 핵심).
- 기록 문장: 머리줄·사진 수·사진 없음·사진 모름·자리 여럿/하나/출처/없음/모름·자리 이름, `S_PLACES`·`S_VISION_PARTIAL`·`S_TRUNCATED`·`S_DAY_OPEN`을 `~요`로.
- 본 장면 없는 날 꼬리: `NO_SCENE_WHY`·`NO_SCENE_MINE`의 「나는/내」→「너는/네」, 보기 문장 `~요`, 끝 「본문은 네댓 문장이면 되고, 끝까지 '요'로 끝나는 말투로 쓴다.」
- 본 장면 있는 날 꼬리: `이 기록으로 그 하루의 일기를 써라. 첫 문장은 '{틀}'처럼 시작하고, 끝까지 '요'로 끝나는 말투로 쓴다.`

### 3.2 첫 문장 틀 — 날짜로 하나

- 틀 11개를 v5 「첫 문장 틀」 블록 순서 그대로 상수 배열로 둔다.
- 고르는 규칙: `request.signals.date`(`YYYY-MM-DD`)를 `Date.UTC(y, m-1, d) / 86_400_000`(1970-01-01부터의 일수)로 바꾸고 **mod 11**.
  - 시각·난수·기기 시간대를 읽지 않는다 → `buildPrompt()` 결정성(005 P6) 유지, 같은 날을 다시 쓰면 같은 틀.
  - 연속한 11일은 11개 틀을 모두 한 번씩 쓴다.
- 이유: 틀을 하나만 주면 모든 일기가 같은 첫 문장(36/36), 한 번에 여럿 주면 첫째만 고른다(12/12) — 고르는 일은 조립이 한다(지시서 §3).

### 3.3 `{reason}` — 프롬프트 쪽 고정 문장 (소유자 결정 2026-10-12)

지금은 `collect.ts`의 평어 이유(「사진 접근 권한이 없다」, 「사진을 조회하지 못했다: {오류 메시지}」)를 그대로 붙여 `~요` 글에 평어·영어 오류 문구가 섞인다.
한국어 경로는 이유 문자열을 읽지 않고 고정 문장을 쓴다:

| 상태 | 프롬프트 문장 | 근거 |
| --- | --- | --- |
| 사진 `unknown`(권한·조회 실패 모두) | 사진은 몰라요. 사진을 볼 수 있는 길이 막혀 있어요. | v5 `h-denied` 측정 |
| 자리 `unknown`, 사진도 `known`이 아님 | 다닌 자리는 몰라요. 사진을 보지 못해 좌표를 물을 수 없어요. | v5 `none`·`h-dayopen`·`h-denied` 측정 |
| 자리 `unknown`, 사진은 `known`(좌표 읽기 실패) | 다닌 자리는 몰라요. 사진의 좌표를 읽지 못했어요. | **재지 않음** — 새 문장 |

- 판정은 신호의 `kind`만 본다(이유 문자열 비교 금지 — 053·062의 「문구로 분기하지 않는다」).
- 대가: 프롬프트에서 「권한 없음」과 「조회 실패」의 구분이 사라진다. 둘 다 「모른다」로 남으므로 원칙 V(`none`/`unknown` 구분)는 유지된다. 진단 화면의 이유는 그대로다.

### 3.4 `instructionLines()` (소유자 결정 2026-10-12)

- 한계 문장 넷은 `~요` 판으로 따라간다(같은 상수를 쓴다).
- **본 장면 있는 날의 꼬리(그날의 틀이 끼워진 한 줄)를 새로 넣는다** — v5 60런이 이 상태로 모두 통과. 틀은 작은따옴표 안이라 `echoPieces()`가 비교에서 빼므로 틀대로 시작해도 거부되지 않는다.
- 본 장면 없는 날의 꼬리·제목 질문·언어 줄은 지금처럼 들어 있다.

### 3.5 로마자 차단 문법

- 문법 문자열 `root ::= [^A-Za-z]*` 를 `src/inference/sampling.ts`에 상수 하나로 둔다(온디바이스·데스크톱이 공유하는 유일한 자리).
- `llama-port.ts`의 `complete()` — 본문(`run`)과 제목(`ask`)이 함께 쓰는 한 곳 — 에 `grammar`로 넘긴다. 프리웜(`n_predict: 1`)에는 넣지 않는다(KV 캐시와 무관).
- `desktop-server.ts`의 `ServerRequest`/`serverRequestFor()`에도 같은 값을 싣는다(FR-005 「온디바이스와 같은 값」).
- 설치본 llama.rn 0.12.9의 `CompletionParams`에 `grammar?: string`이 있다. jinja 경로에서 실제로 듣는지는 실기기에서 본다.
- 영어 캐릭터 경로가 생기면 이 문법이 출력을 막는다 — 지금 로스터는 한국어 하나(`quiet`)뿐이므로 상수 주석에 「로스터에 비한국어 캐릭터가 들어오면 다시 판단」을 남긴다.
  (언어별로 가르는 코드는 만들지 않는다 — YAGNI.)

## 4. 테스트

- 문안을 글자로 잠근 기존 테스트(`__tests__/diary/prompt.test.ts`·`prompt-e2sn.test.ts`·`acceptance.test.ts`·`entry.test.ts` 등)를 새 문안으로 고친다.
- 새 계약:
  - 틀 목록이 v5 `user-prompt.md` 「첫 문장 틀」 블록과 바이트가 같다(11개, 순서 포함).
  - 같은 날짜 → 같은 틀, 연속한 11일 → 11개 모두, 결과가 시간대(`TZ`)와 무관.
  - `{reason}`이 프롬프트에 들어가지 않는다(가짜 이유 문자열을 넣어 프롬프트에 없음을 단언), 세 고정 문장이 갈래대로 나온다.
  - `instructionLines()`가 본 장면 있는 날 꼬리를 담고, 그 줄이 `buildPrompt()` 결과에 실제로 있다(P-7).
  - `llama-port`의 `run`·`ask`가 같은 `grammar`를 넘기고 프리웜은 넘기지 않는다. 데스크톱 요청에도 같은 값.
- 위반 주입: 틀 한 글자 변경·문법 제거·`reason` 되살리기가 각각 테스트를 실패시키는지 본다.
- 바이트 대조(지시서 §8): my-ollama `gen-prompts.ts`로 10케이스를 만들어 v5 `prompts.json`과 견준다. 틀은 날짜로 고르므로 **꼬리 줄은 틀 자리를 빼고 비교**하고 틀 자체는 위 목록 계약으로 잠근다.
  Windows 함정(AGENTS 061: `pathToFileURL`, 진입 가드)을 그대로 따른다.

## 5. 실기기 확인 (dev, 원칙 V)

1. 영어 캡션이 든 날 몇 편 — 본문·제목에 로마자 없음, `eos`로 정상 종료(문법이 jinja 경로에서 듣는가).
2. 열 편쯤 읽기 — 첫 문장이 날마다 다르고 `~요`가 끝까지 가는가, 탐정 말투가 사라졌는가.
3. **헤드리스 자동 쓰기 1회 이상** — 본문 토큰 중앙값 134 → 209(최대 324)라 180초 한도(헤드리스는 포그라운드의 3~4배)를 넘는지 잰다.
4. 사진 권한 없는 날 1편 — 고정 `{reason}` 문장 경로.

## 6. 위험·재지 않은 것

- 헤드리스 시간 한도 초과 가능성(§5-3). 넘으면 `n_predict`·분량 줄을 건드리기 전에 소유자에게 묻는다(문안은 my-ollama에서 다시 잰다).
- llama.rn 문법 옵션의 동작·속도는 미측정.
- 깨진 문장 증가(4/18 → 8/18), 장면 많은 날 때 순서 훑기(9/18) — 소유자가 받아들인 수준.
- 좌표 읽기 실패 문장(§3.3 셋째 줄), 받침 있는 이름, 캡션이 8을 넘는 날은 재지 않았다.
- 053의 「기록 대신 상상으로 하루를 채워요」 안내와 새 글의 관계는 바뀌지 않는다(이 조각 밖).
